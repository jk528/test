# 四方镜子 - 完整总结

## 一、功能概述

**四方镜子** 是一个多列数据循环组合生成工具，支持两种核心算法和多种输出格式。

### 两种核心算法

| 算法 | 原理 | 结果行数 | 适用场景 |
|------|------|----------|----------|
| **四方循环**（笛卡尔积） | 每列各取一个元素，生成所有排列组合 | 各列行数的 **乘积** | 全排列、实验条件组合、测试用例 |
| **双边循环**（LCM独立循环） | 每列各自独立循环，互不影响 | 各列行数的 **最小公倍数** | 周期对齐、循环填充、批量命名 |

### 八种操作模式

```
┌─────────────────────────────────────────────────┐
│                  四方循环                         │
│  （笛卡尔积：2列×3列 = 6行结果）                   │
├─────────────┬─────────────┬─────────────┬───────┤
│  反向 竖向   │  正向 竖向   │  正向 横向   │ 反向 横向│
│  A1B1       │  A1B1       │ A1B1 A2B1… │       │
│  A1B2       │  A2B1       │             │       │
│  A2B1       │  A1B2       │             │       │
│  A2B2       │  A2B2       │             │       │
└─────────────┴─────────────┴─────────────┴───────┘

┌─────────────────────────────────────────────────┐
│                  双边循环                         │
│  （LCM独立循环：LCM(2,4) = 4行结果）               │
├─────────────────────┬───────────────────────────┤
│    竖向输出          │       横向输出              │
│    A1 B1            │  A1 B1  A2 B2  A1 B3  A2 B4│
│    A2 B2            │                           │
│    A1 B3            │                           │
│    A2 B4            │                           │
└─────────────────────┴───────────────────────────┘
```

每种模式又分为 **合并模式**（用连接符拼成一个字符串）和 **分开模式**（各列独立显示）。

## 四、底层逻辑详解

### 4.1 核心数学基础

#### 循环索引函数

```
循环索引(序号, 周期长度) = ((序号 + 周期长度 - 1) mod 周期长度) + 1
```

把任意正整数映射到 `[1, 周期长度]` 的循环范围内，就像钟表一样循环。

```
序号:   1  2  3  4  5  6  7  8  9 ...
结果:   1  2  3  1  2  3  1  2  3 ...  (周期=3)
```

#### 向上取整除法

```
向上取整除法(被除数, 除数) = ceil(被除数 / 除数)
```

用于计算"当前是第几个周期"。

---

### 4.2 四方循环（笛卡尔积）算法

#### 问题：给定 M 列数据，每列有 C₁, C₂, ..., Cm 个元素，生成所有排列组合

**总行数** = C₁ × C₂ × ... × Cm （笛卡尔积）

#### 循环步长

每一列有一个"步长"，表示该列经过多少行才变化一次。

**正向循环**（左列最慢，右列最快）：
```
步长[0] = 1                              第1列每行都变
步长[1] = 步长[0] × C₁ = C₁               第2列每 C₁ 行变一次
步长[2] = 步长[1] × C₂ = C₁×C₂            第3列每 C₁×C₂ 行变一次
...
步长[i] = 步长[i-1] × Cᵢ₋₁
```

**反向循环**（左列最快，右列最慢）：
```
步长[i] = 总行数 / (C₁ × C₂ × ... × Cᵢ)
```

#### 源行号计算公式

```
源行号 = 循环索引( 向上取整除法(当前行号, 步长), 该列元素数 )
```

即：
1. 当前行号 ÷ 步长 → 得到"第几个周期"
2. 对元素数取模循环 → 映射到源数据的行号

#### 示例：2列（A列2个, B列3个），正向循环

| 行号 | A列步长=1 | 第几个周期 | ys(周期,2) | A列值 | B列步长=2 | 第几个周期 | ys(周期,3) | B列值 |
|-----|-----------|-----------|------------|-------|-----------|-----------|------------|-------|
| 1 | 1 | 1 | 1 | A1 | 2 | 1 | 1 | B1 |
| 2 | 1 | 2 | 2 | A2 | 2 | 1 | 1 | B1 |
| 3 | 1 | 3 | 1 | A1 | 2 | 2 | 2 | B2 |
| 4 | 1 | 4 | 2 | A2 | 2 | 2 | 2 | B2 |
| 5 | 1 | 5 | 1 | A1 | 2 | 3 | 3 | B3 |
| 6 | 1 | 6 | 2 | A2 | 2 | 3 | 3 | B3 |

---

### 4.3 双边循环（LCM独立循环）算法

#### 问题：每列各自独立循环，总行数 = LCM(各列行数)

每列直接用行号对自身长度取循环：

```
第j列第i行的源行号 = 循环索引(i, 每列元素个数[j])
```

#### 完整循环 vs 残缺循环

- **完整循环**：乘积 = LCM → 各列互质，一个完整周期内所有列都轮完整数遍
- **残缺循环**：乘积 > LCM → 存在公约数，还没等所有列轮完一遍就开始重复了

工作表命名规则（v5/v6 统一）：
- 四方循环：`四方_{方向}_{模式}_{序号}`，如 `四方_正竖_合并_3`
- 双边循环(完整)：`双边_{方向}_完整_{模式}_{序号}`，如 `双边_竖_完整_合并_4`
- 双边循环(残缺)：`双边_{方向}_残缺{乘积}-{LCM}_{模式}_{序号}`，如 `双边_横_残缺8-2_分开_5`

---

### 4.4 数据流向

#### 四方循环数据流

```
读取工作表
    ↓
统计每列行数 → 计算乘积（总行数）→ 超限检查
    ↓
批量读取源数据（一次Range读取，性能最优）
    ↓
计算循环步长数组（正向/反向）
    ↓
构建笛卡尔积矩阵 [列][行]  ← 核心：逐列逐行计算源行号
    ↓
┌─────────────┴──────────────┐
│                             │
横向输出                     竖向输出
│                             │
├─ 合并：按行拼接字符串        ├─ 合并：按行拼接字符串
│   结果：1行 × N列            │   结果：N行 × 1列
│                             │
└─ 分开：直接输出矩阵          └─ 分开：矩阵转置
    结果：M列 × N行                结果：N行 × M列
    ↓
写入新建结果表（A1起始，统一命名）
```

#### 双边循环数据流

```
读取工作表 → 统计每列行数 → 计算LCM和乘积 → 超限检查
    ↓
批量读取源数据
    ↓
构建LCM循环矩阵（每列独立循环）
    ↓
新建结果表（统一命名：双边_竖_完整_合并_序号）
    ↓
根据输出方向和合并模式准备数据
    ↓
写入新工作表（A1起始）
```

### 4.5 性能优化点

| 优化手段 | 说明 | 提升幅度 |
|----------|------|----------|
| **批量读取** | 一次性 `Range.Value2` 读取全部数据，而非逐单元格 | 10~100倍 |
| **批量写入** | 构建完整数组后一次性写入 | 10~100倍 |
| **关闭屏幕刷新** | `ScreenUpdating = False` | 2~5倍 |
| **手动计算模式** | `Calculation = xlManual` | 1.5~3倍 |
| **数组操作** | 全部在内存数组中计算，最后才写表 | 5~20倍 |
| **Join拼接** | 用 `Array.join()` 代替字符串累加 | 1.2~2倍 |
| **按列预处理格式** | 整列格式相同的只需判断一次日期格式 | 列数倍 |

### 4.6 动态创建窗体原理

#### VBA 版（基于范例111模式）

v5/v6 统一采用 **Designer.Controls.Add + CodeModule.InsertLines** 模式：

```
VBComponents.Add(3)               → 创建空白窗体
    ↓
Designer.Controls.Add("Forms.CommandButton.1", "CommandButton1")  → 添加设计时控件
    ↓
CodeModule.InsertLines(行号, 代码)  → 逐行注入事件处理代码
    ↓
UserForms.Add(名称).Show           → 显示窗体
    ↓
VBComponents.Remove                → 删除临时窗体
```

**v5（modeless）的清理**：Show 立即返回，不能在 Show 后删除。用 `OnTime` 延迟1秒清理，或下次运行时清理。

**v6（modal）的清理**：Show 阻塞直到窗体关闭，返回后立即 `Remove`，安全可靠。

#### 版本演进历程

| 版本 | 实现方式 | 问题 | 状态 |
|------|---------|------|------|
| v1 | Designer直接加控件 | WPS报438 | 废弃 |
| v2 | Initialize中Me.Controls.Add | 事件不触发 | 废弃 |
| v3 | Initialize+Controls集合访问 | 仍不稳定 | 废弃 |
| v4 | 生成frm+Import | OleObjectBlob报错 | 废弃 |
| **v5** | Designer+CodeModule, 模态+无Unload Me | ✅ | 保留 |
| **v6** | Designer+CodeModule, 模态+Unload Me | ✅ | **推荐** |

#### JS 版（InputBox交互）

JS宏无 VBProject API，不能动态创建窗体。v5/v6 用 InputBox 替代：

- **v6 JS**：单次 InputBox → 执行 → 结束
- **v5 JS**：循环 InputBox → 执行 → 询问继续 → 循环

## 七、常见问题

### Q: 提示"已超出表格限制"
A: Excel最大行数是1048576。笛卡尔积增长很快，5列各10个元素就是10万行，6列就是100万行。

### Q: 合并模式下连接符为空会怎样？
A: 连接符为空时，会切换到分开模式（各列独立输出），等价于取消"合并"勾选。

### Q: 双边循环为什么叫"双边"？
A: 原意是"两边各自独立循环"，扩展到多列也是一样，每列独立循环。

### Q: VBA版需要什么权限？
A: 需在 选项→信任中心→宏设置 中勾选"信任对VBA工程对象模型的访问"。

### Q: VBA v5和v6怎么选？
A: v6（推荐）模态窗体，点按钮执行后自动关闭并清理；v5 非模态，窗体保持打开可反复操作。

### Q: JS版需要什么权限？
A: 不需要额外权限，WPS宏环境即可运行。

## 八、开发踩坑记录与解决过程

### 8.1 Error 438：Designer 对象不可用（v1 → v2）

**现象**：`VBComponents.Add(3).Designer.Controls.Add(...)` 在 WPS 中报 "对象不支持该属性或方法"（错误438）。Excel 正常，WPS 不行。

**原因**：WPS VBA 对 `Designer` 对象的接口支持不完整，能创建窗体但不能通过 Designer 添加控件。

**解决**：把控件创建从模块级移到 `UserForm_Initialize` 事件中，用 `Me.Controls.Add` 创建运行时控件。但引入了新问题（见 8.2）。

---

### 8.2 "方法和数据成员未找到"：动态控件引用（v2 → v3）

**现象**：`Me.CommandButton1.SetFocus` 报 "方法和数据成员未找到"。

**原因**：`Initialize` 事件中用 `Me.Controls.Add` 动态添加的控件，在该阶段尚未注册为窗体的成员变量，VBA 无法通过 `Me.CommandButton1` 这种直接引用方式找到它。

**解决**：所有访问动态控件的地方改用 `Me.Controls("CommandButton1")` 集合方式：
```vba
' 报错：直接引用
Me.CommandButton1.SetFocus
' 正确：通过 Controls 集合
Me.Controls("CommandButton1").SetFocus
```

> 注意：事件过程名 `CommandButton1_Click` 本身可以保留，VBA 能通过名称匹配动态控件的事件。只有代码内部访问控件属性时才需要用 `Controls()` 方式。

---

### 8.3 "无有效的文件引用"：frm 文件导入失败（v4）

**现象**：生成的 frm 文件 `Import` 时报 "不是一个已加载的控件类，无有效的文件引用"。

**原因**：frm 文件中的 `OleObjectBlob = "窗体名.frx":0000` 行告诉 VBA 去对应的 .frx 二进制文件读取资源（图标、图片等），但我们没有生成 .frx 文件。

**解决**：窗体只有普通控件（按钮、文本框等），没有二进制资源，直接删除 `OleObjectBlob` 行即可。

---

### 8.4 modeless 窗体弹出后直接隐藏（v5 重构）

**现象**：`Show vbModeless` 后窗体直接隐藏，无法点击使用功能。

**原因**：`Show vbModeless` 立即返回（不阻塞），代码继续执行到下一行 `VBP.VBComponents.Remove 窗体组件`，把刚创建的窗体组件立刻删了。即使加了 `OnTime` 延迟清理，WPS 对动态窗体的 modeless 支持仍不稳定。

**最终解决**：放弃 `vbModeless`，改用模态 `Show` + 按钮事件中不含 `Unload Me`：
- 窗体模态显示（可靠，不会消失）
- 操作按钮执行后不关闭窗体（可反复点击不同操作）
- 增加"关闭窗体"按钮（红色），点击后才 `Unload Me` 退出
- `Show` 返回后立即 `Remove` 清理组件（安全）

这样既保留了"可反复操作"的体验，又避免了 modeless 的不稳定性。

---

### 8.5 `Len(Sheets.Count)` 报错

**现象**：`新建结果表` 函数中表名截断逻辑报错，截断结果不正确。

**原因**：VBA 的 `Len()` 函数对数字参数返回的是**数据类型的字节数**（Long = 4），不是数字的位数。例如 `Sheets.Count = 5`，`Len(5)` 返回 4 而不是 1。

**解决**：用 `CStr()` 先转成字符串再取长度：
```vba
' 错误：Len(5) = 4（Long类型大小）
Len(Sheets.Count)
' 正确：Len("5") = 1（字符串长度）
Len(CStr(Sheets.Count))
```

### 8.6 命名和建表逻辑不统一

**现象**：四方循环和双边循环各自独立创建工作表，命名格式不同：
- 四方：`正横_合并_sheet3`
- 双边：`完整_8sheet3` 或 `残缺_8|2sheet3`

且双边循环还尝试在 `Worksheets("重复字")` 之后创建（如果该表不存在就报错）。

**解决**：
1. 提取公共函数 `新建结果表(名称前缀)`，两个算法统一调用
2. 统一命名格式：`算法_方向_模式_序号`
3. 统一创建方式：`Worksheets.Add(After:=ActiveSheet)`
4. 内置超31字符截断和重名兜底

### 8.7 JS 宏无法动态创建窗体

**现象**：VBA 可以用 `VBProject.VBComponents.Add(3)` 动态创建 UserForm，但 WPS JS 宏没有 `VBProject` API。

**解决**：JS 版用 `Application.InputBox` 替代窗体交互：
- v6 JS：单次 InputBox → 执行 → 结束（对应 VBA v6 模态）
- v5 JS：循环 InputBox → 执行 → 询问继续 → 循环（对应 VBA v5 非模态）

### 8.8 原始 VBA 代码重复率超 70%

**现象**：原始 VBA 的 4 个模式（正/反 × 横/竖）几乎完全复制粘贴，只有循环步长计算略有不同。变量名难理解：`mmm`、`L(1,n)`、`LL`、`lll`、`LLLL`。

**解决**：
1. 提取统一函数 `四方循环_执行(是否正向, 是否横向)`，参数化控制
2. 语义化命名：`连接符`、`每列行数`、`步长`、`结果`
3. 用 `Join()` 替代手动字符串拼接（消除末尾多余连接符）

### 8.9 性能优化版反而更慢

**现象**：某版本试图优化性能，结果反而更慢。

**原因**：改用 `GetCellText` 逐个单元格读取 + 逐个格式化日期，放弃了批量读取的性能优势。日期格式化逐单元格调用，效率极低。

**解决**：
- 批量 `Range.Value2` 读取全部数据（一次读取，10~100倍提升）
- 按列预处理格式（每列只需判断一次格式类型）
- 构建完整数组后一次性写入

### 8.10 日期格式判断逻辑 bug

**现象**：`isTimeOnly` 判断条件自相矛盾。

**原因**：原逻辑为 `isTimeOnly = fmt.indexOf('h') !== -1 && fmt.indexOf('m') === -1`，但含 `h`（小时）的时间格式通常也含 `m`（分钟），导致条件永远为 false。

**解决**：重新设计判断逻辑，正确区分纯时间（`hh:mm`）、纯日期（`yyyy-mm-dd`）、日期时间（`yyyy-mm-dd hh:mm`）。
