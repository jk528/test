## 二、四象限镜像对称

### 2.1 核心发现：方向反转 ≠ 左右镜像

用 A1A2 / B3B4B5 / C6C7C8C9（2×3×4=24组）验证后，发现：

| 概念 | 是否真正镜像 | 说明 |
|------|------------|------|
| 方向反转（正↔反） | ❌ 不是 | 只是不同的遍历顺序，不是镜像 |
| 数据反转（上下颠倒） | ✅ 是 | 等价于行顺序反转，真正的上下镜像 |
| **元素反转（列顺序反转）** | ✅ 是 | 每行元素左右翻转，真正的左右镜像 |

### 2.2 真正的四象限镜像

以基准数据为左上，通过两种翻转生成另外三个象限：

| 位置 | 变换方式 | 说明 | 示例（A1B3C6） |
|------|---------|------|--------------|
| 左上 | 原始（基准） | 基准 | A1B3C6 |
| 右上 | 左右镜像 | 每行元素反转（列顺序翻转） | C6B3A1 |
| 左下 | 上下镜像 | 行顺序反转（第1行 ↔ 最后1行） | A2B5C9 |
| 右下 | 中心镜像 | 行反转 + 元素反转 | C9B5A2 |

**对称性验证（全部严格成立）：**
- ✅ 左右对称：右上 = reverse(左上每行)
- ✅ 上下对称：左下 = 左上行反转
- ✅ 中心对称：右下 = 行反转 + 元素反转

### 2.3 4 种基准

四象限开关打开时，点击按钮 1~4 分别生成不同基准的四象限：

| 按钮 | 基准 | 布局 | 说明 |
|------|------|------|------|
| 按钮1 | 反竖 | 竖向 | 左慢右快为基准的竖向四象限 |
| 按钮2 | 正横 | 横向 | 左快右慢为基准的横向四象限 |
| 按钮3 | 正竖 | 竖向 | 左快右慢为基准的竖向四象限 |
| 按钮4 | 反横 | 横向 | 左慢右快为基准的横向四象限 |

布局自动跟随基准：竖按钮 → 竖四象限，横按钮 → 横四象限。

## 三、两种布局对比

### 3.1 竖向布局（按钮1、按钮3）

组合**竖向排列**（一列一组），四象限按 2×2 摆放：

```
┌───────────────┬───────────────┐
│【原始】       │【左右镜像】   │
│ A1-B3-C6      │ C6-B3-A1      │
│ A2-B3-C6      │ C6-B3-A2      │
│ A1-B4-C6      │ C6-B4-A1      │
│ ...           │ ...           │
├───────────────┼───────────────┤
│【上下镜像】   │【中心镜像】   │
│ A2-B5-C9      │ C9-B5-A2      │
│ A1-B5-C9      │ C9-B5-A1      │
│ A2-B4-C9      │ C9-B4-A2      │
│ ...           │ ...           │
└───────────────┴───────────────┘
```

特点：每个组合占 1 行，适合**列数少、行数多**的数据。

### 3.2 横向布局（按钮2、按钮4）

组合**横向排列**（每列一个组合，元素向下延伸），四象限按 2×2 摆放。

**合并模式**（每个组合1个单元格，横向排列）：
```
┌──────────────────────────────────────────┐
│【原始】         │【左右镜像】             │
│ A1B3C6 A2B3C6… │ C6B3A1 C6B3A2…         │
├────────────────┼─────────────────────────┤
│【上下镜像】     │【中心镜像】             │
│ A2B5C9 A1B5C9… │ C9B5A2 C9B5A1…         │
└────────────────┴─────────────────────────┘
```

**分开模式**（每列一个组合，元素从上往下读，3列元素 × 24列组合 = 3行 × 24列 = 72格）：
```
每象限：3行 × 24列 = 72个单元格

  组1  组2  组3  ...  组24
  A1   A2   A1   ...  A2    ← 第1列元素
  B3   B3   B4   ...  B5    ← 第2列元素
  C6   C6   C6   ...  C9    ← 第3列元素
```

### 3.3 布局尺寸（M=组合数，K=列数）

| 模式 | 竖向布局（每象限） | 横向布局（每象限） |
|------|------------------|------------------|
| 合并 | M 行 × 1 列 | 1 行 × M 列 |
| 分开 | M 行 × K 列 | K 行 × M 列 |

例：3 列 × 24 组合 = 24 组
- 竖合：24 行 × 1 列 = 24 格
- 横合：1 行 × 24 列 = 24 格
- 竖分：24 行 × 3 列 = 72 格
- **横分：3 行 × 24 列 = 72 格** ✅

四象限整体尺寸 = 每象限 × 2 + 分隔（空行/空列）+ 标签行

## 四、使用方法

### 4.1 基本操作

1. 将 `四方镜子_单模块版_v11.bas` 导入 Excel VBA 工程
2. 运行 `四方镜子()` 宏
3. 勾选/取消顶部开关：
   - **合并**：组合元素合并成一列 vs 多列分开
   - **数据反转**：每列数据从下往上读取
   - **四象限对称**：按钮1~4生成四象限 vs 单表
4. 点击对应按钮生成结果

### 4.2 四象限使用技巧

- 想看竖向四象限 → 点按钮1（反竖基准）或按钮3（正竖基准）
- 想看横向四象限 → 点按钮2（正横基准）或按钮4（反横基准）
- 正竖 vs 反竖的区别：生成顺序不同（左快右慢 vs 左慢右快），但镜像关系相同
- 4 种基准生成的表名不同（四象限_正竖_…、四象限_反横_… 等），不会互相覆盖

### 4.3 如何选择竖版还是横版

| 数据特征 | 推荐 | 原因 |
|---------|------|------|
| 2列各3行（2×3=6组合） | 竖版 | 6行少，竖版紧凑 |
| 3列各2行（3×2=6组合） | 横版 | 6列少，横版紧凑 |
| 行数 < 列数 | 横版 | 行数少，横排更直观 |
| 行数 > 列数 | 竖版 | 列数少，竖排更直观 |

简单说：**数据瘦高用竖版，数据矮胖用横版**。

## 八、v11.6 修复：横向布局镜像公式分模式

### 8.1 问题发现

v11.5 中 Q2/Q3/Q4 镜像公式只按"竖向/横向"两种布局区分，但在实际测试 2×3×4 数据时发现：

| 表号 | 基准 | 模式 | 对称性 |
|------|------|------|--------|
| 3 | 反竖 | 合并 | ✓ 正确 |
| 4 | 反竖 | 分开 | ✓ 正确 |
| 5 | 正竖 | 合并 | ✓ 正确 |
| 6 | 正竖 | 分开 | ✓ 正确 |
| 7 | 正横 | 合并 | ✗ **错误** |
| 8 | 正横 | 分开 | ✓ 正确 |
| 9 | 反横 | 合并 | ✗ **错误** |
| 10 | 反横 | 分开 | ✓ 正确 |
| 11 | 正横 | 合并 | ✗ **错误**（用户报告） |
| 12 | 反横 | 分开 | ✓ 正确（用户报告，确认对称） |

**规律**：所有"横向·合并"模式都错误，"横向·分开"模式却正确。

### 8.2 根本原因

**视觉上的"左右/上下"是相对最终输出布局而言的**，而横向布局下"合并"与"分开"的视觉方向完全不同：

```
横向·分开（K行×M列）          横向·合并（1行字符串）
   列1  列2 ... 列M           str1 str2 ... strM
行1  A   A       A             A    A       A      ← 元素左右排列
行2  B   B       B             B    B       B
行3  C   C       C             C    C       C      ↑ 组合上下排列
↑ 元素上下排列                   ↑ 组合左右排列
← 组合左右排列
```

- **横向分开**：视觉左右 = 组合方向；视觉上下 = 元素方向
- **横向合并**：视觉左右 = 字符串内元素方向；视觉上下 = 组合方向

因此镜像公式必须区分：

| 模式 | 视觉左右方向 | 视觉上下方向 | Q2 左右镜像 | Q3 上下镜像 |
|------|----------|----------|-----------|-----------|
| 竖向·合并 | 元素 | 组合 | 元素反转 | 行反转 |
| 竖向·分开 | 元素 | 组合 | 元素反转 | 行反转 |
| 横向·分开 | 组合 | 元素 | **组合反转** | **元素反转** |
| 横向·合并 | 元素 | 组合 | **元素反转** | **行反转** |

关键洞察：横向合并模式下只有 1 行字符串，字符串内元素从左到右排列，所以"左右镜像"反转的是字符串内的元素（同竖向），"上下镜像"是 Q1↔Q3 两行间的关系（行反转）。

### 8.3 修复方案

仅"横向分开"才需要互换 Q2/Q3 公式，其他三种情况都用竖向公式：

```vb
Dim 互换 As Boolean
互换 = (是否横向 And Not 是否合并)  ' 仅横向分开时为 True
If 互换 Then
    Q2(j,i) = Q1(j, 总行数-i+1)     ' 左右镜像=组合反转
    Q3(j,i) = Q1(总列数-j+1, i)     ' 上下镜像=元素反转
Else
    Q2(j,i) = Q1(总列数-j+1, i)     ' 左右镜像=元素反转
    Q3(j,i) = Q1(j, 总行数-i+1)     ' 上下镜像=行反转
End If
Q4(j,i) = Q1(总列数-j+1, 总行数-i+1)  ' 中心镜像=双反转（所有模式相同）
```

| 基准 | 模式 | 左右对称 | 上下对称 | 中心对称 | Q2↔Q3 |
|------|------|--------|--------|--------|-------|
| 反竖 | 合并 | ✓ | ✓ | ✓ | ✓ |
| 反竖 | 分开 | ✓ | ✓ | ✓ | ✓ |
| 正横 | 合并 | ✓ | ✓ | ✓ | ✓ |
| 正横 | 分开 | ✓ | ✓ | ✓ | ✓ |
| 正竖 | 合并 | ✓ | ✓ | ✓ | ✓ |
| 正竖 | 分开 | ✓ | ✓ | ✓ | ✓ |
| 反横 | 合并 | ✓ | ✓ | ✓ | ✓ |
| 反横 | 分开 | ✓ | ✓ | ✓ | ✓ |

## 九、调试过程与逻辑思路

### 9.1 问题排查流程

1. **用户反馈**：反竖合并正确，反横合并错误、反横分开正确
2. **读 MD 文件**：理解设计意图（元素反转=左右镜像，行反转=上下镜像）
3. **用 code_mode 模拟**：构造 2×3 数据（6 组合），分别用竖向/横向公式验证
4. **发现根因**：横向布局下"合并"和"分开"的视觉方向不同，但原代码用同一套公式

### 9.2 关键调试手段

用 Exec 沙箱独立验证公式，不依赖 WPS 环境：

```javascript
// 构造 2x3x4 数据
var 源数据 = [['a1','b1','c1'],['a2','b2','c2'],['','b3','c3'],['','','c4']];
// 生成 Q1，按公式生成 Q2/Q3/Q4，逐一验证对称性
```

每次公式修改后都重新运行验证，8 个四象限 × 4 种对称性 = 32 个检查点全部通过才确认修复。

### 9.3 设计原则总结

**镜像公式取决于最终输出布局的视觉方向**，不是数据存储方向：
- 数据按列存 `Q[c][r]` 是固定的
- 但"左右"和"上下"在最终输出表中的含义会随布局变化
- 必须按"输出布局"而非"数据结构"来定义镜像公式
