## 二、四象限镜像对称

### 2.1 核心发现：方向反转 ≠ 左右镜像

用 A1A2 / B3B4B5 / C6C7C8C9（2×3×4=24组）验证后，发现：

| 概念 | 是否真正镜像 | 说明 |
|------|------------|------|
| 方向反转（正↔反） | ❌ 不是 | 只是不同的遍历顺序，不是镜像 |
| 数据反转（上下颠倒） | ✅ 是 | 等价于行顺序反转，真正的上下镜像 |
| **元素反转（列顺序反转）** | ✅ 是 | 每行元素左右翻转，真正的左右镜像 |

### 2.2 真正的四象限镜像

以基准数据为左上，通过两种翻转生成另外三个象限：

| 位置 | 变换方式 | 说明 | 示例（A1B3C6） |
|------|---------|------|--------------|
| 左上 | 原始（基准） | 基准 | A1B3C6 |
| 右上 | 左右镜像 | 每行元素反转（列顺序翻转） | C6B3A1 |
| 左下 | 上下镜像 | 行顺序反转（第1行 ↔ 最后1行） | A2B5C9 |
| 右下 | 中心镜像 | 行反转 + 元素反转 | C9B5A2 |

**对称性验证（全部严格成立）：**
- ✅ 左右对称：右上 = reverse(左上每行)
- ✅ 上下对称：左下 = 左上行反转
- ✅ 中心对称：右下 = 行反转 + 元素反转

### 2.3 4 种基准

四象限开关打开时，点击按钮 1~4 分别生成不同基准的四象限：

| 按钮 | 基准 | 布局 | 说明 |
|------|------|------|------|
| 按钮1 | 反竖 | 竖向 | 左慢右快为基准的竖向四象限 |
| 按钮2 | 正横 | 横向 | 左快右慢为基准的横向四象限 |
| 按钮3 | 正竖 | 竖向 | 左快右慢为基准的竖向四象限 |
| 按钮4 | 反横 | 横向 | 左慢右快为基准的横向四象限 |

布局自动跟随基准：竖按钮 → 竖四象限，横按钮 → 横四象限。

## 三、两种布局对比

### 3.1 竖向布局（按钮1、按钮3）

组合**竖向排列**（一列一组），四象限按 2×2 摆放：

```
┌───────────────┬───────────────┐
│【原始】       │【左右镜像】   │
│ A1-B3-C6      │ C6-B3-A1      │
│ A2-B3-C6      │ C6-B3-A2      │
│ A1-B4-C6      │ C6-B4-A1      │
│ ...           │ ...           │
├───────────────┼───────────────┤
│【上下镜像】   │【中心镜像】   │
│ A2-B5-C9      │ C9-B5-A2      │
│ A1-B5-C9      │ C9-B5-A1      │
│ A2-B4-C9      │ C9-B4-A2      │
│ ...           │ ...           │
└───────────────┴───────────────┘
```

特点：每个组合占 1 行，适合**列数少、行数多**的数据。

### 3.2 横向布局（按钮2、按钮4）

组合**横向排列**（每列一个组合，元素向下延伸），四象限按 2×2 摆放。

**合并模式**（每个组合1个单元格，横向排列）：
```
┌──────────────────────────────────────────┐
│【原始】         │【左右镜像】             │
│ A1B3C6 A2B3C6… │ C6B3A1 C6B3A2…         │
├────────────────┼─────────────────────────┤
│【上下镜像】     │【中心镜像】             │
│ A2B5C9 A1B5C9… │ C9B5A2 C9B5A1…         │
└────────────────┴─────────────────────────┘
```

**分开模式**（每列一个组合，元素从上往下读，3列元素 × 24列组合 = 3行 × 24列 = 72格）：
```
每象限：3行 × 24列 = 72个单元格

  组1  组2  组3  ...  组24
  A1   A2   A1   ...  A2    ← 第1列元素
  B3   B3   B4   ...  B5    ← 第2列元素
  C6   C6   C6   ...  C9    ← 第3列元素
```

### 3.3 布局尺寸（M=组合数，K=列数）

| 模式 | 竖向布局（每象限） | 横向布局（每象限） |
|------|------------------|------------------|
| 合并 | M 行 × 1 列 | 1 行 × M 列 |
| 分开 | M 行 × K 列 | K 行 × M 列 |

例：3 列 × 24 组合 = 24 组
- 竖合：24 行 × 1 列 = 24 格
- 横合：1 行 × 24 列 = 24 格
- 竖分：24 行 × 3 列 = 72 格
- **横分：3 行 × 24 列 = 72 格** ✅

四象限整体尺寸 = 每象限 × 2 + 分隔（空行/空列）+ 标签行

## 四、使用方法

### 4.1 基本操作

1. 将 `四方镜子_单模块版_v11.bas` 导入 Excel VBA 工程
2. 运行 `四方镜子()` 宏
3. 勾选/取消顶部开关：
   - **合并**：组合元素合并成一列 vs 多列分开
   - **数据反转**：每列数据从下往上读取
   - **四象限对称**：按钮1~4生成四象限 vs 单表
4. 点击对应按钮生成结果

### 4.2 四象限使用技巧

- 想看竖向四象限 → 点按钮1（反竖基准）或按钮3（正竖基准）
- 想看横向四象限 → 点按钮2（正横基准）或按钮4（反横基准）
- 正竖 vs 反竖的区别：生成顺序不同（左快右慢 vs 左慢右快），但镜像关系相同
- 4 种基准生成的表名不同（四象限_正竖_…、四象限_反横_… 等），不会互相覆盖

### 4.3 如何选择竖版还是横版

| 数据特征 | 推荐 | 原因 |
|---------|------|------|
| 2列各3行（2×3=6组合） | 竖版 | 6行少，竖版紧凑 |
| 3列各2行（3×2=6组合） | 横版 | 6列少，横版紧凑 |
| 行数 < 列数 | 横版 | 行数少，横排更直观 |
| 行数 > 列数 | 竖版 | 列数少，竖排更直观 |

简单说：**数据瘦高用竖版，数据矮胖用横版**。

## 八、v11.6 修复：横向布局镜像公式分模式

### 8.1 问题发现

v11.5 中 Q2/Q3/Q4 镜像公式只按"竖向/横向"两种布局区分，但实际测试发现横向合并模式不对称。

### 8.2 根本原因：视觉对称 = 字符串反转

**核心洞察**：视觉对称的本质就是**字符串反转**（含连字符位置对称）。

例如 `2-5-9` 反转 = `9-5-2`，这就是视觉上的左右/上下镜像。

**关键原则**：横向合并每象限仅 1 行，上下镜像 = identity（单行无纵向可翻转），左右镜像 = RE（整行视觉翻转 = 顺序反转 + 元素反转）。

以正横为例，横向合并 [RE,identity,RE] 的输出中，"259 952" 的左右镜像对成立：
- 左右镜像对1：Q1 末位 259 ↔ Q2 首位 952（双反转=视觉翻转）✓
- 左右镜像对2：Q3 末位 259 ↔ Q4 首位 952（双反转）✓
- 上下相同对1：Q1 末位 259 ↔ Q3 末位 259（identity）✓
- 上下相同对2：Q2 首位 952 ↔ Q4 首位 952（identity）✓

| 布局 | Q2 左右镜像 | Q3 上下镜像 | Q4 中心 |
|------|-----------|-----------|--------|
| 竖向 | 元素反转(E) | 行反转(R) | 双反转(RE) |
| 横向合并 | 双反转(RE) | 无变换(identity) | 双反转(RE) |
| 横向分开 | 组合反转(R) | 元素反转(E) | 双反转(RE) |

横向合并用 [RE,identity,RE]；横向分开用 [R,E,RE]；竖向用 [E,R,RE]。

### 8.3 修复方案：变换表 + 取值函数

基于"视觉对称=字符串反转"概念，用变换表统一处理。横向合并用 [RE,identity,RE]，横向分开用 [R,E,RE]，竖向用 [E,R,RE]：

```
变换类型: 0=identity(无变换), 1=R(组合反转, 反转行), 2=E(元素反转, 反转列), 3=RE(双反转)
变换表 = 横向合并 ? [3,0,3] : 横向分开 ? [1,2,3] : [2,1,3]
取值(变换, c, r) = Q1[变换含E?反转c:c][变换含R?反转r:r]
```

代码结构：
- 变换表：按布局+合并模式选择 Q2/Q3/Q4 的变换类型（三分支：横合/横拆/竖向）
- 取值函数：统一处理 identity/R/E/RE 四种变换
- 循环内：Q2/Q3/Q4 都调用同一函数，无需 if-else 分支

### 8.4 区域视觉对称性验证（2×3×4 数据）

横向合并用 [RE,identity,RE]，横向分开用 [R,E,RE]，竖向用 [E,R,RE]：

|--------|------|---------|---------|
| Q1↔Q2 左右 | 镜像 | 镜像 | 相同 |
| Q1↔Q3 上下 | 相同 | 相同 | 镜像 |

8 个四象限 × 6 种对称性 = 48 个检查点全部通过 ✓

### 8.5 同时修复的 WPS VBA 兼容问题

- **重复 Dim**：v11 原版 `Dim 列 As Long` 重复声明，WPS VBA 严格模式触发编译错误
- **Dim 位置**：所有 `Dim` 必须在过程顶部，不能在循环或条件块内

## 九、调试过程与逻辑思路

### 9.1 问题排查流程（多轮迭代）

整个 v11.6 修复历经三轮迭代，每轮都由用户反馈+code_mode 验证驱动：

**第一轮：横向布局公式不分模式**
1. 用户反馈：反横合并错误、反横分开正确
2. code_mode 模拟 2×3 数据，发现横向布局下"合并"和"分开"视觉方向不同
3. 初步修复：仅横向分开互换 Q2/Q3 公式，其他用竖向公式

**第二轮：验证函数公式用错**
1. 自测发现反竖也"假阴性"，排查后发现是验证函数用了错的横向公式
2. 按布局选择验证公式后，8 个四象限 4 种对称性全通过
3. 但用户反馈"四象限_正横_合并_18 还是有问题"

**第三轮：方向重叠错误判断**
1. 误以为横向合并左右方向=列+元素重叠，推导出 Q2=RE、Q4=R（三套独立公式）
2. 用户给出正横·合并_24 实际输出，确认"还要保留"

**第四轮：用户指出横向合并单行视觉翻转 = RE（最终修复）**
1. 用户给出正横·合并输出，指出 Q1=Q3、Q2=Q4（横向合并每象限仅1行）
2. 分析发现：横向合并单行——左右镜像 = 整行视觉翻转 = RE，上下镜像 = identity（单行无纵向可翻转）
3. 关键认知：横向合并用 [RE,identity,RE]，横向分开用 [R,E,RE]，竖向用 [E,R,RE]
4. 变换表从二分支改为三分支，增加 0=identity 类型
5. 验证：左右镜像对 Q1末259↔Q2首952、Q3末259↔Q4首952 全部成立 ✓
6. 上下相同对 Q1末259↔Q3末259、Q2首952↔Q4首952 全部成立 ✓
7. 8 个四象限 × 6 种对称性 = 48 个检查点全部通过 ✓

### 9.2 关键调试手段

用 Exec 沙箱独立验证公式，不依赖 WPS 环境：

```javascript
// 构造 2x3x4 数据
var 源数据 = [['a1','b1','c1'],['a2','b2','c2'],['','b3','c3'],['','','c4']];
// 生成 Q1，按公式生成 Q2/Q3/Q4，逐一验证对称性
```

每次公式修改后都重新运行验证，最终 8 个四象限 × 6 种区域视觉对称性 = 48 个检查点全部通过。

### 9.3 视觉对称的本质

**视觉对称 = 字符串反转**（含连字符位置对称）：

- `2-5-9` ↔ `9-5-2`（字符串反转，视觉对称）
- `1-3-6` ↔ `6-3-1`（字符串反转，视觉对称）

横向合并下，每个象限是 1 行字符串，左右镜像 = 整行视觉翻转 = 双反转（Q2=RE），上下镜像 = 单行无纵向可翻转 = identity（Q3=identity），中心镜像 = 双反转（Q4=RE）。横合用 [RE,identity,RE]，横拆用 [R,E,RE]。

### 9.4 设计原则总结

**镜像公式取决于最终输出布局的视觉方向**，不是数据存储方向：
- 数据按列存 `Q[c][r]` 是固定的
- 但"左右"和"上下"在最终输出表中的含义会随布局变化
- 必须按"输出布局"而非"数据结构"来定义镜像公式
- 横向合并用 [RE,identity,RE]（单行：左右=RE, 上下=identity），横向分开用 [R,E,RE]（多行：左右=R, 上下=E），竖向用 [E,R,RE]

### 9.5 经验教训

1. **局部对称 ≠ 区域对称**：每个位置局部对称不一定保证整个区域视觉对称
2. **验证函数也会用错公式**：调试时验证函数本身可能有 bug，需要根据布局选择验证公式
3. **视觉对称 = 字符串反转**：用字符串反转概念验证比 R/E/RE 代数分析更直观简洁
4. **小数据测边界**：2×3×4=24 组合足够暴露所有对称性问题，又不会太多导致看不清规律

## 十、v12 改动清单（非模态窗体，关闭后才退出清理）

### 10.1 核心变化

| 维度 | v11（模态） | v12（非模态） |
|------|------------|-------------|
| 窗体模式 | `Show` 模态，阻塞执行 | `Show vbModeless` 非模态，不阻塞 |
| 按钮行为 | 点击后 `Unload Me` 关闭窗体 | 点击后执行功能，**保持窗体打开** |
| 退出时机 | 按钮执行完即退出 | **点 X 关闭窗体后**才退出 |
| 宏存活方式 | Show 阻塞 | `DoEvents` 循环保持 |
| 连续操作 | 每次需重新运行宏 | 可连续点击多次按钮 |
| Excel 操作 | 窗体打开时不能操作单元格 | 窗体打开时**可同时操作 Excel** |

### 10.2 实现原理

```
用户运行宏
  ↓
动态创建窗体组件
  ↓
frm.Show vbModeless   ← 非模态显示，立即返回
  ↓
Do While UserForms.Count > 初始数量
    DoEvents           ← 让出 CPU，响应窗体事件和 Excel 操作
Loop                   ← 窗体被 Unload 后，数量回到初始值，循环退出
  ↓
VBP.VBComponents.Remove 窗体组件   ← 安全清理
  ↓
宏结束
```

### 10.3 事件处理

- **按钮 1~7**：执行对应功能，**不关闭窗体**，可连续操作
- **QueryClose（点 X）**：触发 `Unload Me`，使 `UserForms.Count` 减少
- **DoEvents 循环**：检测到窗体已卸载，退出循环，执行清理

### 10.4 JS 版本对应

JS 宏的 HTML 窗体天然支持此模式：
- `ShowDialog` 模态显示，但按钮点击通过 `window.external.notify` 发送消息
- 按钮执行后窗体保持打开，可连续点击
- 点关闭按钮或 X 才关闭对话框，宏退出

功能上与 VBA v12 完全一致。
