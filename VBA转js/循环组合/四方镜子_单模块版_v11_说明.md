## 二、四象限镜像对称

### 2.1 核心发现：方向反转 ≠ 左右镜像

用 A1A2 / B3B4B5 / C6C7C8C9（2×3×4=24组）验证后，发现：

| 概念 | 是否真正镜像 | 说明 |
|------|------------|------|
| 方向反转（正↔反） | ❌ 不是 | 只是不同的遍历顺序，不是镜像 |
| 数据反转（上下颠倒） | ✅ 是 | 等价于行顺序反转，真正的上下镜像 |
| **元素反转（列顺序反转）** | ✅ 是 | 每行元素左右翻转，真正的左右镜像 |

### 2.2 真正的四象限镜像

以基准数据为左上，通过两种翻转生成另外三个象限：

| 位置 | 变换方式 | 说明 | 示例（A1B3C6） |
|------|---------|------|--------------|
| 左上 | 原始（基准） | 基准 | A1B3C6 |
| 右上 | 左右镜像 | 每行元素反转（列顺序翻转） | C6B3A1 |
| 左下 | 上下镜像 | 行顺序反转（第1行 ↔ 最后1行） | A2B5C9 |
| 右下 | 中心镜像 | 行反转 + 元素反转 | C9B5A2 |

**对称性验证（全部严格成立）：**
- ✅ 左右对称：右上 = reverse(左上每行)
- ✅ 上下对称：左下 = 左上行反转
- ✅ 中心对称：右下 = 行反转 + 元素反转

### 2.3 4 种基准

四象限开关打开时，点击按钮 1~4 分别生成不同基准的四象限：

| 按钮 | 基准 | 布局 | 说明 |
|------|------|------|------|
| 按钮1 | 反竖 | 竖向 | 左慢右快为基准的竖向四象限 |
| 按钮2 | 正横 | 横向 | 左快右慢为基准的横向四象限 |
| 按钮3 | 正竖 | 竖向 | 左快右慢为基准的竖向四象限 |
| 按钮4 | 反横 | 横向 | 左慢右快为基准的横向四象限 |

布局自动跟随基准：竖按钮 → 竖四象限，横按钮 → 横四象限。

## 三、两种布局对比

### 3.1 竖向布局（按钮1、按钮3）

组合**竖向排列**（一列一组），四象限按 2×2 摆放：

```
┌───────────────┬───────────────┐
│【原始】       │【左右镜像】   │
│ A1-B3-C6      │ C6-B3-A1      │
│ A2-B3-C6      │ C6-B3-A2      │
│ A1-B4-C6      │ C6-B4-A1      │
│ ...           │ ...           │
├───────────────┼───────────────┤
│【上下镜像】   │【中心镜像】   │
│ A2-B5-C9      │ C9-B5-A2      │
│ A1-B5-C9      │ C9-B5-A1      │
│ A2-B4-C9      │ C9-B4-A2      │
│ ...           │ ...           │
└───────────────┴───────────────┘
```

特点：每个组合占 1 行，适合**列数少、行数多**的数据。

### 3.2 横向布局（按钮2、按钮4）

组合**横向排列**（每列一个组合，元素向下延伸），四象限按 2×2 摆放。

**合并模式**（每个组合1个单元格，横向排列）：
```
┌──────────────────────────────────────────┐
│【原始】         │【左右镜像】             │
│ A1B3C6 A2B3C6… │ C6B3A1 C6B3A2…         │
├────────────────┼─────────────────────────┤
│【上下镜像】     │【中心镜像】             │
│ A2B5C9 A1B5C9… │ C9B5A2 C9B5A1…         │
└────────────────┴─────────────────────────┘
```

**分开模式**（每列一个组合，元素从上往下读，3列元素 × 24列组合 = 3行 × 24列 = 72格）：
```
每象限：3行 × 24列 = 72个单元格

  组1  组2  组3  ...  组24
  A1   A2   A1   ...  A2    ← 第1列元素
  B3   B3   B4   ...  B5    ← 第2列元素
  C6   C6   C6   ...  C9    ← 第3列元素
```

### 3.3 布局尺寸（M=组合数，K=列数）

| 模式 | 竖向布局（每象限） | 横向布局（每象限） |
|------|------------------|------------------|
| 合并 | M 行 × 1 列 | 1 行 × M 列 |
| 分开 | M 行 × K 列 | K 行 × M 列 |

例：3 列 × 24 组合 = 24 组
- 竖合：24 行 × 1 列 = 24 格
- 横合：1 行 × 24 列 = 24 格
- 竖分：24 行 × 3 列 = 72 格
- **横分：3 行 × 24 列 = 72 格** ✅

四象限整体尺寸 = 每象限 × 2 + 分隔（空行/空列）+ 标签行

## 四、使用方法

### 4.1 基本操作

1. 将 `四方镜子_单模块版_v11.bas` 导入 Excel VBA 工程
2. 运行 `四方镜子()` 宏
3. 勾选/取消顶部开关：
   - **合并**：组合元素合并成一列 vs 多列分开
   - **数据反转**：每列数据从下往上读取
   - **四象限对称**：按钮1~4生成四象限 vs 单表
4. 点击对应按钮生成结果

### 4.2 四象限使用技巧

- 想看竖向四象限 → 点按钮1（反竖基准）或按钮3（正竖基准）
- 想看横向四象限 → 点按钮2（正横基准）或按钮4（反横基准）
- 正竖 vs 反竖的区别：生成顺序不同（左快右慢 vs 左慢右快），但镜像关系相同
- 4 种基准生成的表名不同（四象限_正竖_…、四象限_反横_… 等），不会互相覆盖

### 4.3 如何选择竖版还是横版

| 数据特征 | 推荐 | 原因 |
|---------|------|------|
| 2列各3行（2×3=6组合） | 竖版 | 6行少，竖版紧凑 |
| 3列各2行（3×2=6组合） | 横版 | 6列少，横版紧凑 |
| 行数 < 列数 | 横版 | 行数少，横排更直观 |
| 行数 > 列数 | 竖版 | 列数少，竖排更直观 |

简单说：**数据瘦高用竖版，数据矮胖用横版**。

## 八、v11.6 修复：横向布局镜像公式分模式

### 8.1 问题发现

v11.5 中 Q2/Q3/Q4 镜像公式只按"竖向/横向"两种布局区分，但实际测试发现横向合并模式不对称。

### 8.2 根本原因：视觉对称 = 字符串反转

**核心洞察**：视觉对称的本质就是**字符串反转**（含连字符位置对称）。

例如 `2-5-9` 反转 = `9-5-2`，这就是视觉上的左右/上下镜像。

横向合并下每个象限是 1 行字符串，所以镜像就是字符串反转。但因为字符串内同时包含"列方向"和"元素方向"，所以单次字符串反转 = 组合反转 + 元素反转（双反转）。

| 布局 | Q2 左右镜像 | Q3 上下镜像 | Q4 中心 |
|------|-----------|-----------|--------|
| 竖向 | 元素反转 | 行反转 | 双反转 |
| 横向分开 | 组合反转 | 元素反转 | 双反转 |
| 横向合并 | **双反转** | 元素反转 | **组合反转** |

横向合并的 Q2/Q4 公式与另外两种布局不同，是因为左右镜像=字符串反转=双反转，导致 Q4 只能是组合反转。

### 8.3 修复方案：变换表 + 取值函数

基于"视觉对称=字符串反转"概念，用变换表统一处理三种布局：

```
变换类型: 1=R(组合反转, 反转行), 2=E(元素反转, 反转列), 3=RE(双反转)
变换表 = 横向合并 ? [3,2,1] : 横向分开 ? [1,2,3] : [2,1,3]
取值(变换, c, r) = Q1[变换含E?反转c:c][变换含R?反转r:r]
```

代码结构：
- 变换表：一行代码选择 Q2/Q3/Q4 的变换类型
- 取值函数：统一处理 R/E/RE 三种反转
- 循环内：Q2/Q3/Q4 都调用同一函数，无需 if-else 分支

### 8.4 区域视觉对称性验证（2×3×4 数据）

每种布局的对称类型不同（镜像 vs 相同），由变换差决定：

| 对称对 | 竖向 | 横向分开 | 横向合并 |
|--------|------|---------|---------|
| Q1↔Q2 左右 | 镜像 | 相同 | 镜像 |
| Q1↔Q3 上下 | 相同 | 镜像 | 镜像 |
| Q1↔Q4 中心 | 镜像 | 镜像 | 相同 |
| Q2↔Q3 中心 | 镜像 | 镜像 | 相同 |
| Q2↔Q4 上下 | 相同 | 镜像 | 镜像 |
| Q3↔Q4 左右 | 镜像 | 相同 | 镜像 |

8 个四象限 × 6 种对称性 = 48 个检查点全部通过 ✓

### 8.4.1 正横·合并 修复后完整输出（示例）

数据 A=[a1,a2]，B=[b1,b2,b3]，C=[c1,c2,c3,c4]，共 24 组合/象限：

| 象限 | 首 | ... | 末 |
|------|------|------|------|
| Q1 左上 原始 | a1-b1-c1 | ... | a2-b3-c4 |
| Q2 右上 左右镜像 | c4-b3-a2 | ... | c1-b1-a1 |
| Q3 左下 上下镜像 | c1-b1-a1 | ... | c4-b3-a2 |
| Q4 右下 中心相同 | a2-b3-c4 | ... | a1-b1-c1 |

检查点：
- Q1[0]=a1-b1-c1 ↔ Q2[23]=c1-b1-a1（左右镜像：元素反转）✓
- Q1[0]=a1-b1-c1 ↔ Q3[0]=c1-b1-a1（上下镜像：元素反转）✓
- Q1[0]=a1-b1-c1 ↔ Q4[23]=a1-b1-c1（中心相同）✓

### 8.4.2 正横·分开 修复后完整输出（示例）

数据 A=[1,2]，B=[3,4,5]，C=[6,7,8,9]，每象限 3 行 × 24 列：

| 象限 | 行1 (A元素) | 行2 (B元素) | 行3 (C元素) |
|------|-----------|-----------|-----------|
| Q1 左上 原始 | 1,2,1,2,...(交替) | 3,3,4,4,5,5,...(循环) | 6×6,7×6,8×6,9×6(每值6列) |
| Q2 右上 左右相同 | 2,1,2,1,...(交替) | 5,5,4,4,3,3,...(逆循环) | 9×6,8×6,7×6,6×6(逆序) |
| Q3 左下 上下镜像 | 6×6,7×6,8×6,9×6 | 3,3,4,4,5,5,...(同Q1) | 1,2,1,2,...(同Q1) |
| Q4 右下 中心镜像 | 9×6,8×6,7×6,6×6 | 5,5,4,4,3,3,...(逆循环) | 2,1,2,1,...(交替) |

检查点：
- Q1[0][0]=1 ↔ Q2[0][23]=1（左右相同）✓
- Q1[0][0]=1 ↔ Q3[2][0]=1（上下镜像：元素反转，行1↔行3）✓
- Q1[0][0]=1 ↔ Q4[2][23]=1（中心镜像：双反转）✓
- Q2[0][0]=2 ↔ Q4[2][0]=2（Q2↔Q4 上下镜像：元素反转）✓
- Q3[0][0]=6 ↔ Q4[0][23]=6（Q3↔Q4 左右相同）✓

### 8.4.3 横向分开 vs 横向合并的对称类型对比

横向分开有 3 个"相同"对称，横向合并只有 2 个——这是因为方向重叠导致对称类型发生变化：

| 对称对 | 横向分开 | 横向合并 | 差异原因 |
|--------|---------|---------|---------|
| Q1↔Q2 左右 | **相同** | 镜像 | 分开：左右=纯组合方向；合并：左右=组合+元素重叠 |
| Q1↔Q3 上下 | 镜像 | 镜像 | 两种布局上下都是元素方向 |
| Q1↔Q4 中心 | 镜像 | **相同** | 分开：中心=双反转；合并：中心=组合反转 |
| Q2↔Q3 中心 | 镜像 | **相同** | 同 Q1↔Q4 |
| Q2↔Q4 上下 | 镜像 | 镜像 | 两种布局上下都是元素方向 |
| Q3↔Q4 左右 | **相同** | 镜像 | 同 Q1↔Q2 |

**关键洞察**：
- 横向分开：左右方向是纯组合方向（无重叠），所以 Q1↔Q2、Q3↔Q4 是"相同"对称
- 横向合并：左右方向 = 组合 + 元素（重叠），字符串反转 = 双反转，导致 Q1↔Q2、Q3↔Q4 变成"镜像"，而 Q1↔Q4、Q2↔Q3 变成"相同"
- 两种布局的"上下"对称都是镜像（因为上下方向都是元素方向，不发生重叠）

### 8.5 同时修复的 WPS VBA 兼容问题

- **重复 Dim**：v11 原版 `Dim 列 As Long` 重复声明，WPS VBA 严格模式触发编译错误
- **Dim 位置**：所有 `Dim` 必须在过程顶部，不能在循环或条件块内

## 九、调试过程与逻辑思路

### 9.1 问题排查流程（多轮迭代）

整个 v11.6 修复历经三轮迭代，每轮都由用户反馈+code_mode 验证驱动：

**第一轮：横向布局公式不分模式**
1. 用户反馈：反横合并错误、反横分开正确
2. code_mode 模拟 2×3 数据，发现横向布局下"合并"和"分开"视觉方向不同
3. 初步修复：仅横向分开互换 Q2/Q3 公式，其他用竖向公式

**第二轮：验证函数公式用错**
1. 自测发现反竖也"假阴性"，排查后发现是验证函数用了错的横向公式
2. 按布局选择验证公式后，8 个四象限 4 种对称性全通过
3. 但用户反馈"四象限_正横_合并_18 还是有问题"

**第三轮：发现方向重叠本质**
1. 仔细检查横向合并实际输出：Q1[0]=a1-b1-c1，Q2[0]=c1-b1-a1（局部对称）
2. 但区域视觉对称要求 Q1[0]↔Q2[23]：Q1[0]=a1-b1-c1 的镜像 = c1-b1-a1，而 Q2[23]=c4-b3-a2 不等
3. 代数分析发现：横向合并下左右方向 = 列方向 + 字符串内元素方向（重叠）
4. 推导出 Q2=RE（双反转），Q4=R（组合反转），与竖向/横向分开都不同
5. 最终修复：三种布局用三套独立公式

### 9.2 关键调试手段

用 Exec 沙箱独立验证公式，不依赖 WPS 环境：

```javascript
// 构造 2x3x4 数据
var 源数据 = [['a1','b1','c1'],['a2','b2','c2'],['','b3','c3'],['','','c4']];
// 生成 Q1，按公式生成 Q2/Q3/Q4，逐一验证对称性
```

每次公式修改后都重新运行验证，最终 8 个四象限 × 6 种区域视觉对称性 = 48 个检查点全部通过。

### 9.3 视觉对称的本质

**视觉对称 = 字符串反转**（含连字符位置对称）：

- `2-5-9` ↔ `9-5-2`（字符串反转，视觉对称）
- `1-3-6` ↔ `6-3-1`（字符串反转，视觉对称）

横向合并下，每个象限是 1 行字符串，所以左右镜像/上下镜像都是字符串反转。但字符串反转同时包含组合反转和元素反转（双反转），所以 Q2=双反转，Q4 只能是组合反转（保持中心对称）。

这个直观概念比 R/E/RE 代数分析更简洁，也更容易验证：只需检查字符串反转关系即可。

### 9.4 设计原则总结

**镜像公式取决于最终输出布局的视觉方向**，不是数据存储方向：
- 数据按列存 `Q[c][r]` 是固定的
- 但"左右"和"上下"在最终输出表中的含义会随布局变化
- 必须按"输出布局"而非"数据结构"来定义镜像公式
- 当左右方向同时包含列和元素方向（横向合并）时，会产生方向重叠，需要特殊处理

### 9.5 经验教训

1. **局部对称 ≠ 区域对称**：每个位置局部对称不一定保证整个区域视觉对称
2. **验证函数也会用错公式**：调试时验证函数本身可能有 bug，需要根据布局选择验证公式
3. **视觉对称 = 字符串反转**：用字符串反转概念验证比 R/E/RE 代数分析更直观简洁
4. **小数据测边界**：2×3×4=24 组合足够暴露所有对称性问题，又不会太多导致看不清规律
