# 四方镜子 - v8 版本说明：新旧算法对比

> v8 在 v6 基础上**新增备选算法验证功能**，现有功能完全不变。本文档重点对比 v8 内置的新旧核心算法差异。

---

## 一、v8 新增了什么

| 对比项 | v6 | v8 |
|--------|-----|-----|
| 现有 6 个按钮（四方4+双边2） | ✅ | ✅ **不变** |
| 四方循环 `scct` / 双边循环 `zxgbs` | ✅ | ✅ **不变** |
| 窗体 570×520 / 按钮预览 / 命名规则 | ✅ | ✅ **不变** |
| 备选算法验证按钮 | ❌ 无 | ✅ **新增**（按钮7，蓝色） |
| 备选算法 | ❌ 无 | ✅ **新增 7 种** |

**核心原则**：v8 = v6（原样）+ 备选算法验证（新增）。现有功能零改动。

## 二、新旧算法总览

### 2.1 算法全景

| 类别 | 算法 | 行数公式 | 本质 | v8 入口 |
|------|------|---------|------|---------|
| 原有 | 四方循环 `scct` | 各列行数**乘积** | 笛卡尔积（全组合） | 按钮1~4 |
| 原有 | 双边循环 `zxgbs` | 各列行数**LCM** | 每列独立循环 | 按钮5~6 |
| **新增A** | 进位计数法（Odometer） | 各列行数**乘积** | 笛卡尔积（混合进制实现） | 按钮7→A |
| **新增B** | 回溯法（DFS递归） | 各列行数**乘积** | 笛卡尔积（递归实现） | 按钮7→B |
| **新增C** | 自定义周期独立循环 | 各周期**LCM** | 双边循环推广（任意周期） | 按钮7→C |
| **新增D** | 随机抽样组合 | 指定 N 行 | 随机生成 | 按钮7→D |
| **新增E** | 逐列扩展法（Array Expansion） | 各列行数**乘积** | 笛卡尔积（数组复制扩展） | 按钮7→E |
| **新增F** | 格雷码遍历（Gray Code） | 各列行数**乘积** | 笛卡尔积（相邻仅一列变化） | 按钮7→F |
| **新增G** | 混合进制随机访问 | 1 行（指定序号） | 笛卡尔积（直接取第k个） | 按钮7→G |

## 三、新旧算法差异详解

### 3.1 算法A 进位计数法 vs 四方循环 `scct`

**相同点**：
- 输出结果**完全相同**（都是笛卡尔积正向：A1B1, A2B1, A1B2...）
- 行数相同（各列行数乘积）

**差异点**：

| 维度 | scct | 算法A 进位计数 |
|------|------|---------------|
| 实现思路 | **按行定位**：先算每列步长，再用 `ys(cd(行,步长),列数)` 直接算出每行的源行号 | **逐行递推**：每列一个计数器，末位+1满则进位（像计程表） |
| 依赖步长 | 需要预计算 `fwdSteps`/`revSteps` | 完全不需要 |
| 支持正/反向 | 正反向都支持（步长不同） | 天然只产生"正向"顺序 |
| 代码直观度 | 公式化，需理解步长 | 循环+进位，直观易懂 |
| 扩展性 | 支持任意列数 | 同样支持任意列数 |

**本质关系**：算法A 是笛卡尔积的"计数器视角"实现，与 scct 的"步长定位"视角殊途同归。

---

### 3.2 算法B 回溯法 vs 四方循环 `scct`

**相同点**：
- 输出结果**完全相同**（笛卡尔积正向）
- 行数相同

**差异点**：

| 维度 | scct | 算法B 回溯法 |
|------|------|-------------|
| 实现思路 | 步长定位（迭代） | **递归 DFS**：逐列选择，选满输出，回溯 |
| 代码结构 | 双层循环 + 公式 | 递归函数（深度=列数） |
| 加筛选条件 | 难（需改公式） | **容易**（叶子处加 `If 条件 Then`） |
| 性能 | 快（纯循环） | 中（递归有调用开销） |
| 可读性 | 数学公式化 | 贴近"组合的数学定义" |

**典型扩展**（回溯法独有优势）：
```vba
If 当前列 > 总列数 Then
    If 临时行(1) <> 临时行(2) Then   ' 只要两列值不同的组合
        输出当前行
    End If
    Exit Sub
End If
```

---

### 3.3 算法C 自定义周期循环 vs 双边循环 `zxgbs`

**相同点**：
- 都是"每列独立循环"，行数 = LCM
- 输出顺序风格一致（对角线式）

**差异点**：

| 维度 | zxgbs | 算法C 自定义周期 |
|------|-------|-----------------|
| 每列周期 | 固定 = 该列行数 | **可任意指定**（如 A列2、B列3） |
| 周期与列长关系 | 必须相等 | 可不等（数据循环复用） |
| 灵活性 | 低 | 高（zxgbs 是周期=列长的特例） |
| 典型场景 | 标准周期对齐 | 自定义节奏（2-3-4 错开循环） |

**验证**：当周期 = 各列行数时，算法C 输出与 zxgbs **完全一致**（算法C 是 zxgbs 的超集）。

---

### 3.4 算法D 随机抽样 vs 其他所有算法

**核心差异**：

| 维度 | scct/zxgbs/A/B/C | 算法D 随机抽样 |
|------|------------------|---------------|
| 生成方式 | 确定性（每次结果相同） | **随机**（每次结果不同） |
| 覆盖范围 | 全部/部分组合 | 随机子集 |
| 行数控制 | 由列数决定 | **用户指定 N 行** |
| 可重复 | 固定序列 | 可重复模式（同一组合可多次出现） |
| 适用场景 | 全量组合、周期对齐 | 随机测试、抽样 |

**独特价值**：前 5 种算法都无法生成随机组合，算法D 填补了这个空白。

---

### 3.5 算法E 逐列扩展法 vs 四方循环 `scct`

**相同点**：
- 输出结果**完全相同**（笛卡尔积正向）
- 行数相同（各列行数乘积）

**差异点**：

| 维度 | scct | 算法E 逐列扩展 |
|------|------|---------------|
| 实现思路 | 步长定位，一次性算出所有行 | **逐步构建**：从第1列开始，每加一列就把已有结果复制 n 份并追加新列元素 |
| 内存模式 | 一次性分配完整结果数组 | 数组逐列膨胀（中间结果越来越大） |
| 直观性 | 数学公式，需理解步长概念 | **非常直观**：就像"先列A的所有元素，再每个都搭配B的每个元素..." |
| 扩展列 | 列数一开始就要确定 | 天然支持"动态加列"（流式扩展） |
| 性能 | 快（纯索引计算） | 中（大量数组复制） |

**核心思想**：第 k 列加入时，已有 `M` 行结果 → 复制 `每列行数(k)` 份，第 i 份的第 k 列 = 源数据第 i 行。

---

### 3.6 算法F 格雷码遍历 vs 四方循环 `scct`

**相同点**：
- 都生成**全部**笛卡尔积组合（行数=乘积）
- 都覆盖所有组合不重复、不遗漏

**核心差异——相邻组合的变化量**：

| 维度 | scct 正向 | 算法F 格雷码 |
|------|-----------|-------------|
| 相邻变化 | 可能变**多列**（如 A2B3 → A1B1，两列都变） | **只变一列**（每次只有某一列前进/后退一格） |
| 顺序 | 字典序（左列慢、右列快） | 反射格雷码序（递归反射构造） |
| 典型用途 | 常规枚举、输出展示 | **相邻用例测试**（每次只改一个参数，定位问题更快） |
| 实现难度 | 简单 | 中（递归反射，方向交替） |

**直观理解**：格雷码遍历就像在组合空间里"走迷宫"，每次只挪一步（一列变化），走遍所有房间不重复。

**2×3 示例对比**：
- scct：A1B1 → A2B1 → A1B2 → A2B2 → A1B3 → A2B3（第2→3步两列都变）
- 格雷码：A1B1 → A2B1 → A2B2 → A1B2 → A1B3 → A2B3（每步只变一列）

---

### 3.7 算法G 混合进制随机访问 vs 其他所有算法

**核心独特性**：算法G 不是"生成序列"，而是**给定序号直接算出第 k 个组合**。

| 维度 | 其他算法（A/B/E/F等） | 算法G 随机访问 |
|------|----------------------|---------------|
| 输入 | 列数据 | 列数据 + **序号 k** |
| 输出 | 全部 N 行 | **只 1 行**（第 k 个组合） |
| 时间 | O(N) 生成全部 | O(列数)，与总行数无关 |
| 用途 | 全量枚举 | **断点续算、并行分区、随机抽检** |
| 依赖 | 需要按顺序生成 | 完全独立，不需要先生成前面的 |

**数学原理**：把组合序号 k-1 看作一个混合进制数，每列的"进制" = 该列行数，通过取模和整除逐位解码。

```
第k个组合的第i列元素 = 源数据[ ((k-1) / 权重_i) mod 每列行数_i + 1 ][i]
其中 权重_i = 前 i-1 列行数的乘积
```

**典型应用场景**：
- 数据量太大无法一次生成 → 多线程/多进程分区计算（每个 worker 算自己负责的序号段）
- 只想看第 10000 个组合 → 直接算，不用先生成前 9999 个
- 断点续跑 → 记录上次跑到第几个，下次从那个序号继续

## 五、新旧算法差异总表

| 维度 | scct | zxgbs | A 进位 | B 回溯 | C 周期 | D 随机 | E 逐列扩展 | F 格雷码 | G 随机访问 |
|------|------|-------|--------|--------|--------|--------|-----------|---------|-----------|
| 行数 | 乘积 | LCM(列长) | 乘积 | 乘积 | LCM(周期) | N | 乘积 | 乘积 | 1 |
| 覆盖 | 全 | 部分 | 全 | 全 | 部分 | 随机子集 | 全 | 全 | 单点 |
| 顺序 | 正/反向 | 对角线 | 正向 | 正向 | 自定义 | 随机 | 正向 | 格雷码 | 任意 |
| 实现 | 步长定位 | 独立取模 | 递增进位 | 递归 | 独立取模 | 随机索引 | 数组复制 | 递归反射 | 混合进制解码 |
| 确定性 | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ 随机 | ✅ | ✅ | ✅ |
| 加筛选 | 难 | 难 | 难 | **易** | 难 | 可去重 | 难 | 难 | — |
| 性能 | 快 | 快 | 快 | 中 | 快 | 快 | 中 | 中 | **极快** |

**关键差异总结**：
- **A/B/E 与 scct**：输出相同，仅实现方式不同（验证"殊途同归"——笛卡尔积至少有 4 种实现路径）
- **C 与 zxgbs**：C 更通用（任意周期），zxgbs 是特例
- **D 与其他**：唯一支持随机的算法
- **F 独有特性**：相邻组合只变一列（格雷码性质），适合参数调试
- **G 独有特性**：O(1) 随机访问第 k 个组合，是并行计算/断点续算的基础

## 六、验证方法（在 v8 中实际操作）

### 6.1 验证 A/B = scct 正向

1. 活动工作表放 2×3 数据（A1,A2 / B1,B2,B3）
2. 点"备选算法验证"→ 选 **A**，生成 `备选A_进位计数`
3. 再点按钮3（正向竖向）生成 `四方_正竖_合并`
4. **两张表内容应完全一致** → 证明算法A 正确实现了笛卡尔积

同理可验证 B。

### 6.2 验证 C = zxgbs（周期=列长时）

1. 数据用 2×4（A1,A2 / B1..B4）
2. 算法C 周期默认 2,3 → LCM=6，输出 6 行
3. 与 zxgbs 的 LCM(2,4)=4 对比 → 可见"周期可自定义"的差异

### 6.3 验证 D 随机性

连续运行算法D 两次，结果通常不同 → 体现随机性。

### 6.4 验证 E = scct 正向（逐列扩展）

1. 同样用 2×3 数据
2. 选 **E** 生成 `备选E_逐列扩展`
3. 与 scct 正向结果对比 → 应完全一致
4. **直观理解**：E 是"一层一层搭出来的"，先有 A 列 2 行，再加 B 列时复制 3 份，最终 6 行

### 6.5 验证 F 格雷码特性（相邻只变一列）

1. 用 2×3 数据生成 `备选F_格雷码`
2. 逐行对比相邻两行 → 每次只有**某一列**的值不同
3. 这就是格雷码的核心性质："汉明距离 = 1"

### 6.6 验证 G 随机访问正确性

1. 用 2×3 数据（乘积=6）
2. 选 **G**，输入 `4` → 得到第 4 个组合 = A2-B2
3. 与 scct 正向输出的第 4 行对比 → 应完全一致
4. 再试 `k=6` → 应为 A2-B3（最后一个组合）

## 八、结论

- **现有算法不变**：v8 完全兼容 v6 的所有行为，可放心升级
- **备选算法是"验证+补充"**：
  - A/B/E 证明笛卡尔积有多种实现（步长 / 进位 / 递归 / 数组扩展，殊途同归）
  - C 扩展了双边循环（任意周期）
  - D 补充了随机能力（含不重复洗牌算法）
  - F 提供格雷码顺序（相邻只变一列，适合调试）
  - G 提供随机访问能力（并行计算基础）
- **选用建议**：
  - 日常用现有 6 按钮
  - 需要随机数据用 D
  - 需要带筛选条件的组合用 B
  - 需要自定义循环节奏用 C
  - 需要相邻用例测试（每次只改一个参数）用 F
  - 需要大数据量分区计算/断点续跑，底层原理参考 G
