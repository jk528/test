## 二、彩读 ColorTxt 核心实现深度分析

### 2.1 阅读尺算法（readingRuler.ts）—— 视觉行级精度

彩读的阅读尺远超"高亮当前行"的简单实现，达到**视觉行（wrapped line）级精度**。核心算法：

#### （1）视觉行起止列计算 —— 二分查找

```typescript
// 用二分查找确定某个视觉行的起始列
// 原理：同一物理行内，各视觉行的 top 值不同（因 wordWrap 折行）
// 二分查找最小列号，使得 getTopForPosition(line, col) 与目标 top 相等
function visualRowStart(ed, line, column): ReadingRulerPos {
  const top = ed.getTopForPosition(line, column);
  let lo = 1, hi = Math.max(1, column), best = column;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    const t = ed.getTopForPosition(line, mid);
    if (Number.isFinite(t) && Math.abs(t - top) <= TOP_EPS) {
      best = mid; hi = mid - 1;  // 继续向左找更左的同 top 列
    } else {
      lo = mid + 1;
    }
  }
  return { lineNumber: line, column: Math.max(1, best) };
}
```

**优化价值**：当前项目阅读尺基于 `cursorPosition.lineNumber`（物理行），开启 wordWrap 后：
- 一个长段落折成 5 个视觉行，但阅读尺只高亮整段（5 行全亮），失去聚焦效果
- 无法按"视觉行"逐行阅读，ADHD 聚焦体验打折

#### （2）聚焦带（Focus Band）—— 多行聚焦

彩读阅读尺是**N 行聚焦带**（可配置行数，默认 3-5 行），而非单行。算法：
- 以锚点行为中心，向上取 `floor((n-1)/2)` 行，向下取 `ceil((n-1)/2)` 行
- 空行不计入（跳过空白视觉行）
- 文首/文末不够时"先下后上"补齐

```typescript
function collectVisualRowsFromAnchor(ed, model, anchor, count): ReadingRulerPos[] {
  const wantBelow = Math.ceil((n - 1) / 2);
  const wantAbove = Math.floor((n - 1) / 2);
  const below = collectContentInDirection(ed, model, mid, 1, wantBelow);
  const above = collectContentInDirection(ed, model, mid, -1, wantAbove);
  // 一侧不够时补另一侧
  let remaining = n - 1 - below.length - above.length;
  if (remaining > 0) {
    const moreBelow = collectContentInDirection(ed, model, below.at(-1) ?? mid, 1, remaining);
    below.push(...moreBelow);
  }
  return [...above.reverse(), mid, ...below];
}
```

#### （3）非聚焦行淡化（Dim Effect）

彩读用 CSS 变量 `--reader-ruler-dim` 控制非聚焦行的透明度，实现"聚光灯"效果。这比单纯高亮当前行更符合阅读辅助设计。

### 2.2 视口锚点系统（readerViewportAnchor.ts）—— 精确恢复

彩读的视口恢复精度达到**物理行 + 折行内行索引**二级：

```typescript
type ReaderViewportRestoreAnchor = {
  physicalLine: number;       // 物理行号（1-based）
  wrappedLineIndex: number;   // 该物理行内的第几条视觉行（0-based）
};
```

**关键算法**：

#### （1）采锚：二分查找命中行

```typescript
// 用二分查找确定 contentY 处命中哪条模型行
// editor.getTopForLineNumber() 单调递增 → 可二分
function findModelLineAtContentY(editor, model, contentY): number | null {
  let lo = 1, hi = lc, ans = 1;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    const top = editor.getTopForLineNumber(mid);
    if (top <= contentY) { ans = mid; lo = mid + 1; }
    else { hi = mid - 1; }
  }
  return ans;
}
```

**优化价值**：当前 `chapterAtLine` 用线性扫描 `for (const ch of chapters)`，120 章影响可忽略。但如果将来做**按行号查章节**的高频调用（如滚动时每帧调用），应改为二分查找。

#### （2）锚点槽位（Anchor Slot）

视口恢复不是"把行跳到视口顶部"，而是"跳到视口第 N 条字高带"：
- 普通恢复：第 2 条（`READER_VIEWPORT_RESTORE_SLOT_FROM_TOP = 2`）
- 章节跳转：按 headingLevel 决定（`chapterJumpAnchorSlotFromTop`）
- 书签跳转：固定第 2 条

这样黏性章节条不会盖住目标行。

### 2.3 物理行 / 展示行双坐标系（lineMapping.ts）

这是彩读**最核心的架构决策**，也是当前项目最大的架构缺口。

#### 原理

```
磁盘原文（物理行）
    ↓ formatPhysicalLinesForReader
    ① 应用替换规则（替换规则作用域：正文/标题）
    ② 应用简繁转换 / 全半角转换
    ③ 空行压缩（keepOneBlank 等）
    ↓
展示行（Monaco 显示内容）
    ← 双向映射表 →
displayLineToPhysicalLine[]  // displayLine → physicalLine
physicalLineToDisplayLine[]  // physicalLine → displayLine（第一个）
physicalLineToLastDisplayLine[]  // physicalLine → displayLine（最后一个）
```

**关键约束**：一切持久化数据（书签、高亮、笔记、阅读进度、分析锚点）锚定在**物理行**，展示层怎么变都不会让标注错位。

#### 映射查询优化

```typescript
// 物理行 → 展示行（线性扫描，O(n)）
// 注：彩读此处用线性扫描，因为映射数组通常不超过几万行，
// 且实际调用频率不高（滚动时用视口行号，不查映射表）
function physicalLineToFilteredDisplayLine(physicalP, map): number {
  for (let i = 0; i < map.length; i++) {
    if (map[i]! >= p) return i + 1;
  }
  return map.length;
}
```

**可优化点**：映射数组是单调递增的（展示行号递增 → 物理行号非递减），可用**二分查找**替代线性扫描，从 O(n) → O(log n)。

### 2.5 粘性章节条（chapterStickyScroll.ts）—— DocumentSymbolProvider

彩读不用手动实现粘性标题条，而是利用 Monaco 内置的 **stickyScroll + DocumentSymbolProvider**：

1. 注册 `registerDocumentSymbolProvider`，把章节列表转换成 `DocumentSymbol[]`（树形结构）
2. 开启 `stickyScroll: { enabled: true }`
3. Monaco 自动管理粘性条的渲染、层级、滚动同步

**优势**：
- 多级章节（卷 → 章 → 节）自动堆叠显示
- Monaco 内部优化了滚动性能（GPU 合成层）
- 少写几百行 DOM 操作代码

当前项目的 `sticky-title` 是手动实现的单级条，可升级为多级。

### 2.6 流式加载（txtStreamPipeline）—— 大文件处理

彩读对超大文件（>10MB）采用**流式管线**：
- `useTxtStreamPipeline` 逐批读取物理行，边读边解析
- 避免一次性 `split('\n')` 产生大数组内存峰值
- 进度回调 + 可取消

当前项目《红楼梦》仅 2.57 MB，影响不大。但如果目标是"支持任意小说"，流式是必需的。

## 三、算法优化建议（按 ROI 排序）

### ⭐⭐⭐ 高价值（立竿见影）

#### OPT-1：装饰渲染视口化（Viewport-based Decoration Rendering）

**现状问题**：`Reader.vue` 的 `renderDecorations()` 每次都生成**全部**装饰（章节 120 + 书签 N + 情感 3366 行 + 人物出场 30027 + 查找匹配 + 段间距/缩进），一次性全部 `decoColl.set(decos)`。

**性能影响**：
- 30027 条人物出场装饰 → Monaco 内部创建 30027 个 DOM 节点 → 内存占用高 + 首次渲染慢
- 每次滚动/设置变化都重建全部装饰 → 卡顿
- 情感着色 3366 行 + 段间距 3366 行 → 叠加后装饰数爆炸

**优化方案**：参考彩读的视口驱动思路，仅渲染**可见视口 ± 缓冲行**范围内的装饰：

```typescript
// 伪代码：视口装饰渲染
function renderViewportDecorations() {
  const visible = editor.getVisibleRanges()[0];
  if (!visible) return;
  
  const viewTop = visible.startLineNumber - 1;
  const viewBottom = visible.endLineNumber - 1;
  const BUFFER = 50;  // 上下各缓冲 50 行，避免滚动时空白
  const renderTop = Math.max(0, viewTop - BUFFER);
  const renderBottom = Math.min(totalLines - 1, viewBottom + BUFFER);
  
  const decos = [];
  
  // 只添加落在 [renderTop, renderBottom] 范围内的装饰
  for (const ch of chapters) {
    if (ch.line >= renderTop && ch.line <= renderBottom) {
      decos.push(/* 章节标题装饰 */);
    }
  }
  // 情感、人物、书签同理...
  
  decoColl.set(decos);
}

// 滚动时通过 rAF 节流更新
editor.onDidScrollChange(() => {
  if (scrollRaf) return;
  scrollRaf = requestAnimationFrame(() => {
    scrollRaf = 0;
    renderViewportDecorations();
  });
});
```

**预期收益**：
- 人物出场装饰从 30027 → 约 200（视口 + 缓冲）→ **99%+ 减少**
- 情感装饰从 3366 → 约 100 → **97% 减少**
- 滚动帧率显著提升（尤其在低端机上）

**注意事项**：
- `overviewRuler`（右侧概览栏）的标记需要全量，不能视口化 → 分两个 decoration collection
- 书签/章节标题数量少（< 200），可保留全量，不值得视口化
- 段间距/缩进如果用 CSS `text-indent` + 伪元素实现，可完全绕过 decoration

#### OPT-3：阅读尺升级为视觉行级 + 聚焦带

**现状问题**：当前阅读尺基于物理行，wordWrap 开启时长段落一整段都高亮，失去"聚焦一行"的效果。

**优化方案**：参考彩读 `readingRuler.ts` 的二分查找算法：

```typescript
// 关键函数：用二分查找确定视觉行起始列
function visualRowStart(ed: monaco.editor.IStandaloneCodeEditor, 
                        line: number, column: number) {
  const top = ed.getTopForPosition(line, column);
  if (!Number.isFinite(top)) return { lineNumber: line, column: 1 };
  
  let lo = 1, hi = Math.max(1, column), best = column;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    const t = ed.getTopForPosition(line, mid);
    if (Number.isFinite(t) && Math.abs(t - top) <= 0.5) {
      best = mid; hi = mid - 1;
    } else {
      lo = mid + 1;
    }
  }
  return { lineNumber: line, column: Math.max(1, best) };
}
```

**额外特性**：
- 聚焦带（3-5 行）替代单行高亮
- 空行跳过（只在有内容的视觉行间移动）
- 非聚焦行淡化（CSS `opacity`）

**预期收益**：阅读体验从"能用"提升到"专业"，尤其适合长段落小说阅读。

### ⭐⭐ 中价值（体验提升）

#### OPT-4：章节查找二分优化

**现状**：`chapterAtLine` 线性扫描 O(n)。

```typescript
// 当前实现
export function chapterAtLine(chapters: Chapter[], line: number): number {
  let result = 0;
  for (const ch of chapters) {
    if (ch.line <= line) result = ch.index;
    else break;
  }
  return result;
}
```

**优化**：二分查找 O(log n)。

```typescript
export function chapterAtLine(chapters: Chapter[], line: number): number {
  let lo = 0, hi = chapters.length - 1, ans = 0;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    if (chapters[mid].line <= line) {
      ans = chapters[mid].index;
      lo = mid + 1;
    } else {
      hi = mid - 1;
    }
  }
  return ans;
}
```

**收益**：120 章时从 120 次比较 → 7 次。虽然绝对影响小，但这是高频调用（滚动时每帧调用 `updateSticky`），积少成多。

#### OPT-5：查找功能增量优化 + 利用 Monaco 内置 Find

**现状问题**：`doFind` 每次都全文扫描 + 全部转小写 + 生成所有匹配 decoration。

**优化方案**：
1. **利用 Monaco 内置的 find 控制器**：`editor.getAction('actions.find').run()`，Monaco 自带查找栏、高亮、导航、正则、大小写切换等完整功能。
2. 如果需要自定义 UI：用 `editor.getModel().findMatches()` 替代手动循环，Monaco 内部已做了优化。

```typescript
// 方案 A：直接用 Monaco 内置查找
editor.trigger('keyboard', 'actions.find', null);

// 方案 B：用 model.findMatches 替代手动循环
const matches = model.findMatches(
  query,           // 搜索字符串
  true,            // 仅搜索选中区
  !matchCase,      // 是否不区分大小写
  false,           // 是否正则
  null,            // 整体匹配词
  false            // 捕获组
);
```

**预期收益**：查找性能提升（Monaco 内部用 Boyer-Moore 等优化算法），功能更完整（正则、整词匹配）。

#### OPT-6：粘性章节条升级为 Monaco StickyScroll

**现状**：手动实现的单级 `sticky-title` div。

**优化**：用 Monaco 内置的 `stickyScroll` + `DocumentSymbolProvider`（彩读做法）：

```typescript
// 1. 注册文档符号提供者
monaco.languages.registerDocumentSymbolProvider('plaintext', {
  provideDocumentSymbols(model) {
    // 返回章节树形结构
    return chapters.map(ch => ({
      name: ch.title,
      kind: monaco.languages.SymbolKind.Namespace,
      range: new monaco.Range(ch.line + 1, 1, ch.endLine + 1, 1),
      selectionRange: new monaco.Range(ch.line + 1, 1, ch.line + 1, 1),
      children: [],  // 子章节
    }));
  }
});

// 2. 开启粘性滚动
editor.updateOptions({
  stickyScroll: { enabled: true, maxLineCount: 3 }
});
```

**预期收益**：
- 自动支持多级章节（卷 → 章 → 节）堆叠
- Monaco 内部优化，滚动更流畅
- 代码量减少（无需自己监听滚动、计算位置）

#### OPT-7：物理行 / 展示行双坐标系

**现状问题**：当前 Monaco 行 ≡ 物理行 1:1，一旦实现简繁转换/空行压缩/替换规则，书签、情感锚点、人物出场等全部错位。

**优化方案**：实现双坐标系 + 双向映射表。

#### OPT-8：大文件流式加载

《红楼梦》仅 2.57 MB，一次性加载没问题。但如果目标是"支持任意长文本（>10MB）"，需要实现流式加载。

彩读的做法：`useTxtStreamPipeline` → 逐批读取 → 增量更新 model → 分批解析章节。

#### OPT-9：RAG 分块优化

当前分块是按行 + 空行边界。彩读的做法是**按章节分块**，且有更智能的分块策略：
- 不切断句子/段落（语义完整）
- 分块重叠（overlap）避免边界信息丢失
- 标题前缀注入（每个 chunk 前面加上所属章节标题，增强召回相关性）

```python
# 当前分块（按行 + 空行）
def chunk_text(text, chunk_lines=20, ...):
    # 遇到空行就分块
    # 固定 chunk_lines 上限
    pass

# 优化方向
def chunk_text_semantic(text, chapter_title, chunk_chars=500, overlap=50):
    """按字符数 + 句子边界 + 重叠 + 标题前缀"""
    chunks = []
    # 1. 按句子切分
    # 2. 组装成不超过 chunk_chars 的块
    # 3. 块之间重叠 overlap 字符
    # 4. 每个块前加上章节标题作为前缀
    for chunk in chunks:
        chunk.text = f"[{chapter_title}]\n{chunk.text}"
    return chunks
```

**预期收益**：召回准确率提升，尤其对"跨段落的问题"。
