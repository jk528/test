**关键技术决策（打包相关，后续沿用）**
- **onedir 而非 onefile**：onefile 每次启动都要解压几十 MB，首启明显卡顿。
- **不启用 UPX**：拖慢启动且易被杀软误报。
- **Tauri `externalBin` 命名坑**：配置里写不带后缀的名字，实际文件必须带目标三元组后缀 `-x86_64-pc-windows-msvc.exe`，否则构建直接报错。
- **WebView2 用 `downloadBootstrapper`**：切勿用 `embedBootstrapper` / `offlineInstaller`，否则安装包被塞进 100+ MB 运行时。
- **前端 `base: './'`**：WebView2 以 file:// 载入时资源路径必须相对。
- **jieba 瘦身不可逆的代价**：删 `analyse/` 后不得再调 `extract_tags` / `textrank`。

**环境坑（重要）**：PowerShell 的 `Add-Type` 与 `New-Object -ComObject` **均被安全策略拦截**（提示分别为 "Add-Type compiles and loads .NET code at runtime"、"COM object instantiation can run arbitrary code"），因此 `Microsoft.VisualBasic.FileIO.FileSystem::DeleteFile` 和 `Shell.Application.Namespace(0xA)` 两条常规路都走不通。
- **可用方案**：纯标准库 `ctypes.windll.shell32.SHFileOperationW` —— `FO_DELETE=3`，`fFlags = FOF_ALLOWUNDO|FOF_NOCONFIRMATION|FOF_SILENT|FOF_NOERRORUI`，`pFrom` 用 `\0` 连接多个路径并以 `\0\0` 结尾，结构体字段 `fFlags` 用 `wintypes.WORD`。
- **注意**：返回值不可靠 —— 本次返回 `2`（本应视为失败）但操作实际成功。**必须用 `os.path.exists` 做逐项校验，不能只信返回值。**
- 核对回收站可解析 `C:\$Recycle.Bin\<SID>\$I*` 二进制元数据（头 8B 版本 + 8B 大小 + 8B FILETIME + 4B 文件名长度 + UTF-16LE 原路径）。
