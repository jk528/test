# MEMORY.md — 《红楼梦》文本分析工程长期约定

> 跨会话有效。每次涉及文档/文件改动前先读本节。

## 一、文档与磁盘必须同口径
- **凡文档里写了数量的地方，一律以文件系统实测为准**，不许沿用旧值。改完文件系统（删/增文件）后，**必须回扫全工程并把相关文档里的数量同步**。
- 已踩过的坑：把字节数当词条数（同义词「91 万」实为 910,438 字节，真值 17,817 词群 / 107,934 词条）；删冗余后 267→266 份 MD、「80+1」→80、工程 27.88→24.58 MB。
- 同步后要**回读验证**，并做算术自洽检查（如资产表各行合计 ≈ 声明总数）。

## 二、编辑落盘必须验盘
- 本项目的 Edit 工具**偶发「报 success 却没写入」**。
- 对策：编辑后**逐条回读 + 关键词 count 断言**（新值 >0、旧值 ==0）；大区块用一次性整段替换；重要文件编辑后重算围栏配对与 TOC 锚点。

## 三、删除文件的安全规程
- 一律**送回收站**（`ctypes.windll.shell32.SHFileOperationW`，`FO_DELETE=3`，flags 含 `FOF_ALLOWUNDO`），**绝不永久删除**；返回码不可信，必须 `os.path.exists` 逐项复核。
- **删重复文件前先 MD5 校验**两份一致（如 `_归档索引_V3.3.md` 两副本 `c5403520…`）。
- **空目录可能是规范承诺的输出位置**（如 `分析结果/CSV导出/`），删前必须先 grep 规范文档，不能只按「空 = 垃圾」判定。
- 删除后回扫全工程，把**悬空引用**一并修正；数据来源处的引用不整行删，改写为「已退役 / 内容并入 X」以保留 provenance。

## 四、本机工具链
- **Bash 工具不稳定**（`ls`/`dirname`/`head` 常 command not found，管道会失败）。可用替代：
  - 跑脚本：`C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe -c "..."`（绝对路径，always OK）
  - 目录枚举：PowerShell 工具
- **PowerShell 的 `Add-Type` 与 `New-Object -ComObject` 被安全策略拦截** → 回收站/COM 相关操作改用 Python ctypes。

## 五、设计方案载体与关键决策
- 设计方案有**两份载体，分工明确**：
  - `红楼梦文本分析软件设计方案_V2.0.md` —— **析域施工底本**（S0–S9 步骤、八大模块、打包方案）。
  - `红楼梦阅读分析一体化_设计方案_V1.0.md` —— **架构决策记录（ADR）**，参照 ColorTxt 回答「阅读与分析如何共用一套架构」。含：统一锚点模型、混合检索、Tauri+Python stdio JSON-RPC、模块融合表、路线图。
  - 二者不互相取代：V2.0 仍有效，一体化方案在其上做架构修订（通信 HTTP→stdio、存储 文件→SQLite+导出、补读域 R1–R4）。
- **统一锚点模型是本项目跨模块的硬约定**：一切位置统一为 `(bookId, chapterIndex, lineStart, lineEnd, charStart?, charEnd?)`；**物理行号是唯一权威，任何替换/简繁等加工只作用于展示层，不得改变物理行号**。
- 分词锁定 **jieba**；情感分析用项目内置双引擎（`基础/emotion_analysis.py`），**不用 cnsenti**；120 章历史产物口径已锁定，词库扩展只做并集不覆盖。
- 打包：**onedir + 不启用 UPX + Tauri 壳**；Tauri `externalBin` 实际文件名必须带目标三元组后缀；WebView2 用 `downloadBootstrapper`。
