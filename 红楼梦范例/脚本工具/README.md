# 红楼梦章节分析脚本工具使用说明

## 概述

本文件夹包含《红楼梦》双轨六要素分析体系的全部自动化脚本，用于章节分析报告的生成、验证、升级和维护。

**当前版本**：V3.2 / 流程v1.8
**分析框架**：新闻六要素（A轨）+ 叙事六要素（B轨）+ 七类情绪分析（DUTIR+Hownet双轨）+ 冲突动机/叙事手法/情感趋势

## 核心脚本说明

### 一、分析生成类

#### 1. generate_ch01_v32_v3.py
**功能**：按V3.2模板完整生成第1章分析报告（测试用）
- 输入：第1章原文 + 分词数据 + 基础词典
- 输出：`分析结果/001_甄士隐梦幻识通灵_双轨六要素分析报告.md`
- 特点：以V3.2存档为基准，更新字数、分词数等动态字段
- 用法：`python generate_ch01_v32_v3.py`

#### 2. batch_emotion_1_18.py
**功能**：批量分析1-18章的七类情绪（DUTIR+Hownet双轨）
- 输入：各章分词数据 + DUTIR情绪词典 + Hownet情感词典
- 输出：`分析结果/情绪分析数据/ch01-18_emotion_analysis.json`
- 用法：`python batch_emotion_1_18.py`

#### 3. analyze_ch19.py
**功能**：第19章情感分析（三维统计 + 七类情绪）
- 用法：`python analyze_ch19.py`

---

### 二、验证检查类

#### 1. verify_v32.py
**功能**：基础结构验证，检查19章报告的：
- 大章节数（应为10个）
- 子章节数（应为28个）
- §4.3冲突动机分析是否存在
- §4.4叙事手法是否存在
- §5.3情感趋势分析是否存在
- §5.7七类情绪分布是否存在
- V3.2版本号是否存在
- 用法：`python verify_v32.py`

#### 2. deep_verify.py
**功能**：深度验证，检查更多维度：
- §5子章节顺序（5.1→5.2→5.3→5.4→5.5→5.6→5.7）
- 版本号三处一致性（头部/尾部/检测表）
- 流程版本一致性
- 数据占位符数量（≥20项）
- 完整性检测项数量（≥6项）
- §4.3/§4.4内容是否为空
- 用法：`python deep_verify.py`

#### 3. check_dicts.py
**功能**：验证基础词典加载是否正常
- 停用词、同义词、反义词、否定词、递进词
- 用法：`python check_dicts.py`

---

### 三、升级迁移类

#### 1. upgrade_v32_v2.py
**功能**：将1-18章报告从V3.1升级到V3.2
- 新增§4.3冲突动机分析（从V3.0提取）
- 新增§4.4叙事手法与章节定位（从V3.0提取）
- 新增§5.3情感趋势分析（从V3.0提取）
- 重排§5子章节编号（5.3→5.7顺延）
- 更新版本号V3.1→V3.2, v1.7→v1.8
- 更新数据占位符和完整性检测
- 用法：`python upgrade_v32_v2.py`

#### 2. upgrade_ch19_v32.py
**功能**：将第19章从V3.1升级到V3.2（新生成内容）
- 用法：`python upgrade_ch19_v32.py`

#### 3. update_index_v32_v2.py
**功能**：更新归档索引表到V3.2版本
- 新增3列：冲突数/叙事维度/情感分段
- 更新版本号
- 用法：`python update_index_v32_v2.py`

---

### 四、修复维护类

#### 1. fix_headers.py
**功能**：修复1-18章丢失的标题和头部信息块
- 补回一级标题（# 《红楼梦》第X章...）
- 补回分析框架/日期/文本来源引用块
- 用法：`python fix_headers.py`

#### 2. fix_person_order.py
**功能**：修复归档索引中人物出场档案的章号顺序
- 按首次出场章号从小到大排列
- 用法：`python fix_person_order.py`

#### 3. fix_versions_1_18.py
**功能**：批量修复1-18章版本号
- V3.0→V3.1, v1.6→v1.7
- 用法：`python fix_versions_1_18.py`

---

### 五、人物档案类

#### 1. extract_all_persons.py
**功能**：从1-19章报告的§7.1人物占位符中提取全部出场人物
- 输出：`分析结果/人物档案_第1-19章.json`
- 用法：`python extract_all_persons.py`

#### 2. rebuild_person_archive.py
**功能**：用完整人物数据重建归档索引的人物出场档案表
- 用法：`python rebuild_person_archive.py`

---

### 六、索引归档类

#### 1. optimize_index.py
**功能**：优化归档索引结构
- 新增六大板块、目录导航
- 新增基调演变趋势分析
- 用法：`python optimize_index.py`

#### 2. rebuild_index.py
**功能**：完全重建归档索引
- 用法：`python rebuild_index.py`

#### 3. process_tasks.py
**功能**：批量处理任务
- JSON分词文件转TXT
- 更新归档索引
- 用法：`python process_tasks.py`

## 使用流程

### 新增一章分析的标准流程

```
1. 准备原文和分词数据
   └─ 原文放入 红楼梦_拆分/ 文件夹
   └─ 分词数据放入 红楼梦_分词结果/ 文件夹

2. 情绪分析
   └─ 运行 batch_emotion_1_18.py （或单章分析脚本）

3. 生成/升级报告
   └─ 使用对应版本的升级脚本或生成脚本

4. 验证报告
   └─ 运行 verify_v32.py （基础验证）
   └─ 运行 deep_verify.py （深度验证）

5. 更新归档索引
   └─ 运行 update_index_v32_v2.py
   └─ 手动补充新增章节的具体数据

6. 存档
   └─ 复制到 V3.2存档_1-19章/ 文件夹
```

### 版本升级流程

```
1. 先备份当前版本（复制到存档文件夹）
2. 运行升级脚本（upgrade_*.py）
3. 运行验证脚本（verify_v32.py + deep_verify.py）
4. 抽查几章确认内容正确
5. 更新归档索引
6. 创建新版本存档
```

## 注意事项

1. **运行路径**：脚本默认从当前工作目录读取基础资源，请确保路径配置正确
2. **编码问题**：所有脚本均内置编码 fallback 链（utf-8 → gbk → gb18030）
3. **数据口径**：情感词三维统计采用人工校准口径，非纯词典自动匹配
4. **存档习惯**：每次大版本升级前先备份，确认无误后再覆盖
5. **验证优先**：任何修改后务必运行验证脚本确保结构完整
