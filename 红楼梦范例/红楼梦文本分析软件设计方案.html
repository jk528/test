三、现有机制剖析：一套"可软件化"的完整体系

整个范例事实上已经是一套"人工编排 + 脚本辅助 + LLM 生成"的半自动流水线。把它抽象成四个层，每一层都已经有可复用的实现或规范，这正是软件化的基础。

3.1 四层机制总览

层 1 · 数据资产

词库与词典

DUTIR 七类情绪词、Hownet 极性词、停用词、否定词、程度词、人物名表、分词词典、同义/反义词表

层 2 · 预处理管线

拆分 → 分词 → 情感

章节拆分、jieba 分词、双词典情感统计，全部已有可用 Python 脚本（无第三方依赖）

层 3 · 深度分析

LLM 提示词体系

"双轨六要素 V3.4"九大模块模板 + 流程规范 + 任务说明书，驱动 LLM 生成逐章分析

层 4 · 归集索引

结构化提取与归档

从 MD 报告提取结构化数据（JSON）→ 人物归并 / 基调归一 → 生成 7 部分全局索引

3.3 层 2：预处理管线（可直接复用的代码）

管线"3 步走"，脚本已在 基础/emotion_analysis.py 与 skill/红楼梦专用版_前置条件与生成规范.md §13.8 一键管线脚本 中完整实现：

  1. ① 章节拆分

    原文按"第X章"章节标题拆分为 120 个文件；文件名携带元数据：081_06893_第81章　占旺相四美钓游鱼　奉严词两番入家塾.txt（章号_字数_章名）；段落以全角空格开头，末行为"(本章完)"。

  2. ② jieba 分词

    jieba.load_userdict(红楼梦分词词典) + 停用词过滤，输出 JSON 词列表（120 份）与 TXT 视图（120 份）。

  3. ③ 双轨情感统计

    EmotionAnalyzer（DUTIR 七类计数与占比） + SentimentAnalyzer（Hownet 极性 + 否定词翻转 + 程度副词加权，窗口=5），输出 {章号}_emotion.json：七类情绪 count/pct/words、dutir_total/pos/neg/neu、hownet 极性、Top30 高频词。[2]

这是本范例最有价值也最复杂的部分——"双轨六要素分析体系 V3.4"，本质是一套高度结构化的 LLM 提示词工程规范：

关键洞察：逐章分析报告（V3.4）的九大模块 = 软件内"分析任务"的目标 Schema，即：§一 版本定位 → §二 事件接入清单（事件 ID E{章}-{序号}、事件分级 ★/◆/◇、段落索引）→ §三 新闻六要素 A 轨（5W1H）→ §四 叙事六要素 B 轨（人物基准六要素表 11 列）→ §五 情感词三维统计 + 七类情绪 → §六 人物关系 + 伏笔追踪 → §七 占位符统合（人物/时间/地点/数据/内容 5 类）→ §八 双轨校验与完整性检测 → §九 后续分析建议。

3.5 层 4：结构提取与全局索引（已高度软件化）

层 3 产出的是 500 行的 Markdown 报告（非结构化），层 4 用脚本把它"榨干"成结构化数据：

  1. extract_v34_v2.py（结构提取）

    从 80 份 MD 报告正则提取：字数、情感基调、三维统计、事件数（★/◆/◇）、冲突数、人物出场档案（名称/层级/段落/角色/状态）、伏笔数等，容错增强（约数/小数/缺失 fallback），输出 v34_extract_v2.json（17,320 行）。[3]

  2. gen_index.py（全局索引）

    用 ALIAS 人物别名归并字典（黛玉→林黛玉、凤姐→王熙凤、焙茗→茗烟等 40+ 条）+ TONE_MAP 情感基调归一（14 种表述 → 6 标准标签），计算首次出场/新出场人物，生成 7 大部分归档索引。[4]

  3. 人物档案 / 验证 / 升级类脚本

    extract_all_persons、analyze_persons_v2（别名检测、去重、频次）；verify_v32 / deep_verify / verify_alignment / check_dicts；v34_convert（V3.3→V3.4 80 章批量升级）。

三、软件化可行性评估

将现有机制映射到软件模块，按"改造工作量"分为三档：

现有资产软件化改造量说明
情感分析双引擎（emotion_analysis.py）直接复用（约 0 改造）封装为类库，仅需补输出格式与异常处理
jieba 分词 + 词典/停用词直接复用依赖库打包（jieba 体积可接受）
拆分规则（章节标题/全角空格）低改造改为"正则 + 配置化"引擎，支持任意小说章节格式
情感词库资产（DUTIR/Hownet/基础词库）直接随包分发加入"词库热更新/扩展"管理界面（资源统合调研已给出扩展路径）
LLM 提示词规范（九大模块/双轨）中改造（核心工作量）将"规范文档"封装为：模板引擎 + LLM API 调度 + 任务队列 + 断点续跑
报告结构提取（extract_v34_v2）低改造改为"结构化输出"优先（LLM 直接返回 JSON），正则提取作为 fallback
索引生成（gen_index + ALIAS/TONE_MAP）低改造ALIAS/TONE_MAP 配置化，可编辑、可导入导出
校验脚本（verify/deep/check_dicts）中改造迁移为"质量门禁"服务，分析完成后自动执行
V3.4 分析任务说明书中改造成为软件的"任务模板库"，用户可配置

结论：范例现有机制已覆盖软件的全部核心功能域（拆分/情感/事件/人物/索引/校验/词库），且多数模块可直接复用或低改造。主要工程化工作在于"编排"与"界面"：把 38 个离散脚本 + 6 份提示词文档编排成一个有界面、有任务队列、有可视化、可持续运行的软件。

五、软件架构设计

5.1 总体架构（五层）

  • 接入层：拖拽导入 TXT/MD 全文 → 自动识别章节 → 写入项目库
  • 数据层：SQLite（元数据、任务状态、索引）+ 文件系统（原文、分词、情感 JSON、报告 MD、导出文件）
  • 引擎层：拆分引擎 / 分词引擎 / 情感引擎 / LLM 分析调度引擎 / 提取与索引引擎（全部复用或封装现有脚本）
  • 服务层：FastAPI 提供 REST API（任务提交、进度、结果、配置）；任务队列 + 断点续跑 + 增量跳过
  • 呈现层：Web 工作台（Vue3 + ECharts + 后端同源）+ 报告阅读器（MD/HTML 渲染 + 导出 Word/PDF）

5.2 八大核心模块

M1

导入与章节拆分引擎

章节识别规则（"第X回/第X章"）+ 段落切割（全角空格/空行）；输出 {章号}_{字数}_{章名}.txt，保留字数元数据；支持任意中文小说。

M2

分词与词频引擎

jieba 用户词典（可编辑）+ 停用词过滤（可编辑）；输出分词 JSON/TXT 双格式 + 每章 Top30 高频词。

M3

情感分析引擎

复用 EmotionAnalyzer + SentimentAnalyzer：DUTIR 七类 + Hownet 极性 + 否定翻转 + 程度加权；输出逐章 JSON；词库可热更新。

M4

LLM 深度分析引擎

把"V3.4 任务说明书 + 空白模板 + 前置条件"封装为提示词模板库；支持多 LLM 后端（OpenAI 兼容 API）；任务队列、并发批量、断点续跑、增量跳过（已生成章跳过）。

M5

事件挖掘模块

事件拆分规则引擎（事件=起因→行动→结果、ID 规则 E{章}-{序号}、★/◆/◇ 三级分级、段落索引、颗粒度自检清单）→ 5W1H 结构化事件表 → 事件时间线。

M6

人物挖掘模块

人物库（红楼梦人物名 362 行）+ 别名归并（ALIAS 可配置）+ 首次出场/出场次数/人物关系提取 + 人物情感档案（该人物章节情感聚合）+ 人物共现网络图。

M7

报告与全局索引引擎

LLM 输出 JSON → 双格式渲染（Markdown 报告 + 全局索引 7 部分）；extract 正则提取作为校验/降级；TONE_MAP 基调归一。

M8

可视化与导出

章节情感曲线（正/负/七类）、事件时间线、人物关系图谱、高频词云；报告导出 MD/HTML/Word/PDF；索引导出 Excel。

六、实现路线图（里程碑）

  1. 里程碑 1 · 引擎筑基（约 1 周）

    搭建 FastAPI + 前端壳；迁移 38 个脚本为模块（拆分/分词/情感/校验/提取/索引）；词库资产并入项目；单章全流程跑通（输入 txt → 情感 JSON → 索引行）。

  2. 里程碑 2 · 自动化流水线（约 1 周）

    任务队列 + 断点续跑 + 增量跳过；LLM 深度分析调度（九大模块模板）；报告生成 + 校验门禁；结构化提取（LLM 直接输出 JSON，降级正则）。

  3. 里程碑 3 · 可视化与检索（约 1 周）

    情感曲线（逐章正负/七类）、人物关系图谱、事件时间线、章节地图；全局索引视图与全文检索；报告阅读器 + Word/PDF 导出。

  4. 里程碑 4 · 通用化与开放（约 1 周）

    支持任意小说/长文（章节识别规则配置化）；词库热更新（支持情感词库资源统合的外部 5 库导入）；模板自定义；LLM 后端可切换（含本地模型，数据不出本机）。
