# 二、现有机制剖析：四层可复用体系

整个范例事实上已经是一套「人工编排 + 脚本辅助 + LLM 生成」的半自动流水线，抽象为四层，每一层都已有可复用实现或规范 —— 这正是软件化的基础。

| 层 | 名称 | 内涵 |
|---|---|---|
| 层 1 | **数据资产** | DUTIR 七类情绪词、Hownet 极性词、停用词、否定词、程度词、人物名表、分词词典、同义/反义词表 |
| 层 2 | **预处理管线** | 章节拆分、jieba 分词、双词典情感统计，全部已有可用 Python 脚本（无第三方依赖） |
| 层 3 | **深度分析** | 「双轨六要素 V3.4」九大模块模板 + 流程规范 + 任务说明书，驱动 LLM 生成逐章分析 |
| 层 4 | **归集索引** | 从 MD 报告提取结构化数据（JSON）→ 人物归并 / 基调归一 → 生成 7 部分全局索引 |

## 2.2 层 2：预处理管线（可直接复用）

1. **① 章节拆分** —— 原文按「第X章」标题拆分为 120 个文件；文件名携带元数据：`081_06893_第81章　占旺相四美钓游鱼　奉严词两番入家塾.txt`；段落以全角空格开头，末行为「(本章完)」。
2. **② jieba 分词** —— `jieba.load_userdict(红楼梦分词词典)` + 停用词过滤，输出 JSON 词列表（120 份）与 TXT 视图（120 份）。
3. **③ 双轨情感统计** —— EmotionAnalyzer（DUTIR 七类计数与占比） + SentimentAnalyzer（Hownet 极性 + 否定词翻转 + 程度副词加权，窗口 = 5），输出 `{章号}_emotion.json`。[^2]

## 2.4 层 4：结构提取与全局索引（已高度软件化）

1. **`extract_v34_v2.py`（结构提取）** —— 从 80 份 MD 报告正则提取字数、情感基调、三维统计、事件数、冲突数、人物出场档案、伏笔数等，容错增强（约数/小数/缺失 fallback），输出 `v34_extract_v2.json`（17,320 行）。[^3]
2. **`gen_index.py`（全局索引）** —— 用 ALIAS 人物别名归并字典（黛玉→林黛玉、凤姐→王熙凤等 40+ 条）+ TONE_MAP 情感基调归一（14 种表述 → 6 标准标签），生成 7 大部分归档索引。[^4]
3. **人物档案 / 验证 / 升级类脚本** —— `extract_all_persons`、`analyze_persons_v2`（别名检测/去重/频次）；`verify_v32` / `deep_verify` / `verify_alignment` / `check_dicts`；`v34_convert`（V3.3→V3.4 80 章批量升级）。

# 三、软件化可行性评估

| 现有资产 | 改造量 | 说明 |
|---|---|---|
| 情感分析双引擎（emotion_analysis.py） | 直接复用（≈0 改造） | 封装为类库，仅需补输出格式与异常处理 |

| LLM 提示词规范（九大模块 / 双轨） | **中改造（核心工作量）** | 封装为：模板引擎 + LLM API 调度 + 任务队列 + 断点续跑 |

> **结论**
>
> 范例机制已覆盖软件全部核心功能域（拆分 / 情感 / 事件 / 人物 / 索引 / 校验 / 词库），多数模块可直接复用或低改造。主要工程化工作在于「编排」与「界面」。

# 四、软件架构设计

## 4.1 总体架构（五层）

- **接入层**：拖拽导入 TXT/MD 全文 → 自动识别章节 → 写入项目库
- **数据层**：SQLite（元数据、任务状态、索引）+ 文件系统（原文、分词、情感 JSON、报告 MD、导出文件）
- **引擎层**：拆分引擎 / 分词引擎 / 情感引擎 / LLM 分析调度引擎 / 提取与索引引擎
- **服务层**：FastAPI 提供 REST API（任务提交、进度、结果、配置）；任务队列 + 断点续跑 + 增量跳过
- **呈现层**：Web 工作台（Vue3 + ECharts）+ 报告阅读器（MD/HTML 渲染 + 导出 Word/PDF）

## 4.2 八大核心模块

| 模块 | 名称 | 职责 |
|---|---|---|
| M1 | 导入与章节拆分引擎 | 章节识别规则（「第X回 / 第X章」）+ 段落切割（全角空格 / 空行）；输出 `{章号}_{字数}_{章名}.txt`，支持任意中文小说 |
| M2 | 分词与词频引擎 | jieba 用户词典（可编辑）+ 停用词过滤（可编辑）；输出分词 JSON/TXT 双格式 + 每章 Top30 高频词 |
| M3 | 情感分析引擎 | EmotionAnalyzer + SentimentAnalyzer：DUTIR 七类 + Hownet 极性 + 否定翻转 + 程度加权；词库可热更新 |
| M4 | LLM 深度分析引擎 | V3.4 任务说明书 + 空白模板封装为提示词模板库；多 LLM 后端；任务队列、并发批量、断点续跑、增量跳过 |
| M5 | 事件挖掘模块 | 事件拆分规则引擎（起因→行动→结果、ID `E{章}-{序号}`、★/◆/◇ 三级、段落索引）→ 5W1H 结构化事件表 → 事件时间线 |
| M6 | 人物挖掘模块 | 人物库（362 行）+ 别名归并（ALIAS 可配置）+ 首次出场/出场次数/人物关系 + 人物情感档案 + 共现网络图 |
| M7 | 报告与全局索引引擎 | LLM 输出 JSON → 双格式渲染（Markdown 报告 + 全局索引 7 部分）；extract 正则提取作为校验/降级；TONE_MAP 基调归一 |
| M8 | 可视化与导出 | 章节情感曲线、事件时间线、人物关系图谱、高频词云；报告导出 MD/HTML/Word/PDF；索引导出 Excel |

## 4.3 完整数据流

```text
原文 TXT
   │  M1 章节拆分（自动识别 + 元数据命名）
   ▼

   ▼

   ▼
分析结果/{章号}_{简称}_V3.5_分析报告.md（九大模块）
   │  M5 事件挖掘（结构化提取：事件表 + 5W1H + 分级）
   ▼
结构化 JSON（事件 / 人物 / 情绪 / 冲突 / 伏笔）
   │  M6 人物挖掘 + M7 全局索引（ALIAS / TONE_MAP）
   ▼
_归档索引.md（7 大部分）+ 人物档案.json
   │  M8 可视化 & 导出
   ▼
情感曲线 · 关系图谱 · 事件时间线 · 报告 Word/PDF
```

# 五、逐模块具体实施步骤（本版核心）

本章把架构图翻译成施工步骤。每个模块统一按六要素展开：**① 目标与输入输出 → ② 选型与理由 → ③ 安装命令 → ④ 核心代码 → ⑤ 验收标准 → ⑥ 官方链接**。

优先级标记：`P0 必做` · `P1 重要` · `P2 增强`

## S0 环境准备与依赖安装

### S0-1 建立隔离的 Python 环境

**目标**：为项目创建独立虚拟环境，避免污染系统 Python。
**要求**：Python ≥ 3.10（项目脚本已在 3.10 验证，`__pycache__` 中存在 `cpython-310.pyc`）。

```bash
# 1) 确认 Python 版本
python --version           # 需 >= 3.10

# 2) 在项目根目录创建虚拟环境
cd "红楼梦范例"
python -m venv .venv

# 3) 激活（Windows / Git Bash）
source .venv/Scripts/activate
#    激活（Windows / CMD 或 PowerShell）
#   .venv\Scripts\activate.bat     或   .venv\Scripts\Activate.ps1

# 4) 升级 pip
```

```python
# split_chapters.py —— 通用章节拆分器（配置化正则 + 编码自适配）
import os, re, json
import chardet
import cn2an
from config import ROOT, SPLIT_DIR

# 章节标题正则：第X回 / 第X章 / 卷X（X 支持中文数字与阿拉伯数字）
CHAP_RE = re.compile(
    r'^[　\s]*(第[零一二三四五六七八九十百千两壹贰叁肆伍陆柒捌玖拾0-9]+[回章节卷])'
    r'[　\s]*(?P<title>[^\n]{0,60})$', re.M)

def read_text(path):
    raw = open(path, 'rb').read()
    enc = chardet.detect(raw)['encoding'] or 'utf-8'
    return raw.decode(enc, errors='ignore')

def split_by_title(text, keep_blank=True):
    """按章节标题切分，返回 [(标题, 正文), ...]"""
    marks = list(CHAP_RE.finditer(text))
    if not marks:
        return []
    out = []
    for i, m in enumerate(marks):
        start = m.start()
        end = marks[i + 1].start() if i + 1 < len(marks) else len(text)
        out.append((m.group(0).strip(), text[start:end].strip('\n')))
    return out

def normalize(body):
    """段落归一：统一换行、段首补全角空格、去空白行"""
    body = body.replace('\r\n', '\n').replace('\r', '\n')
    lines = []
    for ln in body.split('\n'):
        ln = ln.strip()
        if not ln:
            continue
        lines.append('　' + ln)          # 段首全角空格（与既有口径一致）
    return '\n'.join(lines) + '\n(本章完)'

def chapter_no(title):
    """从标题提取章号（中文数字 → 阿拉伯数字）"""
    m = re.match(r'^第([零一二三四五六七八九十百千两壹贰叁肆伍陆柒捌玖拾0-9]+)[回章节卷]', title)
    if not m:
        return 0
    s = m.group(1)
    try:
        return int(cn2an.cn2an(s, 'smart'))
    except Exception:
        return int(s) if s.isdigit() else 0

def run(src='红楼梦.txt'):
    text = read_text(os.path.join(ROOT, src))
    chapters = split_by_title(text)
    os.makedirs(SPLIT_DIR, exist_ok=True)
    manifest = []
    for title, body in chapters:
        no = chapter_no(title)
        body = normalize(body)
        name = f"{no:03d}_{len(body)}_{title}.txt"
        with open(os.path.join(SPLIT_DIR, name), 'w', encoding='utf-8') as f:
            f.write(body)
        manifest.append({"no": no, "title": title, "chars": len(body), "file": name})
    with open(os.path.join(ROOT, '拆分清单.json'), 'w', encoding='utf-8') as f:
        json.dump(manifest, f, ensure_ascii=False, indent=2)
    print(f"✅ 共拆分 {len(manifest)} 章")
    return manifest

if __name__ == '__main__':
    run()
```

### S2-5 核心代码（精确模式 + 停用词过滤 + 双格式输出）

```python
# tokenize.py —— jieba 分词引擎（完整可运行）
import os, json, glob
from collections import Counter
import jieba

from config import SPLIT_DIR, TOKEN_DIR, TOKEN_TXT, SEG_DICT, STOP_FILES

# ---------- 1. 一次性初始化（务必在循环外调用，避免重复加载词典）----------
jieba.initialize()                       # 手动初始化，1~3 秒
jieba.load_userdict(SEG_DICT)            # 载入红楼梦专名/人名词典
# jieba.set_dictionary('data/dict.txt.big')   # 若原文含繁体，切换大词典

# ---------- 2. 停用词（主表 + 停用词库 4 表并集）----------
def load_stopwords(paths):
    sw = set()
    for p in paths:
        if os.path.isfile(p):
            with open(p, 'r', encoding='utf-8') as f:
                sw.update(l.strip() for l in f if l.strip())
    return sw

STOPWORDS = load_stopwords(STOP_FILES)

# ---------- 3. 单章分词 ----------
def tokenize_text(text):
    """精确模式；过滤空白与纯标点"""
    words = [w.strip() for w in jieba.lcut(text, cut_all=False) if w.strip()]
    return [w for w in words if any('\u4e00' <= c <= '\u9fff' for c in w)]

def tokenize_chapter(path):
    with open(path, 'r', encoding='utf-8') as f:
        text = f.read()
    return tokenize_text(text)

# ---------- 4. 批量跑 120 章 ----------
def run():
    os.makedirs(TOKEN_DIR, exist_ok=True)
    os.makedirs(TOKEN_TXT, exist_ok=True)
    for path in sorted(glob.glob(os.path.join(SPLIT_DIR, '*.txt'))):
        ch = os.path.basename(path)[:3]
        words = tokenize_chapter(path)

        # 输出 JSON（与既有 120 份产物口径一致：list[str]）
        with open(os.path.join(TOKEN_DIR, f'{ch}.json'), 'w', encoding='utf-8') as f:
            json.dump(words, f, ensure_ascii=False)

        # 输出 TXT 视图
        with open(os.path.join(TOKEN_TXT, f'{ch}.txt'), 'w', encoding='utf-8') as f:
            f.write(' '.join(words))

        # Top30 高频词（去停用词后）
        wc = Counter(w for w in words if w not in STOPWORDS)
        top = wc.most_common(30)
        print(f'  {ch}: {len(words)}词   Top3={[w for w, _ in top[:3]]}')
    print('✅ 分词完成')

if __name__ == '__main__':
    run()
```

```python
        out = {"chapter": ch}
        for e in EMOTIONS:
            c = emo['emotion_counts'].get(e, 0)
            out[f'dutir_{e}'] = {
                "count": c,
                "pct": round(c / total * 100, 1) if total else 0,
                "words": ', '.join(emo['emotion_words'].get(e, [])[:15]),
            }
        out.update({
            "dutir_total": total,
            "dutir_pos": emo['positive_emotion_count'],
            "dutir_neg": emo['negative_emotion_count'],
            "dutir_neu": emo['neutral_emotion_count'],
            "hownet_pos": sent['pos_count'],
            "hownet_neg": sent['neg_count'],
            "hownet_pos_pct": sent['pos_percentage'],
            "hownet_neg_pct": sent['neg_percentage'],
            "hownet_total": sent['total_sentiment_words'],
            "top_words": [{"word": w, "count": c} for w, c in wc.most_common(30)],
        })
        with open(os.path.join(EMO_DIR, f'{ch}_emotion.json'), 'w', encoding='utf-8') as f:
            json.dump(out, f, ensure_ascii=False, indent=2)
        print(f"  {ch}: total={total} pos={emo['positive_emotion_count']} neg={emo['negative_emotion_count']}")
    print('✅ 情绪 JSON 生成完成')

if __name__ == '__main__':
    run()
```

**核心算法口径（务必与既有报告保持一致）**：否定词在窗口 = 5 的范围内**奇数次翻转、偶数次还原**；程度副词权重：`very=2.0 / extreme=2.5 / more=1.5 / ish=0.75`，项目递进词表默认 `1.5`；一个词只归入一个情绪类别（`break` 提前跳出）。[^2]

```python
from jinja2 import Template
from openai import OpenAI
from config import ROOT, SPLIT_DIR, EMO_DIR, REPORT_DIR

client = OpenAI(
    api_key=os.getenv("LLM_API_KEY", "sk-local"),
    base_url=os.getenv("LLM_BASE_URL", "https://api.openai.com/v1"),
)
MODEL = os.getenv("LLM_MODEL", "gpt-4o-mini")

# ---------- 1. 提示词模板：由 V3.4 任务说明书 + 空白模板合成 ----------
PROMPT = Template("""你是《红楼梦》文本分析专家。请严格按「双轨六要素 V3.4」九大模块，
为第{{ no }}章（{{ title }}，{{ chars }} 字）生成分析报告。

【硬性规则】
1. 事件数下限 ≥ {{ chars // 500 }} 件；事件 ID 规则 E{{ no }}-{序号}；分级 ★/◆/◇。
2. §五 情感数据必须直接引用下方 JSON，不得自行估算。
3. §六 人物出场须标注段落索引。
4. 输出格式：先输出一个 json 代码块（见下方 SCHEMA），再输出完整 Markdown 报告。

【本章情绪数据 JSON】
{{ emotion_json }}

【结构化输出 SCHEMA】
{"chapter":int,"events":[{"id":str,"level":str,"summary":str,"para":int}],
 "persons":[{"name":str,"level":str,"para":int}],
 "emotion":{"tone":str,"dutir":{"好":int,"乐":int,"哀":int,"怒":int,"惧":int,"恶":int,"惊":int}},
 "foreshadows":[...],"conflicts":int}

【本章原文】

def pending(range_=(1, 120)):
    todo = []
    for ch in range(range_[0], range_[1] + 1):
        hits = glob.glob(os.path.join(REPORT_DIR, f'{ch:03d}_*_V3.5_分析报告.md'))
        if hits and os.path.getsize(hits[0]) > 1000:
            continue                                    # 已完成 → 跳过
        if not os.path.exists(os.path.join(EMO_DIR, f'{ch:03d}_emotion.json')):
            print(f'⚠️ 第{ch}章: 情绪 JSON 不存在，跳过')
            continue
        todo.append(ch)
    return todo

# ---------- 3. 单章分析 ----------
def analyze_one(no):
    ch = f'{no:03d}'
    src = glob.glob(os.path.join(SPLIT_DIR, f'{ch}_*.txt'))[0]
    text = open(src, 'r', encoding='utf-8').read()
    title = os.path.basename(src).split('_', 2)[2].replace('.txt', '')
    emo = open(os.path.join(EMO_DIR, f'{ch}_emotion.json'), 'r', encoding='utf-8').read()

    prompt = PROMPT.render(no=no, title=title, chars=len(text),
                           emotion_json=emo, text=text)
    for attempt in range(3):                            # 失败重试 3 次
        try:
            resp = client.chat.completions.create(
                model=MODEL, temperature=0.2, max_tokens=8000,
                messages=[{"role": "user", "content": prompt}])
            md = resp.choices[0].message.content
            out = os.path.join(REPORT_DIR,
                               f'{ch}_{title.split("　")[0]}_V3.5_分析报告.md')
            open(out, 'w', encoding='utf-8').write(md)
            return True
        except Exception as e:
            print(f'  第{no}章 第{attempt+1}次失败: {e}')
            time.sleep(2 ** attempt)                    # 指数退避
    return False

if __name__ == '__main__':
    todo = pending((1, 120))
    print(f'待处理 {len(todo)} 章')
    for no in todo:
        ok = analyze_one(no)
        print(f'  第{no}章 {"✅" if ok else "❌"}')
```

```python
# events.py —— 事件表构建与合规校验
import json, os
from collections import Counter
from config import REPORT_DIR

def parse_events(structured):
    """从 LLM 结构化输出中取出事件表"""
    rows = []
    for ev in structured.get('events', []):
        rows.append({
            'event_id': ev['id'],                 # E{章}-{序号}
            'chapter': structured['chapter'],
            'level': ev['level'],                 # ★ / ◆ / ◇
            'summary': ev['summary'],
            'para': ev.get('para'),               # 段落索引
            'five_w_one_h': ev.get('5w1h', {}),   # who/what/when/where/why/how
        })
    return rows

def check_events(rows, chars):
    """合规校验：数量下限 + 分级分布 + 段落索引完整"""
    low = chars // 500
    problems = []
    if len(rows) < low:
        problems.append(f'事件数 {len(rows)} < 下限 {low}')
    if any(r['para'] is None for r in rows):
        problems.append('存在缺少段落索引的事件')
    dist = Counter(r['level'] for r in rows)
    if not dist:
        problems.append('事件分级为空')
    return {'count': len(rows), 'lower_bound': low, 'level_dist': dict(dist),
            'problems': problems}
```

```python
# persons.py —— 共现网络 + 关系图导出
import json, itertools
from collections import Counter
import networkx as nx

def build_graph(chapter_persons, alias=None):
    """chapter_persons: {章号: [人物, ...]}；同章共现即连边"""
    alias = alias or {}
    G = nx.Graph()
    for ch, names in chapter_persons.items():
        std = sorted({alias.get(n, n) for n in names})
        for a, b in itertools.combinations(std, 2):
            if G.has_edge(a, b):
                G[a][b]['weight'] += 1
                G[a][b]['chapters'].append(ch)
            else:
                G.add_edge(a, b, weight=1, chapters=[ch])
    return G

# 关键指标：度中心性（社交广度）、介数中心性（关系枢纽）
def key_metrics(G):
    return {
        'degree':  dict(nx.degree_centrality(G)),
        'between': dict(nx.betweenness_centrality(G)),
    }

# 导出交互式关系图（HTML）
from pyvis.network import Network
def export_html(G, path='人物关系图.html'):
    net = Network(height='720px', width='100%', bgcolor='#ffffff', font_color='#1f2d3d')
    for n in G.nodes:
        net.add_node(n, label=n, size=10 + 2 * G.degree(n))
    for a, b, d in G.edges(data=True):
        net.add_edge(a, b, value=d['weight'], title=f"共现 {d['weight']} 次")
    net.show(path, notebook=False)
```

# 七、实施路线图（里程碑 + 验收物）

1. **里程碑 1 · 引擎筑基**
   - **任务**：S0 环境与配置外置 → S1 章节拆分 → S2 分词 → S3 情感分析，跑通单章全流程；迁移 38 个脚本为模块；词库资产并入项目。
   - **验收物**：输入一份 TXT，产出 120 份拆分文件 + 120 份分词 JSON + 120 份情绪 JSON；`check_dicts.py` 通过。

2. **里程碑 2 · 自动化流水线**
   - **任务**：S4 LLM 深度分析调度（九大模块模板 + 任务队列 + 断点续跑 + 增量跳过）→ S7 结构化提取与索引生成 → S4-5 质量门禁接入。
   - **验收物**：一条命令跑完 120 章；中断后可续跑且不重复生成；生成后自动校验并列出不合格章节。

3. **里程碑 3 · 可视化与检索**
   - **任务**：S5 事件时间线 → S6 人物关系图谱与人物情感曲线 → S8 情感曲线 / 词云 / 报告阅读器 / Word·PDF·Excel 导出。
   - **验收物**：6 个工作台可用；图表可交互（点击事件跳原文段落）；导出文件中文无乱码。

4. **里程碑 4 · 通用化与开放**
   - **任务**：章节识别规则配置化（支持任意小说）→ 词库热更新（导入外部 5 库）→ 模板自定义 → LLM 后端可切换（含本地模型，数据不出本机）。
   - **验收物**：换一本非红楼小说，仅改配置即可跑通 S1–S3；词库可在界面内增删并即时生效。

> **推进原则**
>
> 先打通「零依赖的 S1–S3」，再啃「最需要工程化封装的 S4」。S1–S3 全部可直接复用现有脚本，风险极低；S4 是唯一的中改造模块，也是整个软件的价值中枢。

# 八、风险与对策

| 风险 | 表现 | 对策（具体动作） |
|---|---|---|
| LLM 生成质量波动 | 事件 / 人物提取不全、格式漂移 | 九大模块模板约束 + S4-5 质量门禁自动执行四个 verify 脚本；不合格章节自动进入重跑队列；事件数低于「字数 ÷ 500」即判失败 |
| 情感词典覆盖不足 | 文言 / 古语词未被词典命中 | 按 S3-4 引入外部 5 库扩词；增加「未登录词巡检」（频次 ≥ 5 仍被切为单字的二字串）；新词只并集不覆盖，保持既有口径 |
| 结构化提取脆弱 | 报告格式漂移导致正则失败 | 主路径改为 LLM 直接输出 JSON + Pydantic schema 校验；`extract_v34_v2.py` 仅作历史报告兜底与交叉校验 |
| 人物别名 / 异体字 | 同一人物分裂为多条 | ALIAS 外置 JSON + 自动建议（包含关系候选）+ 人工确认；`analyze_persons_v2.py` 别名检测 |
| 分词口径被破坏 | 更换分词器导致 120 份历史产物失效 | 锁定 jieba 为唯一生产引擎；pkuseg / HanLP 仅作为补充分析工具，不替换既有产物 |
| jieba 性能与缓存 | 全量重跑慢；受限文件系统反复建缓存 | 进程内只 `initialize()` 一次；需要提速时切 jieba-fast（接口兼容）；显式设置 `jieba.dt.tmp_dir` |
| 中文导出乱码 | 词云方框、PDF 缺字 | 统一指定中文字体（思源黑体）；导出前做一次字符渲染自检 |
| 版本迁移 | 模板升级后旧报告失效 | 沿用归档规范与版本存档习惯；`v34_convert.py` 已验证可复用 |
| 数据一致性 | 索引与报告不同步 | extract → gen_index 两步串联 + 完整性检测日志；索引生成后抽查 4 个关键章（1/40/80/120） |
| 词典版权 | 商用风险 | 所有外部词典仅供科研教学；软件分发时附来源与许可说明，商用需联系原作者 |
