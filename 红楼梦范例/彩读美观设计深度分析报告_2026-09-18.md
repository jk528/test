# 彩读（ColorTxt）阅读器美观设计深度分析报告

> **报告日期**：2026-09-18
> **研究对象**：彩读（ColorTxt）——基于 Electron + Vue 3 + Monaco Editor 的 AI 阅读器
> **研究问题**：彩读通过哪些设计手段解决阅读器的"美观"问题？颗粒度到具体色值、像素、CSS 属性与动画曲线
> **数据基础**：ColorTxt 官方 GitHub 仓库源码（`ssnangua/ColorTxt`）、README 及第三方评测

---

## 执行摘要

彩读的美观不是由单一设计点支撑，而是由**六层设计系统叠加**而成：基础清零层（去除 Monaco 的代码编辑器特征）、配色系统层（8 套主题 × 明暗双色 × 语法级文字着色）、背景系统层（底色 + 纹理叠加）、阅读细节层（阅读尺淡化、粘性标题融合）、排版美学层（内置老宋体、24px 字号、50% 行长居中）与动效系统层（140–250ms ease-out 浮动面板）。

其中三个设计决策最具迁移价值：其一，**先做减法再做加法**——将 Monaco 的行号、当前行高亮、glyph 边距、小地图、折叠全部关闭，从视觉上彻底摆脱"代码编辑器"身份；其二，**背景采用"底色 + 纹理"两层结构**——Monaco 所有层设为透明，纹理只渲染在最外层，使阅读区呈现"纸质感"；其三，**阅读尺采用"淡化非聚焦行"而非"高亮聚焦行"**——通过降低周围行 opacity（默认 0.2）实现视觉聚焦，比额外添加色块更克制、更不打断阅读。彩读的美观公式可概括为"清零 + 质感 + 排版 + 克制动效 + 融合式设计 + 语法级着色"。

## 1. 背景与研究对象

### 1.1 彩读是什么

彩读（ColorTxt）是一款基于 Electron + Vue + Monaco Editor 的桌面阅读器，定位为"书源 × AI+"，在传统文本阅读器之上叠加了 AI 对话、思维导图、词云、人物关系等分析能力。[cite:1][cite:2]

本项目（红楼梦阅读分析一体化）与彩读使用**相同的技术内核**（Monaco Editor + Vue），因此彩读的视觉设计决策对本项目具有直接的可迁移性。[cite:1]

### 1.2 研究方法

本报告基于 ColorTxt 官方仓库源码进行逐文件分析，主要证据来源包括：`appUi.ts`（默认配置值）、`readerPalette.ts`（配色系统）、`palettes.ts`（内置主题）、`readerBackground.ts`（背景系统）、`textures.ts`（纹理目录）、`readerMainMonaco.css`（阅读器 CSS）、`appShell.css`（应用壳布局）、`readerEditorOptions.ts`（Monaco 选项）、`readingRuler.ts`（阅读尺）等。[cite:3][cite:4][cite:8]

## 2. 核心结论：六层设计系统

彩读的美观由六层设计系统叠加构成，每一层解决一个维度的问题：

| 层级 | 解决什么 | 核心手段 |
|------|---------|---------|
| 第 1 层 基础清零 | 摆脱"代码编辑器"身份 | 关闭 Monaco 全部编辑器特征 |
| 第 2 层 配色系统 | 视觉层次与主题可选性 | 8 套主题 × 明暗双色 × 语法级着色 |
| 第 3 层 背景系统 | 纸张质感 | 底色 + 纹理 + 7 种混合模式 |
| 第 4 层 阅读细节 | 阅读舒适与专注 | 阅读尺淡化、粘性标题融合 |
| 第 5 层 排版美学 | 阅读舒适度 | 内置字体、24px 字号、50% 行长 |
| 第 6 层 动效系统 | 交互质感 | 140–250ms ease-out 浮动面板 |

---

## 3. 第 1 层：基础清零——把代码编辑器变成阅读器

彩读的底层是 Monaco（代码编辑器），但用户完全感受不到，因为其关闭了几乎所有"代码编辑器特征"。[cite:14]

### 3.1 关闭清单

| Monaco 特性 | 只读模式值 | 设计意图 |
|-------------|-----------|---------|
| `lineNumbers` | `off` | 行号是代码编辑器的标志性特征 |
| `glyphMargin` | `false` | 左侧断点/书签槽破坏沉浸感 |
| `minimap` | `disabled` | 小地图是代码导航工具，阅读不需要 |
| `folding` | `false` | 折叠箭头干扰阅读 |
| `contextmenu` | `false` | 右键菜单重写为阅读功能 |
| `renderLineHighlight` | `none` | 整行铺底色是"IDE 感"的主要来源 |
| `cursorBlinking` | `solid` + `cursorWidth: 0` | 阅读模式不显示光标 |
| `roundedSelection` | `false` | 圆角选区会切坏背景纹理 |
| `scrollBeyondLastLine` | `false` | 阅读到文末即停，不出现多余空白 |
| `useShadowDOM` | `false` | 便于 CSS 覆盖 Monaco 内部样式 |
| `disableMonospaceOptimizations` | `true` | 等宽优化对中文阅读有害 |
| `largeFileOptimizations` | `false` | 保证 token 着色完整性 |

[cite:14]

### 3.2 设计意图

这层清零是"美观"的前提——**不把代码编辑器特征去掉，后面所有层级的视觉设计都会被"IDE 感"淹没**。这是最容易被忽略但最基础的一步。

## 4. 第 2 层：配色系统——8 套主题 × 明暗双色 × 语法级着色

### 4.1 主题体系：不是亮/暗两个主题，是 8 套 × 2

彩读内置 8 套配色方案，每套方案包含亮色与暗色两种模式（星空仅暗色）：[cite:5]

| 方案名 | 亮色背景 | 暗色背景 | 纹理 | 风格 |
|--------|---------|---------|------|------|
| 默认 | `#f4ead7` 奶黄 | `#1e1e1e` | 无 | 护眼奶黄 / 代码暗底 |
| 素纸 | `#ffffff` 纯白 | `#0d0d0d` | paper | 纯白纸感 |
| 羊皮纸 | `#f4d8a6` 深黄 | `#21201c` | parchment | 复古书卷气 |
| 护眼 | `#e6eace` 豆绿 | `#333627` | eye-green | 绿色护眼 |
| 毛绒地毯 | `#faf0e8` 暖肤 | `#342c2a` | plush-rug | 温暖舒适 |
| 墨竹 | `#e6eace` 浅绿 | `#333627` | bamboo-grove | 国风竹韵 |
| 雪梅 | `#7f8f9f` 冷灰 | `#33363b` | plum-blossom | 冷调雪景 |
| 星空 | — | `#03040c` 深邃黑 | night-sky | 仅暗色，夜空感 |

[cite:5]

### 4.2 文字配色：语法级着色

彩读的文字不是单一颜色，而是将中文文本按"语法元素"分成 7 类颜色，直接复用 Monaco 的语法高亮引擎（tokenization）：[cite:4]

| 元素 | 亮色 | 暗色 | 代码类比 |
|------|------|------|---------|
| 正文 | `#000000` | `#d4d4d4` | 普通文本 |
| 章节标题 | `#b88230` | `#569cd6` | 标题 |
| 引号内文字 | `#a31515` | `#ce9178` | 字符串 |
| 括号内文字 | `#001080` | `#9cdcfe` | 参数 |
| 标点 | `#267f99` | `#4ec9b0` | 运算符 |
| 数字 | `#795e26` | `#dcdcaa` | 数字字面量 |
| 英文/字母 | `#af00db` | `#c586c0` | 类型 |

[cite:4]

**设计意图**：色值体系继承自 VS Code / Monaco 的语法高亮配色，用户打开书即有颜色层次——这正是"彩读"名字的由来。颜色全部低饱和、克制，不干扰阅读但丰富视觉层次。[cite:2]

### 4.3 高亮与标注颜色体系

**自定义高亮词（前景色）**：10 色，采用 Web 安全色（各通道 ∈ {00,33,66,99,CC,FF}），色相均匀分布（约每 36° 一枚）。亮色系如 `#CC0000` `#009933` `#0033CC`，暗色系如 `#FF6666` `#66FF66` `#66CCFF`。[cite:10]

**划线标注色**（马克笔/波浪线/直线）：5 色，亮暗相同：`#FF6B9D`（粉红）、`#A855F7`（紫）、`#3B82F6`（蓝）、`#22C55E`（绿）、`#F59E0B`（橙）。[cite:11][cite:12]

## 5. 第 3 层：背景系统——"底色 + 纹理"两层结构

这是彩读在视觉质感上最重要的设计。

### 5.1 两层结构

```
┌─────────────────────────────┐
│  纹理层（texture 图片）       │  ← 纸纹/竹纹/星空等
│  混合模式 / 透明度 / 定位     │
├─────────────────────────────┤
│  底色层（readerBg 纯色）      │  ← CSS 变量 --reader-bg
└─────────────────────────────┘
```

[cite:6][cite:7]

### 5.2 实现方式

**Monaco 所有层全部设为透明**，底色与纹理只渲染在最外层 `.readerSurfaceBg`：[cite:8]

```css
.monaco-editor,
.overflow-guard,
.monaco-scrollable-element,
.editor-scrollable,
.margin,
.monaco-editor-background {
  background-color: transparent !important;
}
```

**设计收益**：
1. 纹理只渲染一次，不随滚动重绘，性能可控
2. 文字、高亮、选区半透明叠加在纹理上，质感自然
3. 切换主题只改一个 CSS 变量，瞬间完成

### 5.3 纹理参数系统

| 参数 | 选项 |
|------|------|
| 混合模式 | normal / multiply / lighten / overlay / soft-light / screen / darken（7 种） |
| 尺寸 | cover（填满）/ contain（包含）/ auto（原始） |
| 定位 | 3×3 = 9 种（left/center/right × top/center/bottom） |
| 重复 | 开/关 |
| 透明度 | 0%–100% |

[cite:6]

**典型组合**：素纸 = paper 纹理 + multiply 混合 + auto 尺寸 + 重复；羊皮纸 = parchment + darken（亮）/multiply（暗）；毛绒地毯 = plush-rug + soft-light + opacity 0.6（亮）/1.0（暗）；墨竹 = bamboo-grove + cover + center bottom 定位 + 不重复。[cite:7]

## 6. 第 4 层：阅读细节——三个关键设计

### 6.1 阅读尺：淡化非聚焦行，而非高亮聚焦行

| 维度 | 彩读做法 | 常见做法 |
|------|---------|---------|
| 核心思路 | 非聚焦行 opacity 降到默认 0.2 | 给聚焦行加背景色/边框 |
| 视觉结果 | 聚焦行清晰、周围朦胧 | 聚焦行有额外色块打断阅读 |
| 实现方式 | `.view-line { opacity: 0.2 }` + `:has(.readerRulerFocus) { opacity: 1 }` | decoration 加整行底色 |
| 可调参数 | 淡化程度（0–1）、聚焦行数（1–10） | 颜色、高度 |
| 动画 | 0.2s ease 淡入淡出 | 通常无 |
| 粘性标题 | 默认同时淡化 | 通常不受影响 |
| 无障碍 | 支持 `prefers-reduced-motion` | — |

[cite:13][cite:8]

**设计意图**：README 明确说明阅读尺"适合注意力不容易集中的人（ADHD），聚焦阅读行，淡化其他行"。[cite:2] 淡化周围行比高亮当前行更柔和——不新增视觉元素，只降低干扰项的存在感。

### 6.2 粘性章节标题：融合而非浮层

| 设计点 | 彩读做法 | 效果 |
|--------|---------|------|
| 背景色 | `var(--reader-bg)`（与阅读区完全一致） | 看不出是浮层 |
| 阴影 | `none` | 无缝衔接 |
| 文字色 | `var(--reader-chapter-title)` | 与正文标题颜色一致 |
| 内层透明 | line-numbers 与 scrollable 均 transparent | 透出底色 + 纹理 |
| 点击 | `pointer-events: none` | 防止误触跳转 |

[cite:17][cite:8]

**设计意图**：粘性标题不是"悬浮在内容上方的条"，而是"内容延伸上来的部分"。背景完全一致、无阴影、无分隔线，只有文字颜色提示"这是章节标题"。

### 6.3 选区与当前行：克制到几乎看不见

当前行高亮完全关闭（`renderLineHighlight: none`）；选区背景亮色 `rgba(173,214,255,0.55)` / 暗色 `rgba(38,79,120,0.45)`；选区圆角关闭（`roundedSelection: false`）。[cite:14][cite:8]

**为什么关圆角选区**：圆角选区会"切"掉背景纹理的边缘，破坏纸质感；方角选区与纹理融合更好。

## 7. 第 5 层：排版美学——字体 + 字号 + 行高 + 行长

### 7.1 内置字体：京华老宋体

彩读内置了一套中文字体——**京華老宋体（KingHwa OldSong）**，通过 `@font-face` 加载内置字体文件。[cite:15]

**字体预设系统**（4 套，跨平台自动适配）：[cite:15]

| 预设 | Windows | macOS | Linux |
|------|---------|-------|-------|
| 京华老宋体 | KingHwa OldSong | KingHwa OldSong | KingHwa OldSong |
| 雅黑/苹方 | Microsoft YaHei | PingFang SC | Noto Sans CJK SC |
| 宋体 | SimSun | Songti SC | Noto Serif CJK SC |
| 楷体 | KaiTi | Kaiti SC | AR PL UKai CN |

**为什么默认老宋体**：衬线体在小字号下比黑体易读；宋体是印刷书籍标准字体，自带"书卷气"心理暗示；内置字体保证跨平台一致性。[cite:2][cite:15]

### 7.2 字号与间距默认值

| 参数 | 默认值 | 范围 |
|------|--------|------|
| 字号 | **24px** | — |
| 行高倍数 | 1.5 | 1.0+ |
| 段间距 | 10px | 0–100 |
| 字间距 | 0px | -5~20 |
| 左右边距 | 10px | 0–160 |
| 编辑器上下 padding | 10px | — |

[cite:3]

**注意**：默认字号 24px 明显大于普通网页正文（16px），体现"阅读器核心是读得舒服，不是塞得多"的设计取向。

### 7.3 行长控制：50% 居中

| 参数 | 默认值 |
|------|--------|
| 全屏阅读区宽度 | 视口 50%（可调 30%–100%） |
| 四周边距 | 各 20px |
| 居中方式 | 阅读区居中，两侧留白与正文同底色/纹理 |
| 非全屏最小宽度 | 300px |

[cite:3]

**设计意图**：印刷排版的黄金法则是"行长 60–75 个汉字最舒适"。50% 宽度在 1080p 屏约 960px，放 24px 字约 40 字/行——太宽换行费劲，太窄频繁换行打断思路。

## 8. 第 6 层：动效系统——克制的微交互

彩读的动效全部落在 **140ms–250ms** 区间，使用 `ease-out` 曲线，快、轻、不拖泥带水。[cite:9]

### 8.1 面板浮动动画

| 面板 | 动画 | 时长 | 曲线 |
|------|------|------|------|
| 浮动顶栏 | `translateY(-8px) → 0` + opacity | 140ms | ease-out |
| 浮动底栏 | `translateY(8px) → 0` + opacity | 140ms | ease-out |
| 浮动侧栏 | `translateX(-12px) → 0` + opacity | 180ms | ease-out |
| 拖放遮罩 | opacity 0 ↔ 1 | 150ms | ease |
| 提示条 | opacity → 0 | 250ms | ease |
| 阅读尺淡化 | opacity 0.2 ↔ 1 | 200ms | ease |
| 滚动条淡出 | opacity | 250ms | ease |

[cite:9][cite:8]

**设计原则**：
1. 出现快、消失快（140ms 接近"瞬发"感，不等待）
2. 带方向位移（从哪来、往哪去），符合物理直觉
3. 位移很小（8px/12px），只是"动了一下"而非大张旗鼓

### 8.2 滚动与悬停

| 特性 | 默认值 |
|------|--------|
| 平滑滚动 | 开启 |
| 滚轮倍率 | 1x |
| 快速滚动（Alt+滚轮） | 5x |
| 全屏滚动条宽度 | 14px |
| 内部链接悬停 | 实线下划线 |
| 外部链接悬停 | 虚线下划线（区分内部） |
| 滚动条滑块悬停 | 颜色加深（亮：0.4 → 0.55） |

[cite:3][cite:8]

## 9. UI 组件美学

### 9.1 圆角体系

| 组件 | 圆角 |
|------|------|
| 右键菜单 | 4px |
| 悬停/补全面板 | 3px |
| 拖放遮罩文字 | 4px |
| 全屏提示条 | 999px（pill 形胶囊） |

[cite:8][cite:9]

### 9.2 阴影体系

| 组件 | 阴影 |
|------|------|
| 浮动顶栏 | `0 6px 28px rgba(0,0,0,0.45)` |
| 浮动底栏 | `0 -6px 28px rgba(0,0,0,0.45)` |
| 浮动侧栏 | `6px 0 28px rgba(0,0,0,0.45)` |
| 菜单/面板 | `0 2px 8px color-mix(fg 12%, transparent)` |

[cite:9][cite:8]

**设计手法**：浮动的大面板用大阴影（28px 模糊），强调"浮在内容上方"；菜单等小面板用小阴影（8px + 颜色混合），不抢戏。

### 9.3 图标系统

全部为 **SVG 线性图标**、自制、统一尺寸，覆盖章节、调色板、高亮、全屏、阅读尺、书签、笔记、AI 对话、思维导图、词云、人物、词典、翻译等 20+ 功能。[cite:2]

| 面板浮动动画 | ⭐⭐ | 低 | 中 |
| 浮动面板大阴影 | ⭐⭐ | 低 | 中 |
| 滚动条淡出 | ⭐ | 低 | 低 |
| 摸鱼模式 | ⭐⭐ | 中 | 低 |

### 11.2 设计手法归纳

彩读的美观公式可归纳为：

```
美观 = 清零（去掉 IDE 感）
     + 底色 + 纹理（纸质感）
     + 好字体 + 合适的字号/行高/行长（排版功底）
     + 克制的动效（140–250ms ease-out）
     + 融合式设计（粘性标题不是浮层，是内容延伸）
     + 语法级文字着色（差异化灵魂）
```

### 11.3 最值得借鉴的三件事

1. **背景加纹理**：从"平"到"有质感"的最快路径
2. **行长控制 + 更大默认字号**：阅读舒适度立竿见影
3. **粘性标题融合 + 关闭行高亮**：从"IDE"到"阅读器"的关键两步
