## 一、先建立整体认知：什么是"软件开发生产线"

**一句话理解**：CodeArts 就是一条"软件工厂流水线"。你写的代码是原材料，这条流水线负责把代码自动加工成可以上线运行的软件——中间经过质检（代码检查）、组装（编译构建）、成品检验（测试）、入库（制品仓库）、发货安装（部署）。

**为什么需要它**：新手通常用"手动"方式开发——本地写代码、手动打包、手动传到服务器。这种方式在一个人做小项目时勉强可行，但团队协作时会出现：代码互相覆盖、打包环境不一致、测试靠人肉、上线靠运气。CodeArts 把这些环节全部标准化、自动化，并且**所有环节在同一个平台里打通**（这就是"一体化集成"的含义）。

## 二、逐个拆解：每个部件的作用

### ① 需求管理 CodeArts Req —— "施工图纸"

- **是什么**：项目协作的中枢。所有要做的事都变成一张张"工作项"——需求（Epic/Feature/Story）、任务、Bug，用看板、甘特图、迭代来组织。
- **解决什么问题**：新手最容易犯的错是"想到哪写到哪"。需求管理强迫你先想清楚：这个迭代做什么、谁负责、什么时候完成。
- **新手类比**：装修前先画图纸、列清单，而不是拿到房子就砸墙。
- **关键功能**：Scrum / 看板项目模板、需求-任务-Bug 三层拆解、迭代规划、甘特图、工时统计。
- **官方文档**：[需求管理成长地图](https://support.huaweicloud.com/projectman/index.html)

### ② 代码托管 CodeArts Repo —— "代码的云端保险柜"

- **是什么**：基于 Git 的在线代码仓库（可以理解为华为云版的 GitHub/Gitee），支持分支保护、合并请求评审、成员权限管理。
- **解决什么问题**：代码不能只存在个人电脑上——电脑坏了、版本乱了、多人改同一个文件冲突了怎么办？Git 仓库记录每一次修改历史，多人协作有章可循。
- **新手类比**：一个带完整"修改记录"的共享网盘，谁改了什么、为什么改、改错了一键回退。
- **关键功能**：新建仓库（可从模板创建）、SSH/HTTPS 密钥配置、分支管理与保护、合并请求（MR）评审。
- **官方文档**：[代码托管成长地图](https://support.huaweicloud.com/codehub/index.html) ｜ [快速入门（Scrum 项目体验 Java 开发全流程）](https://support.huaweicloud.com/qs-codeartsrepo/codeartsrepo_02_0001.html)

### ③ 代码检查 CodeArts Check —— "代码体检中心"

- **是什么**：静态代码检查（不需要运行代码，扫一遍源码就能发现问题），检查代码风格、潜在 Bug、安全漏洞、圈复杂度等。
- **解决什么问题**：人眼 Review 容易漏掉低级错误——忘记判空、SQL 注入风险、命名不规范。机器扫一遍，问题清单自动生成，还能分配给人闭环整改。
- **新手类比**：作文交上去之前先过一遍"错别字 + 语法 + 抄袭"自动检查。
- **关键功能**：多语言规则集（Java、C/C++、Python、JS/TS 等）、质量报告、问题闭环处理。
- **官方文档**：[代码检查成长地图](https://support.huaweicloud.com/codecheck/index.html)

### ④ 编译构建 CodeArts Build —— "加工车间"

- **是什么**：云端编译打包服务。配置一次构建任务（Maven、Gradle、npm、Docker 镜像等），之后每次触发都在云端统一环境里把源代码变成软件包。
- **解决什么问题**："在我电脑上是好的"是程序员经典笑话——本地打包依赖的 JDK 版本、环境变量各不相同。云端构建保证**每次打包环境一模一样**，结果可复现。
- **新手类比**：中央厨房统一加工，而不是每家自己开火，出品标准一致。
- **关键功能**：多语言构建模板、图形化配置、构建日志实时查看、失败自动通知。
- **官方文档**：[编译构建成长地图](https://support.huaweicloud.com/cloudbuild/index.html)

### ⑤ 测试计划 CodeArts TestPlan —— "成品质检站"

- **是什么**：测试全过程管理——写测试用例、规划测试轮次、执行接口测试、记录 Bug 并回归验证。
- **解决什么问题**：没有测试的软件等于盲盒。测试计划让"测过什么、还剩什么没测、哪些 Bug 没修"一目了然。
- **新手类比**：汽车出厂前的碰撞测试和路试，每项检查都要留记录、签字。
- **关键功能**：测试用例管理、测试计划与执行、接口自动化测试、测试报告。
- **官方文档**：[测试计划成长地图](https://support.huaweicloud.com/cloudtest/index.html)

### ⑥ 制品仓库 CodeArts Artifact —— "成品仓库"

- **是什么**：两个库——**软件发布库**（存放编译构建产出的软件包/镜像）+ **私有依赖库**（存放项目依赖的第三方库，如 Maven jar 包）。
- **解决什么问题**：软件包不能散落在个人电脑或聊天记录里。统一入库、统一版本号，部署时只从仓库取件，保证"测过的就是上线的那个"。
- **新手类比**：工厂成品仓 + 原材料仓分开设，出库入库都有单据。
- **官方文档**：[制品仓库成长地图](https://support.huaweicloud.com/cloudartifact/index.html)

### ⑦ 部署 CodeArts Deploy —— "上门安装队"

- **是什么**：可视化一键部署。把制品仓库里的软件包自动安装到目标环境（华为云 ECS 主机、CCE 容器集群等），支持回滚。
- **解决什么问题**：手动部署 = SSH 登录服务器、传文件、改配置、重启服务，步骤繁琐且容易漏。部署服务把整套动作编排成模板，一键执行、执行留痕、出错回滚。
- **新手类比**：净水器师傅上门安装——拆箱、安装、调试、验收一套流程标准化执行。
- **官方文档**：[部署成长地图](https://support.huaweicloud.com/clouddeploy/index.html)

### ⑧ 流水线 CodeArts Pipeline —— "总调度台"

- **是什么**：可视化、可定制的自动化任务调度平台，**把代码检查、编译构建、测试、部署等任务按顺序串起来**，代码一提交就自动走完全程。
- **解决什么问题**：如果没有流水线，每个环节都要手动点：提交代码 → 手动跑检查 → 手动打包 → 手动测试 → 手动部署。流水线把它们串成一条链，**一次提交，全程自动**，还能设置门禁（比如"检查不通过就不允许打包"）。
- **新手类比**：餐厅的点单系统——顾客下单（代码提交）后，传菜、炒菜、出餐自动按流程走，不需要经理挨个环节喊话。
- **关键概念**：阶段（Stage）→ 任务（Job）→ 门禁（质量关卡）→ 定时/事件触发。
- **官方文档**：[流水线成长地图](https://support.huaweicloud.com/cloudpipeline/index.html) ｜ [流水线使用流程（讲清它与其他服务的关系，强烈建议新手阅读）](https://support.huaweicloud.com/usermanual-pipeline/pipeline_01_0013.html)

### 补充：AI 编码伙伴

- **码道 CodeArts 代码智能体**：AI 编码工具（IDE / 桌面端 / CLI），与生产线配合使用——AI 帮你写代码，生产线负责质检和交付。官网：[codearts.huaweicloud.com](https://codearts.huaweicloud.com/)

## 三、实战走一遍：一个小项目的完整生命周期

以官方教程"使用 CodeArts 快速搭建基于 ECS 部署的代码开发流水线"为例，看看每个节点上**实际发生什么**：

| 阶段 | 你在哪个服务里操作 | 具体动作 | 产出物 |
|---|---|---|---|
| 1. 立项 | 需求管理 Req | 新建 Scrum 项目，写下"做一个商品展示页"的需求，拆成 3 个任务 | 项目 + 工作项 |
| 2. 建仓 | 代码托管 Repo | 从"Java Maven Demo"模板新建代码仓库 | 初始代码仓 |
| 3. 编码 | 本地 IDE / 码道 | clone 仓库 → 写代码 → `git push` 提交 | 新版本代码 |
| 4. 体检 | 代码检查 Check | 新建检查任务，扫描这次提交 | 质量报告 + 问题清单 |
| 5. 打包 | 编译构建 Build | 新建构建任务（Maven 模板），产出 jar/war 包 | 软件包 |
| 6. 质检 | 测试计划 TestPlan | 设计用例、执行接口测试，Bug 回到 Req 里跟踪 | 测试报告 |
| 7. 入库 | 制品仓库 Artifact | 构建产物自动归档到软件发布库 | 带版本号的制品 |
| 8. 上线 | 部署 Deploy | 配置主机组，把制品安装到 ECS 并启动服务 | 可访问的网站 |
| 9. 串联 | 流水线 Pipeline | 把 3~8 步编排成一条流水线，绑定代码提交事件 | 提交即自动发布 |

**跑通流水线之后的日常**：你只做两件事——写代码、看结果。`git push` 之后，检查、构建、测试、部署全自动执行，每一步的日志和结果在流水线页面一目了然。

## 四、新手学习路径建议

```text
第1周   理解 Git 基本概念 → 代码托管 Repo（建仓、提交、分支）
第2周   编译构建 Build（用模板打包一个 Demo）
第3周   部署 Deploy（把包推到一台 ECS 上跑起来）
第4周   流水线 Pipeline（把前几步串起来，体验"提交即发布"）
之后    逐步加上代码检查、测试计划、需求管理，形成完整习惯
```

**新手最常见误区**：
1. 不要一上来就学全部 8 个服务——先跑通"代码仓 → 构建 → 部署"最小闭环，再加其他环节
2. 流水线不是独立工具，它调度的是其他服务里配置好的任务，所以要先会配各个任务
3. 个人体验版套餐免费，先用免费额度练手，不必先研究计费

**套餐说明**：CodeArts 套餐分为体验版、基础版、专业版、企业版，均包含需求管理、代码托管、流水线、代码检查、编译构建、部署、测试计划、制品仓库等服务资源，区别在于额度与并发规格。详见[定价页](https://www.huaweicloud.com/devcloud/pricing.html)。
