## 一、一句话概括

一个插件（`magpie-officeace`）同时接入华为云的两个模型渠道 —— **果办 OfficeAce** 与 **码道 CodeArts**。同一个华为云账号登录一次，两个渠道的凭证互通、模型目录各自独立，但**积分是同一口径、可以合并计算**。全量积分合计 **15,100**。

---

### 2.1 果办 OfficeAce：4,500 积分

| 项目     |        积分 | 性质            |
| ------ | --------: | ------------- |
| 新用户福利  |     4,000 | 一次性           |
| 个人体验版  |       500 | 一次性           |
| **小计** | **4,500** | 两笔均为一次性，用完不再补 |

### 2.2 码道 CodeArts：10,600 积分

| 项目       |         积分 | 性质   |
| -------- | ---------: | ---- |
| 体验版赠送积分包 |     10,100 | 一次性  |

| **小计**   | **10,600** | —    |

### 2.3 合计

```
果办 4,500 + 码道 10,600 = 15,100 积分（同一账号，同一口径，可合并）
```

- 果办的 4,500 全部是一次性额度，花完即止。
- 码道的 10,600 里，10,100 是一次性积分包，另有 500 属于每月重置部分，可持续补充。
- **所有可获取的积分会自动开启**，不需要手动领取或激活，之后无需再管。

## 三、积分口径：为什么两家可以合起来看

两家对**同一模型**的消耗系数**完全一致**，这就是积分可以合并计算的依据：

| 模型                  | 果办 系数 | 码道 系数 |
| ------------------- | ----: | ----: |
| GLM-5.3-Flash       |  0.08 |  0.08 |
| DeepSeek-V4.1-Flash |  0.18 |  0.18 |
| GLM-5.3             |  0.79 |  0.79 |
| Kimi-K3             |  2.38 |  2.38 |

系数相同 → 同一份积分在两边买到的算力等价 → 15,100 可以当作一个池子来规划。

## 四、积分能换多少 token

按 **DeepSeek-V4.1-Flash（系数 0.18）** 折算，15,100 积分对应约 **8 亿 token** 的处理量。

这个口径有两个必须说明的前提：

1. **它是按本机真实调用流水反推的**，不是官方换算表。官方从未公布过"积分兑 token"的公式。
2. **8 亿 token 含缓存命中**。如果只算输入 + 输出、不含缓存，大约是 **八千万 token**（约 8,000 万）。

### 4.1 单模型吃满 15,100 积分的理论处理量

下表按各模型系数折算，用于横向比较不同模型的"耐烧"程度。含缓存一列按上文的 1:10 放大比例推算，**仅供估算**。

| 模型                  |   系数 |     不含缓存（输入+输出） |         含缓存（估算） |
| ------------------- | ---: | --------------: | --------------: |
| GLM-5.3-Flash       | 0.08 |  约 1.89 亿 token |  约 18.9 亿 token |
| DeepSeek-V4.1-Flash | 0.18 | 约 8,389 万 token |   约 8.4 亿 token |
| GLM-5.3             | 0.79 | 约 1,911 万 token |   约 1.9 亿 token |
| Kimi-K3             | 2.38 |   约 634 万 token | 约 6,345 万 token |

> 结论：想做长文本吞吐，优先 GLM-5.3-Flash 与 DeepSeek-V4.1-Flash；GLM-5.3、Kimi-K3 更适合当作"高质量、少调用"的补位。

## 五、重点三款模型（两家都能用）

| 项目        | 规格                                        |
| --------- | ----------------------------------------- |
| 可用模型      | DeepSeek-V4.1-Flash、GLM-5.3、kimi-k3.1-pro |
| 果办同族对应    | kimi-k3.1-pro-highspeed                   |
| 最大上下文     | **1M（100 万 token）**                       |
| 输出长度 · 果办 | 128K                                      |
| 输出长度 · 码道 | 32K                                       |
| 输入类型      | 纯文本                                       |
| 图片输入      | **不支持**                                   |

注意两点差异：

- **输出上限不同**：同一个 kimi 模型，果办能给到 128K 输出，码道只有 32K。需要一次性产出长文（长报告、长代码文件、整章翻译）时走果办渠道更合适。
- **模型名不完全一样**：果办的 kimi 是 `kimi-k3.1-pro-highspeed` 这一族，码道是 `kimi-k3.1-pro`。选模型时按各自目录里的名字来，不要照抄。

## 六、安装与使用

### 6.1 安装命令

```bash
magpie plugin add github:MYCF711/magpie-officeace
```

一条命令装完，**果办和码道两个 provider 会一起出现**，不需要分别安装。

### 6.2 登录

- 一个华为云账号即可，**果办与码道凭证互通，登录一次就够**。
- 登录在浏览器里完成（走华为云官方授权页面）。
- 插件到期前会**自动续期**，不需要手动重新登录。

### 6.3 多账号

- 加号用来**再加一个华为云账号**。
- 每个新账号在一个**一次性隔离窗口**里登录，账号之间互不串味。

### 6.4 模型目录

- 两个渠道的**模型目录各自独立**：果办 9 款模型、码道 10 款模型，各自列出、各自选择。
- 积分却是同一口径，可以合并看。

## 九、上手清单

1. 跑安装命令 `magpie plugin add github:MYCF711/magpie-officeace`。
2. 确认果办、码道两个 provider 都已出现。
3. 浏览器里用华为云账号登录一次，两边自动通。
4. 检查积分：果办应见 4,500，码道应见 10,600，合计 15,100。
5. 日常重活走 GLM-5.3-Flash / DeepSeek-V4.1-Flash（系数低、耐烧）；要长输出走果办（128K）。
6. 需要换号或加号时用加号开隔离窗口，别在同一个窗口里切。

## 十、需要留意的坑

- **8 亿 token 不是官方承诺**，是本地流水反推值，含缓存。做预算时按 8,000 万 token（不含缓存）打底更稳妥。
- **果办的额度花完就没了**（4,500 全是一次性）；码道每月还有 500 会重置。
- **输出长度要看渠道**：32K vs 128K 的差距在长文任务上会直接失败，不是慢一点的问题。
- **不支持图片输入**，OCR、看图、截图理解这类任务这套渠道做不了。
- 积分规则、活动细则、模型目录随时可能被华为云调整，以官方页面为准。
