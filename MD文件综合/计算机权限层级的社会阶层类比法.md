# 计算机权限层级的社会阶层类比法

> 整理日期：2026-10-25

## 一、总览：8 层权限金字塔

```
权限从高到低
┌─────────────────────────────────────────────┐
│  第 8 层  硬件管理引擎（Intel ME / AMD PSP）  │ ← 幕后控股方
├─────────────────────────────────────────────┤
│  第 7 层  固件层（BIOS / UEFI / SMM）        │ ← 董事会 / 公司章程
├─────────────────────────────────────────────┤
│  第 6 层  内核驱动程序（Kernel Drivers）     │ ← 技术总监 / 设备主管
├─────────────────────────────────────────────┤
│  第 5 层  操作系统内核（Kernel / Ring 0）    │ ← 总裁办 / CEO
├─────────────────────────────────────────────┤
│  第 4 层  系统服务进程（Services）           │ ← 常驻后勤（保安、IT 运维）
├─────────────────────────────────────────────┤
│  第 3 层  管理员用户态（Administrator）      │ ← 部门经理
├─────────────────────────────────────────────┤
│  第 2 层  普通用户态应用（User Apps）        │ ← 普通员工
├─────────────────────────────────────────────┤
│  第 1 层  沙盒层（Sandbox）                  │ ← 外包临时工
└─────────────────────────────────────────────┘
```

**核心规则**：
- **上层可以指挥下层，下层不能越权访问上层**（就像员工不能命令 CEO）
- **每一层有自己的「特权清单」**，超出范围就会被拦截（如普通员工不能进机房）
- **下层请求上层服务必须走「申请通道」**（系统调用 syscall，就像员工找经理审批）

## 二、逐层详解（从低到高）

### 第 1 层：沙盒层（Sandbox）

**公司角色**：外包临时工

| 项目 | 说明 |
|------|------|
| 是谁 | 浏览器标签页里的网页、UWP 应用、微信小程序、Docker 容器内的进程 |
| 拥有什么特权 | 只能在隔离的「工位」上干活，内存、文件、网络都被严格限制；不能碰系统任何东西 |
| 听命于谁 | 宿主应用（浏览器、容器引擎） |
| 典型行为 | 网页里的 JavaScript 只能操作自己的 DOM，不能读你硬盘上的文件 |
| 被谁监管 | 第 2 层（宿主程序）通过系统 API 给它划隔离边界 |

**类比**：外包临时工只能在指定的会议室里做分配的活，不能出会议室，不能碰公司电脑，连喝水都要找正式员工帮忙。

---

### 第 2 层：普通用户态应用（User Mode Applications）

**公司角色**：普通员工

| 项目 | 说明 |
|------|------|
| 是谁 | 记事本、浏览器、Word、你自己写的脚本等所有以普通用户身份运行的程序 |
| 拥有什么特权 | 可以读写当前用户目录（`C:\Users\xxx`）、启动子进程、用系统 API 申请资源；不能改系统目录、不能改注册表 HKLM、不能监听 1024 以下端口 |
| 听命于谁 | 第 5 层内核（通过 syscall 申请服务） |
| 典型行为 | 双击打开 Word 编辑文档、运行 `ping` 命令 |
| 被谁监管 | 内核通过「用户态 / 内核态」隔离（Ring 3 vs Ring 0），越界直接蓝屏或报错 |

**类比**：普通员工有自己的工位和电脑，能办公、能申请报销，但不能进机房、不能改公司制度、不能动其他员工的文件。

---

### 第 3 层：管理员用户态（Administrator User Mode）

**公司角色**：部门经理

| 项目 | 说明 |
|------|------|
| 是谁 | 以「管理员身份运行」的程序（UAC 提权后的 CMD、PowerShell、安装程序） |
| 拥有什么特权 | 可读写系统目录（`C:\Windows`）、修改注册表 HKLM、安装/卸载软件、启停服务、修改防火墙规则；但**仍在用户态（Ring 3）**，不能直接操作硬件 |
| 听命于谁 | 第 5 层内核 |
| 典型行为 | 安装驱动、修改系统服务、以管理员身份运行 `schtasks` 创建开机任务 |
| 被谁监管 | UAC（用户账户控制）审批 + 内核权限检查 |

**类比**：部门经理可以审批本部门预算、调配本部门资源，但不能直接操作公司服务器机房（那是 IT 运维的活），也不能修改公司章程。

> **注意**：管理员 ≠ 内核。管理员仍在 Ring 3，只是权限令牌更高，所有硬件操作仍需通过内核 syscall。

---

### 第 4 层：系统服务进程（Windows Services / Daemons）

**公司角色**：常驻后勤（保安、保洁、IT 运维值班）

| 项目 | 说明 |
|------|------|
| 是谁 | Windows 服务（如 `Spooler` 打印服务、`wuauserv` Windows Update）、Linux 守护进程（如 `sshd`、`nginx`） |
| 拥有什么特权 | 24 小时常驻运行，通常以 `SYSTEM`（Windows）或 `root`（Linux）身份运行，权限比管理员还高；可在用户未登录时运行，可访问所有用户数据 |
| 听命于谁 | 第 5 层内核 + 服务控制管理器（SCM） |
| 典型行为 | 系统启动时自动运行、接收网络请求、定时执行任务 |
| 被谁监管 | 服务控制管理器（SCM）/ systemd 管理启停；内核控制资源访问 |

**类比**：保安 24 小时值班，即使公司没人也在巡逻；IT 运维可以进出机房，但不能修改公司章程。

> **安全风险**：恶意软件如果注册成系统服务，就能以 SYSTEM 权限常驻，极难清除。

---

### 第 5 层：操作系统内核（Kernel Mode / Ring 0）

**公司角色**：总裁办 / CEO

| 项目 | 说明 |
|------|------|
| 是谁 | Windows 内核（`ntoskrnl.exe`）、Linux 内核（`vmlinuz`）、macOS XNU 内核 |
| 拥有什么特权 | 运行在 Ring 0，**掌控全机所有资源**：内存管理、进程调度、文件系统、网络协议栈、设备 I/O；可直接读写所有物理内存、直接与硬件通信 |
| 听命于谁 | 第 6 层驱动 + 第 7 层固件（启动时由固件加载） |
| 典型行为 | 分配内存、调度 CPU、响应 syscall、管理中断 |
| 被谁监管 | 硬件层面的 Ring 隔离（CPU 保护模式）；驱动需签名才能加载（PatchGuard） |

**类比**：CEO 掌控全公司资源分配，所有部门申请都要 CEO 审批；但 CEO 也不能修改公司章程（固件），也不能直接控制每台机器的底层电路（那是驱动+硬件的事）。

> **关键概念**：用户态程序（Ring 3）不能直接访问硬件，必须通过 syscall 陷入内核态，由内核代为执行。这就是「系统调用」。

---

### 第 6 层：内核驱动程序（Kernel Drivers）

**公司角色**：技术总监 / 设备主管

| 项目 | 说明 |
|------|------|
| 是谁 | 显卡驱动、网卡驱动、声卡驱动、杀毒软件内核驱动、虚拟设备驱动 |
| 拥有什么特权 | 运行在内核态（Ring 0），**直接操作硬件寄存器**，可拦截所有 I/O 请求（如过滤键盘输入、网络包）；可读写任意内核内存 |
| 听命于谁 | 第 5 层内核（由内核加载和管理） |
| 典型行为 | 显卡驱动把画面输出到显示器、杀毒驱动拦截文件读写 |
| 被谁监管 | 内核 + 驱动签名要求（Windows 需 WHQL 签名，64 位系统强制） |

**类比**：技术总监直接管理机房里的每台设备，能控制空调、电源、网络交换机；但技术总监是 CEO 任命的（内核加载），CEO 可以随时撤换。

> **安全风险**：恶意驱动 = 内核级 rootkit，可隐藏进程、隐藏文件、拦截键盘记录，杀毒软件极难发现。

---

### 第 7 层：固件层（Firmware / SMM）

**公司角色**：董事会 / 公司章程

| 项目 | 说明 |
|------|------|
| 是谁 | BIOS / UEFI、SMM（系统管理模式）、硬盘固件、网卡固件、TPM |
| 拥有什么特权 | **在操作系统启动之前就运行**，初始化硬件、加载内核；SMM 可在 CPU 最高权限模式下运行，连内核都感知不到；可持久化感染，即使重装系统也清除不了 |
| 听命于谁 | 第 8 层硬件管理引擎（部分功能）+ 硬件本身 |
| 典型行为 | 开机自检（POST）、选择启动设备、加载 bootloader → 内核 |
| 被谁监管 | 硬件厂商；用户可通过固件更新（刷 BIOS）修改，但需物理访问或特殊权限 |

**类比**：公司章程在公司成立时就定好了，CEO 是按章程选出来的；董事会可以修改章程，但那需要特殊程序（股东大会），日常运营中 CEO 改不了章程。

> **安全风险**：UEFI rootkit（如 LoJax）可在重装系统后依然存在，因为它藏在固件里，操作系统碰不到。

---

### 第 8 层：硬件管理引擎（Hardware Management Engine）

**公司角色**：幕后控股方 / 隐形老板

| 项目 | 说明 |
|------|------|
| 是谁 | Intel ME（Management Engine）、AMD PSP（Platform Security Processor）、服务器 BMC（Baseboard Management Controller）、苹果 T2 芯片 |
| 拥有什么特权 | **独立于主 CPU 的微控制器**，在主 CPU 上电前就运行，有自己的独立内核、内存、网络栈；可在主机关机状态下远程控制、监控、甚至重装系统；连操作系统内核都完全感知不到它的存在 |
| 听命于谁 | 硬件厂商（代码闭源，用户无法审计） |
| 典型行为 | 远程开关机、带外管理（vPro）、硬件级加密、DRM 保护 |
| 被谁监管 | 无（硬件厂商完全控制，用户无法禁用或审计） |

**类比**：幕后控股方从不露面，但能在公司关门后仍远程控制财务系统、监控所有邮件、随时换掉 CEO；连 CEO 都不知道他在干什么。

> **安全争议**：Intel ME 被广泛认为是「后门风险」，因为它运行在完全独立的环境中，拥有最高权限且代码闭源。安全研究人员已发现多个 ME 漏洞。

## 四、关键结论

1. **权限是单向的**：上层可以向下访问，下层不能向上访问。员工不能命令 CEO，CEO 不能改公司章程。

2. **提权必须有「审批点」**：
   - 普通员工 → 部门经理：UAC 弹窗确认
   - 部门经理 → 总裁办：syscall 系统调用
   - 总裁办 → 技术总监：内核加载驱动（需签名）
   - 技术总监 → 董事会：刷 BIOS（需物理访问）
   - 董事会 → 幕后控股方：无（用户无法触及）

3. **越往下越安全，越往上越危险**：
   - 沙盒被攻破：只影响一个标签页
   - 用户态被攻破：只影响当前用户数据
   - 管理员被攻破：影响整台机器
   - 内核被攻破：整台机器完全沦陷
   - 固件被攻破：重装系统也没用
   - ME 被攻破：物理销毁硬盘都不一定安全

4. **防御的核心思路**：让攻击尽量停留在低层。这就是为什么有「最小权限原则」「沙盒隔离」「驱动签名」「Secure Boot」等机制。

5. **一句话记忆**：
   > 外包工（沙盒）→ 员工（用户态）→ 经理（管理员）→ 后勤（服务）→ CEO（内核）→ 技术总监（驱动）→ 董事会（固件）→ 幕后老板（ME）。
   > 越往上权力越大，越往下越安全；要提权必须过审批，最高层连 CEO 都管不了。
