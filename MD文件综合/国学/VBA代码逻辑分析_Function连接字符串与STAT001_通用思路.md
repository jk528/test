## 一、Function_连接字符串.bas 逻辑分析

### 1.1 整体定位与数据流

这是一个「**单元格区域 → 一维数值序列 → 字符串/统计特征**」的工具库。所有函数共享一条数据流：

```
单元格区域(rng)
   │
   ▼  CollectNumbers（统一入口）
一维数值数组 vals（0 基 Double）
   │
   ├─→ 连接            → 字符串 "12345"
   ├─→ 相邻差绝对值求和  → 数值 4
   ├─→ 相邻差绝对值数组  → 数组 {1,1,1,1}
   ├─→ 环形相邻差求和    → 数值 8
   ├─→ 环形相邻计数      → 数值 5
   ├─→ 环形相邻判定数组  → 布尔数组 {T,T,T,T,T}
   ├─→ 是否连续序列      → 布尔 True
   └─→ 相邻差统计        → 数组 {max,min,avg,sum,count}
```

**关键设计**：9 个公开函数里有 8 个都先调 `CollectNumbers`，把五花八门的输入（任意矩形区域、行/列优先、含空/非数字）**统一归一化成一维数值数组**，下游逻辑只处理这一种标准结构。

### 1.2 核心设计一：两遍扫描性能优化

`连接` 和 `CollectNumbers` 都用了同一种模式——**先计数定容，再收集填充**：

```vba
' 第一遍：只计数，不存数据
count = 0
For Each cell In rng.Cells
    If Not (skipEmpty And CStr(cell.Value) = "") Then count = count + 1
Next

' 第二遍：一次性 ReDim 定容后收集
ReDim parts(1 To count)
For Each cell In rng.Cells
    ... parts(i) = CStr(cell.Value)
Next
连接 = Join(parts, sep)          ' 最后一次性 Join
```

**为什么这样做**：VBA 里循环内 `ReDim Preserve` 每次都会复制整个数组，O(n²)。两遍扫描把它降成 O(n)，最后用 `Join` 一次性拼接（远快于 `s = s & cell` 循环）。

> 这是 VBA/老语言处理动态集合的经典手法，在 JS/Python 里可用 `push` 自动扩容替代，但「先估算容量再填充」的思路在性能敏感场景依然有效。

### 1.3 核心设计二：线性 / 环形的参数化对称

模块把「相邻」分成两种，用**同一套代码 + 一个布尔开关**切换，而不是复制两份：

| | 线性 | 环形 |
|---|---|---|
| 相邻对数 | n−1 | n |
| 首尾对 | 不计 | `|vals(last) − vals(first)|` |
| 触发函数 | `相邻差绝对值求和`、`相邻差统计(circular:=False)` | `环形相邻差绝对值求和`、`环形相邻计数`、`相邻差统计(circular:=True)` |

`相邻差统计` 的实现最能体现这种对称：

```vba
If circular Then diffCount = n Else diffCount = n - 1
' 线性部分
For i = LBound To UBound - 1: diffs(di) = Abs(vals(i)-vals(i+1)): di=di+1: Next
If circular Then diffs(di) = Abs(vals(last) - vals(first))   ' 环形只多这一行
```

**可迁移思路**：找出两个变体的「差异点」（这里是首尾那一对），用参数控制是否执行差异部分，共享主体代码。

### 1.4 核心设计三：连续序列的 O(n) 判定

`是否连续序列` 判断一个序列是不是 `min..max` 的排列（无重复无缺失），**没有排序**：

```vba
' 条件1：max - min + 1 = n（值域跨度等于元素个数）
If vMax - vMin + 1 <> n Then Return False

' 条件2：无重复（用 seen 数组按值偏移索引，O(n) 查重）
ReDim seen(0 To n - 1)
For i = ... 
    idx = CLng(vals(i) - vMin)        ' 值映射到 0..n-1
    If seen(idx) Then Return False    ' 重复
    seen(idx) = True
Next
Return True
```

**巧妙之处**：条件1保证了值域正好是 n 个连续整数，条件2用「值偏移做下标」的 seen 数组在 O(n) 内判重——比「排序后检查相邻差=1」（O(n log n)）更快。

> 五行模型里「检测一个候选排列是不是合法的层」可以直接用这个函数：合法层 = 0..n−1 的排列 = 连续序列。

### 1.5 核心设计四：环形相邻计数的图论本质

`环形相邻计数` 是两个文件的连接点（STAT_001 复用了它的数组版）。规则：

```
diff = max - min
对每对环形相邻 (a, b)：若 |a-b| = 1 或 |a-b| = diff，则计数 +1
```

**图论解释**（见《STAT_环形相邻词频_公式推导》）：把排列看成 n 个节点的一个 Hamilton 圈，定义参考圈 C_n = 边集 {i—i+1} ∪ {0—(n−1)}。那么 `环形相邻计数` = 该排列的圈与参考圈 C_n **共享的边数**。

- 计数 = n → 排列就是参考圈本身（或其逆）→ **满分**
- 计数 = 0 → 与参考圈无公共边 → **零分**
- 中间值 → 部分重合

脚本验证（n=5，与 STAT_001 文件头一致）：

```
120 个全排列的环形相邻计数分布：
  计数=0 → 10 次   （零分排列）
  计数=2 → 50 次
  计数=3 → 50 次
  计数=5 → 10 次   （满分排列：12345 和 54321 及其旋转）
  合计 = 120 = 5!
```

### 1.6 核心设计五：边界前置防御

每个公开函数开头都有统一的「快速失败」检查：

```vba
If IsEmpty(vals) Then Return 空/0     ' 输入为空
If n < 2 Then Return 空/0              ' 元素不足（相邻至少要 2 个）
```

`连接` 还特判了 `count = 0`（全空区域）。这种**边界前置**让主逻辑不需要处理异常输入，代码更干净。

## 二、STAT_001 逻辑分析

### 2.1 整体定位：一条四步统计流水线

文件头把算法链路写得很清楚：

```
步骤1：Heap 全排列生成        （O(n!)，原地交换，无重复）
步骤2：每个排列 → 环形相邻计数  （特征提取，复用 Function_连接字符串）
步骤3：Dictionary 词频统计     （{特征值 => 出现次数}）
步骤4：排序输出到工作表        （计数值升序，含占比）
```

主函数 `全排列环形词频统计` 只有 3 行核心逻辑：

```vba
Set freq = CreateObject("Scripting.Dictionary")
Call 全排列_HeapCallBack(nums, freq, totalCount)   ' 步骤 1+2+3
全排列环形词频统计 = DictToSortedArray(freq, totalCount, outputCols)  ' 步骤 4
```

### 2.2 核心设计一：生成-回调-流式统计（不存全量）

这是 STAT_001 最关键的架构决策。面对 n! 爆炸（n=8 就有 40320，n=10 达 362 万），**绝不把所有排列存进数组**，而是每生成一个就立刻处理：

```vba
Private Sub 全排列_HeapCallBack(nums, freq, totalCount)
    ...
    Call ProcessOnePerm(nums, freq, totalCount)   ' 生成一个 → 立刻算特征、累加字典
    Do While i < n
        ...交换...
        Call ProcessOnePerm(nums, freq, totalCount)   ' 每次交换后生成新排列 → 立刻处理
        ...
    Loop
End Sub

Private Sub ProcessOnePerm(arr, freq, totalCount)
    cnt = 环形相邻计数_数组(arr)        ' 步骤2：算特征
    If freq.Exists(cnt) Then freq(cnt)=freq(cnt)+1 Else freq.Add cnt,1   ' 步骤3：累加
    totalCount = totalCount + 1
End Sub
```

**内存峰值** = 频率字典的大小（n=5 时只有 4 个 key：0/2/3/5），而不是 120 个排列。这让 n 可以推到 8 甚至更高。

### 2.3 核心设计二：Heap 全排列（原地交换）

`全排列_HeapCallBack` 用了 **Heap 算法**，比 PC_002/PC_004 的递归 used 标记更省空间（O(n) 空间，无需 used 数组）：

```vba
Dim c(0 To n-1) As Long    ' Heap 的计数器数组，初始全 0
Call ProcessOnePerm(nums, ...)   ' 初始排列
i = 0
Do While i < n
    If c(i) < i Then
        ' 偶数 i：交换 0 和 i；奇数 i：交换 c(i) 和 i
        If i Mod 2 = 0 Then j = 0 Else j = c(i)
        swap nums(i), nums(j)
        Call ProcessOnePerm(nums, ...)
        c(i) = c(i) + 1
        i = 0          ' 重置，从头扫描
    Else
        c(i) = 0
        i = i + 1
    End If
Loop
```

**特点**：原地交换、无重复、恰好生成 n! 个。每次交换只动 2 个元素，是生成全排列的最优算法之一。

### 2.4 核心设计三：Dictionary 频率计数器 + 排序输出

```vba
' 计数：Exists 判存 → 累加或新增
If freq.Exists(cnt) Then freq(cnt) = freq(cnt)+1 Else freq.Add cnt, 1

' 输出：先排序 keys，再组装二维数组
keys = freq.Keys
' 冒泡排序 keys（key 数量少，冒泡足够）
For i... For j... If keys(i) > keys(j) Then swap
' 输出 3 列：特征值 / 次数 / 占比
result(r,1) = keys(i)
result(r,2) = freq(keys(i))
result(r,3) = freq(keys(i)) / totalCount    ' 占比
```

**输出三段式**：特征值（x 轴）→ 次数（绝对量）→ 占比（相对量），是通用统计报表的标准列结构。

### 2.5 核心设计四：批量对比 + 自验证

`批量生成_N1到N` 对 N=1..MaxN 各自跑一遍统计，拼成**横向对比表**（列=N，行=特征值），最后加合计行用 `=SUM(...)` 公式。

`全排列总数(N)` = N!，用于核对「频率合计 = N!」——这是一个内置的**正确性自检验证**：如果分布加起来不等于 N!，说明生成或计数有 bug。

## 三、两者关系：特征提取 + 统计聚合的两层架构

两个文件不是孤立的，而是一条清晰的**两层流水线**：

```
┌─────────────────────────────────────────────┐
│  上层：STAT_001（统计聚合层）                  │
│  枚举所有对象 → 提取特征 → 词频统计 → 报表输出   │
│                                              │
│         调用 ↓                                │
│  环形相邻计数_数组（= 下层函数的数组版）        │
└─────────────────────────────────────────────┘
         调用 ↑
┌─────────────────────────────────────────────┐
│  下层：Function_连接字符串（特征提取层）        │
│  区域 → 一维数组 → 单个序列的特征值/字符串       │
│  （连接、相邻差、环形计数、连续序列判定…）        │
└─────────────────────────────────────────────┘
```

**职责分离**：
- **下层**只关心「一个序列长什么样」——输入一个序列，输出它的特征（字符串、差值、是否连续、环形计数）。
- **上层**只关心「一群序列的特征如何分布」——枚举序列、调下层取特征、统计频率。

> STAT_001 注释明确写了：`环形相邻计数_数组` 的「逻辑与 Function_连接字符串.bas 中的 环形相邻计数 完全一致」——它只是把「吃单元格区域」改成「吃数组」，以便在上层循环里高效调用（避免每次都经过单元格）。

## 四、可借鉴的通用思路（不依赖具体业务）

下面 10 条是从两个文件提炼的、可迁移到任意项目的编程模式：

### 思路 1：统一输入归一化
所有函数先把异构输入（不同区域形状、行/列优先、含空值）归一化成**一种标准结构**（一维数组），下游逻辑只处理标准结构。→ 避免每个函数都重复写输入解析。

### 思路 2：两遍扫描（先计数定容，再收集填充）
对动态集合，先遍历计数确定大小，再 `ReDim` 一次填充。→ 避免循环内 `ReDim Preserve` 的 O(n²) 复制。适用 VBA/C 等手动管理数组的语言；高级语言里对应「预估容量 + 预分配」。

### 思路 3：变体用参数开关，不复制代码
线性/环形只差「首尾那一对」，用 `circular` 布尔控制差异部分，主体共享。→ 找变体间的「差异点」，参数化它，而非整段复制。

### 思路 4：边界前置，快速失败
每个公开函数开头统一检查空输入、元素不足，直接返回默认值。→ 主逻辑不被异常分支污染。

### 思路 5：O(n) 判重 / 判连续
用「值偏移做下标」的布尔数组（`seen[val-min]=True`）在 O(n) 内判重，配合 `max-min+1=n` 判断连续，无需排序。→ 值域连续时的高效技巧。

### 思路 6：生成-回调-流式统计（处理爆炸型枚举）
面对 n!、2ⁿ 这类爆炸空间，**边生成边统计，不存全量**。内存峰值 = 统计结构大小，而非对象总数。→ 让枚举上限从「内存装不下」推到「时间耗得起」。

### 思路 7：原地交换生成全排列（Heap 算法）
用 O(n) 空间原地生成 n! 个无重复排列，每次只交换 2 元素。→ 比递归 + used 标记更省内存，适合大规模枚举。

### 思路 8：Dictionary 频率计数器 + 三段式输出
`Exists(key)` 判存 → 累加/新增；输出时排序 key，输出 `{特征值, 次数, 占比}` 三列。→ 通用词频统计的标准模板，任何「枚举对象 → 统计特征分布」的问题都能套。

### 思路 9：批量参数扫描 + 横向对比表
对参数 N=1..MaxN 各跑一遍，结果拼成横向表（列=参数，行=特征）。→ 发现跨参数的规律（如「频率分布如何随 n 变化」）。

### 思路 10：内置正确性自验证
用独立公式（如 N!）核对统计结果的合计。→ 代码自带「我算对了吗」的检查，不是靠外部测试。

## 五、总结

| 文件 | 角色 | 核心价值 |
|---|---|---|
| **Function_连接字符串** | 特征提取层 | 区域→数组的统一归一化；线性/环形对称特征；连续序列与环形计数的高效判定 |
| **STAT_001** | 统计聚合层 | Heap 全排列 + 流式 Dictionary 统计 + 排序报表 + 批量对比 |
| **两者合起来** | 完整统计流水线 | 枚举对象 → 提取特征 → 词频分布 → 报表，外加自验证 |

> **一句话**：这两个文件合起来是一个「**枚举 → 特征 → 频率**」的通用统计引擎。Function_连接字符串负责把单个对象变成可比较的特征，STAT_001 负责对一群对象的特征做分布统计——中间靠 `环形相邻计数` 这个图论特征连接。这套架构不绑定五行或词频，任何「对大量组合对象统计某特征分布」的问题都能直接套用。
