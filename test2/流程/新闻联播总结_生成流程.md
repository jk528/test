## 第零步：前置检查与容错机制

> 本步骤在任何数据采集或报告生成之前执行，确保自动化任务稳定可靠。

### 0.1 文件存在性与完整性检查

| 检查项 | 条件 | 处理方式 |
|--------|------|---------|
| 文件不存在 | 目标日期的 `新闻联播总结_YYYYMMDD.md` 不存在 | 正常执行全流程 |
| 文件存在且>10KB | 文件已存在且大小超过10KB | **跳过不重复生成**，避免浪费资源 |
| 文件存在且≤10KB | 文件存在但内容不完整（上次生成中断） | **覆盖重新生成**，并记录"修复上次失败文件" |

### 0.2 生成中断恢复

若检测到≤10KB的不完整文件，按以下流程恢复：

```
检测到不完整文件 → 删除该文件 → 按正常流程从头重新生成
```

**禁止**：在已有不完整文件上追加内容（会导致重复标题、结构混乱）。

### 0.3 输出要求

- 生成完成后**必须输出 `computer://` 文件链接**，确保用户和自动化系统可确认文件已生成
- 若生成过程中遇到无法恢复的错误（如央视网页面完全无法访问），输出明确的失败说明，**不留下空文件或仅含标题的骨架文件**

### 0.4 排查机制

- 检查目标日期是否为未来日期（不应超过当前日期前一天）
- 检查文件大小是否在正常范围（18-35KB），≤10KB视为异常
- 若自动任务连续2天无文件生成 → 标记"自动化任务异常"，需人工检查

## 第一步：确定日期

1. 默认取"昨晚"的新闻联播（当前日期的前一天）
2. **19:00动态判断**：若当前时间在当天19:00之前，则新闻联播尚未播出，应取前一天的（即当前日期的前两天）；若当前时间在19:00及之后，取前一天
   - 示例：当前为6月26日15:00（19:00前）→ 目标日期为6月24日
   - 示例：当前为6月26日20:00（19:00后）→ 目标日期为6月25日
3. 用户指定日期时以用户为准

**排查机制**：
- 检查日期是否为未来日期（不应超过当前日期）
- 检查日期格式是否正确（YYYY年M月D日）

## 第二步：访问央视网并提取视频列表

### 2.1 使用Python脚本提取（辅助工具，需人工复核）

运行同目录下的 `fetch_xwlb.py` 脚本获取初始数据：

```bash
python fetch_xwlb.py 20260624 xwlb_20260624.json
```

脚本通过 `requests` 解析央视网页面源码，提取标题、时长和URL列表。输出包含：
- 当天央视网页面中匹配到的全部视频条目（数量不固定，通常12-18条）
- 每条视频的标题、时长、独立URL
- JSON配置文件和Markdown表格

**脚本特性与限制**：
- 基于正则匹配 `<li>` + `<a href>` 结构提取，依赖央视网当前HTML格式
- 无需JavaScript渲染，直接解析源码
- **不自动去除任何标题前缀**（完整版保留原样，由人工判断是否单独列出）
- 自动去重，但无法验证是否遗漏条目
- **仅提取央视网数据**，不包含齐鲁网等第三方来源

### 2.2 人工复核与多源交叉验证（必需）

脚本输出**必须经过人工复核**，步骤如下：

1. **核对条数**：对比脚本输出与央视网页面实际显示的条目数，确认无遗漏
2. **核对完整版**：确认脚本是否正确识别完整版视频（标题通常含"完整版"），在报告中单独列出
3. **核对独立URL**：点击每条链接验证是否为独立视频页面，非目录页
4. **齐鲁网补充**：通过齐鲁网索引页获取当天所有新闻（含快讯子条目）的独立页面链接，详见2.3节

### 2.3 齐鲁网索引页获取链接（核心方法）

> **关键规则**：齐鲁网索引页已包含当天全部新闻的独立页面链接（常规新闻 + 快讯子条目），无需逐个URL猜测或搜索。

**访问规则**：
1. **URL格式必须使用 `.html` 后缀**：`https://v.iqilu.com/jcdb/ysxwlb/index_N.html`（**禁止使用 `.shtml`，会返回空页面**）
2. **索引页与日期对应关系**：每个索引页包含约2天的内容（约40-50条链接），需定位到包含目标日期的索引页
3. **从首页开始翻页查找**：访问 `index.html`（第1页）获取最新日期，根据分页导航定位目标日期所在页

**索引页定位方法**：
- 首页 `index.html`：最新日期（约前1-2天）
- `index_1.html`：往前推2-3天
- 依此类推，每页约2天内容
- 示例（2026年7月时点）：`index_25.html` 含6月2-3日，`index_26.html` 含5月30-31日

**完整版锚点法（核心定位逻辑）**：

> 索引页中**"YYYY年MM月DD日中央新闻联播完整版"**是天然的日期分隔锚点。**必须同时定位两端完整版**，两端之间的子条目归属较早完整版对应的日期。

**锚点定位规则**：
1. 索引页按时间倒序排列（最新在上），完整版条目标题格式固定为 `YYYY年MM月DD日中央新闻联播完整版`
2. **每个完整版包含两部分**："总"（完整版本身）+ "子条目"（该日期的所有分条新闻）
3. **必须同时定位两端完整版**，确定目标日期的子条目范围：
   - **上边界完整版**（较新日期，页面上方）→ 其子条目在该完整版**上方**
   - **下边界完整版**（较旧日期，页面下方）→ 其子条目在两个完整版**之间**
4. **两端完整版确定日期区间**：如上边界=6月2日完整版，下边界=6月1日完整版，则区间包含1日和2日

**实际示例（index_25.html结构）**：
```
页面顶部（最新）
  ── 6月3日子条目（总+子条目）           ← 上边界完整版（6月2日）上方 → 归属6月3日
  ── 【2026年06月02日中央新闻联播完整版】  ← 上边界锚点（6月2日的"总"）
  ── 6月2日子条目                        ← 两端之间 → 归属6月2日的"子条目"
  ── 【2026年06月01日中央新闻联播完整版】  ← 下边界锚点（6月1日的"总"）
  ── 6月1日子条目                        ← 下边界下方 → 归属6月1日的"子条目"
页面底部（较旧）
```

**核心理解**：
- 每天的内容结构 = **1个完整版（总）+ N个子条目**
- 完整版（总）是其下方所有子条目的归属标记
- 定位两端完整版 → 就能确定包含哪些日期的子条目
- 例：区间 [6月2日完整版, 6月1日完整版] → 包含6月2日和6月1日的全部子条目

**核心流程：从索引页提取链接（必须定位两端完整版）**：
1. 访问对应索引页（如目标日期为6月2日 → 访问 `index_25.html`）
2. **第一步：扫描全页，列出所有完整版锚点（总）**
   - 找到页面上所有 `YYYY年MM月DD日中央新闻联播完整版` 条目
   - 每个完整版锚点代表一天的"总"，其下方紧跟着该天的"子条目"
3. **第二步：定位两端，确定目标日期的子条目范围**
   - 找到目标日期D的完整版锚点（总D）
   - 找到相邻的下边界完整版锚点（总D-1）
   - 总D 与 总D-1 之间的所有子条目 → 归属日期D
   - 总D 本身即为日期D的完整版链接
   - 总D 上方的子条目 → 归属比D更新的日期
4. **第三步：逐一匹配**
   - 将提取的子条目标题与央视网视频列表逐一匹配，确认一一对应
   - 提取每条对应的独立页面URL（格式：`https://v.iqilu.com/jcdb/ysxwlb/YYYYMM/DD/XXXXXX.html`）
5. **第四步：验证覆盖率**
   - 对比齐鲁网提取数与央视网视频列表数
   - 若齐鲁网已100%覆盖 → 完成
   - 若齐鲁网缺失部分子条目 → 启用降级逻辑（见下方降级策略）

**降级策略（仅在锚点法匹配不完整时启用）**：
1. **检查相邻索引页**：若目标日期的完整版不在当前索引页，访问上一页（index_N+1.html）或下一页（index_N-1.html）查找
2. **site搜索补全**：对锚点法未覆盖的子条目，使用 `site:v.iqilu.com 子条目标题关键词` 搜索独立页面
3. **央视网降级**：若搜索仍无结果，使用央视网快讯目录链接并标注"齐鲁网无独立页面，降级处理"
4. **禁止逐个URL猜测**——仅在上述步骤均失败后才考虑

**注意事项**：
- **两端完整版缺一不可**：只定位一端会导致日期归属错误或子条目遗漏
- **WebFetch可能截断页面顶部内容**：WebFetch工具不一定返回完整HTML，可能漏掉页面最顶部的条目和完整版锚点。**必须使用浏览器渲染（browser_navigate + browser_snapshot）获取完整页面内容**，或交叉验证WebFetch结果是否包含完整版锚点
- 索引页按时间倒序排列，最新日期在最上方
- 每天结构固定为"1总（完整版）+ N子条目"，完整版是子条目的归属标记
- 若页面顶部无完整版标题，说明顶部子条目属于比第一个（最上方）完整版更新的日期
- 若页面底部无完整版标题，说明底部子条目属于比最后一个完整版更旧的日期
- 索引页中【联播快讯】前缀的条目即为快讯子条目的独立页面，无需额外搜索
- **齐鲁网覆盖率判定必须基于完整页面内容**：若WebFetch未显示完整版锚点，不可直接判定"齐鲁网无完整版"，必须通过浏览器渲染确认

### 2.4 排查机制

- 检查页面是否加载成功（HTTP状态码200）
- 检查是否找到对应日期的内容
- **检查提取的标题数量是否与页面实际显示一致**（不预设固定数量，以页面为准）
- **检查完整版是否正确识别并单独标注**
- **检查每条新闻是否提取到独立的视频URL**（不可多条新闻共用同一个URL）
- 若脚本输出条数与页面实际条数不一致 → 标记"数据遗漏异常"，切换至手动提取
- 若标题数量 < 10条 → 标记"数据异常"，尝试重新运行脚本或检查日期
- 若脚本运行失败 → 使用手动提取兜底

## 第三步：提取视频信息（含独立视频URL）

从央视网页面提取：

| 信息项 | 说明 |
|--------|------|
| 新闻标题 | 每条视频的完整标题（含[视频]前缀） |
| 视频时长 | 格式为 HH:MM:SS |
| 总时长 | 完整版视频的总时长 |
| **独立视频URL** | **每条新闻对应的独立央视网视频页面地址** |
| **完整版URL** | **完整版《新闻联播》的视频页面地址** |

**URL提取规则**：
1. 从 `https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml` 页面提取
2. 每条新闻（含完整版）都应有独立的URL
3. URL格式：`https://tv.cctv.com/{YYYY}/{MM}/{DD}/VIDE{GUID}{YYMMDD}.shtml`
4. **同一条新闻不可出现在多个条目中**
5. **不同新闻条目不可共用同一个URL**

**排查机制**：
- 检查每条视频时长是否为有效时间格式（HH:MM:SS）
- 检查总时长是否在 **25-35分钟** 范围内
- 检查是否有重复标题（去重处理）
- **检查URL唯一性**：提取所有URL，若存在重复URL，标记为"URL重复异常"
- **检查URL格式**：确保URL符合 `https://tv.cctv.com/YYYY/MM/DD/VIDE...` 格式
- **检查URL完整性**：确保每条新闻（不含快讯子条目）都有独立URL
- 若总时长 < 25分钟或 > 35分钟，标记为"时长异常"

## 第四步：计算播放时间

1. 第一条开始时间固定为 **19:00:00**
2. 每条结束时间 = 上一条结束时间 + 本条时长
3. 最后一条结束后到19:30:00为片尾时段
4. 验证总时长是否在 **25-35分钟** 范围内

**排查机制**：
- 检查播放时间是否连续无断裂（每条结束时间 = 下一条开始时间）
- 检查最后一条结束时间是否接近19:30:00（允许±2分钟误差）
- 检查片尾时长是否在1-3分钟范围内
- 若时间断裂，标记断裂位置并排查原因

## 第五步：识别快讯目录

从视频分条中识别目录条目（仅标记哪些是目录，子条目数量在第六步搜索后确定）：

- **"国内联播快讯"** → 记录为目录，非独立新闻
- **"国际联播快讯"** → 记录为目录，非独立新闻

**排查机制**：
- 检查是否识别到"国内联播快讯"目录（通常有，偶尔无）
- 检查是否识别到"国际联播快讯"目录（通常有，偶尔无）
- 检查快讯目录的时长是否合理（2-4分钟）
- 若未识别到快讯目录，标记为"快讯缺失"，需手动检查页面
- **注意**：此步骤仅识别目录条目本身，目录内含多少条子快讯需在第六步搜索后确定

**快讯子条目数量验证（关键）**：
- **禁止仅凭齐鲁网分条数量确定快讯子条目数**：齐鲁网并非每天都将所有快讯子条目拆分为独立页面，可能只拆分部分子条目（甚至完全不拆分）
- **必须以央视网视频页面内容为准**：访问国内/国际联播快讯的央视网视频页面（如 `https://tv.cctv.com/YYYY/MM/DD/VIDE{GUID}{YYMMDD}.shtml`），页面中会列出完整的子快讯内容（如"（1）审计署...（2）前五个月...（3）中国超算...（4）今年前五个月..."）
- **央视网与齐鲁网互相验证机制（通过索引页）**：
  - **第一步（确定基准）**：访问央视网快讯视频页面，提取子条目列表（基准数量B，基准标题列表T1...Tn）
  - **第二步（索引页匹配）**：访问包含目标日期的齐鲁网索引页（`index_N.html`，详见2.3节），提取当天所有【联播快讯】前缀条目的独立页面链接（齐鲁网索引页覆盖数Q）
  - **第三步（比对与告警）**：
    - 若 Q = B（每条央视网子条目都在索引页找到对应齐鲁网独立页面）→ 正常，全部使用齐鲁网链接
    - 若 Q < B（部分央视网子条目在索引页无对应页面）→ 告警"齐鲁网缺失N条"，对缺失条目先执行 `site:v.iqilu.com` 搜索补全，仍无结果则使用央视网快讯目录链接并标注"齐鲁网无独立页面"
    - 若 Q > B（齐鲁网有央视网未列出的条目）→ 告警"齐鲁网多出N条"，需回查央视网视频页面确认是否遗漏
    - 若 B = 0（央视网视频页面无法访问或无内容）→ 告警"央视网信息缺失"，以齐鲁网索引页分条数为准
  - **第四步（最终确认）**：生成验证报告表格，确认每条子条目对应的链接来源
- **验证报告表格格式**（附在第四部分联播快讯详解末尾）：

| 子条目 | 标题 | 央视网基准 | 齐鲁网索引页 | 齐鲁网搜索 | 最终链接来源 |
|--------|------|-----------|-------------|-----------|-------------|
| 12-1 | 审计署... | 有 | 有 | — | 齐鲁网独立页面 |
| 12-2 | 财政收入... | 有 | 有 | — | 齐鲁网独立页面 |
| 12-3 | 超算灵晟... | 有 | 有 | — | 齐鲁网独立页面 |
| 12-4 | 广告违法... | 有 | 无 | 无 | 央视网目录链接（齐鲁网无独立页面） |

## 第六步：搜索新闻详情

对每条标题进行网络搜索，获取文字内容：

**搜索优先级（兜底策略）**：
1. **优先搜索**：`新闻联播 YYYY年M月D日 要闻N条 整理` — 一次性获取全部新闻摘要和快讯子条目
2. **补充搜索**：`新闻联播 YYYY年M月D日 标题 主要内容` — 对重点新闻获取更详细内容
3. **专项搜索**：`国内联播快讯 YYYY年M月D日 具体内容` 和 `国际联播快讯 YYYY年M月D日 具体内容` — 展开快讯子条目

**推荐来源与链接模板**：

### 国内联播快讯来源（每条子条目应链接至独立页面）

| 来源类型 | 来源名称 | 典型URL/搜索关键词 | 适用子条目 |
|----------|----------|-------------------|-----------|
| 部委官网 | 审计署官网 | `https://www.audit.gov.cn/...` | 审计工作报告 |
| 部委官网 | 财政部官网 | `https://www.mof.gov.cn/...` | 财政收支数据 |
| 财经媒体 | 新浪财经 | `finance.sina.com.cn/...` | 经济数据、政策解读 |
| 央媒报道 | 央视网/中新网 | `news.cctv.com`、`chinanews.com` | 科技成就、社会新闻 |
| 行业媒体 | 今日头条/搜狐 | `toutiao.com`、`sohu.com` | 发布会实录、专题报道 |
| 地方媒体 | 齐鲁网（备用） | `v.iqilu.com/jcdb/ysxwlb/YYYYMMDD/...` | 完整快讯汇总页 |

### 国际联播快讯来源（每条子条目应链接至独立页面）

| 来源类型 | 来源名称 | 典型URL/搜索关键词 | 适用子条目 |
|----------|----------|-------------------|-----------|
| 央视网国际 | 央视网新闻 | `news.cctv.com/.../ARTI...` | 国际热点、外交新闻 |
| 国际媒体 | 齐鲁网国际 | `v.iqilu.com/jcdb/ysxwlb/YYYYMMDD/...` | 单条国际快讯 |
| 通讯社 | 新华社/中新网 | `xinhuanet.com`、`chinanews.com` | 国际冲突、灾害 |
| 外媒引用 | 俄卫星社/RT | 搜索关键词+日期 | 俄乌、中东议题 |

**快讯子条目链接规范**：
- **禁止多条子条目共用同一URL**：国内4条、国际3条必须分别指向不同页面
- **优先使用齐鲁网独立页面**：每条子条目标题链接必须指向齐鲁网独立页面，一一对应
- **齐鲁网独立页面查找方法（通过索引页，详见2.3节）**：
  1. 定位包含目标日期的齐鲁网索引页（`index_N.html`格式，**必须用`.html`后缀**）
  2. 索引页中已列出当天所有条目的独立页面链接，包括【联播快讯】前缀的快讯子条目
  3. 将索引页条目与央视网快讯视频页面中的子条目标题逐一匹配，提取对应URL
  4. **无需逐个URL猜测或使用 `site:v.iqilu.com` 搜索**——索引页已包含全部链接
  5. 若索引页中确实缺失某条目（极少数情况），再使用 `site:v.iqilu.com 子条目标题关键词` 搜索补全
- **降级条件与标注**：只有索引页和搜索均确认无独立页面时，才允许使用央视网快讯目录链接，并在链接后备注"齐鲁网无独立页面，降级处理"
- **链接格式示例**：
  - 审计报告 → `https://v.iqilu.com/jcdb/ysxwlb/202606/24/5908777.html`（齐鲁网独立页面）
  - 财政收入 → `https://v.iqilu.com/jcdb/ysxwlb/202606/24/5908779.html`（齐鲁网独立页面，需搜索找到）
  - 超算报道 → `https://v.iqilu.com/jcdb/ysxwlb/202606/24/5908781.html`（齐鲁网独立页面，需搜索找到）
  - 国际和谈 → `https://v.iqilu.com/jcdb/ysxwlb/202606/24/5908787.html`（齐鲁网独立页面）

**排查机制**：
- 检查每条新闻是否搜索到至少1个有效来源
- 检查快讯子条目是否全部展开（数量以当天实际播出为准，无固定范围）
- **快讯子条目数量异常验证**：
  - 若国内/国际快讯子条目数为0，标记为"快讯缺失异常"
  - 若快讯子条目数与央视网/齐鲁网显示不一致，标记为"快讯数量异常"
  - 异常时需手动核对页面实际内容，确认是否遗漏
- **快讯链接重复验证**：
  - 提取国内/国际快讯所有子条目的URL
  - 若存在重复URL（2条及以上子条目指向同一页面），标记为"快讯链接重复异常"
  - 处理方式：对重复子条目使用 `site:v.iqilu.com 子条目标题关键词` 搜索齐鲁网独立页面
- **齐鲁网链接覆盖率验证**：
  - 统计快讯子条目中使用齐鲁网链接的数量，应等于子条目总数
  - 若某子条目未使用齐鲁网链接，检查是否已执行 `site:v.iqilu.com` 搜索
  - 若未执行搜索 → 必须先搜索，搜索无结果后才能降级
- **互相验证告警处理**：
  - 收到"齐鲁网缺失N条"告警 → 对缺失子条目执行 `site:v.iqilu.com` 搜索补全，仍无结果则使用央视网目录链接降级
  - 收到"齐鲁网多出N条"告警 → 回查央视网视频页面，确认是否央视网遗漏了该子条目，若是则补充到基准列表
  - 收到"央视网信息缺失"告警 → 以齐鲁网分条列表为基准，但需标注"央视网页面不可用，以齐鲁网为准"
- 检查是否有新闻完全无搜索结果（标记为"信息缺失"）
- 若信息缺失 > 3条，标记为"搜索异常"，尝试更换搜索关键词

## 第八步：统计条数

**前提**：此步骤需要第五步识别的目录数（D）和第六步搜索得到的子条目数（M、K）。

| 统计项 | 计算方式 |
|--------|----------|
| 央视网视频分条 | N条（**不含完整版**，完整版单独列出不计入N） |
| 减：快讯目录数 | -D条（国内+国际联播快讯目录，第五步识别） |
| 加：国内快讯子条目 | +M条（第六步搜索后确定） |
| 加：国际快讯子条目 | +K条（第六步搜索后确定） |
| **实际独立新闻总数** | **N - D + M + K = X** |

**排查机制**：
- 检查公式计算是否正确（N - D + M + K = X）
- **检查实际独立新闻总数是否与当天央视网页面分条+快讯子条目一致**（不预设固定范围，以页面为准）
- 检查国内快讯子条目数是否与页面实际显示一致
- 检查国际快讯子条目数是否与页面实际显示一致
- 若总数与页面实际条数不一致，标记为"条数异常"，排查是否有遗漏或重复

## 第八点五步：敏感词预处理（报告生成前必需）

> **本步骤在数据采集完成（第一至八步）之后、报告撰写（第九步）之前执行，确保AI助手在构思报告内容时不会因引用原始标题中的具体人名而触发敏感词检测。**

### 8.5.1 问题背景

央视网原始视频标题和快讯详情中经常包含具体人名（如国家领导人姓名、外国政要姓名等）。若在撰写报告时直接引用这些原始标题进行思考，AI助手的推理过程中会出现具体人名，触发敏感词检测机制，导致生成流程中断。

### 8.5.2 预处理流程

```
原始数据采集完成（第一至八步）
  │
  ▼
扫描全部原始标题和快讯详情文本
  │
  ▼
识别人名（国内领导人、外国政要等）
  │
  ▼
执行人名→占位符替换
  │
  ▼
生成"脱敏后数据集"（供第九步使用）
  │
  ▼
进入第九步报告撰写（仅使用脱敏后数据）
```

### 8.5.3 人名替换映射表

> 以下为常见替换规则，实际执行时需根据当天新闻内容动态识别所有人名并替换。

#### 国内领导人
| 原始文本 | 替换为 | 说明 |
|----------|--------|------|
| 具体领导人姓名 + "总书记" | "国家领导人" | 中共中央总书记、国家主席、中央军委主席 |
| 具体领导人姓名 + "总理" | "国务院总理" | 国务院总理 |
| 具体领导人姓名 + "委员长" | "全国人大常委会委员长" | 全国人大常委会委员长 |
| 具体领导人姓名（其他正国级） | "国家领导人" | 国家副主席、国务院副总理等 |
| 具体领导人姓名（副国级） | 职务称谓（如"副总理"） | 保留职务，替换姓名 |

#### 外国政要
| 原始文本 | 替换为 | 说明 |
|----------|--------|------|
| 外国总统姓名 | "XX国总统" | 如"白俄罗斯总统""墨西哥总统" |
| 外国总理/首相姓名 | "XX国总理/首相" | 如"英国首相""以色列总理" |
| 外国外长姓名 | "XX国外长" | 如"巴西外长" |
| 其他外国官员姓名 | 职务称谓 | 保留职务，替换姓名 |

### 8.5.4 预处理执行规则

1. **全量扫描**：对央视网JSON数据中所有视频标题、齐鲁网索引页所有条目标题、快讯详情页面所有文本内容进行扫描
2. **动态识别**：不依赖固定词表，根据上下文识别人名（"XX会见""XX表示""XX指出"等句式中的主语）
3. **保留职务**：替换时保留职务称谓（如"总书记""总理""总统"），仅替换姓名部分
4. **下划线标记**：所有由人名替换而来的占位符，均使用HTML `<u>` 标签包裹（如 `<u>国家领导人</u>`、`<u>以色列总理</u>`），以视觉标记区分脱敏内容。机构名称、事件核心对象等非人名替换内容不加下划线
5. **生成脱敏数据集**：将替换后的标题和内容整理为新的数据集，供第九步报告撰写使用
6. **禁止引用原始标题**：第九步报告撰写过程中，**仅使用脱敏后数据集**，禁止回引原始未脱敏的标题

### 8.5.5 预处理验证

| 检查项 | 验证方法 | 通过标准 |
|--------|----------|----------|
| 国内领导人姓名 | 扫描脱敏后数据集 | 无具体人名，全部为 `<u>国家领导人</u>` 等带下划线占位符 |
| 外国政要姓名 | 扫描脱敏后数据集 | 无具体人名，全部为 `<u>XX国总统/总理</u>` 等带下划线职务称谓 |
| 职务称谓保留 | 检查替换后文本 | 职务称谓完整保留（如"国务院总理""全国人大常委会"） |
| 下划线标记完整 | 检查所有占位符 | 所有人名类占位符均有 `<u>` 标签包裹，机构类无标签 |
| 标题语义完整 | 人工复核 | 替换后标题语义无歧义，可正常理解 |

### 8.5.6 排查机制

- 若第九步报告撰写过程中仍出现具体人名 → 返回本步骤重新扫描，补充遗漏的替换规则
- 若替换后标题语义不清 → 调整占位符为更具体的职务称谓
- 若脱敏后数据集条目数与原始数据不一致 → 检查是否因替换操作导致数据丢失

## 第九步：填写报告

按模板结构填写：

| 部分 | 内容 | 排查项 |
|------|------|--------|
| 一、基调概述 | 核心主题、整体基调、重点领域、当日亮点 | 字数100-200字，必填 |
| 二、新闻速览 | 完整版单独置顶（**无序号，标注`### [完整版《新闻联播》...]`**），常规新闻按当天央视网实际分条顺序编号，标注重要性，**附视频链接** | 完整版无序号且不纳入常规计数，常规新闻序号与央视网当天分条一致，无跳号 |
| 三、重点新闻详解 | 仅收录🔴和🟡，按子分类归档，注明播放顺序，**附视频链接** | 无遗漏🔴🟡新闻，播放顺序正确 |
| 四、联播快讯详解 | 列出国内/国际快讯子条目，末尾附4.3验证报告表格 | 子条目完整无遗漏，**每条子条目必须使用齐鲁网独立页面链接（一一对应，禁止共用）**，**验证报告表格必须包含**，验证结论与实际覆盖情况一致 |
| 五、完整性检测 | 播放时间、时长匹配、条数统计、检测结论 | 数据准确，条数公式 `N(央视网分条总数) - D(快讯目录) + M(国内快讯子条目) + K(国际快讯子条目) = X(实际独立新闻数)` 成立 |
| 六、新闻六要素索引 | 完整版单独列出，常规新闻按当天分条序号，快讯子条目`N-M`，**严格10列**，"新闻主体"列填写核心行动者 | **表头必须为**：序号\|新闻标题（可点击跳转）\|类别\|时间\|地点\|新闻主体\|事件\|原因\|方式\|详细信息源链接。序号与当天央视网分条一致，类别正确，新闻主体覆盖完整，快讯子条目链接规范 |

**模板强制读取机制**：
- **每次生成第六部分前，必须先读取模板文件 `新闻联播总结_去敏感词模板.md` 中"## 六、新闻六要素索引"章节**
- 严格按模板表头填写，**禁止自行修改列名、合并列、增减列**
- **禁止将第五部分的时长/播放时间信息放入第六部分**（时长仅在第五部分）
| 七、占位符统合 | 汇总新闻主体、时间、地点、数据、内容占位符（新闻主体含人物/机构/事件核心对象三类） | 汇总完整，双引号标注，无遗漏 |

**编号体系规范**：
1. **新闻联播无固定条目**：每天央视网分条数量和顺序均不同，编号必须基于当天实际分条结果
2. **完整版单独列出，无序号**：在第二部分新闻速览最前面单独列出完整版，标注`### [完整版《新闻联播》...]`，**不加数字序号**，不纳入常规新闻计数
3. **常规新闻按当天分条编号**：以央视网当天视频列表的实际顺序为基准，从1开始连续编号（1、2、3...）
4. **快讯子条目格式**：`N-M`（N为父目录在当天央视网分条中的实际序号，M为子条目序号）
5. **编号连续性**：同一日期内序号必须连续，不允许跳号、重号；不同日期之间无关联

**视频来源链接填写规范**：
1. **常规新闻**：标题链接至央视网独立视频页面，`[标题](https://tv.cctv.com/YYYY/MM/DD/VIDE{GUID}{YYMMDD}.shtml)`，一一对应

## 第十步：质量检查

1. 每条新闻是否有实质性内容（不只是标题）
2. 播放时间节点是否连续无断裂
3. 条数统计是否正确（`N(央视网分条总数) - D(快讯目录) + M(国内快讯子条目) + K(国际快讯子条目) = X(实际独立新闻数)`）
4. 分类是否合理
5. 所有占位符是否使用双引号标注
6. 是否含具体人名（应使用"国家领导人"等通用称谓），新闻主体列是否均有实质内容（禁止大量填"—"）
7. 完整版是否单独列出且**无序号**（不纳入常规序号），常规新闻序号是否与当天央视网分条一致且连续
8. **快讯子条目数量是否与央视网视频页面中列出的子条目一致（非仅齐鲁网分条数）**
9. **常规新闻标题链接是否为央视网独立URL**
10. **快讯子条目标题链接是否为齐鲁网独立URL**
11. **快讯子条目是否共用齐鲁网链接（除降级情况外）**
12. **快讯子条目未使用齐鲁网链接时，是否已执行 `site:v.iqilu.com` 搜索验证**
13. **是否存在多个新闻共用同一个视频链接的情况**

**验证流程**：

### 10.1 编号体系验证
```
检查第二部分新闻速览：
→ 完整版是否单独置顶列出（### [完整版《新闻联播》...]），且无数字序号
→ 常规新闻序号是否与当天央视网分条顺序一致
→ 序号是否连续（1,2,3...无跳号、无重号）
→ 快讯子条目是否在第二部分以目录形式出现
检查第五部分完整性检测：
→ 完整版行序号列是否为"完整版（无序号）"（非数字）
检查第六部分索引：
→ 完整版是否单独列出（序号列填"完整版"）
→ 常规新闻序号是否与第二部分一致
→ 快讯子条目格式是否为 N-M
→ 快讯父目录序号N是否与当天央视网分条一致
→ 国内快讯子条目总数是否与央视网视频页面中列出的子条目数一致
→ 国际快讯子条目总数是否与央视网视频页面中列出的子条目数一致
```

### 10.2 链接来源验证
```
提取快讯子条目标题链接：
→ 链接域名是否为 v.iqilu.com → 标记"齐鲁网 ✓"
→ 链接域名非 v.iqilu.com → 检查是否为降级情况（备注标注）
  → 是 → 标记"降级链接 ✓"
  → 否 → 标记"链接来源异常"
→ 同一齐鲁网链接对应多个不同标题 → 标记"链接合并异常"
```

### 10.3 链接唯一性验证
```
提取报告中所有视频链接（央视网+齐鲁网）
→ 按URL分组，统计每个URL对应的新闻标题数量
→ 若某个URL对应的新闻标题数 > 1
  → 检查是否为快讯目录降级共用（允许）
  → 检查是否为同一新闻的不同部分引用（允许）
  → 其他情况 → 标记"链接共用异常"
→ 若某个URL对应的新闻标题数 = 1
  → 标记"独立链接 ✓"
```

### 10.4 链接可访问性验证
```
对每个视频链接发送HTTP HEAD请求
→ 返回状态码 200 → 标记"可访问 ✓"
→ 返回 404/403/500 → 标记"链接失效"
→ 请求超时 → 标记"访问超时"
```

### 10.5 链接格式验证
```
央视网链接：匹配 https://tv.cctv.com/YYYY/MM/DD/VIDE{GUID}{YYMMDD}.shtml
齐鲁网链接：匹配 https://v.iqilu.com/jcdb/ysxwlb/YYYYMM/DD/XXXXXX.html
→ 符合 → 标记"格式正确 ✓"
→ 不符合 → 标记"格式异常"
```

### 10.6 链接与新闻匹配验证
```
每条常规新闻 → 必须有独立央视网链接
快讯目录 → 必须有央视网汇总链接
快讯子条目 → 优先齐鲁网独立链接，降级时用央视网目录链接
完整版 → 必须在完整性检测中单独列出
```

### 10.7 模板结构合规验证
> **本步骤防止自动化任务自行修改模板结构，是7月10日第六部分出现9列（应为10列）问题的根本防范措施。**

```

→ 标题是否为 "## 六、新闻六要素索引"（非"六要素索引"等变体）
→ 表头列数是否为 10 列
→ 表头列名是否为：序号 | 新闻标题（可点击跳转） | 类别 | 时间 | 地点 | 新闻主体 | 事件 | 原因 | 方式 | 详细信息源链接

→ 完整版行类别列是否为 "完整版"（带双引号）
→ 完整版行新闻主体列是否为 "—"
→ 完整版行详细信息源链接列是否填写（非"—"）

检查所有部分标题：
→ 是否存在7个标准部分标题（## 一 至 ## 七）
→ 部分标题是否与模板一致（如"## 六、新闻六要素索引"非"## 六、六要素索引"）

检查特殊编排标记：
→ 若当天完整版非19:00播出（如21:00），是否在第五部分和文件尾部有特殊说明
→ 若当天快讯目录非标准分离模式（如仅1条合并快讯或无快讯），是否在第四部分和第五部分有特殊说明
```

**排查机制**：
- 检查"信息缺失""时长异常""条数异常""搜索异常"标记
- **检查"编号异常"标记（序号不连续/缺失完整版）**
- **检查"链接来源异常"标记（快讯子条目非齐鲁网链接）**
- **检查"链接合并异常"标记（快讯子条目共用齐鲁网链接）**
- **检查"链接共用异常"标记**
- **检查"链接失效"标记**
- 存在任何异常 → 返回对应步骤重新处理
- 全部通过 → 标记"质量合格"

## 第十一步：保存文件

文件名格式：`新闻联播总结_YYYYMMDD.md`

保存路径：用户工作文件夹

**写入方式：分块写入（必须遵守）**

报告正常约300行、20-30KB，单次生成可能因输出token限制被截断。若截断后的不完整内容被写入文件，会导致文件重复追加、膨胀至数百KB甚至MB级别。**必须使用分块写入策略**：

| 步骤 | 操作工具 | 写入内容 | 预估行数 |
|------|---------|---------|---------|
| 1 | `Write`（覆盖） | 头部 + 第一至二部分（基调概述 + 新闻速览） | ~100行 |
| 2 | `SearchReplace` | 替换占位符为第三至四部分（重点新闻详解 + 联播快讯详解） | ~100行 |
| 3 | `SearchReplace` | 替换占位符为第五至七部分（完整性检测 + 六要素索引 + 占位符统合）+ 尾部数据来源 | ~120行 |

**具体操作流程**：

```
步骤1：Write 写入骨架文件
- content 包含：文件头 + 第一部分 + 第二部分 + 占位符标记
- 占位符格式：<!-- PLACEHOLDER_PART3_START -->
- 文件末尾保留占位符标记，供后续步骤定位替换

步骤2：SearchReplace 追加第三至四部分
- old_str：<!-- PLACEHOLDER_PART3_START -->
- new_str：第三部分完整内容 + 第四部分完整内容 + <!-- PLACEHOLDER_PART5_START -->
- 注意：new_str 末尾必须包含下一个占位符标记

步骤3：SearchReplace 追加第五至七部分
- old_str：<!-- PLACEHOLDER_PART5_START -->
- new_str：第五部分 + 第六部分 + 第七部分 + 尾部（数据来源 + 声明）
```

**禁止事项**：
- **禁止在单次 Write 中传入超过150行的完整报告内容**
- **禁止在生成内容被截断后，将截断内容直接写入文件**
- **禁止在重试时从头生成并覆盖写入，而不检查之前是否已写入部分内容**

**排查机制**：
- 检查文件是否成功保存
- **检查文件大小是否在正常范围（18-35KB），若超过50KB视为异常**
- **检查标题"新闻联播总结报告"是否只出现1次，若出现多次说明存在重复写入**
- **检查7个部分（## 一 至 ## 七）是否齐全**
- 检查文件内容是否完整（开头和结尾是否完整）
- **若发现文件异常膨胀**：立即删除文件，按分块写入策略重新生成
- 若保存失败，尝试重新保存或检查磁盘空间

## 异常处理流程

| 异常类型 | 处理方式 |
|----------|----------|
| 数据异常 | 刷新页面，重新提取数据；若重试仍失败，暂停执行 |
| 时长异常 | 检查是否有遗漏的视频分条 |
| 快讯缺失 | 手动检查页面，确认是否有快讯 |
| 快讯数量异常 | 核对搜索结果，检查是否遗漏子条目或存在重复计数 |
| 信息缺失 | 更换搜索关键词，尝试其他来源 |
| 搜索异常 | 暂停搜索，标记缺失项 |
| 条数异常 | 检查是否有重复或遗漏的新闻 |
| 保存失败 | 检查磁盘空间，尝试重新保存 |
| **自动化执行未触发** | **检查定时任务状态是否Active；确认cron表达式正确（30 6 * * * = 每天06:30）** |
| **数据获取成功但文件未生成** | **报告生成环节失败（token截断/网络超时/session中断），第零步文件检查会在下次自动修复** |
| **文件存在但≤10KB（生成中断）** | **删除不完整文件，按分块写入策略从头重新生成（第零步0.2自动触发）** |
| **自动任务连续2天无输出** | **标记"自动化任务异常"，需人工检查任务状态和系统资源** |
| **URL重复异常** | **检查央视网页面结构，重新提取每个视频的独立URL；若央视网页面本身无独立URL，使用完整版URL + 时间锚点作为替代** |
| **链接失效（404/403）** | **检查URL格式是否正确；尝试访问 `https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml` 重新获取；若仍失效，标记为"链接待验证"** |
| **链接共用异常** | **定位共用URL的新闻条目，返回第二步重新提取每条新闻的独立URL；禁止用同一个URL填充多条不同新闻** |
| **格式异常** | **检查URL是否缺少前缀或GUID部分，修正为完整格式 `https://tv.cctv.com/YYYY/MM/DD/VIDE{GUID}{YYMMDD}.shtml`** |
| **第六部分结构异常** | **表头列数≠10、列名与模板不符、包含"播放时间"/"关键词"等非模板列 → 删除第六部分，重新读取模板文件，按模板表头重新填写** |
| **部分标题与模板不符** | **检查所有7个部分标题，修正为模板中的标准标题（如"新闻六要素索引"非"六要素索引"）** |

# 附录A：视频获取处理流程

## A.1 问题背景

### 遇到的问题
- 使用搜索引擎无法直接获取央视网《新闻联播》完整视频分条信息
- 央视网视频页面使用 JavaScript 动态加载，视频地址通过 GUID 动态生成
- 搜索返回结果有限，仅能获取到第三方转载链接（如齐鲁网）

### 问题原因分析
1. **搜索策略局限**：WebSearch 工具搜索央视网视频列表时，搜索引擎返回结果非常有限
2. **页面动态加载**：央视网视频页面使用 JavaScript 动态渲染内容，静态抓取无法获取完整信息
3. **地址动态生成**：视频 URL 格式为 `https://tv.cctv.com/2026/06/20/VIDE{随机字符}{日期}.shtml`，其中 VIDE 后面的字符是动态生成的 GUID
4. **视频流加密**：视频播放使用 `blob:` 协议，实际视频流地址需要通过 API 接口获取

## A.2 解决方案

### 方案一：Python requests 直接获取页面源码（推荐）

**适用场景**：
- 需要获取完整的视频分条信息（时长、标题、URL）
- 需要定期更新视频列表
- **需要确保每条新闻都有独立的视频URL**
- 无需安装浏览器环境

**核心原理**：
央视网历史日期页面 `day/YYYYMMDD.shtml` 的原始HTML源码中已包含完整的视频列表结构（`<li>` 标签内嵌 `<a>` 链接和时长），虽然页面使用JavaScript进行前端渲染增强，但所有视频数据在服务端渲染时已经写入HTML。因此使用 `requests` 直接获取页面源码并解析，即可获得完整的视频列表，无需等待浏览器JavaScript执行。

**实现步骤**：

**步骤 1：访问央视网历史日期列表页**
```python
import requests
import re

url = "https://tv.cctv.com/lm/xwlb/day/20260624.shtml"
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
    "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
    "Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8",
}

resp = requests.get(url, headers=headers, timeout=30)
resp.encoding = 'utf-8'
html = resp.text
```

**步骤 2：从源码中提取视频列表（含独立URL）**
```python
# 匹配 <li> 内的视频条目
li_pattern = re.compile(
    r'<li[^>]*>.*?'
    r'(\d{2}:\d{2}:\d{2}).*?'
    r'<a[^>]*href=["\'](https://tv\.cctv\.com/[^"\']+)["\'][^>]*>(.*?)</a>.*?'
    r'</li>',
    re.DOTALL | re.IGNORECASE
)

matches = li_pattern.findall(html)
results = []
seen_urls = set()

for match in matches:
    duration = match[0]
    video_url = match[1]
    title_raw = match[2]

    if video_url in seen_urls:
        continue
    seen_urls.add(video_url)

    title = re.sub(r'<[^>]+>', '', title_raw).strip()
    title = title.replace('[视频]', '').strip()
    title = re.sub(r'^完整版', '', title).strip()

    results.append({
        "title": title,
        "duration": duration,
        "url": video_url
    })

print(f"共提取 {len(results)} 条视频")
# 验证URL唯一性
assert len(results) == len(seen_urls), "存在重复URL"
```

**步骤 3：验证URL可访问性**
```python
import requests

def verify_url(url):
    try:
        response = requests.head(url, timeout=10, allow_redirects=True)
        return response.status_code == 200
    except:
        return False

for video in results:
    is_valid = verify_url(video['url'])
    print(f"{video['title']}: {'有效' if is_valid else '待验证'}")
```

**优势**：
- 无需安装浏览器（Playwright/Puppeteer/Selenium）
- 运行速度快（单次请求即可）
- 数据完整性高（源码中包含所有视频条目）
- 可复现为自动化脚本

def get_xwlb_videos():

        browser = p.chromium.launch(headless=True)
        page = browser.new_page()
        page.goto('https://tv.cctv.com/lm/xwlb/day/20260624.shtml')

        page.wait_for_timeout(3000)  # 等待JS渲染

            const items = document.querySelectorAll('li');
            return Array.from(items).map(item => {

                    duration: duration ? duration[0] : '',
                    url: link ? link.href : ''
                };

        }''')
        
        browser.close()
        return videos

## A.4 常见问题

**Q1：为什么直接搜索获取不到视频列表？**
A：央视网视频列表通过 JavaScript 动态加载，搜索引擎爬虫无法执行 JavaScript，因此搜索结果显示不完整。

**Q2：视频 blob: 地址如何转换为真实地址？**
A：blob: 地址是浏览器本地生成的，需要通过央视网 API 接口获取真实的视频流地址。

**Q3：GUID 会变化吗？**
A：每个视频的 GUID 是固定的，但新发布的视频会生成新的 GUID。

**Q4：如何获取历史日期的视频？**
A：使用历史日期页面 `https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml`，该页面包含当日所有视频的独立分条链接和完整版链接。

**Q5：为什么报告中多条新闻用了同一个视频链接？**
A：这是最常见的错误。原因通常有：
1. 从搜索结果中只获取了一个视频URL，然后复制到所有新闻条目
2. 未访问历史日期页面，而是使用了默认列表页的单个链接
3. 未执行URL唯一性检查

**解决方法**：
- 必须访问 `https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml` 获取当日完整视频列表
- 每条新闻从页面中提取其对应的独立 `href`
- 使用 `Set` 去重验证URL唯一性
- 写入报告前，再次检查不同新闻条目是否共用URL

**Q6：如何验证报告中的视频链接都是独立的？**
A：使用以下PowerShell命令自查：
```powershell
# 提取所有央视网链接
$allUrls = Select-String -Path '新闻联播总结_20260624.md' -Pattern 'https://tv\.cctv\.com/[^)]+' -AllMatches | ForEach-Object { $_.Matches.Value }

# 统计每个URL出现次数
$allUrls | Group-Object | Sort-Object Count -Descending | Format-Table Name, Count

# 理想结果：每个URL只出现1次（对应1条新闻）
# 若某URL出现多次，说明多条新闻共用同一个链接，需要修正
```

**Q7：如果央视网某条新闻没有独立视频页面怎么办？**
A：正常情况下，央视网《新闻联播》的每条新闻（含完整版）都有独立的视频页面。若遇到缺失：
1. 检查是否访问了正确的历史日期页面
2. 刷新页面重新提取
3. 若确实缺失，使用该新闻所在快讯目录的汇总链接作为替代
4. 在报告中标注"该条新闻无独立视频页，使用快讯汇总页"

        response = requests.head(url, timeout=10, allow_redirects=True)
        return response.status_code == 200
    except:
        return False

## C.2 核心代码参考

如需在自定义脚本中集成提取逻辑，可直接复用以下函数：

```python
import requests
import re
import json
from urllib.parse import unquote

def fetch_xwlb_list(date_str):
    """
    获取指定日期的新闻联播视频列表
    :param date_str: 日期字符串，格式 YYYYMMDD
    :return: list[dict]，每个元素包含 title, duration, url
    """
    url = f"https://tv.cctv.com/lm/xwlb/day/{date_str}.shtml"
    headers = {
        "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
        "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
        "Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8",
        "Referer": "https://tv.cctv.com/lm/xwlb/",
    }

    resp = requests.get(url, headers=headers, timeout=30)
    resp.encoding = 'utf-8'
    html = resp.text

    results = []
    li_pattern = re.compile(
        r'<li[^>]*>.*?(\d{2}:\d{2}:\d{2}).*?'
        r'<a[^>]*href=["\'](https://tv\.cctv\.com/[^"\']+)["\'][^>]*>(.*?)</a>.*?</li>',
        re.DOTALL | re.IGNORECASE
    )
    seen_urls = set()

    for match in li_pattern.findall(html):
        duration = match[0]
        video_url = match[1]
        title_raw = match[2]

        if video_url in seen_urls:
            continue
        seen_urls.add(video_url)

        title = re.sub(r'<[^>]+>', '', title_raw).strip()
        title = unquote(title)
        title = title.replace('[视频]', '').strip()
        title = re.sub(r'^完整版', '', title).strip()

        results.append({"title": title, "duration": duration, "url": video_url})

    return results


# 使用示例
if __name__ == '__main__':
    date_str = "20260624"
    videos = fetch_xwlb_list(date_str)
    print(json.dumps(videos, ensure_ascii=False, indent=2))
```
