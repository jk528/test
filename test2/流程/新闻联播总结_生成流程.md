# 新闻联播总结报告生成流程

---

## 第一步：确定日期

1. 默认取"昨晚"的新闻联播（当前日期的前一天）
2. 若当前时间在当天19:00之前，则取前一天的
3. 用户指定日期时以用户为准

**排查机制**：
- 检查日期是否为未来日期（不应超过当前日期）
- 检查日期格式是否正确（YYYY年M月D日）

---

## 第二步：访问央视网并提取视频列表

### 2.1 使用Python脚本提取（推荐）

运行同目录下的 `fetch_xwlb.py` 脚本：

```bash
python fetch_xwlb.py 20260624 xwlb_20260624.json
```

脚本通过 `requests` 直接获取页面源码并解析，无需浏览器环境即可提取完整的标题、时长和独立URL列表。输出包含：
- 完整的15条视频（含完整版 + 14条分条）
- 每条视频的标题、时长、独立URL
- JSON配置文件和Markdown表格

**脚本特性**：
- 央视网历史日期页面 `day/YYYYMMDD.shtml` 的原始HTML中已包含完整的视频列表结构
- 无需等待JavaScript渲染，直接解析源码即可获取全部数据
- 自动去除"完整版"前缀，保留标准标题格式
- 自动验证URL唯一性

### 2.2 手动提取（备选）

若脚本不可用，可手动访问：
- 历史日期页面：`https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml`
- 示例：2026年6月24日 → `https://tv.cctv.com/lm/xwlb/day/20260624.shtml`

从页面中提取完整标题列表、每条视频的时长、**每条视频对应的独立URL**。

### 2.3 排查机制

- 检查页面是否加载成功（HTTP状态码200）
- 检查是否找到对应日期的内容
- 检查提取的标题数量是否 >= 10条（通常12-18条）
- **检查每条新闻是否提取到独立的视频URL**（不可多条新闻共用同一个URL）
- 若标题数量 < 10条，标记为"数据异常"，尝试重新运行脚本或检查日期
- 若脚本运行失败，检查Python环境和requests库是否安装

---

## 第三步：提取视频信息（含独立视频URL）

从央视网页面提取：

| 信息项 | 说明 |
|--------|------|
| 新闻标题 | 每条视频的完整标题（含[视频]前缀） |
| 视频时长 | 格式为 HH:MM:SS |
| 总时长 | 完整版视频的总时长 |
| **独立视频URL** | **每条新闻对应的独立央视网视频页面地址** |
| **完整版URL** | **完整版《新闻联播》的视频页面地址** |

**URL提取规则**：
1. 从 `https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml` 页面提取
2. 每条新闻（含完整版）都应有独立的URL
3. URL格式：`https://tv.cctv.com/{YYYY}/{MM}/{DD}/VIDE{GUID}{YYMMDD}.shtml`
4. **同一条新闻不可出现在多个条目中**
5. **不同新闻条目不可共用同一个URL**

**排查机制**：
- 检查每条视频时长是否为有效时间格式（HH:MM:SS）
- 检查总时长是否在 **25-35分钟** 范围内
- 检查是否有重复标题（去重处理）
- **检查URL唯一性**：提取所有URL，若存在重复URL，标记为"URL重复异常"
- **检查URL格式**：确保URL符合 `https://tv.cctv.com/YYYY/MM/DD/VIDE...` 格式
- **检查URL完整性**：确保每条新闻（不含快讯子条目）都有独立URL
- 若总时长 < 25分钟或 > 35分钟，标记为"时长异常"

---

## 第四步：计算播放时间

1. 第一条开始时间固定为 **19:00:00**
2. 每条结束时间 = 上一条结束时间 + 本条时长
3. 最后一条结束后到19:30:00为片尾时段
4. 验证总时长是否在 **25-35分钟** 范围内

**排查机制**：
- 检查播放时间是否连续无断裂（每条结束时间 = 下一条开始时间）
- 检查最后一条结束时间是否接近19:30:00（允许±2分钟误差）
- 检查片尾时长是否在1-3分钟范围内
- 若时间断裂，标记断裂位置并排查原因

---

## 第五步：识别快讯目录

从视频分条中识别目录条目（仅标记哪些是目录，子条目数量在第六步搜索后确定）：

- **"国内联播快讯"** → 记录为目录，非独立新闻
- **"国际联播快讯"** → 记录为目录，非独立新闻

**排查机制**：
- 检查是否识别到"国内联播快讯"目录（通常有，偶尔无）
- 检查是否识别到"国际联播快讯"目录（通常有，偶尔无）
- 检查快讯目录的时长是否合理（2-4分钟）
- 若未识别到快讯目录，标记为"快讯缺失"，需手动检查页面
- **注意**：此步骤仅识别目录条目本身，目录内含多少条子快讯需在第六步搜索后确定

---

## 第六步：搜索新闻详情

对每条标题进行网络搜索，获取文字内容：

**搜索优先级（兜底策略）**：
1. **优先搜索**：`新闻联播 YYYY年M月D日 要闻N条 整理` — 一次性获取全部新闻摘要和快讯子条目
2. **补充搜索**：`新闻联播 YYYY年M月D日 标题 主要内容` — 对重点新闻获取更详细内容
3. **专项搜索**：`国内联播快讯 YYYY年M月D日 具体内容` 和 `国际联播快讯 YYYY年M月D日 具体内容` — 展开快讯子条目

**排查机制**：
- 检查每条新闻是否搜索到至少1个有效来源
- 检查快讯子条目是否全部展开（国内通常5-8条，国际通常3-5条）
- **快讯子条目数量异常验证**：
  - 若国内快讯子条目 < 3条或 > 10条，标记为"快讯数量异常"
  - 若国际快讯子条目 < 2条或 > 7条，标记为"快讯数量异常"
  - 异常时需手动核对搜索结果，确认是否遗漏
- 检查是否有新闻完全无搜索结果（标记为"信息缺失"）
- 若信息缺失 > 3条，标记为"搜索异常"，尝试更换搜索关键词

---

## 第七步：分类与标注

### 7.1 重要性标注

| 标注 | 条件 |
|------|------|
| 🔴 必标重点 | "最高层"活动、"国务院"重大政策、国际热点冲突、重大突发事件 |
| 🟡 选标重点 | "副国家级"活动、部委政策、经济数据、科技/文化事件 |
| 一般 | 常规报道、快讯 |

### 7.2 子分类

| 分类 | 收录内容 |
|------|----------|
| 政策/会议 | 国务院政策、部委文件、重要会议 |
| 国际新闻 | 外交活动、国际冲突、国际关系 |
| 经济要闻 | 经济数据、产业政策、金融动态、科技成就 |
| 社会/文化 | 社会事件、文化活动、民生热点 |

**排查机制**：
- 检查是否有新闻未被标注重要性（所有新闻必须有标注）
- 检查🔴必标重点数量是否合理（通常3-6条）
- 检查是否有新闻未被分类（所有新闻必须有分类）
- 检查分类是否合理（是否有明显错分类的新闻）

---

## 第八步：统计条数

**前提**：此步骤需要第五步识别的目录数（D）和第六步搜索得到的子条目数（M、K）。

| 统计项 | 计算方式 |
|--------|----------|
| 央视网视频分条 | N条 |
| 减：快讯目录数 | -D条（国内+国际联播快讯目录，第五步识别） |
| 加：国内快讯子条目 | +M条（第六步搜索后确定） |
| 加：国际快讯子条目 | +K条（第六步搜索后确定） |
| **实际独立新闻总数** | **N - D + M + K = X** |

**排查机制**：
- 检查公式计算是否正确（N - D + M + K = X）
- 检查实际独立新闻总数是否在 **15-30条** 范围内
- 检查国内快讯子条目数是否合理（通常5-8条）
- 检查国际快讯子条目数是否合理（通常3-5条）
- 若总数 < 15条或 > 30条，标记为"条数异常"，排查是否有遗漏或重复

---

## 第九步：填写报告

按模板结构填写：

| 部分 | 内容 | 排查项 |
|------|------|--------|
| 一、基调概述 | 核心主题、整体基调、重点领域、当日亮点 | 检查是否填写完整，字数是否在100-200字 |
| 二、新闻速览 | 按播放顺序列出所有新闻，标注重要性，**附独立视频来源链接** | 检查是否包含所有新闻，快讯目录是否正确标注，**视频链接是否为独立URL** |
| 三、重点新闻详解 | 仅收录🔴和🟡，按子分类归档，注明播放顺序，**附独立视频来源链接** | 检查是否遗漏🔴或🟡新闻，播放顺序是否正确，**视频链接是否为独立URL** |
| 四、联播快讯详解 | 列出国内/国际快讯子条目 | 检查子条目是否完整，是否有遗漏 |
| 五、完整性检测 | 播放时间、时长匹配、条数统计、检测结论 | 检查表格数据是否准确，结论是否合理 |
| 六、新闻六要素索引 | 序号、标题、类别、时间、地点、人物、事件、原因、方式，**附独立视频来源链接** | 检查是否包含所有新闻，类别是否正确，**视频链接是否为独立URL** |
| 七、占位符统合 | 汇总人物、机构、时间、地点、数据、内容占位符 | 检查是否汇总完整，是否有遗漏 |

**视频来源链接填写规范**：
1. **必须使用独立URL**：每条新闻（含完整版）必须链接到其独立的央视网视频页面
2. **禁止共用URL**：不同新闻条目不可使用同一个视频链接
3. **链接格式**：`[央视网视频地址](https://tv.cctv.com/YYYY/MM/DD/VIDE{GUID}{YYMMDD}.shtml)`
4. **快讯目录**：国内联播快讯和国际联播快讯作为目录，链接到其各自的汇总视频页面
5. **快讯子条目**：子条目链接到其父目录（快讯）的视频页面，或使用文字链接（无需独立视频页）
6. **完整版链接**：在完整性检测表格中单独列出完整版视频链接

**排查机制**：
- 检查每个部分是否都有内容（不允许空部分）
- 检查是否有新闻在多个部分重复出现（除索引外）
- 检查是否有新闻完全未出现在报告中
- 检查占位符是否统一使用双引号标注
- **检查视频链接唯一性**：搜索报告中所有 `https://tv.cctv.com/` 链接，统计每个URL出现次数，若某URL出现次数 > 1且对应不同新闻标题，标记为"链接共用异常"

---

## 第十步：质量检查

1. 每条新闻是否有实质性内容（不只是标题）
2. 播放时间节点是否连续无断裂
3. 条数统计是否正确（N - D + M + K = X）
4. 分类是否合理
5. 所有占位符是否使用双引号标注
6. 是否含具体人名（应使用"国家领导人"等通用称谓）
7. **每条新闻是否有独立的视频来源链接**
8. **视频链接是否可访问（HTTP 200）**
9. **是否存在多个新闻共用同一个视频链接的情况**

**视频链接验证流程（新增）**：

### 10.1 链接唯一性验证
```
提取报告中所有 https://tv.cctv.com/ 开头的链接
→ 按URL分组，统计每个URL对应的新闻标题数量
→ 若某个URL对应的新闻标题数 > 1
   → 检查这些标题是否属于同一条新闻的不同部分
   → 若不是，标记为"链接共用异常"
→ 若某个URL对应的新闻标题数 = 1
   → 标记为"独立链接 ✓"
```

### 10.2 链接可访问性验证
```
对每个独立视频链接发送HTTP HEAD请求
→ 返回状态码 200 → 标记为"可访问 ✓"
→ 返回状态码 404/403/500 → 标记为"链接失效"，尝试重新获取
→ 请求超时 → 标记为"访问超时"，稍后重试
```

### 10.3 链接格式验证
```
检查每个URL是否符合格式：
https://tv.cctv.com/YYYY/MM/DD/VIDE{GUID}{YYMMDD}.shtml
→ 符合 → 标记为"格式正确 ✓"
→ 不符合 → 标记为"格式异常"
```

### 10.4 链接与新闻匹配验证
```
检查每个新闻条目是否都有对应的视频来源链接
→ 每条常规新闻（不含快讯子条目）都必须有独立链接
→ 快讯目录（国内/国际联播快讯）必须有各自的汇总链接
→ 完整版视频必须在完整性检测部分单独列出
```

**排查机制**：
- 检查是否有"信息缺失"标记的新闻
- 检查是否有"时长异常"标记的新闻
- 检查是否有"条数异常"标记的情况
- 检查是否有"搜索异常"标记的情况
- **检查是否有"URL重复异常"标记的情况**
- **检查是否有"链接失效"标记的情况**
- **检查是否有"链接共用异常"标记的情况**
- 若存在任何异常标记，需返回对应步骤重新处理
- 若所有检查通过，标记为"质量合格"

---

## 第十一步：保存文件

文件名格式：`新闻联播总结_YYYYMMDD.md`

保存路径：用户工作文件夹

**排查机制**：
- 检查文件是否成功保存
- 检查文件大小是否合理（通常10-50KB）
- 检查文件内容是否完整（开头和结尾是否完整）
- 若保存失败，尝试重新保存或检查磁盘空间

---

## 异常处理流程

| 异常类型 | 处理方式 |
|----------|----------|
| 数据异常 | 刷新页面，重新提取数据；若重试仍失败，暂停执行 |
| 时长异常 | 检查是否有遗漏的视频分条 |
| 快讯缺失 | 手动检查页面，确认是否有快讯 |
| 快讯数量异常 | 核对搜索结果，检查是否遗漏子条目或存在重复计数 |
| 信息缺失 | 更换搜索关键词，尝试其他来源 |
| 搜索异常 | 暂停搜索，标记缺失项 |
| 条数异常 | 检查是否有重复或遗漏的新闻 |
| 保存失败 | 检查磁盘空间，尝试重新保存 |
| **URL重复异常** | **检查央视网页面结构，重新提取每个视频的独立URL；若央视网页面本身无独立URL，使用完整版URL + 时间锚点作为替代** |
| **链接失效（404/403）** | **检查URL格式是否正确；尝试访问 `https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml` 重新获取；若仍失效，标记为"链接待验证"** |
| **链接共用异常** | **定位共用URL的新闻条目，返回第二步重新提取每条新闻的独立URL；禁止用同一个URL填充多条不同新闻** |
| **格式异常** | **检查URL是否缺少前缀或GUID部分，修正为完整格式 `https://tv.cctv.com/YYYY/MM/DD/VIDE{GUID}{YYMMDD}.shtml`** |

### 链接验证自查方法
```powershell
# 提取报告中所有央视网视频链接并统计
$urls = Select-String -Path '新闻联播总结_YYYYMMDD.md' -Pattern 'https://tv\.cctv\.com/[^)]+' -AllMatches | ForEach-Object { $_.Matches.Value } | Sort-Object -Unique
$urls.Count  # 应接近新闻条数（不含快讯子条目）

# 检查重复
$allUrls = Select-String -Path '新闻联播总结_YYYYMMDD.md' -Pattern 'https://tv\.cctv\.com/[^)]+' -AllMatches | ForEach-Object { $_.Matches.Value }
$allUrls | Group-Object | Where-Object { $_.Count -gt 1 }  # 应无输出或有合理解释

# 验证可访问性
foreach ($url in $urls) {
    try { $r = Invoke-WebRequest -Uri $url -Method HEAD -TimeoutSec 10; "$url : $($r.StatusCode)" }
    catch { "$url : 失败" }
}
```

# 附录A：视频获取处理流程

## A.1 问题背景

### 遇到的问题
- 使用搜索引擎无法直接获取央视网《新闻联播》完整视频分条信息
- 央视网视频页面使用 JavaScript 动态加载，视频地址通过 GUID 动态生成
- 搜索返回结果有限，仅能获取到第三方转载链接（如齐鲁网）

### 问题原因分析
1. **搜索策略局限**：WebSearch 工具搜索央视网视频列表时，搜索引擎返回结果非常有限
2. **页面动态加载**：央视网视频页面使用 JavaScript 动态渲染内容，静态抓取无法获取完整信息
3. **地址动态生成**：视频 URL 格式为 `https://tv.cctv.com/2026/06/20/VIDE{随机字符}{日期}.shtml`，其中 VIDE 后面的字符是动态生成的 GUID
4. **视频流加密**：视频播放使用 `blob:` 协议，实际视频流地址需要通过 API 接口获取

## A.2 解决方案

### 方案一：Python requests 直接获取页面源码（推荐）

**适用场景**：
- 需要获取完整的视频分条信息（时长、标题、URL）
- 需要定期更新视频列表
- **需要确保每条新闻都有独立的视频URL**
- 无需安装浏览器环境

**核心原理**：
央视网历史日期页面 `day/YYYYMMDD.shtml` 的原始HTML源码中已包含完整的视频列表结构（`<li>` 标签内嵌 `<a>` 链接和时长），虽然页面使用JavaScript进行前端渲染增强，但所有视频数据在服务端渲染时已经写入HTML。因此使用 `requests` 直接获取页面源码并解析，即可获得完整的视频列表，无需等待浏览器JavaScript执行。

**实现步骤**：

**步骤 1：访问央视网历史日期列表页**
```python
import requests
import re

url = "https://tv.cctv.com/lm/xwlb/day/20260624.shtml"
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
    "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
    "Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8",
}

resp = requests.get(url, headers=headers, timeout=30)
resp.encoding = 'utf-8'
html = resp.text
```

**步骤 2：从源码中提取视频列表（含独立URL）**
```python
# 匹配 <li> 内的视频条目
li_pattern = re.compile(
    r'<li[^>]*>.*?'
    r'(\d{2}:\d{2}:\d{2}).*?'
    r'<a[^>]*href=["\'](https://tv\.cctv\.com/[^"\']+)["\'][^>]*>(.*?)</a>.*?'
    r'</li>',
    re.DOTALL | re.IGNORECASE
)

matches = li_pattern.findall(html)
results = []
seen_urls = set()

for match in matches:
    duration = match[0]
    video_url = match[1]
    title_raw = match[2]

    if video_url in seen_urls:
        continue
    seen_urls.add(video_url)

    title = re.sub(r'<[^>]+>', '', title_raw).strip()
    title = title.replace('[视频]', '').strip()
    title = re.sub(r'^完整版', '', title).strip()

    results.append({
        "title": title,
        "duration": duration,
        "url": video_url
    })

print(f"共提取 {len(results)} 条视频")
# 验证URL唯一性
assert len(results) == len(seen_urls), "存在重复URL"
```

**步骤 3：验证URL可访问性**
```python
import requests

def verify_url(url):
    try:
        response = requests.head(url, timeout=10, allow_redirects=True)
        return response.status_code == 200
    except:
        return False

for video in results:
    is_valid = verify_url(video['url'])
    print(f"{video['title']}: {'有效' if is_valid else '待验证'}")
```

- 无需安装浏览器（Playwright/Puppeteer/Selenium）
- 运行速度快（单次请求即可）
- 数据完整性高（源码中包含所有视频条目）
- 可复现为自动化脚本

def get_xwlb_videos():
    with sync_playwright() as p:

        page = browser.new_page()

            const items = document.querySelectorAll('li');
            return Array.from(items).map(item => {
                const link = item.querySelector('a');
                const duration = item.textContent.match(/(\d{2}:\d{2}:\d{2})/);

                    title: item.textContent.replace(duration ? duration[0] : '', '').trim(),
                    duration: duration ? duration[0] : '',
                    url: link ? link.href : ''
                };
            }).filter(v => v.url && v.duration);
        }''')
        
        browser.close()
        return videos

## A.4 常见问题

**Q1：为什么直接搜索获取不到视频列表？**
A：央视网视频列表通过 JavaScript 动态加载，搜索引擎爬虫无法执行 JavaScript，因此搜索结果显示不完整。

**Q2：视频 blob: 地址如何转换为真实地址？**
A：blob: 地址是浏览器本地生成的，需要通过央视网 API 接口获取真实的视频流地址。

**Q3：GUID 会变化吗？**
A：每个视频的 GUID 是固定的，但新发布的视频会生成新的 GUID。

**Q4：如何获取历史日期的视频？**
A：使用历史日期页面 `https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml`，该页面包含当日所有视频的独立分条链接和完整版链接。

**Q5：为什么报告中多条新闻用了同一个视频链接？**
A：这是最常见的错误。原因通常有：
1. 从搜索结果中只获取了一个视频URL，然后复制到所有新闻条目
2. 未访问历史日期页面，而是使用了默认列表页的单个链接
3. 未执行URL唯一性检查

**解决方法**：
- 必须访问 `https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml` 获取当日完整视频列表
- 每条新闻从页面中提取其对应的独立 `href`
- 使用 `Set` 去重验证URL唯一性
- 写入报告前，再次检查不同新闻条目是否共用URL

**Q6：如何验证报告中的视频链接都是独立的？**
A：使用以下PowerShell命令自查：
```powershell
# 提取所有央视网链接
$allUrls = Select-String -Path '新闻联播总结_20260624.md' -Pattern 'https://tv\.cctv\.com/[^)]+' -AllMatches | ForEach-Object { $_.Matches.Value }

# 统计每个URL出现次数
$allUrls | Group-Object | Sort-Object Count -Descending | Format-Table Name, Count

# 理想结果：每个URL只出现1次（对应1条新闻）
# 若某URL出现多次，说明多条新闻共用同一个链接，需要修正
```

**Q7：如果央视网某条新闻没有独立视频页面怎么办？**
A：正常情况下，央视网《新闻联播》的每条新闻（含完整版）都有独立的视频页面。若遇到缺失：
1. 检查是否访问了正确的历史日期页面
2. 刷新页面重新提取
3. 若确实缺失，使用该新闻所在快讯目录的汇总链接作为替代
4. 在报告中标注"该条新闻无独立视频页，使用快讯汇总页"

import requests
import re

def get_video_urls(date_str):
    """获取指定日期的新闻联播视频列表"""

        if video_url in seen_urls:
            continue
        seen_urls.add(video_url)

        title = re.sub(r'<[^>]+>', '', title_raw).strip()
        title = unquote(title)
        title = title.replace('[视频]', '').strip()
        title = re.sub(r'^完整版', '', title).strip()

        results.append({"title": title, "duration": duration, "url": video_url})

    return results

if __name__ == '__main__':
    date_str = "20260624"
    videos = fetch_xwlb_list(date_str)
    print(json.dumps(videos, ensure_ascii=False, indent=2))

## C.3 浏览器自动化备选方案

若页面结构发生重大变化导致 `requests` 方案失效，可使用 Playwright 作为备选：

from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto('https://tv.cctv.com/lm/xwlb/day/20260624.shtml')
    page.wait_for_timeout(3000)
    videos = page.evaluate('''() => {
        const items = document.querySelectorAll(\"li\");
        return Array.from(items).map(item => {
            const link = item.querySelector(\"a\");
            const duration = item.textContent.match(/(\\d{2}:\\d{2}:\\d{2})/);
            return {
                title: item.textContent.replace(duration ? duration[0] : \"\", \"\").trim(),
                duration: duration ? duration[0] : \"\",
                url: link ? link.href : \"\"
            };
        }).filter(v => v.url && v.duration);
    }''')
    browser.close()
    print(videos)
