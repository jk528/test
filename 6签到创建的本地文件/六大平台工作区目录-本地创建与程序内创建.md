# 六大平台工作区目录清单：本地创建 vs 程序内创建

> 目的：区分“六大签到平台在仓库内自建的工作区目录”中，哪些是**本机客户端运行时创建**、哪些是**签到程序代码主动创建**；前者核对清单是否有遗漏，后者写明精确地址与创建逻辑，作为 Git 忽略规则的依据。
> 核查时间：2026-10-23（对 `C:\Users\Administrator\Desktop\JK-temp` 实际扫描）
> 代码依据：`自动化与工具/签到程序/checkin_all.js`、`run_checkin.cmd`、`sync_gitee.ps1`
> 关联文档：[签到程序本地文件夹与配置路径说明.md](签到程序本地文件夹与配置路径说明.md)

---

## 〇、判定口径

| 类别 | 含义 | 判定依据 |
|---|---|---|
| **本地创建** | 平台客户端/智能体在本机打开某个仓库子目录时**自行生成**的工作区目录；签到脚本不参与 | 目录实际存在 + 内部文件特征（如 `memory.db`、`governance-bootstrap-report.json`）+ 根 `.gitignore` 既有注释 |
| **程序内创建** | 签到程序（`checkin_all.js`）**代码里显式创建**的目录 | 代码中存在 `fs.mkdirSync(...)` / `fs.writeFileSync(...)`，可逐行定位 |

前提说明：6 个平台客户端均为闭源，无法读取其建目录源码；下表“创建逻辑”为**代码可证**（程序内）与**实物可证**（本地创建）两种，不做无依据推断。

## 三、程序内创建（签到程序代码主动创建）

### 3.1 唯一新建目录：`.temp`

| 项 | 内容 |
|---|---|
| **精确地址** | `C:\Users\Administrator\Desktop\JK-temp\自动化与工具\签到程序\.temp\`（等价写法：`<checkin_all.js 所在目录>\.temp\`，代码用 `__dirname` 取目录） |
| **创建代码** | `checkin_all.js` 第 613–617 行：`const dir = path.join(__dirname, '.temp'); fs.mkdirSync(dir, { recursive: true });` |
| **触发时机** | WorkBuddy 密钥获取成功后写缓存时；目录已存在则 `recursive: true` 静默通过 |

| **生命周期** | 解密校验失败（`authTag` 不匹配）时 `wbClearKeyCache()`（第 531–535 行）删除两个缓存文件，再重新获取并写回 |
| **安全属性** | 含本机 WorkBuddy 密钥，**严禁入库**；根 `.gitignore` 第 42 行 `/自动化与工具/签到程序/.temp/` |
| **其他平台** | Trae / TeleAgent / CodeArts / Qoder / OfficeAce 的签到逻辑**不创建任何目录**，只读取既有凭证文件 |
