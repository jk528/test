# 维读架构与计划预案

> 基于：维读提示词控制需求规格（spec.md）、红楼梦范例教训、彩读依赖经验
> 核心理念：万维不局限于彩读和红楼梦范例，架构留扩展性，大模型自打磨维度
> 日期：2026-10-18

---

## 一、设计哲学

### 1.1 三大核心原则

**原则一：提示词即控制**
- 用户用自然语言描述阅读意图，系统自动解析为配置
- 8+ 通道组合不再需要手动逐项设置
- 降低认知负担，新用户零门槛上手

**原则二：骨架稳定，内容可变**
- 框架骨架（扩展点、接口契约、调度核心）由维护者管理，稳定不变
- 维度内容（提示词模板、分析参数、展示规则）可由大模型自打磨，动态优化
- 大模型在契约约束内运作，禁止越权修改骨架

**原则三：万维不局限**
- 不绑定单一后端（Tauri/Electron/未来新后端均可接入）
- 不绑定单一实现（彩读/红楼梦范例仅作参考，非依赖）
- 不绑定单一数据源（EPUB/TXT/Markdown/书源/未来新格式均可接入）
- 架构预留扩展点，新维度/新引擎/新数据源可随时注册

### 1.2 与彩读/红楼梦范例的关系

| 项目 | 角色 | 关系 |
|------|------|------|
| 彩读（ColorTxt） | 参考实现 | 复用已验证依赖（jszip/opencc/marked 等）、借鉴 Monaco 补丁经验 |
| 红楼梦范例 | 参考实现 | 复用 Tauri+sidecar 通信经验、规避 16 项偏差与 5 大卡顿根因 |
| 维读框架 | 独立框架 | 不依赖二者特定实现，二者仅提供经验输入 |

### 3.2 扩展点契约

每个扩展点契约包含：

```typescript
interface ExtensionPoint {
  id: string;                    // 全局唯一标识
  contractVersion: string;       // 语义化版本号
  layer: 'skeleton';             // 归属层（固定为骨架）
  registeredDimensions: string[];// 已注册维度列表
  validate(contract: DimensionContract): ValidationResult;
  register(dimension: Dimension): void;
  unregister(dimensionId: string): void;
  discover(): DimensionMetadata[];
}
```

### 3.3 维度契约

每个维度必须实现：

```typescript
interface DimensionContract {
  id: string;                    // 维度标识
  category: 'reading' | 'analysis' | 'display' | 'interaction';
  values: DimensionValue[];      // 取值列表
  defaultValue: string;          // 默认取值
  metadata: DimensionMetadata;   // 元数据
  examplePrompts: string[];      // 示例提示词
  execute(value: string, context: ReadContext): Promise<Result>;
}
```

## 四、维度体系

### 4.1 四类维度

#### 阅读维度

| 维度 | 取值 | 说明 |
|------|------|------|
| 阅读模式 | 精读/泛读/略读/研读 | 控制标注密度、分析深度 |
| 阅读辅助 | 阅读尺/禅模式/极简/摸鱼 | ADHD 聚焦、沉浸、分心场景 |
| 文本处理 | 简繁转换/空行压缩/替换规则 | 文本展示层加工 |

#### 分析维度

| 维度 | 取值 | 说明 |
|------|------|------|
| 情感分析 | 七类情绪/极性/强度 | DUTIR + Hownet 双引擎 |
| 人物分析 | 高亮/角色卡/出场曲线/关系图谱 | 别名归并、NER |
| 事件分析 | 抽取/级别/时间线/就地标记 | 5W1H、伏笔起收 |
| 关系分析 | 共现/关系图/邻接矩阵 | 人物关系网络 |
| 词频分析 | 分词/词云/高频词 | jieba + d3-cloud |
| **可扩展** | **新分析维度** | **通过扩展点注册** |

#### 展示维度

| 维度 | 取值 | 说明 |
|------|------|------|
| 着色方式 | 情感着色/人物着色/自定义 | Monaco decorations |
| 图表展示 | 情感曲线/时间线/关系图/词云 | ECharts |
| 卡片展示 | 角色卡/事件卡/伏笔卡 | 弹出面板 |
| 导出格式 | MD/JSON/DOCX/PNG | 导出扩展点 |
| **可扩展** | **新展示方式** | **通过扩展点注册** |

#### 交互维度

| 维度 | 取值 | 说明 |
|------|------|------|
| 选区交互 | 问AI/看分析/查词典/加笔记 | 浮动工具条 |
| 标记交互 | glyph margin事件/伏笔标记 | 装订线标记 |
| 导航交互 | 章节跳转/锚点跳转/进度 | 导航系统 |
| **可扩展** | **新交互方式** | **通过扩展点注册** |

### 4.2 维度组合

通道 = 阅读维度取值 × 分析维度取值 × 展示维度取值 × 交互维度取值

**示例**：
```
提示词："用情感着色精读这一回的人物，展示关系图"
→ 阅读模式=精读
→ 分析维度=情感+人物
→ 展示方式=着色+关系图
→ 交互方式=默认
```

### 4.3 维度正交性保证

- 同类维度取值可正交组合
- 不同维度间无隐式耦合
- 所有维度协作通过调度器，禁止直接调用
- 通道组合校验在解析后执行

## 五、大模型接入与自打磨

### 5.1 大模型在框架中的三个角色

| 角色 | 作用 | 约束 |
|------|------|------|
| **提示词解析器** | 将自然语言解析为阅读配置 | 产出必须通过通道组合校验 |
| **维度内容生成器** | 生成提示词模板/分析参数/展示规则 | 产出必须通过维度契约校验 |
| **自打磨优化器** | 持续优化已有维度内容 | 仅改内容层，骨架不可变 |

### 5.2 自打磨流程

```
1. 维护者触发自打磨（指定维度 + 优化目标）
2. 框架提交当前维度内容 + 契约 + 优化目标给大模型
3. 大模型返回优化后维度内容
4. 框架进行契约校验
   ├─ 通过 → 写入新版本（灰度标记）
   └─ 失败 → 拒绝采纳，记录失败样本
5. 灰度发布（按比例对新用户生效）
6. 质量监控
   ├─ 指标提升 → 扩大灰度
   ├─ 指标持平 → 保持灰度
   └─ 指标下降 → 自动阻断 + 回滚
```

### 5.3 自打磨可打磨的内容

| 内容类型 | 示例 | 大模型如何优化 |
|----------|------|---------------|
| 提示词模板 | "情感着色"→分析维度=情感 | 根据解析历史调整关键词映射 |
| 分析参数 | 情感阈值=0.6 | 根据文本类型自动调参 |
| 展示规则 | 七类情绪对应七种颜色 | 生成新的着色方案 |
| 示例提示词 | "用情感着色分析" | 为新维度自动生成示例 |

### 5.4 自打磨不可修改的骨架

| 骨架元素 | 为什么不可变 |
|----------|-------------|
| 扩展点定义 | 变更影响所有已注册维度 |
| 接口契约 | 变更可能破坏维度实现 |
| 调度核心 | 变更影响全局执行逻辑 |
| 维度注册中心 | 变更影响维度发现 |
| 后端适配接口 | 变更影响多后端兼容 |

- 维度实现跨后端复用

- 切换通过配置，无需修改维度代码

## 七、性能架构

### 7.1 性能红线（从红楼梦范例教训提炼）

| 指标 | 红线 | 机制 |
|------|------|------|
| 装饰渲染 | ≤16ms（60fps） | 视口化渲染 |
| 全书预处理首跑 | ≤15s | 后台异步预处理 |
| 预处理后秒回 | ≤50ms | 入库后直接查库 |
| 提示词解析 | ≤3s | 本地规则+大模型 |
| 本地回退解析 | ≤200ms | 规则匹配 |
| 维度注册查询 | ≤10ms | 内存注册表 |

### 7.2 四大性能保证机制

**1. 分析前置**
- 所有分析在"开书时"预处理，非"阅读时"实时算
- 预处理结果入库，阅读时直接查库
- 缺失数据增量补算

**2. 渲染视口化**
- 装饰仅渲染可见区域 ± 缓冲
- overview ruler 保留全量 collection
- 滚动增量更新

**3. 装饰最小化**
- 段距/缩进用 CSS/ViewZone，非 decoration
- decoration 仅用于必须逐行着色的场景
- 装饰数量与段数解耦

**4. 惰性加载**
- 首帧仅渲染可见区域
- 分析引擎按需加载
- 大文件流式读取

## 十、扩展性保证

### 10.1 扩展点版本化

- 扩展点契约带语义化版本号
- 次版本升级向后兼容
- 主版本升级需迁移指南
- 维度包声明依赖的契约版本

### 10.2 第三方维度包

```
custom-dimension-package/
  ├─ manifest.json        维度元数据 + 契约版本
  ├─ signature.sig        可信签名
  ├─ implementation/      维度实现
  └─ content/             维度内容（提示词模板等）
```

注册流程：
1. 提交维度包 + 签名
2. 注册中心校验签名
3. 校验契约版本兼容
4. 校验维度元数据完备
5. 通过 → 注册成功，发布可用事件
6. 失败 → 返回失败详情

### 10.3 未来扩展方向

## 十二、总结

维读架构的三大核心设计：

1. **提示词控制**：一句话控制阅读方式，解决 8+ 通道组合爆炸问题
2. **骨架/内容分离**：框架稳定留扩展性，大模型自打磨维度内容
3. **万维不局限**：多后端、多引擎、多数据源、新维度随时可扩展

架构不绑定彩读或红楼梦范例的特定实现，二者仅提供经验输入（依赖管理、性能教训、通信协议）。通过扩展点机制，维读可容纳任意新的阅读模式、分析维度、展示方式和交互方式，实现真正的"万维读书"。
