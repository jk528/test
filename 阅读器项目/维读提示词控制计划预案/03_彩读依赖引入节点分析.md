# 彩读（ColorTxt）依赖引入节点分析

> 依据：ColorTxt 官方迭代史研究报告、CHANGELOG v1.1–v3.8.11
> 日期：2026-10-18

---

## 一、总览

彩读用约 5 个月（2026-04 ~ 2026-09）从 v1.0 迭代到 v3.8.11，共 24 个 GitHub Release。每个大版本引入新功能时伴随新依赖，形成了清晰的"功能→依赖"映射链。

| 阶段 | 版本范围 | 时间 | 主题 | 依赖引入密度 |
|------|----------|------|------|-------------|
| 1.x | v1.0–v1.4 | 2026-04 | 阅读器本体打磨 | 低（首发即定） |
| 2.x | v2.0–v2.8 | 2026-05~06 | 语音+AI+编辑三合一 | 高（向量/图表/分词） |
| 3.x | v3.0–v3.8 | 2026-07~09 | 书源+找书+界面革命 | 中（书源引擎/词典/TTS） |

## 二、依赖引入关键节点详表

### 2.1 v1.0（2026-04-04）：首发即定技术栈

| 依赖 | 用途 | 引入原因 |
|------|------|----------|
| **Electron** | 桌面壳 | 跨平台桌面应用框架 |
| **Vue3** | 前端框架 | 组件化开发 |
| **Monaco Editor** | 阅读器内核 | 百万行级性能、行列模型、装饰器体系、stickyScroll |
| **TypeScript** | 类型安全 | 大型项目可维护性 |
| **electron-vite** | 构建工具 | Electron + Vite 集成 |

**关键决策**：Monaco 而非富文本 div——因为小说动辄数百万字、需要精确行列定位（书签/笔记/划线）。灵感来源于 VS Code 插件 vscode-txt-syntax。

### 2.2 v1.2（2026-04-13）：电子书格式支持

| 依赖 | 用途 | 引入原因 |
|------|------|----------|
| **jszip** | EPUB 解压 | EPUB 本质是 ZIP 包 |
| **cheerio** | HTML 解析 | EPUB/MOBI 内容解析 |
| foliate-js | 电子书引擎 | MOBI/AZW3/FB2 等格式支持 |

**演进**：v2.5 将中间格式从 .txt 改为 Markdown；v3.3 将 Markdown 解析从手写正则改为 marked。

### 2.3 v2.0（2026-05 中）：语音朗读 + AI + 编辑三合一

| 依赖 | 用途 | 引入原因 |
|------|------|----------|
| **Edge TTS** | 语音朗读 | 微软免费 TTS，音质好 |
| 阿里云通义（DashScope） | 语音朗读 | 中文 TTS |
| Web Speech API | 系统语音 | 兜底方案 |
| AI 服务商 SDK | AI 阅读助手 | 对话/检索/角色卡 |

**关键决策**：三引擎首发（Edge/系统/通义），后续扩展到 7 引擎。

### 2.4 v2.3（2026-05-26）：本地向量模型——最重依赖引入

| 依赖 | 用途 | 引入原因 |
|------|------|----------|
| **better-sqlite3** | 本地向量库存储 | 同步 API，性能好 |
| **sqlite-vec** | 向量检索 | SQLite 向量扩展 |
| **@huggingface/transformers** | 模型加载 | BGE Small ZH v1.5（512维，~47MB） |

**关键决策**：
- 向量/会话/消息同库（vector.sqlite）
- 默认走 hf-mirror.com 镜像（国内可用性）
- API 密钥改系统钥匙串加密（不再明文）

**影响**：这是项目最重的依赖引入，奠定了 RAG 检索的基础。

### 2.5 v2.4（2026-05-29）：思维导图 + 词云

| 依赖 | 用途 | 引入原因 |
|------|------|----------|
| **markmap-lib** | 思维导图 | Markdown → 思维导图 |
| **d3-cloud** | 词云图 | 词云可视化 |
| **@node-rs/jieba** | 分词 | 词云分词（Rust 绑定，性能好） |

**注意**：@node-rs/jieba 是原生模块，后续导致 macOS Intel 交叉编译崩溃（v3.0 修复）。

### 2.6 v2.5（2026-06-12）：Markdown 中间格式

| 依赖 | 用途 | 引入原因 |
|------|------|----------|
| **marked** | Markdown 解析 | 标准库替代手写正则（v3.3 正式切换） |

**演进**：电子书中间格式从 .txt → Markdown，目录映射为 ATX 标题，支持内链/注脚/外链。

### 2.7 v2.6（2026-06-15）：简繁转换 + 标注

| 依赖 | 用途 | 引入原因 |
|------|------|----------|
| **opencc** | 简繁互转 | 中文转换标准库 |

**同时引入**：划线标注与记笔记功能（参考微信读书网页版）。

### 2.8 v3.0（2026-07-18）：书源引擎——最大子系统

| 依赖 | 用途 | 引入原因 |
|------|------|----------|
| **jsonpath-plus** | JSON 路径解析 | 书源规则引擎 |
| **@xmldom/xmldom** | XML 解析 | XPath 支持 |
| **xpath** | XPath 查询 | 书源规则 |
| tldts | eTLD+1 Cookie 归档 | 书源登录态保持 |
| tough-cookie | Cookie 管理 | 书源网络请求 |

**关键决策**：不造新格式，直接兼容 Legado（阅读）书源生态。用 TypeScript 复刻 Java 规则引擎，是项目最大单一子系统。

**网络层**：普通请求走 Chromium `session.fetch`（浏览器 TLS 指纹），对抗 Cloudflare 类检测。

### 2.9 v3.2（2026-07-30）：书包加密 + WebDAV

| 依赖 | 用途 | 引入原因 |

| AES-256-GCM + PBKDF2 | 书包加密 | .ctzx 加密包 |
| WebDAV | 跨设备同步 | 书架/书源/配置三线同步 |

### 2.10 v3.6（2026-08-12）：词典 + 翻译

| 依赖 | 用途 | 引入原因 |
|------|------|----------|

| 翻译 API（微软/Google/DeepL/百度/有道/腾讯/火山/阿里） | 翻译 | 多翻译服务商 |

### 2.11 v3.7（2026-08-28）：火山引擎 TTS

| 依赖 | 用途 | 引入原因 |
|------|------|----------|
| 火山引擎豆包 TTS 2.0 | 语音朗读 | 444 音色，方言标签 |

**注意**：这是 PR #67，有外部贡献者参与。

## 三、依赖引入规律分析

### 3.1 按功能域分类

| 功能域 | 引入版本 | 核心依赖 | 依赖密度 |
|--------|----------|----------|----------|
| 阅读器内核 | v1.0 | Electron, Vue3, Monaco, TypeScript | 首发 |
| 电子书格式 | v1.2 | jszip, cheerio, foliate-js | 中 |
| 语音朗读 | v2.0→v3.7 | Edge TTS, 通义, MiniMax, MiMo, 火山 | 高（7 引擎） |
| AI/RAG | v2.0→v2.3 | better-sqlite3, sqlite-vec, transformers | 高（最重） |
| 可视化 | v2.4 | markmap-lib, d3-cloud, @node-rs/jieba | 中 |
| 文本处理 | v2.5→v2.6 | marked, opencc | 低 |
| 书源引擎 | v3.0 | jsonpath-plus, xmldom, xpath, tldts | 高（最大子系统） |
| 词典翻译 | v3.6 | StarDict, MDict, 多翻译 API | 中 |
| 界面形态 | v3.8 | （无新依赖） | 无 |

### 3.2 依赖引入策略

**彩读的依赖管理策略**：
1. **优先复用已有生态**：不造新格式（兼容 Legado 书源）、不造新解析器（用 marked 替代手写正则）
2. **原生模块谨慎引入**：@node-rs/jieba 导致 macOS 交叉编译崩溃，后改为原生构建
3. **网络层用浏览器能力**：session.fetch 而非 Node fetch，获得 TLS 指纹伪装
4. **加密用标准算法**：AES-256-GCM + PBKDF2，不自造加密
5. **模型走镜像**：hf-mirror.com 国内镜像，解决可用性

### 3.3 依赖引入时间线

```
v1.0  ├─ Electron + Vue3 + Monaco + TypeScript（首发即定）
v1.2  ├─ jszip + cheerio（电子书格式）
v2.0  ├─ Edge TTS + AI SDK（语音+AI）
v2.3  ├─ better-sqlite3 + sqlite-vec + transformers（向量库）★最重
v2.4  ├─ markmap-lib + d3-cloud + @node-rs/jieba（可视化）
v2.5  ├─ marked（Markdown）
v2.6  ├─ opencc（简繁）
v3.0  ├─ jsonpath-plus + xmldom + xpath（书源引擎）★最大
v3.2  ├─ AES加密 + WebDAV（书包同步）
v3.6  ├─ 词典 + 翻译 API
v3.7  ├─ 火山引擎 TTS
v3.8  └─ （无新依赖，纯界面创新）
```

## 四、对维读框架的启示

### 4.1 应复用的彩读依赖

| 依赖 | 复用场景 | 维读中的用途 |
|------|----------|-------------|
| Monaco | 阅读器内核 | 统一阅读器内核 |
| better-sqlite3 + sqlite-vec | 向量检索 | 提示词语义检索 |
| @huggingface/transformers | 本地模型 | 提示词向量化 |
| marked | Markdown 解析 | 文档格式支持 |
| opencc | 简繁转换 | 文本处理维度 |
| jszip + cheerio | 电子书格式 | 数据源适配器 |
| markmap-lib + d3-cloud | 可视化 | 展示维度 |

### 4.2 应避免的坑

| 坑 | 彩读教训 | 维读预防 |
|----|----------|----------|
| 原生模块跨平台 | @node-rs/jieba 导致 macOS 崩溃 | 优先纯 JS/Wasm 方案，原生模块需跨平台 CI |
| 大文件优化冲突 | Monaco 大文件优化与软换行冲突 | 禁用 Monaco 大文件优化，自管线管理 |
| TLS 指纹识别 | Node fetch 被站点拦截 | 网络请求走浏览器 session.fetch |
| API Key 明文 | 早期明文存配置 | 加密存储，分槽管理 |
| 依赖集中启动 | sidecar 启动加载所有依赖 | 延迟加载，按需初始化 |

### 4.3 维读的依赖引入策略

基于彩读经验，维读框架应采用：

1. **分层依赖**：核心依赖（框架骨架）+ 维度依赖（按需加载）+ 引擎依赖（按需加载）
2. **扩展点隔离**：每个维度的依赖独立加载，不互相影响
3. **延迟初始化**：依赖在首次使用时才初始化，不集中启动
4. **跨平台优先**：优先纯 JS/Wasm 依赖，原生模块需跨平台 CI 验证
5. **复用彩读验证**：已验证的依赖直接复用，不重新选型

## 五、总结

彩读的依赖引入遵循"功能驱动依赖"的清晰路径：
- **v1.0 定基调**：Electron + Vue3 + Monaco + TypeScript
- **v2.3 引入最重依赖**：向量库（better-sqlite3 + sqlite-vec + transformers）
- **v3.0 引入最大子系统**：书源引擎（jsonpath-plus + xmldom + xpath）
- **v3.8 零新依赖**：纯界面创新（极简/阅读尺/摸鱼）

核心规律：**早期版本引入基础依赖（密度高），后期版本以功能创新为主（依赖密度低）**。维读框架应复用彩读已验证的依赖，同时通过扩展点机制实现依赖隔离与按需加载。
