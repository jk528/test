# ColorTxt 阅读分析 · 一键版

把 ColorTxt 的"按维度给关键词上色 + 字频/词频 + 正则检索 + 聚合图表"这套阅读分析方法，落地成一个**不写代码也能用**的 Excel 工作簿：粘贴正文 → 点一个按钮 → 出逐句结果、汇总统计、颜色标注和图表。

本目录所有内容均为新建，未修改 `ColorTxt项目分析` 下的任何原有文件。

---

## 一、交付清单

| 文件 | 说明 |
|---|---|
| `ColorTxt阅读分析_一键版.xlsm` | **可运行工作簿**。12 张工作表、3 个按钮、9 个 VBA 标准模块，已内置样例正文与一次完整分析的结果（打开即可看到效果）。 |
| `VBA源码/*.bas` | 工作簿内全部模块的源码（UTF-8，便于阅读、评审、版本管理）。 |
| `VBA源码_导出GBK/*.bas` | 从**工作簿内**导出的模块（GBK 编码），可直接在中文 VBE 中"导入文件"重装，不会乱码。 |
| `build_workbook.py` | 可复现的生成脚本：用 pywin32 驱动 Excel 建表、导入模块、保存 xlsm、跑一次分析并自检。 |
| `requirements.txt` | 脚本依赖（`pywin32`）。 |
| `build_run_log.txt` | 最近一次生成时，工作簿「运行日志」的导出内容（阶段耗时、告警）。 |
| `README.md` | 本文件。 |

> 为什么是 `.xlsm`：分析逻辑全部由 VBA 实现（分句、匹配裁决、`Characters` 字符级上色、图表），`.xlsx` 无法承载宏。本机已实际生成并打开验证，**不是"有宏但打不开"的空壳**。

## 二、一键流程

1. 双击 `ColorTxt阅读分析_一键版.xlsm`，若出现"安全警告"，点 **启用内容**（详见第七节）。
2. 切到「**正文输入**」表，从 **A5** 开始粘贴正文：**每行一段**；也可以把多行文本整段粘进 A5，宏会按换行自动拆分。想先看效果，直接点「**载入示例**」。
3. 点「**一键分析**」（形状按钮，绑定的宏是 `RunFullAnalysis`）。

一次点击内部依次完成：

```
读配置 → 读词表 → 读正文 → 分句(按标点/长度/超长块) → 关键词匹配
→ 重叠与优先级裁决 → 生成着色片段 → 写「上色预览」 → 逐字符上色
→ 写「逐句结果」/「汇总统计」/「图表数据」/「词频Top」 → 重建「图表」 → 写「运行日志」
```

全程约 **0.8 秒**（内置 506 字样例）到 **10 秒**（5 万字），实测见第六节。

### 可用宏

| 宏 | 用途 | 入口 |
|---|---|---|
| `RunFullAnalysis` | 一键分析（主入口） | 按钮「一键分析」 |
| `MainLoadSample` | 把隐藏的示例原文载入「正文输入」A5 | 按钮「载入示例」 |
| `MainClearInput` | 清空「正文输入」（带确认） | 按钮「清空正文」 |
| `MainClearResults` | 清空所有结果表（配置/词表不动） | VBE 或 `Alt+F8` |
| `MainSelfCheck` | 自检，返回 `sheets/sent/resultRows/hits/coloredChars/...` 一行字符串 | 供自动化验证调用 |

改配置、改词表后**直接再点一次「一键分析」**即生效，不需要改代码。

## 四、配置项（「配置」表，A 列键 / B 列值）

| 键 | 默认 | 含义 |
|---|---|---|
| `match_mode` | 词典最大匹配 | 全局默认匹配方式：`词典最大匹配` / `关键词包含` / `正则`。词表「匹配规则」为"继承"时用此值 |
| `case_sensitive` | 否 | 是否区分英文大小写（汉字不受影响） |
| `overwrite_results` | 是 | 每次运行清空旧结果；选"否"时「逐句结果」追加到末尾，汇总/图表仍按本次重建 |
| `enable_dimensions` | 是 | 维度总开关（否 = 全部停用） |
| `enable_color` | 是 | 是否启用单元格内富文本上色 |
| `color_mode` | 逐字符 | `逐字符` / `整格` / `关闭`。整格最省性能，只用主维度底色 |
| `max_color_sentences` | 300 | 最多对多少句做字符级上色，同时决定「上色预览」行数 |
| `max_hits_per_sentence` | 20 | 单句最多着色片段数，防单句大量 `Characters` 调用 |
| `max_color_chars` | 20000 | 全工作簿着色字符总预算，超出后剩余句子自动降级为整格浅色 |
| `font_name` | 微软雅黑 | 结果表与预览字体 |
| `font_size` | 11 | 结果表字号（预览自动 +1） |
| `result_start_row` | 2 | 逐句结果数据起始行（第 1 行固定表头） |
| `top_n` | 30 | 词频/字频 Top N |
| `summary_top_n` | 5 | 汇总中每个维度展示的 Top 词数量 |
| `ignore_blank_lines` | 是 | 是 = 忽略空行；否 = 空行保留为空段（图表数据里占一行 0 值） |
| `max_paragraph_chars` | 2000 | 单段最大字符数，超出按标点切块（避免撞 32767 上限、也避免超长单元格） |
| `max_sentence_chars` | 200 | 单句最大字符数，超出继续切分 |
| `max_total_chars` | 60000 | 单次最多处理字符数，超出截断并在日志 WARN |
| `max_sentences` | 5000 | 单次最多处理句子数 |
| `chart_type` | 折线堆叠 | `折线堆叠` / `柱状堆叠` |
| `show_finish_msg` | 否 | 结束/失败是否弹窗；自动化验证请保持"否" |
| `min_word_len` | 2 | 词频统计的最小词长（只影响 Top 词表，不影响维度匹配） |
| `dim_人物`…`dim_其他` | 是 | 8 个维度开关，键名必须与「词表」的维度名一致（`dim_` + 维度名） |

参数越界会被 `ValidateConfig` 自动钳制并在日志里写 WARN（例如句子上限被压到 1–5000、字符预算压到 1–60000），不会因为填错值直接崩掉。

## 五、词表与裁决规则

「词表」8 列：**维度名 / 关键词 / 颜色 / 优先级 / 匹配规则 / 启用 / 来源 / 备注**，当前内置 36 条规则、8 个维度、30 个词典词。

- **颜色**：`#RRGGBB`，同维度的词建议同色（可不同）。
- **优先级**：数字越小越优先。当前 人物 1 > 地点 2 > 功法/行为 3 > 物品 4 > 时间 5 > 情绪/神态 6 > 事件 7 > 其他 8。
- **匹配规则**：`继承`（用 `match_mode`）/ `包含`（子串命中）/ `正则`（VBScript.RegExp，支持分组与量词）。
- **启用**：`是/否`，配合 `dim_维度名` 开关；两者都开才生效。
- **来源**：`继承` / `简化`，用于区分"从 ColorTxt 继承的维度"与"为 Excel 落地补的维度"，也会写进词表本身，便于审阅。

**一个词命中多个维度时的裁决**（`AnaResolve`）：

1. 同一句内得到全部候选命中（位置 + 长度 + 维度 + 优先级）；
2. 按 **优先级升序 → 长度降序 → 位置升序** 排序；
3. 依次接受，与已接受片段**重叠**的直接丢弃（`rejected` 计入备注）；
4. 被接受的片段按位置排序，生成 `pos|len|rgb;...` 着色串；
5. 句子"主维度" = 命中次数最多的维度，次数相同按维度优先级。

所以：`炼药` 同时属于「功法/行为」和「事件」，实际归 **功法/行为**；`三年` 与 `三年之期` 重叠时取 **长词**；`城外`（包含规则）在"城外郭"里也会命中，这是"包含匹配"的已知精度代价。

## 六、分析逻辑：哪些继承自 ColorTxt，哪些为 Excel 简化

| 环节 | 做法 | 来自哪里 |
|---|---|---|
| 维度 × 颜色的词表驱动着色 | 维度名 + 关键词 + 颜色，逐词着色 | **继承**：ColorTxt 颜色维度体系、`READ_上色.bas` 的上色思路 |
| 词表外置、可编辑 | 「词表」= 颜色词典，改词表即改分析 | **继承**：`READ_字典查询.bas` 的词典查询、`READ_正则查询替换目录.bas` 的模式列表 |
| 关键词包含匹配 | `InStr` 子串命中 + 全句扫描 | **继承**：`READ_字典查询.bas` 的 `Like "*词*"` 前端匹配 |
| 正则查询 | VBScript.RegExp，词表里写 `正则` 即生效 | **继承**：`READ_正则查询替换目录.bas` 的正则查询与替换、匹配计数 |
| 词频 / 字频 | 关键词词频字典 + 汉字字频字典，Top N 输出 | **继承**：`READ_字频音.bas`、`Read_最新字频.bas`、`READ_正则查询替换目录.bas` 的 matchDict 计数 |
| 聚合 + 堆叠折线图 | 维度 × 段落命中矩阵 → 堆叠折线/柱状图 | **继承**：`READ_聚合生成折线堆叠图.bas` |
| 中文分词 | **词典最大匹配（FMM）**：从长到短在词典里找，命中即切分 | **简化**：原项目用 `PC_005_分词和缺失.bas` 的分词能力；Excel 内没有分词引擎，用词表词典替代 |
| 逐句结果表 | 固定 13 列，一次数组写入 | **简化**：原项目是多表 + 多宏串联，这里收敛成一张结果表 |
| 情绪/神态、事件维度 | 退化为关键词命中 | **简化**：不做句法/语义分析，精度取决于词表 |
| 上色范围 | 句数 + 单句命中数 + 总字符预算三重限制，超预算降级整格 | **简化（必须）**：`Characters` 上色在大文本下会卡死，见第七节 |
| 段落/句子切分 | 标点优先（。！？；…」等），超长段按标点切块，超长句再切 | **改造**：为适配单元格 32767 上限与可读性 |

统计口径：句命中率 = 命中句 / 总句数；维度覆盖率 = 该维度命中句数 / 总句数；字数覆盖 = 该维度命中片段的字符数 / 总字数；「汇总统计」里还有一处一致性校验（逐句结果行数 vs 句子数、命中次数求和的交叉检查）。

## 七、现实约束与已知限制（重要）

### 1. Excel 单元格 32767 字符上限
- 「正文输入」是**一行一段**，单格最多 32767 字符。真正粘贴超长文本时，Excel 本身就会先拒绝。
- 因此 `max_paragraph_chars`（默认 2000）把超长段按标点切成多个段块，`max_sentence_chars`（默认 200）继续切长句；`max_total_chars`（默认 60000）是整次处理的硬上限。
- 实测：单格 6,072 字 → 切成 13 段 / 300 句，正常出结果；7 万字 → 截断到 60,000 字，日志出现 `WARN 已因 max_total_chars 上限截断正文`。

### 2. 单元格内富文本上色的真实代价
- 逐字符上色只能靠 `Range.Characters(start,length).Font.Color`，**每次调用都有固定开销**；几万次调用就会让 Excel 长时间无响应，这是硬限制，不是优化技巧能绕过的。
- 本工作簿的应对：`max_color_sentences`（默认 300 句）+ `max_hits_per_sentence`（默认 20 段）+ `max_color_chars`（默认 20000 字符）三重预算；预算用尽后**剩余句子自动降级为整格浅色底纹**，并在「上色状态」列与日志标注 `降级:整格(总字符预算用尽)`。
- 事实上的后果：**只有前 300 句（默认）有字符级彩色**，「上色预览」也只渲染这些句；但「逐句结果」的"主色(HEX)"和"主维度"列对**全部句子**都有值，汇总与图表也是全量统计。
- 想要"整本书全彩"：把 `color_mode` 改为 `整格`（性能最好，只有主维度底色），或分批次（每批 ≤300 句）跑。

### 3. 中文分词
- Excel 内没有分词引擎。本工作簿用三种可组合的替代：**词典最大匹配（默认）**、**关键词包含**、**正则**。
- 精度边界：词表里没有的词永远切不出来；词频统计本质是"**关键词词频**"，不是通用分词词频（`min_word_len` 只过滤长度，不产生新词）；字频只统计汉字（CJK 区），英文单词不进字频。
- 想提高分词质量：往「词表」里加词/加长词，或把某个维度改成 `正则` 用更精确的模式。

### 4. 其它
- **只读 A 列**：正文必须放 A 列（A5 起），多列/合并单元格不会读。
- **图表最多 120 段**：超出在日志 WARN；完整矩阵始终在「图表数据」。
- **不改原文件**：本工作簿只读「示例原文」，其余全部重写；清空类操作用「清空正文/清空结果」按钮，均有确认框。
- **结果表不含公式**：全部是值（`MainSelfCheck` 返回 `resultsHasFormula=False`），不会出现 `#REF!`/`#VALUE!` 之类的公式错误。
- **全角标点/空行**：全角标点参与分句；空行默认忽略（`ignore_blank_lines=否` 时保留为空段）；段内连续空白会被压缩。
- **宏安全**：见下节。另存时**必须**保持 `.xlsm`，存成 `.xlsx` 会丢宏；Excel 网页版/移动端不能跑 VBA。

### 5. 宏安全与启用
1. 文件下载/拷贝到本机后，右键 → 属性 → 勾选"解除锁定"（若有）。
2. 打开工作簿，顶部出现"安全警告：宏已被禁用" → 点 **启用内容**。
3. 若没出现提示：文件 → 选项 → 信任中心 → 宏设置，选"禁用所有宏，并发出通知"（默认），或把本文件所在目录加入受信任位置。
4. 修改后保存：**文件 → 另存为 → Excel 启用宏的工作簿 (.xlsm)**。

## 八、性能实测（本机实测，非估算）

环境：Windows + Microsoft Excel 16，`DispatchEx` 自动化调用 `RunFullAnalysis`，正文为样例段落循环拼接，默认配置（词典最大匹配 / 逐字符上色 / 300 句 / 2 万字符预算）。

| 场景 | 段落 | 句子 | 分析耗时 | 上色耗时 | 全流程 |
|---|---|---|---|---|---|
| 内置样例 506 字 | 10 | 23 | 0.094 s | 0.094 s | **0.84 s** |
| 5,050 字 | 75 | 228 | 0.672 s | 0.617 s | **3.60 s** |
| 20,036 字 | 297 | 910 | 2.820 s | 0.813 s | **5.06 s** |
| 50,050 字 | 742 | 2,274 | 6.875 s | 0.789 s | **10.38 s** |
| 60,000 字（截断上限） | 1,186 | 2,726 | 7.039 s | 0.766 s | **9.87 s** |
| 50,050 字 + 关闭上色 | 742 | 2,274 | 8.945 s | 0 | **10.54 s** |
| 单格 6,072 字（切成 13 段） | 13 | 300 | 0.781 s | 0.797 s | **3.88 s** |

结论：

- **耗时主要在匹配**（36 条规则 × 逐句 `InStr` + FMM 词典扫描），不在上色。关掉上色并不会明显变快（上表倒数第二行）。
- **建议可用范围：≤2 万字（约 900 句）5 秒级；≤5 万字（约 2,300 句）10 秒级**；超过 6 万字请调大 `max_total_chars` 或分批跑。
- 表格渲染（写「逐句结果」的行、`Characters` 上色）在 5 万字内都不会让 Excel 卡死；只有"给所有句子都做字符级彩色"才会卡死，所以默认只上色前 300 句。
- 首次运行会多一点（VBA 首次编译 + 首次写表布局），后续同会话运行更快。

## 九、重建 / 重新安装宏

### 方式 A：用脚本一键重建（推荐）

```powershell
pip install -r requirements.txt      # 只需 pywin32
python build_workbook.py
```

前提：本机装有 Microsoft Excel。脚本会：

1. 新建工作簿、建 12 张表、写配置/词表/样例、加 3 个按钮；
2. 把 `VBA源码/*.bas` 转成 GBK 临时文件后 `VBComponents.Import`（中文 Windows 的 VBE 使用 ANSI/GBK，直接导 UTF-8 会乱码）；
3. `SaveAs(..., FileFormat=52)` 存成 `.xlsm`；
4. 运行一次 `RunFullAnalysis` 与 `MainSelfCheck`，把结果与「运行日志」写到 `build_run_log.txt`；
5. 把工作簿内模块**导出**到 `VBA源码_导出GBK/`；
6. 结束时恢复 `AccessVBOM` 注册表项（脚本运行期间临时设为 1，否则无法写 VBA 工程）。

### 方式 B：手工导入模块

1. 新建工作簿，按第三节的表名**精确**建 12 张表（`modUtil` 是按表名取工作表的，表名不一致会直接报错）；
2. `Alt+F11` 打开 VBE → 文件 → 导入文件 → 选择 `VBA源码_导出GBK/*.bas`（GBK 版，9 个模块）；
3. 在「正文输入」放按钮并指定 `RunFullAnalysis`（可选）；
4. 另存为 `.xlsm`。

> 若要导入 `VBA源码/`（UTF-8）里的文件：请先用记事本/编辑器另存为 ANSI(GBK)，否则中文会乱码并触发"编译错误"。

### 文件依赖关系

`modMain`（入口）→ `modConfig`（配置）/ `modLexicon`（词表）/ `modText`（切分）/ `modAnalyze`（匹配裁决与统计）/ `modOutput`（写表）/ `modColor`（上色）/ `modChart`（图表）；全部依赖 `modUtil`（表引用、颜色转换、日志、字典排序）。

## 十一、快速排错

| 现象 | 处理 |
|---|---|
| 点按钮没反应 | 顶部"启用内容"是否点了；`Alt+F8` 看 `RunFullAnalysis` 是否在列表里 |
| 提示"词表没有可用关键词" | 「词表」F 列启用是否为"是"，「配置」`dim_维度名` 是否为"是"，维度名与词表是否完全一致 |
| 提示"正文输入为空" | 文本是否放在 **A5 起**的 A 列（不是 A1–A4 提示区） |
| 日志里 `已因 max_total_chars 上限截断` | 调大 `max_total_chars` 或分批 |
| 只有前若干句有彩色 | 正常：`max_color_sentences` 默认 300；调大或改 `color_mode=整格` |
| 打开后看不到「示例原文」 | 它是 VeryHidden，用「载入示例」按钮即可，不需要直接看 |

所有阶段耗时、WARN、ERROR 都在「运行日志」表，先看它。
