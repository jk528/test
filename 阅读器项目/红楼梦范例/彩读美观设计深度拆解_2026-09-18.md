# 彩读（ColorTxt）美观设计深度拆解

> 调研日期：2026-09-18
> 调研目标：回答「彩读是如何解决美观问题的」，颗粒度到具体色值、像素、CSS 属性、动画曲线
> 资料来源：ColorTxt GitHub 源码（ssnangua/ColorTxt）+ README + 第三方评测

---

## 核心结论：彩读的「美观」不是靠某一个点，而是 6 层叠加

```
第6层 动效系统      →  140ms~250ms ease-out，浮动面板滑入滑出
第5层 排版美学      →  京华老宋体 + 24px + 1.5行高 + 50%行长居中
第4层 阅读细节      →  阅读尺淡化 + 粘性标题融合 + 关闭行高亮
第3层 背景系统      →  底色 + 纹理叠加 + 7种混合模式
第2层 配色系统      →  8套主题 × 明暗双色 × 语法级文字着色
第1层 基础清零      →  关掉 Monaco 所有「代码编辑器」特征
```

**最关键的洞察**：彩读的底层是 Monaco（代码编辑器），但用户完全感觉不到——因为它把 Monaco 所有「代码编辑器特征」全部关掉或覆盖了，然后在上面重建了一整套「阅读器」视觉语言。

---

## 第 1 层：基础清零 — 把代码编辑器变成阅读器

这是最容易被忽略但最重要的一步。Monaco 天生是写代码的，有行号、glyph 边距、小地图、折叠、当前行高亮、光标闪烁……这些东西不关，怎么调都像 IDE 不像阅读器。

### 彩读关掉了什么

| Monaco 特性 | 只读模式 | 为什么关 |
|-------------|---------|---------|
| `lineNumbers` | `off` | 行号是代码编辑器的标志 |
| `glyphMargin` | `false` | 左侧边距（断点/书签槽）破坏阅读沉浸感 |
| `minimap` | `disabled` | 小地图是代码导航工具，阅读不需要 |
| `folding` | `false` | 代码折叠箭头干扰阅读 |
| `contextmenu` | `false` | 右键菜单自己重写（阅读相关功能） |
| `renderLineHighlight` | `none` | **关键** — 整行铺底色是 IDE 感的来源 |
| `cursorBlinking` | `solid` + `cursorWidth: 0` | 阅读模式不显示光标 |
| `roundedSelection` | `false` | 圆角选区会切坏背景纹理 |
| `scrollBeyondLastLine` | `false` | 阅读到文末就停，不要空白 |
| `useShadowDOM` | `false` | 便于 CSS 覆盖 Monaco 内部样式 |
| `disableMonospaceOptimizations` | `true` | 等宽字体优化对中文阅读有害 |
| `largeFileOptimizations` | `false` | 关闭 tokenization 加速，保证着色完整 |

> **对比当前项目**：我们也关了大部分，但 `renderLineHighlight` 可能没关（或设成了 `"line"`），`cursorWidth` 可能还在，`glyphMargin` 我们因为书签功能是开着的（这是功能取舍不是美观问题）。

## 第 2 层：配色系统 — 8 套主题 × 明暗双色 × 语法级文字着色

### 2.1 不是"亮/暗"两个主题，是 8 套 × 2

| 方案名 | 亮底 | 暗底 | 纹理 | 风格 |
|--------|------|------|------|------|
| 默认 | `#f4ead7` 奶黄 | `#1e1e1e` VS Code暗 | 无 | 护眼奶黄 / 代码暗底 |
| 素纸 | `#ffffff` 纯白 | `#0d0d0d` 纯黑 | paper 纹理 | 纯白纸感 |
| 羊皮纸 | `#f4d8a6` 深黄 | `#21201c` 暗棕 | parchment 纹理 | 复古书卷气 |
| 护眼 | `#e6eace` 豆绿 | `#333627` 暗绿 | eye-green 纹理 | 绿色护眼 |
| 毛绒地毯 | `#faf0e8` 暖肤 | `#342c2a` 暖棕 | plush-rug 纹理 | 温暖舒适 |
| 墨竹 | `#e6eace` 浅绿 | `#333627` 暗绿 | bamboo-grove 纹理 | 国风竹韵 |
| 雪梅 | `#7f8f9f` 冷灰 | `#33363b` 灰蓝 | plum-blossom 纹理 | 冷调雪景 |
| 星空 | — | `#03040c` 深邃黑 | night-sky 纹理 | 仅暗，夜空感 |

**设计手法**：每套主题不是只换背景色，而是 **底色 + 纹理 + 文字配色** 三位一体。文字颜色在亮/暗模式下有独立的色值表，保证对比度和可读性。

### 2.2 文字不是一个颜色，是语法级着色（这是彩读的灵魂）

彩读的文字不是全黑/全灰，而是把中文文本按"词性"分成 7 种颜色：

| 元素 | 亮色 | 暗色 | 类比代码 |
|------|------|------|---------|
| 正文 | `#000000` | `#d4d4d4` | 普通文本 |
| 章节标题 | `#b88230` | `#569cd6` | 关键字/标题 |
| 引号内文字 | `#a31515` | `#ce9178` | 字符串 |
| 括号内文字 | `#001080` | `#9cdcfe` | 变量/参数 |
| 标点 | `#267f99` | `#4ec9b0` | 运算符 |
| 数字 | `#795e26` | `#dcdcaa` | 数字字面量 |
| 英文/字母 | `#af00db` | `#c586c0` | 类型/函数 |

**为什么这么设计**：直接复用了 Monaco 的语法高亮引擎（tokenization），把中文文本的"语法元素"映射到 VS Code 的配色体系上。用户不需要任何设置，打开书就有颜色层次——这就是"彩读"名字的由来。

> **对比当前项目**：我们的文字只有一个颜色（正文字 + 章节标题色），情感着色是整行底色，人物高亮是下划线/底色。彩读的做法更精细——**字本身就有颜色**，阅读时视觉层次更丰富，但又不干扰阅读（因为颜色都很克制，是低饱和的）。

### 2.3 高亮与标注的颜色体系

**自定义高亮词（前景色）**：10 色，Web 安全色，色相均匀分布（每 36° 一个）

- 亮：`#CC0000` `#CC6600` `#996600` `#669900` `#009933` `#009999` `#0033CC` `#6633CC` `#990099` `#CC3399`
- 暗：`#FF6666` `#FFCC66` `#FFFF66` `#66FF66` `#66FFFF` `#66CCFF` `#9999FF` `#CC66FF` `#FF99CC` `#FFCCCC`

**划线标注色**（马克笔/波浪线/直线）：5 色，亮暗相同

`#FF6B9D` 粉红 / `#A855F7` 紫 / `#3B82F6` 蓝 / `#22C55E` 绿 / `#F59E0B` 橙

## 第 3 层：背景系统 — 不是纯色，是「底色 + 纹理叠加」

这是彩读在视觉质感上最大的秘密。

### 3.1 两层结构

```
┌─────────────────────────────┐
│  纹理层（texture）            │  ← 纸纹/竹纹/星空等图片
│  混合模式：multiply/soft-light│
│  透明度：可调                 │
├─────────────────────────────┤
│  底色层（readerBg）           │  ← CSS 变量控制的纯色
└─────────────────────────────┘
```

### 3.2 实现方式

**Monaco 所有层全部设为透明**，底色和纹理只画在最外层 `.readerSurfaceBg`：

```css
.monaco-editor,
.overflow-guard,
.monaco-scrollable-element,
.editor-scrollable,
.margin,
.monaco-editor-background {
  background-color: transparent !important;
}
```

这样做的好处：
1. 纹理只渲染一次，不随滚动重绘
2. 文字、高亮、选区都是半透明叠加在纹理上，质感自然
3. 切换主题只改一个 CSS 变量，瞬间完成

### 3.3 纹理系统的参数

| 参数 | 选项 |
|------|------|
| 混合模式 | normal / multiply（正片叠底）/ lighten / overlay / soft-light（柔光）/ screen / darken |
| 尺寸 | cover（填满）/ contain（包含）/ auto（原始） |
| 定位 | 3×3 = 9 种（left/center/right × top/center/bottom） |
| 重复 | 开/关 |
| 透明度 | 0% - 100% |

**典型组合**：
- 素纸：paper 纹理 + multiply 混合 + auto 尺寸 + 重复
- 羊皮纸：parchment 纹理 + darken（亮）/ multiply（暗）
- 毛绒地毯：plush-rug 纹理 + soft-light 混合 + opacity 0.6（亮）/ 1.0（暗）
- 墨竹：bamboo-grove 纹理 + cover 尺寸 + center bottom 定位 + 不重复

> **对比当前项目**：我们的背景是纯色（亮 `#faf8f0` / 暗 `#1a1a2e`），没有纹理层。这是视觉质感差距最大的地方——纯色再好看也是"平"的，加了纸纹就有"纸"的感觉。

## 第 4 层：阅读细节 — 三个关键设计

### 4.1 阅读尺：不是"高亮聚焦行"，是"淡化非聚焦行"

| 维度 | 彩读做法 | 常见做法 |
|------|---------|---------|
| 核心思路 | 非聚焦行 opacity 降到 0.2 | 给聚焦行加背景色/边框 |
| 视觉效果 | 聚焦行清晰，周围朦胧 | 聚焦行有额外色块，打断阅读 |
| 实现方式 | `.view-line { opacity: 0.2 }` + `.view-line:has(.focus) { opacity: 1 }` | decoration 加整行底色 |
| 可调参数 | 淡化程度（0~1）、聚焦行数（1~10） | 颜色、高度 |
| 动画 | 0.2s ease 淡入淡出 | 通常无动画 |
| 粘性标题 | 也会被淡化（默认开启） | 通常不受影响 |
| 无障碍 | 支持 `prefers-reduced-motion` | — |

**设计意图**：彩读的 README 明确写了"适合注意力不容易集中的人（ADHD）"。淡化周围行比高亮当前行更柔和——没有额外的视觉元素加进来，只是降低了干扰项的存在感。

> **对比当前项目**：我们的阅读尺是"聚焦带"（3 行高亮），用 decoration 加半透明底色。彩读的做法更"轻"——不靠加东西，靠减东西（降低 opacity）。两种风格各有侧重，但彩读的更接近"隐形辅助"的感觉。

### 4.2 粘性章节标题：不是浮层，是"融合"

| 设计点 | 彩读做法 | 效果 |
|--------|---------|------|
| 背景色 | `var(--reader-bg)`（与阅读区底色完全一致） | 看不出是浮层 |
| 阴影 | `none` | 无缝衔接 |
| 文字色 | `var(--reader-chapter-title)` | 与正文标题颜色一致 |
| 内层透明 | line-numbers 和 scrollable 都是 transparent | 透出底色+纹理 |
| 点击事件 | `pointer-events: none` | 防止误触跳转 |

**关键**：粘性标题不是"悬浮在内容上方"的一个条，而是"内容延伸上来"的一部分。背景完全一致，没有阴影，没有分隔线——只有文字颜色告诉你"这是章节标题"。

> **对比当前项目**：我们的 StickyScroll 也做了，但可能用了 Monaco 默认的 sticky widget 样式（有背景色、有阴影），看起来还是代码编辑器的感觉。彩读的做法是把 sticky widget 的背景改成和阅读区一样，彻底"融"进去。

### 4.3 选区与当前行：克制到几乎看不见

| 元素 | 亮色 | 暗色 |
|------|------|------|
| 当前行高亮 | 完全关了（`none`） | 完全关了 |
| 选区背景 | `rgba(173,214,255,0.55)` | `rgba(38,79,120,0.45)` |
| 选区圆角 | 关了（`roundedSelection: false`） | 关了 |

**为什么关圆角选区**：因为选区如果是圆角的，会"切"掉背景纹理的边缘，纸的质感就破了。方角选区和纹理融合得更好。

## 第 5 层：排版美学 — 字体 + 字号 + 行高 + 行长

### 5.1 字体：京华老宋体（内置字体）

这是彩读在"颜值"上最下血本的地方——**内置了一套中文字体**。

**字体名**：京華老宋体（KingHwa OldSong）
**文件**：`KingHwa_OldSong_3.0.ttf`（内置，通过 `@font-face` 加载）

**字体预设系统**（4 套，跨平台自动适配）：

| 预设 | Windows | macOS | Linux |
|------|---------|-------|-------|
| 京华老宋体 | KingHwa OldSong | KingHwa OldSong | KingHwa OldSong |
| 雅黑/苹方 | Microsoft YaHei | PingFang SC | Noto Sans CJK SC |
| 宋体 | SimSun | Songti SC | Noto Serif CJK SC |
| 楷体 | KaiTi | Kaiti SC | AR PL UKai CN |

**为什么默认用老宋体**：
1. **辨识度高** — 老宋体的衬线（字脚）在小字号下比黑体更易读
2. **书卷气** — 宋体是印刷书籍的标准字体，有"读书"的心理暗示
3. **内置一致性** — 不依赖系统字体，Windows/Mac/Linux 看起来都一样

> **对比当前项目**：我们的默认字体是系统默认（Windows 上可能是微软雅黑，Mac 上是苹方），没有内置字体。字体对阅读体验的影响怎么高估都不为过——这是"看起来专业"和"看起来像个 demo"的分水岭。

### 5.2 字号与行高

| 参数 | 默认值 | 范围 |
|------|--------|------|
| 字号 | **24px** | — |
| 行高倍数 | 1.5 | 1.0+ |
| 段间距 | 10px | 0-100 |
| 字间距 | 0px | -5~20 |
| 左右边距 | 10px | 0-160 |

**注意**：默认字号 24px，比一般网页正文（16px）大很多。阅读器的核心是"读得舒服"，不是"塞得多"。

### 5.3 行长控制（全屏模式的核心）

这是排版美学最容易被忽略但最重要的参数。

- **全屏阅读区域宽度**：默认 **50%** 视口宽度（可调 30%-100%）
- **居中留白**：阅读区居中，两侧留白与正文同底色/纹理
- **四周边距**：各 20px

**为什么 50% 是默认值**：印刷排版的黄金法则——**行长 60-75 个汉字最舒适**。太宽了换行费劲，太窄了频繁换行打断思路。50% 宽度（在 1080p 屏幕上约 960px，放 24px 字大约 40 字一行）是保守但安全的选择。

> **对比当前项目**：我们的阅读区是撑满容器的（flex: 1），没有行长控制。宽屏下一行可能有 80+ 字，读起来很累。这是体验差距很大的一个点。

## 第 6 层：动效系统 — 克制到你感觉不到，但没了就不对

彩读的动效全部在 **140ms ~ 250ms** 这个区间，用 `ease-out` 曲线——快、轻、不拖泥带水。

### 6.1 面板浮动动画

| 面板 | 动画 | 时长 | 曲线 |
|------|------|------|------|
| 浮动顶栏 | `translateY(-8px) → 0` + opacity | 140ms | ease-out |
| 浮动底栏 | `translateY(8px) → 0` + opacity | 140ms | ease-out |
| 浮动侧栏 | `translateX(-12px) → 0` + opacity | 180ms | ease-out |
| 拖放遮罩 | opacity 0 ↔ 1 | 150ms | ease |
| 提示条 | opacity → 0 | 250ms | ease |
| 阅读尺淡化 | opacity 0.2 ↔ 1 | 200ms | ease |
| 滚动条淡出 | opacity | 250ms | ease |

**设计原则**：
1. **出现快，消失也快** — 140ms 几乎是"瞬发"的感觉，不会让用户等
2. **带方向的位移** — 从哪个方向来就往哪个方向走，符合物理直觉
3. **位移很小** — 8px / 12px，只是"动了一下"的感觉，不是大张旗鼓的动画

### 6.2 滚动相关

| 特性 | 默认值 |
|------|--------|
| 平滑滚动 | 开启 |
| 滚轮倍率 | 1x |
| 快速滚动（Alt+滚轮） | 5x |
| 滚动条宽度（全屏） | 14px |
| 滚动条淡出（极简模式） | 随光标隐藏，250ms |

### 6.3 悬停反馈

| 元素 | 悬停效果 |
|------|---------|
| 内部链接 | 下划线（实线） |
| 外部链接 | 下划线（虚线，区分内部） |
| Resizer 分隔条 | 300ms 延迟后显示 accent 色蓝条 |
| 滚动条滑块 | 颜色变深（亮：rgba(100,100,100,0.4) → 0.55） |
| 菜单项 | 背景色变为 list-item-bg-hover |

## UI 组件的美学细节

### 圆角体系

| 组件 | 圆角 | 风格 |
|------|------|------|
| 右键菜单 | 4px | 微圆，克制 |
| 悬停/补全面板 | 3px | 更小，紧凑 |
| 拖放遮罩文字 | 4px | 与菜单一致 |
| 全屏提示条 | 999px | pill 形（胶囊），完全圆头 |

### 阴影体系

| 组件 | 阴影 | 用途 |
|------|------|------|
| 浮动顶栏 | `0 6px 28px rgba(0,0,0,0.45)` | 大阴影，强调浮层感 |
| 浮动底栏 | `0 -6px 28px rgba(0,0,0,0.45)` | 同上，反向 |
| 浮动侧栏 | `6px 0 28px rgba(0,0,0,0.45)` | 同上，横向 |
| 菜单/面板 | `0 2px 8px color-mix(..., fg 12%, transparent)` | 小阴影，轻量浮层 |

**设计手法**：浮动的大面板用大阴影（28px 模糊半径），强调"浮在内容上方"；菜单和小面板用小阴影（8px 模糊 + 颜色混合），不抢戏。

### 图标系统

- **全部 SVG 线性图标**，自制，统一尺寸
- 不是 emoji，不是填充图标 — 线性风格与 VS Code/Monaco 生态一致
- 数量极多：章节、调色板、高亮、全屏、阅读尺、书签、笔记、编辑、播放、AI 对话、思维导图、词云、人物、词典、翻译、暗色、快捷键、字体、行高……

## 三种沉浸模式

### 1. 全屏阅读（禅模式）

- 阅读区居中，宽度可调（默认 50%）
- 鼠标静止后隐藏系统光标
- 左下角显示系统时间（默认开启）
- 顶部 pill 形提示条（`border-radius: 999px`）

### 2. 极简视图

- 顶/侧/底栏全部隐藏，阅读区撑满
- 鼠标移到边缘唤出对应面板
- 浮动面板带大阴影，浮在内容上方

### 3. 摸鱼模式

- 无边框、无任务栏、透明背景、始终置顶
- 独立小窗口，像便签一样浮在其他窗口上面

## 与当前项目的差距对照

按"投入产出比"排序，从最高到最低：

| 差距 | 影响 | 实现难度 | 优先级 |
|------|------|---------|--------|
| 背景纹理层（纸感） | ⭐⭐⭐⭐⭐ | 中（需要纹理图 + CSS 叠加） | 🔴 高 |
| 字体（京华老宋体） | ⭐⭐⭐⭐⭐ | 高（字体授权 + 文件体积） | 🟡 中 |
| 行长控制（50%居中） | ⭐⭐⭐⭐ | 低（CSS max-width + margin auto） | 🔴 高 |
| 默认字号 24px | ⭐⭐⭐⭐ | 极低（改默认值） | 🔴 高 |

## 总结：彩读的"美观公式"

```
美观 = 清零（去掉 IDE 感）
     + 底色 + 纹理（纸质感）
     + 好字体 + 合适的字号行高行长（排版功底）
     + 克制的动效（140-250ms ease-out）
     + 融合式设计（粘性标题不是浮层是内容延伸）
     + 语法级文字着色（彩读的灵魂差异化）
```

**最值得抄的 3 件事**（投入产出比最高）：
1. **背景加纹理** — 立刻从"平"变"有质感"
2. **行长控制 + 更大的默认字号** — 阅读舒适度立竿见影
3. **粘性标题融合 + 关闭行高亮** — 从"IDE"变"阅读器"的关键两步
