# 拆分文本白描逐回分析·通用任务白描

> **性质**：本文是「对已拆分长文本做白描手法逐章统合分析」这一任务的完整生成逻辑白描——流程、模板、脚本、校验与防错全部来自一次实际跑通的实战任务，未经过验证的环节不写入。
> **通用性约定**：全文不绑定任何具体书名、章数与绝对路径。凡随项目变化的量，一律使用统一占位符（见 §0.2），复用时替换占位符即可；文档内示例路径均为相对路径形式。
> **生成日期**：2026-09-24
> **版本**：v2（2026-09-24 修订）——**首轮片段口径由「精选」改为「全集」**，取消 v1 的「首轮精选 2–4 条 + 补全轮」两轮制。

### v1 → v2 变更摘要

| 项 | v1（精选口径） | v2（全集口径） |
|---|---|---|
| 首轮每章片段数 | 只写最典型 2–4 条 | = 该章命中的全部手法，一一对应 |
| 常规轮次 | 两轮（首轮 + 补全轮，补全轮可选） | **一轮**（首轮即全集） |
| 补全轮定位 | 常规第二阶段 | 降级为「补漏轮」，**仅异常时启用** |
| 首轮写入方式 | 一次性整写 | **强制分段落盘**（每 3–6 章一次，先覆写后追加） |
| 一致性校验 | 命中 ⊆ 片段（补全轮后） | 命中 ⊆ 片段，且首轮后即应成立 |

> **为什么必须改**：v1 的差集（命中 − 精选片段）实测约占总命中点位的 59%，即首轮只完成了四成工作量，其余靠补全轮补——而补全轮恰恰是空返回重灾区（10 批并发 6 批失败）。v2 把全集要求前置到首轮，省掉一整轮调度，代价是首轮输出变长，用「分段落盘」对冲。

## 0. 阅读约定

### 0.1 任务一句话定义

输入「一部已按章拆分的文本 + 一个写作手法分析框架」，输出「一份含全书统计与逐章**全集引证**的统合分析 md」。全程由多个并行子代理执行阅读与分析，主控负责调度、统计、拼接与校验；**首轮即产出全集片段，不经「精选再补全」的两段式过程**。

## 一、输入要求与前置勘察

### 1.1 输入硬性要求

1. **文本已拆分**：每 {章单位} 一个独立 txt，位于同一 {拆分目录}；
2. **文件名含序号**：序号在文件名前缀且可机械提取（如 `001_xxx.txt`），这是分批与排序的唯一依据；
3. **文件内首行为该章标题**（`第N{章单位}　标题`），供分析条目引用；
4. **无缺号**：序号从起点到终点连续；如勘察发现缺号，先补拆或把实际清单作为事实源；
5. **框架先定**：分析框架（§2）先于读文本确定，防止各代理自行发挥造成口径漂移。

### 1.2 勘察步骤（主控执行）

| 勘察项 | 方法 | 用途 |
|---|---|---|
| 文件总数与序号连续性 | 列目录 + 序号集合检查 | 确定 {总章数}，缺号即报 |
| 单文件字节数区间 | 列目录取大小 | 决定 {批次大小}（读入侧） |
| 标题行格式 | 抽读首尾各 1 个文件 | 确定条目标题写法与 {章单位} |
| 文件名特殊字符 | 检查全角空格等 | 决定代理取文件时用 glob 还是明确列表 |
| 编码 | 抽读确认乱码情况 | 决定脚本读写编码参数 |
| **单章手法密度**（抽样） | 抽 3–5 章试跑一遍框架，数命中数 | 估 {单章命中区间}，定 {批次大小}（输出侧） |

> 实测提示：中文拆分文件名常含**全角空格**，直接拼路径易出错。稳妥做法二选一：① 在调度模板中给出完整文件名列表；② 要求子代理用 glob 列目录后按序号筛选，不手工拼文件名。

## 二、分析框架（与目标文本无关，可直接复用）

### 2.1 框架来源

「白描」中文改写方法论（开源项目 adoresever/baimiao，Apache-2.0）。原用途是中文初稿润色，本任务**反向使用**：不改写、只拆解——用它作识别框架去分析成熟文本。其"成熟文本：原样返回"的前提恰好保证分析过程不产生改写污染。

| 一·让内容落地 | 动作承载 | 评价让位于动作 |
| 一·让内容落地 | 物件承载 | 意思落在物件状态上 |
| 一·让内容落地 | 数字对比 | 两个同口径数字直接对比 |

五个观察维度：①内容是否落地 ②信息顺序是否清楚 ③句子是否有呼吸 ④叙述态度是否合适 ⑤结尾是否收得住。维度特征融入手法解析，不单列评分。

### 2.3 判定口径（所有代理统一遵守）

- **信号导向**：只认文本中实际出现的信号，边界模糊的不收——统计宁可低估不做高估；
- **命中 = 片段（首轮即全集）**：每 {章单位} 的「手法片段」必须覆盖该 {章单位}「本{章单位}命中」清单里的**全部**手法，一一对应。允许**合条写法** `手法A（手法B）`、`手法A/手法B` 让一条片段覆盖 2 个手法，但校验脚本必须能归一解析（§6.2）。
- **取消精选**：不再规定"每章只写最典型 2–4 个"。片段条数由该章实际命中数决定，不设上限；同一手法仍只举 1 个最典型片段，不重复举例。

## 三、产物与目录结构

```
{中间目录}（.temp 下，过程产物，不面向用户）
├── batch_01.md … batch_{总批数}.md   # 各批次逐章分析（首轮即为全集片段；若曾补漏，为补漏后版本）
├── hits.txt                          # 全书命中数据，每行：章号|手法A,手法B,…
├── head.md                           # 统合文档头部（框架说明+全书统计）
└── tail.md                           # 统合文档尾部（统合观察+使用说明）

{输出目录}
└── {输出文件名}                       # 最终交付：head + 全部 batch + tail 拼接
```

每章条目格式（所有 batch 文件统一，这是机器校验的前提）：

```markdown
### 第 N {章单位}　标题上联　标题下联

**主线**：（30字以内，"谁+做了什么+结果"句式）

**手法片段**：

1. **手法名**：「原文引用（50字以内，逐字）」——解析：信号与效果，一到两句。

2. ……（**条数 = 该{章单位}命中的手法数**；合条写法可让条数略少于手法数）

**本{章单位}命中**：手法A、手法B、手法C（顿号分隔，供机器解析）
```

> 三条格式约定（**中途不可变更**）：① 片段手法名集合必须覆盖命中清单（全集口径）；② 命中行格式固定；③ 合条写法只有上述两种。统计脚本、覆盖校验、补漏差集全部依赖这三条。
> 全集口径下每章条目长度是 v1 的 2–3 倍，因此 batch 文件**必须分次写入**（§5.1 第五节），不可整批一次性写。

## 四、完整生成流程（八步）

流程总览：勘察 → 分批 → **首轮分析（全集）** → 命中回收与统计 → 头尾撰写 → 统合拼接 → 完整性校验 →（**仅异常时**）补漏轮。

### 步骤 1：文本勘察

按 §1.2 执行，产出：{总章数}、{批次大小}、{总批数}、{单章命中区间}、文件名清单、编码与特殊字符结论。

**验收标准**：序号集合 = 1..{总章数} 无缺口；单章字节区间已知；单章手法密度已有抽样估值。

### 步骤 2：批次规划

**批次大小计算**（两道约束，取小者）：

```
读入侧：{批次大小} ≤ floor(100KB ÷ max{单章字节区间})
输出侧：{批次大小} ≤ floor(60KB ÷ 单章命中的中位字数预算)
                     其中 单章输出 ≈ 命中数 × 约 120 字，全集口径实测约 1.5–2.5KB/章
{批次大小} = min(两者)，并落在 [6, 12] 区间
{总批数}   = ceil({总章数} ÷ {批次大小})
```

**全集口径的输出预算（v2 新增，最容易踩的坑）**：v1 首轮每章只写 2–4 条，v2 每章片段数 = 命中数（示例任务实测 4–17 条/章，均值约 10）。单批输出约为 v1 的 2–3 倍。因此：

- 若 `max{单章字节区间}` > 12KB，或 `{单章命中区间}` 上限 > 15，**把 {批次大小} 下调到 8–10**，给输出与写入留余量；
- 无论批次大小，首轮**必须分段落盘**——见 §5.1 第五节，这是 v2 取代 v1「两轮制」的核心稳定性措施。

**并行调度**：一次消息内并发多个子代理（实测每波 5 个稳定；10 个同波未观察到失败，但波内越多、空返回比例越高）。批次划分按序号连续切块，不交错。

**验收标准**：批次表已建（批次号 → 章号区间 → 文件清单 → 输出文件名），每批一个 batch_NN.md 目标路径。

### 步骤 3：首轮逐章分析（并行，产出全集）

向 {总批数} 个子代理派发模板 A（§5.1）。核心约束：

1. 按序号顺序**逐个**读文件、读完一章**立即写完该章的全部分片段**，再读下一章（避免一次读入全部撑爆上下文）；
2. **全集口径**：每章「手法片段」的手法名集合必须覆盖「本{章单位}命中」清单里的**全部**手法，一一对应（允许合条）；**不得只挑最典型的几条写**；
3. 引文逐字摘自所读文本，**禁止凭记忆改写**；
4. 每章必须输出完整"命中"行，且与片段手法名集合一致；
5. **分段落盘**：每完成 3–6 {章单位} 写一次文件（先覆写前段，再用 Edit 追加后段），**禁止全部完成才一次写入**；
6. 返回只给两行：完成状态 + 命中汇总（`N{章单位}:手法A|手法B|…` 分号分隔），**不粘贴分析全文**。

**验收标准**：每批文件存在、章标题数 = 该批章数、每章有命中行、**且每章片段手法集合 ⊇ 该章命中清单**（全集）。空返回批次按 §7.7 处置。

### 步骤 4：命中数据回收与全书统计

1. 把各代理返回的命中汇总（或从各 batch 文件反解析，二者互为校验）整理为 `hits.txt`：每行 `章号|手法A,手法B,…`；
2. 跑统计脚本（§6.1）产出：每手法全书命中章数、前段/后段密度对比、五组合计、零命中的手法（零命中本身就是发现——见 §8）；
3. 顺带跑 §6.2 的反向差集预览（片段手法 − 命中清单），**正常情况下应为空**；非空即为待补漏清单，直接进步骤 8；
4. 统计结论回填进 head.md（§4 步骤 5）。

**验收标准**：hits.txt 行数 = {总章数}；各章命中手法名全部在框架 25 手法集合内（防代理发明手法名）。

### 步骤 5：头尾撰写（主控）

- **head.md**：任务元信息 → 框架来源与手法表 → 条目结构说明 → **统计口径声明（必写，见 §7.4）** → **片段口径声明（必写：首轮即全集，片段条数 = 命中手法数，允许合条）** → 全书命中总表 → 组级合计 → 前后段对比；
- **tail.md**：统合观察（支柱手法、结构手法、前后段差异——从统计+典型例证写）→ 使用与复用说明（命中行可机器解析、引文可核对、与既有系列交叉引用）。

**验收标准**：head 中的统计数字与脚本输出完全一致；口径声明显式存在。

### 步骤 6：统合拼接

按 `head + batch_01 … batch_{总批数} + tail` 顺序拼接（脚本见 §6.3），无 BOM UTF-8 写入 {输出目录}/{输出文件名}。

**验收标准**：文件存在；`### 第 N {章单位}` 标题数 = {总章数}，序号无缺。

### 步骤 7：完整性校验（脚本见 §6.2）

| 校验项 | 判据 |
|---|---|
| 章齐全 | 标题数 = {总章数}，章号 1..N 无缺 |
| 命中行齐全 | `**本回命中**` 行数 = {总章数} |
| 片段-命中一致性（全集口径核心） | 每章：命中清单 ⊆ 片段手法名集合；**首轮后即应为真**，不成立才进补漏轮 |
| 片段越界（反向，可选从严） | 每章：片段手法名 ∈ 命中清单；用于发现代理自行加写未列入命中的手法 |
| 合条归一化 | 片段手法名支持三种写法归一：`A（B）`、`A/B`、`A/B（C）`——括号与斜杠内手法均计入覆盖集合 |
| 编码 | 读写均显式 UTF-8，输出无 BOM |

**验收标准**：缺漏章数 = 0。任一项不过，先定位到批次（报章号），再决定重发该批次或进补漏轮。

### 步骤 8：补漏轮（**异常专用**，v1 的"补全轮"在 v2 降级）

v2 首轮即全集，**正常情况下没有"待补差集"**，此轮只在两类情形启用：

- 某批次空返回/中断，文件未生成或未覆盖全章；
- 步骤 7 校验发现某章片段未覆盖全部命中（差集非空）。

启用时按下列执行：

1. **差集计算**：对每章，`命中清单 − 已有片段手法名集合` = 待补手法（用 §6.2 脚本输出直接得到）；
2. **派发模板 B**（§5.2）给补漏代理，硬性要求：
   - 补充片段追加到该章原有片段之后，**编号顺延，原内容零改动**；
   - 引文同样逐字、50 字内、解析克制；
   - **分批写入**：每完成 3–6 章即写一次文件（先覆写前半，再 Edit 追加后半）；
3. **失败处置**：补漏代理空返回或中断时，先看文件字节数/片段数是否变化判断真实进度，只重发未更新的批次（§7.7）；
4. **终验**：重跑步骤 7 的"片段-命中一致性"校验，缺漏章数必须为 0，然后重跑步骤 6 拼接。

**验收标准**：全覆盖校验通过 + 统合文档重新生成且数字更新。

## 六、可复用脚本（PowerShell 5.1 兼容，参数化）

> 三个脚本都以"变量区开头、其余全引用变量"的方式参数化，换项目只改变量区。编码统一显式 UTF-8；最终输出无 BOM。

### 6.1 命中统计（hits.txt → 手法分布表）

```powershell
# ===== 变量区 =====
$hitsFile = "{中间目录}\hits.txt"          # 每行：章号|手法A,手法B,…
$totalN    = {总章数}                        # 全书章数
$sliceN    = {前段章数}                      # 前段分界（后段 = totalN - sliceN）
# ==================
$lines = Get-Content $hitsFile -Encoding UTF8 | Where-Object { $_.Trim() -ne '' }
$all=@{}; $first=@{}; $second=@{}
foreach ($line in $lines) {
  $parts = $line -split '\|',2; $n=[int]$parts[0]
  foreach ($t in ($parts[1] -split ',')) {
    $t=$t.Trim(); if($t -eq ''){continue}
    if(-not $all.ContainsKey($t)){$all[$t]=0;$first[$t]=0;$second[$t]=0}
    $all[$t]++
    if($n -le $sliceN){$first[$t]++}else{$second[$t]++}
  }
}
$all.Keys | Sort-Object { -$all[$_] } | ForEach-Object {
  "{0}`t{1}`t{2}`t{3}`t{4}%`t{5}%" -f $_,$all[$_],$first[$_],$second[$_],
    [math]::Round($first[$_]/$sliceN*100,1),[math]::Round($second[$_]/($totalN-$sliceN)*100,1)
}
```

### 6.2 片段-命中全覆盖校验（含合条归一化）

> 全集口径下，本校验应在**首轮之后立即执行并直接通过**（缺漏 = 0）；出现缺漏即转入 §4 步骤 8 补漏轮。

```powershell
# ===== 变量区 =====
$batchDir = "{中间目录}"                     # batch_NN.md 所在目录
# ==================
$totalMissing = 0
foreach ($b in 1..{总批数}) {
  $file = Join-Path $batchDir ("batch_{0:d2}.md" -f $b)
  $c = [System.IO.File]::ReadAllText($file, [System.Text.Encoding]::UTF8)
  foreach ($blk in [regex]::Split($c, '(?=### 第)')) {
    if ($blk -notmatch '### 第 (\d+) {章单位}') { continue }
    $n = $Matches[1]
    $m2 = [regex]::Match($blk, '\*\*本{章单位}命中\*\*[:：]?\s*(.+)')
    if (-not $m2.Success) { continue }
    $hits = $m2.Groups[1].Value -split '[、,，;；]' | ForEach-Object { $_.Trim() } | Where-Object { $_ }
    # 片段手法名集合；合条归一化：斜杠拆分 + 括号内手法也计入
    $set=@{}
    foreach ($f in ([regex]::Matches($blk,'(?m)^\d+\.\s+\*\*([^*]+)\*\*') | ForEach-Object { $_.Groups[1].Value.Trim() })) {
      foreach ($part in ($f -split '[/／]')) {
        $core = ($part -replace '（[^）]*）','').Trim(); if ($core){ $set[$core]=$true }
        foreach ($mm in [regex]::Matches($part,'（([^）]+)）')) { $set[$mm.Groups[1].Value.Trim()]=$true }
      }
    }
    $missing = @($hits | Where-Object { -not $set.ContainsKey($_) })
    if ($missing) { "第 $n {章单位} 缺: $($missing -join '、')"; $totalMissing++ }
    # 反向校验（可选从严）：片段里出现、但不在命中清单中的手法
    $extra = @($set.Keys | Where-Object { $hits -notcontains $_ })
    if ($extra) { "第 $n {章单位} 越界(片段不在命中清单): $($extra -join '、')" }
  }
}
"存在缺漏的章数: $totalMissing"   # 验收标准：0（全集口径下首轮后即应为 0）
```

### 6.3 统合拼接（head + batches + tail → 无 BOM UTF-8）

```powershell
# ===== 变量区 =====
$dir     = "{中间目录}"
$outPath = "{输出目录}\{输出文件名}"
# ==================
$parts = @("$dir\head.md")
1..{总批数} | ForEach-Object { $parts += "$dir\batch_$('{0:d2}' -f $_).md" }
$parts += "$dir\tail.md"
$full = ((foreach ($p in $parts) { [System.IO.File]::ReadAllText($p,[System.Text.Encoding]::UTF8) }) -join "`r`n`r`n")
[System.IO.File]::WriteAllText($outPath, $full, (New-Object System.Text.UTF8Encoding($false)))
# 拼接后自查：标题数 = 总章数、章号无缺
$c = [System.IO.File]::ReadAllText($outPath,[System.Text.Encoding]::UTF8)
"逐章标题数: " + ([regex]::Matches($c,'(?m)^### 第 \d+ {章单位}')).Count
```

## 九、文体适配与局限

1. **收尾类手法的适配边界**：框架第五组（动作/条件/问题收尾）面向现代文章收尾场景。章回体等连续连载文体的"回末钩子"会让"问题收尾"判定显著放宽，而"条件收尾"可能全书零命中——这不是文本缺陷，是框架与文体的适配边界，应在统合观察中显式记录。
2. **口径差异不可消除只能声明**：分批并行的本质是多个判定者，批次间尺度差异数个百分点到一倍都有可能。可选缓解：在模板 A 中附 1–2 个"标准示例片段"统一锚点（代价是增加模板长度）；声明是底线。**全集口径下这一差异会直接放大——判定尺度松的批次片段更多**，故声明比 v1 更重要。
3. **非章回文本适配**：占位符 {章单位} 换成"节/讲/篇"即可用于课程文稿、技术文档连载等；但"主线 30 字概括"对说明文类文本应改为"本节核心结论"。
4. **零命中与低命中手法**：低命中既可能是文体不适配，也可能是该文本风格特征（如数字白描稀薄），两种解释都要摆在统计结论里，不下单一判语。
5. **本方法不做改写**：白描框架含"成熟文本原样返回"前提，本流程只读不写原文，任何"顺手润色"都越界。
6. **全集口径的代价（v2 新增）**：首轮即全集，单批输出长、单次落盘风险上升，因此 v2 用"分段落盘"替代 v1 的"两轮制"。若某文本单章平均命中极高（> 15），应进一步下调批次大小；仍不稳时把"每 3–6 章落盘"加密为"每 2–3 章落盘"，极端情况下改为一章一落盘（追加）。这是用更多写操作换稳定性，取舍方向与 v1 相反。
