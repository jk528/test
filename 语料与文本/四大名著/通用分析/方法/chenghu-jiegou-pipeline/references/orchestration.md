# 批量编排、子代理模板与故障排查

> 批量执行前必读。本文件把《西游记》100 回、《三国演义》120 回两轮并行工程的编排经验固化下来。

## 1. 预判四题设计法

预判四题是该著称谓系统的四条贯穿主线，在每回 §5「对预判四题」滚动呼应，并在末回总收束、与首回起点形成闭环。

设计步骤：

1. **从首回抽三条主轴**：读第 1 回底本，找出该著命名／称谓最独特的三种动作。
2. **补一条权力轴**：谁有权命名、谁被收编——这条通常贯穿全书。
3. **每题写成一句可判定的命题**，不做情节复述；附 3–5 个代表性称谓词。
4. 把四题写入 `config.themes` 与批次简报 §5，供所有执行单元共用。

既有实例（可作类比，不照抄）：

| 书目 | 题 1 | 题 2 | 题 3 | 题 4 |
| :--- | :--- | :--- | :--- | :--- |
| 西游记（100 回） | 称号刻度：美猴王→弼马温→齐天大圣→行者→斗战胜佛 | 师徒多名：三藏／唐僧／御弟／江流儿；一名一档 | 妖魔名号政治：大王／圣／祖师／菩萨，名号即靠山 | 命名权归属：观音、如来赐名 vs 妖怪自称 |
| 三国演义（120 回） | 正统与名分：汉室宗亲／皇叔／丞相／魏王 | 尊号与自称落差：温侯／卧龙／凤雏／武侯 | 名字与命运（谶纬命名）：字、号、童谣、品评 | 命名权与收编：天子封拜／诸侯自封／赐姓 |

末回要求：§5 对四题逐条作全书总收束，并呼应首回立起的三重奠基（如三国「皇叔／结义／奸雄」、西游「石猴→美猴王→孙悟空」），形成首尾闭环。

## 2. 子代理 prompt 模板（可复制）

以下七项为必备项，缺一即易出回归。占位符由编排层替换：`<BOOK>` 书名、`<ROOT>` 工作区根、`<BOOK_DIR>` 书目录、`<OUT>` 输出目录相对路径、`<CONFIG>` 配置路径、`<P>` pipeline.py 路径、`<MAP>` 文件映射表、`<THEMES>` 四题、`<N>` 总回数。

```
负责《<BOOK>》称呼学解构（整合版）第 A–B 回成稿，共 K 篇。文本学术创作，需逐字精度。

【第一步：必读，不可跳过】依次完整读取：
1. <BOOK_DIR>/称呼学解构/批次执行简报.md（自包含执行指令，严格遵守每条）
2. 样板笔法：<OUT>/001_第一回_*.md 与 <OUT>/<上一批末篇>.md（模仿结构、密度、判语风格）
3. <skill>/references/spec.md、<skill>/assets/skeleton.md、<skill>/references/methodology.md（术语不明时查）

【第二步：逐回生成】
底本 <BOOK_DIR>/<拆分目录>/、列锦 <BOOK_DIR>/<列锦目录>/、输出 <OUT>/。
文件映射（由 plan 输出，原样贴入，不得凭记忆写文件名）：
<MAP>

每回严格按简报 §2：精读底本全文至回末 → 读列锦 → A5 引文预截 → 六节成文 →
归属门核对 → 写文件 → 跑 `python <P> check --config <CONFIG> "<稿件>"` 直到未锚定 0。

【硬指标】每篇 ≥15700 字符（目标 15700–17000）、事件 10–12 件（按情节切分，§1 表 N 行连续 1–N，不足不凑）、
### 恰 3 段、定律表 66–72 行、「」185–215 处、未锚定 0、全文简体中文严禁中英混用。
**篇末必须有「（注：…）」尾注块与独立一行「> AI生成」结尾，缺一即失败。**
头标 `# 《<BOOK>》第N回　上句　下句　称呼学解构（整合版）`，系列标注 (N/<N>)，
底本含「拆分底本」字样。
每回「一句话」含核心矛盾＋两个相反动作并与前后回递进。
预判四题在 §5 滚动呼应：<THEMES>

【边界】**除指定回次外不得修改任何文件**；不改 README；不跑全局质检 qc
（会读到其他单元半成品）；只跑单篇 check。涉及敏感情节时以从容、学术、
聚焦称谓／名号／身份的方式处理，不渲染。不要提问，直接做完。

【收尾报告】逐回：`NNN 文件名 | 字符数 | 事件N(10–12) | ###3 | 「」数 | 未锚定0 | 尾注齐`。
```

**编排层下发要点**：映射表用 `plan --batch 5` 的输出；样板文件选本次工程已定稿的篇目；每个单元 `name` 唯一；并行启动 4–6 个单元为一轮，一轮结束后跑 `qc` 阶段验收。

## 3. 故障排查表（实战实录）

| 现象 | 原因 | 处置 |
| :--- | :--- | :--- |
| `QMISS` 未锚定，片段含「／」或斜杠分隔的并列词 | 把节选／并列词塞进同一个「」 | 拆成各自独立的「」，每段都取底本连续原文；错误例「成仙了道／霞举飞升／与天地齐寿」 |
| `QMISS` 长引文命中不了 | 漏掉底本中间短句，或动作词被改（`推他道`→`道`） | 回底本逐字照抄整段，不凭记忆补写 |
| `QMISS` 报 `→NNN` | 引文出自**别的回** | 改为转述或换成本回原句 |
| 缺尾注块／缺 AI 尾标 | 执行单元漏写收尾 | 补标准块：空行 + `---` + `（注：…）` + 独立一行 `> AI生成` |
| 计数不符（声明 12／表行 11） | §1 事件表漏一行 | 回底本定位缺失事件，插入该行并保持编号 1–N 连续；若该回本就只有 10–11 件，改声明数即可，不必补凑 |
| 缺 §3 | 单元整节漏写 | 用本回已有事实转述补 L1–L4 四层观察与综合判读，**不新增「」**以免引入锚定风险 |
| 字符不足 | 分析段偏薄 | 优先增厚 §2 判语后的方法性分析、§3 综合判读、§5 钩连；不新增引文 |
| 英文残留 | 生成时混入 `Here`／`decoding`／`vs`／`providing`／`parallel`／`Name` 等 | 扫描 `[A-Za-z]{3,}`，白名单外逐个替换为中文；注意繁简混用一并修 |
| 回数偏差 | 照抄上一部书回数 | **以底本 txt 实际数为准**；`init` 自动校正；漏做的尾段单独补批次 |
| 单元异常／返回空输出 | 子代理中断 | 先核查哪些回已落盘，只补做缺失回，不整批重做 |
| 子代理拒绝某回（情节敏感） | 内容策略 | 编排层亲自精读底本，按同一规格撰写；必要时在 prompt 里加「从容学术处理、聚焦称谓名号身份」 |
| 范围外稿件被改写 | 子代理越界 | prompt 明确「除指定回次外不得修改任何文件」；批次后用修改时间＋「」计数复核（「」<100 即异常），发现回归立即派独立单元修复 |
| 并发期间质检偶报他回失败 | 读到半成品 | 只认本回结果行；整批落盘后再跑 `qc` 全目录复核 |
| 头标引用声明被判失败 | 头标未含底本路径 | 头标写「拆分底本」字样或 `<拆分目录>/NNN_` 路径 |
| README 统计与正文不符 | 正文后续又改动 | 任何正文修改后重跑 `readme --config` 刷新统计 |
| 首末回未闭环 | 末回只作阶段性收束 | 末回 §5 对四题作全书总收束并呼应首回；中途如曾误把某回当末回，保留其阶段表述、以真实末回为准 |

## 4. 批次节奏与验收点

- 原工程 SOP 规定单会话 4–6 回防上下文衰减；全书批量改用**并行执行单元**（每单元 5 回），各单元按同一简报产出，编排层统一质检。
- 每轮启动 4–6 个单元 → 收尾核对落盘 → 跑 `qc` 阶段验收 → 再启动下一轮。
- 全书完成后：`qc` 退出码 0、未锚定 0、篇数齐、无缺号重号 → `readme` → 工作日志 → `present_files`。
- 交付指标固定口径：篇数、累计事件（**各篇实际件数求和**，勿用「篇数×12」估算）、字符合计、引文「」合计、引文片段数、未锚定数。

## 5. 与既有工程方法包的关系

本 skill 是以下既有资产的参数化重封装，不改动原文件：

- `通用分析/方法/称呼学整合版工作流包/` 00–05：调用指南、生成步骤 SOP、硬性限制、模板骨架、整合版方法论、归属门 → 收敛为 `references/spec.md`、`references/methodology.md`、`assets/skeleton.md`。
- `通用分析/方法/称呼学工作流包/03_质检脚本_参数化.ps1`：五维质检与码点归一化 → 收敛为 `scripts/pipeline.py` 的 `check`／`qc`（结果互认）。
- `通用分析/_archive/称呼学_西游记批次执行简报.md`、`称呼学_三国批次执行简报.md` → 收敛为 `assets/brief_template.md` 加 config。
- `通用分析/_archive/称呼学_锚定自检*.py`、`gen_*_readme.py` → 收敛为 `scripts/pipeline.py` 的 `check`／`readme`。

新书移植只需四个参数：底本目录名、列锦目录名、总回数、预判四题；其余框架与脚本原样复用。
