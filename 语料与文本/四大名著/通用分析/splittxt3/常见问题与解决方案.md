# splittxt3 常见问题与解决方案

本文档记录 splittxt3（VBA版 + Python版）开发和使用过程中遇到的所有问题及其解决方案，供后续参考。

---

## 一、VBA 代码问题

### 1. For Each 遍历字典键时报类型不匹配

**现象**：`For Each cn In flatMap.Keys` 或 `For Each numKey In dict.Keys` 时报错"类型不匹配"。

**原因**：VBA 中 `Scripting.Dictionary` 的 `Keys` 集合返回的是 `Variant` 数组，`For Each` 循环变量必须声明为 `Variant` 类型。声明为 `String` 或 `Long` 都会报错。

**错误写法**：
```vb
Dim numKey As String   ' ❌ 错误
For Each numKey In flatMap.Keys
    ' ...
Next numKey
```

**正确写法**：
```vb
Dim numKey As Variant  ' ✅ 正确
For Each numKey In flatMap.Keys
    ' ...
Next numKey
```

**类似问题**：所有 `For Each` 遍历字典 `Keys` 或 `Items` 的循环变量都必须用 `Variant`。

---

### 2. 下标越界（下界超标）

**现象**：访问数组元素时报"下标越界"，如 `topCounts(-1)`。

**原因**：VBA 的 `And` 运算符**不短路求值**，两边都会计算。

**错误写法**：
```vb
Do While insPos > 0 And topCounts(insPos - 1) < vv   ' ❌ 当 insPos=0 时，topCounts(-1) 也会被求值
    insPos = insPos - 1
Loop
```

**正确写法**：
```vb
Do While insPos > 0
    If topCounts(insPos - 1) < vv Then
        insPos = insPos - 1
    Else
        Exit Do
    End If
Loop
```

**经验**：VBA 中不要在 `Do While` 或 `If` 条件中用 `And` 连接数组边界检查和数组访问，必须分开写。

---

### 3. 缺失 End If / 结构不配对

**现象**：编译时报"块 If 没有 End If"或"For 没有 Next"。

**原因**：新增代码时只加了 `If` 忘了加对应的 `End If`，或 `For`/`Do`/`Select` 没有对应结束语句。

**检查方法**：
- 检查 `If ... Then` 是否都有 `End If`
- 检查 `For` 是否都有 `Next`
- 检查 `Do` 是否都有 `Loop`
- 检查 `Select Case` 是否都有 `End Select`
- 检查 `Sub`/`Function` 是否都有 `End Sub`/`End Function`

**经验**：每次新增 `If` 块时，先写 `End If` 再写中间内容，避免遗漏。

---

### 4. 策略组合溢出错误

**现象**：各策略效果预览时溢出或结果异常。

**原因**：将 `lis`/`sort` 等排序策略作为去重策略传入 `ApplyDedup`，导致去重函数收到不认识的策略名，逻辑异常。

**正确做法**：
- 去重策略（`ApplyDedup`）：`none` / `adjacent` / `first` / `longest`
- 排序策略（`ApplySort`）：`none` / `lis` / `sort`
- 两者是独立的两步，需要分开调用

```vb
ApplyDedup "longest", "flat"   ' 先去重
ApplySort "sort", "flat"       ' 再排序
```

---

### 5. 变量未声明（Option Explicit 下报错）

**现象**：运行时报"变量未定义"。

**原因**：VBA 文件顶部有 `Option Explicit`，所有变量必须先声明后使用。新增代码时用了变量但忘了加 `Dim`。

**常见遗漏**：
- 新增功能中新增的变量忘了在过程顶部 `Dim`
- 复制粘贴代码时，变量声明没一起复制
- `ReDim` 的数组变量也需要先用 `Dim` 声明

**检查方法**：
1. 检查所有赋值变量是否都有 `Dim` 声明
2. 检查 `For` 循环变量是否已声明
3. 检查字典 `For Each` 循环变量是否为 `Variant`

---

### 6. 字典对象使用后未释放导致的问题

**现象**：循环内创建 `Dictionary` 对象，使用后未释放，可能导致内存泄漏或引用混乱。

**正确做法**：
```vb
Set normTitles = CreateObject("Scripting.Dictionary")
' 使用 normTitles ...
Set normTitles = Nothing   ' ✅ 用完释放
```

**注意**：如果在循环中创建字典，每次循环结束都要释放。

---

### 7. 在循环外引用循环内已释放的对象

**现象**：在 `Next` 循环结束后，引用了循环内创建并已释放的 `Dictionary` 对象（如 `normTitles.Count`），导致报错。

**原因**：循环内 `Set normTitles = Nothing` 后，循环结束时该对象已不存在，但显示代码中还在使用。

**解决方法**：在循环内将需要的值保存到数组变量中，循环结束后用数组中的值。

```vb
' 循环内保存
titleDiffTCnts(tdIdx) = normTitles.Count

' 循环外使用（不用 normTitles.Count，改用数组）
AddRptLine lines_arr, rptIdx, "第" & titleDiffArr(ti) & "章（" & titleDiffTCnts(ti) & "个不同标题）:"
```

---

### 7.5 数组参数用 ByVal 声明（VBA 不支持按值传数组）

**现象**：`AutoNFromBodies(ByVal lines() As String)` 函数声明中数组参数用了 `ByVal`。

**原因**：VBA 不支持真正按值传递数组。虽然语法上 `ByVal arr() As String` 不会报错，但 VBA 会忽略 `ByVal`，仍然按引用传递。这是不规范的写法，可能导致预期外的行为。

**解决方法**：改为 `ByRef`（VBA 标准写法）。

```vb
' ❌ 不规范
Private Function AutoNFromBodies(ByVal lines() As String) As Long

' ✅ 规范
Private Function AutoNFromBodies(ByRef lines() As String) As Long
```

## 二、分析报告显示问题

### 8. 重复章节列表只有章号没有标题，容易混淆

**现象**：分析报告中"重复最严重的前10个章号"只显示 `第X章: N次`，光看章号不知道具体是哪一章，多个重复章号之间容易混淆。

**解决方法**：增加完整标题和出现行号。

**改进后**：
```
重复最严重的前10个章号：
  第1章 (3次): 第一回 甄士隐梦幻识通灵 贾雨村风尘怀闺秀
    出现行号: 1、50、120
  第3章 (2次): 第三回 贾雨村夤缘复旧职 林黛玉抛父进京都
    出现行号: 80、200
```

### 9. 同章异题标题被截断，无法看出区别

**现象**：同章异题示例中标题只截前15个字，用"/"分隔。如果标题前15字相同（很常见），看不出区别在哪里。

**解决方法**：完整显示所有不同标题，每行一个，不截断。

**改进前**：
```
第2章: 第二回贾夫人仙逝扬 / 第二回 不同标题的第
```

**改进后**：
```
第2章（2个不同标题）:
    · 第二回贾夫人仙逝扬州城冷子兴演说荣国府
    · 第二回 不同标题的第二章
```

### 10. 目录区起始标题被截断

**现象**：目录区起始标题只显示前40字，长标题被截断。

**解决方法**：完整显示，不截断。

### 10.5 同章异题只显示前5个，数量多时看不到全貌

**现象**：同章异题有几十个甚至上百个（如《玄鉴仙族》有136个），但报告只显示前5个示例，无法看到全部情况。

**原因**：最初设计时假设同章异题数量不多，只做了示例展示。实际脏数据严重的文件可能有大量同章异题。

**解决方法**：同章异题改为**全部列出**，不限制数量。用字典存储所有同章异题信息（章号→标题列表，章号→标题数），输出时完整遍历。

**输出格式**：
```
章号相同但标题不同: 136 个章号
  完整列表：
    第2章（2个不同标题）:
        · 第二回贾夫人仙逝扬州城冷子兴演说荣国府
        · 第二回 不同标题的第二章
    第3章（2个不同标题）:
        · ...
    ...（全部列出）
```

## 四、功能逻辑问题

### 12. 仅按章号去重会误删同章异题的章节

**现象**：同一章号下有不同标题的章节（如目录式标题和正文式标题），仅按章号去重会只留一个，另一个被误删。

**原因**：去重键只有卷号+章号，没有考虑标题差异。

**解决方法**：增加**标题级去重**（`--title-dedup`），去重键 = 卷号 + 章号 + 规范化标题。

**标题规范化**：
- 全角→半角（数字、字母、符号）
- 空白压缩
- 移除常见标点（逗号、句号、冒号、引号、括号等）
- 转小写
- 移除零宽字符

---

### 13. 中文数字识别不全

**现象**：某些中文数字格式（如大写、繁体、俗写）无法正确识别和转换。

**解决方法**：扩展 `CnToInt` 函数，支持：
- 简体中文数字：一二三四五六七八九十百千万亿零〇○
- 大写数字：壹贰叁肆伍陆柒捌玖拾佰仟
- 繁体数字：億、兩
- 俗写：廿、卅、卌、皕
- 特殊：两

---

### 13.5 分析报告策略预览与实际拆分结果数量不一致

**现象**：分析报告中"各策略效果预览"显示的章节数，和实际拆分后生成的文件数不一致。

**可能原因1：卷模式不同**
- 预览固定用 `flat`（扁平）模式
- 实际拆分用用户选择的卷模式（auto/by_volume）
- 如果文件有多卷，by_volume 模式每卷独立去重，章节数会更多

**可能原因2：标题级去重未传入**
- 预览代码中 `ApplyDedup` 调用未传 `titleDedup` 参数，默认为 `False`
- 实际拆分传入了 `g_titleDedup`（可能为 `True`）
- 启用标题级去重后，同章异题不会被去重，章节数会更多

**修复**：确保预览调用也传入 `titleDedup` 参数：
```vb
ApplyDedup comboDedup(s_idx), "flat", g_titleDedup
```

---

### 13.6 special 章节判断逻辑不一致（VBA vs Python）

**现象**：VBA 版和 Python 版在处理 special（无号）章节时结果数量不一致。

**原因**：
- Python版：`ch_num <= 0 且 level == 'special'` 才算 special，按标题去重
- VBA版（旧）：只要 `level = "special"` 就算 special，不管有没有章号

**影响**：如果存在有章号的 special 章节（少见情况），两版的去重结果会不同。

**修复**：统一 VBA 版判断逻辑，所有去重函数（DedupFirst、DedupLongest、DedupLIS、DedupSort）和排序函数都改为：
```vb
If ch_nums(chapIdx(i)) <= 0 And ch_levels(chapIdx(i)) = "special" Then
    key = "S|" & ch_titles(chapIdx(i))
Else
    key = DedupKey(chapIdx(i), volMode, titleDedup)
End If
```

## 五、使用类问题

### 14. VBA 版怎么导入？

**方法**：
1. 打开 WPS 表格 / Excel / Word
2. 按 `Alt + F11` 打开 VBA 编辑器
3. 菜单：文件 → 导入文件 → 选择 `split_txt_v3.bas`
4. 或：直接打开 `.bas` 文件，全选复制，粘贴到 VBA 编辑器的模块中

然后运行 `拆分TXTv3` 或 `分析TXTv3`。

---

### 15. 怎么选去重策略？

**决策树**：
```
先分析（--analyze）
  ↓
有卷结构吗？
  ├─ 有，且卷间章号重复 → auto 或 by_volume
  └─ 无 → flat（默认auto会自动判断）
  ↓
有重复吗？
  ├─ 无 → 直接拆分
  └─ 有
       ↓
    有乱序吗？
       ├─ 无 → longest（留内容最全的）
       └─ 有
            ↓
         乱序严重吗？
            ├─ 轻微（<10处） → lis
            └─ 严重 → sort（最稳妥）
```

---

### 16. lis 策略为什么会少几章？

**原因**：LIS（最长递增子序列）找的是章号严格递增的最长主线。如果文件末尾有重复块，LIS 会选择前面那条主线，末尾重复块里的章节会被舍弃。

**解决**：想要最完整的结果用 `sort` 策略（1到最大章号齐全且完全有序）。

---

### 17. 多卷小说用 flat 模式为什么章节少了？

**原因**：`flat` 模式忽略卷结构，所有章节按章号去重。如果第一卷和第二卷都有"第1章"，flat 模式会只留一个。

**解决**：用 `auto` 或 `by_volume` 模式，每卷独立去重。

## 六、编码与文件问题

### 18. 文件编码识别错误导致乱码

**现象**：打开生成的文件是乱码。

**原因**：源文件编码识别错误，或输出编码不匹配。

**支持的编码检测**：
- UTF-8 BOM
- UTF-16 LE/BE
- UTF-8（无BOM，通过字节分布判断）
- ANSI/GBK（默认回退）

**输出编码**：统一输出 UTF-8（无BOM）。

## 七、开发规范与经验总结

### VBA 编码规范

1. **必须声明变量**：顶部有 `Option Explicit`，所有变量先 `Dim` 后使用
2. **字典遍历用 Variant**：`For Each` 遍历字典键/值，循环变量必须是 `Variant`
3. **条件不短路**：VBA 的 `And`/`Or` 不短路，数组边界检查要分开写
4. **对象用完释放**：`CreateObject` 创建的对象用完 `Set obj = Nothing`
5. **循环内创建的对象循环外不能用**：需要的值提前保存到变量
6. **新增 If 块先写 End If**：避免遗漏导致编译错误
7. **变量命名有意义**：用驼峰或下划线，避免单字母变量（循环变量除外）

### Python 编码规范

1. **函数参数完整**：新增参数时确保所有调用处都更新
2. **注释同步更新**：修改功能后同步更新文档字符串和注释
3. **错误处理**：文件操作要有异常处理
4. **编码处理**：统一用 UTF-8，中文环境注意 GBK 编码

## 七之二、v3.4 升级过程的问题与解决方案（2026-10-01）

本次升级：弹窗 9~10 个压缩为 4 个、去重排序合并为 3×2 六组合、新增独立设置入口、报告改总-分结构、新增自动化线、删除 adjacent 策略、新增 WPS JS宏 版。

### 19. VBA 版无法在本机运行验证

**现象**：本机没有可用的 VBA 编译/运行环境，`.bas` 只能做静态检查（Sub/Function/If/For/Select 配平计数），无法保证语法与逻辑正确。

**解决方案**：改用 **WPS JS宏版**（JScript）做真实端到端验证——本机 cscript 就是 JScript 引擎，可直接运行。VBA 版作为交付件保留，文档中注明"未经编译验证，以 JS宏版为准"。

**JS宏离线验证工作流**（可复用）：
1. 引导器保存为 **GBK 或纯 ASCII** 文件（cscript 不支持 UTF-8 BOM 脚本，BOM 会按 GBK 解码破坏首行）
2. 被测单元文件（UTF-8 BOM）用 `ADODB.Stream(Charset="utf-8")` 读入
3. `(1,eval)(code)` 间接 eval 加载到**全局作用域**（直接 eval 只在局部作用域生效）
4. 定义 `Application` 桩：MsgBox 按预设队列返回、FileDialog 返回测试文件路径、CreateObject 兜底 `new ActiveXObject`
5. 运行：`cscript //nologo //E:JScript run_tests.js`

### 20. cscript/JScript 环境的中文编码陷阱（连环坑）

**现象**：测试脚本连续报"return 语句在函数外"、Syntax error、"参数类型不对"等错误，且错误行号与实际代码对不上。

**原因链**：
- cscript 默认按 **GBK** 解码脚本文件；若文件含 UTF-8 中文，中文字节被拆开，可能吞掉换行符导致两行粘连
- 即使文件存为 UTF-8 带 BOM，本机 cscript 也会把 BOM 按 GBK 解码破坏首行注释
- 编辑工具（Write/Edit）写入的中文是 UTF-8 字节，写入 GBK 语义文件后变成乱码占位符
- PowerShell 用 ASCII 编码写文件时，非 ASCII 字符被写成 `?`

**解决方案（硬性规则）**：
- 测试脚本**只用 ASCII**：所有中文字符串一律用 `\uXXXX` 转义写（如 `"\u4fdd\u7559\u5927\u4e8e\u7b49\u4e8e100_"` = "保留大于等于100_"）
- 用 Edit 工具改过含中文的行后，**必须检查**该行是否被写入裸中文（可用 PowerShell 正则 `[^\x00-\x7F]` 扫描）
- 断言失败需要转储中文文件名时，写到文件再用 `Get-Content -Encoding UTF8` 读，不靠控制台输出（控制台 GBK 下中文会乱码）

**另一个坑**：中文显示宽度与字节数不一致导致"多一个字"的错觉。例如 `保留大于等于` 是「大/于/等/于」四个字（以`于`结尾），测试常量漏掉末尾的「于」导致前缀匹配失败——看起来"对了"实则差一个字符。**文件名校验要用码点逐字符对比**（`charCodeAt(i).toString(16)`），不要靠肉眼。

### 21. 编码检测器对病态人造数据的误判

**现象**：构造的"干净测试文件"（30章，每章正文全是同一个字重复70次×3行）被 `detect_encoding` 误判：GBK 字节流凑巧能按 UTF-8 解码成功，识别为 utf-8，后续解码出乱码、章节数为 0。

**原因**：检测逻辑是 `utf-8 → gbk → gb18030 → big5` 依次尝试解码、**第一个不抛异常者胜出**。GBK 双字节序列恰好落入合法 UTF-8 范围时会"成功"。

**解决方案（测试侧）**：构造测试数据时，正文用**多样的常见汉字**（如千字文切片），不要全篇同一字；测试文件之间可混用编码（脏文件 GBK、干净文件 UTF-8）分别覆盖两条路径。真实小说不会出现"全文只有几十个字"的病态分布，无需为此改检测器。

**教训**：测试数据要**贴近真实分布**，否则测的是检测器边界而非业务逻辑。

### 22. adjacent 策略的删除依据

**现象**：用户指出 `adjacent`（相邻双标题去重）与清洁模式功能重合。

**确认后删除**：
- 目录区检测自动跳过开头的纯目录段（前30%内连续≥10个短正文章节）
- 清洁模式自动跳过仅标题/正文不足的章节
- 两者联合已覆盖双标题场景；残留情况用组合3（first+none）
- **刻意保留**「相邻双标题占比」检测指标——它是自动决策规则2（占比≥30%且乱序<10 → first+none）的输入，删掉的只是同名去重策略
- 三端（VBA/Python/JS宏）+ 使用说明同步删除；`--dedup adjacent` 被 argparse 拒绝（exit 2）

### 23. 子代理工具在会话中不可用时的降级

**现象**：`Task`/`Agent` 子代理工具报错 `subagent_type is not a valid value`，此前能用的调用方式失效（会话中模型/工具集发生切换）。

**解决方案**：降级为主会话直接操作——机械性删除+定点替换用 Read/Edit 完成；JS 验证用 cscript 实跑；Python 验证复制到 **ASCII 临时目录**再跑（规避中文路径下 `python 脚本名` 的参数编码问题：`python.exe: can't open file ... Errno 2`，即使文件存在）。测试结束清理临时目录。

### 24. 中文路径下 python 无法接收脚本路径参数

**现象**：`python "c:\...\语料与文本\...\test.py"` 报 `Errno 2: No such file or directory`，但文件确实存在。

**原因**：PowerShell 向 python.exe 传参时的编码转换问题（中文路径在 GBK/UTF-8 边界损坏）。

**解决方案**：
- 方案A：复制到 `%TEMP%` 下纯 ASCII 路径再运行（最稳妥）
- 方案B：用 `Scripting.FileSystemObject` 的 `ShortPath` 取 8.3 短路径（本机 NTFS 若禁用 8.3 名则不可用，实测本机 GetFile 抛 FILENOTFOUND，不可用）
