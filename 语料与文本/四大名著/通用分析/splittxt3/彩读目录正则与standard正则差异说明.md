# 彩读目录正则 vs 拆分工具 standard 正则 · 差异说明

## 一、总纲

### 1.1 两条正则原文

**A. 彩读目录正则**（彩读阅读 ColorTxt 内置的目录识别规则，下游阅读器侧）

```
^[ \t　]*(第[0-9０-９一二三四五六七八九十百千万亿億零〇○两兩壹貳贰叁參肆伍陸陆柒捌玖拾佰仟廿卅卌皕萬]{1,12}[章回卷节集部篇])(?:[ \t　：:]+(.*))?$
```

**B. 拆分工具 standard 正则**（本工具章节级第 1 优先级规则，见 split_txt_v3.py / split_txt_v3.bas）

```
^[ \t　]*第([0-9０-９一二三四五六七八九十百千万亿億零〇○两兩壹貳贰叁參肆伍陸陆柒捌玖拾佰仟廿卅卌皕萬]+)(章|回|节|卷)(?:[ \t　：:]+(.*))?$
```

### 1.2 一句话结论

两条正则的**数字字符集、行首缩进、分隔符、标题可选部分完全相同**；真正差异只有三处——**捕获组结构、单位字覆盖范围、数字长度上限**。三者均由各自定位决定：A 是阅读器的"目录展示"规则（认得宽、整体取用），B 是拆分修复工具的"结构化解析"规则（认得准、拆解取用）。

### 1.3 差异速览表

| 维度 | A. 彩读目录 | B. standard（本工具） |
|------|------------|----------------------|
| 数字字符集 | 相同（49 个字符：阿拉伯/全角/中文大小写/廿卅卌皕等） | 相同 |
| 行首空白 | `^[ \t　]*` 相同 | `^[ \t　]*` 相同 |
| 分隔符与标题 | `(?:[ \t　：:]+(.*))?$` 相同 | `(?:[ \t　：:]+(.*))?$` 相同 |
| **捕获组结构** | 2 组：`("第N章")`、`(标题)` | 3 组：`(N)`、`(单位)`、`(标题)` |
| **单位字覆盖** | 7 个：章 回 卷 节 **集 部 篇** | 4 个：章 回 节 卷 |
| **数字长度上限** | `{1,12}`，超过 12 字不匹配 | `+`，无上限 |
| 匹配范围关系 | 单位更宽、长度更窄 | 单位更窄、长度更宽（**两者互为交叉，互不包含**） |
| 用途定位 | 阅读器目录识别与展示 | 章节切分、章号归一化、去重、排序 |

---

## 二、逐项差异详解

### 2.1 差异①：捕获组结构（整体捕获 vs 拆解捕获）

- **A**：`(第N[单位])` 把"第""数字""单位"作为**一个整体**捕获。彩读只需把这一串原样放进目录显示，不需要拆开。
- **B**：`第(N)(章|回|节|卷)` 把**数字**和**单位**各自单独成组。本工具后续要做：
  - 中文数字 → 阿拉伯数字转换（章号归一化）
  - 按章号排序、乱序修复
  - 重复章号检测与去重
  - 跨卷同章号判定

  这些操作都必须拿到独立的数字串和单位字，所以 B 必须拆组。

> 结果：同一行"第十二回 义释严颜"，A 得到 `("第十二回", "义释严颜")`，B 得到 `("十二", "回", "义释严颜")`。

### 2.2 差异②：单位字覆盖（7 个 vs 4 个）

- **A** 的字符类 `[章回卷节集部篇]` 多认 **集、部、篇** 三个单位。彩读作为阅读器，目标是"尽量多的章节行都能进目录"，所以放宽单位范围，遇到"第三集""第一部""第二篇"也能列出目录项。
- **B** 只认 **章、回、节、卷**。这不是遗漏，而是**分层设计**：在本工具中，`卷/部/册/篇/集/季` 属于**卷级标题**，由专门的 VOLUME_PATTERNS（卷级正则）在更高层级处理；章节级的 standard 正则只负责"章/回/节/卷"四种，避免同一行被卷级和章级重复识别。

> 结果："第三集 风云再起"——A 能识别进目录；B 的 standard 不匹配，改由工具内的卷级正则接管。

### 2.3 差异③：数字长度上限（{1,12} vs +）

- **A** 限制数字部分 **1~12 个字符**。阅读器做目录是逐行实时扫描，加上限可防御异常长行导致的匹配成本，也避免把正文里"第……（一长串数字）……章"的叙述句误当目录。
- **B** 用 `+`，**不设上限**。修复工具要处理各种极端脏文本（如大写繁体混排的超长数字"第壹万贰仟叁佰肆拾伍亿陆仟柒佰捌拾玖回"），宁可多认也不能漏认。

> 结果：数字部分超过 12 个字符的标题行，A 放弃识别（目录里看不到），B 仍能正常匹配。

### 2.4 三点差异的共同根源：定位不同

| | A. 彩读目录 | B. standard（本工具） |
|---|---|---|
| 角色 | 下游阅读器（只读） | 中游整理工具（读写修复） |
| 对文件 | 不修改，只识别展示 | 切分、去重、重排、归一化 |
| 设计取向 | 宽松展示、防御异常 | 精确解析、结构化输出 |

## 四、对本项目的实际影响（兼容性结论）

1. **工具输出 → 彩读目录：完全兼容。** 本工具 standard 正则认出的所有章节（第N章/回/节/卷），数字部分在正常长度内，彩读 100% 能识别进目录。
2. **反向不成立。** 彩读能认的"第N集/部/篇"行，本工具的 standard 不认——这是分层设计，由卷级正则补齐，整体识别能力不降。
3. **极端超长数字（>12 字）**：工具能修复，但修复后若保留超长中文数字原样，彩读目录仍不显示；工具的"章号归一化"（中文数字→阿拉伯数字）恰好能把数字压短到 12 字以内，**归一化是打通两者的关键环节**。
4. **流水线验证口诀**：工具负责"修得准"（B 精确解析），彩读负责"看得全"（A 宽松展示），两者是上下游互补关系，不是替代关系。

---

## 五、总结

| | A. 彩读目录 | B. standard（本工具） |
|---|---|---|
| 本质 | 目录**展示**正则 | 章节**解析**正则 |
| 三组差异 | 整体捕获 / 7 单位 / 限 12 字 | 拆解捕获 / 4 单位 / 不限长 |
| 共同底座 | 同一数字字符集、行首空白、分隔符、标题可选 | 同左 |
| 关系 | 互不包含的交叉关系，流水线上下游互补 | 同左 |

**记法**：彩读"认得宽、取得整"；工具"认得准、拆得开"。
