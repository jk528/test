# TXT章节拆分工具 v3.6（万章级性能优化版）—— 使用说明

## 1. 概述

`splittxt3` 是在 `splittxt2` 基础上，全面解决TXT小说质量问题的增强版本。

**三版本**（功能对齐，任选其一）：

| 版本 | 文件 | 运行环境 | 状态 |
|------|------|----------|------|
| Python版 | `split_txt_v3.py` | 命令行，分析功能更详细，适合批量处理 | v3.6 |
| VBA版 | `split_txt_v3.bas` | WPS/Excel/Word VBA 编辑器，图形化交互 | v3.6 代码已写入，但本机无法运行VBA、**未经编译验证**，如有问题以 JS宏版为准 |
| WPS JS宏版 | `split_txt_v3.js` | WPS JS宏编辑器（JScript ES3） | v3.6，已通过本机 cscript 实测 **38/38 PASS** |

**v3.6 变更摘要（万章级性能优化）**：

针对 **10000章以上 / 600万字** 超大规模数据的全链路性能优化：

| 变更 | 说明 | 复杂度变化 |
|------|------|------------|
| 预计算一次，处处复用 | 扫描完成后一次遍历算出每章字符数+汉字数，AutoN/清洁模式/字数统计 三处直接读取，消除重复行遍历 | 行遍历从 4次 → 2次 |
| 数组倍增扩容 | VBA版初始容量从128提到2048，不足时翻倍（2048→4096→8192→16384），万章级只需扩容3次 | 扩容从 ~78次 → 3次 |
| 全局正则对象复用 | VBA版汉字正则只创建一次（g_regCn），所有计数环节共享 | 正则对象创建从 N次 → 1次 |
| AutoN O(章节数) | 自动判定N值从逐行计数改为直接读预计算数组 | 从 O(总行数) → O(章节数) |
| 清洁模式 O(章节数) | 字符数+汉字数全部读预计算结果，写文件循环不再做行遍历计数 | 从 O(总行数) → O(章节数) |

**性能收益（万章级估算）**：总耗时减少约 **40%~60%**，主要节省在重复行遍历和正则匹配上。

| 排序算法全面升级 | VBA版两处排序全部改用快速排序 O(n log n)：AutoN字数排序、SortFullFromIndices卷章排序 |
| 字符串拼接全面优化 | 三端所有"拼接全文再正则计数"改为逐行计数，减少大字符串内存开销：AutoN计数、清洁模式正文计数、预计算字数 |
| Top10索引预建 | VBA版重复Top10从O(M*N)改为O(N+M)：一次遍历建立章号信息索引，Top10直接查表 |

**覆盖 13 类问题场景**：

### 一、重复类问题
| 编号 | 类型 | 表现 | 举例 |
|------|------|------|------|
| 1 | 相邻双标题 | 每章标题连续出现2次 | 第1章 标题（行首）+ 第1章 标题（缩进） |
| 2 | 整块重复粘贴 | 某段章节被连续复制N次 | 第962-970章反复出现10次 |
| 3 | 末尾重复块 | 文件尾部又重复了前面的章节 | 末尾重复第1554-1560章 |
| 4 | 卷间章号重复 | 不同卷有相同章号 | 第一卷第一章 vs 第二卷第一章 |

### 二、乱序类问题
| 编号 | 类型 | 表现 | 原因 |
|------|------|------|------|
| 5 | 重复导致乱序 | 章号在某范围内来回跳 | 整块重复粘贴 |
| 6 | 末尾回退乱序 | 章号已经很大，突然又从前面开始 | 末尾重复块 |
| 7 | 整体完全乱序 | 文件拼接顺序完全错误 | 下载/合并不慎 |

### 三、结构类问题
| 编号 | 类型 | 表现 | 说明 |
|------|------|------|------|
| 8 | 多卷/多部/多册 | 存在卷/部/册等上级结构 | 每卷内章号重新编号 |
| 9 | 多轨目录 | 文件中有多套独立章节体系 | 目录区+正文区各一套 |
| 10 | 多级嵌套 | 卷→篇→章→节多层结构 | 当前支持两级（卷+章） |
| 11 | 无号章节 | 序章/楔子/番外/尾声等 | 无数字编号的特殊章节 |
| 12 | 章号缺失 | 中间缺章，章号不连续 | 分析报告可列出缺失章号 |
| 13 | 格式混合 | 阿拉伯数字+中文数字混合 | 多种单位词混合 |
| 14 | 同章异题 | 章号相同但标题内容不同 | 仅按章号去重可能误删 |

## 3. 图形化版使用指南（VBA / WPS JS宏）

VBA版与JS宏版**交互流程完全一致**，入口同名，以下说明两端通用。

### 3.1 导入方法

**VBA版**：
1. 打开 WPS 表格 / Excel / Word
2. 按 `Alt + F11` 打开 VBA 编辑器
3. 菜单：文件 → 导入文件 → 选择 `split_txt_v3.bas`
4. 或：直接打开 `.bas` 文件，全选复制，粘贴到 VBA 编辑器的模块中

**WPS JS宏版**：
1. 打开 WPS 表格
2. 菜单：工具 → 开发工具 → JS宏（或 `Alt + F11` 视版本而定）
3. 打开 `split_txt_v3.js`，全选复制，粘贴到 JS宏编辑器中

### 3.2 四个入口

| 入口 | 功能 |
|------|------|
| `拆分TXTv3` | 完整拆分流程（仅4个弹窗，见 3.3） |
| `分析TXTv3` | 仅分析不拆分，生成总-分结构分析报告文件 |
| `自动TXTv3` | 全自动决策（组合+清洁N），一次确认即完成拆分（见 5. 自动化线） |
| `设置TXTv3` | 查看/修改三项默认设置（见 4. 默认设置） |

### 3.3 拆分TXTv3 交互流程（仅4个弹窗）

```
弹窗1：选择TXT文件
   ↓
弹窗2：选择正则表达式（可多选并列，默认 1,4，与splittxt2一致）
   ↓
弹窗3：去重+修序 六合一（默认 6）

   | 选项 | 去重     | 排序   | 适用场景                       |
   |------|----------|--------|--------------------------------|
   | 1    | 不去重   | 不排序 | 文件干净无重复无乱序，仅拆分   |
   | 2    | 不去重   | 排序   | 无重复但整体乱序，按章号重排   |
   | 3    | 保留首次 | 不排序 | 相邻双标题/简单重复，留首次    |
   | 4    | 保留首次 | 排序   | 简单重复且乱序                 |
   | 5    | 保留最长 | 不排序 | 整块重复，留最全内容且不改顺序 |
   | 6    | 保留最长 | 排序 ★ | 重复+乱序严重，最彻底（默认）  |

   选择建议：乱序严重（≥10处）选带"排序"的；想保留最全内容选"保留最长"
   ↓
弹窗4：输出模式（一体输入，按第一个空格切分模式与参数）
   1      清洁模式（默认N=100；可输 "1 200" 自定义N）
          = 固定五件套：分析报告.txt + 拆分完成报告.txt + 保留≥N / 清理<N 双合并文件
            + 拆分文档\（每章单文件，命名 序号_源行号_标题.txt）
   2      聚合拆分（默认40,3；可输 "2 20,1|20,1|80,1" 自定义格式）
```

> **说明**：v3.4 删除了独立的"按章节一一拆分"模式——清洁模式（选项1）本身即输出每章单文件，同时附带双合并文件，一次完成。v3.5 起单章文件统一输出到 `拆分文档\` 子目录，并附分析报告.txt + 拆分完成报告.txt（即固定五件套）。
> 广告清理/标题去重/卷模式不再逐项弹窗询问，改用「设置TXTv3」预设默认值（见下章）。

### 3.4 分析TXTv3 输出

运行后会在源文件同目录生成 `<源文件名>_分析报告.txt`。v3.4 起报告为**总-分结构**：

- **【总】结论与建议**（开头）：问题计数汇总（重复章号数/乱序处数/同章异题数/目录区章节数）+ 推荐组合 + 建议清洁N值
- **【分】明细**：
  - 卷/部结构分析
  - 重复章节分析（扁平视角）
  - 乱序分析
  - 多轨目录检测
  - 格式多样性分析
  - 章号连续性分析
  - 各去重策略效果预览
  - 处理建议

拆分完成弹窗同样为总-分结构：
```
【总】清洁模式完成：N个文件｜输出目录｜耗时
【分】
  来源：编码 X→UTF-8｜正则 标准中文｜识别章节 N
  质量：去重 longest(-N章)｜排序 sort(修N处)｜卷模式 自动(扁平)｜目录区跳过 N章
  清理：广告行 -N｜跳过章节 N（仅标题N/正文不足N）｜前三正文字数 ...
  计时：选文件 Xs｜处理 Xs｜写入 Xs
```

**v3.3 报告增强（避免章号与内容混淆）**：

| 项目 | 改进前 | 改进后 |
|------|--------|--------|
| 重复最严重Top10 | 仅显示"第X章: N次" | 显示完整标题 + 出现行号（前5次） |
| 同章异题列表 | 只显示前5个示例，标题截前15字 | **全部列出**，所有不同标题完整显示，每行一个 |
| 目录区起始标题 | 截前40字 | 完整显示不截断 |

示例（改进后）：
```
重复最严重的前10个章号：
  第1章 (3次): 第一回 甄士隐梦幻识通灵 贾雨村风尘怀闺秀
    出现行号: 1、50、120

章号相同但标题不同: 136 个章号
  完整列表：
    第2章（2个不同标题）:
        · 第二回贾夫人仙逝扬州城冷子兴演说荣国府
        · 第二回 不同标题的第二章
    第3章（2个不同标题）:
        · 第三回 贾雨村夤缘复旧职 林黛玉抛父进京都
        · 第三回 另一个标题版本
    ...（全部列出，不省略）
```

## 4. 默认设置

`设置TXTv3` 是独立入口，三项默认值一张表改完，不占拆分/分析/自动的正常流程。

| 设置项 | 默认值 | 选项 | 作用 |
|--------|--------|------|------|
| 广告/垃圾行清理 | 0（不清理） | 0=不清理 / 1=清理 | 拆分前移除网址/推广语/分页提示/求票/分隔线等7类垃圾行 |
| 标题级去重 | 1（章号+标题） | 0=仅章号 / 1=章号+标题 | 去重键是否包含规范化标题，避免同章异题被误删 |
| 卷级处理模式 | 1（自动） | 1=自动 / 2=扁平 / 3=按卷分目录 | 多卷检测：自动=有多卷则卷感知、无则扁平 |

**持久化位置**：

| 版本 | 存储位置 | 说明 |
|------|----------|------|
| VBA版 | `SaveSetting` 注册表（HKCU\Software\VB and VBA Program Settings\SplitTxtV3） | 随WPS/Office使用 |
| JS宏版 | `WScript.Shell` 注册表（HKCU\Software\SplitTxtV3\AdClean 等） | 随WPS JS宏使用 |
| Python版 | 命令行参数（`--ad-clean`/`--no-ad-clean`、`--title-dedup`/`--no-title-dedup`、`--volume-mode`） | 无注册表，每次显式传入 |

读取失败时自动回退到上述默认值，无需担心配置丢失。

### 4.1 清理注册表痕迹

日常使用中，设置会保存到注册表以便下次使用。如果需要彻底清除 SplitTxtV3 在注册表中的所有痕迹，可以运行「清理注册表痕迹TXTv3」：

1. 打开 VBA 编辑器（Alt + F11）
2. 在模块中找到 `清理注册表痕迹TXTv3` 并运行
3. 确认弹窗后，注册表中的所有 SplitTxtV3 设置会被彻底删除
4. 下次运行拆分/分析/自动功能时，会自动恢复默认值（0,1,1）

> **Python版**：无注册表，不传参数即为默认值，无需清理。
> **JS宏版**：同样使用注册表保存，可通过对应入口清理。

## 5. 自动化线

`自动TXTv3`（VBA/JS宏）和 `--auto`（Python）实现相同逻辑：分析 → 自动决策 → 一次确认 → 执行。

### 5.1 输出结构

`--auto` 忽略 `--out`，固定输出到源文件旁的 `<源文件名>_自动\` 目录，含五件套（与手动清洁模式结构一致）：

```
小说.txt
└── 小说_自动/
    ├── 分析报告.txt                  总-分结构深度分析报告（七大维度）
    ├── 拆分完成报告.txt               总-分结构精简完成报告（质量/清理/计时）
    ├── 保留大于等于N_小说.txt         正文≥N字的纯净合并文件
    ├── 清理小于N_小说.txt             正文<N字的纯净合并文件
    └── 拆分文档/
        ├── 001_xxxx_第一章 xxx.txt
        ├── ...
        └── NNN_xxxx_第N章 xxx.txt
```

**两个报告的区别**：

| 文件 | 内容 | 生成时机 |
|------|------|----------|
| 分析报告.txt | 七大维度深度分析（重复/乱序/多轨/格式/连续性等） | 分析阶段生成 |
| 拆分完成报告.txt | 总-分精简摘要（去重结果/清理统计/耗时） | 拆分完成后生成 |

### 5.2 自动决策规则（仅统计 ch_num>0 且非目录区章节）

| 触发条件 | 推荐去重 | 推荐排序 | 典型场景 |
|----------|----------|----------|----------|
| dup=0 且 ooo=0 | none | none | 干净文件，直接拆分 |
| adjRatio≥0.3 且 ooo<10 | longest | none | 标准双标题结构（保留内容最全的） |
| ooo≥10 | longest | sort | 乱序严重 |
| dup>0 | longest | none | 有重复但不算太乱 |
| 其他 | longest | sort | 兜底最稳妥方案 |

> `dup` = 重复章号数；`ooo` = 乱序处数；`adjRatio` = 相邻双标题占比。

### 5.3 N 值自动判定算法

1. 取所有章节正文汉字数，升序排列；
2. 取下半区（≤中位数）的最大相邻间隔中点，取整到 10；
3. `clamp[50, 2000]`；
4. 回退：章节<20 或 gap<50 或 最大gap<次大gap×2 → N=100。

示例：若下半区字数集中在 80~120 字，中位数约100，判定 N≈100，与经验值吻合。

## 7. 去重策略详解

v3.4 将拆分主流程的去重+排序简化为 **六合一弹窗**（3 去重 × 2 排序 = 6 种组合）。

### 7.0 通用输出结构

所有6种组合在**清洁模式**下输出结构一致（五件套），仅内容（章节数、顺序）不同：

```
源文件.txt
└── 源文件_拆分/          （输出目录名可自定义）
    ├── 分析报告.txt           总-分结构深度分析报告（七大维度）
    ├── 拆分完成报告.txt        总-分结构精简完成报告（质量/清理/计时）
    ├── 保留大于等于N_源文件.txt  正文≥N字的纯净正文合并（无报告头部）
    ├── 清理小于N_源文件.txt      正文<N字的纯净正文合并（无报告头部）
    └── 拆分文档/
        ├── 001_xxxx_第一章 xxx.txt   单章文件（序号_字数_标题）
        ├── 002_xxxx_第二章 xxx.txt
        ├── ...
        └── NNN_xxxx_第N章 xxx.txt
```

> **普通拆分模式**（非清洁模式）：仅输出 `拆分文档/` 下单章文件，无合并文件和报告。
> **自动模式**：输出目录名为 `源文件_自动/`，结构同上。

---

### 7.1 六种组合对比

| 组合 | 去重 | 排序 | 去重力度 | 修序 | 章节完整性 | 适用场景 |
|------|------|------|----------|------|------------|----------|
| 1 | none | none | — | ✗ | 100%（原样） | 文件干净，仅拆分 |
| 2 | none | sort | — | ✓ | 100%（重排） | 无重复但整体乱序 |
| 3 | first | none | ★★★☆☆ | ✗ | 去重后保留首次 | 相邻双标题/简单重复 |
| 4 | first | sort | ★★★☆☆ | ✓ | 去重后保留首次+重排 | 简单重复且乱序 |
| 5 | longest | none | ★★★☆☆ | ✗ | 去重后保留最长 | 整块重复，想留最全 |
| 6 ★ | longest | sort | ★★★★★ | ✓ | 去重后保留最长+重排 | 重复+乱序严重，最彻底（默认） |

---

### 7.2 各组合输出特点详解

#### 组合 1：none + none（不去重+不排序）

**输入假设**：文件完全干净，无重复无乱序。

**输出特点**：
- 章节数 = 原始识别章节数（跳过目录区）
- 顺序 = 原文出现顺序
- 无任何内容丢失

**适用**：质量良好的源文件，仅需拆分。

```
输出示例（1560章原文）：
  拆分文档/  → 1560个文件，顺序与原文一致
```

---

#### 组合 2：none + sort（不去重+排序）

**输入假设**：无重复章号，但章节顺序乱了。

**输出特点**：
- 章节数 = 原始识别章节数（不去重）
- 顺序 = 按章号升序重排（卷模式下按卷→章号排序）
- 无任何内容丢失，仅调整顺序

**适用**：排版乱序但无重复的文件。

```
输出示例（1560章乱序）：
  拆分文档/  → 1560个文件，从第1章到第1560章完全有序
```

---

#### 组合 3：first + none（保留首次+不排序）

**输入假设**：有简单重复（如双标题结构），无严重乱序。

**输出特点**：
- 章节数 = 去重后数量（每个去重键只留第一次出现的）
- 顺序 = 原文出现顺序（首次出现的位置）
- 重复章节的后续出现会被删除

**适用**：相邻双标题/目录式重复，想保留第一个标题章节。

```
输出示例（每章出现2次，共3120行识别）：
  拆分文档/  → 1560个文件，保留每章第一次出现，顺序与原文一致
```

---

#### 组合 4：first + sort（保留首次+排序）

**输入假设**：有简单重复且有乱序。

**输出特点**：
- 章节数 = 去重后数量（每个去重键只留第一次出现的）
- 顺序 = 按章号升序重排
- 内容保留首次出现的版本，顺序按章号重新排列

**适用**：双标题结构 + 乱序的文件。

```
输出示例（每章出现2次且乱序，共3120行识别）：
  拆分文档/  → 1560个文件，保留首次内容，从第1章到第1560章有序
```

---

#### 组合 5：longest + none（保留最长+不排序）

**输入假设**：有整块重复（如整段重复），想保留内容最全的版本，无严重乱序。

**输出特点**：
- 章节数 = 去重后数量（每个去重键只留正文最长的）
- 顺序 = 最长章节在原文中出现的顺序
- 保留内容最多的版本，可能不是第一次出现的

**适用**：重复块内容有差异，想留最全的，且顺序基本正常。

```
输出示例（有重复块，共1800行识别）：
  拆分文档/  → 1560个文件，每章保留正文最长的那个，顺序与原文一致
```

---

#### 组合 6：longest + sort ★推荐（保留最长+排序）

**输入假设**：重复+乱序都严重，需要最彻底修复。

**输出特点**：
- 章节数 = 去重后数量（每个去重键只留正文最长的）
- 顺序 = 按章号升序完全有序
- 内容最全 + 顺序正确，**1到最大章号齐全**
- 是默认推荐方案

**适用**：脏数据严重的文件，一步到位。

```
输出示例（重复+乱序严重）：
  拆分文档/  → 1560个文件，每章内容最长，从第1章到第1560章完全有序
```

> **玄鉴仙族案例**：原始 1560 个章号识别，去重+排序后 1560 章齐全且完全有序，内容也是各章中最长的版本。

---

### 7.3 双标题场景与 lis 兼容说明

- **相邻双标题**（目录式标题+正文式标题连续出现两次）：v3.4 不再提供单独的 adjacent 去重策略。目录区自动检测会跳过开头的纯目录段（前30%内连续≥10个短正文章节），清洁模式会跳过仅标题/正文不足的章节——两者联合已覆盖该场景；仍有残留时用 longest+none（保留内容最全且不改顺序）即可。
- **lis**（最长递增子序列修序）：v3.4 主流程不再单独列出，其效果大致等价于 `first + sort` 或 `longest + sort`，但存在关键差异（见下）。命令行 `--sort lis` 仅兼容保留。

**LIS vs 保留首次/最长 + 排序 的关键差异**：

| 维度 | LIS | first/longest + sort |
|------|-----|----------------------|
| 章节完整性 | **可能少几章**（不在最长递增主线的章节被丢弃） | 所有章节都被保留（重复的去重，乱序的移动到正确位置） |
| 顺序正确性 | 完全有序 | 完全有序 |
| 典型差异案例 | 玄鉴仙族：LIS 结果 1553 章，sort 结果 1560 章 | 1 到最大章号齐全 |
| 适合场景 | 想保留原文脉络，接受少量章节取舍 | 想要完整有序的结果，**不丢章** |

> **玄鉴仙族案例**：原始 1560 个章号，LIS 策略得到 1553 章（7 章因不在最长递增主线上被舍弃），而 `longest + sort` 得到 1560 章齐全且完全有序。这是 v3.4 推荐用组合 6 替代 lis 的核心原因。

#### 7.3.1 LIS vs Sort 对比表（保留参考）

| 维度 | LIS | Sort |
|------|-----|------|
| 章节完整性 | 可能少几章（末尾重复块） | 1到最大章号齐全 |
| 顺序正确性 | 完全有序 | 完全有序 |
| 原文相邻关系 | 保留较好 | 完全忽略 |
| 适合场景 | 想保留原文脉络 | 想要完整有序的结果 |

### 7.4 标题级去重（默认开启）

**适用场景**：同一章号下存在不同标题的章节（同章异题），仅按章号去重会误删内容。**v3.5 起默认开启**，无需手动启用。

**原理**：去重键 = 卷号 + 章号 + **规范化标题**，只有章号相同**且**标题相同才视为重复。

**标题规范化处理**：
- 全角数字/字母/符号 → 半角
- 空白压缩（多个空格/制表符合并为一个）
- 移除常见标点（逗号、句号、冒号、引号、括号等）
- 转小写
- 移除零宽字符

**示例**：
```
第1章 张三出世
第1章 张三出世　（全角空格）
第1章 张三出世。（带句号）
第1章 张三出世!（带感叹号）
→ 以上4个标题规范化后相同，视为重复

第1章 张三出世
第1章 李四入世
→ 标题不同，不视为重复（各保留各的）
```

**使用方法**：
```bash
# 默认已开启，无需任何参数
python split_txt_v3.py --src 小说.txt

# 如确实需要关闭（回到仅按章号去重）
python split_txt_v3.py --src 小说.txt --no-title-dedup
```

**VBA/JS宏版**：标题级去重默认已开启（1=章号+标题）。如需关闭，通过独立入口「设置TXTv3」将第2位改为 0，设置持久化、不占拆分流程。
- 深度分析报告会自动统计"章号相同但标题不同"的数量，并给出示例
- 玄鉴仙族实测：默认开启后从 1560 章 → 1698 章，救回 138 章同章异题内容

## 8. 卷级处理模式

| 模式 | 说明 | 输出方式 |
|------|------|----------|
| **auto**（默认） | 自动检测：有多卷则卷感知，无则扁平 | 单目录 |
| **flat** | 强制扁平：忽略卷结构，所有章节按章号去重 | 单目录 |
| **by_volume** | 按卷分目录：每卷独立子文件夹 | 多卷子目录 |

**by_volume 输出结构**：
```
小说_拆分/
├── 第一卷/
│   ├── 001_xxxx_第一章 xxx.txt
│   ├── 002_xxxx_第二章 xxx.txt
│   └── ...
├── 第二卷/
│   ├── 001_xxxx_第一章 xxx.txt
│   └── ...
└── ...
```

## 9. 多轨目录问题

### 什么是多轨目录？

文件中存在多套独立的章节体系：
- **目录区 + 正文区**：开头有一份完整目录（只有标题），正文区又有完整章节
- **双轨粘贴**：两份小说被拼接在一起
- **卷间重复**：不同卷的章号各自独立

### 检测方法

- VBA版：运行 `分析TXTv3`，查看分析报告
- Python版：`python split_txt_v3.py --src 小说.txt --analyze`

自动检测项：
- 相邻双标题比例（>30% 提示疑似双标题结构）
- 最长连续递增章号段长度
- 卷间章号重复情况

### 处理方案

| 情况 | 推荐策略 |
|------|----------|
| 仅每章双标题 | longest+none（保留内容最全且不改顺序）；通常目录区检测+清洁模式已自动覆盖 |
| 目录区+正文区（目录只有标题） | longest（留正文最长的） |
| 两份完整小说拼接 | sort（lis 仅兼容保留，不推荐使用） |
| 多卷且每卷章号独立 | sort + --volume-mode auto/by_volume |

## 10. 策略选择决策树


## 11. 无号章节处理

支持识别的无号章节：
- 序章、楔子、引子、序言、前言
- 尾声、终章、后记、跋
- 番外

处理方式：
- 按标题文本去重（完全相同标题只留一个）
- 排序时排在所有有号章节前面
- 文件名正常生成，序号照常递增

## 12. 清洁模式

跳过正文中文字数不足的章节，输出纯净的合并文本（仅保留正文≥N字的章节，无报告头部）。

**v3.5 变更**：手动 `--clean` 与自动 `--auto` 统一输出**固定五件套**——分析报告.txt（深度分析七大维度）+ 拆分完成报告.txt（总-分摘要）+ 双合并文件（保留≥N + 清理<N）+ `拆分文档\` 子目录单章文件（命名 序号_源行号_标题.txt）。

**Python版**：
```bash
# 跳过正文<100字的章节，输出五件套：分析报告 + 拆分完成报告 + 保留≥100 / 清理<100 合并文件 + 拆分文档\ 单章文件
python split_txt_v3.py --src 小说.txt --clean 100
```

**VBA/JS宏版**：输出模式弹窗输入 `1`（默认N=100）或 `1 200`（自定义N=200）

**输出文件**（五件套，均在输出根目录）：
- `分析报告.txt` —— 总-分结构深度分析报告（七大维度）
- `拆分完成报告.txt` —— 总-分结构精简完成报告（质量/清理/计时）
- `保留大于等于N_原文件名.txt` —— 正文≥N字的章节，按顺序合并
- `清理小于N_原文件名.txt` —— 正文<N字的章节，按顺序合并（v3.4 新增）
- `拆分文档/` 目录下每章一个单文件（v3.5 起统一落子目录，与清洁模式并存，无需单独拆分）

格式：纯净正文，无统计信息、无分隔线、无报告头部。

### 案例3：多卷小说（一二卷各有第一章）

**原始**：两卷，每卷200章，章号各自从1开始

| 模式 | 效果 |
|------|------|
| flat | 只剩200章（两卷合并去重了） |
| auto | 400章（卷感知，同卷内去重） |
| by_volume | 400章，分两卷目录 |

**结论**：auto 或 by_volume 正确，flat 会丢章。

## 14. 与 splittxt / splittxt2 的关系

```
splittxt   → 基础版（单一正则，VBA/Python/JS）
splittxt2  → 多正则版（9套正则可选，支持多选并列，仅VBA）
splittxt3  → 质量修复版（重复+乱序+卷结构+自动化，Python / VBA / WPS JS宏 三版本）
```

splittxt3 专注于**数据质量修复**：
- 正则方面继承 splittxt2 的终极数字字符类和多选并列
- 新增卷级识别、无号章节识别
- v3.4 核心：3去重×2排序六组合 + 3种卷模式 + 全自动决策线
- v3.5 追加：清洁模式统一五件套 + 聚合模式强制扁平 + 广告清理默认关/标题去重默认开 + 死代码清理

**使用建议**：
- 如果格式不标准 → 先用 splittxt2 选合适正则确认能识别
- 如果有重复/乱序问题 → 用 splittxt3 去重修序
- 习惯图形交互 → 用 VBA 版（split_txt_v3.bas）或 WPS JS宏版（split_txt_v3.js，已经实测）
- 需要批量处理/详细分析 → 用 Python 版（split_txt_v3.py）
- 不想逐项选择 → 用 自动TXTv3 / --auto 一键完成

### 15.4 业界常见去重算法

**1. 精确去重（Exact Deduplication）**
- 方法：标题或正文完全相同视为重复
- 优点：简单高效，准确率最高
- 缺点：无法处理内容略有差异的重复
- splittxt3对应：first / longest（基于章号精确去重）

**2. 章节标题去重（Title-based）**
- 方法：提取"第N章"作为识别单元，同章号只留一份
- 优点：实现简单，覆盖大部分场景
- 缺点：依赖标题规范性
- splittxt3对应：全部3种去重策略（none/first/longest）都基于此

**3. 章节序号检测（Number Analysis）**
- 方法：解析章号，检测缺章、重复、序号回退、空章
- 优点：能发现多种问题类型
- splittxt3对应：--analyze 深度分析报告

**4. 最长递增子序列（LIS）**
- 方法：在章节序列中找章号递增的最长主线
- 优点：去重+修序二合一，智能选择正确主线
- 缺点：可能舍弃少量章节（选择最优主线时的正常取舍）
- splittxt3对应：lis 策略（v3.4 起主流程移除，仅命令行 `--sort lis` 兼容保留）

**5. 按章号重排（Sort by Number）**
- 方法：每章取最长内容，按章号重新排序
- 优点：结果最完整，完全有序
- 缺点：完全忽略原文相邻关系
- splittxt3对应：sort 策略

**6. 相似度去重（进阶算法）**
- N-gram + Jaccard：n元语法片段集合的重叠度
- MinHash + LSH：局部敏感哈希，大规模近似去重
- SimHash：海明距离衡量相似度
- 适用：标题不同但内容相似的近似重复章节
- splittxt3现状：暂未实现（精确去重已能覆盖绝大多数场景）

### 15.5 行业最佳实践

1. **下载阶段去重优先**：在源头过滤重复章节，比事后修复效率高得多
2. **体检先行**：先用分析工具诊断问题类型和严重程度，再选策略
3. **精确去重优先，相似度兜底**：标题精确去重解决90%+问题，近似去重处理特殊情况
4. **分卷小说分别计算**：每卷章号独立，不能拉通计算缺章和重复
5. **自动去重要有复核机制**：操作前备份，避免误删无法恢复
6. **优先本地化工具**：小说原文涉及版权和隐私，尽量不上传在线工具

### 15.6 splittxt3 的定位

splittxt3 属于 **"TXT整理阶段的专用工具"**：

- 上游：splittxt / splittxt2（章节识别和基础拆分）
- 中游：**splittxt3（去重+乱序修复+卷感知，本工具）**
- 下游：EPUB转换工具、阅读器、校对工具

与通用工具相比，splittxt3 的优势在于**理解章节语义**——知道"第N章"是什么，
能识别卷结构，能处理中文数字，能在"章"的维度上去重和排序，而不是简单的行级/段落级处理。

## 16. 常见问题

**Q: 为什么 lis 策略会少几章？**
A: LIS 找的是最长递增子序列。如果文件末尾有重复块，LIS 会选择前面那条主线。
想要最完整的结果，用 sort 策略。

**Q: by_volume 模式下序号是每卷从1开始吗？**
A: 目前是全局连续编号（1,2,3...贯穿所有卷）。如果需要每卷独立编号，
可以后续加参数支持。

**Q: 支持篇/卷/章三级结构吗？**
A: 目前支持两级（卷+章）。如果是"卷→篇→章"三级结构，篇会被当作卷来处理。
更复杂的多级结构可以按需扩展。

**Q: 三个版本功能完全一样吗？**
A: 核心功能（3去重×2排序六组合、3种卷模式、聚合拆分、清洁模式、自动化线）完全一致。
差异：Python版分析报告更详细（七大维度）；VBA/JS宏版是图形化交互操作。
JS宏版已经本机 cscript 实测 38/38 PASS；VBA版 v3.5 未经编译验证，如有问题以 JS宏版为准。

**Q: VBA版怎么导入？**
A: 打开WPS表格/Excel/Word → Alt+F11 → 文件→导入文件 → 选择 split_txt_v3.bas
或者直接复制 .bas 文件内容粘贴到模块中。JS宏版则把 split_txt_v3.js 粘贴到 WPS JS宏编辑器。
四个入口：「拆分TXTv3」「分析TXTv3」「自动TXTv3」「设置TXTv3」。

## 17. v3.2 新增功能详解（VBA版）

### 17.1 目录区自动检测

**原理**：文件开头连续 N 个章节的正文都极短（≤2行）且章号递增 → 判定为目录区。

**判定条件**：
- 位置在文件前 30% 的章节内
- 连续 ≥ 10 个章节正文行数 ≤ 2 行
- 章号整体呈递增趋势

**效果**：
- 自动跳过目录区章节，不参与去重和排序
- 分析报告中明确标注检测到的目录区位置和数量
- 避免目录区干扰乱序检测和缺章分析

### 17.2 广告/垃圾行清理

**7类清理规则**：

| 类型 | 示例 |
|------|------|
| 网址行 | `http://xxx.com`、`www.xxx.net`、含域名后缀的短行 |
| 站点推广 | 记住本站、收藏本站、永久域名、最新地址、笔趣阁等 |
| 分页提示 | 本章未完、下一页继续、点击下一页、上一页、返回目录 |
| 求票求收藏 | 求月票、求推荐票、求打赏、感谢订阅（40字内短行） |
| 纯符号分隔线 | `*****`、`-----`、`=====`、`~~~~~` 等 |
| 手机端提示 | 手机用户请浏览、手机版 |
| 加入书架 | 加入书签、加入书架 |

**使用方式**：v3.5 起由「设置TXTv3」统一控制（默认 0=不清理），Python 版用 `--ad-clean`/`--no-ad-clean`（默认关闭，保留原文）。

### 17.3 章号归一化预处理

**自动处理（不影响原文输出）**：
- 全角数字 → 半角数字（`０１２` → `012`）
- 全角空格 → 半角空格
- 全角冒号 → 半角冒号（统一"第N章：标题"格式）
- 压缩多个连续空格为一个
- 清除零宽字符（U+200B/U+200C/U+200D/U+FEFF）
- Tab → 空格

**效果**：显著提升格式不规范TXT的章节识别率，尤其是全角/半角混杂的文件。

### 18.6 脏数据来源深度分析

本案例的脏数据不是随机产生的，而是**多源抓取 + 自定义标记 + 数字/文字混排**三个系统性因素叠加的结果。

#### 18.6.1 多源抓取导致的重复结构

| 现象 | 数据 | 根因 |
|------|------|------|
| 平均每章 2 份拷贝 | 3126 份 / 1560 章 = 2.00 | 至少两个下载源拼接 |
| 116 章仅 1 份 | 可能是单源独有章节 | 其中一个源缺失这些章 |
| 1425 章恰好 2 份 | 双源完整覆盖 | 标准双备份 |
| 10 章 3 份 / 3 章 4 份 | 三源拼接 | 更复杂的采集历史 |
| 962-967 章 18-20 份 | 同一章被反复抓取 | 该段在多个源被重复收录 |

**结论**：这不是"错误"，而是**多源备份策略的自然结果**。工具的去重逻辑正是为此设计。

#### 18.6.2 自定义标记目录（加更/打赏/盟主）

| 标记类型 | 数量 | 示例 |
|----------|------|------|
| 含括号/加更/盟主/赏 的标题 | **369 章** | `第789章 西岸血书（1+22）` |
| 含分章标记（上/下/1/2/112/122） | **39 章** | `第1515章 旧陵(下)` |

**问题**：起点官方目录没有这些标记，但下载站为了标注"这是加更内容"自行添加。同一章号在不同源中：
- 源 A：`第789章 西岸血书（122）`
- 源 B：`第789章 西岸血书（1+22）`
- 源 C：`第789章 西岸血书`（无标记）

**结果**：标题级去重把它们当成不同章节，产生 ~90 个假重复。

#### 18.6.3 数字目录与文字目录并存

| 形式 | 示例 | 出现场景 |
|------|------|----------|
| 阿拉伯数字 `第1012章` | `第1012章 兵至` | 多数源 |
| 中文数字 `第一千零十二章` | `第一千零十二章 魄炼（1+12）` | 少数源/早期章节 |
| 裸数字 `101` | `101 体验佳...` | 广告水印行 |

**工具处理**：正则统一识别，归一化为同一 `ch_num`。但**标题文本保留原样**，导致同一章号的标题看起来不同。

#### 18.6.4 目录缺失与填充

| 检查项 | 结果 | 说明 |
|--------|------|------|
| 章号 1-1560 缺失 | **0** | 所有章号都有至少一份拷贝 |
| 但 116 章仅 1 份 | 若该份是空壳/残缺，则该章实际缺失 | 需人工核查 |

**结论**：多源拼接**挽救了潜在缺失**。如果只用单一来源，这 116 章中可能有部分是真正的"空章"。

#### 18.6.5 综合根因图

```
原始小说（起点中文网）
    │
    ├─ 源 A 抓取（含加更标记 (112)）
    ├─ 源 B 抓取（含加更标记 (1+1/2)）
    ├─ 源 C 抓取（无标记，但部分章节缺失）
    └─ 源 D 抓取（早期章节，中文数字标题）
    │
    ▼
合并为单一 TXT（未去重）
    │
    ▼
3126 份章节结构 → 1560 唯一章号 → 139 个"差异"章节
    │
    ├─ ~90 章：加更记法差异（假重复，应合并）
    ├─ ~16 章：真正内容差异（应保留）
    └─ ~33 章：空壳/残缺/斜接（清洁模式分流）
```

#### 18.6.6 应对策略

| 问题类型 | 当前工具对策 | 局限 | 建议 |
|----------|-------------|------|------|
| 多源重复 | `longest` 保留最长版本 | 无法识别"记法不同但内容相同" | 未来可加"加更标记归一化"预处理 |
| 自定义标记 | 标题级去重保留差异 | 产生假重复 | 人工核查清理文件 |
| 数字/文字混排 | 正则统一识别章号 | 标题原文保留差异 | 不影响去重，只影响标题显示 |
| 空壳章节 | 清洁模式 N=100 分流 | 无法自动修复 | 人工从其他源补齐 |
| 内容斜接 | 保留并标记 | 无法自动修复 | 人工核查后删除 |

## 19. 批量处理使用说明（v3.5 新增）

### 19.1 适用场景

对整个文件夹（含子目录）的多本小说 txt 统一执行清洁模式拆分，每本输出固定五件套结构：

```
<书名>_自动\
├── 分析报告.txt
├── 拆分完成报告.txt
├── 保留大于等于100_<书名>.txt
├── 清理小于100_<书名>.txt
└── 拆分文档\            ← 每章一个单文件
```

### 19.2 批处理脚本（PowerShell，已踩坑修复版）

```powershell
# ============================================================
# 批量拆分小说 txt（清洁模式五件套）
# 参数：$root   要扫描的根目录（递归含子目录）
#       $minMB  只处理大于该体积的 txt（默认 5MB）
#       $skip   文件名排除正则（默认排除已处理的玄鉴仙族）
# ============================================================
$script = "c:\...\splittxt3\split_txt_v3.py"   # ← 改为实际路径
$root   = "c:\...\语料与文本\小说"              # ← 改为实际路径
$minMB  = 5
$log    = "$env:TEMP\batch_split_log.txt"

$files = Get-ChildItem $root -Recurse -Filter "*.txt" -File |
    Where-Object {
        $_.FullName -notmatch '_自动|拆分文档|保留大于等于|清理小于|分析报告' -and
        $_.Length -gt ($minMB * 1MB)
    }

"开始: $(Get-Date -Format 'HH:mm:ss')，共 $($files.Count) 个文件" |
    Out-File $log -Encoding utf8
$ok = 0; $fail = 0; $skipN = 0

foreach ($f in $files) {
    $outDir = Join-Path $f.DirectoryName ($f.BaseName + "_自动")

    # 要点①：-LiteralPath 防止文件名含 [ ] 被当通配符误判
    if (Test-Path -LiteralPath $outDir) {
        $skipN++
        "跳过(已存在): $($f.Name)" | Out-File $log -Append -Encoding utf8
        continue
    }

    $t0 = Get-Date
    # 要点②：输出落日志文件，禁止重定向到 $null（否则报错被吞无法追溯）
    python -X utf8 $script --src $f.FullName --dedup longest --sort none `
           --clean 100 --out $outDir *> "$env:TEMP\batch_last_run.log"

    # 要点③：用退出码判定成败，不要用文件存在性
    if ($LASTEXITCODE -eq 0) {
        $ok++
        "OK $([math]::Round(((Get-Date)-$t0).TotalSeconds,1))s: $($f.Name)" |
            Out-File $log -Append -Encoding utf8
    } else {
        $fail++
        "FAIL(exit=$LASTEXITCODE): $($f.Name)" | Out-File $log -Append -Encoding utf8
        # 失败时保留 batch_last_run.log 供排查
        Copy-Item "$env:TEMP\batch_last_run.log" "$env:TEMP\batch_err_$($f.BaseName).log"
    }
}
"完成: $(Get-Date -Format 'HH:mm:ss')，成功 $ok，失败 $fail，跳过 $skipN" |
    Out-File $log -Append -Encoding utf8
```

### 19.3 关键要点（踩坑记录）

| # | 要点 | 反例（会踩坑） | 正确做法 |
|---|------|----------------|----------|
| ① | **Test-Path 通配符陷阱** | `Test-Path (Join-Path $dir "分析报告.txt")`，文件名含 `[修真]` 时 `[...]` 被解析为字符集通配符 → 实际成功也误判 FAIL | 一律用 `Test-Path -LiteralPath` |
| ② | **成功判定用退出码** | 用"某文件是否存在"判定成功，脆弱且受 ① 影响 | `$LASTEXITCODE -eq 0` |
| ③ | **错误输出必须留痕** | `python ... 2>&1` 重定向到 `$null`，失败后无任何报错可查 | 输出落 `batch_last_run.log`，失败时复制保存 |
| ④ | **跳过已处理目录** | 重复跑会覆盖已有 `_自动` 目录 | 先 `Test-Path -LiteralPath` 跳过 |
| ⑤ | **递归扫描要排除产物** | 不排`_自动`/`拆分文档` 会把已拆出的单章 txt 再次当源文件处理 | Where-Object 过滤五类关键词 |
| ⑥ | **后台长跑任务** | 前台跑 50+ 文件会阻塞会话 | `run_in_background` + 日志文件轮询进度 |
| ⑦ | **文件名特殊字符** | `[ ]`、`@`、`（）`、空格在 Join-Path / Remove-Item 中均有通配符歧义 | 所有路径操作统一 `-LiteralPath` |

### 19.4 实战数据（2026-10-01 批处理 53 本小说）

| 指标 | 数值 |
|------|------|
| 总文件 | 53 本（>5MB） |
| 单本耗时 | 2~27 秒（与体积线性相关，约 0.5s/MB） |
| 成功 | 33 本 |
| 失败（误报） | 15 本 → 全部为批处理脚本缺陷（要点①②③），拆分器本身无故障 |
| 失败（真实） | 0 本 |

### 19.5 删除批处理产物

```powershell
# 删除本次批处理生成的所有 _自动 目录（注意 -LiteralPath）
Get-ChildItem $root -Recurse -Directory |
    Where-Object { $_.Name -match '_自动$' -and $_.LastWriteTime -gt (Get-Date).Date } |
    ForEach-Object { Remove-Item -LiteralPath $_.FullName -Recurse -Force }
```
