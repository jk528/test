# TXT章节拆分工具 v3（去重+乱序修复+卷级感知增强版）—— 使用说明

## 1. 概述

`splittxt3` 是在 `splittxt2` 基础上，全面解决TXT小说质量问题的增强版本。

**双版本**：
- **Python版**（`split_txt_v3.py`）：命令行使用，分析功能更详细，适合批量处理
- **VBA版**（`split_txt_v3.bas`）：WPS/Excel/Word 中运行，图形化交互，与 splittxt2 用法一致

**覆盖 13 类问题场景**：

### 一、重复类问题
| 编号 | 类型 | 表现 | 举例 |
|------|------|------|------|
| 1 | 相邻双标题 | 每章标题连续出现2次 | 第1章 标题（行首）+ 第1章 标题（缩进） |
| 2 | 整块重复粘贴 | 某段章节被连续复制N次 | 第962-970章反复出现10次 |
| 3 | 末尾重复块 | 文件尾部又重复了前面的章节 | 末尾重复第1554-1560章 |
| 4 | 卷间章号重复 | 不同卷有相同章号 | 第一卷第一章 vs 第二卷第一章 |

### 二、乱序类问题
| 编号 | 类型 | 表现 | 原因 |
|------|------|------|------|
| 5 | 重复导致乱序 | 章号在某范围内来回跳 | 整块重复粘贴 |
| 6 | 末尾回退乱序 | 章号已经很大，突然又从前面开始 | 末尾重复块 |
| 7 | 整体完全乱序 | 文件拼接顺序完全错误 | 下载/合并不慎 |

### 三、结构类问题
| 编号 | 类型 | 表现 | 说明 |
|------|------|------|------|
| 8 | 多卷/多部/多册 | 存在卷/部/册等上级结构 | 每卷内章号重新编号 |
| 9 | 多轨目录 | 文件中有多套独立章节体系 | 目录区+正文区各一套 |
| 10 | 多级嵌套 | 卷→篇→章→节多层结构 | 当前支持两级（卷+章） |
| 11 | 无号章节 | 序章/楔子/番外/尾声等 | 无数字编号的特殊章节 |
| 12 | 章号缺失 | 中间缺章，章号不连续 | 分析报告可列出缺失章号 |
| 13 | 格式混合 | 阿拉伯数字+中文数字混合 | 多种单位词混合 |

## 3. VBA版使用指南

### 3.1 导入方法

1. 打开 WPS 表格 / Excel / Word
2. 按 `Alt + F11` 打开 VBA 编辑器
3. 菜单：文件 → 导入文件 → 选择 `split_txt_v3.bas`
4. 或：直接打开 `.bas` 文件，全选复制，粘贴到 VBA 编辑器的模块中

### 3.2 两个入口

| 入口 | 功能 |
|------|------|
| `分析TXTv3` | 仅分析不拆分，生成详细分析报告文件 |
| `拆分TXTv3` | 完整拆分流程（选文件→选正则→选去重→选卷模式→选模式） |

### 3.3 拆分TXTv3 交互流程

```
步骤1：选择TXT文件
   ↓
步骤2：选择正则表达式（可多选并列，与splittxt2一致）
   输入 1 或 1,4 等
   ↓
步骤3：选择去重策略
   1. 相邻重复去重（仅合并连续相同章号）
   2. 保留首次出现（每章只留第一次）
   3. 保留内容最长的（每章留正文最多的）
   4. 最长递增子序列（智能找主线，去重+修序）★推荐
   5. 按章号重新排序（最彻底，章号齐全）★推荐
   ↓
步骤4：选择卷级处理模式
   1. 自动检测（有多卷则卷感知，无则扁平）
   2. 强制扁平（忽略卷结构）
   3. 按卷分目录（每卷独立子文件夹输出）
   ↓
步骤5：选择拆分模式
   [是]    按章节一一拆分
   [否]    聚合拆分
   [取消]  清洁模式（按正文字数过滤并合并）
```

### 3.4 分析TXTv3 输出

运行后会在源文件同目录生成 `<源文件名>_分析报告.txt`，包含：
- 卷/部结构分析
- 重复章节分析（扁平视角）
- 乱序分析
- 多轨目录检测
- 格式多样性分析
- 章号连续性分析
- 各去重策略效果预览
- 处理建议

## 4. Python版使用指南

### 4.1 快速开始

```bash
# 第一步：深度分析
python split_txt_v3.py --src 你的小说.txt --analyze

# 第二步：拆分（推荐LIS智能策略）
python split_txt_v3.py --src 小说.txt --dedup lis

# 乱序严重用sort策略
python split_txt_v3.py --src 小说.txt --dedup sort

# 多卷小说按卷分目录
python split_txt_v3.py --src 小说.txt --dedup lis --volume-mode by_volume

# 聚合拆分
python split_txt_v3.py --src 小说.txt --dedup lis --chunk 40,3
```

### 4.2 完整参数

```bash
python split_txt_v3.py [参数]

必选:
  --src 文件路径        源TXT文件路径

分析模式:
  --analyze             深度分析：全面诊断所有问题（不拆分）

拆分模式:
  --mode chapter|groups 拆分模式：chapter=每章一文件(默认), groups=聚合拆分
  --chunk 格式          聚合格式，如 40,3 或 20,1|20,1|80,1 或 40
  --out 目录路径        输出目录（空则自动派生）

去重与修序:
  --dedup 策略          去重策略：adjacent/first/longest/lis/sort（默认lis）
  --volume-mode 模式    卷级处理：auto/flat/by_volume（默认auto）

文件命名:
  --prefix 前缀         文件名前缀
  --serial-width N      序号位数，默认3，不足自动扩展

编码与质量:
  --encoding 编码       手动指定源文件编码（gbk/utf-8/big5等）
  --min-body-len N      最小正文字数，少于该值的章节跳过
  --keep-title-only     生成仅有标题/正文不足的章节文件（默认跳过）
  --clean N[,flag]      清洁模式：N=最小正文字数，flag=0跳过/1保留(默认)
```

## 5. 五种去重策略详解

| 策略 | 原理 | 去重 | 修序 | 卷感知 | 适用场景 |
|------|------|------|------|--------|----------|
| **adjacent** | 相邻相同章号只留一个 | ★☆☆☆☆ | ✗ | ✓ | 仅双标题问题 |
| **first** | 每章保留首次出现 | ★★★☆☆ | △ | ✓ | 简单重复 |
| **longest** | 每章留正文最长的那次 | ★★★☆☆ | △ | ✓ | 整块重复，想留最全 |
| **lis** ⭐ | 最长递增子序列找主线 | ★★★★☆ | ✓ | ✓ | 重复+乱序都有，最智能 |
| **sort** ⭐ | 每章取最长，按章号重排 | ★★★★★ | ✓ | ✓ | 乱序严重，要最完整 |

**LIS vs Sort 怎么选？**

| 维度 | LIS | Sort |
|------|-----|------|
| 章节完整性 | 可能少几章（末尾重复块） | 1到最大章号齐全 |
| 顺序正确性 | 完全有序 | 完全有序 |
| 原文相邻关系 | 保留较好 | 完全忽略 |
| 适合场景 | 想保留原文脉络 | 想要完整有序的结果 |

## 6. 卷级处理模式

| 模式 | 说明 | 输出方式 |
|------|------|----------|
| **auto**（默认） | 自动检测：有多卷则卷感知，无则扁平 | 单目录 |
| **flat** | 强制扁平：忽略卷结构，所有章节按章号去重 | 单目录 |
| **by_volume** | 按卷分目录：每卷独立子文件夹 | 多卷子目录 |

**by_volume 输出结构**：
```
小说_拆分/
├── 第一卷/
│   ├── 001_xxxx_第一章 xxx.txt
│   ├── 002_xxxx_第二章 xxx.txt
│   └── ...
├── 第二卷/
│   ├── 001_xxxx_第一章 xxx.txt
│   └── ...
└── ...
```

## 7. 多轨目录问题

### 什么是多轨目录？

文件中存在多套独立的章节体系：
- **目录区 + 正文区**：开头有一份完整目录（只有标题），正文区又有完整章节
- **双轨粘贴**：两份小说被拼接在一起
- **卷间重复**：不同卷的章号各自独立

### 检测方法

- VBA版：运行 `分析TXTv3`，查看分析报告
- Python版：`python split_txt_v3.py --src 小说.txt --analyze`

自动检测项：
- 相邻双标题比例（>30% 提示疑似双标题结构）
- 最长连续递增章号段长度
- 卷间章号重复情况

### 处理方案

| 情况 | 推荐策略 |
|------|----------|
| 仅每章双标题 | adjacent 或 first |
| 目录区+正文区（目录只有标题） | longest（留正文最长的） |
| 两份完整小说拼接 | lis 或 sort |
| 多卷且每卷章号独立 | lis + --volume-mode auto/by_volume |

## 8. 策略选择决策树

```
拿到TXT文件
    ↓
先分析（--analyze 或 分析TXTv3）
    ↓
有卷结构吗？
    ├─ 有，且卷间章号重复 → 用 auto 或 by_volume 模式
    └─ 无 → 用 flat 模式（默认auto会自动判断）
    ↓
有重复吗？
    ├─ 无 → 直接拆分即可
    └─ 有
         ↓
      有乱序吗？
         ├─ 无 → longest（留内容最全的）
         └─ 有
              ↓
           乱序严重吗？
              ├─ 轻微（<10处） → lis
              └─ 严重 → sort（最稳妥）
```

## 9. 无号章节处理

支持识别的无号章节：
- 序章、楔子、引子、序言、前言
- 尾声、终章、后记、跋
- 番外

处理方式：
- 按标题文本去重（完全相同标题只留一个）
- 排序时排在所有有号章节前面
- 文件名正常生成，序号照常递增

## 10. 清洁模式

跳过正文中文字数不足的章节：

**Python版**：
```bash
# 跳过正文<100字的章节
python split_txt_v3.py --src 小说.txt --clean 100

# 合并所有跳过章节
python split_txt_v3.py --src 小说.txt --clean 100,0

# 合并所有保留章节
python split_txt_v3.py --src 小说.txt --clean 100,1
```

**VBA版**：拆分模式选择「取消」→ 输入清洁参数

## 11. 实际案例

### 案例1：玄鉴仙族（重复+乱序严重）

**原始**：3126次识别，1560个章号，乱序36处，第962-970章重复10-20次

| 策略 | 剩余 | 乱序 | 推荐度 |
|------|------|------|--------|
| adjacent | 1642 | 36处 | ✗ |
| first | 1560 | 7处 | △ |
| longest | 1560 | 7处 | △ |
| lis | 1553 | 0处 | ★★★★ |
| **sort** | **1560** | **0处** | ★★★★★ |

**结论**：sort 策略效果最好，1-1560章齐全且完全有序。

### 案例2：标准双标题小说

**原始**：每章标题出现2次（目录式+正文式）

| 策略 | 效果 |
|------|------|
| adjacent | 完全解决，保留原顺序 |

**结论**：adjacent 最简单高效。

### 案例3：多卷小说（一二卷各有第一章）

**原始**：两卷，每卷200章，章号各自从1开始

| 模式 | 效果 |
|------|------|
| flat | 只剩200章（两卷合并去重了） |
| auto | 400章（卷感知，同卷内去重） |
| by_volume | 400章，分两卷目录 |

**结论**：auto 或 by_volume 正确，flat 会丢章。

## 12. 与 splittxt / splittxt2 的关系

```
splittxt   → 基础版（单一正则，VBA/Python/JS）
splittxt2  → 多正则版（9套正则可选，支持多选并列，仅VBA）
splittxt3  → 质量修复版（重复+乱序+卷结构，Python+VBA双版本）
```

splittxt3 专注于**数据质量修复**：
- 正则方面继承 splittxt2 的终极数字字符类和多选并列
- 新增卷级识别、无号章节识别
- 核心是 5 种去重策略 + 3 种卷模式

**使用建议**：
- 如果格式不标准 → 先用 splittxt2 选合适正则确认能识别
- 如果有重复/乱序问题 → 用 splittxt3 去重修序
- 习惯图形交互 → 用 VBA 版（split_txt_v3.bas）
- 需要批量处理/详细分析 → 用 Python 版（split_txt_v3.py）

**彩读阅读特别说明**：彩读是本地阅读器（支持TXT/EPUB），核心卖点是内容上色、语音朗读、AI阅读助手等阅读体验优化 [$TRAE_REF](https://www.ghxi.com/colortxt.html)。
它只做**识别和展示**，不做**修改和去重**。打开有重复章节的TXT（如玄鉴仙族）时：
- 重复章节 → 目录出现多个同名章节，正文重复显示
- 乱序章节 → 按文件原顺序排列，阅读时章号跳号
- 跨卷同章号 → 识别卷结构则分开，不识别则都叫"第N章"

**启示**：主流阅读器大多不直接修改TXT文件，而是在"阅读体验"层面规避问题（目录导航、书签过滤、手动排序）。真正做文件级去重和修序的是专用整理工具。

**推荐流程**：先用 splittxt3 去重修复，再用彩读阅读享受阅读体验——两者是上下游关系，不冲突。

### 13.4 业界常见去重算法

**1. 精确去重（Exact Deduplication）**
- 方法：标题或正文完全相同视为重复
- 优点：简单高效，准确率最高
- 缺点：无法处理内容略有差异的重复
- splittxt3对应：first / longest（基于章号精确去重）

**2. 章节标题去重（Title-based）**
- 方法：提取"第N章"作为识别单元，同章号只留一份
- 优点：实现简单，覆盖大部分场景
- 缺点：依赖标题规范性
- splittxt3对应：全部5种策略都基于此

**3. 章节序号检测（Number Analysis）**
- 方法：解析章号，检测缺章、重复、序号回退、空章
- 优点：能发现多种问题类型
- splittxt3对应：--analyze 深度分析报告

**4. 最长递增子序列（LIS）**
- 方法：在章节序列中找章号递增的最长主线
- 优点：去重+修序二合一，智能选择正确主线
- 缺点：可能舍弃少量章节（选择最优主线时的正常取舍）
- splittxt3对应：lis 策略

**5. 按章号重排（Sort by Number）**
- 方法：每章取最长内容，按章号重新排序
- 优点：结果最完整，完全有序
- 缺点：完全忽略原文相邻关系
- splittxt3对应：sort 策略

**6. 相似度去重（进阶算法）**
- N-gram + Jaccard：n元语法片段集合的重叠度
- MinHash + LSH：局部敏感哈希，大规模近似去重
- SimHash：海明距离衡量相似度
- 适用：标题不同但内容相似的近似重复章节
- splittxt3现状：暂未实现（精确去重已能覆盖绝大多数场景）

### 13.5 行业最佳实践

1. **下载阶段去重优先**：在源头过滤重复章节，比事后修复效率高得多
2. **体检先行**：先用分析工具诊断问题类型和严重程度，再选策略
3. **精确去重优先，相似度兜底**：标题精确去重解决90%+问题，近似去重处理特殊情况
4. **分卷小说分别计算**：每卷章号独立，不能拉通计算缺章和重复
5. **自动去重要有复核机制**：操作前备份，避免误删无法恢复
6. **优先本地化工具**：小说原文涉及版权和隐私，尽量不上传在线工具

### 13.6 splittxt3 的定位

splittxt3 属于 **"TXT整理阶段的专用工具"**：

- 上游：splittxt / splittxt2（章节识别和基础拆分）
- 中游：**splittxt3（去重+乱序修复+卷感知，本工具）**
- 下游：EPUB转换工具、阅读器、校对工具

与通用工具相比，splittxt3 的优势在于**理解章节语义**——知道"第N章"是什么，
能识别卷结构，能处理中文数字，能在"章"的维度上去重和排序，而不是简单的行级/段落级处理。

## 14. 常见问题

**Q: 为什么 lis 策略会少几章？**
A: LIS 找的是最长递增子序列。如果文件末尾有重复块，LIS 会选择前面那条主线。
想要最完整的结果，用 sort 策略。

**Q: by_volume 模式下序号是每卷从1开始吗？**
A: 目前是全局连续编号（1,2,3...贯穿所有卷）。如果需要每卷独立编号，
可以后续加参数支持。

**Q: 支持篇/卷/章三级结构吗？**
A: 目前支持两级（卷+章）。如果是"卷→篇→章"三级结构，篇会被当作卷来处理。
更复杂的多级结构可以按需扩展。

**Q: VBA版和Python版功能完全一样吗？**
A: 核心功能（5种去重策略、3种卷模式、聚合拆分、清洁模式）完全一致。
差异：Python版分析报告更详细（七大维度），VBA版是图形化交互操作。

**Q: VBA版怎么导入？**
A: 打开WPS表格/Excel/Word → Alt+F11 → 文件→导入文件 → 选择 split_txt_v3.bas
或者直接复制 .bas 文件内容粘贴到模块中。然后运行「拆分TXTv3」或「分析TXTv3」。
