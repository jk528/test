# TXT 章节拆分工具 — 使用说明

## 1. 概述

本工具将大型 TXT 小说文件按章节拆分为多个小文件，支持三种模式：

- **按章节一一拆分**：每章生成一个独立文件
- **聚合拆分**：按自定义格式将多章合并为一份
- **清洁模式**：按正文字数过滤章节，并生成合并文件

提供 VBA、Python 和 WPS JS宏 三个版本，功能完全对齐，复制粘贴即可运行，无需外部依赖。

## 2. 文件结构

```
splittxt/
├── split_txt.bas       # VBA 合并版（1066行）
├── split_txt.py        # Python 合并版（705行）
├── split_txt.js        # WPS JS宏 合并版（925行）
└── 使用说明.md          # 本文档
```

## 3. 功能特性

| 特性 | 说明 |
|------|------|
| 编码自动检测 | ANSI(GBK) / UTF-8(含/无BOM) / UTF-16LE / UTF-16BE |
| 章节识别 | 正则匹配 `第N章/回/节/卷`，中文数字含"万"支持大章节号 |
| 输出编码 | 统一 UTF-8 无 BOM |
| 序号自适应 | 文件数超当前位数容量时自动扩展（3位→4位→...） |
| 旧文件清理 | 写入前自动清理输出目录中的旧 .txt 文件 |
| 余数补齐 | 聚合拆分时不足总章数自动追加余数文件 |
| 错误捕获 | 写入循环包裹 On Error，出错时报告具体文件名 |
| 计时报告 | 完成后显示计时明细：选择/读取/识别/写入/总计 |
| 仅有标题处理 | 仅有标题/正文不足的章节默认跳过不生成文件，可开关控制 |
| 最小正文字数 | 可指定正文字数阈值，正文少于该值的章节也跳过 |
| 清洁模式 | 跳过正文汉字<N的章节，可选合并保留章节(>=N)或跳过章节(<N) |

## 4. 使用方法

### 4.1 VBA 版

**安装：** 复制 `split_txt.bas` 全部内容，粘贴到 WPS/Excel/Word 的 VBA 编辑器（Alt+F11）的模块中。

**运行：** 执行 `拆分TXT` 宏。

**流程：**

```
选择TXT文件 → 选择拆分模式 → [仅有标题处理] / [输入聚合格式] / [输入清理参数] → 生成文件
```

1. 文件选择对话框（仅显示 .txt 文件）
2. 模式选择对话框：
   - **[是]** 按章节一一拆分 → 仅有标题处理选择 → 生成
   - **[否]** 聚合拆分 → 输入聚合格式 → 预览确认 → 生成
   - **[取消]** 清洁模式 → 输入 `N,flag` 参数 → 生成
3. 章节内容处理选择（仅按章节拆分时出现）：
   - **[否]**（默认）跳过仅有标题无正文的章节
   - **[是]** 生成所有章节（含仅有标题/正文不足）
4. 清洁模式（[取消] 时进入）：
   - 输入 `N,flag`：正文汉字 < N 的章节跳过
   - `flag=1`（默认）：合并保留章节（>= N）→ `保留大于等于N_小说名.txt`
   - `flag=0`：合并跳过章节（< N）→ `清理小于N_小说名.txt`
   - 合并文件首部列出跳过明细（跳过数、明细、前三正文字数、保留数）

### 4.2 Python 版

**运行：** 命令行执行，无需安装（Python 3 标准库即可）。

```bash
# 按章节一一拆分（每章一个文件，跳过仅有标题章节）
python split_txt.py --src 红楼梦.txt

# 按章节一一拆分（包含仅有标题/正文不足的章节）
python split_txt.py --src 红楼梦.txt --keep-title-only

# 按章节一一拆分（正文汉字少于50字的章节也跳过）
python split_txt.py --src 红楼梦.txt --min-body-len 50

# 清洁模式：跳过正文<N字的章节，合并保留章节(>=N)
python split_txt.py --src 红楼梦.txt --clean 100
python split_txt.py --src 红楼梦.txt --clean 100,1

# 清洁模式：合并跳过章节(<N)，用于确认问题
python split_txt.py --src 红楼梦.txt --clean 100,0

# 聚合拆分（默认 40,3）
python split_txt.py --src 红楼梦.txt --mode groups

# 聚合拆分（指定格式）
python split_txt.py --src 红楼梦.txt --mode groups --chunk "20,1|20,1|80,1"

# 便捷：传 --chunk 自动切换为 groups 模式
python split_txt.py --src 红楼梦.txt --chunk 40,3

# 仅检测文件编码（不拆分）
python split_txt.py --detect 红楼梦.txt
```

**参数说明：**

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `--src` | 是 | — | 源 TXT 文件路径 |
| `--mode` | 否 | `chapter` | 拆分模式：`chapter`=每章一文件，`groups`=聚合拆分 |
| `--out` | 否 | 自动派生 | 输出目录（空=源目录下 `<文件名>_拆分` 或 `_分组`） |
| `--chunk` | 否 | `40,3` | 聚合格式，传入时自动切换为 groups 模式 |
| `--prefix` | 否 | 空 | 文件名前缀 |
| `--serial-width` | 否 | 3 | 序号位数（文件数超容量时自动扩展） |
| `--encoding` | 否 | 自动检测 | 手动指定源文件编码（如 `gbk`/`big5`/`utf-8`），跳过自动检测 |
| `--detect` | 否 | — | 仅检测编码（不拆分），后跟文件路径 |
| `--keep-title-only` | 否 | `False` | 生成仅有标题/正文不足的章节文件（默认跳过） |
| `--min-body-len` | 否 | `0` | 最小正文汉字数(0=不检测)，正文汉字少于该值的章节跳过 |
| `--clean` | 否 | — | 清洁模式 `N[,flag]`：跳过正文汉字<N的章节；flag=1(默认)合并保留章节(>=N)，flag=0合并跳过章节(<N) |

**编码说明：**

```bash
# 自动检测编码（默认）
python split_txt.py --src 红楼梦.txt

# 手动指定编码（解决乱码问题）
python split_txt.py --src 红楼梦.txt --encoding gbk
python split_txt.py --src 红楼梦.txt --encoding big5
python split_txt.py --src 红楼梦.txt --encoding gb18030
```

自动检测失败时会报错并提示使用 `--encoding` 参数。VBA 版会在完成报告中显示检测到的编码（如 `ANSI → UTF-8`），便于确认。

**可选依赖：**

```bash
pip install charset-normalizer
```

安装后编码检测精度提升；未安装时自动降级为内置字节模式扫描。

**流程：**

```
选择TXT文件 → 选择拆分模式 → [章节内容处理] / [输入聚合格式] / [输入清理参数] → 生成文件
```

1. 文件选择对话框（FileDialog / GetOpenFilename / InputBox 三级降级）
2. 模式选择对话框（与VBA一致）：
   - **[是]** 按章节一一拆分 → 仅有标题处理选择 → 生成
   - **[否]** 聚合拆分 → 输入聚合格式 → 预览确认 → 生成

**技术特点：**

| 项目 | 实现方式 |
|------|----------|

| 调试日志 | `debugLog()` 安全包装（兼容无 console 环境） |
| 计时 | `Date.now() / 1000` |
| 文件选择 | `FileDialog` → `GetOpenFilename` → `InputBox` 三级降级 |

## 5. 聚合格式详解

### 格式语法

| 格式 | 含义 | 示例（120章） |
|------|------|----------------|
| `N` | 便捷模式：每 N 章一份 | `40` → 3份（1-40, 41-80, 81-120） |
| `a,b` | 单段：每份 a 章，共 b 份 | `40,3` → 3份各40章 |
| `a,b\|c,d\|...` | 多段：各段顺序聚合 | `20,1\|20,1\|80,1` → 3份（1-20, 21-40, 41-120） |

### 余数补齐

当总消耗章数不足总章数时，自动追加一个余数文件：

```
输入: 40,2    总章数: 120
消耗: 40×2 = 80
余数: 120-80 = 40
结果: 3份 → 001_第1-40章.txt, 002_第41-80章.txt, 003_第81-120章.txt
```

## 6. 命名规则

### 按章节拆分

```
<序号补零>_<章节字数>_<完整章节标题>.txt
```

- **序号补零**：基于实际生成文件的顺序连续编号（001, 002, ...），位数自适应
- **章节字数**：统计该章全部字符（含标题行、正文、标点、换行符等全部数据），不用正则过滤汉字；位数自适应（按最大字数确定位数，零填充对齐）
- **完整章节标题**：取自章节行的完整匹配行（含"第N回"前缀），半角空格转全角
- 示例：`001_06928_第1章　甄士隐梦幻识通灵　贾雨村风尘怀闺秀.txt`

### 聚合拆分

```
<序号补零>_第<起>-<止><单位>.txt
```

- 单位自动检测（章/回/节/卷），取首个匹配章节的单位词
- 示例：`001_第1-40章.txt`

### 清洁模式合并文件

```
flag=1: 保留大于等于<N>_<小说名>.txt     （包含正文汉字 >= N 的章节）
flag=0: 清理小于<N>_<小说名>.txt          （包含正文汉字 < N 的章节）
```

- 合并文件首部包含清理报告：跳过数、跳过明细（标题+字数）、前三正文字数、保留数
- 示例：`保留大于等于5000_红楼梦.txt`、`清理小于5000_红楼梦.txt`

### 带前缀

```
<前缀>_<序号补零>_<章节字数>_<完整章节标题>.txt（按章节拆分）
<前缀>_<序号补零>_第<起>-<止><单位>.txt（聚合拆分）
```

- 示例：`红楼梦_001_06928_第1章　甄士隐梦幻识通灵.txt`

### 文件名清洗

- 半角空格 → 全角空格 `　`
- 非法字符 `\ / : * ? " < > |` → 全角空格
- 连续全角空格折叠为单个
- 长度限制 60 字符

## 7. 核心逻辑

### 7.1 编码检测（三层策略）

```
第1层: BOM 快速检测（确定性100%）
  FF FE → UTF-16LE
  FE FF → UTF-16BE
  EF BB BF → UTF-8 BOM

第2层: 字节模式扫描（VBA）/ charset-normalizer 统计分析（Python）
  扫描高位字节，检查是否符合 UTF-8 多字节序列模式
  符合 → UTF-8
  不符合 → ANSI(GBK)

第3层: 全 ASCII → ANSI（纯英文文件两者兼容）
```

### 7.2 章节识别正则

```
^第([0-9一二三四五六七八九十百千万零两]+)(章|回|节|卷)(\s*)(.*)$
```

- 数字部分支持阿拉伯数字和中文数字（含"万"）
- 单位词支持 章/回/节/卷
- 标题部分为第4捕获组，空标题时回退为"第N章"

### 7.3 处理流程

```
读取源文件 → 检测编码 → 归一化行结束符(vbLf/\n)
    ↓
扫描章节起点 → 计算每章行范围
    ↓
确定输出目录 → 清理旧文件
    ↓
循环写入文件（UTF-8 无BOM）
    ↓
完成报告（文件数 + 计时明细：选择/读取/识别/写入/总计）
```

### 7.4 输出目录派生

| 模式 | 派生规则 | 示例 |
|------|----------|------|
| 按章节拆分 | `<源目录>\<文件名>_拆分\` | `红楼梦_拆分\` |
| 聚合拆分 | `<源目录>\<文件名>_分组\` | `红楼梦_分组\` |

### 7.5 不足章节处理

某些 TXT 文件中可能存在仅有标题行而无正文的章节，或正文内容极短的章节。工具对此的处理：

| 状态 | 行为 |
|------|------|
| 开关关闭（默认） | 不足章节**不生成文件**，序号连续编号（001, 002, 003...，无跳号），完成后提示跳过数量及分类 |
| 开关打开 | 不足章节**正常生成文件**，完成后提示不足章节数量及分类 |

**不足章节的两种类型：**

| 类型 | 判断条件 | 说明 |
|------|----------|------|
| 仅有标题 | `n_lines == 1`（仅含标题行，无正文行） | 下一章标题紧跟当前章标题 |
| 正文不足 | 正文汉字数 < `min_body_len` | 有正文但汉字太少（仅当指定阈值时检测） |

**汉字计数规则：** 正文字数仅统计汉字（`\u4e00`-`\u9fff`），标点符号、数字、字母、空白等均不计入。

**三种控制方式：**

| 方式 | VBA | Python | 行为 |
|------|-----|--------|------|
| 默认跳过 | 对话框选 [否] | 默认（不加参数） | 仅跳过仅有标题章节 |
| 全部生成 | 对话框选 [是] | `--keep-title-only` | 生成所有章节（含不足章节） |
| 自定义阈值 | 清洁模式 `N,flag` | `--clean N[,flag]` | 跳过正文汉字 < N 的章节（含仅有标题），可选合并保留/跳过章节 |

**优先级：** `--keep-title-only`（全部生成）优先于 `--min-body-len`（自定义阈值）。同时指定时全部生成。

**序号说明：** 跳过不足章节时，序号基于实际生成文件的顺序连续编号（001, 002, 003...），无跳号。

## 8. 优化过程

### 8.1 Bug 修复

| 问题 | 原因 | 修复方案 |
|------|------|----------|
| 一一拆分无法运行 | `vbYesCancel` 非 VBA 有效常量，被当作空值(0)处理，等价于 `vbOKOnly`，用户点确定后 `vbOK(1) <> vbYes(6)` 导致直接退出 | 改为 `vbYesNo` |
| 大量文件清理报错 | `CleanOutputDir` 使用 `Dir`+`Kill` 循环，`Kill` 后 `Dir()` 内部状态被破坏，文件数多时跳过文件或报错 | 改用 `fso.GetFolder` + `For Each file` + `file.Delete` |
| 行结束符不一致 | `SplitByChapter` 用 `vbCrLf` 拼接，内容已归一化为 `vbLf`，导致输出文件行结束符混乱 | 统一使用 `vbLf` |
| COM 对象泄漏 | `ADODB.Stream` 用后未 `Set Nothing`，120次循环累积资源 | 所有 COM 对象用后显式 `Set Nothing` |
| ANSI 文件读取报 Error 62 | `Open...For Input` 文本模式将 `0x1A`(Ctrl+Z/DOS EOF) 解释为文件尾；`LOF()` 返回实际文件大小，但 `Input()` 只能读到 `0x1A` 位置，两者不匹配导致"输入超出文件尾" | 改用 `ReadFileBytes`(Binary 模式) + `StrConv(bytes, vbUnicode)` 转换，完全绕过 `0x1A` 解释 |
| Python 编码丢失数据 | `read_text_auto` 最终用 `errors="replace"` 将无法解码的字节替换为 �(U+FFFD)，用户无感知地丢失数据；`latin-1` 兜底可"解码"任何字节但结果全错 | 改用 `errors="strict"`，解码失败时报错并提示 `--encoding` 参数；删除 `latin-1` 兜底 |
| Python `if prefix:` 缩进错误 | 编辑文件名拼接时丢失了 `if` 块内的缩进，导致 `IndentationError` | 恢复正确的 8 空格缩进 |

### 8.2 死代码清理

| 删除项 | 文件 | 原因 |
|--------|------|------|
| `WriteTextANSI` | VBA | 全局零调用，输出始终用 `WriteTextUTF8NoBOM` |
| `WriteTextUTF8BOM` | VBA | 同上 |
| `write_text_ansi` | Python | 同上 |
| `write_text_utf8_bom` | Python | 同上 |

### 8.3 性能优化

| 优化项 | 修改前 | 修改后 | 效果 |
|--------|--------|--------|------|
| `ReadTextANSI` | 逐行 `Line Input` + 字符串拼接 | `ReadFileBytes` + `StrConv` 一次性读取 | O(n²) → O(n)，减少2个变量 |
| `SanitizeFileName` | 10 个独立 `Replace` 调用 | 1 个 `Replace` + 循环遍历 | 10行→4行，与 Python 对齐 |
| Python `_BOM_MAP` | 含 UTF-7 BOM 条目 | 删除 UTF-7 | 与 VBA 对齐，UTF-7 极罕见 |

### 8.4 健壮性增强

| 增强项 | 说明 |
|--------|------|
| 写入循环 `On Error` | 出错时报告具体文件名和错误信息，而非通用 VBA 错误对话框 |
| 文件选择过滤 | 仅显示 .txt 文件，移除"所有文件"过滤项 |
| `SplitByChapter` 参数 | 补齐 `ByVal`，与 `SplitByGroups` 一致 |
| 头注释修正 | "写入前预览并经用户确认" → "聚合拆分写入前预览确认"（一一拆分已删除预览步骤） |
| Python `--encoding` 参数 | 手动指定源文件编码（如 `gbk`/`big5`），跳过自动检测，解决乱码问题 |
| VBA 编码显示 | 完成报告中显示 `源文件编码：UTF-8 → UTF-8`，便于用户确认 |
| Python 解码严格模式 | `errors="strict"` 替代 `errors="replace"`，解码失败时报错而非静默丢数据 |
| 空文件处理 | `ReadTextANSI` 检查 `UBound < 0`，空文件返回空串而非报错 |

### 8.5 计时系统

| 计时项 | VBA | Python | 说明 |
|--------|-----|--------|------|
| 文件选择 | 有（`g_tSelect`） | — | VBA 文件对话框耗时（Python 无此阶段） |
| 读取文件 | 有（`tRead0`/`tRead1`） | 有（`time.time()`） | 编码检测 + 文件读取 + 行归一化 |
| 识别章节 | 有（`tScan0`/`tScan1`） | 有 | 正则扫描全部行 |
| 写入文件 | 有（`t0`/`t1`） | 有 | 循环写入 + UTF-8 编码 |
| 总计耗时 | 有（`g_tTotal0`） | 有 | 从函数入口到报告显示 |

VBA 使用模块级全局变量 `g_tSelect`/`g_tTotal0`/`g_detectedEnc` 传递计时和编码信息，支持从 `拆分TXT` 入口和直接调用 `SplitByChapter`/`SplitByGroups` 两种方式。

### 8.6 命名格式演进

| 版本 | 按章节拆分 | 聚合拆分 |
|------|------------|----------|
| 初版 | `001 标题.txt`（仅标题部分，空格分隔） | `001_第1-40章.txt` |

## 11. 思考过程

### 11.1 清洁模式的设计演进

**初版：MergeKept(Boolean) — 单方向合并**

最初清洁模式仅支持一种合并方向：将保留章节（正文汉字 >= N）合并为一个文件。使用 `MergeKept As Boolean` 控制：
- `True`：合并保留章节 → `清理小于N_小说名.txt`
- `False`：不合并

**问题：** 用户反馈需要"确认问题"——即查看被跳过的短章节内容，判断是否需要调整阈值。单方向合并无法满足这一需求。

**改进版：MergeFlag(Long) — 双方向合并**

将 `MergeKept(Boolean)` 升级为 `MergeFlag(Long)`，支持三态：
- `-1`：不合并（默认，对应普通拆分）
- `0`：合并跳过章节（< N）→ `清理小于N_小说名.txt`（确定问题）
- `1`：合并保留章节（>= N）→ `保留大于等于N_小说名.txt`（得到需要章节）

**设计决策：** flag 值沿用用户的输入习惯（`N,0` / `N,1`），内部映射为 `-1/0/1` 三态。`-1` 作为"不合并"的哨兵值，避免与用户输入的 `0` 冲突。

### 11.2 VBA 对话框重构思路

**旧结构（三层嵌套）：**
```
拆分TXT → [是/否/取消]
  [是] → 一一拆分 → [是/否/取消]
    [取消] → 自定义最小正文字数 → [是/否] 合并文件？
  [否] → 聚合拆分
  [取消] → 退出
```

**问题：** 清洁模式藏在第三层子对话框中，入口隐蔽；[取消] 在主对话框中仅用于退出，浪费按钮资源。

**新结构（两层扁平化）：**
```
拆分TXT → [是/否/取消]
  [是] → 一一拆分 → [是/否]（简化，移除第三选项）
  [否] → 聚合拆分
  [取消] → 清洁模式 → InputBox "N,flag"
```

**设计决策：**
1. [取消] 从"退出"改为"清洁模式"，使三种模式在同一层级可选
2. 一一拆分子对话框从三选项（是/否/取消）简化为二选项（是/否），移除了原来通过[取消]进入清洁模式的路径
3. 清洁模式通过 InputBox 一次性输入 `N,flag`，替代旧版的多步对话框（先输入N，再确认是否合并）

### 11.3 双方向合并的命名语义

| flag | 合并内容 | 文件名前缀 | 语义 |
|------|----------|------------|------|
| 0 | 跳过章节（< N） | `清理小于N_` | "清理"= 被移除的内容 |
| 1 | 保留章节（>= N） | `保留大于等于N_` | "保留"= 被保留的内容 |

**设计决策：** 旧版对保留章节使用 `清理小于N_` 前缀（意为"清理小于N之后的结果"），但语义模糊。新版改为 `保留大于等于N_`，直接表明文件内容。跳过章节使用 `清理小于N_`，表示这些是被清理掉的章节。

### 11.4 合并文件头部设计

头部信息分两部分：**清理报告**（两种 flag 共享）+ **本文件内容**（区分 flag）。

```
==================================================
清理说明：正文中文字数小于 N 的章节已跳过       ← 共享：清理操作描述
跳过章节：X 个                                   ← 共享：跳过统计
跳过明细：                                       ← 共享：跳过明细
  第2章 ...（4782字）
  ...
前三正文：4978字、4957字、4944字                 ← 共享：跳过章节的前三字数
保留章节：Y 个                                   ← 共享：保留统计
本文件内容：跳过章节（正文汉字 < N）             ← 区分：flag=0
# 或
本文件内容：保留章节（正文汉字 >= N）            ← 区分：flag=1
==================================================
[章节内容]
```

### 11.5 代码优化决策

**优化1：body 提取前移**

原始代码中，章节完整文本（含标题）的提取出现在两个位置：skip 路径和 kept 路径各一次。优化后提前到循环体开头，一次提取、两处复用：

```python
# 优化前：body 在两个分支中各提取一次
if is_insufficient and not generate_title_only:
    ...
    if merge_flag == 0:
        body = "\n".join(lines[start_line:end_line + 1])  # ← 重复
        skipped_texts.append(body)
    continue
...
body = "\n".join(lines[start_line:end_line + 1])  # ← 重复
write_file(out_dir, fname, body)

# 优化后：提前提取一次，两处复用
body = "\n".join(lines[start_line:end_line + 1])  # ← 仅一次
if is_insufficient and not generate_title_only:
    ...
    if merge_flag == 0:
        skipped_texts.append(body)  # ← 复用
    continue
...
write_file(out_dir, fname, body)  # ← 复用
```

**优化2：合并文件写入统一**

原始代码中，flag=0 和 flag=1 各有一套完整的文件写入逻辑（路径拼接 + 写入 + 打印）。优化后先选择合并文本集合和文件名，再统一写入：

```python
# 优化后：先选择，再统一写入
if merge_flag == 1 and kept_texts:
    merge_texts = kept_texts
    merge_name = "保留大于等于%d_%s.txt" % (min_body_len, src_name)
elif merge_flag == 0 and skipped_texts:
    merge_texts = skipped_texts
    merge_name = "清理小于%d_%s.txt" % (min_body_len, src_name)
else:
    merge_texts = None
if merge_texts:
    # 统一写入逻辑（仅一处）
    with open(merge_path, "w", encoding="utf-8") as f:
        f.write("\n".join(header_lines))
        f.write("\n".join(merge_texts))
```

VBA 端使用 `mergeCol As Collection` 实现相同优化：先 `Set mergeCol = skippedTexts` 或 `Set mergeCol = keptTexts`，再统一 `ReDim + Join + WriteTextUTF8NoBOM`。

**优化3：skip 报告去重**

原始代码中，`parts`（Python）/ `skipDetail`（VBA）的构建在 `skipped_count > 0` 和 `elif` 两个分支中各写一遍。优化后提前到条件判断之前构建一次。

**优化效果：**

| 文件 | 优化前 | 优化后 | 减少 |
|------|--------|--------|------|
| VBA | 965 行 | 952 行 | -13 行 |
| Python | 587 行 | 582 行 | -5 行 |

### 11.6 VBA 与 Python 对齐策略

两端共享相同的参数语义（`MergeFlag = -1/0/1` ↔ `merge_flag = None/0/1`），但在实现细节上保持各语言惯用方式：

| 方面 | VBA | Python |
|------|-----|--------|
| 不合并哨兵 | `MergeFlag = -1`（Long 默认可设） | `merge_flag = None`（Python 惯用 None） |
| 文本收集 | `Collection` 对象 | `list` 列表 |
| 合并文本选择 | `Set mergeCol = skippedTexts` | `merge_texts = skipped_texts` |
| 空集合判断 | `mergeCol Is Nothing` | `if merge_texts:` |
| 头部构建 | 内联字符串拼接 | `_build_clean_header()` 函数 |

Python 端额外提取了 `_build_clean_header()` 公共函数消除头部构建重复；VBA 端因函数调用开销和 Dim 限制，保持内联但通过 `mergeCol` 统一写入路径。

## 12. 从零开始的对话过程

本章按时间线统合整个开发对话，记录从最初需求到最终实现的完整演进路径。与第 11 章（按主题分类的思考过程）互补，本章侧重于"需求如何一步步演进到这里"。

### 12.1 需求起源：清洁模式的提出

**用户需求：** "一一拆分，输入数字100就跳过正则后文字小于100以下的目录。"

**思考过程：**

1. **识别核心需求**：用户希望在按章节拆分时，能够根据正文长度过滤章节——跳过正文字数太少的章节。
2. **设计参数**：需要在 `SplitByChapter` 中增加 `MinBodyLen` 参数，表示最小正文汉字数。
3. **关键决策点——计数规则**：用户提到"正则后文字"，这里需要明确：
   - 是总字符数（含标点、数字、字母）还是仅汉字数？
   - 标题行是否计入？
   - 此时暂未明确，留待用户进一步指定。
4. **实现方案**：在循环中计算每章正文汉字数，小于阈值的章节跳过不生成文件，序号连续编号。

### 12.2 需求演进：合并文件生成

**用户需求：** "如果input 100,1（默认值），就同时生成等于大于100的文本合并项目，txt文本名字，清理小于100_小说名，以及txt首文增加提示 跳过的章节等信息。"

**思考过程：**

1. **需求升级**：从单纯的"过滤"升级为"过滤 + 合并"。不仅要跳过短章节，还要把保留的长章节合并成一个文件。
2. **参数设计**：需要一个控制是否合并的参数。最初设计为 `MergeKept As Boolean`：
   - `True`：合并保留章节
   - `False`：不合并
3. **合并文件命名**：`清理小于100_小说名.txt`——意为"清理掉小于100字的章节后保留的内容"。
4. **合并文件头部**：用户要求"txt首文增加提示 跳过的章节等信息"，需要设计结构化头部：
   - 跳过章节数
   - 跳过明细（标题 + 字数）
   - 保留章节数
5. **思考：头部应该包含什么？** 决定增加"前三正文字数"——即被跳过章节中正文最长的前三个字数，帮助用户判断阈值是否合理。

### 12.3 计数规则明确

**用户需求：** "需要正则只保留汉字，汉字的字符串才计数。"

**思考过程：**

1. **明确计数范围**：仅统计汉字（U+4E00–U+9FFF），标点符号、数字、字母、空白均不计入。
2. **实现方式**：
   - Python：`len(re.sub(r'[^\u4e00-\u9fff]', '', body_text))`
   - VBA：使用 `VBScript.RegExp` 匹配 `[\u4e00-\u9fff]` 并计数
3. **标题行处理**：计数时排除标题行，仅统计正文部分。
4. **这个决策影响后续所有字数判断**，包括 `MinBodyLen` 和清洁模式的 `N` 阈值。

### 12.4 VBA 交互设计：三模式对话框

**用户需求：**

**思考过程：**

2. **从单方向到双方向合并**：
   - 原方案 `MergeKept(Boolean)` 只能控制"合并/不合并"
   - 用户需要 `flag=0`（合并跳过章节）和 `flag=1`（合并保留章节）两个方向
   - Boolean 不足以表达三态，升级为 `MergeFlag(Long)`
3. **三态设计**：
   - `-1`：不合并（默认，对应普通拆分）
   - `0`：合并跳过章节（< N）→ `清理小于N_小说名.txt`（确定问题）
   - `1`：合并保留章节（>= N）→ `保留大于等于N_小说名.txt`（得到需要的章节）
4. **flag 值映射**：用户输入 `N,0` / `N,1`，内部映射为 0/1；`-1` 作为"不合并"的哨兵值，避免与用户输入的 0 冲突。
5. **对话框重构**：
   - 旧版：三层嵌套（主对话框 → 子对话框 → 清洁模式）
   - 新版：两层扁平化（主对话框 → [取消]直接进入清洁模式 → InputBox 输入 `N,flag`）

问题：flag=0 和 flag=1 各有完整的文件写入逻辑（路径拼接 + 写入 + 打印），分支重复。

if merge_flag == 1 and kept_texts:
    merge_texts = kept_texts
    merge_name = "保留大于等于%d_%s.txt" % (min_body_len, src_name)

    merge_texts = skipped_texts
    merge_name = "清理小于%d_%s.txt" % (min_body_len, src_name)
else:
    merge_texts = None
if merge_texts:
    # 统一写入逻辑（仅一处）
    with open(merge_path, "w", encoding="utf-8") as f:
        f.write("\n".join(header_lines))

### 12.9 核心设计决策回顾

**决策 1：MergeFlag 用 Long 而非 Boolean**
- 原因：需要三态（不合并 / 合并跳过 / 合并保留），Boolean 只能两态
- 实现：-1=不合并，0=合并跳过，1=合并保留
- Python 端用 `None` 代替 `-1`，符合 Python 惯用法

**决策 2：flag 值沿用用户输入习惯**
- 用户输入 `N,0` 和 `N,1`，内部映射为 0 和 1
- `-1` 作为"不合并"的哨兵值，避免与用户输入的 0 冲突

**决策 3：合并文件命名语义化**
- flag=0：`清理小于N_小说名.txt`（被清理的内容）
- flag=1：`保留大于等于N_小说名.txt`（被保留的内容）
- 旧版对保留章节用 `清理小于N_` 前缀（语义模糊），新版改进

**决策 4：汉字计数范围**
- 仅统计 U+4E00–U+9FFF（CJK 统一汉字基本区）
- 不含扩展区、标点、数字、字母、空白
- VBA 和 Python 实现一致

**决策 5：VBA 对话框扁平化**
- 旧版：三层嵌套（主对话框 → 子对话框 → 清洁模式）
- 新版：两层扁平化（主对话框 → [取消]直接进入清洁模式）
- 减少用户操作步骤

**决策 6：合并文件头部包含"前三正文字数"**
- 帮助用户判断阈值是否合理
- 如果前三正文字数都接近 N，说明阈值可能偏高
- 如果前三正文字数远小于 N，说明跳过的确实是短章节

**决策 7：文件名章节字数统计全部字符（非仅汉字）**
- 用户需求："不用正则只统计汉字，需要统计全部数据"
- 与清洁模式的汉字计数（`re.sub` 过滤非汉字）区分：文件名字数统计 `len(body)`，包含标题行、正文、标点、换行符等全部字符
- 位数按全部章节的最大字数自适应（如最大11977字→5位），零填充使所有文件名字数部分长度一致
- 预计算在主循环前完成，基于全部章节（含跳过章节）确定宽度，确保清洁模式下字数位数仍一致
