## 3. 三种调用模式

### 模式 A：续做红楼梦工程（最常用）

给智能体的任务提示词模板（可直接复制）：

```
继续《红楼梦》称呼学解构工程。请按以下步骤：
1. 读 A:\HuaweiMoveData\Users\代\Desktop\JK-temp\语料与文本\四大名著\通用分析\称呼学工作流包\00_INDEX_智能体调用指南.md
2. 读 01_SOP_批次执行手册.md，从工程 README（语料与文本\四大名著\红楼梦\称呼学解构\README：工程总纲与进度.md）
   的批次表确认下一批起点回号；
3. 按 SOP 执行一个批次（4–6 回）：逐回精读底本→用 02 模板生成→跑 03 质检→审计→收敛→提交推送；
4. 单轮会话完成一个批次即收束报告，不要跨批。
```

### 模式 B：移植到其他名著

1. 复制本包整文件夹到目标名著工程旁（或直接在原位引用）；
2. 建工程目录 `<名著>\称呼学解构\`，放一份按 02 模板改头的 README（批次表+纲领+预判题）；
3. 适配四个参数（详见 01_SOP §7）：拆分目录名、名词列锦目录名、关键词表（如三国加"主公/军师/都督/贤弟"、水浒加"哥哥/员外/押司/提辖"）、预判四题（换成该著的全书级问题）；
4. 03 质检脚本用 `-ProjectDir` 参数指向新工程目录即可直接运行（脚本自身不绑定红楼梦）。

### 模式 C：存量审计修复

只做两步：`04_审计扫描脚本.ps1` 扫指定回目 → 对候选句逐条核对底本 → 按 01_SOP §5 的 Nb 规则补全 → 跑 03 质检 → 提交。

## 4. 核心纪律（一句话版，详见 01/06）

1. **引文只从拆分底本复制**——凭记忆复述实测错 20+ 处；
2. **质检退出码 0 才能 commit**——pre-commit 已硬挂；
3. **三处计数一致**：§0 声明＝§1 表行数（含 Nb）＝尾注计数；
4. **底本异文照录**＋尾注存档，禁止擅自校字；
5. **Nb 编号插入不重排**原编号；
6. **单会话 4–6 回收束**，防上下文衰减；
7. 理论回指不展开：只写"件号+定律号"（体系 11 篇见 `通用分析\通用模板库\释义方法\称呼学\`）。
