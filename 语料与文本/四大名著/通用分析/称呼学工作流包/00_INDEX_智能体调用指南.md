## 4. 三种调用模式

### 模式 A：续做红楼梦工程（最常用）

```
继续《红楼梦》称呼学解构工程。请按以下步骤：
1. 读 ……\通用分析\称呼学工作流包\00_INDEX_智能体调用指南.md；
2. 读 ……\通用分析\称呼学整合版工作流包\04_整合版方法论.md 与 05_称呼归属核验与防错清单.md；
3. 读本包 01_SOP_批次执行手册.md，从工程 README 的批次表确认下一批起点回号；
4. 按 SOP 执行一个批次（4–6 回）：逐回精读底本→用 02 模板生成→过 05 归属门→跑 03 质检→04 审计→收敛→提交推送；
5. 单轮会话完成一个批次即收束报告，不要跨批。
```

### 模式 B：移植到其他名著

1. 复制本包与整合版包到目标名著工程旁（或原位引用）；
2. 建工程目录 `<名著>\称呼学解构\`，按 02 模板改头的 README（批次表＋纲领＋预判题）；
3. 适配四个参数（详见 01_SOP §7）：拆分目录名、名词列锦目录名、关键词表、预判四题；
4. 03 质检脚本用 `-ProjectDir` 指向新工程目录即可；05 的五类错误与四步法与名著无关，可直接复用，只需替换实例表。

### 模式 C：存量审计修复

`04_审计扫描脚本.ps1` 扫指定回目 → 对候选句逐条核对底本 → **按 05 清单核归属** → 按 01_SOP §5 的 Nb 规则补全 → 跑 03 质检 → 提交。

## 5. 核心纪律（一句话版）

1. **引文只从拆分底本复制**——凭记忆复述实测错 20+ 处；
2. **引文命中底本 ≠ 归属正确**——每条"谁称谁"另过 05 清单；
3. **质检退出码 0 才能 commit**——pre-commit 已硬挂；
4. **三处计数一致**：§0 声明＝§1 表行（含 Nb）＝尾注；
5. **底本异文照录**＋尾注存档，禁止擅自校字；
6. **Nb 编号插入不重排**原编号；
7. **单会话 4–6 回收束**，防上下文衰减；
8. 理论回指不展开：只写"件号＋定律号"（体系见 `通用分析\通用模板库\释义方法\称呼学\`）。
