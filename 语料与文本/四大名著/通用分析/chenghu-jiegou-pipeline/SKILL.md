# 称呼学解构（整合版）· 全书流水线

把一部章回小说的**全部回目**逐回生成为整合版称呼学解构稿，并做到引文逐字锚定、结构计数守恒、全书零缺号。理论框架（十问／四层十二件／双公式／26 定律）跨书复用，只有目录、回数、预判四题需要按书适配。

## 适用条件与产物

| 项 | 要求 |
| :--- | :--- |
| 输入 | 拆分底本目录：一回一文件，文件名以三位数字开头（`NNN_字数_第N回　上句　下句.txt`）；可选参考坐标目录 `名词列锦章节/NNN_第N回.md` |
| 输出 | `<书目录>/称呼学解构/整合版可查/NNN_第N回_上句.md` × 全部回数，另加 `README：整合版规格与进度.md` |
| 配置 | `<书目录>/chenghu.config.json`（由 `init` 生成，是全部脚本的唯一参数源） |
| 不适用 | 无逐回拆分底本的书；只需单篇分析时只用 `check` 子命令即可 |

## 三条红线（违反即返工）

1. **「」只放本回底本连续逐字原文**：不漏中间短句、动作词与语气词一致、不把并列／节选词塞进同一个「」、跨回一律转述。
2. **锚定通过 ≠ 归属正确**：每条「谁称谁」另过归属门（施称者／受称者／引语三格）。质检脚本只证明句子存在，不证明说话人正确。
3. **执行单元只改指定回次文件**：不改 README、不跑全局质检、不碰范围外稿件；批量结束后复核修改时间与「」计数，防子代理回归改写。

## 快速开始

以下命令中的 `P` 指 `~/.workbuddy/skills/chenghu-jiegou-pipeline/scripts/pipeline.py`。

```bash
# 0 探查并生成配置、简报、输出目录（回数以底本实际数为准）
python P init --root "<工作区根>" --book "<书名>" --book-dir "<书目录>" \
              --split-dir "<拆分目录名>" --chapters <声明回数>

# 1 列出「底本 → 稿件」映射与每 5 回的单元划分
python P plan  --config "<书目录>/chenghu.config.json" --batch 5

# 2 单篇成稿门禁
python P check --config "<…>/chenghu.config.json" "<稿件.md>"

# 3 全书质检 + 进度表
python P qc     --config "<…>/chenghu.config.json"
python P readme --config "<…>/chenghu.config.json"
```

## 阶段 0　探查与适配

1. **先数底本**：以 `*.txt` 实际数量为准，不照抄上一部书的回数。既有工程曾把 120 回误按 100 回推进、漏做尾部 20 回；`init` 在声明数与实际数不符时自动按实际值写入配置并打印提示。
2. 确认拆分目录名、坐标目录名、回目中文数字格式、输出目录位置；记录到 config。
3. 设计**预判四题**（该著独有的四条称谓主线），填入 `config.themes`；设计法见 `references/orchestration.md` §1。
4. 执行 `init`：生成 `chenghu.config.json`、`称呼学解构/批次执行简报.md`（由 `assets/brief_template.md` 实例化）、输出目录。
5. 执行 `plan`，核对「底本总数 = 配置回数 = 计划篇数」，并确认输出文件命名与样板一致。

## 阶段 1　样板回（批量前必须完成）

按 `references/spec.md` 的 A→H 流程做第 1 回：

1. 精读本回底本**全文至回末**，不抽样。
2. 读本回名词列锦作检索坐标。
3. **A5 引文预截**：先把计划引用的全部连续原句原封不动拷出，再动笔写分析（这是防未锚定的根）。
4. 按 `assets/skeleton.md` 六节骨架成文，指标见下方硬规格表。
5. 过归属门，全文搜「」逐条核。
6. `check` 单篇至未锚定 0 且无 ERROR；再跑一次 `qc` 验证头标能被识别。
7. 样板定稿后再批量；样板是后续所有执行单元的唯一笔法与密度标准。

## 阶段 2　批次划分

`plan --batch 5` 输出每个单元的回次区间与文件映射。把映射**原样贴进子代理 prompt**，不要凭记忆写文件名。补做时用 `--missing-only` 只列缺口。

## 阶段 3　并行执行单元

1. 每个单元一个子代理，prompt 用 `references/orchestration.md` §2 模板；单元内必须包含「必读文件、文件映射、硬指标、尾注要求、只改指定回次、不跑全局质检、收尾报告」七项。
2. 每回写完立刻跑 `check`，未锚定 0 才落盘下一回。
3. 单元异常或返回空输出时，**先核查哪些回已落盘**，再只补做缺失回；不要整批重做。
4. 涉及敏感情节的回目，子代理可能拒绝，编排层亲自精读底本并按同一规格撰写。
5. 每批完成后跑一次 `qc` 做阶段验收，再启动下一批。

## 阶段 4　全局质检与修复

执行 `qc --config`。通过条件四项同时成立：退出码 0、未锚定 0、篇数等于配置回数、无缺号无重号。按 `[FAIL]` 逐篇修复后重跑；`[WARN]`（字符不足、英文残留、「」越界、定律行数、头标系列标注）虽不阻断退出码，交付前仍须人工清零。

典型故障与处置见 `references/orchestration.md` §3（尾注缺失、事件表缺行、整节漏写、引文并列、回数偏差、单元中断、并发假报等）。

## 阶段 5　归档与交付

1. `readme --config` 生成全书统计表、批次表、预判四题与适配参数。
2. 追加工作日志到工作区 `.workbuddy/memory/YYYY-MM-DD.md`（记录书目、篇数、指标、修复项）。
3. 用 `present_files` 呈现 README 与首回、末回等代表性文件。
4. 未经用户明确说「同步／提交」，不 commit、不 push。

## 硬规格表

| 项 | 规格 |
| :--- | :--- |
| 单篇字符 | ≥ 15,700（含空白），目标 15,700–17,000 |
| 称呼事件 | 12 件；§1 表 12 行，`\| 1 \|`…`\| 12 \|` 连续无缺号；§0 声明数＝表行数＝尾注数 |
| 重点解构 | `###` 恰 3 段；声明「重点解构 3 段」 |
| 定律表 | 55–72 行，表头 `\| 定律 / 命中（编号） \| 本回证据 \|` |
| 引文「」 | 185–215 处，全部逐字锚定本回底本或本回列锦 |
| 六节 | `## 0.` … `## 5.` 一节不缺 |
| 头标 | `# 《书名》第N回　上句　下句　称呼学解构（整合版）`；系列标注 `(N/总回数)`，允许全角括号；含「拆分底本」字样与【A】锚 |
| 尾注 | 「（注：…）」块 + 独立末行 `> AI生成` |
| 语言 | 全文简体中文，严禁中英混用（模板固定标签 WHO／STANCE／MOOD／CHANNEL／LEXEME／BCC／handicap／To／CC 除外） |
| 一句话 | 指出核心矛盾 + 两个相反动作，落到称谓系统动作（授予／剥夺／冒用／定价／失信／收编／复名），与前后回递进 |

## 脚本子命令索引

| 命令 | 作用 | 关键参数 |
| :--- | :--- | :--- |
| `init` | 探查底本、校正回数、生成 config／简报／输出目录 | `--root --book --book-dir --split-dir --chapters` |
| `plan` | 底本→稿件映射、批次划分、缺口清单 | `--batch --from-chapter --to-chapter --missing-only` |
| `check` | 单篇六节／计数守恒／引文锚定／密度／英文残留 | `<file.md>` 或 `--all` |
| `qc` | 全书完整性 + 五维质检 + 汇总 | `--config` |
| `readme` | 生成 README 统计表与批次表 | `--config` |

所有脚本路径由 config 决定，无书目硬编码；`check`／`qc` 的码点归一化与既有工程 PowerShell 质检脚本 v2.1 完全一致，结果可直接互认。
