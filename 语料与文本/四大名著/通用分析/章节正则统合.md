## 3. splittxt2 九套预设（VBA 多正则版）

**来源**：./splittxt2/split_txt.bas `InitRegexPatterns()`（L73-138）。**此为事实源**。

> ⚠ 文档滞后提示：./splittxt2/使用说明.md §4.1 表格为旧版（`\s*`/`(.*)$` 松散尾部、无行首容错、字符类缺 `○/億/兩`），代码已全面升级为「终极数字字符类 + 行首容错 + 单位后必须有空白」。下表以代码为准。

| 序号 | 名称 | 正则表达式 | unitGroupIdx | 默认单位 |
|------|------|------------|--------------|----------|
| 1 | 标准中文 | `^[ \t　]*第([0-9０-９一二三四五六七八九十百千万亿億零〇○两兩壹貳贰叁參肆伍陸陆柒捌玖拾佰仟廿卅卌皕萬]+)(章\|回\|节\|卷)(?:[ \t　]+(.*))?$` | 1 | 章 |
| 2 | 纯阿拉伯数字 | `^[ \t　]*第([0-9０-９]+)(章\|回\|节\|卷)(?:[ \t　]+(.*))?$` | 1 | 章 |
| 3 | 英文Chapter | `^[ \t　]*[Cc]hapter\s+([0-9０-９]+)(?:[ \t　]*[:\.\-]?[ \t　]+(.*))?$` | -1 | Chapter |
| 4 | 序章/楔子/番外 | `^[ \t　]*(序章\|楔子\|尾声\|番外\|引子\|后记\|终章\|序言\|前言)(?:[ \t　]+(.*))?$` | -1 | 章 |
| 5 | 数字+标题（无"第"） | `^[ \t　]*([0-9０-９]+)(章\|回\|节\|卷)(?:[ \t　]+(.*))?$` | 1 | 章 |
| 6 | 精简中文 | `^[ \t　]*第([零〇○一二三四五六七八九十百千两兩]{1,7})(章\|节)(?:[ \t　]+(.*))?$` | 1 | 章 |
| 7 | 宽松匹配 | `^[ \t　]*第(.+?)(章\|回\|节\|卷)(?:[ \t　]+(.*))?$` | 1 | 章 |
| 8 | 纯数字起始 | `^[ \t　]*([0-9０-９]{3,4})(?:[ \t　]+(.*))?$` | -1 | 章 |
| 9 | 自定义 | 用户输入 | -1 | 章（聚合时询问） |

捕获组约定：`1=序号`、`2=单位词`（`unitGroupIdx` 指其 SubMatches 下标，`-1` 表示无单位组）；标题取整行 `m(0).Value`（不依赖捕获组）。尾部 `(?:[ \t　]+(.*))?$` 表示**单位后接内容必须有空白**，防正文「第四回中…」误判（同 ColorTxt 收紧策略）。

### 5.1 内置三条

| 规则 id | 正则表达式 | 默认启用 |
|---------|-----------|----------|
| builtin-main 主规则 | `^\s*(第[零一二三四五六七八九十百千万亿億两兩〇○壹貳贰叁參肆伍陸陆柒捌玖拾佰仟廿卅卌皕萬0-9０-９]{1,12}[章回卷节集部篇])(?:\s+(.{1,40}))?\s*$` | 是 |
| builtin-alt 特殊章节 | `^\s*(目录\|序章\|楔子\|引子\|尾声\|后记\|番外\|完结感言)(?:\s+(.{1,40}))?\s*$` | 是 |
| builtin-num-ordered 数字顿号 | `^\s*([0-9０-９]+、)\s*(.{0,40})\s*$` | 否 |

主规则数字字符类（终极版，与 splittxt2 同源）：


## 6. 废弃版本（宽松版，已自动升级）

**来源**：renderer/src/chapter.ts `SUPERSEDED_BUILTIN_PATTERNS`（L306-337）。旧版持久化数据加载时静默升级为新版，用户手改过的规则不动。

| 规则 | 废弃旧式（宽松） | 现行新式（收紧） |
|------|------------------|------------------|
| main | `^\s*(第[…]{1,12}[章回卷节集部篇])\s*(.{0,40})\s*$` | `(?:\s+(.{1,40}))?` |
| alt | `^\s*(目录\|序章\|…\|完结感言)\s*(.{0,40})\s*$` | 同上收紧 |
| st2 各条 | `...\s*(.*)$` / `...(.*)$` | `(?:\s+(.*))?\s*$` |

**收紧的核心规则（防误判关键）**：

```
副标题前必须有至少一个空白：(?:\s+(.{1,40}))?
```

| 输入 | 宽松旧版 | 收紧新版 |
|------|---------|---------|
| `第一章 你好` | ✓ 误判风险低 | ✓ 命中 |
| `第一章` | ✓ | ✓（纯序号行仍命中） |
| `第一章你好` | ✗ 误判为章节 | ✗ 正确拒绝 |
| `第四回中既将…`（红楼梦正文） | ✗ 误判（123回事故根因） | ✗ 正确拒绝 |

事故背景：红楼梦全书因 `第四回中…`、`第三十八回林…`、`第一一九回中…` 三行零空白匹配，120 回被误判为 123 章。

## 8. 设计要点沉淀

| 要点 | 说明 |
|------|------|
| **跨工具捕获组约定（重要坑）** | splittxt2 的 `([0-9…]+)(章\|回\|节\|卷)` 中 **组1=数字、组2=单位**，标题取整行 `m(0).Value`；彩读 `matchToTitle` 用 **组1+组2 拼标题**。若把 splittxt2 正则直接粘进彩读，标题会变成「一回」「二回」（"第"字与标题丢失）。**彩读必须用组1=完整序号（含第与单位）、组2=副标题 的版本**。⚠ 关键细节：`第` **必须在捕获组1括号内**——`(第[数字]+[章回节卷])`，写在外（`第([数字]+…)`）则组1不含"第"，标题仍会缺"第"字（实测：`一○○回` vs `第一○○回`）。正确写法：`^[ \t　]*(第[数字类]+[章回节卷])(?:[ \t　]+(.*))?$`；或直接启用彩读内置 st2 适配规则 |
| 两套捕获约定 | 工具族：序号/单位/标题；ColorTxt：完整序号 + 副标题 两组。splittxt2 标题取整行 `m(0).Value`，不依赖捕获组 |
| 整行锚定 | 全部为 `^...$` 全行匹配，防止正文内「第…章」句式误判 |
| **行首容错需配尾部约束** | 加行首 `[ \t　]*`（含全角空格）后，**必须**同步把尾部改为「单位后接内容须有空白」`(?:[ \t　]+(.*))?$`，否则正文缩进行「　第四回中…」会被误判（实测 121>120） |
| `\s*` 与 `\s+` 的分界 | 行首行尾用 `\s*`（消化缩进/尾空白）；副标题**前**用 `\s+`（必须有空白才认为是标题） |
| VBA 与 JS 的空白差异 | VBScript `\s` **不含**全角空格 U+3000，须显式写 `[ \t　]`；JS `\s` 含全角空格，写 `\s` 即可 |
| 宽松兜底的代价 | R2-7 / st2-loose 用 `.+?` 可配 `第序章`，但正文中「第…回」句式有风险，仅作最后手段 |
| ○ 与 〇 双收 | `○`（U+25CB 白圈）与 `〇`（U+3007 汉字零）字形相同、编码不同，**常见小说文本混用**，数字字符类应同时包含两者 |
| 全角数字/繁体 | 部分小说全文全角数字（`第１２３章`）、繁体 `億萬兩`、大写 `貳參陸` 均需收入字符类 |
| 升级兼容 | ColorTxt 用 SUPERSEDED 表静默升级旧规则，保留用户自定义；splittxt2 无持久化无此问题 |

## 9. 两种「第N回」写法的优缺点对比

### 9.1 两种写法（同一正则，捕获组不同）

以标准中文（终极字符类）为例，数字类缩写为 `[数]`：

| 方案 | 正则写法 | 组1 | 组2 | 组3 | 标题来源 |
|------|----------|-----|-----|-----|----------|
| **A splittxt2 式** | `第([数]+)(章\|回\|节\|卷)(?:[ \t　]+(.*))?` | `一○○`（纯数字） | `回`（单位） | `破好事…`（副标题） | **整行** `m(0).Value` |
| **B 彩读式** | `(第[数]+[章回节卷])(?:[ \t　]+(.*))?` | `第一○○回`（完整序号） | `破好事…`（副标题） | 无 | **组1 + 组2** |

### 9.2 方案 A（splittxt2）：组1=数字、组2=单位，标题取整行

**优点**

| # | 优点 | 说明 |
|---|------|------|
| A1 | 标题永不丢字 | 标题取整行匹配值，`第`、副标题、中间任何字符天然完整，不依赖捕获组划分 |
| A2 | 数字与单位分离 | 组1 可直接转数字（排序、章号区间计算），组2 独立（聚合文件名"第1-40**章**"用） |
| A3 | 单条正则自解释 | 各语义段各占一组，改一处不影响其他（如只改单位、只改数字） |
| A4 | 与"仅标题"场景兼容 | 纯序号行（`第1章`）无副标题时组2 留空，整行仍完整 |

**缺点**

| # | 缺点 | 说明 |
|---|------|------|
| A5 | 跨工具迁移易丢字 | 若下游按「组1+组2」拼标题（彩读），得到"一回""二回"（`第` 与副标题全丢）——本轮实际踩坑 |
| A6 | 依赖"整行取标题"约定 | 换个工具不取整行，行为立即失效，隐式约定难发现 |
| A7 | 副标题分组松散 | 组3 可含任意内容，若工具对组3有格式要求（如截断 40 字）需另配 |

### 9.3 方案 B（彩读）：组1=完整序号（含第与单位）、组2=副标题

**优点**

| # | 优点 | 说明 |
|---|------|------|
| B1 | 标题=组1+组2 天然完整 | `第` 在组1内，任何按「组1+组2」拼接标题的引擎都直接得到完整标题，**跨工具鲁棒** |
| B2 | 自包含 | 组1 即完整可显示的章节名，无需额外整行上下文 |
| B3 | 与主流引擎习惯一致 | 多数阅读器/工具按「序号组+标题组」设计，迁移成本低 |
| B4 | 天然收窄误判面 | 序号必须"第+数字+单位"连成一组才匹配，正文「第四回中…」因组1内部必须紧连、尾部又要求空白而被拒 |

**缺点**

| # | 缺点 | 说明 |
|---|------|------|
| B5 | 数字、单位耦合 | 组1 混含 `第`/数字/单位，需再拆正则（或二次提取）才能拿纯数字排序/算区间 |
| B6 | 无单位组的格式适配复杂 | 序章/英文 Chapter/纯数字类（组1 无单位）需单独规则，无法复用「单位在组2」的结构 |
| B7 | 副标题缺失时组2 为空 | 纯序号行组1 单独成标题；若工具对空组2 处理不同（如丢弃组1），需验证 |

### 9.4 结论与选型建议

| 场景 | 推荐 | 原因 |
|------|------|------|
| VBA 拆分工具（聚合、按章区间命名） | **A** | 需要纯数字与单位分离做区间计算，整行标题最省心 |
| 彩读等按「组1+组2」拼标题的引擎 | **B** | 组1 自包含完整序号，标题不缺字 |
| 同一正则要同时喂两个工具 | **B + 二次提取** | B 组1 用正则再抠数字（`第([0-9…]+)[章回节卷]`）即可兼顾 A 的数字需求；A 进彩读必丢字，B 是唯一两全解 |

**核心结论**：`第` 在组1内还是外，是"标题完整"的分水岭。**跨工具复用优先 B**（组1=完整序号），数字/单位需要分离时用二次提取，而不是退回 A 造成丢字。

### 9.5 「第」字缺失导致匹配失败的案例与修复逻辑

> 实测环境：PowerShell `[regex]::IsMatch`（.NET 引擎，与 JS/VBA 的字符类语义一致）。`[数]` = 终极数字字符类。

**案例总览表（X=匹配失败，O=匹配成功）**

| 输入行 | 预设1 含第式 `第([数]+)(章\|回...)` | 预设5 无第式 `([数]+)(章\|回...)` | 无"第"无数字 `([数]+[章回节卷])` |
|--------|-----------------------------------|---------------------------------|---------------------------------|
| `第一回　甄士隐…`（正常） | O | X | X |
| `一回　甄士隐…`（**缺第**） | X | O | O |
| `1章　标题`（**缺第+数字**） | X | O | O |
| `章　标题`（**缺第+缺数字**） | X | X | X |
| `第回　标题`（**缺数字**） | X | X | X |
| `第一回中既将…`（正文句式） | X（正确拒绝） | X | X |
| `一○○回　破好事…`（缺第+○写法） | X | O | O |

**结论规律**：
1. **数字类 `+` 至少匹配 1 个字符**：`章　标题`（无数）与 `第回　标题`（无数）在任一版本都失败——这是"至少 1 位"的硬约束；
2. **`第` 字在预设1中是必需字面量**：`一回`、`1章`、`一○○回` 都因缺 `第` 而预设1失败；预设5（无第式）专为此设计，**多选 1,5 或 1+自定义无第式**才能同时覆盖两类文本；
3. **正文句式防御与 `第` 无关**：`第一回中既将…` 因尾部收紧（单位后接内容必须有空白）被拒，任何预设都不会误判。

**修复逻辑（三个层次）**

| 场景 | 修复 | 示例 |
|------|------|------|
| 仅缺 `第`（`一回`、`1章`、`一○○回`） | 用预设5 无第式：`([数]+)(章\|回\|节\|卷)(?:[ \t　]+(.*))?$`，或与预设1 多选 | splittxt2 输入 `1,5` |
| 同时缺 `第` 且缺数字（`章`、`回`） | 无法用正则可靠识别（信息不足以区分正文），**不修复**，提示用户文本格式异常 | — |
| 有 `第` 缺数字（`第回`） | 同上，信息不足，不匹配是正确行为 | — |
| 跨工具（彩读）场景 | 用彩读约定版：`^[ \t　]*(第[数]+[章回节卷])(?:[ \t　]+(.*))?$`，且 `第` 必须在组1内 | 标题完整「第一○○回」 |
| 同时覆盖"带第"与"缺第"两种文本 | splittxt2 多选（预设1+预设5）；彩读同时启用内置 main + st2-num-unit | `1,5` / 勾选两条 |

**设计取舍**：预设1 强约束 `第` 字，换取对正文"第…回"句式的最低误判；预设5 放宽，换取对无 `第` 格式的覆盖。**二者是互补关系而非替代**，多选并列机制正是为此设计（见 §4.3）。
