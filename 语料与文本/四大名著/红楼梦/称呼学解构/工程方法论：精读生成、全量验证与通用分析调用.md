## 1. 精读生成机制：一回 MD 的产出流程

### 1.1 输入与权威分级

| 级 | 来源 | 用途 | 权威性 |
| :--- | :--- | :--- | :--- |
| 底本 | `红楼梦_拆分\NNN_XXXX_第N章　回目.txt` | **唯一引文权威**：所有「」引文逐字从此复制 | 100% |
| 坐标 | `名词列锦章节\NNN_第N章.md` | 参考坐标：C 编号可引〔C〕、词族表辅助检索；**不得作为引文源**（节选不全） | 参考 |
| 常识 | 通行本回目、情节、脂批、谐音判读 | 【B】级背景与后文钩连（须显式标注） | 辅证 |
| 解读 | 本工程展开分析 | 【E】级（呼叫学、通信学、经济学展开） | 产出层 |

### 1.2 六步生成流程

1. **通读全文**：一次读完该回底本（约 5000–9000 字），不在中途动笔——先建全局事件图，再取舍；
2. **选事件**（5–11 件）：标准三轴——**密度**（本回收束观察是否值得单列）、**新颖性**（新定律命中/新称谓现象优先）、**钩连性**（能接前后回或预判四题者优先）；命名、骂称、自称、排行、避讳、戏言谶语、转述链、位格裁定都是高价值事件型；
3. **录引文**：从底本**复制粘贴**，任何改动＝违规（见 §3 踩坑 1/2/3）；
4. **定位映射**：每件做三行标注——四维定位（场/单位/极性档/通道）→ 层位/件（L1–L4＋件号）→ 命中定律（编号回指总架构 §7.2，见 §4.3）；
5. **填模板**：§0 速览（一句话＋判定表）→ §1 事件清单表 → §2 重点解构 2–3 段 → §3 回内系统观察 → §4 定律命中表 → §5 钩连（对前回/对后文/对预判四题）→ 尾注块＋「> AI生成」；
6. **声明计数**：**三处计数必须一致**——§0 声明件数＝§1 表行数＝尾注计数（004/010 实测曾两处不同步）。

### 1.3 Nb 编号规则（补全不破坏引用）

补全漏收事件时，新行用 **Nb 编号插入**（如 1b/4b/6b），**不重排原有编号**——因为 §2 重点解构、§4 命中表、前后续回的钩连、README 存档都按原编号引用（如"008 绛芸轩"）。表行计数含 b 行；声明格式如 `本回解构 10 件（见 §1，含 1b/4b/6b）`。

### 1.4 事件归属核查（防"张冠李戴"）

写关键引文前**核对说话人语境**：探查引文前后 50–100 字确认说话人。实测教训：008「别理那老货」误记为薛姨妈的话，实际是黛玉的咕哝——归属错则整段分析全错。归属可疑的高危场景：多人在场对白密集段、咕哝/悄悄话、转述句（"某某道"后面接引文的嵌套）。

## 2. 全量验证机制：从单文件质检到全工程审计

### 2.1 五维自动质检（质检脚本.ps1，验证逻辑 v2）

| 维 | 检查项 | 典型捕获 |
| :--- | :--- | :--- |
| 结构 | §0–§5 六节齐全、头标（N/120）、尾注块、AI 尾标、底本引用声明 | 模板残缺 |
| 计数 | 声明件数＝表行数（含 **Nb** 带标记行）、解构段数＝### 数、总和与 README 批次链一致 | 004/010 曾 6 声明 7 行 |
| 字符 | 零宽字符＝0（[\u200B-\u200F\u202A-\u202E\uFEFF]）、错字「诒」＝0 | 历史两大惯犯 |
| 锚定 | 全部「」引文经码点归一化后，在拆分底本/名词列锦做**子串匹配** | 21 处真实差异（§2.2） |
| 完整 | 【A】锚存在 | 引文裸奔 |

退出码 0 才允许 commit；已接入 `.githooks/pre-commit`（本机生效；脚本入库为版本化保障）。

### 2.2 引文锚定算法（归一化匹配）

对每条「」引文按 `……|＋|——|—` 分段，每段 ≥12 字符者做**码点归一化**后在底本归一化文本中 `Contains` 查找：

**归一化剥离表**（按码点区间，凡命中即删）：
- 控制符（<0x20）、空格三系（0x20/0x3000/0xA0）；
- 不可见系：0xAD/0x180E/0xFEFF、U+200B–200F、U+202A–202E、U+2060–2064；
- **私用区 U+E000–F8FF 与变体选择符 U+FE00–FE0F**（关键：拆分底本 019 在"的卍"后藏隐形 U+E02D，不剥离则全回误报）；
- 全部 ASCII/全角标点区间（0x21–0x2F、0x3A–0x40、0x5B–0x60、0x7B–0x7E 及全角对应段）＋中文标点（0x3001–0x303F）＋引号系（0x2010–0x2027）。

未命中片段的处置三选一（禁止第四种"放着不管"）：
1. **改从底本逐字录**（衍字/漏字/记忆偏差——21 处中 8 处）；
2. **补省略号**（跳引未标——10 处：`……`必须在跳句处）；
3. **异文照录＋注记**（底本确与通行本不同——3 处：如 009「金相公了」了〔通行本作"金相公"〕、019「摇身说：'变。'」〔通行本"摇身一变"〕，注"底本如此，通行本作 X"）。

### 2.3 计数守恒链（全工程级）

```
每回三处一致 → 批次累加表（README §5）→ 工程累计
001–008＝78 → 009–012＝88 → 013–017＝130 → 018＝139 → 019–020＝157 → 021–024＝193 → 补全+19+3＝215
```
任何一处改动（补件、合并、删除）都必须沿链更新到 README；质检脚本输出声明总数供人工比对批次表。

### 2.4 漏收补全流程（关键词密度扫描法）

对"按节选撰写、可能漏事件"的文档（本工程首批 001–008 即此情况）：

1. **密度扫描**：以称谓关键词表（爷/奶奶/姑娘/嫂/太太/夫人/小姐/哥儿/丫头/小厮/老爷/浑名/表字/小名/姨娘/舅舅/……约 40 词）切句扫描底本，筛出**含 ≥2 个关键词且归一化后未出现在现有文档中**的句子（每回约 8–29 句候选）；
2. **候选过滤**：剔除非事件句（族谱叙述、场景描写），保留真事件（新称谓对/命名/骂称/自称/转述链/谶语）；
3. **人工核底本**：逐条读原文语境，确认事件成立＋归属正确；
4. **Nb 插入**＋引文照录＋计数链更新；
5. **质检回归**：全量脚本重跑（本工程补全后：193→215 件、341→372 片段全锚定、0 异常）。

> 经验值：此法对"节选写作漏收"检出率高，但**不能替代精读**——它只能找含关键词的句，找不到纯叙事里的人物称谓关系变化；全量精读仍是第一道工序。

### 2.5 pre-commit 双关卡

```
.githooks/pre-commit
 ├─ Markdown 相对链接校验（既有：md_links.js，checked/broken 计数）
 └─ 工程质检脚本.ps1（本工程新增：结构/计数/字符/引文锚定，退出码硬门）
```
提交动作即活体验证：两次实测提交均在钩子内跑完"链接 20/0＋质检 215 件 372 片段 0 异常"后放行。

### 2.6 底本异文政策（总纲）

- 引文**一律以拆分底本为准**，禁止凭通行本记忆复述（实测 21 处差异中 11 处源于此）；
- 底本讹字/异形字**照录不校**（"睛雯""排揎""搬配""癍回"等），尾注集中存档；
- 底本与通行本有**实质异文**（词序/用词不同）时照录底本＋括注"通行本作 X"；
- 底本衍字（如 005"司人间之宇"衍"宇"）照录＋注记。

### 4.2 回指纪律（工程不重复展开体系）

每回文档只在**头标一行**声明框架回指（`称呼学\称呼逻辑思维总架构`），正文以**件号＋定律编号**回指，例：
- 「L2 极性档／对象位」「L4 攻击帧·燃料定律 21」「L3 三方篇 To/CC/BCC」「密级正反律 19」「handicap 铁律 25」；
- 体系概念（黑盒、路由、三色、五级介质等）**不在本工程重复定义**——工程只产出红楼梦的事件与发现（README 工程纲领第 2 条）。

### 4.3 映射表：事件行三标注的标准格式

| 标注位 | 取值来源 | 例（008 事件 5） |
| :--- | :--- | :--- |
| 四维定位 | 场（社会全枚举场景坐标）／单位（亲缘/职分/位格）／极性档（立场全枚举极性矩阵）／通道（信号学信道） | 面称＋笑语壳＋醋核／亲密档负极性 |
| 层位/件 | 总架构四层十二件：L1 词库层、L2 立场极性层、L3 通信协议层、L4 治理攻防层 | L3 三方篇 BCC 结构 |

### 4.4 新命题的两级归档路径

工程中原创的命题（体系未覆盖的发现）走两级流转：
1. **工程级**（先）：写入当回 §4 命中表＋README 对应批次"要点存档"（累计如：信物即冻结的称呼、自称＝状态机标签、历史身份不保值、位格优先于血缘、餐饮撤人术、称谓买路权、删名与复名的一字战争……）；
2. **体系级**（终局后）：工程完结时批量评估——哪些命题足够普适，升格回 `称呼学\` 体系文档（保留旧版备份，版本号升级）。**工程期间不轻易动体系**，避免边施工边改图纸。

### 4.5 钩连规范（§5 节的固定四向）

每回钩连必须覆盖：
- **对前回**：本回事件与前回文档的接续（用编号回指，如"019 三规条约"）；
- **对后文**：伏笔与预告（【B】级通行本常识支撑，标回号区间如〔036〕〔077〕）；
- **对预判四题**：README §3 四题（黛玉称谓轨迹／宝玉多名体系／詈骂极性光谱／名分即命运）的滚动登记；
- **对体系/其他名著**（如有）：理论反哺点或跨著对照。

### 4.6 重点解构的复盘工具

§2 重点解构段的标配分析器（按事件类型选）：
- **通信五段复盘**（双公式：WHO×STANCE×MOOD×CHANNEL×LEXEME）——适合单事件深析；
- **帧序列复盘**（触发→升级→插入→回归→终审）——适合吵架/冲突全程；
- **谈判/流程拆步**（造势→止损→出价→担保）——适合权谋操作；
- **对表分析**（两事件/两人物/两回并读）——适合镜像结构（如 022 与 023 的"一空一执"）。

## 5. 全流程 SOP（批次作业标准序列）

```
A. 开工前     读 README §5 批次表确认起点回号；确认上一批"要点存档"已读（续接上下文）
B. 单回生成   精读底本全文 → 六步流程（§1.2）→ 存盘
C. 单回质检   跑质检脚本（全量亦无妨，24 文件 <1 分钟）
D. 批次收敛   本批 4–6 回齐后：更新 README 批次表（回目/状态/累计数）＋批次要点存档
E. 提交       git add 工程目录 → commit（pre-commit 自动跑双关卡）→ push origin main
F. 会话管理   每轮会话做 1–2 批即可；上下文接近极限前以"批次完成点"为安全提交位收束
G. 周期审计   每 6 批左右做一次全量审计（§2.2 锚定＋§2.4 覆盖扫描），欠账即时补
```

异常处置：质检 FAIL → 按脚本输出逐条修复 → 重跑至退出码 0；pre-commit 拒绝 → 同上（钩子即质检的活体运行）。

| 适配点 | 红楼梦工程取值 | 移植方法 |
| :--- | :--- | :--- |
| 语料源 | `红楼梦_拆分\NNN_*.txt` | 各名著的拆分目录（结构同：NNN_字数_第N章 回目.txt） |
| 参考坐标 | `名词列锦章节\NNN_第N章.md` | 同左（各著均有） |
