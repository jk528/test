# 新闻联播总结报告 — 分阶段生成方案

> **版本**：v1.0.0（2026-09-08）  
> **核心思路**：固定格式内容由脚本生成（1-5部分 + 6-7部分骨架），六要素由AI一次性填写（JSON交互），脚本根据AI数据一次性输出第六七部分，保证六七一致性。

---

## 一、设计理念

### 1.1 问题背景

| 方案 | 数据来源 | 六要素 | 七部分一致性 | AI积分消耗 | 耗时 |
|------|---------|--------|-------------|-----------|------|
| 原始12步AI流程 | Python脚本 | AI逐条分析填写 | 手动保证 | 高（28次交互） | ~30分钟 |
| gen_report_v2.py（全自动） | 运行时抓取 | 7层级正则提取 | 自动保证 | 零 | ~15秒 |
| gen_report_hybrid.py（混合） | 运行时抓取 | 占位符+AI逐条Edit | 手动保证 | 高（28次Edit） | ~20分钟 |
| **gen_report_final.py（本方案）** | **运行时抓取** | **AI一次性JSON** | **自动保证** | **低（1次Write）** | **~2分钟** |

### 1.2 核心改进

- **固定格式部分（1-5 + 6-7骨架）**：脚本100%可靠，比AI更准确
- **六要素部分**：AI基于正文摘要一次性生成JSON，脚本格式化为第六七部分
- **六七一致性**：第七部分的占位符统合表从同一份JSON数据驱动，天然保证一致

### 2.1 三步流程

```

└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  Phase 2: AI一次性填写六要素JSON                   │
│  读取数据源JSON → 填写elements → 保存结果JSON      │
```

## 四、使用方法

### 4.1 日常使用（3步）

```bash
# Step 1: Phase 1 — 生成1-5部分 + 数据源JSON
python gen_report_final.py 20260907

# Step 2: Phase 2 — AI填写六要素JSON
#   - 读取 归档/2026年9月/六要素数据源_20260907.json
#   - 根据每条的 title/summary/full_text 填写 elements
#   - 保存为 归档/2026年9月/六要素结果_20260907.json

# Step 3: Phase 3 — 合并生成完整报告
python gen_report_final.py 20260907 --merge
```

### 4.2 参数说明

| 参数 | 说明 |
|------|------|
| `date` | 目标日期 YYYYMMDD，不填默认昨天 |
| `--merge` | Phase 3 模式：读取AI结果JSON，生成第六七部分，拼接完整报告 |
| `--force` | 强制重新生成（删除旧文件） |

### 4.3 完整命令示例

```bash
# 生成昨天的报告
python gen_report_final.py

# 生成指定日期
python gen_report_final.py 20260907

# 强制重新生成
python gen_report_final.py 20260907 --force

# 合并AI数据
python gen_report_final.py 20260907 --merge
```

## 五、六要素数据源JSON格式

### 5.1 数据源JSON（Phase 1输出）

```json
{
  "date": "20260907",
  "date_display": "2026年09月07日",
  "total_items": 28,
  "ai_items": 27,
  "instructions": "请根据每条的 title/url/summary/full_text 填写...",
  "news_items": [
    {
      "idx": "完整版",
      "title": "完整版《新闻联播》2026年09月07日",
      "url": "https://tv.cctv.com/...",
      "category": "完整版",
      "is_placeholder": true,
      "elements": {
        "location": "全国",
        "subject": "—",
        "event": "当日全部新闻汇总",
        "cause": "—",
        "method": "完整播报"
      }
    },
    {
      "idx": "1",
      "title": "《<u>国家主席</u>生态文明思想概论》出版发行",
      "url": "https://tv.cctv.com/...",
      "category": "政策/会议",
      "importance": "🔴",
      "summary": "为深入推动...",
      "full_text": "为深入推动...（前500字）",
      "is_placeholder": false,
      "elements": null
    },
    ...
  ]
}
```

### 5.2 结果JSON（Phase 2 AI输出）

与数据源JSON结构相同，区别在于 `elements` 字段从 `null` 变为填写好的对象：

```json
{
  "idx": "1",
  "title": "《<u>国家主席</u>生态文明思想概论》出版发行",
  "elements": {
    "location": "北京",
    "subject": "<u>国家主席</u>",
    "event": "《生态文明思想概论》出版发行",
    "cause": "深入推动生态文明思想进教材进课堂进头脑",
    "method": "中央宣传部、生态环境部组织编写"
  }
}
```

### 5.3 六要素填写规则

| 字段 | 规则 | 示例 |
|------|------|------|
| `location` | 地点，无明确值填"—" | `北京` / `全国` / `也门` |
| `subject` | 新闻主体（人物用`<u>`标记，机构不加） | `<u>国家主席</u>` / `财政部` / `也门冲突双方` |
| `event` | 核心事件，简短描述 | `会见卡塔尔首相` |
| `cause` | 原因/目的，无则填"—" | `推动数字贸易发展` |
| `method` | 方式/手段 | `在京会见` / `发布统计数据` |

**特殊行**：
- 完整版：`location=全国, subject=—, event=当日全部新闻汇总, cause=—, method=完整播报`
- 快讯目录行：`location=—, subject=—, event=播报XX联播快讯, cause=—, method=目录播报`

### 5.4 JSON注意事项

> **重要**：JSON值内部不要使用ASCII双引号 `"`。如需引用，使用中文引号 `""` 或转义 `\"`。
>
> 错误：`"method": "首设"词元"主题展区"` （内部ASCII引号破坏JSON）
> 正确：`"method": "首设\u201c词元\u201d主题展区"` 或 `"method": "首设\"词元\"主题展区"`

## 六、第六七部分生成逻辑

### 6.1 第六部分（六要素索引）

从结果JSON的 `news_items` 逐行生成表格：

| 列 | 来源 |
|----|------|
| 序号 | `item.idx` |
| 新闻标题 | `item.title`（含链接） |
| 类别 | `item.category` |
| 时间 | `item.elements.time` |
| 地点 | `item.elements.location` |
| 新闻主体 | `item.elements.subject` |
| 事件 | `item.elements.event` |
| 原因 | `item.elements.cause` |
| 方式 | `item.elements.method` |
| 详细信息源链接 | `item.source_url` 或 `item.url` |

### 6.2 第七部分（占位符统合）

从结果JSON的 `news_items` **扫描提取**，保证与第六部分一致：

| 子表 | 提取逻辑 |
|------|---------|
| 7.1.1 人物类 | 扫描所有 `subject` 中的 `<u>...</u>`，去重排序 |
| 7.1.2 机构类 | 扫描所有 `subject`（非人物、非事件核心对象），匹配全称 |
| 7.1.3 事件核心对象 | 扫描含"冲突双方""火山""产油国"等的 `subject` |
| 7.2 时间占位符 | 固定：播出日期 |
| 7.3 地点占位符 | 扫描所有 `location`，去重 |
| 7.4 数据占位符 | 正则扫描 `title` + `summary` + `full_text` 中的数字+单位 |

## 七、质量保障

### 7.1 已集成

| 机制 | 实现位置 | 说明 |
|------|---------|------|
| 脱敏预处理 | `fetch_xwlb.desensitize()` | 两阶段脱敏，所有标题正文经过处理 |
| HTTP缓存 | `gv2.http_get()` 的 `_cache` 字典 | 避免重复请求 |
| 文件存在性检查 | Phase 1 `--force` | >10KB跳过，≤10KB覆盖 |
| 六七一致性 | `generate_part67()` | 同一份JSON驱动两个部分 |

### 7.2 建议补充

- 生成后运行 `check_md_quality.py` 验证结构完整性
- 如齐鲁网正文抓取返回JS脚本（已知问题），六要素填写时依赖央视网 `summary` 字段即可

## 八、已知问题

| 问题 | 影响 | 应对 |
|------|------|------|
| 齐鲁网正文抓取返回JS | 快讯 `full_text` 不可用 | AI填写时依赖 `summary` 字段（央视网提取的摘要，正常可用） |
| JSON值内部ASCII引号 | JSON解析失败 | AI填写时使用中文引号或转义 |
| 分类关键词覆盖面 | 未覆盖的新闻落入"其他" | 可在 `gen_report_v2.classify_news()` 中扩充关键词 |
