# TXT 章节拆分工具 — 使用说明

## 1. 概述

本工具将大型 TXT 小说文件按章节拆分为多个小文件，支持两种模式：

- **按章节一一拆分**：每章生成一个独立文件
- **聚合拆分**：按自定义格式将多章合并为一份

提供 VBA 和 Python 两个版本，功能完全对齐，复制粘贴即可运行，无需外部依赖。

## 2. 文件结构

```
splittxt/
├── split_txt.bas       # VBA 合并版（818行）
├── split_txt.py        # Python 合并版（501行）
└── 使用说明.md          # 本文档
```

## 3. 功能特性

| 特性 | 说明 |
|------|------|
| 编码自动检测 | ANSI(GBK) / UTF-8(含/无BOM) / UTF-16LE / UTF-16BE |
| 章节识别 | 正则匹配 `第N章/回/节/卷`，中文数字含"万"支持大章节号 |
| 输出编码 | 统一 UTF-8 无 BOM |
| 序号自适应 | 文件数超当前位数容量时自动扩展（3位→4位→...） |
| 旧文件清理 | 写入前自动清理输出目录中的旧 .txt 文件 |
| 余数补齐 | 聚合拆分时不足总章数自动追加余数文件 |
| 错误捕获 | 写入循环包裹 On Error，出错时报告具体文件名 |
| 计时报告 | 完成后显示计时明细：选择/读取/识别/写入/总计 |

## 4. 使用方法

### 4.1 VBA 版

**安装：** 复制 `split_txt.bas` 全部内容，粘贴到 WPS/Excel/Word 的 VBA 编辑器（Alt+F11）的模块中。

**运行：** 执行 `拆分TXT` 宏。

**流程：**

```
选择TXT文件 → 选择拆分模式 → [输入聚合格式] → 生成文件
```

1. 文件选择对话框（仅显示 .txt 文件）
2. 模式选择对话框：
   - **[是]** 按章节一一拆分 → 直接生成
   - **[否]** 聚合拆分 → 输入聚合格式 → 预览确认 → 生成
   - **[取消]** 退出

### 4.2 Python 版

**运行：** 命令行执行，无需安装（Python 3 标准库即可）。

```bash
# 按章节一一拆分（每章一个文件）
python split_txt.py --src 红楼梦.txt

# 聚合拆分（默认 40,3）
python split_txt.py --src 红楼梦.txt --mode groups

# 聚合拆分（指定格式）
python split_txt.py --src 红楼梦.txt --mode groups --chunk "20,1|20,1|80,1"

# 便捷：传 --chunk 自动切换为 groups 模式
python split_txt.py --src 红楼梦.txt --chunk 40,3

# 仅检测文件编码（不拆分）
python split_txt.py --detect 红楼梦.txt
```

**参数说明：**

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `--src` | 是 | — | 源 TXT 文件路径 |
| `--mode` | 否 | `chapter` | 拆分模式：`chapter`=每章一文件，`groups`=聚合拆分 |
| `--out` | 否 | 自动派生 | 输出目录（空=源目录下 `<文件名>_拆分` 或 `_分组`） |
| `--chunk` | 否 | `40,3` | 聚合格式，传入时自动切换为 groups 模式 |
| `--prefix` | 否 | 空 | 文件名前缀 |
| `--serial-width` | 否 | 3 | 序号位数（文件数超容量时自动扩展） |
| `--encoding` | 否 | 自动检测 | 手动指定源文件编码（如 `gbk`/`big5`/`utf-8`），跳过自动检测 |
| `--detect` | 否 | — | 仅检测编码（不拆分），后跟文件路径 |

**编码说明：**

```bash
# 自动检测编码（默认）
python split_txt.py --src 红楼梦.txt

# 手动指定编码（解决乱码问题）
python split_txt.py --src 红楼梦.txt --encoding gbk
python split_txt.py --src 红楼梦.txt --encoding big5
python split_txt.py --src 红楼梦.txt --encoding gb18030
```

自动检测失败时会报错并提示使用 `--encoding` 参数。VBA 版会在完成报告中显示检测到的编码（如 `ANSI → UTF-8`），便于确认。

**可选依赖：**

```bash
pip install charset-normalizer
```

安装后编码检测精度提升；未安装时自动降级为内置字节模式扫描。

## 5. 聚合格式详解

### 格式语法

| 格式 | 含义 | 示例（120章） |
|------|------|----------------|
| `N` | 便捷模式：每 N 章一份 | `40` → 3份（1-40, 41-80, 81-120） |
| `a,b` | 单段：每份 a 章，共 b 份 | `40,3` → 3份各40章 |
| `a,b\|c,d\|...` | 多段：各段顺序聚合 | `20,1\|20,1\|80,1` → 3份（1-20, 21-40, 41-120） |

### 余数补齐

当总消耗章数不足总章数时，自动追加一个余数文件：

```
输入: 40,2    总章数: 120
消耗: 40×2 = 80
余数: 120-80 = 40
结果: 3份 → 001_第1-40章.txt, 002_第41-80章.txt, 003_第81-120章.txt
```

## 6. 命名规则

### 按章节拆分

```
<序号补零>_<完整章节标题>.txt
```

- 标题取自章节行的完整匹配行（含"第N回"前缀）
- 半角空格转全角
- 示例：`001_第1章　甄士隐梦幻识通灵　贾雨村风尘怀闺秀.txt`

### 聚合拆分

```
<序号补零>_第<起>-<止><单位>.txt
```

- 单位自动检测（章/回/节/卷），取首个匹配章节的单位词
- 示例：`001_第1-40章.txt`

### 带前缀

```
<前缀>_<序号补零>_<完整章节标题>.txt（按章节拆分）
<前缀>_<序号补零>_第<起>-<止><单位>.txt（聚合拆分）
```

- 示例：`红楼梦_001_第1章　甄士隐梦幻识通灵.txt`

### 文件名清洗

- 半角空格 → 全角空格 `　`
- 非法字符 `\ / : * ? " < > |` → 全角空格
- 连续全角空格折叠为单个
- 长度限制 60 字符

## 7. 核心逻辑

### 7.1 编码检测（三层策略）

```
第1层: BOM 快速检测（确定性100%）
  FF FE → UTF-16LE
  FE FF → UTF-16BE
  EF BB BF → UTF-8 BOM

第2层: 字节模式扫描（VBA）/ charset-normalizer 统计分析（Python）
  扫描高位字节，检查是否符合 UTF-8 多字节序列模式
  符合 → UTF-8
  不符合 → ANSI(GBK)

第3层: 全 ASCII → ANSI（纯英文文件两者兼容）
```

### 7.2 章节识别正则

```
^第([0-9一二三四五六七八九十百千万零两]+)(章|回|节|卷)(\s*)(.*)$
```

- 数字部分支持阿拉伯数字和中文数字（含"万"）
- 单位词支持 章/回/节/卷
- 标题部分为第4捕获组，空标题时回退为"第N章"

### 7.3 处理流程

```
读取源文件 → 检测编码 → 归一化行结束符(vbLf/\n)
    ↓
扫描章节起点 → 计算每章行范围
    ↓
确定输出目录 → 清理旧文件
    ↓
循环写入文件（UTF-8 无BOM）
    ↓
完成报告（文件数 + 计时明细：选择/读取/识别/写入/总计）
```

### 7.4 输出目录派生

| 模式 | 派生规则 | 示例 |
|------|----------|------|
| 按章节拆分 | `<源目录>\<文件名>_拆分\` | `红楼梦_拆分\` |
| 聚合拆分 | `<源目录>\<文件名>_分组\` | `红楼梦_分组\` |

## 8. 优化过程

### 8.1 Bug 修复

| 问题 | 原因 | 修复方案 |
|------|------|----------|
| 一一拆分无法运行 | `vbYesCancel` 非 VBA 有效常量，被当作空值(0)处理，等价于 `vbOKOnly`，用户点确定后 `vbOK(1) <> vbYes(6)` 导致直接退出 | 改为 `vbYesNo` |
| 大量文件清理报错 | `CleanOutputDir` 使用 `Dir`+`Kill` 循环，`Kill` 后 `Dir()` 内部状态被破坏，文件数多时跳过文件或报错 | 改用 `fso.GetFolder` + `For Each file` + `file.Delete` |
| 行结束符不一致 | `SplitByChapter` 用 `vbCrLf` 拼接，内容已归一化为 `vbLf`，导致输出文件行结束符混乱 | 统一使用 `vbLf` |
| COM 对象泄漏 | `ADODB.Stream` 用后未 `Set Nothing`，120次循环累积资源 | 所有 COM 对象用后显式 `Set Nothing` |

### 8.2 死代码清理

| 删除项 | 文件 | 原因 |
|--------|------|------|
| `WriteTextANSI` | VBA | 全局零调用，输出始终用 `WriteTextUTF8NoBOM` |
| `WriteTextUTF8BOM` | VBA | 同上 |
| `write_text_ansi` | Python | 同上 |
| `write_text_utf8_bom` | Python | 同上 |

### 8.3 性能优化

| 优化项 | 修改前 | 修改后 | 效果 |
|--------|--------|--------|------|
| `ReadTextANSI` | 逐行 `Line Input` + 字符串拼接 | `Input(LOF(fileNo), #fileNo)` 一次性读取 | O(n²) → O(1)，减少2个变量 |
| `SanitizeFileName` | 10 个独立 `Replace` 调用 | 1 个 `Replace` + 循环遍历 | 10行→4行，与 Python 对齐 |
| Python `_BOM_MAP` | 含 UTF-7 BOM 条目 | 删除 UTF-7 | 与 VBA 对齐，UTF-7 极罕见 |

### 8.4 健壮性增强

| 增强项 | 说明 |
|--------|------|
| 写入循环 `On Error` | 出错时报告具体文件名和错误信息，而非通用 VBA 错误对话框 |
| 文件选择过滤 | 仅显示 .txt 文件，移除"所有文件"过滤项 |
| `SplitByChapter` 参数 | 补齐 `ByVal`，与 `SplitByGroups` 一致 |
| 头注释修正 | "写入前预览并经用户确认" → "聚合拆分写入前预览确认"（一一拆分已删除预览步骤） |

## 9. 工程约定

| 约定 | 说明 |
|------|------|
| `Option Explicit` | 所有变量必须显式声明 |
| Dim 在过程顶部 | WPS VBA 严格性要求 |
| 数组收集 + Join | 避免循环内字符串拼接的 O(n²) 问题 |
| 行结束符 `vbLf` | 与内容归一化一致，避免混合行结束符 |
| UTF-8 无 BOM 输出 | 所有输出文件统一编码 |
| 零硬编码路径 | VBA 用文件选择对话框，Python 用 `--src` 参数 |
| 旧文件预清理 | 写入前清理输出目录中的旧 .txt 文件 |

## 10. VBA 与 Python 对齐情况

| 功能 | VBA | Python | 对齐 |
|------|-----|--------|------|
| 编码检测 | BOM + 字节扫描(100字节) | BOM + charset-normalizer + 字节扫描(1024字节) | 策略不同，结果一致 |
| 章节正则 | `VBScript.RegExp` | `re.compile` | 正则完全一致 |
| 文件名清洗 | 循环 Replace | 循环 Replace | 逻辑一致 |
| 输出目录派生 | `fso.GetParentFolderName` + `GetBaseName` | `os.path.dirname` + `splitext` | 逻辑一致 |
| 旧文件清理 | `fso.GetFolder` + `file.Delete` | `shutil.rmtree` + `os.makedirs` | VBA 仅删 .txt，Python 重建目录 |
| 序号补零 | `Format(n, "000")` | `str(n).zfill(width)` | 逻辑一致 |
| 用户交互 | 文件对话框 + MsgBox + InputBox | argparse 命令行参数 | 逻辑一致 |
