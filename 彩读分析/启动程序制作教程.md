# Windows 一键启动程序制作教程

> 从「红楼梦阅读分析」与「彩读分析」两个真实启动器的实践中总结。
> 适用场景：为本地开发项目（Vite/Electron/Tauri 等）制作双击即可启动的桌面入口，自动检查端口、复用运行中的服务、后台起服务、等待就绪后拉起应用窗口。
> 生成日期：2026-09-21。本文档与彩读分析目录下的 `启动彩读分析.vbs`、`start_colortxt.bat` 配套。

---

## 0. 前置条件检查（必须先做）

> 制作启动程序前，**逐项确认**以下前置条件，全部满足才继续。任一不满足先解决，否则启动器做了也会失败。

| # | 前置条件 | 检查方法 | 不满足的后果 |
|---|----------|----------|--------------|
| 1 | Windows 环境 + WScript 可用 | `cscript` 或 `wscript` 能运行（系统自带） | VBS 无法执行 |
| 2 | 目标项目目录存在 | 确认项目根路径真实存在 | 启动器第一步就报错 |
| 3 | 依赖已安装 | 项目内 `node_modules` 存在（npm/pnpm 项目）或已有编译产物（`app.exe`/`dist`） | dev 起不来，仅提示先 install |
| 4 | 运行命令可在 PATH 找到 | `where node` / `where npm` / `where pnpm` 有输出 | BAT 内命令找不到 |
| 5 | 项目 dev 端口确定且未被占用 | `netstat -ano \| findstr ":<端口>"` 为空表示空闲 | 端口被占会起不来或起两个 |
| 6 | 图标文件存在（可选） | 项目内有 `.ico` 图标 | 快捷方式用默认图标，不影响功能 |
| 7 | 已确认启动命令 | 开发：`npm run dev` / `pnpm tauri dev`；正式：exe 全路径 | 启动器不知道跑什么 |

**检查命令示例（PowerShell）**：

```powershell
# 1. 项目目录
Test-Path "C:\path\to\project"
# 2. 依赖
Test-Path "C:\path\to\project\node_modules"
# 3. 命令
Get-Command node, npm -ErrorAction SilentlyContinue | Select-Object Name, Source
# 4. 端口（以 5173 为例）
Get-NetTCPConnection -LocalPort 5173 -State Listen -ErrorAction SilentlyContinue
# 5. 图标
Test-Path "C:\path\to\project\resources\icon.ico"
```

## 1. 三种交付物

一个完整的启动器由三个文件组成：

| 文件 | 作用 | 放在哪 |
|------|------|--------|
| **主启动器 `启动<名字>.vbs`** | 检查端口 → 后台起服务 → 等待就绪 → 检测窗口进程；带日志 | 项目分析目录（脚本同目录） |
| **辅助脚本 `start_<name>.bat`** | 被 VBS 以最小化窗口调用，真正执行启动命令，输出写日志 | 与 VBS 同目录 |
| **桌面快捷方式 `<名字>.lnk`** | 指向 VBS，双击触发；可配图标 | 桌面 |

> 为什么不只用 BAT？VBS 可以**无窗口**（或最小化窗口）运行并轮询端口/进程，体验比黑窗口友好；BAT 负责真正的阻塞式启动命令并把输出重定向到日志，两者分工。

## 2. 前置条件检查在代码里的落地（VBS 内做）

VBS 开头必须做 3 项检查，任一失败就弹窗退出：

```vb
' ---- sanity checks ----
If Not objFSO.FolderExists(projectDir) Then
    MsgBox "Project not found:" & vbCrLf & projectDir, 16, "Launch failed"
    WScript.Quit 1
End If
If Not objFSO.FileExists(projectDir & "\node_modules\.bin\electron.cmd") Then
    MsgBox "Dependencies missing. Run `npm install` first.", 16, "Launch failed"
    WScript.Quit 1
End If
```

- 项目目录检查：`objFSO.FolderExists`
- 依赖检查：检查 `node_modules`（npm）或 `node_modules\.bin\<cli>.cmd`，Tauri 项目则检查 `src-tauri\target\debug\app.exe`
- 也可检查图标/日志目录并自动创建

## 3. 主启动器 VBS 模板（通用版）

```vb
' ============================================================
'  <Name> launcher  — 一键启动 <Name>
'    1. checks project exists / deps installed
'    2. checks whether the dev port is already listening
'    3. otherwise starts the helper .bat in a minimized window
'    4. waits until the port is listening (max N s)
'    5. waits until the app window process appears (max N s)
'  Encoding: pure ASCII (English only) to avoid codepage issues.
' ============================================================
Option Explicit

Dim objShell, objFSO
Dim baseDir, projectDir, helperBat, logFile, port
Dim startedVite, tries, ready, appSeen, appExePath, appCheckKind

Set objShell = CreateObject("WScript.Shell")
Set objFSO = CreateObject("Scripting.FileSystemObject")

' ---- 配置区：按项目修改 ----
baseDir = objFSO.GetParentFolderName(WScript.ScriptFullName)   ' 脚本所在目录
projectDir = baseDir & "\<相对项目路径>"                        ' 例如 .temp\ColorTxt
helperBat = baseDir & "\start_<name>.bat"
logFile = baseDir & "\.temp\launcher.log"
port = "5173"                        ' 项目 dev 端口
' 应用进程检测方式：'electron' | 'node' | 'exe文件名'
appCheckKind = "electron"

startedVite = False

' ---- 前置条件 ----
If Not objFSO.FolderExists(projectDir) Then
    MsgBox "Project not found:" & vbCrLf & projectDir, 16, "Launch failed"
    WScript.Quit 1
End If
If Not objFSO.FolderExists(projectDir & "\node_modules") Then
    MsgBox "Dependencies missing. Run `npm install` in:" & vbCrLf & projectDir, 16, "Launch failed"
    WScript.Quit 1
End If
If Not objFSO.FolderExists(baseDir & "\.temp") Then objFSO.CreateFolder baseDir & "\.temp"
WriteLog "=== <Name> launcher ==="

' ---- 1) port already listening? ----
If CheckPort(port) Then
    WriteLog "port " & port & " already listening - reuse"
Else
    WriteLog "starting dev server..."
    objShell.Run """" & helperBat & """", 2, False   ' 2 = minimized
    startedVite = True

    ' ---- 2) wait for port (max 60s) ----
    tries = 0
    Do While tries < 60
        WScript.Sleep 1000 : tries = tries + 1
        If CheckPort(port) Then WriteLog "port ready after " & tries & "s" : Exit Do
    Loop
    If Not CheckPort(port) Then WriteLog "WARN: port not ready after 60s, continuing..."
End If

' ---- 3) wait for app window process (max 30s) ----
appSeen = False : tries = 0
Do While tries < 30
    If IsAppRunning() Then appSeen = True : WriteLog "app detected after " & tries & "s" : Exit Do
    WScript.Sleep 1000 : tries = tries + 1
Loop
If Not appSeen Then
    MsgBox "Dev server started but the app window did not appear. Check log:" & vbCrLf & logFile, 48, "<Name>"
End If
WriteLog "=== launcher finished ==="

' ============================================================
'  helpers
' ============================================================
Function WriteLog(msg)
    Dim fso, ts
    Set fso = CreateObject("Scripting.FileSystemObject")
    Set ts = fso.OpenTextFile(logFile, 8, True)   ' 8 = append
    ts.WriteLine Now & "  " & msg
    ts.Close
End Function

Function CheckPort(portNum)
    Dim exec, output, lines, i, line
    Set exec = objShell.Exec("netstat -ano")
    output = exec.StdOut.ReadAll
    lines = Split(output, vbCrLf)
    CheckPort = False
    For i = 0 To UBound(lines)
        line = lines(i)
        If InStr(line, ":" & portNum & " ") > 0 And InStr(line, "LISTENING") > 0 Then
            CheckPort = True : Exit For
        End If
    Next
End Function

Function IsAppRunning()
    Dim exec, output
    If appCheckKind = "electron" Then
        Set exec = objShell.Exec("tasklist /FI ""IMAGENAME eq electron.exe""")
    ElseIf appCheckKind = "node" Then
        Set exec = objShell.Exec("tasklist /FI ""IMAGENAME eq node.exe""")
    Else
        Set exec = objShell.Exec("tasklist /FI ""IMAGENAME eq " & appCheckKind & """")
    End If
    output = exec.StdOut.ReadAll
    IsAppRunning = InStr(output, LCase(appCheckKind)) > 0
End Function
```

## 4. 辅助 BAT 模板（通用版）

```bat
@echo off
rem ============================================================
rem  <Name> launcher helper — start dev server
rem  Called by 启动<name>.vbs in a minimized window.
rem ============================================================
setlocal
set "LOG=%~dp0.temp\<name>_dev.log"
set "APP=%~dp0<相对项目路径>"
if not exist "%APP%\node_modules" (
  echo [<name>] ERROR: node_modules not found. Run `npm install` first.
  goto done
)
cd /d "%APP%"
echo [<name>] starting dev... > "%LOG%" 2>&1
npm run dev >> "%LOG%" 2>&1
:done
```

**关键点**：
- `%~dp0` 是 BAT 自身所在目录，用它定位项目，**不要写死绝对路径**，保证目录可移动；
- 输出全部重定向到 `colortxt_dev.log`，排障直接看日志；
- `npm run dev` 是阻塞式命令，窗口保持最小化运行，**不要**加 `exit` 或后台化。

## 5. 桌面快捷方式（PowerShell 生成）

```powershell
$ws = New-Object -ComObject WScript.Shell
$lnk = $ws.CreateShortcut("$env:USERPROFILE\Desktop\<名字>.lnk")
$lnk.TargetPath = "C:\path\to\启动<名字>.vbs"        ' 指向 VBS
$lnk.WorkingDirectory = "C:\path\to"                 ' 建议设脚本目录
$lnk.IconLocation = "C:\path\to\icon.ico,0"          ' 图标（0=第一个图标）
$lnk.Description = "<描述>"
$lnk.Save()
```

## 6. 两种项目形态的适配

| 项目形态 | dev 命令 | 端口检测 | 应用进程检测 | 依赖检查 |
|----------|----------|----------|--------------|----------|
| **Electron（彩读）** | `npm run dev`（electron-vite，一次性拉起 vite + 窗口） | vite 端口 5173 | `tasklist ... electron.exe` | `node_modules\.bin\electron.cmd` |
| **Tauri（红楼梦）** | `pnpm tauri dev`（先起 vite 再起 app.exe） | vite 端口 1420 | 直接 `start /wait app.exe`（VBS 阻塞等它退出） | `src-tauri\target\debug\app.exe` |
| 纯 Vite 前端 | `npm run dev` | vite 端口 | 无独立窗口进程（端口就绪即成功） | `node_modules` |

**Tauri 差异**：应用是独立 exe，VBS 里改为 `objShell.Run """" & appExe & """", 1, True`（第 3 参 True = 等待应用退出），退出后再清理自己启动的 vite。

## 8. 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 弹"Project not found" | 路径配置错 | 检查 VBS 里 `projectDir` 拼接 |
| 弹"Dependencies missing" | 没装依赖 | 在项目目录 `npm install` |
| 端口一直不就绪 | dev 报错 | 看 `*_dev.log` 尾部错误 |
| 应用窗口没出现 | 进程检测名不对 / 启动失败 | 改 `appCheckKind`；看 dev log |
| VBS 中文乱码 | 编码问题 | **VBS 全部用英文**（纯 ASCII） |
| 重复启动两个实例 | 端口检测失效 | 确认端口号与 dev 配置一致 |

## 9. 实战踩坑：vite 残留与静默失败

> 2026-09-22 在彩读分析启动器上遇到的两个真实 Bug，原模板（第 3 节）存在逻辑漏洞，已修复。
> 如果你的项目也用"端口复用"策略，**必须**读这一节。

### Bug 1：vite 在跑但 electron 已退出 → 不会重启

**现象**：用户关掉彩读窗口后，再次双击快捷方式 → 窗口不出现 → 等 30 秒弹"app window did not appear"。

**日志证据**：
```
5:35:52  vite already listening on port 5173 - reuse it
5:37:02  WARNING: no electron process detected within 30s
```

**根因**：VBS 的"端口复用"分支（原模板 :121-135）检测到 5173 在监听就直接跳过启动，只等 electron 进程。但 electron-vite 架构下，electron 窗口被关后 vite dev server 可能还在跑——VBS 复用了一个"只有 vite 没有 electron"的半死状态，永远等不到 electron。

**修复**：端口在跑时，**先检查应用进程是否也在**。如果不在，kill 掉占端口的残留进程，走完整启动：

```vb
If CheckPort(port) Then
    If IsAppRunning() Then
        WriteLog "port + app both running - nothing to do"
        WScript.Quit 0
    End If
    ' port alive but app gone: kill stale process, then restart cleanly
    Dim killed
    killed = KillPortOwners(port)
    WriteLog "port running but app gone - killed " & killed & " stale process(es)"
    WScript.Sleep 3000   ' wait for port release
End If
' fall through to full startup below ↓
```

### Bug 2：vite 60 秒没起来时静默继续 → 什么都开不起来

**现象**：双击快捷方式 → 等了很久没反应 → 没有窗口、没有提示。

**日志证据**：
```
13:16:50  vite not running - starting dev server...
13:19:27  WARNING: vite not listening after 60s, continuing...
```

dev log 停在 `transforming...`（构建卡住，可能因磁盘 IO / 残留进程 / 偶发）。

**根因**：原模板 :134 对 60 秒超时只 `WriteLog "WARN..."` 就继续往下走——后续等 electron 自然也是 30 秒空等，最终弹一个模糊的"窗口未出现"提示，用户完全不知道是 vite 没起来。

**修复**：vite 超时 = 致命错误，弹窗 + 退出，不再继续：

```vb
If Not CheckPort(port) Then
    WriteLog "ERROR: port not listening after 60s"
    MsgBox "Dev server failed to start within 60s." & vbCrLf & _
           "Check log: " & vbCrLf & logFile, 16, "Launch failed"
    WScript.Quit 1
End If
```

### 修复补充：KillPortOwners 辅助函数

```vb
' Kill all processes listening on the given port (returns count killed)
Function KillPortOwners(portNum)
    Dim exec, output, lines, i, line, parts, pid, count
    Set exec = objShell.Exec("netstat -ano")
    output = exec.StdOut.ReadAll
    lines = Split(output, vbCrLf)
    count = 0
    For i = 0 To UBound(lines)
        line = Trim(lines(i))
        If InStr(line, ":" & portNum & " ") > 0 And InStr(line, "LISTENING") > 0 Then
            parts = Split(line)
            pid = parts(UBound(parts))
            If IsNumeric(pid) And CLng(pid) > 0 Then
                objShell.Run "taskkill /PID " & pid & " /F", 0, True
                count = count + 1
            End If
        End If
    Next
    KillPortOwners = count
End Function
```

### BAT 诊断增强

```bat
echo [<name>] === %date% %time% === > "%LOG%" 2>&1
echo [<name>] node: >> "%LOG%" 2>&1
call node --version >> "%LOG%" 2>&1
echo [<name>] npm: >> "%LOG%" 2>&1
call npm --version >> "%LOG%" 2>&1
echo [<name>] starting dev... >> "%LOG%" 2>&1
call npm run dev >> "%LOG%" 2>&1
```

加时间戳 + node/npm 版本，排障时能快速判断是环境问题还是代码问题。`call` 防止某些环境下直接调 npm.cmd 的路径问题。

### 修复后的完整启动流程（替代原模板第 3 节主流程）

```
1. CheckPort(port)?
   ├─ Yes + app running  → 退出（已在运行，幂等）
   ├─ Yes + app gone     → KillPortOwners → Sleep 3s → 走 ②
   └─ No                  → 走 ②
2. 启动 BAT（minimized）
3. 等 port 就绪（max 60s）→ 超时 = 弹错误框 + 退出 1
4. 等 app 进程出现（max 30s）→ 超时 = 弹警告框
5. 成功 → 记日志结束
```

> **总结**：原模板的"端口复用"和"超时静默继续"是两个设计缺陷。端口复用必须验证应用进程也在，否则要清理残留重启；超时必须是致命退出，不能静默继续——否则用户只看到"什么都没发生"。
