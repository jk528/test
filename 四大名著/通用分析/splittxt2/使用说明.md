# TXT 章节拆分工具（多正则版） — 使用说明

## 1. 概述

本工具是 `splittxt` 的增强版本，核心改进：**将章节正则表达式独立为可选的多套方案，支持多套正则并列选择**，用户可同时选择多套正则（如"1,2,3"或"1,4,5"），所有选中正则同时匹配章节标题，结果合并。

支持三种拆分模式（与 `splittxt` 完全一致）：

- **按章节一一拆分**：每章生成一个独立文件
- **聚合拆分**：按自定义格式将多章合并为一份
- **清洁模式**：按正文字数过滤章节，并生成合并文件

仅提供 VBA 版本，复制粘贴即可运行，无需外部依赖。

## 3. 与 splittxt 的差异

| 对比项 | splittxt（原版） | splittxt2（多正则版） |
|--------|------------------|----------------------|
| 语言版本 | VBA + Python + JS宏 | 仅 VBA |
| 章节正则 | 硬编码单一正则 | 8套预设 + 自定义输入 |
| 正则选择 | 无 | **支持多选并列**（如"1,2,3"） |
| 正则匹配方式 | 单一正则扫描 | **多正则同时扫描，任一匹配即为章节** |
| 单位词提取 | 正则第2捕获组 | 可配置单位组索引（支持无单位组正则） |
| 默认回退正则 | `^第([0-9一二三四五六七八九十百千万零两]+)(章\|回\|节\|卷)...` | 含 `〇` 字符 |
| 完成报告 | 显示编码+计时 | 额外显示"使用正则：N套: 名称A + 名称B" |
| 聚合预览 | 显示格式+章数 | 额外显示使用的正则名称 |
| 未识别提示 | "未识别到任何章节标题" | "使用正则：XXX，请尝试其他正则表达式" |
| 功能完整性 | 全部功能 | 全部功能（完全继承） | |

## 4. 预设正则表达式

### 4.1 正则列表

| 序号 | 名称 | 正则表达式 | 适用场景 | 单位词来源 |
|------|------|------------|----------|------------|
| 1 | 标准中文（默认） | `^第([0-9一二三四五六七八九十百千万零〇两]+)(章\|回\|节\|卷)(\s*)(.*)$` | 通用，含阿拉伯数字+中文数字+〇 | 正则提取 |
| 2 | 纯阿拉伯数字 | `^第(\d+)(章\|回\|节\|卷)(\s*)(.*)$` | 仅阿拉伯数字的文本 | 正则提取 |
| 3 | 英文Chapter | `^[Cc]hapter\s+(\d+)(\s*[:\.\-]?\s*)(.*)$` | 英文小说 | 默认 "Chapter" |
| 4 | 序章/楔子/番外 | `^(序章\|楔子\|尾声\|番外\|引子\|后记\|终章\|序言\|前言)(\s*)(.*)$` | 无章号的作品 | 默认 "章" |
| 5 | 数字+标题 | `^(\d+)(章\|回\|节\|卷)(\s*)(.*)$` | 无"第"字的格式 | 正则提取 |
| 6 | 精简中文 | `^第([零〇一二三四五六七八九十百千两]{1,7})(章\|节)(\s*)(.*)$` | 参考清洁工具，限纯中文数字 | 正则提取 |
| 7 | 宽松匹配 | `^第(.+?)(章\|回\|节\|卷)(\s*)(.*)$` | 非标准格式兜底 | 正则提取 |
| 8 | 自定义 | 用户输入 | 特殊需求 | 用户指定 |

### 4.2 正则优化说明

基于参考文件分析的 3 项优化：

| 优化项 | 原版 | 优化后 | 原因 |
|--------|------|--------|------|
| 新增 `〇` 字符 | `[0-9一二三四五六七八九十百千万零两]` | `[0-9一二三四五六七八九十百千万零〇两]` | `〇`（U+3007）是 `零` 的变体，部分小说使用 `第一〇〇章` 格式 |
| 新增精简中文正则 | 无 | `^第([零〇一二三四五六七八九十百千两]{1,7})(章\|节)...` | 参考清洁工具正则，限1-7字纯中文数字，仅匹配 `章节`（不含 `回卷`），减少误匹配 |
| 新增宽松匹配正则 | 无 | `^第(.+?)(章\|回\|节\|卷)...` | 适配 `第序章`、`第ABC章` 等非标准格式，作为最后兜底 |

### 4.3 正则选择逻辑（支持多选并列）

```
选择TXT文件
    ↓
选择正则表达式（InputBox 输入序号，可多选）
    ↓
  "1"        单选：使用预设正则1
  "1,2,3"    多选：同时使用正则1+2+3，任一匹配即为章节
  "1 4"      多选：空格分隔，等价于 "1,4"
  "8"        自定义：输入正则 → 输入默认单位词
  "1,8"      混合：预设1 + 自定义正则
    ↓
验证每个正则合法性 → 继续
    ↓
选择拆分模式
```

**多选并列的核心逻辑：**

- 每行依次测试所有选中正则，任一正则匹配即为章节标题
- 首个匹配的正则决定该行的标题和单位词提取
- 多正则结果按行号顺序合并，去重（同一行不会重复识别）

**正则合法性验证：** 对每个选中正则使用 `VBScript.RegExp.Test` 测试是否能正确编译和执行，错误时提示具体正则序号和原因并退出。

### 4.4 单位词提取机制

不同正则的单位词获取方式不同：

| 类型 | unitGroupIdx | 行为 | 示例 |
|------|-------------|------|------|
| 有单位组 | >= 0 | 从 SubMatches(idx) 提取 | 正则 `^第(\d+)(章\|回)...`，idx=1，提取 "章"/"回" |
| 无单位组 | -1 | 使用 defaultUnit | 正则 `^Chapter\s+(\d+)...`，使用默认 "Chapter" |

单位词用于聚合拆分的文件名（如 `001_第1-40章.txt`）。多正则并列时，首个匹配到的章节的单位词决定全局单位。

## 5. 使用方法

### 5.1 安装与运行

**安装：** 复制 `split_txt.bas` 全部内容，粘贴到 WPS/Excel/Word 的 VBA 编辑器（Alt+F11）的模块中。

**运行：** 执行 `拆分TXT` 宏。

### 5.2 完整流程

```
选择TXT文件 → 选择正则表达式(可多选并列) → 选择拆分模式 → [章节内容处理] / [输入聚合格式] / [输入清理参数] → 生成文件
```

**步骤详解：**

1. **文件选择对话框**（仅显示 .txt 文件）
2. **正则选择对话框**（InputBox 输入序号，支持多选）
   - 单选：输入 `1` 使用预设正则1
   - 多选：输入 `1,2,3` 或 `1 2 3`（逗号或空格分隔），同时使用多套正则
   - 自定义：输入 `8` → 输入正则表达式 → 输入默认单位词
   - 混合：输入 `1,8` 同时使用预设1和自定义正则
   - 取消：退出
3. **模式选择对话框**：
   - **[是]** 按章节一一拆分 → 仅有标题处理选择 → 生成
   - **[否]** 聚合拆分 → 输入聚合格式 → 预览确认 → 生成
   - **[取消]** 清洁模式 → 输入 `N,flag` 参数 → 生成
4. **章节内容处理选择**（仅按章节拆分时出现）：
   - **[否]**（默认）跳过仅有标题无正文的章节
   - **[是]** 生成所有章节（含仅有标题/正文不足）
5. **清洁模式**（[取消] 时进入）：
   - 输入 `N,flag`：正文汉字 < N 的章节跳过
   - `flag=1`（默认）：合并保留章节（>= N）→ `保留大于等于N_小说名.txt`
   - `flag=0`：合并跳过章节（< N）→ `清理小于N_小说名.txt`
   - `flag=2`：同时合并两者 → 生成上述两个文件
   - 合并文件首部列出跳过明细（跳过数、明细、前三正文字数、保留数）

### 5.3 正则选择示例

**场景1：红楼梦（标准中文格式）**

```
第1章　甄士隐梦幻识通灵　贾雨村风尘怀闺秀
```

选择正则 **1（标准中文）**，匹配 `第1章`、`第一百二十回` 等。

**场景2：英文小说**

```
Chapter 1 - The Beginning
```

选择正则 **3（英文Chapter）**，单位词默认 "Chapter"。

**场景3：无章号的作品**

```
序章
楔子
番外篇
```

选择正则 **4（序章/楔子/番外）**。

**场景4：非标准格式**

```
第序章
第ABC章
```

选择正则 **7（宽松匹配）**，匹配 `第` 和 `章` 之间的任意内容。

**场景5：自定义正则**

文件中使用 `卷一`、`卷二` 格式，无预设正则匹配。

选择正则 **8（自定义）**，输入：
```
^卷(\d+)(\s*)(.*)$
```
默认单位词输入 `卷`。

**场景6：混合格式（多选并列）**

文件中同时存在多种章节格式：

```
第1章　甄士隐梦幻识通灵
Chapter 2 - The Beginning
序章
```

输入 `1,3,4`（逗号分隔），同时使用正则1（标准中文）+ 正则3（英文Chapter）+ 正则4（序章），三种格式都能匹配。

**场景7：正文与标题混排（多选并列）**

文件中 `第N章` 和 `第N回` 混合使用：

```
第1章　开头
第2回　发展
第3节　转折
```

输入 `1,2` 同时使用标准中文（含中文数字）和纯阿拉伯数字正则，覆盖更广。

| 清洁模式 | 跳过正文汉字<N的章节，可选合并保留章节(>=N)、跳过章节(<N)或两者同时合并(flag=2) |

## 7. 聚合格式详解

### 格式语法

| 格式 | 含义 | 示例（120章） |
|------|------|----------------|
| `N` | 便捷模式：每 N 章一份 | `40` → 3份（1-40, 41-80, 81-120） |
| `a,b` | 单段：每份 a 章，共 b 份 | `40,3` → 3份各40章 |
| `a,b\|c,d\|...` | 多段：各段顺序聚合 | `20,1\|20,1\|80,1` → 3份（1-20, 21-40, 41-120） |

### 余数补齐

当总消耗章数不足总章数时，自动追加一个余数文件：

```
输入: 40,2    总章数: 120
消耗: 40×2 = 80
余数: 120-80 = 40
结果: 3份 → 001_第1-40章.txt, 002_第41-80章.txt, 003_第81-120章.txt
```

## 8. 命名规则

### 按章节拆分

```
<序号补零>_<章节字数>_<完整章节标题>.txt
```

- **序号补零**：基于实际生成文件的顺序连续编号（001, 002, ...），位数自适应
- **章节字数**：统计该章全部字符（含标题行、正文、标点、换行符等全部数据），位数自适应零填充
- **完整章节标题**：取自章节行的完整匹配行（含"第N回"前缀），半角空格转全角
- 示例：`001_06928_第1章　甄士隐梦幻识通灵　贾雨村风尘怀闺秀.txt`

### 聚合拆分

```
<序号补零>_第<起>-<止><单位>.txt
```

- 单位由正则提取或使用默认单位词
- 示例：`001_第1-40章.txt`

### 清洁模式合并文件

```
flag=1: 保留大于等于<N>_<小说名>.txt     （包含正文汉字 >= N 的章节）
flag=0: 清理小于<N>_<小说名>.txt          （包含正文汉字 < N 的章节）
flag=2: 同时生成上述两个文件
```

- flag=2 时两个文件共享相同的清理报告头部（跳过数、明细、前三正文字数、保留数）
- 每个文件头部额外标注"本文件内容：跳过章节"或"本文件内容：保留章节"

### 文件名清洗

- 半角空格 → 全角空格 `　`
- 非法字符 `\ / : * ? " < > |` → 全角空格
- 连续全角空格折叠为单个
- 长度限制 60 字符

## 9. 核心逻辑

### 9.1 编码检测

```
第1层: BOM 快速检测
  FF FE → UTF-16LE
  FE FF → UTF-16BE
  EF BB BF → UTF-8 BOM

第2层: 字节模式扫描（前100字节）
  扫描高位字节，检查是否符合 UTF-8 多字节序列模式
  符合 → UTF-8
  不符合 → ANSI(GBK)

第3层: 全 ASCII → ANSI
```

### 9.2 多正则选择流程（支持多选并列）

```
InitRegexPatterns()     ← 初始化8套预设正则
    ↓
SelectRegexPattern()    ← InputBox 输入序号（支持"1,2,3"多选）
    ↓
解析多选输入（逗号或空格分隔）
    ↓
  [含8] 自定义 → InputBox 输入正则 → InputBox 输入默认单位词
    ↓
填充全局数组 g_selPatterns / g_selUnitGroups / g_selDefaultUnits
    ↓
验证每个正则合法性 (VBScript.RegExp.Test)
    ↓
ScanChapters(lines, ...)  ← 从全局数组读取多套正则
    ↓
每行依次测试所有选中正则，任一匹配即为章节起点
    ↓
无选中正则时回退到默认标准中文正则（含〇）
```

### 9.3 处理流程

```
读取源文件 → 检测编码 → 归一化行结束符(vbLf)
    ↓
选择正则(可多选) → 验证每个正则 → 预编译正则对象数组
    ↓
逐行扫描：依次测试所有正则，首个匹配即章节起点
    ↓
计算每章行范围 → 预计算章节字数
    ↓
确定输出目录 → 清理旧文件
    ↓
循环写入文件（UTF-8 无BOM）
    ↓
[清洁模式] 生成合并文件
    ↓
完成报告（文件数 + 正则名称(N套: A + B + C) + 计时明细）
```

### 9.4 输出目录派生

| 模式 | 派生规则 | 示例 |
|------|----------|------|
| 按章节拆分 | `<源目录>\<文件名>_拆分\` | `红楼梦_拆分\` |
| 聚合拆分 | `<源目录>\<文件名>_分组\` | `红楼梦_分组\` |

### 9.5 不足章节处理

| 状态 | 行为 |
|------|------|
| 开关关闭（默认） | 不足章节**不生成文件**，序号连续编号，完成后提示跳过数量及分类 |
| 开关打开 | 不足章节**正常生成文件**，完成后提示不足章节数量及分类 |

**不足章节的两种类型：**

| 类型 | 判断条件 | 说明 |
|------|----------|------|
| 仅有标题 | `n_lines == 1`（仅含标题行，无正文行） | 下一章标题紧跟当前章标题 |
| 正文不足 | 正文汉字数 < `min_body_len` | 有正文但汉字太少（仅当指定阈值时检测） |

**汉字计数规则：** 正文字数仅统计汉字（U+4E00–U+9FFF），标点符号、数字、字母、空白等均不计入。

## 10. 工程约定

| 约定 | 说明 |
|------|------|
| `Option Explicit` | 所有变量必须显式声明 |
| Dim 在过程顶部 | WPS VBA 严格性要求 |
| 数组收集 + Join | 避免循环内字符串拼接的 O(n²) 问题 |
| 行结束符 `vbLf` | 与内容归一化一致，避免混合行结束符 |
| UTF-8 无 BOM 输出 | 所有输出文件统一编码 |
| 零硬编码路径 | VBA 用文件选择对话框 |
| 旧文件预清理 | 写入前清理输出目录中的旧 .txt 文件 |
| 正则合法性验证 | 选择正则后用 `VBScript.RegExp.Test` 验证 |
| 单位组索引可配置 | `unitGroupIdx` 参数支持无单位组正则（-1） |
| COM 对象显式释放 | `ADODB.Stream` 用后 `Set Nothing` |

## 11. 思考过程

### 11.1 为什么需要多正则选择

**原版问题：** `splittxt` 硬编码单一正则 `^第([0-9一二三四五六七八九十百千万零两]+)(章|回|节|卷)...`，遇到非标准格式的小说时无法识别章节：

- 英文小说（`Chapter 1`）
- 无章号作品（`序章`、`楔子`）
- 无"第"字的格式（`1章 标题`）
- 使用 `〇` 的古旧格式（`第一〇〇章`）
- 非标准格式（`第序章`、`第ABC章`）

**解决思路：** 将正则表达式从代码中独立出来，提供多套预设方案让用户选择，并支持自定义输入。

### 11.2 正则预设的设计原则

| 原则 | 说明 |
|------|------|
| 严格优先 | 序号1-5为严格匹配，减少误匹配 |
| 宽松兜底 | 序号7为宽松匹配，作为最后手段 |
| 参考成熟方案 | 序号6参考清洁工具的正则，限1-7字纯中文数字 |
| 自定义留路 | 序号8为自定义，任何特殊格式都能处理 |

### 11.3 单位组索引（unitGroupIdx）的设计

**问题：** 不同正则的单位词位置不同，有的甚至没有单位组。

**解决：** 引入 `unitGroupIdx` 参数（0-based SubMatch 索引）：

| 正则类型 | unitGroupIdx | 单位词来源 |
|----------|-------------|-----------|
| `^第(\d+)(章\|回)...` | 1 | SubMatches(1) = "章"/"回" |
| `^Chapter\s+(\d+)...` | -1 | 无单位组，使用 defaultUnit |
| `^(序章\|楔子)...` | -1 | 无单位组，使用 defaultUnit "章" |

**默认值 -1** 表示无单位组，使用 `defaultUnit` 参数。

### 11.4 `〇` 字符的发现

参考文件中的正则使用 `[零〇一二三四五六七八九十百千两]`，其中 `〇`（U+3007，CJK符号和标点区）是 `零` 的变体：

- `零`（U+96F6）在 CJK 统一汉字区
- `〇`（U+3007）在 CJK 符号和标点区

部分小说使用 `第一〇〇章` 而非 `第一百章`，原版正则无法匹配。优化后在所有含中文数字的正则中添加 `〇`。

### 11.5 精简中文正则的设计

参考清洁工具的正则 `^第([零〇一二三四五六七八九十百千两]{1,7})(章|节)`：

| 设计点 | 说明 |
|--------|------|
| `{1,7}` 限长 | 防止匹配过长的数字序列（如日期、电话号码误匹配） |
| 仅 `章\|节` | 不含 `回\|卷`，进一步收窄匹配范围 |
| 纯中文数字 | 不含阿拉伯数字，适用于古典文学 |

### 11.6 宽松匹配正则的设计

`^第(.+?)(章|回|节|卷)` 使用非贪婪匹配 `.+?`：

- `.+?` 匹配"第"和单位词之间的任意内容（尽可能少）
- 适配 `第序章`、`第ABC章`、`第一卷之一` 等非标准格式
- 风险：可能误匹配正文中包含"第...章"的句子，但章节标题通常在行首，风险可控

### 11.7 多选并列的设计

**用户需求：** "选择正则表达式，可以并列的情况，举例123或456或135等情况。"

**问题分析：** 原设计仅支持单正则选择，但实际场景中小说可能混排多种格式：
- 正文用 `第N章`，序言用 `序章`
- 中文章节用 `第N章`，附录用 `Chapter N`
- 不同卷使用不同单位词（`第N章` + `第N回`）

**设计方案：**

| 设计点 | 决策 | 原因 |
|--------|------|------|
| 输入格式 | 逗号或空格分隔 | `"1,2,3"` 和 `"1 2 3"` 均可 |
| 匹配逻辑 | 依次测试，首个匹配即停止 | 避免同一行被多个正则重复匹配 |
| 单位词提取 | 取首个匹配到的正则的单位组 | 首个章节决定全局单位词 |
| 全局存储 | 用全局数组 `g_selPatterns()` 等 | 避免函数参数传递数组的复杂性 |
| 正则预编译 | 扫描前一次性创建所有 RegExp 对象 | 避免循环内反复创建 COM 对象 |
| 报告显示 | `"3套正则: 标准中文 + 英文Chapter + 序章"` | 清晰展示选中了哪些正则 |

**架构变化：**

```
旧（单正则）:
  SelectRegexPattern → 返回 pattern/unitGroup/defaultUnit
  ScanChapters(pattern, unitGroup, defaultUnit) → 逐行测试1个正则

新（多正则并列）:
  SelectRegexPattern → 填充全局数组 g_selPatterns[] 等
  ScanChapters() → 逐行依次测试N个正则，首个匹配即章节
```

**去重保证：** 同一行只会被识别为1个章节起点（For 循环中 `Exit For` 跳出正则测试），不会因多个正则匹配同一行而重复。
