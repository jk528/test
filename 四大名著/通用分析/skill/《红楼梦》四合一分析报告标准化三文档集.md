## 第零步：前置检查（生成前必须执行）

> **目的**：防止覆盖已完成的分析报告，确保文件完整性

1. 检查目标章节分析报告文件是否已存在
2. 若文件存在且大小 > 10KB，跳过生成，标记为"已完成"
3. 若文件不存在或大小 ≤ 10KB，执行覆盖重生成
4. 记录检查时间、检查结果、操作人

**排查机制**：

* [ ] 文件存在性检查

* [ ] 文件大小检查（正常范围：15-50KB）

* [ ] 文件标题唯一性检查（"红楼梦第 X 章分析报告"仅出现 1 次）

***

## 第一步：章节信息确认

1. 确认章节编号（001-120）
2. 确认章节标题（如"甄士隐梦幻识通灵 贾雨村风尘怀闺秀"）
3. 确认文本来源文件（如 `001_第 1 章.txt`）
4. 确认分析日期与操作人

**排查机制**：

* [ ] 章节编号与标题匹配验证

* [ ] 文本文件存在性验证

* [ ] 文本内容完整性验证（字数 > 5000 字）

***

## 第二步：事件接入清单梳理

> **目的**：确保章节全部事件节点无遗漏，建立事件分级体系

### 2.1 事件分级标准

| 级别   | 标识 | 定义          | 示例         |
| ---- | -- | ----------- | ---------- |
| 核心事件 | ★  | 推动主线情节的关键节点 | 宝玉出生、黛玉进府  |
| 关键事件 | ◆  | 重要人物出场或关系建立 | 雨村遇士隐、宝钗入京 |
| 背景事件 | ◇  | 环境描写或次要情节   | 士隐做梦、丫鬟对话  |

### 2.2 事件接入流程

1. 通读章节全文，标记所有事件节点
2. 按三级标准对事件进行分级标注
3. 填写事件接入清单表格（第 3.4 节）
4. 核对事件数量与原文段落对应关系

**排查机制**：

* [ ] 事件数量 ≥ 8 个（第一章基准）

* [ ] 核心事件 ≥ 3 个

* [ ] 每条事件有原文段落支撑

***

## 第三步：词汇统计与情感分析

1. 提取章节全部词汇
2. 按正/反/中性三类进行标注
3. 统计各类词汇频次与占比
4. 生成情感词三维分布数据

**词汇判定标准**（与模板 V2.3 第 2.1 节一致）：

* 正向词：表达喜悦、赞美、希望等积极情感

* 反向词：表达悲伤、愤怒、绝望等消极情感

* 中性词：客观描述、无情感倾向词汇

**排查机制**：

* [ ] 词汇总数 ≥ 100 个

* [ ] 正/反/中性词覆盖率 ≥ 80%

* [ ] 无重复统计词汇

***

## 第四步：新闻六要素 5W1H 拆解

1. Who（人物）：提取章节全部人物
2. What（事件）：梳理核心情节
3. When（时间）：标注时间节点
4. Where（地点）：记录场景位置
5. Why（原因）：分析动机背景
6. How（方式）：描述行为手段

**排查机制**：

* [ ] 六要素完整性 ≥ 90%

* [ ] 人物层级标注正确（★核心/◆关键/◇背景）

* [ ] 时间地点无矛盾

***

## 第五步：小说叙事六要素解析

1. 时空背景：朝代、季节、具体时辰
2. 人物角色：主角、配角、群像
3. 核心情节：主线、支线、伏笔
4. 冲突动机：内部冲突、外部冲突
5. 叙事手法：倒叙、插叙、多线并行
6. 章节定位：开篇、发展、高潮、收尾

**排查机制**：

* [ ] 六要素全部填写

* [ ] 章节定位准确

* [ ] 叙事手法识别正确

***

## 第六步：可视化数据准备

1. 情感分布图数据（正/反/中性词占比）
2. 人物关系网络图数据（人物层级与关联）
3. 情节时间轴数据（事件节点与时间顺序）

**占位符规范**（与模板 V2.3 第 10.2 节一致）：

* 图表占位符格式：`[图表：情感分布饼图]`

* 禁止双重标签：`<u>标签</u>` 不可嵌套

* 禁止相邻重复：同一占位符不可连续出现

***

## 第七步：跨章对比数据录入

1. 将本章正反义词占比录入全书累计表（第 7.2 节）
2. 将本章事件数量录入跨章对比表（第 7.1 节）
3. 更新人物首次出场记录（第 5.2 节）

**排查机制**：

* [ ] 累计表数据更新

* [ ] 人物档案建立（首次出场时）

* [ ] CSV 数据接口准备（第 7.3 节）

***

## 第八步：版本差异记录

1. 对比脂评本与程高本同一章节内容
2. 记录关键差异点（文字、情节、人物）
3. 填写版本差异记录表（第 8.1 节）

**排查机制**：

* [ ] 版本来源标注清晰

* [ ] 差异点有原文支撑

* [ ] 无主观臆断内容

***

## 第八点五步：脱敏预处理（生成前必须执行）

> **目的**：确保敏感信息处理符合规范，避免泄露风险

### 脱敏规则（与模板 V2.3 第 10.3 节一致）

| 敏感类型 | 处理方式     | 示例          |
| ---- | -------- | ----------- |
| 真实人名 | 保留（小说人物） | 贾宝玉、林黛玉     |
| 真实地址 | 脱敏处理     | 北京市→\[具体城市] |
| 联系方式 | 完全删除     | 电话、邮箱       |
| 内部数据 | 占位符替换    | 内部编号→\[编号]  |

**排查机制**：

* [ ] 无真实联系方式泄露

* [ ] 无内部数据直接暴露

* [ ] 脱敏标记统一格式

***

## 第九步：报告填写（分块写入策略）

> **禁止事项**：
>
> * **禁止在单次 Write 中传入超过 150 行的完整报告内容**
>
> * **禁止在生成内容被截断后，将截断内容直接写入文件**
>
> * **禁止在重试时从头生成并覆盖写入，而不检查之前是否已写入部分内容**

### 分块写入流程

| 步骤 | 操作工具            | 写入内容                                 | 预估行数    |
| -- | --------------- | ------------------------------------ | ------- |
| 1  | `Write`（覆盖）     | 头部 + 第一至三部分（数据来源 + 词汇统计 + 事件清单）      | \~100 行 |
| 2  | `SearchReplace` | 替换占位符为第四至六部分（5W1H+ 叙事要素 + 可视化）       | \~120 行 |
| 3  | `SearchReplace` | 替换占位符为第七至九部分（跨章对比 + 版本差异 + 校验记录）+ 尾部 | \~100 行 |

**具体操作流程**：

```
步骤 1：Write 写入骨架文件
- content 包含：文件头 + 第一部分 + 第二部分 + 第三部分 + 占位符标记
- 占位符格式：<!-- PLACEHOLDER_PART4_START -->
- 文件末尾保留占位符标记，供后续步骤定位替换

步骤 2：SearchReplace 追加第四至六部分
- old_str：<!-- PLACEHOLDER_PART4_START -->
- new_str：第四部分完整内容 + 第五部分完整内容 + 第六部分完整内容 + <!-- PLACEHOLDER_PART7_START -->
- 注意：new_str 末尾必须包含下一个占位符标记

步骤 3：SearchReplace 追加第七至九部分
- old_str：<!-- PLACEHOLDER_PART7_START -->
- new_str：第七部分 + 第八部分 + 第九部分 + 尾部（数据来源 + 声明 + 模板版本）
```

### 12.1 版本绑定机制

流程、模板、检测脚本三者必须版本绑定，确保一致性：

| 组件   | 当前版本   | 文件路径                   | 功能说明                 |

| 流程文件 | v3.1.0 | 《红楼梦》四合一分析报告\_生成流程.md  | 主流程手册（12 步 + 确认清单）   |

**版本对应关系**：流程 v3.1.0 = 模板 V2.3 = 检测脚本 v1.0.0 = 评估框架 v1.0.0（四位一体）

**不匹配时的处理**：

* 若脚本版本低于绑定版本 → 必须先升级脚本再执行生成

* 若模板版本低于绑定版本 → 必须先更新模板再执行生成

* 修改脚本或模板后 → 必须同步更新流程文件的版本号和变更日志

### 12.2 完整性检测指标（三重校验）

| 检测维度   | 检测内容             | 告警阈值     | 触发操作   |

### 12.3 复测触发条件

满足以下任一条件时，启动第 9.3 节复测机制：

1. 事件遗漏数量 > 3 个
2. 人物层级标注错误 > 2 处
3. 情感词覆盖率 < 70%
4. 文件大小异常（<15KB 或 >60KB）
5. 九大模块缺失 ≥ 1 个
