方式一（推荐，解压分发包）：把 `chenghu-jiegou-pipeline.zip` 解压到本机 WorkBuddy 用户级 skill 目录，解压后应为：

方式二（直接用仓库副本）：把本文件夹整体复制到 `~/.workbuddy/skills/` 下，保持目录名不变。安装后由 WorkBuddy 按 `SKILL.md` 的 `description` 自动触发，也可显式调用。

分发包与本目录的 7 个源文件已逐文件做过 SHA256 比对，内容完全一致。

## 快速开始

`P` 指安装后的 `~/.workbuddy/skills/chenghu-jiegou-pipeline/scripts/pipeline.py`。

```bash
# 0 探查底本并生成 config / 批次简报 / 输出目录（回数以底本实际文件数为准，自动校正）
python P init --root "<工作区根>" --book "<书名>" --book-dir "<书目录>" \
              --split-dir "<拆分底本目录名>" --chapters <声明回数>

# 1 底本 → 稿件映射与每 5 回的批次划分（补做时用 --missing-only）
python P plan  --config "<书目录>/chenghu.config.json" --batch 5

# 2 单篇成稿门禁（每回写完立刻跑）
python P check --config "<书目录>/chenghu.config.json" "<稿件.md>"

# 3 全书质检 + 生成进度表
python P qc     --config "<书目录>/chenghu.config.json"
python P readme --config "<书目录>/chenghu.config.json"
```

`init` 还可加 `--nieq-dir`（名词列锦目录，默认 `名词列锦章节`）、`--out-dir`（默认 `称呼学解构/整合版可查`）、`--events`（每回事件上限，默认 12；下限固定 10）、`--min-chars`（默认 15700）、`--batch`（默认 5）。配置写入 `min_events`＝10、`max_events`＝`--events`。

> 事件数不是配额：按「一次称谓变更／一次立场冲突／一次授权或拒绝」切分，10 件、11 件、12 件都合规，`check` 与 `qc` 对 <10 或 >12 报 ERROR；宁少一件不空转，不得为凑满上限把一件事拆成两件。这与原始模板 `称呼学整合版工作流包/03_模板骨架.md`「10–12 件，按情节先后」及 `02_硬性限制与质检清单.md` 一致。红楼样板 120 篇实测 108 篇 12 件、11 篇 11 件、1 篇 10 件；水浒 120 篇实测 91 篇 12 件、22 篇 11 件、7 篇 10 件。

所有路径由 `<书目录>/chenghu.config.json` 决定，**无书目硬编码**；`check`／`qc` 的码点归一化与既有 PowerShell 质检脚本 v2.1 一致，结果可互认。

## 五个子命令

| 命令 | 作用 |
| :--- | :--- |
| `init` | 探查底本、按实际文件数校正回数、生成 config／简报／输出目录 |
| `plan` | 底本→稿件映射、批次划分、缺口清单 |
| `check` | 单篇六节／计数守恒／引文锚定／密度／英文残留 |
| `qc` | 全书完整性 + 五维质检 + 汇总（通过条件：退出码 0、未锚定 0、篇数等于配置回数、无缺号无重号） |
| `readme` | 生成全书统计表、批次表、预判四题与适配参数 |

## 三条红线

1. **「」只放本回底本连续逐字原文**：不漏中间短句，不把并列／节选词塞进同一个「」，跨回一律转述。
2. **锚定通过 ≠ 归属正确**：每条「谁称谁」另过归属门（施称者／受称者／引语三格）。
3. **执行单元只改指定回次文件**：不改 README、不跑全局质检、不碰范围外稿件；批量后复核修改时间与「」计数。

单篇硬规格摘要：字符 ≥ 15,700；**10–12 件**称呼事件且 §1 表 1–N 连续（N＝10–12）；`###` 重点解构恰 3 段；定律表 55–72 行；「」185–215 处且全部锚定；六节 `## 0.`…`## 5.` 齐全；头标含系列标注 `(N/总回数)` 与「拆分底本」【A】锚；尾注「（注：…）」+ 独立末行 `> AI生成`；全文简体中文。完整规格见 `references/spec.md`。

- 阶段 0 必须先数底本文件数，不沿用上一部书的回数（三国曾误按 100 回推进、漏做尾部 20 回）。

- 未经用户明确说「同步／提交」，不 commit、不 push。
