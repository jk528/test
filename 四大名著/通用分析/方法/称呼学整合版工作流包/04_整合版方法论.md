## 1. 生成机制

### 1.1 输入权威分级（两条线路共用）

| 级 | 来源 | 用途 | 权威性 |

### 1.2 八阶段（对齐工作流包 01_SOP）

A 备料（定位底本／读旧稿只取事件与错漏）→ B 定调（一句话＋十问速查＋十二件分布＋判定表）→ C 切事件（五列表＋事件链读法）→ D 三段重点（每段以"判语："收束）→ E 四层观察（L1 词库／L2 生成／L3 执行／L4 治理，各 3–5 条）→ F 定律表（①→⑫→跨层，55–60 行）→ G 钩连（前回／后文／体系／预判四题）→ H 自检交付（跑质检、按标准名入库）。

### 1.3 事件切分与编号

- 切分单位是"一次称谓变更／一次立场冲突／一次授权或拒绝"，不是段落。
- 每件五列：`#｜事件（原文锚）｜四维定位｜层位/件｜命中`；四维＝场／单位／极性／通道。
- 层位**只写理论件号**（①亲缘网…⑫成本底账），不写 L1–L4 当层名；一件可标两件，用"；"分隔。
- 补件仍用 **Nb 编号**（1b／4b），不重排；声明格式注明含 b 行。

### 1.4 归属核查

写关键引文前回看前后 50–100 字确认说话人。高危场景：多人密集对白、咕哝与悄悄话、"某某道"后嵌套转述。旧 058 曾把"贾母托薛姨妈入园"写成"薛家送"，即主语未核。

> **归属核验细则见** [`05_称呼归属核验与防错清单.md`](05_称呼归属核验与防错清单.md)：五类错误（主客倒置／施受倒置／张冠李戴／关系错标／引文不存在）、五个高危位置、核验四步法与三格模板、交付前七项硬门。2026-11-25 复核 001–080 确认的 65 处同类错误及其对照样本均收录其中。

## 2. 验证机制

### 2.1 五维质检＋整合版增项

| 维 | 检查项 | 整合版增项 |
| :--- | :--- | :--- |
| 结构 | §0–§5 齐全、头标、尾注、AI 尾标 | 十问表 10 行、十二件分布 12 行、判定表 |
| 计数 | 声明＝表行＝尾注；###＝3 | 与 README 本线路累计一致 |
| 字符 | 零宽字符＝0、错字＝0 | 16–18k 区间 |
| 锚定 | 「」≥12 字归一化后子串匹配 | **跨回引文一律不得用「」** |
| 完整 | 【A】锚存在 | 每条命中含原文锚＋机理＋规律句 |

### 2.2 锚定算法与处置

按 `……|＋|——` 分段，≥12 字者做码点归一化（剥离控制符、空格三系、零宽与私用区 U+E000–F8FF、变体选择符、ASCII 与全角标点、中文标点）后 `Contains` 匹配。未命中三选一：改从底本逐字录／补省略号／异文照录＋注记。**禁止放着不管。**

### 2.3 计数守恒

每回三处一致 → 本线路 README 累计，README 各记各的账（人读版线路已归档，不再另计）。质检输出头行的"声明事件总数"即本目录合计，应与 README §2 表尾一致，不一致先查是否有同回双文件或半成品残留。

### 2.4 密度目标

字符 16,000–18,000；定律行 55–60；「」185–200；事件 10–12；每段重点 3 个 `###`。宁可少一件事件，不可让命中条目空转。
字符略超上限（如 073 回 18,414）而质检通过时，不再为凑数压缩，只在 README 表内如实登记；「」超过 200 则必须删冗余短引，不得删长引。

## 4. 理论引用规范

- 头标一行回指 `称呼学\称呼逻辑思维总架构`；正文用**件号＋定律编号**，不重复定义体系概念。
- 双公式：生成＝立场×见识×智慧×对话者；通信＝WHO×STANCE×MOOD×CHANNEL×LEXEME。
- 攻防用 21 燃料／22 靶心／23 真值；三方用 To/CC/BCC；成本用 25 handicap／26 账本不对称。
- 新命题先入当回 §4 与 README 要点，工程完结再评估升格体系，**施工期不改图纸**。

## 5. SOP（批量推进，059 起定型）

```
A 读 README（本线路）确认下一回号与累计数；按 4–6 回切一批
B 每回一通：精读底本 → 八阶段成文 → 写入 整合版可查\标准名
C 每篇写完跑质检，本回未锚定须为 0；并发时只认本回结果行
D 整批落盘后，全目录再跑一次质检（退出码 0、未锚定 0）
E 回填 README（篇目表＋累计件数＋批次状态），偏差写入备注
F 用户说"同步"才 commit/push
```

并行建议：同一时刻 2–3 个任务，每个任务只负责一回，提示词须给全底本路径、055 锚、01/02/03 文档路径与全部红线；并发期间出现的"他回异常"报告一律不处理，留待整批复核。
