# 天翼云盘签到逆向过程

> 独立文档：记录天翼云盘（cloud.189.cn）每日签到接口的逆向与实测过程，
> 含密码链路撞设备锁（result=-133）的失败教训与最终 Cookie 方案，可脱离原项目单独阅读。

## 一、目标

实现天翼云盘每日签到的全自动：不打开网页/客户端，直接调用后端 API 领取每日空间奖励。

## 二、关键结论

| 项 | 值 |
|---|---|
| 签到接口 | `GET https://cloud.189.cn/mkt/userSign.action?rand=<ts>&clientType=TELEANDROID&version=8.6.3&model=SM-G930K` |
| 签到接口（旧密码链路） | `GET https://api.cloud.189.cn/mkt/userSign.action?...`（同参，移动端 UA + `Referer: m.cloud.189.cn/zhuanti/...`；2026-10-25 已随密码登录链路整体从脚本删除） |
| 鉴权方式（推荐链路） | 请求头 `Cookie: COOKIE_LOGIN_USER=...; JSESSIONID=...`（cloud.189.cn 网页登录态） |
| 关键请求头 | `Referer: https://cloud.189.cn/web/portal.html`、桌面 UA |
| 成功判定 | 返回 JSON 含 `isSign`（今日是否已签）与 `netdiskBonus`（累计空间奖励 MB） |
| 幂等 | 已签返回 `isSign=true`，视为成功 |
| 签名/加密 | 签到请求本身**无签名**；难点在登录态获取 |
| Cookie 有效期 | 经验值数月~一年，改密码即失效 |

## 三、逆向步骤

### 1. 第一选择：账号密码登录链路（撞墙，教训记录）

密码登录链路移植自 cloud189-sdk / [vistal8/tianyiyun](https://github.com/vistal8/tianyiyun)，
PC 端流程四步：

```
POST open.e.189.cn/api/logbox/config/encryptConf.do
      → 拿 RSA 公钥 pubKey 与前缀 pre
GET  cloud.189.cn/api/portal/unifyLoginForPC.action?appId=8025431004&clientType=10020&...
      → 从 HTML 正则提取 captchaToken / lt / paramId / reqId
POST open.e.189.cn/api/logbox/oauth2/loginSubmit.do
      → 表单提交 userName/password（RSA 加密、hex 输出、加 pre 前缀）
      → 请求头必须带 lt + REQID
GET  响应里的 toUrl → 建立会话（写 SSON 等 Cookie）
```

**实测撞墙**：账号开启设备锁后，`loginSubmit.do` 返回
`result=-133 "设备ID不存在，需要二次设备校验"`（短信二次验证），
wap 链路与 PC 链路均如此——**密码登录无法全自动**，脚本里只保留为兜底。

教训：凡接天翼账号体系自动化，先假设目标账号开了设备锁；
`-133` 出现即放弃密码链路，不要尝试绕过二次验证。

### 2. 最终方案：Cookie 模式（绕过设备锁）

浏览器正常登录 cloud.189.cn 网页版后，登录态由 Cookie 承载。
实测结论：**`COOKIE_LOGIN_USER` + `JSESSIONID` 两个 Cookie 即可直接调用
`mkt/userSign.action`**，完全绕开设备锁校验。

签到响应：

```json
{ "isSign": true,  "netdiskBonus": 1900, "signTime": "..." }
```

`isSign=false` 表示本次是新签；`isSign=true` 表示今日已签（幂等成功）。

### 3. 凭证自动提取：不让用户手动抓包

手动复制 Cookie 给普通用户太麻烦，且失效后又要重来。
利用浏览器本地 Cookie 库实现**自动提取 + 失效自动续期**（以夸克浏览器为例，
Chromium 系通用，改路径常量即可换 Chrome/Edge）：

```
%LOCALAPPDATA%\Quark\User Data\Default\Network\Cookies   (SQLite)
%LOCALAPPDATA%\Quark\User Data\Local State               (os_crypt.encrypted_key)
```

提取链路（全部是已公开的技术，无机密外泄）：

1. Cookie 库被运行中的浏览器独占 → 先尝试直接拷贝；失败则
   `vssadmin create shadow /for=C:` 建卷影 → `mklink /d` 符号链接进卷影 → 拷出数据库
2. `Local State` 的 `os_crypt.encrypted_key` 去掉前 5 字节 `DPAPI` 前缀
   → Windows DPAPI(CurrentUser) 解密得 AES-256-GCM 主密钥
3. Cookie 值是 `v10` 信封：`3B 前缀 + 12B nonce + 密文 + 16B tag`，AES-256-GCM 解密
4. **新版 Chromium 陷阱**：解密明文前 32 字节是 `SHA256(host_key)`，比对剥除，
   否则拿到的 Cookie 带垃圾前缀
5. SQLite 查询用 Node 内置 `node:sqlite`（Node 22.5+），
   注意**不能 SELECT `expires_utc`**（大整数会溢出报错）

脚本策略（三级降级）：

```
Cookie 直接签到 → 失效则自动从浏览器重新提取并回写配置，重试一次
→ 提取也失败才走账号密码登录（可能撞设备锁 -133，需人工网页端过验证）
```

### 4. 幂等性与保活

- 已签：接口返回 `isSign=true`，脚本视为成功（退出码 0），定时任务重复触发安全
- Cookie 失效特征：签到接口返回非 JSON（HTML 登录页）或缺少 `isSign/netdiskBonus`
  → 自动触发浏览器重新提取，浏览器仍登录 cloud.189.cn 即可全自动恢复
- DPAPI 密钥绑定 Windows 当前用户：**换 Windows 账号或系统重装后需重新登录浏览器**

### 5. 已知风险点

| 风险 | 影响 | 预警信号 |
|---|---|---|
| 天翼改签到接口鉴权（校验 clientType 真实性） | Cookie 模式失效 | 返回"请使用客户端签到"类错误 |
| 浏览器升级改 Cookie 加密方案（v10→v20） | 自动提取失效 | 提取报密文前缀不符 |
| 出现图形验证码 | 属风控 | 网页端手动登录解除后再运行 |

## 四、落地调用链

```
config/tianyi_config.json 读 Cookie（可空）
      │
      ▼
GET cloud.189.cn/mkt/userSign.action ──► isSign=true? 已签结束
      │ Cookie 失效
      ▼
夸克浏览器 Cookie 库提取（VSS 卷影 + DPAPI + AES-GCM v10 + 剥 SHA256 前缀）
      │ 回写 tianyi_config.json
      ▼
重试签到（仅一次）
      │ 提取失败且配置了账号密码
      ▼
密码 RSA 登录兜底（loginSubmit.do；撞 -133 设备锁则报错提示人工）
```

- **零依赖**：只用 Node 内置模块（`fetch` / `crypto` / `node:sqlite` / `child_process`）
- **无硬编码凭证**：Cookie 来自配置文件，失效自动从本机浏览器续期
- **随机延迟**：默认签到前随机等待 30~300 秒防检测（`--no-delay` 可跳过，
  范围可在上级 `config.json` 调整）

## 五、合规说明

本逆向仅涉及读取并解密本机当前用户自己浏览器的 Cookie（DPAPI 限定当前用户解密），
调用平台自身网页端使用的公开接口，未绕过任何服务端校验（设备锁等照实规避而非破解）。
仅限个人学习研究，请遵守平台条款。Cookie 等同登录态，配置文件绝不入库。
