# Trae 环境与配置检查清单

> 使用前逐项核对；缺失项按「解决方案」列处理。最后一节有一键自检命令。

## 一、运行环境

| 项 | 要求 | 检查方法 | 缺失解决方案 |
|---|---|---|---|
| 操作系统 | Windows 10/11 | — | 不支持其他系统 |
| Node.js | 18+（可选） | `node -v` | 官网安装即可；未安装时 `run_checkin.cmd` 自动依次兜底：`C:\Program Files\nodejs\node.exe` → 注册表探测到的 `Trae CN.exe`（ELECTRON_RUN_AS_NODE=1 模式运行） |
| Trae CN 客户端 | 已安装且已登录 | 数据目录 `%APPDATA%\Trae CN\User\globalStorage\storage.json` 存在（旧版客户端为 `%APPDATA%\TRAE SOLO CN\` 下同路径） | 安装 Trae CN 客户端并登录 |
| 登录态数据 | storage.json 内含加密登录态（`iCubeAuthInfo://icube.cloudide`），可解密出 token | 自检命令输出「检测到数据目录」且不报「未找到登录态数据」 | 打开 Trae 客户端确认已登录；报「登录态已过期」时重新登录客户端，脚本下次运行自动读取新凭证 |
| 设备信息 | aha 网络组件配置中的 device_id：`%APPDATA%\Trae CN\ahanet\tt_net_config.config`（旧版本在 `ModularData\ttnet\` 或 `ModularData\ckg_server\local_env.json`） | 脚本自动多候选探测，输出不含「未找到设备 ID」即正常 | 可缺省（脚本仅警告），但签到可能被拒；登录客户端后通常自动生成 |
| 网络 | 可访问 `https://api.trae.cn` | `curl https://api.trae.cn` | 检查网络 / 代理设置 |

## 二、基础配置清单

| 配置项 | 位置 | 必填 | 默认值 | 缺失/失效解决方案 |
|---|---|---|---|---|
| delayMinSec / delayMaxSec | config.json | 否 | 30 / 300 | 删除 config.json 即用默认 |
| 计划任务 | 注册计划任务.ps1 | 否（仅手动运行则无需） | 每天 00:10 | 运行一次 `.\注册计划任务.ps1`；`-Time "09:30"` 改触发时间，`-Remove` 卸载 |

无需任何手填密钥类配置：凭证由脚本自动从本机客户端数据目录解密取用。

## 三、一键自检

```powershell
.\scripts\run_checkin.cmd --status --no-delay
# 退出码 0 = 环境与凭证就绪；非 0 按上方清单逐项排查
```
