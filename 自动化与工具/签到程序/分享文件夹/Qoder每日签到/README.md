# Qoder 每日签到（独立模板）

读取 Qoder 客户端本地登录态，自动领取「每天领 100 Credits」活动奖励。**不需要账号密码**，凭证不离开本机。
纯 Node 零依赖（Node 18+；没有装 Node 也能用 Qoder 客户端自身兜底运行）。

> **⚠️ 重要：计划任务时间不能早于 10:30！**
> Qoder 签到活动**每日 10:00（UTC+8）才刷新**生成当天活动。凌晨或早上 10 点前运行必然扑空
> （脚本会提示「今日活动尚未刷新」并跳过）。模板默认触发时间 **10:40**。

## 前置条件

| 条件 | 说明 |
|---|---|
| Qoder 客户端 | 已安装且**已登录**（国内版 Qoder CN 或国际版 Qoder 均可，脚本自动探测） |
| 客户端不可卸载 | 风控请求头依赖客户端自带的 `runtime-info.exe` 设备指纹程序，卸载客户端后签到失效 |
| Node.js 18+ | 可选。没装的话 `run_checkin.cmd` 会尝试用 Qoder 客户端自带的运行时兜底 |
| Windows | 脚本与计划任务配置均面向 Windows |

## 目录结构

```
Qoder每日签到/
├── README.md              # 本文件（统领）
├── config.json            # 可选配置：随机延迟范围
├── 注册计划任务.ps1        # 一键注册/卸载每日计划任务（默认 10:40）
├── scripts/
│   ├── qoder_checkin.js   # 签到主脚本
│   └── run_checkin.cmd    # 入口（自动探测 Node 运行时）
├── docs/
│   └── Qoder签到逆向过程.md # 接口逆向过程（独立文档）
└── logs/                  # 运行日志（注册计划任务后自动生成）
```

## 快速开始（3 步）

```powershell
# 1. 确认 Qoder 客户端已登录，然后手动测试一次
.\scripts\run_checkin.cmd --no-delay

# 2. 注册计划任务（默认每天 10:40，切勿早于 10:30）
.\注册计划任务.ps1

# 3. 手动触发验证 + 看日志
Start-ScheduledTask -TaskName "Qoder每日签到"
Get-Content .\logs\checkin.log -Tail 20
```

## 配置说明

**config.json**（都可删除，删除后用默认值）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `delayMinSec` | 30 | 随机延迟下限（秒） |
| `delayMaxSec` | 300 | 随机延迟上限（秒） |

**计划任务**：`.\注册计划任务.ps1 -Time "11:30"` 改触发时间（**必须 ≥ 10:30**，脚本会对过早的时间发出警告）；`-Remove` 卸载。

**命令行参数**：

| 参数 | 说明 |
|---|---|
| `--no-delay` | 跳过随机延迟（手动测试用） |
| `--status` | 只查询活动列表与领取状态，不执行领取 |

## 常见问题

| 报错/现象 | 原因与处理 |
|---|---|
| `未找到 Qoder 登录态` | 客户端未安装或未登录，打开 Qoder 客户端登录即可 |
| `登录态已失效，请打开 Qoder 客户端重新登录` | token 与 refreshToken 均失效，重新登录客户端（脚本下次运行自动读取新凭证） |
| `今日活动尚未刷新（每日 10:00 刷新）` | 运行时间早于当天 10:00，属正常跳过；把计划任务调到 10:30 之后 |
| `未找到设备指纹程序` | Qoder 客户端被卸载/移动，重装客户端 |
| `No Node.js runtime found` | 安装 Node 18+，或确认 Qoder 客户端存在 |
| 计划任务秒退码 1 且无日志 | 文件夹路径含空格，移到无空格路径重新注册 |

凭证维护基本不用操心：token 临期（<3 天）脚本会自动刷新并加密写回客户端登录态文件
（refreshToken 有效期约 1 年）；彻底失效时重新登录客户端即可，无需改任何配置。

## 原理简介

签到接口与请求头来自对 Qoder 客户端的逆向分析，完整过程见
[docs/Qoder签到逆向过程.md](docs/Qoder%E7%AD%BE%E5%88%B0%E9%80%86%E5%90%91%E8%BF%87%E7%A8%8B.md)。简要链路：

```
auth.v1.dat 读加密登录态 → DPAPI 取主密钥 + AES-256-GCM 解密 → (临期自动刷新)
→ runtime-info.exe 生成设备指纹 → GET campaigns → POST claim → 复查
```
