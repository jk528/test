# 百度网盘签到逆向过程

> 独立文档：记录百度网盘会员每日签到接口的来源与实测结论，可脱离原项目单独阅读。

## 一、目标

实现百度网盘（pan.baidu.com）会员成长体系的每日自动签到：
不打开网页，直接调用后端 API 完成签到 + 每日答题领积分。

## 二、关键结论

| 项 | 值 |
|---|---|
| 签到 | `GET https://pan.baidu.com/rest/2.0/membership/level?app_id=250528&web=5&method=signin` |
| 每日答题（取题） | `GET https://pan.baidu.com/act/v2/membergrowv2/getdailyquestion?app_id=250528&web=5` |
| 每日答题（提交） | `GET https://pan.baidu.com/act/v2/membergrowv2/answerquestion?app_id=250528&web=5&ask_id=<id>&answer=<ans>` |
| 成长值查询 | `GET https://pan.baidu.com/rest/2.0/membership/user?app_id=250528&web=5&method=query` |
| 鉴权方式 | 请求头 `Cookie: BDUSS=...; STOKEN=...; BAIDUID=...`（浏览器登录态整段复制） |
| 关键请求头 | `User-Agent`（移动端 UA）、`Referer: https://pan.baidu.com/wap/svip/growth/task`、`X-Requested-With: XMLHttpRequest` |
| 签名/加密 | **无签名**，纯 Cookie 鉴权 |
| 幂等 | 重复签到返回 `error_code=421001 repeat signin`，脚本视为成功 |
| Cookie 失效特征 | 签到返回 `errno=-6`（未登录类错误） |

## 三、逆向/移植步骤

### 1. 接口来源：开源社区已验证的端点

接口不是从零抓包得来，而是移植自青龙签到社区的
[tunecc/DuPan](https://github.com/tunecc/DuPan)（Python），改写为零依赖 Node.js。
三个接口均属会员成长体系（wap 端任务页 `pan.baidu.com/wap/svip/growth/task` 实际调用的后端），
公共参数固定 `app_id=250528&web=5`，全部为 GET 请求，无任何签名参数。

### 2. 凭证定位：只要浏览器 Cookie

百度网页端的登录态完全由 Cookie 承载，核心字段：

- `BDUSS`（约 192 字符，主登录态，必需）
- `STOKEN` / `PTOKEN` / `BAIDUID` / `csrfToken`（建议一并带上）

获取方式：浏览器登录 pan.baidu.com → F12 → 网络 → 点任意发往 pan.baidu.com 的请求
→ 复制请求头里的 Cookie 整段，填入 `config/baidupan_config.json`。
有效期经验值数月，修改密码或安全设置即失效。

### 3. 每日答题是「白送分」

`getdailyquestion` 的响应里**直接带有正确答案**（`answer` 字段）和题目 ID（`ask_id`），
把它原样提交给 `answerquestion` 即可拿分。实测签到后答题 +3 积分。

### 4. 响应字段嵌套的坑

成长值查询接口的响应 JSON 层级比文档预期深（会员信息嵌在
`current_product` / `current_product_v2` 等结构里），按固定路径取值经常拿到 `undefined`。
解决：递归 `deepFind` 在整棵 JSON 树里搜 `current_value` / `current_level`。

### 5. 幂等性确认

今日已签到时 signin 接口返回 `error_code=421001，error_msg=repeat signin`。
脚本用正则 `/421001|repeat/i` 识别该响应并视为成功（退出码 0），
因此定时任务重复触发、手动补跑都安全。

### 6. 凭证保活

Cookie 失效表现：signin 返回 `errno=-6` 或查询接口拿不到会员信息。
处理方式：浏览器重新登录 pan.baidu.com 后重新复制 Cookie 覆盖配置即可，
脚本本身无需任何改动。

## 四、落地调用链

```
config/baidupan_config.json 读 Cookie
      │
      ▼
GET membership/level?method=signin ──► error_code=421001? 已签则跳过
      │
      ▼
GET getdailyquestion ──► 响应自带 answer + ask_id
      │
      ▼
GET answerquestion?ask_id=..&answer=.. ──► score 入账
      │
      ▼
GET membership/user?method=query ──► 复查等级/成长值
```

- **零依赖**：只用 Node 18+ 内置模块（`fetch` / `fs`）
- **无硬编码凭证**：Cookie 全部来自本地配置文件，环境变量 `BAIDUPAN_COOKIE` 可覆盖
- **随机延迟**：默认签到前随机等待 30~300 秒防检测（`--no-delay` 可跳过，
  范围可在上级 `config.json` 调整）

## 五、合规说明

本逆向仅涉及使用本人账号的浏览器登录态，调用平台自身网页端使用的公开接口，
未绕过任何服务端校验。仅限个人学习研究，请遵守平台条款。
Cookie 等同登录态，请勿分享或入库。
