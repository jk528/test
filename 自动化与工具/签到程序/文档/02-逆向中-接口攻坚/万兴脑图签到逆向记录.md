## 二、APK DEX strings 提取法（核心方法）

网页版没有入口时，接口路径盲猜全 404。标准动作：

1. 获取 APK（官网/应用商店/分享链接），改名 `.zip` 解压
2. 取 `classes.dex`、`classes2.dex` …（约 90MB 包）
3. 提取连续可打印 ASCII 字符串（≥4 字符）
4. **先搜类名**确认功能存在：`CheckInPresenter`、`ClockIn` → 命中，确认 APP 内有签到模块
5. **再搜接口路径**：`/api/` 开头的字符串 → 找到 `userapi.edrawsoft.cn` 域名下的端点
6. 用浏览器 Cookie 里的 token 逐个实测端点（GET 405 响应会提示应使用 POST）

### 提取到的接口

| 端点 | 方法 | 用途 |
|---|---|---|
| `https://userapi.edrawsoft.cn/api/user/{uid}/clockin` | POST | 签到（重复签到返回 `already check in`，幂等） |
| `.../clockin/list` | GET | 本周 7 天签到状态数组，如 `[1,1,1,1,1,1,1]` |
| `.../point` | GET | 当前积分余额 |

### 关键幸运点

**接口只要 Bearer token，无任何动态签名参数**（不像夸克网盘的 kps/sign/vcode），因此无需逆向签名算法，直接打通。

## 三、凭证方案：refresh_token 自续命（二次逆向后重构）

> ⚠️ 本节初版结论「JWT 仅 2 小时、每次现从浏览器提取 Cookie」**已被推翻**——
> 该方案下每天 10:35 计划任务必撞 token 过期（浏览器 Cookie 是凌晨前写入的）。
> 二次逆向找到刷新接口，改为自续命闭环，详见第六节。初版思路保留备查：

- 鉴权 token 藏在夸克浏览器 Cookie `EDCurrent` 中（JWT 格式）
- ~~**JWT 有效期仅 2 小时** → 预存到配置文件没有意义~~
- ~~改为**每次签到运行时现从浏览器提取**~~ → **已废弃**，现仅作为兜底路径
- 兜底保留价值：config 凭证失效时，用户重新登录后脚本可从浏览器再提取 refresh_token

**注意事项**：EDCurrent 是**会话 Cookie**——浏览器进程彻底退出（服务器重启/杀进程）即失效，需重新登录网页版。

## 六、二次逆向：refresh_token 自续命闭环（2026-10-25 下午）

### 6.1 起因

EDCurrent 的 access token 经解码确认 **exp 硬编码 2 小时**（HS256，iss=EdrawSoft），
每天 10:35 计划任务必过期。浏览器 Cookie/localStorage/Session Storage/IndexedDB
全域扫描均无可用 refresh token → 回 APK 找刷新机制。

### 6.2 定位过程（DEX strings + 网页版 JS 双路印证）

| 步骤 | 发现 |
|---|---|
| classes2.dex 搜 refresh | `ws/account/refresh/token`、`RefreshTokenWorker`、`WS_USER_REFRESH_TOKEN` |
| 域名矩阵探测 | account.edrawsoft.cn 的 `ws/` 是静态站（GET 回 SPA、POST 405）；goapi 全 404 |
| 账号中心 SPA（edapp.js） | 配置 `(c=o)&&(d.wsidUrl="https://goapi.edrawsoft.cn/")` → `ws/` 前缀归属 goapi |
| **路径拼接实测** | **`POST goapi.edrawsoft.cn/api/user/ws/account/refresh/token` → 400 `The refresh_token field is required`（路由确认！）** |
| mm 网页版主包（index-*.js） | 找到生产代码 `refreshToken()`：`goHttp.post("/user/ws/account/refresh/token", {data:{refresh_token}})`，响应 `{token, refresh_token}` 回写 EDCurrent Cookie，过期前 90 秒自动调度 |

### 6.3 最终接口

```
POST https://goapi.edrawsoft.cn/api/user/ws/account/refresh/token
Content-Type: application/x-www-form-urlencoded
Body: refresh_token=<JWT>

→ 200 {"status":"success","data":{"token":<新2h token>,"refresh_token":<轮换新refresh_token>}}
```

- **access token**：2 小时有效（签到用，即用即抛）
- **refresh_token**：**30 天有效，每次刷新轮换**（旧立即失效）→ 必须每次保存新值
- 错误应答：缺字段 400 code-633；签名错误 401 `signature is invalid`

### 6.4 凭证来源（关键坑）

- `refresh_token` 只在**登录响应的 ws_info** 里下发，浏览器不单独持久化
- EDCurrent Cookie 是否含 `refresh_token` 字段取决于登录入口：
  账号中心/旧流程 `refreshMode:0` → 不含；**mm 网页版 mm.edrawsoft.cn/app `refreshMode:"1"` → 含**
- localStorage 里 mm 域下的 `access_token`/`refresh_token` 键是**文档协作服务**的
  HS512 令牌（`sub=weixin_*`），与账号刷新接口**签名域不同**，误用报 `signature is invalid`
- 因此启动方式：**在夸克浏览器对 mm.edrawsoft.cn/app 退出并重新登录一次**，
  EDCurrent 即带 refresh_token，脚本提取一次后进入自续命

### 6.5 自续命实现（edraw_checkin.js 重构）

```
读 config/edraw_config.json 的 refresh_token（30d）
  → 调刷新接口换新 token + 轮换 refresh_token
  → 先保存新 refresh_token 到 config（再签到，防凭证丢失）
  → 用新 token 签到
  → 兜底：config 失效时 VSS+DPAPI 从浏览器 EDCurrent 再提取
```

每天运行 = 每天轮换，30 天有效期永远用不完，**理论上永久免维护**。
实测：刷新 200 ✓ 状态查询 ✓ 签到链路 ✓（2026-10-25 11:21）

### 6.6 方法论沉淀

1. **「405 + Allow 头」是路由探测器**：405 说明路由存在但方法错，比 404 有价值
2. **静态站的 SPA fallback 会伪装 200**：GET 任何路径都回 index.html，必须用 POST 区分
3. **web 端主包是 APK 的解码器**：APK strings 给出路径碎片（`ws/account/refresh/token`），
   网页版 JS 给出 baseURL 拼接与请求形状（`goHttp.post` + `{data:{refresh_token}}`），两者互补
4. **同名 token 分属不同签名域**：leveldb 里扫到的 JWT 不一定是目标服务的，
   看 `iss`/`sub`/alg 字段区分（HS512+weixin sub = 协作服务；HS256+EdrawSoft iss = 账号服务）
5. **登录入口参数决定凭证内容**：`refreshMode:0/1` 影响 Cookie 是否带 refresh_token，
   找不对入口永远拿不到完整凭证

### 7.2 凭证体系：两个签名域，别混用

```
登录响应 (login / auth 流程)
  │
  ├─► 账号族令牌 (HS256, iss="EdrawSoft")
  │     ├─ token (2h)                  → 签到 / 积分 / 用户信息
  │     └─ refresh_token (30d, 轮换)   → goapi 刷新接口 → 存 config 自续命
  │
  └─► 协作族令牌 (HS512, sub="weixin_*", 带 authorities)
        ├─ access_token (24h)          → wss 文档协作连接
        └─ refresh_token (60d)         → 与签到刷新接口【签名域不同】,
                                         误用报 "signature is invalid"
```

载体分布：

| 端 | 账号族令牌 (HS256) | 协作族令牌 (HS512) |
|---|---|---|
| 手机 APP | SharedPreferences：`WS_USER_ACCESS_TOKEN` / `WS_USER_REFRESH_TOKEN` | 同处一并存储 |
| 网页版 | `EDCurrent` Cookie（**refreshMode=1 入口登录才含 refresh_token**） | localStorage：`access_token` / `refresh_token` 等键 |


### 7.4 签到调用链（最终形态）

```
edraw_checkin.js
   │
   ├─ 1. 读 config/edraw_config.json { user_id, refresh_token }
   │     （缺失/过期 → 兜底：VSS+DPAPI 解浏览器 EDCurrent 重提取）

```
