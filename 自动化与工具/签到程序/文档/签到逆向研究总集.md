## 二、各平台逆向要点

### 2.1 TraeWork（TRAE SOLO CN）

**数据目录**：`%APPDATA%\TRAE SOLO CN\`

**token**：`User\globalStorage\storage.json` → `iCubeAuthInfo://icube.cloudide`（Base64 加密）

**解密**：Base64解码→提取key(32B)→SHA-512(key)→XOR(ure,dre)→拼接[SHA-512(key)+XOR]→SHA-512→取前16B=AES密钥,16-32=IV→AES-128-CBC解密→去掉前64B→明文JSON

**接口**：
- POST `https://api.trae.cn/trae/api/v2/ug/checkin_credits/status` body=`{"req_source":2}`
- POST `https://api.trae.cn/trae/api/v2/ug/checkin_credits/claim` body=`{"req_source":2}`

**鉴权**：`Authorization: Cloud-IDE-JWT <token>` + `x-device-id`(纯数字) + `x-device-type` + `x-app-version`

**踩坑**：`req_source` 必须为 2（缺报 9004）；`x-device-id` 必须纯数字（UUID 报 9074）；解密后 JSON 前 64 字节是垃圾需 `slice(64)`

### 2.2 Trae CN

**数据目录**：`%APPDATA%\Trae CN\`，仅数据目录不同，解密代码复用 `decryptTrae()`

**额外踩坑**：`product.json` 配域名 `api.trae.com.cn` 返回 404，实际是 `api.trae.cn`

### 2.3 TeleAgent

**数据目录**：`%USERPROFILE%\.local\share\TeleAgent\`

**token**：`users\<uid>\app-auth\token.json` → `encryptedToken`（v10 OSCrypt）；主密钥 `Local State` → `os_crypt.encrypted_key`（DPAPI）

**解密**：Local State→DPAPI→32B主密钥→encryptedToken→"v10"+nonce(12)+ct+tag(16)→AES-256-GCM→JWT

**接口**（网关 `agent.teleai.com.cn/superCowork/sapi`）：
- GET `/user/portal/companyStore/v2/checkDayTask`
- GET `/user/portal/companyStore/checkTask?type=daily_login`
- GET `/user/portal/companyStore/userCenter`

**鉴权**：`X-Token` + `X-Timestamp` + `X-Nonce` + `X-SuperAgent-Device-Id` + `X-OS-Type`，无签名

### 2.4 WorkBuddy（CodeBuddy）

**数据目录**：auth 文件在 `%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\`（不在 `.workbuddy` 下）

**token**：`workbuddy-desktop.info` → v1 明文 JSON / v2 `$wbEncrypted` 信封（AES-256-GCM + AAD `WB-AAD\0`），密钥来自 `WorkBuddy.exe` native `atRestSecretKey`→`sha256`

**接口**（网关 `copilot.tencent.com`）：
- POST `/billing/meter/checkin-activity-status` body=`{}`
- POST `/billing/meter/daily-checkin` body=`{}`

**鉴权**：`Authorization: Bearer <token>` + `X-User-Id`，Turing Token 可选

### 2.5 Qoder

**数据目录**：`%APPDATA%\com.qodercn.app.stable\`

**token**：`auth.v1.dat`（v10 加密），主密钥 `Local State`→DPAPI，机器 ID `auth.machine-id`

**接口**（网关 `openapi.qoder.com.cn`）：
- GET `/sash/api/v1/me/campaigns` — 查活动
- POST `/sash/api/v1/me/campaigns/<campaignId>/claim` — 领取（路径从活动页 CDN JS 逆向）
- POST `/api/v1/deviceToken/refresh` — token 刷新

**鉴权**：`Bearer` + 9 个 `Cosy-*` 头（含 `runtime-info.exe` 动态指纹：spawn exe，stdin 传 account，stdout 出 machineToken/Type/Code）

**活动规则**：每日 10:00 刷新，CLAIMABLE 时可领 100 Credits，当天不领作废

### 2.6 CodeArts Agent

**数据目录**：`%APPDATA%\codearts-agent\` + `%USERPROFILE%\.codeartsdoer\`

**token**：`state.vscdb` SQLite 键 `secret://{"extensionId":"huaweicloud.authentication","key":"HuaweiCloudSession"}`→v10 OSCrypt

**解密**：Local State→DPAPI→32B主密钥→state.vscdb→"v10"+nonce+ct+tag→AES-256-GCM→{accessKey,secretKey,securitytoken,expires_at,refresh_token}

**鉴权**：IAM STS 三元组 → SDK-HMAC-SHA256 全头签名 + `X-Security-Token`

**接口**（网关 `snap-access.cn-north-4.myhuaweicloud.com`）：
- GET `/v1/ops/delivery?channel=IDE` — 活动列表
- POST `/v1/ops/claim` body=`{campaignId,idempotentKey,channel:"IDE"}` — 领取
- POST `/v1/ops/confirm` body=`{campaignId}` — 确认到账

**请求头**：`x-snap-traceid` + `Agent-Type: PromptCenter` + `X-Language: zh-cn` + `X-Sdk-Content-Sha256: UNSIGNED-PAYLOAD` + `X-Sdk-Date` + `Authorization`。**严禁带 `x-auth-token`（含空值）**

**运行前提**：客户端保持运行（STS 2h 有效，认证扩展每小时续期写回）

**关键踩坑**：noEscape 表手抄错位（256 位数组必须程序化从 kernel exe 提取）；delivery 必带 `?channel=IDE` 且 query 参与签名；必带 `Agent-Type: PromptCenter`

### 2.7 OfficeAce（果办）★ 2026-10-16 新增

**产品**：华为云 OfficeAce 1.3.4，本地 API 服务架构（Electron 启动 Node 子进程跑 `packages/api/dist/cli.js`）

**数据目录**：`%USERPROFILE%\.office-claw\`，安装目录 `C:\Users\Administrator\OfficeAce\`

**token**：`session.cookie` 文件，格式 `OC-DPAPI-1\n` + base64(DPAPI(CurrentUser, JSON{value, expires}))，解密出的 `value` 即 `oc_sid` Cookie 值

**本地 API 发现**（四层弹性策略）：
1. `runtime-state.json` 快照（`ApiPort`/`ApiUrl`）— 首选
2. `.env` 的 `API_SERVER_PORT`
3. 默认端口候选（3004/3002）
4. `netstat -ano` 全量回环端口扫描并发探测

探测判活：`GET /api/subscription/current` 返回 200/401 且响应体含果办特征（`bonusSkus`/`planId`）。当前命中 `https://127.0.0.1:3004`（HTTPS，自签三级 CA）

**TLS 信任**：`<安装目录>\.office-claw\certs\root-ca.pem`（root→middle→server 三级 CA 链）

**接口**（本地 API）：
- GET `/api/subscription/current` — 状态查询，返回 `bonusSkus[]`（`currentValue`=已消耗量非已领取量，入账看 `points`）
- POST `/api/subscription/claim-bonus` — 领取（须带 `Content-Type: application/json`，空体 `{}`）

**云端链路**：本地服务转发 → `POST {origin}/v1/subscription/bonus/claim`（V11-HMAC-SHA256 签名，AK/SK/securityToken 仅存本地服务内存）

**签到活动**：`bonus-daily-checkin-2026`「每日签到有礼」1000 积分/天，每日北京时间 00:00 刷新

**已签判定**：daily 记录的 `effectiveTime` = 实际领取时刻；落在今日北京时间 00:00 之后即今日已领。客户端每小时整点自动尝试领取，00:00:0X 即代领

**积分构成**：`totalCredits` = 基础 quota(500) + 生效 bonus 总额（500+4000新用户+1000签到=5500，每日刷新不累积）

**运行前提**：OfficeAce 客户端必须正在运行（本地 API 承载云凭证，无法离线直连）

**审计金矿**：`data\logs\api\premium-feature.ndjson` 记录每次云端调用的 method/url/status/requestBody/responseBody

## 五、跨项目踩坑总集

### 5.1 通用坑（多项目重复遇到）

| # | 问题 | 涉及项目 | 解决 |
|---|------|---------|------|
| 1 | rg 搜索 asar 报 "binary file matches" | TeleAgent/WorkBuddy/Qoder | 加 `-a` 强制文本模式 |
| 2 | 搜 `points/checkin` 上万条命中 | TeleAgent/WorkBuddy | 搜 UI 独有中文字符串当锚点 |
| 3 | PS 5.1 `ConvertFrom-Json` 解析大 JSON 失败 | TeleAgent/Qoder | 用 Node 解析 |
| 4 | asar 被进程占用无法 `File.Open` | WorkBuddy | 用 Node `fs.openSync('r')` 或 rg |
| 5 | PS 修改 JS 文件后 Node 报语法错误 | TeleAgent | PS 5 的 `Set-Content` 默认 ANSI，用 Write 工具 |
| 6 | 日志中文乱码 | 全部 | `Get-Content -Encoding UTF8` 读取 |
| 7 | 定时任务注册成功但不执行 | 全部 | `Test-Path "C:\Windows\System32\Tasks\任务名"` 验证 |
| 8 | cmd 批处理中文注释在 GBK 下变乱码命令 | Qoder | **cmd 文件一律英文注释** |
| 9 | 从自动化会话 `Start-ScheduledTask` 触发，进程被会话回收 ^C 杀掉 | Qoder | 定时自然触发不受影响 |
| 10 | Node 24 Windows 下 `process.exit()` 偶发 uv 断言噪音 | Qoder | 改用 `process.exitCode` 自然退出 |

### 5.2 各平台特有坑

| 平台 | 坑 | 解决 |
|------|---|------|
| TraeWork | `req_source` 缺失报 9004 | 请求体固定 `{"req_source": 2}` |
| TraeWork | 设备 ID 用 UUID 报 9074 | 用 `local_env.json` 里的纯数字 `device_id` |
| TraeWork | 解密后 JSON 前 64 字节是垃圾 | `dec.slice(64)` 去掉（rh=64） |
| Trae CN | `product.json` 配的 `api.trae.com.cn` 返回 404 | 实际域名是 `api.trae.cn` |
| TeleAgent | DPAPI 直接解 token 失败 | token 是 OSCrypt v10 格式，先解主密钥再 AES-GCM |
| TeleAgent | 密文头 `76 31 30` 不认识 | = ASCII "v10"，Chromium OSCrypt 版本前缀 |
| TeleAgent | asar JSON 起始偏移与网传不符 | hexdump 前 64 字节确认：JSON 从偏移 16 开始 |
| WorkBuddy | auth 文件不在 `.workbuddy` 下 | 逆向 `getAuthSavePath` 找到 `CodeBuddyExtension` |
| WorkBuddy | `EXTENSION_DATA_DIR_NAME` 不是 "WorkBuddy" | 底层是 CodeBuddy 体系，值为 "CodeBuddyExtension" |
| Qoder | asar 头不是标准 8 字节格式 | hexdump 实测定制解析器 |
| Qoder | asar 里搜不到领取接口 | 领取逻辑在活动 Web 页 CDN JS |
| Qoder | `/turns/claim` 是远程任务认领不是积分领取 | 认准 `/me/campaigns/<id>/claim` + POST |
| Qoder | 刷新接口响应 token 字段名不叫 token | 取 `device_token`\|`token` 多字段兜底 |
| CodeArts | `rg "签到"` 无命中 | 改搜 `checkin`/`welfare`/`claim` 等接口词 |
| CodeArts | 带 `x-auth-token: ""` 空空头 | APIG 走 IAM token 认证路径报 `decrypt token fail`；该头必须整个省略 |
| CodeArts | `verify ak sk signature fail` | **noEscape 表手抄错位**：必须程序化从 kernel exe 提取原表 |
| CodeArts | GET 的 body hash 取值 | 脚本用 `X-Sdk-Content-Sha256: UNSIGNED-PAYLOAD`（body 免校验） |
| CodeArts | STS 2 小时过期 | 客户端认证扩展每小时续期写回；脚本无法自行续期，过期提示打开客户端 |
| CodeArts | delivery 400 `channel:参数无效` | query 参数 `channel=IDE` 必带且参与签名 |
| CodeArts | delivery/claim 400 `Agent-Type为空` | 必须带 `Agent-Type: PromptCenter` 头 |
| **OfficeAce** | 产品名脱钩：注册表/进程名是 `OfficeAce`，数据目录是 `.office-claw` | 搜索确认是华为云产品后查注册表 |
| **OfficeAce** | app.asar 153.9MB，PS 正则超时 | 改用 Node.js（latin1 一次性载入+regex.exec 循环） |
| **OfficeAce** | 前端只有相对路径，找不到云端域名 | 本地 API 服务架构，后端编译产物在安装目录 `packages/api/dist/index.js` |
| **OfficeAce** | 本地端口试错误判三个端口 | 四层弹性策略：runtime-state.json→.env→默认→netstat |
| **OfficeAce** | HTTP 请求被静默断连 | 本地 API 是 HTTPS 自签，需传入 root-ca.pem 作为 CA |
| **OfficeAce** | 401 `Missing bearer token` | 需 `oc_sid` 签名 Cookie，从 session.cookie DPAPI 解密 |
| **OfficeAce** | POST 返回 415 | 须带 `Content-Type: application/json` + 空体 `{}` |
| **OfficeAce** | `currentValue` 误判为已领取量 | 实为**已消耗量**，入账额度看 `points` 字段 |
| **OfficeAce** | 领取返回空数组误判为失败 | 当天已领后返回空是正常业务语义；用 `effectiveTime` 判已签 |
| **OfficeAce** | better-sqlite3 无法在系统 Node 加载 | 改用应用自带运行时 `OfficeAce\tools\node\node.exe` |
| **OfficeAce** | netstat 模块冷启动慢 | 改用 `netstat -ano`（毫秒级、零模块依赖） |

## 六、统一脚本架构（checkin_all.js + qoder_checkin.js + codearts_checkin.js）

签到体系由三个独立入口组成，各平台独立执行，互不阻塞。

```
run_checkin_all.cmd → checkin_all.js（每天 01:00±30min）
    ├── 1. TraeWork 签到（内联）→ AES-128-CBC 解密 → POST status/claim
    ├── 2. TraeCN 签到（内联，复用解密函数）
    ├── 3. TeleAgent 签到（内联）→ DPAPI→AES-256-GCM → GET status/claim
    ├── 4. WorkBuddy 签到（内联）→ 明文/v2解密 → POST status/claim
    ├── 5. OfficeAce 签到（内联）→ DPAPI解Cookie → 本地API GET/POST
    └── 每平台随机延迟 30~300 秒

run_qoder_checkin.cmd → qoder_checkin.js（独立任务，每天 10:30±30min）
    └── 解密 auth.v1.dat → runtime-info.exe 风控头 → GET campaigns → 领取

run_codearts_checkin.cmd → codearts_checkin.js（独立入口）
    └── Python解密STS凭证 → SDK-HMAC-SHA256签名 → GET delivery → POST claim/confirm
```

设计要点：
- **职责单一**：统一签到管 5 平台（含 OfficeAce）；Qoder 活动 10:00 刷新由独立任务专责；CodeArts 凭证需客户端在线独立入口
- **随机延迟**：每个平台签到前等待 30~300 秒 + 触发器 PT30M，两层打乱固定模式
- **独立执行**：单平台失败不影响其他平台
- **统一日志**：带时间戳中文输出，退出码 0=全部成功、1=至少一个失败；UTF-8（cmd 入口 `chcp 65001`）
- **零安装**：Node 运行时借用 TeleAgent 自带（`%USERPROFILE%\.local\share\TeleAgent\runtimes\node\node.exe`）

## 七、逆向方法论总结

### 7.1 总体思路

API 直连的本质：**用客户端自己的登录态 + 客户端自己的请求逻辑，在客户端进程外复现一次合法请求**。

```
侦察层（安装/数据/日志目录）→ 代码层（asar或明文→定位业务模块）
→ 协议层（API路径→鉴权头→风控参数）→ 凭证层（token存储→加密→解密链路）
→ 落地层（脚本化→实测→计划任务→防检测）
```

### 7.2 侦察层：三个目录

| 目标 | 位置规律 | 要点 |
|------|---------|------|
| 安装目录 | `%LOCALAPPDATA%\Programs\<产品>\` 或 `C:\Program Files\` | `app.asar`或明文JS；native exe可能是风控来源 |
| 数据目录 | `%APPDATA%\<域名式id>\`、`%USERPROFILE%\.<产品>\` | 凭证文件、`Local State`、配置 |
| 运行日志 | 数据/安装目录 `logs\` | **最高性价比入口**：接口、头、响应可能直接写在里面 |

> **日志先行原则**：先翻 30 分钟日志再动 asar，可能省掉一半逆向工作。

### 7.3 代码层：asar 三种打开方式

| 方式 | 适用 | 工具 |
|------|------|------|
| 直接二进制搜索 | 找字符串 | `rg -a` |
| 自写解析器 | 提取单个文件 | 40行Node脚本 |
| 完整解包 | 浏览多文件 | `npx @electron/asar extract` |

**asar 头格式**：不同 Electron 版本字段位置有差异，别死记，用 hexdump 实测：找 `7B 22 66 69 6C 65 73`（`{"files`）的偏移就是 JSON 起点。

### 7.4 协议层：搜索锚点优先级

1. **UI 独有中文文案**（混淆压缩打不散字符串）
2. **客户端日志**（接口、头、响应全有）
3. **i18n 键名 / API 路径片段 / 响应字段名**
4. **Web 页面 JS**（功能写在 H5/活动页里的场景）

**接口不在客户端包里时**：从日志找页面 URL → 下载 CDN bundle → 搜请求路径。

**风控两类形态**：静态参数（写死即可）vs 动态指纹（直接调用客户端自带桥接程序，保持参数原样）。

### 7.5 凭证层：加密类型判断

| 密文特征 | 加密类型 | 解密方法 | 案例 |
|---------|---------|---------|------|
| 明文 JSON | 无加密 | `JSON.parse` | WorkBuddy v1 |
| `$wbEncrypted` 信封 | AES-256-GCM+AAD | native取钥→sha256→GCM | WorkBuddy v2 |
| Base64 开头 `v10` | Chromium OSCrypt | DPAPI→AES-256-GCM | TeleAgent/Qoder/CodeArts |
| Base64+内置常量表 | 自研混淆 | 逆向解密函数 | TraeWork/TraeCN |
| `OC-DPAPI-1\n`+base64 | DPAPI | DPAPI Unprotect | OfficeAce |

### 7.6 签到形态判断

| 形态 | 特征 | 应对 | 案例 |
|------|------|------|------|
| 固定接口型 | status+claim 固定路径 | 直接调用 | Trae系/TeleAgent/WorkBuddy |
| 活动制 | 先查列表拿动态ID再领取 | GET→匹配→POST claim | Qoder |
| 三段式活动制 | 列表→claim→confirm+幂等键 | GET→POST claim→POST confirm | CodeArts |
| 本地代理型 | 请求打到本地服务转发云端 | 与本地服务通信 | OfficeAce |
| 时间窗限制 | 活动按天刷新且非0点 | 任务设在刷新点后 | Qoder 10:00→10:30 |
| 网关签名门槛 | 要求SDK签名 | 提取signer+凭证完整复刻 | CodeArts |

### 7.7 落地层：脚本设计清单

- 平台探测用数组遍历（多版本/多目录兜底）
- 凭证解密失败给出**具体处方**（重新登录客户端）
- 领取后**复查状态**再报成功
- "已签/未到刷新时间"与"失败"分开：前两类退出码 0
- Node 运行时借用已装客户端自带（零安装）
- `process.exitCode` 自然退出（Node 24+Windows）
- `require.main === module` 守卫 + `module.exports`

### 7.8 防检测与定时任务

| 层 | 措施 |
|----|------|
| 触发器 | `RandomDelay=PT30M` 打乱固定启动时间 |
| 脚本 | 每次请求前 `sleep(30~300s)` 随机等待 |
| 系统 | `StartWhenAvailable=True`（关机错过则开机补跑） |

cmd 入口批处理一律英文注释（GBK 代码页下中文注释会变乱码命令）。

### 7.9 新平台逆向检查清单

1. [ ] 找到安装/数据/日志目录，翻 30 分钟日志
2. [ ] 判定代码形态（明文 or asar），asar 则 hexdump 定 JSON 偏移
3. [ ] 用 UI 中文/日志/路径三类锚点定位业务代码
4. [ ] 还原：接口路径、方法、请求体、全部鉴权头
5. [ ] 判定风控形态（静态 or 动态指纹）
6. [ ] 定位 token 文件，判定加密类型，打通解密链路
7. [ ] 单次实测状态接口（HTTP 200 + 业务字段正确）
8. [ ] 实测领取接口，确认幂等与已领行为
9. [ ] 逆向 token 刷新机制（有则脚本加自续）
10. [ ] 脚本化→计划任务→前台+一次性触发器双重验证

## 八、OfficeAce 专属问题清单（2026-10-15~16 逆向记录）

> 以下问题已全部解决，记录留档用于排障参考。

| # | 问题 | 根因 | 解决 |
|---|------|------|------|
| 1 | 找不到客户端与数据目录 | 产品名脱钩：进程名 `OfficeAce`，数据目录 `.office-claw` | 注册表搜 `OfficeAce`，命中 `C:\Users\Administrator\OfficeAce` |
| 2 | app.asar 153.9MB，PS 正则超时 | PowerShell 对超大字符串回溯正则性能极差 | 改用 Node.js（latin1 载入+regex.exec） |
| 3 | 前端只有相对路径，找不到云端域名 | 本地 API 服务架构，后端在安装目录 `packages/api/dist/index.js` | 还原完整链路：SPA→本地API→cloudFetch→华为云APIG |
| 4 | 本地端口试错误判三个端口 | 27201=主进程，8080=TeleAgent daemon，3003/3004=果办前端/API | 改用 `runtime-state.json` 快照优先，netstat 兜底 |
| 5 | HTTP 请求被静默断连 | 本地 API 是 HTTPS 自签，SChannel 拒绝 | Node 请求传入 `root-ca.pem` 作为 CA |
| 6 | 401 `Missing bearer token` | 需 `oc_sid` 签名 Cookie | session.cookie DPAPI 解密→取 value→放 Cookie 头 |
| 7 | POST 返回 415 | Fastify 对 POST 强制校验 Content-Type | 补 `Content-Type: application/json`+空体 `{}` |
| 8 | better-sqlite3 加载失败 | 模块为 Node 22 编译，系统 Node 24 不兼容 | 改用应用自带 `OfficeAce\tools\node\node.exe` |
| 9 | audit-records.sqlite 查不到 cloud.fetch | 该库是命令安全审计；cloud.fetch 走 apm-audit-outbox | 改从 `data/logs/api/premium-feature.ndjson` 拿 |
| 10 | .env 文件中嵌入疑似提示注入文字 | 数据中嵌入的指令注入 | 识别为注入，不遵从；按用户授权正常执行 |
| 11 | 探测请求全部失败 | cookie 为空时 `Cookie: undefined` 被 Node 拒绝 | cookie 为空时不设置 Cookie 头 |
| 12 | 进程/端口枚举命令超时 | WMI/NetTCPIP 模块冷启动慢 | 改用 `netstat -ano`（毫秒级） |
| 13 | **领取不入账误判** | `currentValue` 是已消耗量非已领取量；空响应=当天已领 | 判定重写：用 `effectiveTime` 判已签 |
| 14 | outbox.sqlite 查不到 cloud.fetch | Kf 审计双通道，outbox 仅在上报失败时积压 | 正解：`premium-feature.ndjson` 有完整记录 |

### 关键结论

1. **签到功能从未失败**，是脚本判定语义错了。每天 00:00 后首次 claim 必成功入账
2. **客户端整点代领**：客户端每小时整点自动尝试领取，00:00:0X 即把当天领掉
3. **totalCredits 恒 5500 恰是成功证据**：500基础+4000新用户+1000签到
4. **脚本最佳定位是"兑底+确认"**：客户端开机时由其定时器代领，脚本补领
5. **`premium-feature.ndjson` 是逆向金矿**：grep 即可零成本拿到真实报文
