## 二、目录迁移操作流程（改路径后必做）

签到程序目录移动后，两个计划任务的绝对路径引用会全部失效，需逐一改绑：

```powershell
$newDir = "C:\Users\Administrator\Desktop\JK-temp\自动化与工具\签到程序"

# 1) 签到任务
$action = New-ScheduledTaskAction -Execute "cmd.exe" -Argument "/s /c ""`"$newDir\run_checkin.cmd`" >> `"$newDir\checkin_all.log`" 2>&1"""
Set-ScheduledTask -TaskName "统一签到" -Action $action

# 2) Gitee 同步任务（任务名含中文，用通配符取对象避免控制台编码问题）
$t = Get-ScheduledTask | Where-Object { $_.TaskName -like "*Gitee*" }
$action2 = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-ExecutionPolicy Bypass -NoProfile -File `"$newDir\sync_gitee.ps1`""
Set-ScheduledTask -TaskName $t.TaskName -Action $action2
```

要点：

- 用 `Set-ScheduledTask -Action` 就地改绑，触发器/设置原样保留，无需重建任务
- 迁移后先 `Test-Path` 确认旧目录已不存在、新目录脚本齐全，再改绑
- 控制台显示中文任务名乱码（GBK 读 UTF-8）只是显示问题，对象内部名称完好，经管道取 `$t.TaskName` 传递不会出错

## 三、经验教训

1. **任务计划程序会将 PowerShell 崩溃误判为任务执行成功**（LastTaskResult=0），导致故障难以排查。判断真实结果要看脚本自己的日志，不能只看任务状态
2. **脚本中未捕获的「命令不存在」错误不会写入日志**，日志会停留在最后执行的命令行且无明确报错信息。脚本内关键命令必须校验 `$LASTEXITCODE` 并显式输出
3. **绝对路径引用 = 移动即失效**（2026-09-09 事件）：脚本被移动后任务报「文件不存在」集体失败。此后约定：移动目录后立即改绑全部任务（见 §二），并在项目记忆中登记新路径
4. **含中文的 .ps1 必须以 UTF-8 BOM 保存**，否则 PowerShell 5 解析中文路径为乱码，git 报 `not a git repository`
5. **注册/改绑用 `Register-ScheduledTask` / `Set-ScheduledTask`，不用 `schtasks`**：后者中文任务名会乱码；`cmd /c` 含 `>>`、`&` 时必须加 `/s`
6. **签到触发时间必须 ≥ 10:35**：Qoder 每日活动 10:00 刷新，早了领不到
