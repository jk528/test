# 六平台 Token/Cookie 获取步骤 + 华为云 2核2G 服务器部署评估

> 本文回答两个问题：**每个平台的登录态（Token / Cookie）到底存在哪里、怎么解出来**，以及**能不能把这套签到程序搬到华为云 2 核 2G 服务器上跑**。
> 本文为纯文档记录，**未改动 `checkin_all.js` 任何代码**；文中所列函数名/路径/请求头均与当前脚本一致，可直接对照 [checkin_all.js](../../scripts/checkin_all.js) 检索。
> 配套阅读：[使用说明.md](../04-维护-巡检排障/使用说明.md)、[排障手册.md](../04-维护-巡检排障/排障手册.md)、[果办签到逆向记录.md](../02-逆向中-接口攻坚/果办签到逆向记录.md)。

---

## 零、先读这一节：一条硬约束

六个客户端（Trae / TeleAgent / WorkBuddy / CodeArts / Qoder / OfficeAce）**全部是 Windows 桌面客户端**，登录态一律落在 **Windows 用户目录 + DPAPI（CurrentUser 加密）+ 注册表 / 客户端可执行文件** 上：

| 依赖的 Windows 专属能力 | 被哪些平台使用 |
|---|---|
| DPAPI `ProtectedData.Unprotect(...,'CurrentUser')` | TeleAgent、Qoder、CodeArts、OfficeAce（脚本由 `powershell.exe` 调用，见 [dpapiUnprotect()](../../scripts/checkin_all.js#L76-L90)） |
| `%APPDATA%` / `%LOCALAPPDATA%` / `%USERPROFILE%` | 全部六个 |
| 注册表 `Uninstall` 项查安装目录 | 除 TeleAgent 外的全部（见 [regQueryInstallLocation()](../../scripts/checkin_all.js#L50-L60)） |
| 需拉起客户端 `.exe` | WorkBuddy（`WorkBuddy.exe` 取密钥）、Qoder（`runtime-info.exe` 设备指纹） |
| 需客户端**进程常驻** | OfficeAce（本地 HTTPS API 承载云凭证） |
| Node 内置 `node:sqlite` | CodeArts（读 `state.vscdb`，需 Node 22.13+） |

**结论：把完整程序原样搬到「Linux 华为云 ECS」上跑不通**——DPAPI 在 Linux 上不存在，TeleAgent/Qoder/CodeArts/OfficeAce/WorkBuddy 的登录态根本无法在本机解密；OfficeAce 还必须有客户端进程。

**能够跨机外带（解出明文后拿到别处用）的只有 Trae**（纯算法解密，不碰 DPAPI）。其余平台要么强绑本机 DPAPI，要么强绑本机 exe / 进程。

因此服务器部署有两条路线（详见第四章）：

- **路线 A（推荐，改动为零）**：用 **Windows 版华为云 ECS**，把六个客户端装在这台服务器上并登录，直接复用现有 `run_checkin.cmd` + 计划任务。
- **路线 B（改动大，本次不做）**：Linux ECS 上只跑「已外带明文凭证」的签到流程，需要新增一个「从明文凭证文件读取」的脚本，属于**改代码**，本文仅给出思路。

## 一、总览表

| # | 平台 | 凭证形态 | 凭证文件 | 解出明文的关键 | 签到请求如何带上 | 有效期 / 续期 |
|---|---|---|---|---|---|---|
| 1 | Trae | JWT（明文可外带） | `%APPDATA%\Trae CN\User\globalStorage\storage.json` | AES-128-CBC + SHA-512 派生，**纯算法、无 DPAPI** | `Authorization: Cloud-IDE-JWT <token>` | 长期，客户端重登才换 |
| 2 | TeleAgent | 加密 token → 明文 | `%USERPROFILE%\.local\share\TeleAgent\users\<owner>\app-auth\token.json` | Chromium 主密钥（DPAPI）→ AES-256-GCM | `X-Token: <token>` | 中长，过期需客户端重登 |
| 3 | WorkBuddy | 加密信封 → 明文 | `%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info` | `atRestSecretKey`（来自 `WorkBuddy.exe`）+ AES-256-GCM | `Authorization: Bearer <token>` + `X-User-Id: <uid>` | 中长，客户端重登 |
| 4 | CodeArts | STS 临时 AK/SK/Token | `%APPDATA%\codearts-agent\User\globalStorage\state.vscdb` | Chromium 主密钥（DPAPI）+ `node:sqlite` + AES-256-GCM | `X-Security-Token` + SDK-HMAC-SHA256 签名 | **短**（临期需客户端在线续期） |
| 5 | Qoder | token + refreshToken | `%APPDATA%\com.qodercn.app.stable\auth.v1.dat`（国际版 `com.qoder.app.stable`） | Chromium 主密钥（DPAPI）→ AES-256-GCM | `Authorization: Bearer <token>` + `Cosy-*` 风控头 | 中长，**可 API 自助刷新**并原子写回 |
| 6 | OfficeAce | 签名会话 Cookie `oc_sid` | `%USERPROFILE%\.office-claw\session.cookie` | **DPAPI** 解出 `{value,expires}` | `Cookie: oc_sid=<value>`（打本地 API） | 约 1 个月，客户端重登 |

## 二、逐平台获取步骤

> 通用前提：**对应客户端已安装且当前用户已登录**；所有解密都在「该 Windows 用户」的上下文里做（DPAPI CurrentUser）。脚本运行方式：`.\run_checkin.cmd --no-delay`（跳过随机延时快速验证）。

### 2.1 Trae

**凭证位置与结构**
- 数据目录自动探测：`%APPDATA%\Trae CN`（旧名 `TRAE SOLO CN`），命中标志是存在 `User\globalStorage\storage.json`（[findTraeAppDataRoot()](../../scripts/checkin_all.js#L152-L161)）。
- 键名：`storage.json` → `iCubeAuthInfo://icube.cloudide`，值为 **base64 密文**。
- 解密后是 JSON，关键字段 `token`（JWT）、`userRegion.region`。

**解密算法（[decryptTrae()](../../scripts/checkin_all.js#L187-L202)）**
- 密文布局：`6B 前缀 + 32B salt + AES-CBC 密文`。
- 派生：`SHA512(salt) ‖ (硬编码表 ure ⊕ dre)` 再 `SHA512` → 取前 16B 为 **AES-128 key**、紧接 16B 为 **IV**。
- 明文前 64 字节为 padding/头，实际 JSON 从其之后开始。
- **注意：全程使用 `crypto.subtle`，没有任何 DPAPI / 本机绑定**，所以**明文 token 可以拷到别的机器直接用**（这是六平台里唯一干净的）。

**签到需要的附加字段**
- `device_id`：`%APPDATA%\Trae CN\ModularData\ckg_server\local_env.json` 的 `device_id`（[checkinTrae()](../../scripts/checkin_all.js#L226-L230)）；缺失会告警「签到可能被拒绝」。
- `x-app-version`：安装目录 `resources\app\package.json` 的 `version`（[findTraeAppVersion()](../../scripts/checkin_all.js#L167-L175)）。设备信息不全会带 `x-device-id` / `x-device-type` / `x-os-version` 头。

**请求用法**
```
Authorization: Cloud-IDE-JWT <token>
X-User-Region: <userRegion.region>            # 有才带
x-device-id / x-device-type: Windows / x-os-version / x-app-version
POST https://api.trae.cn/trae/api/v2/ug/checkin_credits/status|claim
```

**手动获取步骤**
1. 打开 Trae 客户端并确认已登录（升级常被踢下线）。
2. 取 `storage.json` 中 `iCubeAuthInfo://icube.cloudide` 的 base64 串。
3. 用 Node（任意版本）解出 `token`：`decryptTrae()` 未包含在 `module.exports`（[见导出清单](../../scripts/checkin_all.js#L1650-L1663)），最简单的方式是临时脚本里**照抄这 20 行算法**（`sha512` + `decryptTrae`），把 base64 串喂进去即可，不影响主脚本。
4. 同步取出 `device_id` 与版本号，与 token 一起外带。

### 2.2 TeleAgent

**凭证位置**
- 根目录：`%USERPROFILE%\.local\share\TeleAgent`（[TA_DATA_ROOT](../../scripts/checkin_all.js#L322)）。
- owner 定位：先读根目录 `current-owner.json` 取 `ownerDir`；读不到则遍历 `users\*` 兜底（[taFindTokenJson()](../../scripts/checkin_all.js#L336-L350)）。
- token 文件：`users\<ownerDir>\app-auth\token.json`，字段 `encryptedToken`（base64），`encrypted:false` 时即明文直用。

**解密路径**
1. Chromium 主密钥：根目录 `Local State` → `os_crypt.encrypted_key`（base64，前缀 `DPAPI`）→ 去掉 5 字节前缀后 DPAPI 解密 → 32B 主密钥（[readChromiumMasterKey()](../../scripts/checkin_all.js#L94-L101)）。
2. `encryptedToken` base64 → `aesGcmDecryptV10()`（`v10` + 12B nonce + 密文 + 16B tag）→ 明文 token（[taDecryptToken()](../../scripts/checkin_all.js#L353-L359)）。

**签到需要的附加字段**
- `deviceId`：`app-auth\device-meta.json` 的 `deviceId`（[taReadDeviceId()](../../scripts/checkin_all.js#L361-L366)）。
- `X-App-Version`：安装目录 `resources\app\package.json`，兜底 `2.5.2`。

**请求用法（[taBuildHeaders()](../../scripts/checkin_all.js#L368-L380)）**
```
X-Token: <token>     X-Timestamp: <秒>     X-Nonce: <uuid>
X-App-Version / X-OS-Type: Windows / X-SuperAgent-Device-Id
GET https://agent.teleai.com.cn/superCowork/sapi/user/portal/companyStore/v2/checkDayTask
GET .../companyStore/checkTask?type=daily_login
```

**手动获取**：本机 PowerShell 环境执行以上两步。DPAPI 是 CurrentUser 作用域，**换机器/换用户即失效**，所以 token 只能在本机解出后按明文外带。

### 2.3 WorkBuddy

**凭证位置**
- 认证目录：`%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth`（[WB_AUTH_DIR](../../scripts/checkin_all.js#L458-L461)）。
- 登录态文件：`workbuddy-desktop.info`（缺失时取目录内最新非时间戳 `.info` 兜底）。
- 关键字段：`auth.accessToken.envelope`（加密信封）、`account.uid`。

**解密路径（[wbGetToken()](../../scripts/checkin_all.js#L577-L620)）**
1. 取 `atRestSecretKey`（44 字符），三层来源（[wbGetAtRestSecretKey()](../../scripts/checkin_all.js#L492-L528)）：
   ① 进程内 native binding（本进程就是 WorkBuddy.exe/Electron 时）；
   ② `.temp\wb_key.json` 缓存；
   ③ **spawn `WorkBuddy.exe -e "<内联脚本>"` + `ELECTRON_RUN_AS_NODE=1`** 自取（只需 exe 存在，客户端无需运行）。
2. `envelope` 是 `sym-v1` 信封 JSON（`suite/keyId/nonce/authTag/ciphertext`），密钥 = `SHA256(atRestSecretKey)`，用 **AES-256-GCM + 自建 AAD**（`WB-AAD\0…`，[wbBuildAad()](../../scripts/checkin_all.js#L549-L562)）解密 → 明文 accessToken。
3. authTag 校验失败（密钥随客户端升级轮换）→ 清缓存重新取密钥重试一次。

**请求用法**
```
Authorization: Bearer <token>     X-User-Id: <uid>     X-Domain（有才带）
POST https://copilot.tencent.com/...  （见 checkinWorkBuddy()）
```

**手动获取**：必须有 `WorkBuddy.exe`（注册表或 `%LOCALAPPDATA%\Programs\WorkBuddy`）。**依赖本机 exe**，这也是它不能纯 Linux 的原因。

### 2.4 CodeArts

**凭证位置**
- 数据库：`%APPDATA%\codearts-agent\User\globalStorage\state.vscdb`（[CODEARTS_DB](../../scripts/checkin_all.js#L833)）。
- 表项 key：`secret://{"extensionId":"huaweicloud.authentication","key":"HuaweiCloudSession"}`，`value` 为 `{"data":"<base64 密文>"}`。

**解密路径（[codeartsLoadCredentials()](../../scripts/checkin_all.js#L836-L861)）**
1. Chromium 主密钥：`%APPDATA%\codearts-agent\Local State` → DPAPI（同上）。
2. 读库：**Node 内置 `node:sqlite` 的 `DatabaseSync`**（只读）——这就是「CodeArts 需 Node 22.13+」的根因。
3. `data` base64 → `aesGcmDecryptV10()` → JSON，含 `accessKey / secretKey / securitytoken`（**华为云 STS 临时凭证**）、`expires_at`、`account.label`。

**请求用法**
- 复刻客户端 kernel 的 **SDK-HMAC-SHA256** 签名（[codeartsSignedHeaders()](../../scripts/checkin_all.js#L768-L799)）+ 业务头 `X-Security-Token` / `Agent-Type: PromptCenter` / `X-Language`（[codeartsBusinessHeaders()](../../scripts/checkin_all.js#L820-L830)）。
- 端点：`https://snap-access.cn-north-4.myhuaweicloud.com/v1/ops/delivery|claim|confirm`。

**续期**
- `expires_at` 过期会抛「请打开 CodeArts Agent 让其刷新登录态」——**STS 临时凭证寿命短（小时级）**，客户端每小时自动续期（[排障手册](../04-维护-巡检排障/排障手册.md) §二）。
- 这决定了 CodeArts **不适合「解一次扔服务器长期用」**，服务器端必须能持续拿到新凭证（即客户端在线）。

### 2.5 Qoder

**版本与凭证位置**
- 国内版：数据目录 `%APPDATA%\com.qodercn.app.stable`，API `https://openapi.qoder.com.cn`，`runtimeEnv=0`。
- 国际版：`%APPDATA%\com.qoder.app.stable`，API `https://openapi.qoder.sh`，`runtimeEnv=3`。
- 有 `auth.v1.dat` 的版本即为生效版本（[qoderDetectVariant()](../../scripts/checkin_all.js#L988-L996)）。
- 相关文件：`auth.v1.dat`（主凭证）、`auth.machine-id`（设备号）。

**解密路径（[checkinQoder()](../../scripts/checkin_all.js#L1110-L1131)）**
1. Chromium 主密钥：对应 `dataDir\Local State` → DPAPI。
2. `auth.v1.dat` → `aesGcmDecryptV10()` → JSON：`token`、`refreshToken`、`expiresAt`、`user.id/name`。

**续期（无需客户端，脚本可自助）**
- 距过期 < 3 天自动 `POST {api}/api/v1/deviceToken/refresh {refresh_token}`，成功后**原子写回** `auth.v1.dat`（含 `.bak` 备份 3 份，[qoderWriteAuthAtomic()](../../scripts/checkin_all.js#L1003-L1015)），与客户端共享凭证。
- token 被拒（401/403）会强刷一次。

**风控头（本机 exe 依赖）**
- `Cosy-MachineToken / MachineCode / MachineType / vmInfo` 来自安装目录 `resources\umid\runtime-info.exe <env> --account-stdin`（[qoderRiskIdentity()](../../scripts/checkin_all.js#L1021-L1031)）；取不到只告警、继续尝试。
- 其余头：`Cosy-ClientType: 10`、`Cosy-Version`（安装目录 package.json）、`Cosy-MachineOS: x86_64_windows`、`Cosy-MachineHostname`、`Cosy-MachineId`（= `auth.machine-id`）、`User-Agent: Qoder`。
- 端点：`GET {api}/sash/api/v1/me/campaigns`、`POST {api}/sash/api/v1/me/campaigns/<id>/claim`。

**时间约束**：活动每日 **10:00（UTC+8）**刷新，故定时任务必须在 10:30 之后。

### 2.6 OfficeAce（果办）

**凭证位置与结构**（[OFFICEACE_SESSION_COOKIE_PATH](../../scripts/checkin_all.js#L1399)）
- 文件：`%USERPROFILE%\.office-claw\session.cookie`。
- 格式：`"OC-DPAPI-1\n" + base64(DPAPI(CurrentUser, JSON{value, expires}))`。
- `value` 即签名后的 **`oc_sid` Cookie**；`expires` 为 epoch 秒。

**解密路径**（[officeaceDecryptSessionCookie()](../../scripts/checkin_all.js#L1401-L1408)）
- 去掉 `OC-DPAPI-1\n` 头 → base64 解码 → **DPAPI 解密** → JSON。注意是脚本里**唯一直接用 DPAPI 而非 Chromium 主密钥**的平台。

**签到链路（强依赖客户端进程）**
1. 本地 API 地址四层弹性发现：`<安装目录>\.office-claw\run\windows\runtime-state.json` 快照 → `.env/.inner.env` 的 `API_SERVER_PORT` → 默认 `3004/3002` → `netstat -ano` 回环端口扫描（[officeaceDiscoverApiOrigin()](../../scripts/checkin_all.js#L1332+)）。
2. HTTPS **自签证书**，用 `<安装目录>\.office-claw\certs\root-ca.pem` 作 `ca`；找不到才退化为 `rejectUnauthorized:false`。
3. 请求：`GET /api/subscription/current`、`POST /api/subscription/claim-bonus`（必须带 `Cookie: oc_sid=<value>` + `Content-Type: application/json` + 空体 `{}`）。
4. 判定铁律：daily 记录 `effectiveTime` 在今日北京 00:00 后 = 已领（客户端整点会自动代领）。

**关键限制**：本地 API 承载华为云签名凭证，**客户端不运行时无法离线直连**——服务器上必须让果办客户端常驻进程。

## 三、凭证有效期 / 续期一览

| 平台 | 失效触发 | 能不能自愈 |
|---|---|---|
| Trae | 客户端升级 / 重登 | 否，需重登取新 token |
| TeleAgent | 客户端重登、DPAPI 主密钥重建 | 否 |
| WorkBuddy | 客户端升级致密钥轮换（authTag 校验失败） | 部分：脚本清缓存重取密钥重试 |
| CodeArts | STS 临时凭证到期（小时级） | 否，需客户端在线续期 |
| Qoder | token 临期（<3 天） | **是**：脚本 API 自助刷新并写回 |
| OfficeAce | 会话 Cookie 过期（约 1 个月） | 否，需重登；且客户端需常驻 |

## 四、华为云 2 核 2G 服务器部署评估

### 4.1 可行性矩阵

| 平台 | Linux ECS（纯 API） | Windows ECS | 卡点说明 |
|---|---|---|---|
| Trae | ✅ 可（需外带 token + device_id） | ✅ | 纯算法解密，唯一能干净外带的 |
| TeleAgent | ❌ | ✅（需客户端登录一次） | 主密钥靠 DPAPI，换机不可解 |
| WorkBuddy | ❌ | ✅（需 `WorkBuddy.exe` 存在） | 密钥靠本机 exe 自取 |
| CodeArts | ❌ | ✅（需客户端在线续期） | DPAPI + `node:sqlite`，且 STS 短命 |
| Qoder | ❌ | ✅（需安装目录含 `runtime-info.exe`） | DPAPI + 本机设备指纹 exe |
| OfficeAce | ❌ | ⚠️（需客户端**进程常驻**） | 本地 API 承载云凭证 |

> 一句话：**只有 Trae 适合 Linux 纯外带；其余五个都强绑 Windows 本机。**

### 4.2 路线 A —— Windows 华为云 ECS（推荐，现有代码零改动）

**为什么选它**：脚本本身 `run_checkin.cmd` + 计划任务这套是 Windows 原生的，`reg query`、DPAPI、`netstat`、spawn exe 全都天然可用，**不需要改一行代码**。

**资源评估（2 核 2G）**
- 纯 Node 脚本本身极轻：零第三方依赖、6 个平台顺序执行、主体开销是 fetch + 随机 sleep；2C2G 跑脚本绰绰有余。
- 真正的内存压力来自**常驻的 Electron 客户端**：OfficeAce 必须常驻；若还想让 CodeArts/Qoder/Trae 同时开，2G 会很紧张。**建议 2C4G 起，或让客户端按需错峰启动**。

**部署步骤**
1. **镜像**：Windows Server 2019/2022（中文），2 核 2G（常驻多客户端建议 2C4G）。
2. **Node**：装 **Node 24+**（CodeArts 需内置 `node:sqlite`，即 22.13+/24）。装到 `C:\Program Files\nodejs` 可被 `run_checkin.cmd` 第二级探测命中。
3. **拷贝程序**：把整个签到程序目录放到服务器（`run_checkin.cmd` 里 `SCRIPT_DIR=%~dp0` 自动定位，无需改路径）。
4. **逐客户端安装并登录**：Trae CN / TeleAgent / WorkBuddy / CodeArts / Qoder CN / OfficeAce，各自打开一次确认已登录（生成各自登录态文件）。
5. **试跑**：`cd <目录> && .\run_checkin.cmd --no-delay`，看控制台/`checkin_all.log` 六个平台是否各有结果。
6. **注册计划任务**：沿用 [使用说明.md](../04-维护-巡检排障/使用说明.md) §五 的 PowerShell 脚本，触发时间 **≥ 10:35**（Qoder 限制），`-StartWhenAvailable` 开机补跑、限时 90 分钟。
7. **OfficeAce 常驻**：把果办客户端设为登录自启或计划任务前置拉起，保证本地 API 在线（它整点还会自动代领，脚本是兜底）。
8. **网络**：见第五章出站域名清单，安全组放行出站 443（以及本机回环 3004/3002，只在本机访问，无需放行公网）。

**注意**
- Windows Server 若为 **Core 版（无桌面）**，Electron 客户端装不上/起不来，OfficeAce 直接不可用——必须是**带桌面体验**的版本。
- 服务器时区建议设为 **UTC+8 中国标准时间**，与 Qoder 10:00 刷新、果办 00:00 刷新的口径一致。

### 4.3 路线 B —— Linux 华为云 ECS（改动大，本次不做，仅给思路）

若坚持用 Linux（比如已有 Linux ECS 配额）：

1. **能走的平台**：仅 Trae —— 在一台 Windows 上解出明文 token + `device_id` + 版本号，拷到 Linux，用同样的 `fetch` + 头即可签到（`refreshTrae` 逻辑与平台无关）。
2. **其余平台**：需要先在「有客户端且已登录的 Windows 机器」上**解出明文凭证**（TeleAgent token、WorkBuddy accessToken+uid、Qoder token+refreshToken、OfficeAce oc_sid；CodeArts 的 STS 凭证寿命太短，需高频重取或干脆放弃离线），再让 Linux 端脚本从明文文件读取。
3. **必须新增适配代码**：把各平台「DPAPI/exe 取值」环节替换成「读明文凭证文件」，属于**改 `checkin_all.js`**，与本次「只出文档不改代码」的约束冲突，故**此处只记录思路，不实现**。
4. Linux 侧运行依赖：Node 22.5+ 才有稳定 `node:sqlite`（CodeArts 若保留）；计划任务改用 `cron`；随机 sleep 逻辑不变。
5. **结论**：除非你只想保 Trae，否则 Linux 方案收益低、维护成本高，**不推荐**。

### 4.5 安全与运维

- **Token 等同账号密码**：服务器登录口令、安全组、远程访问都要收紧；`.temp\wb_key.json`、`checkin_all.log` 里的 token 片段不要外传。
- **不要提交到 git**：`.temp/`、`*.log`、`auth*.dat` 等已在仓库清理记录中处理过，新增服务器副本同理排除。
- **时区 + 时间**：确保 10:35 触发时服务器时间正确（NTP 同步）。
- **单实例**：不要把签到任务和客户端自身的整点代领叠加成并发写入，Qoder 的 `auth.v1.dat` 写回已是原子的（tmp+rename），一般安全。
- **观测**：`Get-ScheduledTaskInfo -TaskName "统一签到"` 看 `LastTaskResult`（`0x0` 成功 / `0x1` 有平台失败）；失败按 [排障手册.md](../04-维护-巡检排障/排障手册.md) 分流。
