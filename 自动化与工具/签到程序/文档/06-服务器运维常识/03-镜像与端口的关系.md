# 03 · 镜像与端口的关系

> 一句话答案：**没有直接关系，但有间接联系。**
> 镜像不"决定"端口能不能用（端口是 TCP/IP 协议层，任何系统都支持 0–65535），
> 但镜像决定"预装了什么软件、默认防火墙策略"，因此间接影响"哪些端口在监听、哪些被本机拦住"。

---

## 一、先分清三层归属

| 层 | 由谁决定 | 换镜像会变吗 |
|---|---|---|
| **① 安全组** | 华为云控制台，实例级配置 | ❌ **完全不变** |
| **② 本机防火墙**（ufw / firewalld / Windows 防火墙） | **镜像的默认策略 + 你装的软件** | ✅ 会变 |
| **③ 进程监听**（谁占端口） | **镜像预装的软件 + 你装的服务** | ✅ 会变 |

**关键推论**：换镜像后"访问不通"，九成是 ② 变了；① 从来不会因为你换系统而自动调整。

---

## 二、不同镜像的默认行为对照

| 镜像 | 默认防火墙 | 默认监听端口 | 说明 |
|---|---|---|---|
| **Ubuntu Server（纯净 24.04）** | ufw 已安装但**默认未启用** | 22（+本机 53） | 最干净，开端口要自己来 |
| **Debian（纯净）** | 默认无规则 | 22 | 同上，更精简 |
| **CentOS Stream / Rocky / Alma** | **firewalld 默认启用**（public 区域只放 22 + DHCP） | 22 | 新端口需 `firewall-cmd --add-port=8080/tcp --permanent` |
| **Huawei Cloud EulerOS** | firewalld 通常默认启用 | 22 | 与 CentOS 同族 |
| **Windows Server** | Windows 防火墙启用 | **3389 RDP、445 SMB、135 RPC、5985 WinRM** 等 | 默认暴露面最大，风险最高 |
| **市场镜像（宝塔/LAMP/WordPress）** | 安装脚本自动改写 | **8888、888、80、443、3306** | 装完自带一套规则，容易与已有服务冲突 |

> 你这台的真实情况：**Ubuntu 纯净镜像 + 手动装宝塔**。ufw 里那 20/21/888/39000-40000 全是**宝塔装的**，不是镜像带的——这就是"镜像间接影响"的典型：软件改了防火墙，不是镜像本身改了。

---

## 三、三种"真实存在的联系"

### 联系 1：预装软件抢占端口

市场镜像装好那一刻，端口就被占了：

| 镜像 | 被占的端口 |
|---|---|
| 宝塔镜像 | 8888（面板）、888（phpMyAdmin）、3306（MySQL）、80/443（Nginx） |
| LAMP 镜像 | 80、3306 |
| WordPress 镜像 | 80、3306 |

**后果**：你再装一个 Web 服务想用 80 → 直接 `Address already in use`。

### 联系 2：默认防火墙策略不同

同一份配置，换个系统结果就不同：

| 场景 | Ubuntu（ufw） | CentOS（firewalld） |
|---|---|---|
| 装了 Nginx 用 80 | 默认可能就通（ufw 未启用） | **默认不通**，必须手动放行 |
| 开了 8080 | `ufw allow 8080/tcp` | `firewall-cmd --add-port=8080/tcp --permanent && reload` |

这就是为什么"同一篇教程在 CentOS 上跑不通"——不是教程错，是防火墙默认策略不同。

### 联系 3：端口占用冲突

换镜像（或重装系统）后，同名端口可能被不同软件占用：

| 端口 | 可能在 Ubuntu 被谁占 | 可能在宝塔镜像被谁占 |
|---|---|---|
| 80 | 你装的 Node/Nginx | 预装 Nginx |
| 3306 | 你装的 MySQL | 预装 MySQL |
| 8888 | 一般空着 | **宝塔面板** |

## 四、换镜像前必做的 5 项检查

| 检查 | 命令 / 位置 | 关注点 |
|---|---|---|
| 1. 现在谁在监听 | `ss -lntp` | 记下清单，换完对比 |
| 2. 本机防火墙规则 | `ufw status` / `firewall-cmd --list-all` | 换完要重建 |
| 3. 安全组规则 | 华为云控制台 | **不用改**，但要知道哪些开着 |
| 4. 业务数据 | `/opt`、`/www`、数据库 | 先备份再换 |
| 5. 启动方式 | `systemctl list-units --type=service`、`crontab -l` | 换完要重建 |

**换镜像 = 换系统盘，数据全没。** 唯一安全做法：先把 `/opt` + 配置 + 数据库 dump 备份出去，再换。

---

## 五、常见误区（都是真踩过的）

| 误区 | 事实 |
|---|---|
| "换镜像后端口自动就开了" | ❌ 安全组与镜像无关，一条都不会变 |
| "安全组是跟着系统走的" | ❌ 安全组挂在实例/网卡上，跟镜像无关 |
| "ufw 放行了就能访问" | ❌ 还有安全组这一层（你这次就卡在这） |
| "Windows 也能跑我这套 Linux 脚本" | ❌ 环境、命令、路径、权限模型完全不同 |
| "市场镜像更省事" | ⚠️ 建站省事，但预装软件抢端口、改防火墙，排障更难 |
| "重装系统端口就重置了" | ⚠️ 本机防火墙会重置，安全组不会 |
| "80 端口不安全，所以不用" | ❌ 80 只是明文；安全性取决于服务本身，HTTPS 才加密 |

## 六、对你当前场景的结论

| 问题 | 答案 |
|---|---|
| 需要换镜像吗？ | **不需要**。Ubuntu 24.04 够用，换来只是重装麻烦 |
| 换镜像能让端口更好开吗？ | **不能**。能开不能开取决于安全组 + 本机防火墙 |
| 想跑全部 10 个签到平台要换吗？ | 要换 **Windows Server**（6 个平台强绑 Windows），但那是换架构，不是换端口策略 |
| 换 Windows 后端口会怎样？ | 3389（RDP）会暴露，Linux 那套 SSH/ufw 命令全失效，需用 Windows 防火墙 |
| 市场镜像（宝塔镜像）值得吗？ | 你这台已经手动装了宝塔，等价；不必再换 |

---

## 七、一句话模型

```
镜像  →  决定「预装软件」→ 决定「谁占端口」
      →  决定「默认防火墙」→ 决定「本机放不放行」
安全组 →  实例级配置，与镜像无关，**永远要单独维护**
```

记住这三行，以后任何"换系统/换镜像"的疑问都能自己判断。
