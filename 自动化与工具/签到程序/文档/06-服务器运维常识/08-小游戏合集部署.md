# 08 · 小游戏合集部署（路径复用 80 端口）

> 目标：在不改安全组、不加端口的前提下，把多个纯静态游戏挂在同一个 80 端口下。
> 访问地址：**http://121.36.27.69/**（导航页）

---

## 一、为什么要用"路径"而不是"端口"

| 方案 | 端口占用 | 需要动安全组 | 结论 |
|---|---|---|---|
| 每个游戏一个端口（8080/8081…） | 多个 | ✅ 要去控制台逐条放行 | 麻烦 |
| **路径前缀（/2048/、/snake/…）** | **只有 80** | ❌ **完全不用** | **采用** |

原因：安全组当前只放行 22 和 80，路径方案让所有游戏共享 80，等于零额外配置。

## 二、最终结构

```
/opt/games/                      ← 根目录（systemd 服务 games 的工作目录）
├── server.js                    ← 多目录静态服务（约 60 行）
├── index.html                   ← 导航页（4 个游戏卡片）
├── 2048/                        ← 684K（数字合并）
│   ├── index.html
│   ├── js/  style/  meta/
├── hextris/                     ← 1.6M（六边形消除）
│   ├── index.html
│   ├── js/  style/  images/  vendor/
├── minesweeper/                 ← 12K（自研单文件扫雷）
│   └── index.html
├── snake/                       ← 12K（自研单文件贪吃蛇）
│   └── index.html

```

总占用约 **2.3 MB**，Node 进程内存 ~50 MB，几乎可忽略。

## 四、server.js 的路由逻辑（4 条规则）

| 请求 | 实际返回 |
|---|---|
| `/` | `index.html`（导航页） |
| `/xxx/`（以斜杠结尾） | `xxx/index.html` |
| `/xxx`（目录但无斜杠） | `301 → /xxx/`（保证相对路径正确） |
| `/xxx/yyy.css` | 真实文件，按扩展名给 Content-Type |

**两个安全点**：
- `path.normalize` + `startsWith(ROOT)` 挡住 `../` 目录穿越
- `decodeURIComponent` 包了 try/catch，畸形 URL 返回 400 而不是崩溃

## 五、新增一个游戏的完整流程

### 5.1 纯静态游戏（推荐，90% 的情况）

```powershell
# 1) 本地下载/解压到临时目录
# 2) 上传到服务器对应子目录
scp -r .\新游戏\* root@121.36.27.69:/opt/games/新游戏名/

# 3) 修权限（scp 从 Windows 传过去可能是 700）
ssh root@121.36.27.69 "chmod -R 755 /opt/games/新游戏名"

# 4) 立刻可访问，无需重启服务
#    http://121.36.27.69/新游戏名/
```

**不需要重启**：静态文件是请求时读的，传上去立即生效。

### 5.2 在导航页加一张卡片

编辑 `/opt/games/index.html`，在 `.grid` 里复制一段：

```html
<a class="card" href="/新游戏名/">
  <span class="icon">🎮</span>
  <div class="name">游戏名</div>
  <div class="desc">一句话说明</div>
</a>
```

### 5.3 需要构建的项目（如 React/Vue 写的游戏）

```powershell
npm run build              # 本地构建
scp -r .\dist\* root@121.36.27.69:/opt/games/新游戏名/
```

**只传构建产物**，不要把 `node_modules` 传上服务器。

## 九、与旧服务的关系（重要）

| 项 | 状态 |
|---|---|
| 旧服务 `game2048` | **已 `disable --now`**（它占着 80，不关会冲突） |
| 旧目录 `/opt/game2048` | 已复制进 `/opt/games/2048`，原目录保留作为备份 |
| 旧 unit 文件 | 仍在 `/etc/systemd/system/game2048.service`，未删除 |
| 新服务 `games` | 占用 80，接管全部访问 |

**确认稳定后可以清理旧文件**：

```bash
rm -f /etc/systemd/system/game2048.service
systemctl daemon-reload
rm -rf /opt/game2048
```

## 十、回滚与卸载

### 10.1 只想去掉某个游戏

```bash
rm -rf /opt/games/新游戏名
# 再把 index.html 里对应卡片删掉，无需重启
```

### 10.2 想回到"只有 2048"

```bash
systemctl disable --now games
systemctl enable --now game2048      # 旧服务仍在，直接启用即可
```

### 10.3 完全卸载

```bash
systemctl disable --now games
rm -rf /opt/games /etc/systemd/system/games.service
systemctl daemon-reload
```

## 十一、后续可扩展的方向

| 方向 | 做法 | 增量成本 |
|---|---|---|
| 加更多静态游戏 | 传目录 + 加卡片 | 0（不用重启） |
| 加"分数排行榜" | 在 server.js 加 `/api/score` + JSON 文件 | 约 20 行 |
| 换域名 | 买域名 + 解析到 IP，无需改代码 | 域名费用 |
| 加 HTTPS | 装 Nginx + 证书，反向代理到 127.0.0.1:8080 | 需把 games 挪到 8080 |
| 多人对战 | 引入 socket.io 另起一个 Node 服务 | 需 Nginx 反代或开端口 |

**提醒**：一旦装了 Nginx 想用 80，必须把 `games` 挪到 8080（改 `Environment=PORT=8080`），否则两者抢 80。

## 十二、附：复古模拟器（EmulatorJS 自托管）

### 12.1 为什么单独写一节

"整套开源项目"类游戏分两种：**引擎类**（EmulatorJS、js-dos）和**内容类**（2048、Hextris）。
引擎类本身不含游戏，需要 ROM 才能玩，所以做法与前面的纯静态游戏不同。

### 12.2 选型取舍

| 方案 | 问题 | 结论 |
|---|---|---|
| 直接引 CDN（cdn.emulatorjs.org） | 客户端能否访问不确定，且依赖第三方可用性 | 不采用 |
| 自己塞 ROM | ROM 有版权，**不能分发** | 坚决不做 |
| **自托管引擎 + 用户从浏览器上传自己的 ROM** | 文件不上服务器，只在本机内存里跑 | **采用** |

### 12.3 实际部署的文件清单

```
/opt/games/emulatorjs/            4.7 MB
├── index.html                    ← 上传 ROM 的壳页面
└── data/                         ← 从 CDN 镜像的引擎文件
    ├── loader.js                 7.6 KB  启动器
    ├── emulator.min.js         426 KB   主逻辑
    ├── emulator.min.css         26 KB   样式
    ├── version.json            126 B    版本
    ├── localization/en-US.json   9.8 KB  语言包
    └── cores/                            各机型模拟核心（每个约 1 MB）
        ├── fceumm-wasm.data           NES / FC
        ├── snes9x-wasm.data           SNES / SFC
        ├── mgba-wasm.data             GBA
        └── genesis_plus_gx-wasm.data  MD / Genesis
```

**关键点**：`<core>-wasm.data` 是"打包好的核心"（内含 .js/.wasm/.worker.js/build.json），**一个文件就是一整个机型**，所以只需镜像 4 个核心，不用整站搬（整站约 100 MB+）。

### 12.4 页面逻辑（12 行核心代码）

```js
window.EJS_player   = '#game';
window.EJS_core     = core;                                    // 机型
window.EJS_gameUrl  = URL.createObjectURL(file);               // 本地文件 → blob URL
window.EJS_pathtodata = '/emulatorjs/data/';                   // 指向本站，不走外网
window.EJS_startOnLoaded = true;
window.EJS_defaultOptions = { 'save-state-location': 'browser' };
// 然后动态插入 <script src="/emulatorjs/data/loader.js">
```

`URL.createObjectURL(file)` 是精髓：**ROM 只存在于浏览器内存**，服务器全程没收到任何 ROM 文件，因此没有版权与存储问题。

### 12.5 支持的机型与扩展

| 机型 | 核心名 | ROM 后缀 |
|---|---|---|
| NES / FC | `fceumm` | `.nes` |
| SNES / SFC | `snes9x` | `.smc` `.sfc` |
| GBA | `mgba` | `.gba` |
| MD / Genesis | `genesis_plus_gx` | `.bin` `.md` `.gen` |
| N64（未装） | `mupen64plus` | `.z64` `.n64` |
| 街机（未装） | `fbneo` | `.zip` |

**加一个机型 = 下载一个 `<core>-wasm.data` 放进 `cores/` + 下拉框加一项**，约 1 MB，不用重启。

```bash
curl -o /opt/games/emulatorjs/data/cores/mupen64plus-wasm.data \
  https://cdn.emulatorjs.org/stable/data/cores/mupen64plus-wasm.data
```

> N64 核心较大（10 MB+），且 1.7G 内存的服务器与本模拟器无关（运行在浏览器端），但手机端可能吃力。

### 12.6 已验证 / 未验证

| 项 | 结果 |
|---|---|
| 页面渲染、下拉框、未选 ROM 的提示 | ✅ 浏览器实测通过，无 JS 报错 |
| data/ 下引擎与核心文件公网可下载 | ✅ 全部 200（loader/emulator/cores/localization） |
| 真实 ROM 加载运行 | ⚠️ **未测**（本机无合法 ROM）。你上传自己的 `.nes` 即可验证 |

### 12.7 版权与安全边界（重要）

1. **本站不提供任何 ROM**，也不打算提供。ROM 属于游戏厂商版权，公开分发属侵权。
2. 上传的文件**不会离开浏览器**，服务器日志里只有 `GET /emulatorjs/` 一条。
3. 存档默认存浏览器 localStorage，换设备/清缓存会丢。
4. 若未来想做"预置游戏"，只能用**开源/自制 ROM**（如 Nova the Squirrel 这类 GPL 自制游戏）。

## 十三、附：自研大富翁的实现说明（`/opt/games/monopoly/`）

### 13.1 为什么自研而不是找现成的

DOS 版《大富翁》需要游戏本体/ROM（版权问题），js-dos 的 CDN 时有 405；GitHub 上的开源大富翁多是带服务端、数据库的重型多人项目。**单文件网页版最省事**：17 KB、无依赖、传上去就能玩。

### 13.2 棋盘规则

- **24 格环形棋盘**（7×7 外圈），格子索引 0–23 顺时针排布
- 起点（0）：经过/踩中 **+2000**
- 角格：监狱（6，休息一站）、免费停车（12，安全区）、医院（18，交 300）
- **14 处地产**：价格 600–1900，`租金 = 价格 × 0.12`（取整到 10）
- 机会 4 处、税收 2 处（税务局 500 / 市政费 800）
- 4 名玩家（你 + 红/绿/黄 3 个 AI），初始现金 **5000**，破产出局，剩 1 人获胜

### 13.3 核心机制

| 机制 | 规则 |
|---|---|
| 掷骰 | 两个骰子，步数 = 点数之和，逐格移动（110ms/格） |
| 买地 | 踩中无主地产可买；不买则跳过 |
| 升级 | 自有地产可升到 Lv3，费用 `价格 × 0.5`，每级租金 ×1.5 |
| 收租 | 踩中他人地产，按当前租金付给地主 |
| 破产 | 现金 < 0 即出局，名下地产全部释放 |
| AI 决策 | 买地：`现金 > 价格 + 900`；升级：`现金 > 费用 + 1500` |

### 13.4 扩展方向（改一个文件即可）

| 想加什么 | 改哪里 |
|---|---|
| 更多地产/更大的棋盘 | 扩 `POS` 循环格数（当前 7×7，可改 9×9 → 32 格） |
| 玩家变多/变少 | 改 `THEMES` 数组（UI 自动适配） |
| 平衡性调整 | 改 `rent` 系数、起点奖励、AI 阈值 |
| 存档 | 把 `players` / `CELLS` 序列化进 `localStorage` |
