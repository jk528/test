# 02 · 端口完全指南

> 目标：彻底搞懂"端口是什么、为什么打不开、怎么查、怎么开"。这一篇是整套常识的核心。

---

## 一、端口是什么

一台服务器只有一个公网 IP，却要同时提供 SSH、网站、数据库……**靠端口号区分不同服务**。

```
IP  = 大楼地址     121.36.27.69
端口 = 房间号      22 / 80 / 8080
协议 = 进门方式     TCP / UDP
```

一次完整访问：`TCP + 目标IP + 目标端口` 三者确定唯一服务。

| 协议 | 特点 | 典型端口 |
|---|---|---|
| **TCP** | 有连接、可靠、丢包重传 | SSH 22、HTTP 80、MySQL 3306 |
| **UDP** | 无连接、快、不保证送达 | DNS 53、DHCP 67/68、游戏/视频 |

> 网页、API、数据库、SSH **全是 TCP**。新手 99% 的问题都在 TCP 上。

---

## 二、端口总数与三段划分

**总数固定 65536 个：0 – 65535。** 这是 TCP/IP 协议规定的 16 位字段上限，不会变多也不会变少。

| 区段 | 名称 | 特点 | 例子 |
|---|---|---|---|
| **0 – 1023** | 知名端口（Well-known） | **必须 root 才能监听** | 22 SSH、80 HTTP、443 HTTPS |
| **1024 – 49151** | 注册端口 | 普通用户可监听，约定用途 | 3306 MySQL、3389 RDP、8080 备用 HTTP |
| **49152 – 65535** | 动态/临时端口 | 客户端发起连接时随机分配 | 浏览器访问网站时的源端口 |

**所以"服务器有多少个端口"= 65536 个，但真正有意义的只有"被监听"和"被放行"的那几个。**

> 你现在这台：监听 7 个、ufw 放行 11 条、安全组对公网只开 2 个、实际被使用 2 个。

## 四、判断"访问不通"的标准四步

**永远是这四步，不要跳、不要猜。**

```
第 1 步：服务器自己能访问吗？
    curl -I http://127.0.0.1:80
    ✅ 通  → 说明服务正常，问题在网络层（走第 2 步）
    ❌ 不通 → 服务没起来，查 systemctl status / 日志

第 2 步：端口在监听吗？绑定哪个地址？
    ss -lntp
    看到 0.0.0.0:80  → 对全网卡开放
    看到 127.0.0.1:80 → 只有本机能访问（外网永远不通！）

第 3 步：本机防火墙放行了吗？
    ufw status                      # Ubuntu/Debian
    firewall-cmd --list-all         # CentOS/EulerOS

第 4 步：安全组放行了吗？（只能去华为云控制台看）
    外网 Test-NetConnection IP -Port 80
```

## 五、`0.0.0.0` 与 `127.0.0.1`（最常见的隐形坑）

| 绑定地址 | 含义 | 外网能否访问 |
|---|---|---|
| `0.0.0.0` | 监听**所有**网卡 | ✅ 可以（前提是防火墙/安全组放行） |
| `127.0.0.1` | 只听**回环**（本机自己） | ❌ **永远不能** |
| `::` | IPv6 所有网卡 | ✅ 同上 |
| `192.168.x.x` / `10.x.x.x` | 只听内网某张网卡 | ❌ 公网不能 |
| `127.0.0.53` | 系统 DNS 专用 | ❌ 仅本机 |

**实战**：你服务器上 `53` 和 `29338/29339` 都是 `127.0.0.1`，所以从外网永远打不通——这不是配置错误，是设计如此。

## 六、端口能不能重复使用

| 场景 | 能否共存 |
|---|---|
| 同协议（TCP）+ 同端口 | ❌ 只能一个进程，第二个报 `Address already in use` |
| 不同协议（TCP 80 + UDP 80） | ✅ 可以同时存在 |
| `0.0.0.0:80` 与 `127.0.0.1:80` | ❌ 冲突（前者已包含后者） |
| `127.0.0.1:80` 与 `192.168.1.5:80` | ✅ 可以（不同网卡） |
| IPv4 80 与 IPv6 80 | ✅ 通常可共存（`ss` 会显示两行） |

**冲突排查**：

```bash
ss -lntp | grep :80          # 谁占了 80
lsof -i :80                  # 更详细（需装 lsof）
```

## 七、查端口的全部命令

```bash
ss -lntp                     # ★ 最常用：监听中的 TCP 端口 + 进程名
ss -lnup                     # UDP 版本
ss -lntp | grep :80          # 只看 80
netstat -anp                 # 老写法，部分系统没装
lsof -i :8080                # 按端口反查进程

ufw status verbose           # Ubuntu 防火墙规则
firewall-cmd --list-all      # CentOS 防火墙规则
iptables -L -n               # 底层规则（宝塔/Docker 会改这里）

curl -I http://127.0.0.1:80  # 测 HTTP 响应头
curl -v telnet://IP:22       # 测 TCP 连通
nc -zv IP 8080               # 测某个端口通不通（需装 netcat）
```

Windows 本地：

```powershell
Test-NetConnection 121.36.27.69 -Port 80     # 外网连通性（最准）
Test-NetConnection 121.36.27.69 -Port 8080
tnc 121.36.27.69 -Port 80                    # 简写
```

## 八、端口选择怎么定（实践建议）

| 场景 | 建议 | 理由 |
|---|---|---|
| 对外网站 | **80 / 443** | 用户不用输端口号，且安全组默认常开 |
| 开发测试 | 3000 / 5000 / 8080 | 不占特权端口，不用 root |
| 面板/管理后台 | 8888 / 随机高位端口 | 改默认端口可减少扫描 |
| 数据库 | **只监听 127.0.0.1** | 数据库永远不该对公网 |
| 临时调试 | 8000+ | 用完即关 |

**改端口三步走**：改程序配置 → 重启服务 → 放行新端口（安全组 + 本机防火墙）→ 验证 → 关闭旧端口。

> 你这次就是踩了"只放行 ufw、没放行安全组"。教训：**ufw 放行 ≠ 外网可访问**。

## 九、端口安全常识

1. **最小暴露**：只开必须的端口，能开 `我的IP` 就不开 `0.0.0.0/0`。
2. **22 端口是扫描重灾区**，公网每天被爆破上万次；建议改用密钥登录 + fail2ban，或换非标端口。
3. **数据库/缓存永不对外**（3306 / 6379 / 27017）。
4. **Docker 会绕过 ufw**：`-p 8080:80` 通过 iptables 直接放行，ufw 拦不住。要在安全组或 `daemon.json` 里控制。
5. **改默认管理端口**（8888 → 随机）能挡掉 90% 的自动扫描。

---

## 十、这一篇的 6 个关键结论

1. 端口共 **65536 个**，1024 以下要 root。
2. **端口"关闭"是个误解**：没人监听 = 自然没人能连，不需要"关"。
3. 排障四步：**本机 curl → ss 监听 → ufw → 安全组**。
4. `127.0.0.1` 绑定 = 外网永远不通，最容易忽略。
5. `ufw 放行` 与 `安全组放行` 是两道独立门槛，**缺一不可**。
6. 同端口同协议只能一个进程，冲突用 `ss -lntp` 一眼看穿。
