## 二、和博客原文的 3 处差异

| 博客做法 | 实际做法 | 原因 |
|---|---|---|
| 装 Nginx 或 Node 二选一 | **直接用 Node 内置 http** | 已有 Node 22，省一次安装 + 一套配置 |
| 用 8080 端口，需放行安全组 | **改用 80 端口** | 安全组本来就开着 80；8080 未放行（实测超时） |
| `npm install` 后启动 | **不需要任何安装** | 2048 官方仓库是纯静态，无构建步骤 |

### 3.1 本地：下载并解压

```powershell
cd "C:\Users\Administrator\Desktop\JK-temp\自动化与工具\签到程序"
```

解压后目录含：`index.html`、`js/`、`style/`、`meta/`、`favicon.ico` 等。

### 3.2 上传到服务器

```powershell
ssh root@121.36.27.69 "mkdir -p /opt/game2048"
scp -r .temp\2048\2048-master\* root@121.36.27.69:/opt/game2048/
ssh root@121.36.27.69 "du -sh /opt/game2048"   # 应显示约 684K
```

### 3.3 上传服务脚本 server.js

```powershell
scp .temp\2048\server.js root@121.36.27.69:/opt/game2048/server.js
```

### 3.4 配置 systemd 并启动

```bash
cat > /etc/systemd/system/game2048.service <<'EOF'
[Unit]
Description=2048 Game Static Server
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/game2048
Environment=PORT=80
ExecStart=/usr/bin/node /opt/game2048/server.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable game2048 --now
```

### 3.5 验证

```bash

curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/   # 200
```

## 四、核心文件全文

### 4.1 `/opt/game2048/server.js`

```js
// 2048 静态服务 — 零依赖，Node 内置模块
const http = require('http');
const fs = require('fs');
const path = require('path');

const ROOT = __dirname;
const PORT = Number(process.env.PORT || 8080);
const MIME = {
  '.html': 'text/html; charset=utf-8',
  '.css': 'text/css; charset=utf-8',
  '.js': 'application/javascript; charset=utf-8',
  '.png': 'image/png',
  '.jpg': 'image/jpeg',
  '.ico': 'image/x-icon',
  '.svg': 'image/svg+xml',
  '.json': 'application/json; charset=utf-8',
  '.woff': 'font/woff',
  '.woff2': 'font/woff2',
};

http.createServer((req, res) => {
  let rel = decodeURIComponent(req.url.split('?')[0]);
  if (rel === '/') rel = '/index.html';
  const file = path.join(ROOT, path.normalize(rel).replace(/^\.\.\//, ''));
  if (!file.startsWith(ROOT)) { res.writeHead(403); return res.end('forbidden'); }
  fs.readFile(file, (err, data) => {
    if (err) { res.writeHead(404, { 'Content-Type': 'text/plain; charset=utf-8' }); return res.end('404 Not Found'); }
    res.writeHead(200, { 'Content-Type': MIME[path.extname(file).toLowerCase()] || 'application/octet-stream' });
    res.end(data);
  });
}).listen(PORT, '0.0.0.0', () => console.log(`2048 serving on ${PORT}`));
```

**这段代码的 4 个关键点**：

| 行 | 作用 | 为什么重要 |
|---|---|---|
| `const ROOT = __dirname` | 以脚本所在目录为根 | 不依赖启动时的当前目录 |
| `rel === '/' → index.html` | 根路径映射默认页 | 否则访问 `/` 会 404 |
| `path.normalize + startsWith(ROOT)` | 防目录穿越 | 挡住 `/../../etc/passwd` 这类攻击 |
| `MIME[...]` | 按扩展名设 Content-Type | 不设的话浏览器可能下载而不是渲染 |

## 七、为什么用 80 而不是 8080（决策过程）

```
部署到 8080 → ufw allow 8080 → 本机 200 ✅
                        ↓
            本地 Test-NetConnection 8080 → 超时 ❌
                        ↓
            查 ufw：已放行 → 不是本机防火墙
                        ↓
            判定：安全组未放行 8080
                        ↓
            两个选择：
              A. 让用户去控制台放行 8080（需要账号权限，多一步）
              B. 换到安全组已放行的 80（无需任何人操作）
                        ↓
            选 B：改 Environment=PORT=80 → 立即公网 200 ✅
```

**可复用的判断**：新服务上线前，**先 `Test-NetConnection` 试探 80/443/22**，哪个通就用哪个，能省掉一轮控制台操作。

## 九、两个后续场景

### 9.1 以后装了 Nginx 想用 80（端口让位）

```bash
# 1) 2048 挪到 8080
sed -i 's/Environment=PORT=80/Environment=PORT=8080/' /etc/systemd/system/game2048.service
systemctl daemon-reload && systemctl restart game2048

# 2) ufw 放行 8080（之前加过就不用）
ufw allow 8080/tcp

# 3) 安全组也要放行 8080 —— 只能去华为云控制台（见 04 篇）
```

### 9.2 完全卸载

```bash
systemctl disable --now game2048
rm -rf /opt/game2048
rm -f /etc/systemd/system/game2048.service
systemctl daemon-reload
ufw delete allow 8080/tcp        # 如果加过
```
