## 一、systemd：Linux 服务管理的标准答案

### 1.1 为什么不用 `nohup node xxx &`

| 方式 | 断电/崩溃后 | 开机自启 | 日志 | 结论 |
|---|---|---|---|---|
| `nohup ... &` | 不会恢复 | 要自己写 | 手写重定向 | 临时测测可以 |
| 宝塔"进程守护" | 会恢复 | 面板配 | 面板看 | 有面板时够用 |
| **systemd** | **自动重启** | **enable 一条命令** | `journalctl` | **标准做法** |

### 1.2 unit 文件结构（背这 6 个字段就够）

```ini
[Unit]
Description=服务说明
After=network.target          # 网络就绪后再启动

[Service]
Type=simple
User=root                     # 建议改成普通用户（更安全）
WorkingDirectory=/opt/app
Environment=PORT=80           # 环境变量，改配置不用改代码
ExecStart=/usr/bin/node /opt/app/server.js
Restart=always                # 崩溃自动拉起
RestartSec=5                  # 5 秒后重试

[Install]
WantedBy=multi-user.target    # enable 时挂到哪个启动目标
```

**位置**：`/etc/systemd/system/<名字>.service`（系统级）；`~/.config/systemd/user/`（用户级）。

### 1.3 五个必用命令

```bash
systemctl daemon-reload        # ★ 改完 unit 文件必须执行
systemctl enable --now xxx     # 开机自启 + 立即启动
systemctl status xxx           # 状态（active/failed/inactive）
systemctl restart xxx          # 改代码后重启
journalctl -u xxx -n 50 --no-pager   # 最近 50 行日志
```

### 1.4 状态含义

| 状态 | 含义 | 处理 |
|---|---|---|
| `active (running)` | 正常 | — |
| `failed` | 启动失败或崩溃 | `journalctl -u xxx -n 50` 看原因 |
| `inactive (dead)` | 停了 | `systemctl start` |
| `activating` | 正在启动 | 等几秒再看 |
| `enabled` / `disabled` | 是否开机自启 | `systemctl enable/disable` |

## 二、日志：出问题第一现场

### 2.1 两套日志系统

| 来源 | 查看方式 | 内容 |
|---|---|---|
| **journald**（systemd） | `journalctl -u game2048` | 标准输出/错误（`console.log`、`console.error`） |
| **文件日志** | `tail -f /opt/trae-checkin/checkin.log` | 自己 `>>` 重定向写的 |

### 2.2 常用查询

```bash
journalctl -u game2048 -n 100           # 最近 100 行
journalctl -u game2048 --since today    # 今天
journalctl -u game2048 -f                # 实时跟（Ctrl+C 退出）
journalctl -p err -n 50                  # 只看错误级别
journalctl --disk-usage                  # 日志占多少空间
```

### 2.3 日志轮转（防止撑爆磁盘）

自己写到文件的（如 `checkin.log`）**不会自动清理**，两种做法：

```bash
# 做法 A：脚本内判断（签到脚本已实现）
if [ 文件 > 5MB ]; then mv checkin.log checkin.log.old; fi

# 做法 B：logrotate（系统级，更规范）
cat > /etc/logrotate.d/trae-checkin <<'EOF'
/opt/trae-checkin/checkin.log {
    size 5M
    rotate 3
    compress
    missingok
    notifempty
    copytruncate
}
EOF
```

> 你的签到脚本用的是做法 A（代码里 `statSync > 5MB → rename .old`），够用。

## 三、定时任务：cron

### 3.1 语法（5 个字段）

```
分 时 日 月 周   命令
*  *  *  *  *    ...
│  │  │  │  └── 周几（0-7，0 和 7 都是周日）
│  │  │  └───── 月（1-12）
│  │  └──────── 日（1-31）
│  └─────────── 时（0-23）
└────────────── 分（0-59）
```

| 写法 | 含义 |
|---|---|
| `0 0 * * *` | 每天 00:00 |
| `10 0 * * *` | 每天 00:10 |
| `*/5 * * * *` | 每 5 分钟 |
| `0 9 * * 1-5` | 工作日 09:00 |
| `0 0 1 * *` | 每月 1 号 00:00 |

### 3.2 操作

```bash
crontab -l              # 看当前用户的
crontab -e              # 编辑（改完保存即生效）
crontab -r              # ★ 删除全部，慎用
```

**注意**：
- root 的 crontab 与普通用户**互相独立**
- cron 环境变量很少（PATH 极简），**命令一律写绝对路径**（`/usr/bin/node`）
- 输出必须重定向，否则 cron 会发邮件（多半失败）：`>> log 2>&1`

### 3.3 常见坑

| 坑 | 表现 | 解决 |
|---|---|---|
| 用 `node` 而非 `/usr/bin/node` | `command not found` | 写绝对路径 |
| 不重定向输出 | 日志丢失 / 有邮件告警 | `>> xxx.log 2>&1` |
| 时区不对 | 该 00:00 跑却 08:00 跑 | `timedatectl set-timezone Asia/Shanghai` |
| 改脚本时任务正在跑 | 随机报错（cmd/流式读取特性） | 避开执行窗口再改 |
| 忘记 enable cron 服务 | 规则不生效 | `systemctl status cron` |

## 四、资源监控

### 4.1 五分钟体检

```bash
uptime                     # 跑了多久 + 负载
free -m                    # 内存（重点看 available）
df -h                      # 磁盘
ps aux --sort=-%mem | head # 内存 TOP10
ps aux --sort=-%cpu | head # CPU TOP10
ss -lntp                   # 端口状态
```

### 4.2 数值怎么看

| 指标 | 健康值 | 告警线 |
|---|---|---|
| 内存 `available` | > 30% | < 10% 会 OOM |
| 磁盘使用率 | < 70% | > 90% 危险 |
| load average（2 核） | < 2.0 | > 4 长期高 |
| swap 使用 | 接近 0 | 大量使用 = 内存不足 |

### 4.3 内存不足的两个救急手段

```bash
# ① 加 swap（1.7G 小内存有用）
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# ② 清缓存（治标，慎用）
sync && echo 3 > /proc/sys/vm/drop_caches
```

## 五、备份与重建

**核心思想：机器会没，数据和配置要能重建。**

| 备份对象 | 位置 | 方式 |
|---|---|---|
| 业务代码 | `/opt/game2048`、`/opt/trae-checkin` | `tar -czf` + 下载 |
| 配置 | `/etc/systemd/system/*.service`、`crontab -l` | 导出文本 |
| 凭证 | `config/*.json`、`trae_cred.json` | 单独加密保存，**不放公开仓库** |
| 数据库 | 若装了 MySQL | `mysqldump` |

```bash
# 一键打包（示例）
tar -czf /root/backup-$(date +%F).tar.gz /opt/game2048 /opt/trae-checkin /etc/systemd/system/game2048.service
crontab -l > /root/crontab.bak
```

**重建清单**（换机器时照此走）：

1. 装 Node（v22+）
2. 恢复 `/opt` 目录
3. 恢复 systemd unit → `daemon-reload` → `enable --now`
4. 恢复 crontab
5. 恢复凭证文件 → `chmod 600`
6. 放行端口（安全组 + ufw）
7. 逐项验证

## 六、安全加固（个人服务器版）

| 项 | 做法 | 优先级 |
|---|---|---|
| **SSH 密钥登录** | 禁用密码：`PasswordAuthentication no` | ★★★ |
| **SSH 限源 IP** | 安全组 22 只开自己 IP | ★★★ |
| **凭证文件 600** | `chmod 600` 所有含 token/cookie 文件 | ★★★ |
| **不用 root 跑 Web** | unit 里 `User=www-data` | ★★ |
| **fail2ban** | 自动封禁爆破 IP | ★★ |
| **定期更新** | `apt update && apt upgrade -y`（每周） | ★★ |
| **面板改端口** | 8888 → 随机，且只开自己 IP | ★★ |
| **数据库不外露** | 只监听 127.0.0.1 | ★★★ |

```bash
# SSH 加固示例
sed -i 's/#PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/#PermitRootLogin yes/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
systemctl restart ssh
# ★ 改完先另开一个窗口测试能否登录，别把自己锁在外面
```

## 七、故障定位方法论（背这套顺序）

```
① 状态：systemctl status、uptime
② 日志：journalctl -u xxx -n 50、tail 业务日志
③ 端口：ss -lntp，本机 curl 127.0.0.1
④ 资源：free -m、df -h、top
⑤ 网络：ping、curl 外网、Test-NetConnection
⑥ 防火墙：ufw status → 安全组
```

**三条纪律**：
1. **先复现，再动手**（别一边猜一边改）
2. **一次只改一个变量**（改多个就不知道谁起效）
3. **改前备份**（`cp file file.bak`，30 秒换安心）

## 八、常见故障速查表

| 现象 | 最可能原因 | 一句话解决 |
|---|---|---|
| 网站 502/504 | 后端服务挂了 | `systemctl status` + 日志 |
| 网站 404 | 路径/根目录配错 | 查 `WorkingDirectory`、`ROOT` |
| 网站打不开、curl 本机 200 | 安全组或 ufw | 见 04 篇四步法 |
| `Address already in use` | 端口被占 | `ss -lntp \| grep :端口` |
| 服务启动失败 `failed` | 代码报错 / 路径错 / 权限 | `journalctl -u xxx -n 50` |
| 磁盘满了 | 日志/缓存堆积 | `du -sh /*` 逐层找，清日志 |
| 内存 OOM（进程莫名消失） | 内存不足 | `dmesg \| grep -i kill`，加 swap/减服务 |
| cron 不执行 | 路径/权限/时区 | 改绝对路径，看 `journalctl -u cron` |
| 修改 unit 无效 | 忘了 reload | `systemctl daemon-reload` |
| SSH 突然连不上 | 改配置把自己锁了 / 安全组 | 用控制台 VNC 登录救回 |

## 九、从"能跑"到"跑得住"的 6 个动作

| 动作 | 价值 |
|---|---|
| 全部服务改 systemd 托管 | 崩溃自愈、开机自启 |
| 加健康检查 + 推送告警 | 出问题第一时间知道（你的签到已接入方糖） |
| 日志轮转 | 不会被 5G 日志撑爆磁盘 |
| 定期备份到本地 | 服务器没了也能重建 |
| 端口最小化 | 减少被扫、被爆破 |
| 写一份重建清单 | 三个月后还看得懂 |
