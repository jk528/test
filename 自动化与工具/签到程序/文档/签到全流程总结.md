# 统一签到全流程总结

> 整理时间：2026-10-24
> 覆盖范围：定时触发 → 批处理包装 → Node 脚本 → 六个平台 → 汇总输出 → 日志与排障

## 一、总览

```
Windows 任务计划「统一签到」 每日 10:35
        │  触发（仅当前用户登录时）
        ▼
cmd.exe /s /c "run_checkin.cmd" >> checkin_all.log 2>&1
        │  批处理：切 UTF-8、日志轮转、探测 Node、透传参数
        ▼
checkin_all.js（纯 Node、零依赖、单文件）
        │  按固定顺序逐平台执行，每个平台前随机等待 30~300 秒
        ▼
Trae → TeleAgent → WorkBuddy → CodeArts → Qoder → OfficeAce
        │  各平台独立 try/catch，单个失败不阻塞后续
        ▼
签到汇总 → 成功 x/6、失败 y/6 → 退出码 0/1
```

参与文件：

| 文件 | 作用 |
|---|---|
| `run_checkin.cmd` | 唯一入口，自动探测 Node 运行时 |
| `checkin_all.js` | 全部签到逻辑与公共工具（自包含） |
| `checkin_all.log` | 运行日志（计划任务重定向写入，UTF-8，超过 5 MB 轮转为 `.old`） |
| `sync_gitee.ps1` | 每 30 分钟同步仓库，与签到无关 |

## 二、触发层：Windows 任务计划

- **任务名**：`\统一签到`（中文名，用 `Register-ScheduledTask` 注册，避免 `schtasks` 乱码）
- **触发**：每天 10:35（Qoder 活动 10:00 才刷新，10:35 之后才可靠）
- **账户**：`Administrator`，`InteractiveToken`（仅用户登录时运行）
- **关键设置**：`StartWhenAvailable=true`（关机错过后开机补跑）、单次限时 90 分钟、失败重启 2 次（间隔 2 分钟）、`MultipleInstancesPolicy=IgnoreNew`
- **动作**：

```
cmd.exe /s /c ""<目录>\run_checkin.cmd" >> "<目录>\checkin_all.log" 2>&1"
```

`/s` 不可省：命令里同时出现引号、`>>`、`&` 时必须由 `/s` 处理外层引号剥离。

## 三、包装层：run_checkin.cmd

1. `chcp 65001`：让 cmd 自身提示与 Node 的 UTF-8 输出共用一种编码，避免日志混合乱码。文件本身保持纯 ASCII（否则 `chcp` 后 cmd 重新按偏移读取批处理会执行到注释碎片）。
2. **日志轮转**：`checkin_all.log` 超过 5 MB 时改名为 `.old`，旧 `.old` 删除。文件大小先由 `for %%A in (...)` 取到 `LOG_SIZE`，**必须在括号块之外**再判断（见第七节故障复盘）。
3. **Node 运行时探测**（按序，命中即停）：
   - PATH 中的 `node`
   - `C:\Program Files\nodejs\node.exe`
   - TeleAgent 自带 Node（`%USERPROFILE%\.local\share\TeleAgent\runtimes\node\node.exe`）
   - Trae CN / TRAE SOLO CN 的 EXE，设 `ELECTRON_RUN_AS_NODE=1` 兜底
   - 全部失败：输出 `ERROR: No Node.js runtime found` 并退出 1
4. **参数透传**：`%*` 原样传给脚本，所以 `run_checkin.cmd --no-delay` 即跳过随机延时。
5. **退出码**：直接沿用脚本的 `%ERRORLEVEL%`。

## 四、脚本层：checkin_all.js

- **入口**：`node checkin_all.js [--no-delay]`，由 `require.main === module` 守卫；同时 `module.exports` 导出各平台函数与公共工具，便于单独测试。
- **日志格式**：`YYYY-MM-DD HH:mm:ss 消息`（`toLocaleString('sv-SE')`），每个平台前打印 `====` 分隔段。
- **随机延时**：非 `--no-delay` 时，每个平台签到前等待 30~300 秒（`30 + rand(271)`），打乱固定时间特征；最坏总时长约 30 分钟，因此任务限时设为 90 分钟。
- **平台顺序**：Trae → TeleAgent → WorkBuddy → CodeArts → Qoder → OfficeAce，串行执行。
- **失败隔离**：每个平台单独 `try/catch`，抛错只记 `[平台] 致命错误`，循环继续。
- **汇总**：逐行输出 `[OK]/[FAIL] 平台名`，最后 `成功 x/6，失败 y/6`。
- **退出码**：有失败置 `process.exitCode = 1`，否则 0。用 `exitCode` 而非 `process.exit()`，避免 fetch(undici) 后强杀触发 libuv 断言崩溃。

## 五、六个平台的签到过程

### 1. Trae

- 凭证：`%APPDATA%\Trae CN\User\globalStorage\storage.json` 中 `iCubeAuthInfo://icube.cloudide` 字段，AES-CBC 解密得到 JWT；数据目录自动遍历 `Trae CN`（新）/`TRAE SOLO CN`（旧）。
- 附加头：`Authorization: Cloud-IDE-JWT`、区域头、`x-device-id`（来自 `ModularData\ckg_server\local_env.json`）、`x-device-type`、`x-os-version`、`x-app-version`。
- 流程：`checkin_credits/status` → 未签则 `checkin_credits/claim` → 再次 status 刷新积分 → 打印 `签到成功！积分：N`。
- 判定：`checked_in=true` 记“今日已签到”，`enable=false` 记“签到功能未启用”。

### 2. TeleAgent

- 凭证：`%USERPROFILE%\.local\share\TeleAgent\current-owner.json` 定位 owner → `users\<owner>\app-auth\token.json`，用 Chromium 主密钥做 AES-GCM 解密。
- 流程：`checkDayTask`（状态）→ 未领则 `checkTask?type=daily_login` → 复查 `checkDayTask` + `userCenter` → 打印今日得分、累计天数、余额。
- 判定：`daily_task.claimed_today` 为真即成功；401/登录类错误提示“打开客户端重新登录”。

### 3. WorkBuddy

- 凭证：`%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info`；accessToken 为 `$wbEncrypted` 信封，密钥由 `WorkBuddy.exe` 自取（无需客户端常驻）。
- 流程：`checkin-activity-status` → 未签则 `daily-checkin` → 复查状态。
- 判定：`today_checked_in` 为真即成功；领取返回 `10001`（云端竞态：已签）按已签处理；`active=false` 记活动未开启。

### 4. CodeArts

- 凭证：`%APPDATA%\codearts-agent\User\globalStorage\state.vscdb`，经 DPAPI + `node:sqlite` + AES-256-GCM 解出 AK/账号，需 Node 22.13+。
- 流程：`/v1/ops/delivery` 拉活动列表 → 定位 `campaignId=1`（每日签到）→ 状态判定 → `/v1/ops/claim` 领取 → `/v1/ops/confirm` 确认到账。
- 判定：`ELIGIBLE` 才领；`CLAIMED` 属“已领待确认”，补一次 confirm；`CONFIRMED/CONSUMED` 记已完成；AK 过期提示打开客户端续期。

### 5. Qoder

- 凭证：`%APPDATA%\com.qodercn.app.stable\auth.v1.dat`（国内版优先，国际版 `com.qoder.app.stable`），AES-GCM 解密；`auth.machine-id` 参与请求头。
- 流程：token 距到期不足 3 天自动刷新 → 拉 `campaigns` → 只认 `CLAIM_BENEFIT` 类型 → 领取 `CLAIMABLE` 活动 → 2 秒后复查。
- 判定：活动**每日 10:00（UTC+8）刷新**，早于刷新只记“今日活动尚未刷新”并跳过（不算失败）；`CLAIMED` 且 `startAt` 在今日刷新点之后记“今日已签到”。

### 6. OfficeAce（果办）

- 凭证：`%USERPROFILE%\.office-claw\session.cookie`，DPAPI 解出 `oc_sid`。
- 流程：弹性发现本地 API 地址（运行态快照 → `.env` 端口 → 默认端口 → 回环扫描）并信任 `root-ca.pem` → `GET /api/subscription/current` → `POST` 领取 → 2 秒后复查余额。
- 判定：「今日已领」看该活动 `effectiveTime` 是否落在北京时间今日 00:00 之后（`currentValue` 是已消耗量，不作依据）；活动每日 00:00 刷新、当日 23:59:59 过期；**客户端必须处于运行状态**，否则报“本地 API 无法连接”。

## 六、日志、结果与退出码

| 日志关键字 | 含义 | 是否算失败 |
|---|---|---|
| `签到成功！` | 本次领取成功 | 否 |
| `今日已签到` / `今日已领` / `今日签到已完成` | 今天此前已领过（客户端或本脚本） | 否 |
| `跳过` / `活动尚未刷新` / `活动未开启` | 活动不可领，非脚本问题 | 否 |
| `错误：...` / `签到失败：...` / `[FAIL]` | 需要人工处理（登录态、客户端未运行等） | 是 |
| `警告：...` | 非致命，继续执行 | 否 |

- 日志位置：`签到程序\checkin_all.log`；UTF-8；由任务重定向追加写入；超过 5 MB 轮转为 `checkin_all.log.old`。
- 退出码：`0` = 全部成功/已签/跳过；`1` = 至少一个平台失败。
- 单平台日志段以 `[平台名]` 分隔，汇总段固定为 `签到汇总：` 与 `成功 x/6，失败 y/6`。

## 七、2026-10-24 故障复盘

**现象**：当天 10:35 的签到没有任何平台记录，日志末尾只有两行：

```
5242880 was unexpected at this time.
```

任务“上次运行结果”为 `255`。

**根因**：10-23 14:05 为 `run_checkin.cmd` 新增日志轮转代码时，把大小判断写成了括号块内的 `if %LOG_SIZE% GTR 5242880 (`。cmd 会先解析整个括号块再执行，此时 `%LOG_SIZE%` 尚未被 `for` 赋值，被替换为空，语句变成 `if GTR 5242880 (`，cmd 报语法错误并中止整个批处理——所以连“统一签到开始”都没打印，6 个平台全部未执行。

**修复**：先取大小、再单独判断，把变量读取移出括号块：

```bat
set "LOG_SIZE=0"
if exist "%LOG_FILE%" for %%A in ("%LOG_FILE%") do set "LOG_SIZE=%%~zA"
if %LOG_SIZE% GTR 5242880 (
    move /y "%LOG_FILE%" "%LOG_FILE%.old" >nul 2>&1
    if exist "%LOG_FILE%.old.old" del /q "%LOG_FILE%.old.old" >nul 2>&1
)
```

**验证**：用 6 MB 假日志在临时目录实测，取到 `6000000` 且成功轮转；再手动补跑一次，6/6 成功、退出码 0，不再出现该报错。

**补跑结果（2026-10-24 20:57）**：Trae / WorkBuddy / OfficeAce 显示“今日已签到”（此前客户端已领，未重复领取），TeleAgent +100、CodeArts +1000 CREDIT、Qoder +100 CREDITS 由本次补上。

## 九、维护要点

1. **时间不要早于 10:35**：Qoder 活动 10:00 刷新，提早会漏签。
2. **登录态是第一依赖**：各平台重新登录后脚本自动复用凭证，无需改代码；出现“登录态已过期”打开对应客户端登录即可。
3. **OfficeAce 需客户端运行**：它是本地 API 桥接，客户端未启动必失败。
4. **CodeArts 需 Node 22.13+**（`node:sqlite`），其余平台 Node 18+ 即可。
5. **改 `run_checkin.cmd` 时的批处理陷阱**：括号块内的 `%VAR%` 在解析期展开，需先赋值再在块外使用，或启用 `EnableDelayedExpansion` 用 `!VAR!`；文件保持纯 ASCII。
6. **只注册一个计划任务**，避免重复签到与并发写日志（`IgnoreNew` 已限制同一任务多实例）。
7. **Trae 1024 抽奖已移除**：原 `checkin_1024` 抽奖逻辑（签到后调 `activity/action`）已从 `checkin_all.js` 删除，Trae 段现在只做每日签到。历史逆向记录仍保留在 `文档\Trae1024签到抽奖逆向记录*.md` 备查。
