# 项目架构整理方法论：从杂乱目录到 SKILL 规范式结构

> 整理日期：2026-10-25　|　素材来源：签到程序目录重构实战（17→23 文档、4 阶段分类、总分结构）
> 定位：通用方法论。下次整理任何项目（不限于签到）按此走一遍

---

## 一、整理六步法（通用）

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| 1. 盘点 | 列出全部文件，逐个读开头判断内容归属与重复度 | 文件清单 + 内容一句话摘要 |
| 2. 分类 | 按**生命周期/工作流**设计分类维度（不是按文件类型） | 分类框架（本项目：逆向前/中/后/维护） |
| 3. 建结构 | 根目录 = 总纲 + scripts/ + config/ + logs/ + 文档/ | SKILL 规范式骨架 |
| 4. 迁移 | 移动文件；重复的去重（留新删旧）、过时的归档 | 物理落位 |
| 5. 适配引用 | 改代码里的路径、改外部引用（计划任务/快捷方式/.gitignore） | 引用一致性 |
| 6. 验证 | 端到端跑一遍真实链路 | 不是"文件看起来整齐"就算完 |

**总分结构**：整体一个总纲 md；每个分类文件夹一个 `00-总结.md`（30 秒版结论 + 详细文档索引 + 上位文档指路）。阅读路径：总 → 分 → 细节，每层不迷路。

## 二、通用规则 vs 项目特殊处理

### 通用的（任何项目照搬）

1. **根目录只放总纲**——其余全部进子目录，根目录一眼看清结构
2. **可执行 / 配置 / 产物 / 文档 四类分离**——scripts、config、logs、docs 各司其职
3. **配置与凭证隔离成独立目录**——便于整体 .gitignore 排除（本项目：`config/` 整目录排除，新增凭证文件天然安全，不用每次加规则）
4. **00-总结.md 命名**——数字前缀让它在文件管理器里永远排在最前
5. **冗余处置三档**：重复内容留新删旧；过时但有史料价值的归档并标注；纯垃圾直接删
6. **移动后必须改引用**——代码路径、外部调度、忽略规则，一个都不能漏

### 特别的（本项目特有，其他项目不会遇到）

| 特殊点 | 原因 | 处理 |
|---|---|---|
| 计划任务引用绝对路径 | Windows 任务计划程序的 Action 写死了 .cmd 路径 | 移动后必须 Set-ScheduledTask 更新，且**参数不能加引号**（见下） |
| cmd 中文路径 + 引号 + `>>` 重定向解析失败 | cmd 对中文路径下「引号包裹的批处理 + 重定向」组合有解析 bug | 路径无空格时全程无引号（实测六组对照实验定位） |
| cmd 用 `%~dp0` 自定位 | 批处理按自身位置找 js | 脚本整体移动零改动，只有日志路径要改 |
| 凭证文件散在根目录 | 历史遗留 | 收拢进 config/，3 个脚本 cfgPath 改 `..\config\` |
| 四阶段分类法 | 签到平台的生命周期（逆向→接入→维护） | 其他项目应换自己的维度，如「需求→开发→发布→运营」 |

## 三、好例子（从本项目提炼）

### 例 1：分类维度要跟着工作流走

❌ 按文件类型分：`文档/逆向记录/`、`文档/指南/`、`文档/记录/` —— 想知道"新增平台怎么做"要翻三个目录
✅ 按生命周期分：`01-逆向前` → `02-逆向中` → `03-逆向后` → `04-维护` —— 做事的顺序就是目录的顺序

### 例 2：总纲放根部，像 SKILL.md

❌ 总纲藏在 `文档/` 里和 23 个文档并列 —— 等于没有总纲
✅ `签到程序/签到平台开发维护手册.md` 根部独立存在 —— 打开项目第一眼就是它

### 例 3：00-总结.md 解决"文档多了反而找不到"

每个阶段文件夹里 5~8 个详细文档，但入口永远只有一个 `00-总结.md`：30 秒版结论 + 索引表 + "已删除的冗余"说明。详细文档退化为按需查阅的存档。

### 例 4：凭证整目录排除优于逐文件排除

❌ `.gitignore` 里每加一个凭证文件加一行规则 —— 总会忘
✅ `/签到程序/config/` 整目录排除 —— 约定"凭证只放 config/"，新增凭证文件零操作

### 例 5：迁移后验证要跑真实链路，不是看文件在不在

本次重构中文件移动全部"成功"，但计划任务实测秒退码 1——cmd 引号解析坑只有端到端触发才暴露。**整理的最后一步永远是：把系统真实跑一遍。**

### 例 6：合并重复文档时保留双方独特信息

TraeWork/TraeCN 两份逆向记录内容重复（API 一致），但各有独特信息（配置演进史、实测输出）。合并版保留两者增量 + 注明合并来源和时间，而不是粗暴删一份。

## 五、收尾优化：引用一致性与乱码修复（2026-10-25 实战补充）

文件迁移完≠整理完。文档网络（md 互链 + 代码文件链接）和文件编码还要过一遍收尾。

### 5.1 断链扫描修复（三层）

| 层 | 模式 | 本项目战果 |
|---|---|---|
| md 互链 | `[名](名.md)` 同目录拼接验证 | 8 处跨目录断链（目录重构后 `../02-.../` 补前缀） |
| 代码文件链接 | `](../xxx.js#L123)` 验证文件存在 | **28 处断链**——首轮只修了 1 处纯文件名链接，漏了 27 处带 `#L行号` 锚点的变体。教训：**替换链接时模式要覆盖锚点变体** |
| 文本路径引用 | 正文里的 `签到程序\run_checkin.cmd` 类描述 | 6 处过时路径（脚本进 scripts/、日志进 logs/） |

### 5.2 乱码检测的三种模式

编码事故（GBK/UTF-8 转换）不只有 U+FFFD 替换字符一种表现：

| 模式 | 特征 | 实例 |
|---|---|---|
| 反引号→同字包裹 | `` `code` `` 变成 `文code文` / `签code签`（`` ` `` 被转成汉字，不同文件坏成不同字） | 本项目 160 处，跨 3 个文档 |
| 符号→汉字 | ` [` 变 ` 任` | 使用说明.md 2 处 |
| 混合损坏 | 同一段落前后损坏字符不一致（`签MD文`） | 需逐处精准替换 |

**修复模式**：正则 `同字([A-Za-z0-9_./:=+() -]{2,})同字` 还原为 `` `$1` ``。字符类要含空格和括号——首轮漏了 `` `checkinKuku()` ``（含括号）和 `` `push exit code: 1` ``（含空格）两类。

### 5.3 扫描误报清单（本项目实测）

| 误报 | 原因 |
|---|---|
| "任务计划配置记录.md]" 被判乱码 | 文件名恰好以"任"字开头 |
| "备份 3 份"、"本地 API 地址" 被判同字包裹 | 中文量词/正常词汇天然满足模式 |
| 扫描器把已修好的 `../02-xxx/果办.md` 链接报为断链 | 检查器只按同目录拼接，没解析 `../` |

**对策**：扫描结果必须人工复核或 Test-Path 真实验证，不能全信正则。

### 5.4 历史快照 vs 现行指南的区分原则

不是所有"过时路径"都要改：

- **现行指南**（使用说明/排障手册/部署文档）：路径必须与当前结构一致，错的就是 bug
- **历史记录**（逆向研究/修复总结）：文中的旧路径是**当时的事实**（如"桌面\定时任务脚本\"），改了反而破坏史料真实性——保持原样

### 5.5 收尾检查清单（并入第四节）

- [ ] md 互链断链扫描通过（含 `../` 解析验证）
- [ ] 代码文件链接验证（含 `#L行号` 锚点变体）
- [ ] 乱码三模式扫描（同字包裹 / 符号变汉字 / U+FFFD）零残留
- [ ] 现行指南路径与真实结构一致；历史记录保持原样
- [ ] 扫描误报已人工复核排除
