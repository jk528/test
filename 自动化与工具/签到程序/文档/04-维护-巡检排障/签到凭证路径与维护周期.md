# 签到凭证的两条技术路径与维护周期

> 整理日期：2026-10-25　|　回答两个核心问题：
> 1. 逆向类平台是否"永久解决"？
> 2. Cookie 类平台是否需要定期登录？

---

## 一、当前各平台的凭证路径归类

| 平台 | 路径 | 凭证来源 | 凭证载体 |
|---|---|---|---|
| Trae | **本地逆向** | 客户端 storage.json，AES-128-CBC+SHA-512 自研算法解密 | JWT token |
| TeleAgent / WorkBuddy / CodeArts / Qoder / OfficeAce | **本地逆向** | 客户端 Chromium 数据库，DPAPI+AES-GCM 解密 | accessToken |
| 库库AI（kuku） | **Cookie** | 夸克浏览器提取 BDUSS/STOKEN，STOKEN 可由 ptoken 自动换新 | BDUSS（百度账号级） |
| 百度网盘 | **Cookie** | 夸克浏览器提取 BDUSS/STOKEN 等 | BDUSS（百度账号级） |
| 天翼云盘 | **Cookie + 自动续期** | 夸克浏览器提取 COOKIE_LOGIN_USER，失效时脚本自动重新提取 | COOKIE_LOGIN_USER |
| 万兴脑图 | **refresh_token 自续命**（2026-10-25 重构） | config/edraw_config.json 存 refresh_token（30 天有效，每次运行刷新时轮换），浏览器提取仅作兜底 | refresh_token（EDCurrent Cookie 内提取） |
| 夸克网盘 | ~~Cookie + 签名~~ **已放弃**（2026-10-25） | 实测网页版 Cookie 链路签到为空操作，移动端链路必须 kps/sign/vcode | — |

## 二、两条路径的本质区别

### 路径 A：本地逆向（Trae 等 6 平台）

```
脚本启动 → 读客户端本地数据库 → 解密出最新 token → 调接口
```

**关键点：脚本不保存凭证，每次运行时从客户端现取现用。** token 的刷新、续期全部由客户端自己完成（客户端只要保持登录，就会持续刷新 token）。

### 路径 B：Cookie 复用（网盘类平台）

```
脚本启动 → 读 config.json 里保存的 Cookie → 调接口
         ↓ Cookie 失效
         从浏览器重新提取（天翼已自动化）或人工更新
```

**关键点：凭证是"快照"，有固定有效期，过期必须换新。**

## 三、问题 1：逆向类是永久解决吗？

**准确说：是"免维护"，不是"永久"。** 在以下条件全部满足时，逆向类平台可以无限期无人值守运行：

| 条件 | 说明 | 破坏后果 |
|---|---|---|
| 客户端保持登录 | 用户不主动退出登录，token 由客户端自动刷新 | 退出登录后脚本拿到的是失效 token，需重新登录客户端 |
| 客户端定期启动过 | token 有有效期（通常数天~数周），客户端运行时才刷新 | 客户端长期不开 → token 过期 → 签到失败，需打开一次客户端 |
| 客户端不大版本升级 | 加密算法、存储路径、数据格式是逆向钉死的 | 存储结构变了 → 解密失败 → 需重新逆向适配 |

**结论：只要客户端正常用着（每天开过、保持登录），逆向类就是零维护；真正的风险只在"客户端大改版"——届时需要重新逆向。**

## 四、问题 2：Cookie 类需要定期登录吗？

分平台，差异很大：

| 平台 | 需要定期登录吗 | 维护动作 |
|---|---|---|
| 天翼云盘 | **不需要主动管** | Cookie 失效时脚本自动从夸克浏览器重新提取；唯一前提：夸克浏览器里 cloud.189.cn 保持登录（浏览器自己会保持，除非手动退出/清 Cookie）。**注意：COOKIE_LOGIN_USER 是会话 Cookie，浏览器进程彻底退出即失效——服务器重启后需确认 cloud.189.cn 仍登录** |
| 万兴脑图 | **不需要主动管** | refresh_token 30 天有效、每次运行自动轮换保存（每天跑=永久续命）；**唯一点：若连续 30 天未运行则 refresh_token 过期，需在夸克浏览器退出并重新登录 https://mm.edrawsoft.cn/app（应用内登录流程才会把 refresh_token 写进 EDCurrent Cookie），脚本兜底提取一次即恢复** |
| 百度网盘 | **数月一次** | BDUSS 有效期数月，失效后需在浏览器重新登录 pan.baidu.com，再提取一次（可半自动化） |
| 库库AI | **数月一次** | 与百度网盘共用 BDUSS；STOKEN 会过期但脚本可用 ptoken 自动换新，BDUSS 才是根基 |
| 夸克网盘 | — | 已放弃（2026-10-25），见「三云盘签到平移实现记录.md」三-3 |

**加速失效的共同事件（任何平台改密码/安全设置后，Cookie 立即作废）：**

- 修改账号密码
- 账号安全设置变更（开启/关闭设备锁、二次验证）
- 在浏览器里手动退出登录
- 清理浏览器 Cookie

## 五、失效时的快速判断

看签到日志的报错形态即可定位是哪一层的问题：

```
解密失败 / 找不到登录态        → 路径 A 问题：客户端退出登录了，打开客户端登录即可
401 / require login / 未登录   → 路径 B 问题：Cookie 过期，按上表第四列处置
errno=-6（库库AI）            → BDUSS 失效，需重新提取
HTTP 4xx/5xx 且非鉴权错误      → 接口变动：查上游仓库/抓包对比，改脚本
```

## 六、演进方向

- 百度网盘、库库AI 的 Cookie 提取可以和天翼一样做成**失效自动重新提取**（技术链路已就绪，复用同一套 VSS+DPAPI 代码），把"数月一次人工"也消掉
- 夸克网盘若 kps/sign 验证为长期有效，则补一次抓包后同样进入"免维护"区间
- 所有平台的兜底警报：连续失败 N 天时在日志中显著标记（或接入消息推送），避免静默失效
