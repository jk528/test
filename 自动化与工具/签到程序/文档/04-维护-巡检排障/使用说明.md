# 签到程序使用说明

多平台积分每日自动签到，**API 直连**，无需打开客户端窗口。`scripts\run_checkin.cmd`（唯一入口，自动探测 Node）调用 `scripts\checkin_all.js`（主控 10 平台，AI 平台逻辑自包含，云盘/库库等平台经 PLATFORMS 注册表 spawn 子脚本，纯 Node 零依赖）。

## 一、目录结构

```
签到程序/
├── 签到平台开发维护手册.md   # 总纲（四阶段方法论 + 文档索引）
├── scripts/               # 可执行文件
│   ├── run_checkin.cmd    # 唯一入口（自动探测 Node 运行时）
│   ├── checkin_all.js     # 主控：PLATFORMS 注册表 + 6 个 AI 平台内联逻辑
│   ├── kuku_checkin.js    # 库库AI（子脚本，config/kuku_config.json）
│   ├── baidupan_checkin.js# 百度网盘（子脚本）
│   ├── tianyi_checkin.js  # 天翼云盘（子脚本）
│   ├── edraw_checkin.js   # 万兴脑图（子脚本，config/edraw_config.json 存 refresh_token 自续命）
│   └── sync_gitee.ps1     # Gitee 仓库定时同步（可选，与签到无关）
├── config/                # 凭证（.gitignore 整目录排除，严禁提交）
├── logs/                  # checkin_ai.log / checkin_daily.log
├── 分享文件夹/             # 10 平台独立模板合集（可单独拷走分享，先读其 README.md）
└── 文档/                  # 四阶段分类（各阶段先看 00-总结.md）
```

## 二、平台与执行时间

**凌晨 AI 组（00:05，6 平台）**：

| 平台 | 说明 |
|---|---|
| Trae | 原 TraeWork/TraeCN 已合并为单平台，数据目录自动遍历新旧名 |
| TeleAgent | 经 current-owner.json 定位 token |
| WorkBuddy | 密钥自动获取（binding → 缓存 → WorkBuddy.exe 自取），无需客户端运行 |
| CodeArts | DPAPI + node:sqlite + AES-GCM 解密，需 Node 22.13+ |
| OfficeAce（果办） | **需果办客户端处于运行状态**，本地 API 调用 |
| 库库AI | 百度 BDUSS 鉴权（config/kuku_config.json） |

**白天组（10:35，4 平台）**：

| 平台 | 说明 |
|---|---|
| Qoder | **活动每日 10:00 刷新，必须在白天组** |
| 百度网盘 | BDUSS 鉴权（config/baidupan_config.json） |
| 天翼云盘 | 浏览器 Cookie，失效自动重新提取（config/tianyi_config.json 缓存） |
| 万兴脑图 | refresh_token 自续命（30 天轮换，config/edraw_config.json），浏览器重新登录可兜底重建 |

**两个计划任务分组执行**（00:05 AI 组 / 10:35 白天组）。各平台顺序执行，签到前随机等 30~300 秒；单平台失败记录日志并继续，不影响其它平台。退出码：`0` = 全部成功/已签，`1` = 至少一个平台失败。

## 三、运行依赖

- **Node 18+**（CodeArts 需 22.13+）。`run_checkin.cmd` 按序探测：PATH 的 `node` → `C:\Program Files\nodejs` → TeleAgent 自带 Node → Trae EXE（`ELECTRON_RUN_AS_NODE=1`）
- **各平台已登录**产生的本地凭证（脚本只复用，不存账号密码）：

| 平台 | 凭证位置 |
|---|---|
| Trae | `%APPDATA%\Trae CN\User\globalStorage\storage.json`（旧名 `TRAE SOLO CN`） |
| TeleAgent | `%USERPROFILE%\.local\share\TeleAgent\users\<owner>\app-auth\token.json` |
| WorkBuddy | `%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info` |
| Qoder | `%APPDATA%\com.qodercn.app.stable\auth.v1.dat`（国际版 `com.qoder.app.stable`） |
| CodeArts | `%APPDATA%\codearts-agent\User\globalStorage\state.vscdb` |
| OfficeAce | `%USERPROFILE%\.office-claw\session.cookie` |

## 四、手动运行

```powershell
cd "<签到程序目录>"
.\scripts\run_checkin.cmd --group=ai               # 凌晨 AI 组（6 平台）
.\scripts\run_checkin.cmd --group=daily            # 白天组（4 平台）
.\scripts\run_checkin.cmd --group=daily --no-delay # 跳过延迟快速测试
node scripts\checkin_all.js --group=ai --no-delay  # 直接调用主控
```

## 五、注册计划任务（PowerShell）

```powershell
$dir = $PSScriptRoot   # 粘贴执行时改为：$dir = (Get-Location).Path
# 注意：路径含中文时，cmd 路径与 >> 重定向目标都不要加引号（路径无空格），
# 否则任务秒退码 1 且无日志（2026-10-25 实测定位，见任务计划配置记录）
$argAI  = "/s /c $dir\scripts\run_checkin.cmd --group=ai >> $dir\logs\checkin_ai.log 2>&1"
$argDay = "/s /c $dir\scripts\run_checkin.cmd --group=daily >> $dir\logs\checkin_daily.log 2>&1"
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Minutes 90)
Register-ScheduledTask -TaskName "签到-凌晨AI组" -Action (New-ScheduledTaskAction -Execute "cmd.exe" -Argument $argAI)  -Trigger (New-ScheduledTaskTrigger -Daily -At "00:05") -Settings $settings -Force
Register-ScheduledTask -TaskName "签到-白天组"   -Action (New-ScheduledTaskAction -Execute "cmd.exe" -Argument $argDay) -Trigger (New-ScheduledTaskTrigger -Daily -At "10:35") -Settings $settings -Force
```

要点：用 `Register-ScheduledTask` 而非 `schtasks`（中文任务名无乱码）；`cmd /c` 含 `>>`、`&` 必须加 `/s`；白天组触发时间 ≥ 10:35（Qoder 每日 10:00 刷新限制）；`-StartWhenAvailable` 关机错过后开机补跑；限时 90 分钟（随机延时最坏约 30 分钟）。目录迁移后的改绑流程与历史教训见 [任务计划配置记录.md](../03-逆向后-落地接入/任务计划配置记录.md)。

常用管理：

```powershell
Get-ScheduledTaskInfo -TaskName "签到-凌晨AI组","签到-白天组"   # 状态与下次运行时间
Start-ScheduledTask -TaskName "签到-白天组"                     # 手动触发
Unregister-ScheduledTask -TaskName "签到-凌晨AI组" -Confirm:$false
```

## 六、日志与常见问题

日志在 `logs/` 目录（`checkin_ai.log` / `checkin_daily.log`，UTF-8，由计划任务重定向写入）。客户端升级跑挂了看 [排障手册.md](排障手册.md)。

| 报错 | 原因 |
|---|---|
| `未检测到数据目录` | 客户端未安装或未登录 |
| `登录态已过期` | 打开客户端重新登录 |
| `未找到 Node.js 运行时` | 安装 Node 18+ |
| `缺少内置 node:sqlite` | CodeArts 需 Node 22.13+ |
| Qoder 领不到 | 任务时间早于 10:30，改到 10:35 后 |

## 七、自动探测机制

所有路径无硬编码，客户端更名/迁移/卸载自动适配：

| 探测项 | 方式 |
|---|---|
| Trae 数据目录 | 遍历 `%APPDATA%` 下新→旧目录名，选含 `storage.json` 的 |
| 客户端安装目录 | 注册表 `Uninstall` → 常见安装路径 |
| WorkBuddy EXE / 各版本号 | 注册表 / 常见路径；`resources\app\package.json` |
| OfficeAce 本地 API | 运行态快照 → `.env` 端口 → 默认端口 → 回环端口扫描 |
| Node / Git 运行时 | PATH → 常见路径 → TeleAgent 自带 → Trae EXE 兜底 |

公共工具（`regQueryInstallLocation`、`detectAppVersion`、`dpapiUnprotect`、`aesGcmDecryptV10` 等）集中在 `checkin_all.js` 顶部，`module.exports` 导出便于单独测试；入口由 `require.main === module` 守卫。
