# 三云盘签到：青龙方案平移到本地脚本的实现记录

> 整理日期：2026-10-25　|　落地环境：Windows Server 2022 + Node 24 + Windows 任务计划（无 Docker 青龙）

---

## 一、背景与目标

参考青龙面板脚本仓库的签到逻辑，为**天翼云盘、百度云盘、夸克网盘**实现本地自动签到。本机因云平台未开放嵌套虚拟化装不了 Docker，无法部署青龙面板，因此采用「独立 Node.js 脚本 + Windows 任务计划程序」的平替方案，与现有 `checkin_all.js` / `kuku_checkin.js` 同风格。

## 二、平移思路：从青龙仓库到裸脚本

青龙仓库的签到脚本本质是「凭证 + HTTP 接口调用」，平移时剥离青龙框架（`Env` 环境变量、notify 推送），保留核心接口逻辑：

| 青龙仓库 | 对应平台 | 凭证类型 | 平移产出 |
|---|---|---|---|
| tunecc/DuPan | 百度网盘 | Cookie（BDUSS 等） | `baidupan_checkin.js` |
| vistal8/tianyiyun | 天翼云盘 | 账号密码（RSA 加密登录） | `tianyi_checkin.js` |
| Cp0204/quark-auto-save + as.js.cool | 夸克网盘 | Cookie + kps/sign/vcode | `quark_checkin.js` |

脚本统一规范（对齐 kuku_checkin.js）：

- 同目录 `*_config.json` 存凭证，环境变量可覆盖，全部加入 `.gitignore`
- `--status` 只读查询、`--no-delay` 跳过随机延时（默认签到前随机等 30~300 秒防检测）
- 退出码 0=成功/已签，1=失败；`process.exitCode` 自然退出（避免 Node 24 + Windows 下 `process.exit` 触发 libuv 断言）
- `module.exports` 导出 `run` + `require.main` 守卫，便于后续并入统一签到

## 三、各平台接口要点

### 1. 百度网盘（已实测通过）

移植自 tunecc/DuPan，三个接口（均 GET，Cookie 鉴权，`app_id=250528&web=5`）：

1. **签到**：`pan.baidu.com/rest/2.0/membership/level?method=signin`
2. **每日答题**：`getdailyquestion` 取答案 → `answerquestion` 提交（答题答案由接口直接返回，白送分）
3. **成长值查询**：`membership/user?method=query`

凭证：复用从夸克浏览器 Cookie 库提取的 BDUSS（192 字符）/ STOKEN / PTOKEN / BAIDUID / csrfToken，写入 `baidupan_config.json`。

实测结果：签到成功、答题 +3 积分、等级 1 成长值 2。

### 2. 天翼云盘（已实测通过，Cookie 模式）

密码登录链路移植自 cloud189-sdk（PC 链路）：

1. POST `open.e.189.cn/api/logbox/config/encryptConf.do` → 拿 RSA 公钥与前缀 `pre`
2. GET `cloud.189.cn/api/portal/unifyLoginForPC.action` → 正则提取 `captchaToken / lt / paramId / reqId`
3. 账号密码 RSA 加密（**hex 输出**，`pre` 前缀）POST 到 `loginSubmit.do`（带 `lt` + `REQID` 头）

**实测撞墙**：账号开启设备锁，`loginSubmit.do` 返回 `result=-133 "设备ID不存在，需要二次设备校验"`（短信二次验证），wap 链路与 PC 链路均如此，密码登录无法全自动。

**最终方案：Cookie 模式（绕过设备锁）**

用户夸克浏览器已登录 cloud.189.cn 网页版 → 自动提取 `COOKIE_LOGIN_USER` + `JSESSIONID` 等 cookie → 直接调 `cloud.189.cn/mkt/userSign.action` 签到（实测返回 `isSign/netdiskBonus`）。

脚本策略（`tianyi_checkin.js`）：

1. **Cookie 优先**：有 cookie 直接签到
2. **失效自动续**：Cookie 失效时自动从夸克浏览器重新提取（VSS+DPAPI 链路，与百度凭证提取同源）并回写配置，重试一次
3. **密码兜底**：提取失败才走账号密码登录（可能撞设备锁，需人工网页端过验证）

### 3. 夸克网盘（接口就绪，凭证待抓包）

移植自 Cp0204/quark-auto-save：

- 状态查询：`GET drive-m.quark.cn/1/clouddrive/capacity/growth/info`
- 签到：`POST .../capacity/growth/sign`，body `{"sign_cyclic": true}`
- 返回连签进度 `sign_progress/sign_target`、累计空间 `cap_composition.sign_reward`

**关键障碍**：接口除 Cookie 外还强制要求移动端签名参数 `kps / sign / vcode`（query 或 `x-u-kps-wg` 等请求头）。

## 四、问题与解决过程

### 问题 1：凭证来源——如何不麻烦用户手动抓包

**思路**：夸克浏览器已登录百度账号、夸克网盘 PC 客户端已登录，尝试从本地浏览器/客户端数据库自动提取 Cookie。

**技术链路**（此前在库库AI签到中已验证）：

1. Cookie 库被运行中的浏览器独占 → `vssadmin create shadow /for=C:` 创建卷影副本 → `mklink /d` 符号链接进卷影 → 拷出 `Cookies` 数据库
2. 从 `Local State` 的 `os_crypt.encrypted_key` 去掉 `DPAPI` 前缀 → DPAPI(CurrentUser) 解密得 AES-256-GCM 主密钥
3. Cookie 值 `v10` 信封解密：3B 前缀 + 12B nonce + 密文 + 16B tag
4. **新版 Chromium 陷阱**：明文前 32 字节是 `SHA256(host_key)`，需剥除
5. `node:sqlite` 查询时不能 SELECT `expires_utc`（大整数溢出）

**结果**：百度网盘凭证提取成功（签到实测通过）。

### 问题 2：夸克客户端 Cookie 里没有 kps/sign/vcode

从夸克网盘客户端（`%LOCALAPPDATA%\QuarkCloudDrive`）提取的 Cookie 仅 3 条（`__kuus/__uus/_UP_RI_`），调用 `growth/info` 返回 **401 require login**——说明客户端真正的登录态不在标准 Cookie 库。

继续排查：

- `user_info/`、`account.json`、`preference.json`、`config.json` → 只有设备 GUID 和加密票据，无三参数
- **Local Storage leveldb**（`Default/Local Storage/leveldb`）→ 发现 `drive_member_info` 记录里有 `kps_wg / sign_wg / vcode` 字段！

**结论**：新版夸克客户端的 `kps_wg/sign_wg` 是**按请求动态生成**的（sign 每次都不同），vcode 实际是时间戳，落盘记录里均为空或过期值。无法靠本地提取获得可用凭证。

**最终方案**：脚本支持「cookie 中自动提取 kps/sign/vcode」+「config 单独字段覆盖」双通道，凭证需用户手机 APP 或 PC 客户端抓包 `growth/info` 请求获取（与青龙社区通行做法一致，as.js.cool 文档亦如此要求）。

### 问题 3：百度网盘接口字段嵌套层级与文档不符

tunecc/DuPan 用正则从响应文本提取 `current_value`，实测响应 JSON 层级比预期深（会员信息在 `current_product_v2` 等嵌套里）。解决：用递归 `deepFind` 兼容查找 `current_value/current_level`，并兜底返回 `product_type`。

### 问题 4：PowerShell 内嵌 Node 代码的引号转义地狱

调试期用 `node -e "..."` 内嵌 PS 脚本片段，双引号/`$`/反引号三层转义反复报错。解决：一律写临时 `.js` 文件执行，用完删除，不在命令行里嵌套多语言代码。
