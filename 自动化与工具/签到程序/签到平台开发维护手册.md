## 一、逆向前：调研与路线选择

**目标：不重复造轮子，选对最省力的凭证路线。**

1. **先查 GitHub 有没有现成脚本**
   - 搜索词：平台中文名+签到、拼音、英文品牌名（如 mindmaster/edrawmind）
   - 查综合库覆盖：sitoi/dailycheckin、Wenmoux/checkbox、sudojia/AutoTaskScript
   - 案例：天翼/百度网盘有青龙脚本可参考接口；万兴脑图/库库AI 没有，只能自己逆向
2. **判断凭证路线（决定后续所有工作量和维护成本）**

   | 路线 | 适用条件 | 维护成本 | 案例 |
   |---|---|---|---|
   | 客户端本地逆向 | 有 PC 客户端且保持登录 | 零维护 | Trae、TeleAgent、WorkBuddy、CodeArts、Qoder、OfficeAce |
   | 浏览器 Cookie | 网页版能完成签到动作 | 低（可自动续期） | 天翼云盘、万兴脑图 |
   | 账号密码 | 无设备锁/滑块 | 低，但易被风控 | 天翼（已被设备锁堵死，弃用） |
   | Cookie + 动态签名 | 移动端专属活动 | 高，需逆向签名算法 | 夸克网盘（放弃） |
3. **准备工作**
   - 夸克浏览器登录目标网站（Cookie 路线的前提）
   - 移动端专属活动：准备好 APK（官网扫码页/应用商店/第三方市场）
   - 确认本机工具链：Node 24+（node:sqlite）、PowerShell（DPAPI）、管理员权限（VSS）

## 二、逆向中：问题与解决方案速查

**按出现频率排序，全是实战踩过的坑：**

| 问题 | 现象 | 解决方案 |
|---|---|---|
| Cookie 库被浏览器独占 | 读 Cookies 文件报锁/内容为空 | **VSS 卷影**：`vssadmin create shadow /for=C:` → mklink 符号链接 → 拷出主库+`-wal`/`-shm` → 删卷影 |
| Cookie 解密失败 | v10 前缀但 AES-GCM 报错 | Local State 的 `os_crypt.encrypted_key` 去 "DPAPI" 前缀 → DPAPI(CurrentUser) 解密得主密钥 → AES-256-GCM（nonce=3..15字节，tag=末16字节） |
| 解密出来是乱码 | 新版 Chromium 明文前附 32 字节 | 剥除 `SHA256(host_key)` 前缀再解析 |
| SQLite 查询报错 | `expires_utc` 大整数溢出 | `CAST(expires_utc AS TEXT)` 读出再转 BigInt |
| 网页版没有签到入口 | 页面搜"签到/任务/积分"零命中 | 走 APK 路线：DEX strings 提取接口路径（本手册万兴案例） |
| 接口路径盲猜失败 | 全 404 | 别猜了。解压 APK → 提取所有 `api/` 开头字符串 → 找 clockin/sign/task 端点 |
| 设备锁拦登录 | 天翼 `result=-133 二次设备校验` | 放弃密码登录，改用浏览器已登录会话的 Cookie（服务端只校验会话，不校验 clientType 真实性） |
| 接口要动态签名 | 夸克 kps/sign/vcode | 评估是否值得逆向签名算法；不值得就放弃该平台（投入产出不匹配） |
| JWT 短寿 | 万兴 token 仅 2 小时 | 不存凭证，**每次运行现从浏览器提取**，token 短寿反而无关 |
| 签到返回 200 但没生效 | 夸克 fr=pc 签到前后容量不变 | 对比签到前后的真实资产数值（容量/积分），别信 status=success |

**DEX strings 提取法（万兴案例，GitHub 无脚本时的标准动作）：**

1. APK 改名 .zip 解压，取 `classes*.dex`
2. 提取连续可打印 ASCII（≥4 字符）
3. 先搜类名（`CheckInPresenter` 等）确认功能存在，再搜 `/api/` 路径
4. 用浏览器拿到的 token 实测端点（GET 405 会告诉你支持 POST）

## 三、逆向后：落地标准动作

1. **写独立脚本 `xxx_checkin.js`**，遵循统一范式（参照 kuku_checkin.js）：
   - 凭证走 `xxx_config.json`（纯 JSON 无注释）或浏览器自动提取
   - `--status` 只读查询、`--no-delay` 跳过随机延时、退出码 0=成功/已签、1=失败
   - `process.exitCode` 自然退出（Node 24+Windows 下 `process.exit()` 强杀会触发 libuv 断言）
   - 签到前随机延时 30~300 秒防检测
2. **凭证文件立即加入 .gitignore**（BDUSS/Cookie ≈ 账号密码），提交前用真实凭证值反查一遍 Git 历史
3. **接入统一任务**：在 `checkin_all.js` 的 `PLATFORMS` 注册表加一行 `{ name, group, script }`，主控零改动（spawnSync 子进程，进程隔离）
   - 分组判断：每日 0 点刷新的放 `ai` 组；刷新时间晚或网盘类放 `daily` 组
4. **三层实测**：`node --check` → `--status` 只读 → 真实签到一次，再 `--group=xxx` 整组串联验证
5. **更新文档**：《签到全流程总结》加平台小节；凭证有特殊性时更新《签到凭证路径与维护周期》

## 四、维护：日常要做什么

**巡检节奏：**

| 频率 | 动作 |
|---|---|
| 每周 | 看 `checkin_ai.log` / `checkin_daily.log` 有无 `[FAIL]` |
| 每月 | 跑一次 `node checkin_all.js --no-delay` 全量验证；浏览器里打开各 Cookie 依赖站点确认登录态 |
| 改密码/动安全设置后 | 立即验证对应平台（BDUSS/天翼 Cookie 会立即失效） |
| 服务器重启后 | 确认夸克浏览器里 cloud.189.cn、mm.edrawsoft.cn 仍登录（这两个是会话 Cookie） |

**失效特征速查（日志关键字 → 处置）：**

| 日志关键字 | 含义 | 处置 |
|---|---|---|
| `凭证提取失败` / 找不到 Cookie | 浏览器登录态掉了 | 浏览器重新登录对应站点，零改动恢复 |
| `errno=-6`（库库AI） | BDUSS 失效 | 浏览器重新登录 pan.baidu.com |
| `用户未登录` / 401 | Cookie/Token 过期 | 按上表逐平台处理 |
| 接口 404 或响应结构突变 | 平台接口改版 | 回到阶段二重新逆向，先看上游青龙仓库有没有更新 |

**结构性认知（不再展开，详见专题文档）：**

- 逆向类 6 平台：零维护，前提是客户端保持登录且不定期启动（token 由客户端自己刷新）
- 天翼：浏览器进程别彻底退出（会话 Cookie 失效自动重提取兜底）；重启服务器后确认 cloud.189.cn 登录
- 万兴：refresh_token 自续命（30 天轮换），每天自动跑即永久免维护；仅当连续 30 天未运行才需重新登录网页版
- 百度系：BDUSS 实测 399 天有效，数月看一眼即可
- 客户端大版本升级后：逆向类平台需重新确认存储结构没变（跑一次 --status 便知）

## 附：快速入口

- 跑签到：`.\scripts\run_checkin.cmd --group=ai` / `--group=daily`
- 查任务：`Get-ScheduledTaskInfo -TaskName "签到-凌晨AI组","签到-白天组"`
- 排查日志：`logs\checkin_ai.log` / `logs\checkin_daily.log`
- 新增平台：按本手册四个阶段走一遍

> **计划任务命令行注意**：路径含中文时，任务参数里 .cmd 路径和 `>>` 重定向目标**都不要加引号**（路径本身无空格，加引号反而触发 cmd 解析失败，任务秒退退出码 1 且不产生日志）。2026-10-25 目录重构时踩过此坑。
