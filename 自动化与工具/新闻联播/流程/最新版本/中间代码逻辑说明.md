## 二、核心机制

### 2.1 脱敏与不脱敏开关

**实现位置**：`fetch_xwlb.py` 的 `desensitize()`（唯一入口，全链路生效）

```python
NAME_TO_CODE = [ (人名unicode, "aaa"), ... ]      # 阶段1：人名 → 中间代码
CODE_TO_POSITION = { "aaa": "国家主席", ... }       # 阶段2：代码 → 职务

def desensitize(text, mark=True):
    # 不脱敏开关：设置环境变量 XWLB_NO_DESENSITIZE=1 时直接返回原文
    if os.environ.get("XWLB_NO_DESENSITIZE"):
        return text
    SENTINEL = "\u0000"
    # 五阶段替换：人名→代码 → 去重 → 智能转换(职务+代码相邻去重) → 代码→职务 → 去重
    ...
```

**三处开关联动**（2026-10-07 新增，行为完全一致）：

| 文件 | 开关作用 |
|------|---------|
| `fetch_xwlb.py` `desensitize()` | 设 `XWLB_NO_DESENSITIZE=1` → 返回原文（不做人名替换） |
| `check_md_quality.py` 第5项敏感词检查 | 设 `XWLB_NO_DESENSITIZE=1` → 跳过 sensitive_name_found 检查 |
| `gen_report_v2.py` `desensitize()` | 纯转发到 fetch_xwlb 实现，无需单独改 |

**默认行为**：不设环境变量时，脱敏 + 敏感词质检照常（兼容历史归档）。

### 2.2 抓取链路

| 环节 | 函数 | 要点 |
|------|------|------|
| 央视网列表 | `fetch_xwlb_videos(date_str)` | 解析 `tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml`，正则提取视频条目（标题/时长/URL），14 条左右含完整版 |
| 快讯子条目 | `fetch_kuaixun_details(video_url)` | 解析央视网快讯视频页"主要内容"区块 `<strong>` 标签：`<strong>标题</strong>` + 正文段落 |
| 齐鲁网链接 | `fetch_iqilu_entries(date_str)` | 索引页锚点法定位目标日期区间，`match_iqilu_url()` 模糊匹配快讯标题 → 独立页 URL |
| 快讯正文 | `fetch_iqilu_detail(url)` | **已知缺陷**：部分日期返回 JS 脚本而非正文（见 4.1） |

### 2.3 数据源 JSON 结构（Phase 1 → AI 精读的接口）

```json
{
  "date": "20261006",
  "date_display": "2026年10月06日",
  "total_items": 21,
  "ai_items": 20,
  "news_items": [
    { "idx": "完整版", "title": "...", "url": "...", "category": "完整版",
      "is_placeholder": true, "elements": {固定值} },
    { "idx": "1", "title": "...", "url": "...", "category": "...", "importance": "🟡",
      "summary": "正文前300字", "full_text": "正文前500字",
      "is_placeholder": false, "elements": null },
    { "idx": "8-1", "title": "...", "url": "齐鲁网URL", "source_url": "央视网快讯目录URL",
      "summary": "...", "full_text": "...", "elements": null }
  ]
}
```

**字段语义**：
- `summary` / `full_text`：正文摘要与正文（均截断至 300/500 字符，足够六要素提取）
- `url`：标题链接（常规新闻=央视网；快讯子条目=齐鲁网独立页）
- `source_url`：仅快讯子条目有，指向央视网快讯目录视频（第六部分"详细信息源链接"列用）
- `elements`：null 待 AI 填写；填写后为 `{location, subject, event, cause, method}`

## 三、渲染逻辑（脚本 vs AI 的分工）

### 3.1 脚本渲染部分（1-5 部分，`gen_report_v2.generate_report()`）

| 部分 | 渲染逻辑 |
|------|---------|
| 一、基调概述 | `generate_tone_overview()`：从标题关键词归纳主题/基调/重点领域 |
| 二、新闻速览 | 逐条输出 `### 重要性 N. 标题` + `[一句话概括]` + 视频来源；完整版置顶无序号 |
| 三、重点新闻详解 | 仅 🔴🟡 新闻，按 `classify_news()` 结果归入 3.1-3.4 子分类 |
| 四、联播快讯详解 | 快讯子条目逐条输出；4.3 验证表由匹配结果生成（见 4.2 已知问题） |
| 五、完整性检测 | 播放时间从 19:00:00 连续推算；条数公式 N - D + M + K = X |

### 3.2 AI 渲染部分（六七部分，按 `生成结果模板.md`）

**为什么六七部分交给 AI**：
1. 六要素需要**精读正文**（脚本正则只能机械抽取，质量差：历史一键版约半数"原因/方式"为"—"，主体错乱如"也门媒体称政府"）
2. 第七部分占位符统合需要语义归类（人物/机构/事件核心对象的区分、机构全称补全）

**AI 渲染规则**（详见生成结果模板第六、七章）：
- 第六部分：10 列表格逐行填（完整版行 + 常规新闻行 + 快讯子条目行）+ 编号规则说明
- 第七部分：从六要素数据反向扫描提取（人物→7.1.1；机构→7.1.2 补全称；事件核心对象→7.1.3；地点→7.3；正文数字→7.4 不设上限；书名/文件名→7.5）

## 四、已知问题与修复方案

### 4.1 齐鲁网快讯正文返回 JS 脚本

**现象**：`fetch_iqilu_detail()` 对部分日期返回页面 JS 代码（`无法完成此操作...设为首页`），而非新闻正文。

**影响**：数据源 JSON 中快讯子条目的 `full_text` 不可用。

**当前应对**（流程层）：AI 精读时依赖央视网 `summary` 字段（央视网"主要内容"区块提取，正常可用）；第四部分快讯正文以央视网快讯页提取内容为准。

**根治方向**（代码层，待实施）：`fetch_iqilu_detail()` 增加正文有效性校验——返回内容含 `$(document)` / `设为首页` 等 JS 特征时判为失败，回退央视网快讯页正文。

### 4.2 快讯排版问题（本版已定位，模板已规范，代码待修）

**代码位置**：`gen_report_v2.py` `generate_report()` 第四部分渲染（约第 1654-1658 行）：

```python
for i, item in enumerate(domestic_briefs):
    title = desensitize(item["title"])
    link_url = item.get("iqilu_url") or domestic_url
    summary = item["summary"]
    L(f"> ({i+1}) [{title}]({link_url}) — {summary}")   # ← 条目间无空 > 行
```

**问题**：每条快讯连续输出，条目之间没有空 `>` 行，所有条目挤成一个引用块（对照基准样例 20260915 应有条目间空行）。

**修复方案**（两条路线，当前流程采用 B）：
- **路线 A（代码层，待实施）**：循环体改为每条快讯后追加一个空 `>` 行：

```python
for i, item in enumerate(domestic_briefs):
    ...
    L(f"> ({i+1}) [{title}]({link_url}) — {full_text}")
    L(">")   # 条目分隔空行
```

- **路线 B（流程层，当前生效）**：1-5 部分仍由脚本生成，但**第四部分由 AI 按生成结果模板 4.A/4.B 规范重排**——AI 渲染六七部分时同步修正第四部分的排版与正文完整性。

### 4.3 快讯正文截断问题（本版已定位，模板已规范，代码待修）

**代码位置**：`gen_report_v2.py` `fetch_kuaixun_details()`（约第 201 行）：

```python
# 摘要（前80字）
summary = body[:80] + "..." if len(body) > 80 else body
items.append({"title": title, "summary": summary, "full_text": body})
```

**问题**：完整正文存在 `full_text`，但第四部分渲染用的是截断版 `summary`（前 80 字 + `...`），导致报告快讯信息被省略。

**修复方案**（两条路线，当前流程采用 B）：
- **路线 A（代码层，待实施）**：第四部分渲染改用 `item.get("full_text") or item["summary"]`，输出完整正文。
- **路线 B（流程层，当前生效）**：AI 重排第四部分时以数据源 JSON 的 `full_text` 为准（央视网快讯页"主要内容"完整提取），禁止用截断 `summary`。

### 4.4 merge 模式第七部分简化问题（已绕开）

**代码位置**：`gen_report_final.py` `generate_part67()`——数据占位符扫描在累计 5 条后 `break`；地点表只输出"北京/全国"两类；机构全称映射表有限。

**影响**：若走纯脚本 `--merge` 路线，第七部分质量低（数据占位符最多 5 条、地点残缺、无内容占位符 7.5）。

**当前应对**：正式流程不用 `--merge` 渲染六七部分，改由 AI 按 `生成结果模板.md` 完整渲染（7.4 数据占位符不设上限）。`--merge` 仅作为应急降级手段。

### 4.5 历史遗留：Phase 1 截断逻辑对已有文件的影响

**代码位置**：`gen_report_final.py` `phase1_generate()`：

```python
output_path, _ = gv2.generate_report(...)   # 文件>10KB时跳过生成
part1to5 = full_content.split("## 六、新闻六要素索引")[0]  # 直接截取现有文件
with open(output_path, "w") as f:
    f.write(part1to5)
```

**现象**：目标日期已有完整报告（>10KB）时，Phase 1 不重新抓取渲染，而是把现有报告截断为 1-5 部分写回——若不做备份，现有报告被破坏；截断产物末尾可能带 `> AI生成` 标记行。

**应对**（流程层，已写入生成过程控制阶段 0）：重跑前**必须先备份**现有报告到 `.temp\`；拼接后**清理多余 `> AI生成` 标记行**。

## 五、质检脚本检测项与开关

`check_md_quality.py` 12 项检测（详见生成过程控制 3.1），其中：

| 检测项 | 开关行为 |
|--------|---------|
| 第5项 sensitive_name_found | 默认：扫描 `fetch_xwlb.NAME_TO_CODE` 全部 20 个人名；设 `XWLB_NO_DESENSITIZE=1`：整项跳过 |
| 其余 11 项（大小/结构/表头/URL/双重标签/重复占位符/主体覆盖率/统计信息等） | 与开关无关，恒生效 |

**退出码**：CRITICAL>0 → 1；ERROR>0 → 1；全过 → 0（供自动化链路判断）。
