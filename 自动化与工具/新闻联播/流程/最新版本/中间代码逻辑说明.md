## 二、核心机制

### 2.1 脱敏与不脱敏开关

**实现位置**：`fetch_xwlb.py` 的 `desensitize()`（唯一入口，全链路生效）

```python
NAME_TO_CODE = [ (人名unicode, "aaa"), ... ]      # 阶段1：人名 → 中间代码
CODE_TO_POSITION = { "aaa": "国家主席", ... }       # 阶段2：代码 → 职务

def desensitize(text, mark=True):
    # 不脱敏开关：设置环境变量 XWLB_NO_DESENSITIZE=1 时直接返回原文
    if os.environ.get("XWLB_NO_DESENSITIZE"):
        return text
    SENTINEL = "\u0000"
    # 五阶段替换：人名→代码 → 去重 → 智能转换(职务+代码相邻去重) → 代码→职务 → 去重
    ...
```

**三处开关联动**（2026-10-07 新增，行为完全一致）：

| 文件 | 开关作用 |
|------|---------|
| `fetch_xwlb.py` `desensitize()` | 设 `XWLB_NO_DESENSITIZE=1` → 返回原文（不做人名替换） |
| `check_md_quality.py` 第5项敏感词检查 | 设 `XWLB_NO_DESENSITIZE=1` → 跳过 sensitive_name_found 检查 |
| `gen_report_v2.py` `desensitize()` | 纯转发到 fetch_xwlb 实现，无需单独改 |

**默认行为**：不设环境变量时，脱敏 + 敏感词质检照常（兼容历史归档）。

### 2.2 抓取链路

| 环节 | 函数 | 要点 |
|------|------|------|
| 央视网列表 | `fetch_xwlb_videos(date_str)` | 解析 `tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml`，正则提取视频条目（标题/时长/URL），14 条左右含完整版 |
| 快讯子条目 | `fetch_kuaixun_details(video_url)` | 解析央视网快讯视频页"主要内容"区块 `<strong>` 标签：`<strong>标题</strong>` + 正文段落 |
| 齐鲁网链接 | `fetch_iqilu_entries(date_str)` | 索引页锚点法定位目标日期区间，`match_iqilu_url()` 模糊匹配快讯标题 → 独立页 URL |
| 快讯正文 | `fetch_iqilu_detail(url)` | **已知缺陷**：部分日期返回 JS 脚本而非正文（见 4.1） |

### 2.3 数据源 JSON 结构（Phase 1 → AI 精读的接口）

```json
{
  "date": "20261006",
  "date_display": "2026年10月06日",
  "total_items": 21,
  "ai_items": 18,
  "instructions": "不脱敏版。请根据每条 title/url/summary/full_text 填写...（与脱敏模式联动）",
  "news_items": [
    { "idx": "完整版", "title": "...", "url": "...", "category": "完整版",
      "is_placeholder": true, "elements": {固定值} },
    { "idx": "1", "title": "...", "url": "...", "category": "...", "importance": "🟡",
      "summary": "正文前300字", "full_text": "正文前1200字",
      "is_placeholder": false, "elements": null },
    { "idx": "8", "title": "国内联播快讯", "category": "快讯目录",
      "is_placeholder": true, "elements": {预填固定值} },
    { "idx": "8-1", "title": "...", "url": "齐鲁网URL", "source_url": "央视网快讯目录URL",
      "summary": "...", "full_text": "央视网完整正文", "elements": null }
  ]
}
```

**字段语义**：
- `summary` / `full_text`：正文摘要（300 字）与正文（**1200 字**，v2.0.0 由 500 字扩充，保证 7.4 数据占位符能扫到长文深处的数值）
- `full_text`（快讯子条目）：**优先用央视网完整正文**（`fetch_kuaixun_details` 的 `full_text` 字段），齐鲁网详情页正文（已知会返回 JS 脚本，坑见 4.1）仅作兑底
- `url`：标题链接（常规新闻=央视网；快讯子条目=齐鲁网独立页）
- `source_url`：仅快讯子条目有，指向央视网快讯目录视频（第六部分"详细信息源链接"列用）
- `elements`：null 待 AI 填写；填写后为 `{location, subject, event, cause, method}`
- `is_placeholder=true` 的行（完整版、快讯目录行）已预填，AI 可原样保留或**直接省略**（merge 会自动补回）
- `instructions`：与 `XWLB_NO_DESENSITIZE` 联动——不脱敏版要求"人物主体直接写职务+姓名"；脱敏版要求"人物用 `<u>占位符</u>`"（v2.0.0 修复：旧版内嵌的固定脱敏指令与不脱敏流程矛盾）

**★第六部分渲染规则**（v2.0.0 起由脚本实施）：
- 数据源 JSON 中的快讯父目录行（`idx` 为纯数字且 `title` 含"联播快讯"）**不进入第六部分表格**——`generate_part67()` 渲染时 `continue` 跳过
- `is_placeholder` 行（完整版）保留在表格但**不参与第七部分占位符收集**（与示例输出一致）
- 第二、五部分仍由脚本渲染父目录行（保持央视网分条顺序的完整性）

## 三、渲染逻辑（脚本 vs AI 的分工）

### 3.1 脚本渲染部分（1-5 部分，`gen_report_v2.generate_report()`）

| 部分 | 渲染逻辑 |
|------|---------|
| 一、基调概述 | `generate_tone_overview()`：从标题关键词归纳主题/基调/重点领域 |
| 二、新闻速览 | 逐条输出 `### 重要性 N. 标题` + `[一句话概括]` + 视频来源；完整版置顶无序号 |
| 三、重点新闻详解 | 仅 🔴🟡 新闻，按 `classify_news()` 结果归入 3.1-3.4 子分类 |
| 四、联播快讯详解 | 快讯子条目逐条输出；4.3 验证表由匹配结果生成（见 4.2 已知问题） |
| 五、完整性检测 | 播放时间从 19:00:00 连续推算；条数公式 N - D + M + K = X |

### 3.2 脚本渲染部分（六七部分，`gen_report_final.generate_part67()` v2.1.0）

**为什么六七部分交给 AI 填六要素、脚本渲染表格**（优化1，2026-10-07 实施）：
1. 六要素需要**精读正文**（脚本正则只能机械抽取，质量差：历史一键版约半数"原因/方式"为"—"，主体错乱如"也门媒体称政府"）——这部分仍由 AI 完成
2. 表格排版、占位符提取、机构全称映射是**机械性工作**，脚本渲染零积分消耗、零排版误差；旧版 AI 渲染一次拼接要 15K+ token，脚本渲染后每日省约 50% 积分

**AI 只需输出精简结果 JSON**（`六要素结果_YYYYMMDD.json`）：
```json
{
  "date": "20261006", "date_display": "2026年10月06日",
  "news_items": [
    { "idx": "1", "category": "经济要闻",
      "elements": {"location": "全国", "subject": "...", "event": "...",
                   "cause": "...", "method": "..."} },
    { "idx": "8-1", "elements": {...} }
  ]
}
```
- 仅需 `idx` + `elements`（+ 可选 `category` 修正），title/url/summary/full_text 等**基础字段由 phase3_merge 自动从数据源 JSON 补齐**（base.update(it) 合并，AI 字段优先）
- 预填行（完整版、快讯目录行）可省略，merge 自动补回
- 完整格式（含全部字段的旧式结果 JSON）仍然兼容

**generate_part67 v2.1.0 渲染能力**（2026-10-07 E2E 验证通过）：
- 第六部分：10 列表格逐行（跳过快讯父目录行）+ 编号规则说明
- 7.1.1 人物类：不脱敏版直接列"姓名 | 职务"；已知人名表（NAME_TO_CODE 20 人）匹配 + **表外人物启发式**（职务关键词最靠右匹配 + 尾部 2-5 字视为姓名，覆盖古特雷斯/扎哈罗娃/塞西等；职务优先取主体原文全称如"中共中央总书记、国家主席、中央军委主席"）
- 7.1.2 机构类：70+ 全称映射，无映射标注"（待补充全称）"
- 7.4 数据占位符：26 种正则不限量，**分组件扫描**（title/summary/full_text 各自提取短语，避免拼接跨界），**跨度去重**（"3亿"被"3亿人次"覆盖则跳过），说明列取**数值所在短语**（最近 、，。；！？ 及摘要截断省略号 "..." 边界）
- 7.5 内容占位符：扫描《...》书名/文件名（is_placeholder 行除外，避免《新闻联播》混入）
- 空表兑底：无数据时显示"本日无XXX"

## 四、已知问题与修复方案

### 4.1 齐鲁网快讯正文返回 JS 脚本

**现象**：`fetch_iqilu_detail()` 对部分日期返回页面 JS 代码（`无法完成此操作...设为首页`），而非新闻正文。

**影响**：数据源 JSON 中快讯子条目的 `full_text` 不可用。

**当前应对**（流程层）：AI 精读时依赖央视网 `summary` 字段（央视网"主要内容"区块提取，正常可用）；第四部分快讯正文以央视网快讯页提取内容为准。

**根治方向**（代码层，待实施）：`fetch_iqilu_detail()` 增加正文有效性校验——返回内容含 `$(document)` / `设为首页` 等 JS 特征时判为失败，回退央视网快讯页正文。

### 4.2 快讯排版问题 ★已修复（2026-10-07 路线 A 代码层实施）

**代码位置**：`gen_report_v2.py` `generate_report()` 第四部分渲染

**修复内容**：循环体改为每条快讯之间输出空 `>` 行分隔，并改用完整正文：
```python
for i, item in enumerate(domestic_briefs):
    title = desensitize(item["title"])
    link_url = item.get("iqilu_url") or domestic_url
    # 优先用央视网完整正文（fetch_kuaixun_details 的 full_text），禁止用截断 summary
    body = desensitize(item.get("full_text") or item.get("summary", ""))
    if i > 0:
        L(">")   # 条目分隔空行
    L(f"> ({i+1}) [{title}]({link_url}) — {body}")
```

**附带修复**：正文经 `desensitize()` 处理（旧版直接用原始 summary，脱敏模式下第 4 部分会泄漏人名，如内塔尼亚胡）。

**效果**（20261006 E2E 验证）：与基准样例 20260915/09:07 手工版完全一致，无需 AI 再修正第 4 部分，任务 prompt 中"第 4 部分重排"步骤已作废。

### 4.3 快讯正文截断问题 ★已修复（随 4.2 一并修复）

第四部分渲染改用 `item.get("full_text") or item["summary"]`，完整正文优先；数据源 JSON 中快讯子条目的 `full_text` 也改为优先取央视网完整正文（齐鲁网 JS 垃圾仅作兑底）。

### 4.4 merge 模式第七部分简化问题 ★已修复（优化1核心，generate_part67 v2.1.0 重写）

**历史问题**：旧版 `generate_part67()` 数据占位符扫描在累计 5 条后 `break`；地点表只输出"北京/全国"两类；机构全称映射表仅 17 个。

**修复**（v2.0.0 重写 + v2.1.0 精修，E2E 验证）：`--merge` 成为**正式主路径**——26 种数据正则不限量、地点从六要素全量提取、机构全称 70+ 映射、7.5 内容占位符、不脱敏版人物表、表外人物启发式、空表兑底。每日流程不再由 AI 渲染六七部分（旧流程已作废）。

### 4.5 BASE_DIR 智能查找（v1.0.0 已修复）

**代码位置**：`gen_report_final.py`、`gen_report_v2.py`、`fill_elements_api.py` 三处 BASE_DIR 定义

**历史问题**：原 `分阶段生成方案/` 目录下，`BASE_DIR = dirname(dirname(SCRIPT_DIR))` 向上两层恰好是项目根。但代码副本位于 `最新版本/代码/`，多一层嵌套，向上两层只到 `流程/`，导致报告误生成到 `流程/归档/` 而非项目根 `归档/`。

**修复方案**（已在代码副本中实施）：三处 BASE_DIR 改为智能查找函数——从脚本所在目录向上逐级查找，直到找到含"归档"子目录的祖先作为项目根；6 层内找不到则回退到向上三层。这样无论代码放在哪个层级（`分阶段生成方案/`、`最新版本/代码/`、或自定义路径），都能正确定位项目根。

**注意**：原 `分阶段生成方案/` 目录下的脚本未做此修改（保持向上两层），因为那里向上两层就是项目根，无需智能查找。两套代码功能等价，仅路径自适应能力不同。

### 4.6 历史遗留：Phase 1 截断逻辑对已有文件的影响

**代码位置**：`gen_report_final.py` `phase1_generate()`：

```python
output_path, _ = gv2.generate_report(...)   # 文件>10KB时跳过生成
part1to5 = full_content.split("## 六、新闻六要素索引")[0]  # 直接截取现有文件
with open(output_path, "w") as f:
    f.write(part1to5)
```

**现象**：目标日期已有完整报告（>10KB）时，Phase 1 不重新抓取渲染，而是把现有报告截断为 1-5 部分写回——若不做备份，现有报告被破坏。

**应对**：重跑前**必须先备份**现有报告到 `.temp\`（已写入生成过程控制阶段 0）。中间件尾部可能被平台水印 hook 追加 `> AI生成` 行，**phase3_merge 已内置尾部清理**：拼接前剔除该行并去除与第六部分开头重复的 `---` 分隔线，无需人工处理（最终报告写入后 hook 会在文末自行追加水印，交付物水印保留，见部署避坑指南坑 17）。
