# 部署避坑指南 — 一次性配置必读

> **版本**：v1.0.0（2026-10-07）
> **用途**：在其他电脑复现时，把本项目踩过的所有坑汇总到一处，避免逐个重踩
> **适用**：用积分方案 + 不用积分方案通用

---

## 一、环境准备坑

### 坑 1：Python requests 未安装

**现象**：脚本运行报 `ModuleNotFoundError: No module named 'requests'`

**原因**：定时任务以服务账户运行时 PATH 可能与交互式登录不同；或新装 Python 没装 requests

**解决**：
```powershell
python -m pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**验证**：
```powershell
python -c "import requests; print(requests.__version__)"
```

### 坑 2：Python 路径在定时任务环境中找不到

**现象**：Windows 任务计划程序运行时报"未找到 Python 解释器"

**原因**：定时任务以服务账户运行时 PATH 不含 Python 安装目录

**解决**：`config.json` 中 `python_exe` 必须用**完整绝对路径**，不能只写 `python`：
```json
{
  "paths": {
    "python_exe": "C:\\Users\\你的用户名\\AppData\\Local\\Programs\\Python\\Python312\\python.exe"
  }
}
```

**获取路径**：
```powershell
(Get-Command python).Source
```

### 坑 3：PowerShell 执行策略阻止脚本运行

**现象**：运行 `.ps1` 脚本报"无法加载，因为在此系统上禁止运行脚本"

**解决**：
```powershell
powershell -ExecutionPolicy Bypass -File .\register_task.ps1
```

或一次性放开当前用户：
```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### 坑 4：注册任务需要管理员权限

**现象**：`register_task.ps1` 报"需要管理员权限"

**解决**：右键 PowerShell → "以管理员身份运行"，再执行脚本；或用 `-NonInteractive` 参数在已提权的会话中运行

## 二、路径与文件部署坑

### 坑 5：代码放在嵌套目录导致 BASE_DIR 错误 ★高频

**现象**：报告生成到错误位置（如 `流程\归档\` 而非项目根 `归档\`）

**原因**：原脚本 `BASE_DIR = dirname(dirname(SCRIPT_DIR))` 假设代码在"分阶段生成方案/"（向上两层=项目根）。若代码放在 `最新版本/代码/`（多一层嵌套），向上两层只到 `流程/`

**解决**：本发布包的代码已改为智能查找——从脚本位置向上查找含"归档"子目录的祖先，6 层内找不到则回退向上三层。无需手动处理

**验证**：
```powershell
# 跑一次看报告生成在哪
python gen_report_final.py 20261006
# 预期：归档\2026年10月\ 而非 流程\归档\2026年10月\
```

### 坑 6：config.json 相对路径层级错误 ★高频

**现象**：不用积分方案运行后报告找不到，或脚本找不到

**原因**：`config.json` 的相对路径以 `不用积分/` 目录为基准。原 `自动化任务/` 目录向上两层到项目根，但 `不用积分/` 向上三层才到项目根

**解决**：本发布包的 `config.json` 已修正：
- `output_dir`: `../../../归档`（向上三层到项目根）
- `oneshot_dir` / `script_dir`: `../代码`（向上一层到 `最新版本/`，再进 `代码/`）

**验证**：见 `不用积分\README.md` 步骤 3

### 坑 7：check_status.ps1 硬编码归档路径

**现象**：`check_status.ps1` 报"归档目录不存在"

**原因**：脚本中 `$archiveRoot = Join-Path $ProjectRoot "..\..\归档"` 是按原 `自动化任务/` 层级写的（向上两层），在 `不用积分/` 嵌套下需要向上三层

**解决**：本发布包已修正为 `..\..\..\归档`（两处：目标报告检查 + 最近报告）

### 坑 8：归档月份目录不存在

**现象**：跨月时报告写入失败

**原因**：`归档\YYYY年M月\` 目录首次使用时不存在

**解决**：脚本内置 `os.makedirs(archive_dir, exist_ok=True)`，自动创建。无需手动处理

## 三、数据抓取坑

### 坑 9：齐鲁网快讯正文返回 JS 脚本

**现象**：数据源 JSON 中快讯子条目的 `full_text` 字段是 JS 代码（`无法完成此操作...设为首页`），而非新闻正文

**原因**：齐鲁网部分日期的详情页结构变化，`fetch_iqilu_detail()` 抓取到页面 JS 而非正文

**影响**：第四部分快讯正文不可用

**解决**（流程层）：AI 精读时依赖央视网 `summary` 字段（央视网"主要内容"区块提取，正常可用）；第四部分用央视网快讯页提取的完整正文

**解决**（代码层，待实施）：`fetch_iqilu_detail()` 增加正文有效性校验——返回内容含 `$(document)` / `设为首页` 等 JS 特征时判为失败，回退央视网快讯页正文

### 坑 10：央视网页面结构变化导致抓取失败

**现象**：`fetch_xwlb_videos()` 返回 0 条

**原因**：央视网 HTML 结构改版，正则失配

**解决**：脚本内置重试 1 次（等 3 秒）；仍失败则报告失败，不留空文件。需人工检查央视网页面结构是否变化，更新 `fetch_xwlb.py` 的正则

### 坑 11：快讯子条目数量以齐鲁网为准（错误做法）

**现象**：快讯子条目数量与央视网实际播出不符（偏少）

**原因**：齐鲁网并非每天都将所有快讯子条目拆分为独立页面

**解决**：**必须以央视网快讯视频页面为准**——页面中列出完整的子快讯内容（如"(1)审计署...(2)前五个月..."）。齐鲁网仅用于补充独立页面链接，不作为计数基准

## 四、报告渲染坑

### 坑 12：快讯排版挤成一团 ★已修复

**现象**：第四部分每条快讯连续输出，条目之间无空行，视觉上一大坨

**原因**：`gen_report_v2.py` 第 1658 行 `L(f"> ({i+1}) [{title}]({link_url}) — {summary}")` 每条快讯后没空 `>` 行

**解决**：
- 代码层（`xwlb_report.py` 已修复）：每条快讯后加 `L(">")` 空行分隔
- 流程层（用积分方案）：AI 渲染时按 `生成结果模板.md` 4.A 规范重排，每条快讯之间空 `>` 行

### 坑 13：快讯正文被截断为 80 字 ★已修复

**现象**：第四部分快讯正文以 `...` 结尾，关键数据丢失

**原因**：`gen_report_v2.py` 第 201 行 `summary = body[:80] + "..."` 截断为前 80 字，而完整正文在 `full_text` 字段却没被使用

**解决**：
- 代码层（`xwlb_report.py` 已修复）：第四部分渲染改用 `full_text`（完整正文），不用截断版 `summary`
- 流程层（用积分方案）：AI 渲染时以数据源 JSON 的 `full_text` 为准，禁止用截断 `summary`，禁止 `...` 省略号结尾

### 坑 14：第六部分快讯父目录行制造噪音 ★已修复

**现象**：第六部分同时列出父目录行（序号8"国内联播快讯"、序号12"国际联播快讯"）和子条目行（8-1、12-1），父目录行用占位值填充，语义勉强且制造噪音

**解决**（本发布包已统一修复）：第六部分**不出现父目录行**，只列子条目行：
- `xwlb_report.py` 的 `all_elements_rows()` 跳过 `is_dir=True` 的条目
- `gen_report_final.py` 的 `generate_part67()` 跳过 `idx.isdigit() and "联播快讯" in title` 的条目
- 父目录行仍保留在第二部分（新闻速览）和第五部分（完整性检测标题清单）

### 坑 15：merge 模式第七部分简化

**现象**：走纯脚本 `--merge` 路线时，第七部分质量低（数据占位符最多 5 条、地点残缺、无内容占位符 7.5）

**原因**：`gen_report_final.py` 的 `generate_part67()` 数据占位符扫描在累计 5 条后 `break`；地点表只输出"北京/全国"两类；机构全称映射表有限

**解决**：正式流程不用 `--merge` 渲染六七部分，改由 AI 按 `生成结果模板.md` 完整渲染（7.4 数据占位符不设上限）。`--merge` 仅作应急降级手段

### 坑 16：Phase 1 截断已有文件的副作用

**现象**：重跑时已有完整报告（>10KB）被截断为 1-5 部分写回，原有内容被破坏

**原因**：`gen_report_final.py` 的 `phase1_generate()` 调用 `generate_report()` 时，文件 >10KB 会跳过重新生成，但之后又 `full_content.split("## 六")[0]` 截取现有文件——若不备份，现有报告被破坏

**解决**（流程层）：重跑前**必须先备份**现有报告到 `.temp\`。已写入 `生成过程控制.md` 阶段 0。（注：报告末尾的 `> AI生成` 是平台水印，不属于本坑，详见坑 17）

### 坑 17：报告末尾的 `> AI生成` 行 —— 平台 AIGC 水印，必须保留 ★已正名

**现象**：AI 会话写入的 `.md` 文件末尾自动多出 `> AI生成` 一行，与定时脚本生成的报告（以声明行结尾）不一致

**原因**（已查实，非缺陷）：这是**平台自动追加的 AIGC 水印**，不是模板残留。验证依据：①所有 AI 会话写入的 `.md` 文件末尾统一带此行（`.py`/`.json`/`.ps1` 不带）；②手动删除后 hook 会在数秒内自动恢复（文件反而 +2 字节，末尾补了换行）；③定时任务里纯脚本写入的报告（如 9 月归档）末尾没有此行

**处置**：**保留水印，禁止删除**。任何"删除多余 `> AI生成` 标记行"的指引均作废（删除也会被 hook 恢复，白耗功夫）。定时任务纯脚本产物无此行属正常差异，无需人工补齐

## 五、脱敏与质检坑

### 坑 18：不脱敏版质检报 CRITICAL sensitive_name_found ★已修复

**现象**：不脱敏版报告质检报 `sensitive_name_found: 习近平`

**原因**：`check_md_quality.py` 第 5 项默认扫描敏感人名，不脱敏版报告含真名必然触发

**解决**：不脱敏版运行质检前**必须设 `XWLB_NO_DESENSITIZE=1`**——质检脚本会跳过敏感人名检查（其余 11 项仍生效）。已同步到定时任务 prompt 和不用积分 config

**验证**：
```powershell
$env:XWLB_NO_DESENSITIZE='1'
python check_md_quality.py <报告路径>
# 预期：All checks passed
Remove-Item Env:\XWLB_NO_DESENSITIZE
```

### 坑 19：脱敏函数 AB→AA 去重失败

**现象**：脱敏后出现"英国首相英国首相"重复

**原因**：脱敏函数 `desensitize()` 旧版去重逻辑有 bug

**解决**：`fetch_xwlb.py` 已升级为五阶段替换法（含 SENTINEL 包裹、相邻去重、智能转换），已修复。可用 `python check_md_quality.py --test-desensitize` 验证

### 坑 20：第六部分新闻主体大量填"—"

**现象**：质检 WARNING `high_dash_ratio`，新闻主体列"—"占比 > 30%

**原因**：正则提取覆盖率不足（oneshot 模式约 70%）；AI 填写时滥填"—"

**解决**：
- oneshot 模式：`xwlb_report.py` 已扩充主体抽取规则（"记者从X了解到"句式、机构简称、地名兜底）
- 用积分方案：AI 精读时**禁止大量填"—"**，必须依据正文实质提炼

## 六、定时任务坑

### 坑 21：Windows 任务计划程序任务到点没触发

**现象**：05:00 任务没运行

**排查**：
| 检查项 | 方法 |
|--------|------|
| 任务状态 | `check_status.ps1` 或任务计划程序 GUI |
| 电脑是否开机 | 05:00 时需运行且用户已登录 |
| 任务已禁用 | 任务计划程序右键"启用" |
| cron 表达式 | 确认 `0 5 * * *`（5点）非 `5 0 * * *`（0点5分） |

### 坑 22：TeleAgent 定时任务不触发

**现象**：05:00 TeleAgent 没唤醒

**排查**：
| 检查项 | 方法 |
|--------|------|
| TeleAgent 是否运行 | 桌面端是否在线 |
| 任务状态 | `teleai-agent-schedule list` 状态列 ✅ |
| daemon 是否响应 | `teleai-agent-schedule list` 能否返回 |

### 坑 23：两套方案同时启用导致互相覆盖

**现象**：两套方案都在 05:00 运行，后执行的覆盖先执行的

**解决**：只用其中一套。若两套都启用，oneshot 脚本文件 >10KB 会跳过（保护已有报告），但 TeleAgent AI 会备份后覆盖

### 坑 24：修改执行时间后没重新注册

**现象**：改了 `config.json` 的 `schedule.time` 但任务还在原时间运行

**原因**：任务计划程序的触发时间在注册时写入，不随配置文件变化

**解决**：修改后**必须重新注册**：
```powershell
# 不用积分方案
powershell -ExecutionPolicy Bypass -File .\register_task.ps1 -NonInteractive

# 用积分方案
teleai-agent-schedule update <task-id> --expr "30 6 * * *"
```

## 七、编码与格式坑

### 坑 25：报告文件带 BOM

**现象**：某些 Markdown 渲染器显示首行乱码

**原因**：PowerShell `Set-Content` 默认带 BOM

**解决**：写报告时用 UTF-8 无 BOM：
```powershell
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($path, $content, $utf8NoBom)
```

### 坑 26：Markdown 分隔线被解析成 setext 标题

**现象**：`---` 上方一行加粗文字被 Markdown 渲染成二级标题

**原因**：`---` 前缺少空行

**解决**：`xwlb_report.py` 已在分隔线前后各留一个空行：`"\n\n---\n\n".join(...)`

### 坑 27：JSON 值内部 ASCII 双引号破坏解析

**现象**：AI 填六要素 JSON 时，值内部出现 `"` 导致 JSON 解析失败

**解决**：JSON 值内部不要使用 ASCII 双引号；如需引用，使用中文引号 `""` 或转义 `\"`

## 八、优化1 实施坑（2026-10-07 新增，均已修复）

### 坑 28：中间产物 md 被平台水印追加，拼接后嵌入正文中部

**现象**：Phase 1 写出的 1-5 部分中间件（也是 .md）会被平台水印 hook 在末尾追加 `> AI生成`；随后 `--merge` 拼接时该行被带到第五、六部分交界处，报告正文中部出现水印行

**解决**★已修复：`phase3_merge` 拼接前清理中间件尾部——剔除尾部水印行并去除与第六部分开头重复的 `---` 分隔线。最终报告写入后 hook 是否再在文末追加水印属平台行为（两种情况都正常），交付物水印保留（见坑 17）

### 坑 29：generate_part67 分类块变量遮蔽新闻标题

**现象**：7.4 数据占位符的"说明"列对含人物主体的条目显示成了职务（如"中共中央总书记、国家主席、中央军委主席"）而非新闻标题

**原因**：主体三分类新增代码把人物职务命名为局部变量 `title`，覆盖了循环变量新闻标题 `title`——第六部分行渲染在分类之前所以正确，之后的数据扫描全用了被覆盖的职务

**解决**★已修复：改名 `person_title`。**经验**：新增代码勿与循环内已有变量重名；此类 bug 首发症状是"表格某列内容错位但其他列正常"

### 坑 30：数据源 full_text 截断 500 字导致 7.4 长文数据漏采

**现象**：长新闻正文 500 字之后的数值（如"粮食产量超过1.4万亿斤"）进不了 7.4 数据占位符

**解决**★已修复：数据源 full_text 上限 500→1200 字；同时修复短语提取的边界回退 off-by-one（回退值应写 `[-1]` 而非 `[0]`，否则首字符被吞掉："国庆"变"庆"、"今年"变"年"），并把 7.4 说明列改为分组件扫描+短语上下文提取（避免 title/summary/full_text 拼接后短语跨界、摘要截断省略号泄漏）

### 坑 31：批量编辑工具可能部分应用且报成功

**现象**：一次 multiedit 提交两个编辑，工具回复成功，但其中一个 oldString 不匹配时实际未落盘（另一个生效）——原子性未如预期

**解决**（经验）：批量编辑后**必须 grep 验证每个编辑点已落位**（搜新增注释/变量名），不要信工具的成功回执；对结构不确定的代码段，先 Read 再单编辑

## 十、一次性配置检查清单

在新电脑部署时，按以下清单逐项确认：

- [ ] **Python 3.10+** 已安装且 `requests` 可导入
- [ ] **Python 完整路径** 已记下并填入 `config.json` 的 `python_exe`
- [ ] **文件夹结构** 正确：`最新版本\代码\` 含 8 个脚本；`归档\` 目录存在或可自动创建
- [ ] **路径验证**：从 `不用积分\scripts\` 运行 `run_now.ps1`，报告生成到 `归档\YYYY年M月\`
- [ ] **不脱敏开关**（如需不脱敏）：`XWLB_NO_DESENSITIZE=1` 在执行前设置、执行后取消
- [ ] **管理员权限**：注册 Windows 任务计划程序需要管理员身份
- [ ] **TeleAgent 运行**（如用积分方案）：桌面端在线，`teleai-agent-schedule list` 可响应
- [ ] **任务计划程序**：注册后 `check_status.ps1` 显示状态 Ready、下次运行时间正确
