## 一、三层分离架构

### 1.1 设计理念

本版本延续旧版本（`旧版本/新闻联播总结_生成流程.md` v3.2.0）的**过程、模板、代码三层分离**思路，并升级为"脚本自动化 + AI 精读"的融合架构：

```
┌──────────────────────────────────────────────────────────┐
│ 第一层：生成过程控制（本文档）                              │
│   职责：定义执行流程、步骤顺序、质检标准、异常处理            │
│   消费者：AI 执行者（TeleAgent） / 定时任务 / 人工           │
├──────────────────────────────────────────────────────────┤
│ 第二层：生成结果模板（生成结果模板.md）                      │
│   职责：定义报告的七部分结构、排版格式、内容规范              │
│   消费者：脚本渲染 + AI 填写时参照                          │
├──────────────────────────────────────────────────────────┤
│ 第三层：中间代码逻辑（中间代码逻辑说明.md + 分阶段生成方案/） │
│   职责：数据抓取、脱敏开关、分类、模板渲染、质检              │
│   消费者：脚本本身（Python 解释器）                          │
└──────────────────────────────────────────────────────────┘
```

|-----------|----------|------|

### 1.3 执行模式

| 模式 | 触发方式 | 说明 |
|------|---------|------|
| **定时自动** | TeleAgent 定时任务"新闻联播日报"（每天 05:00，cron `0 5 * * *`） | 无人值守，AI 全流程执行 |
| **手动单次** | 用户对话中指定日期 | AI 执行，可交互确认 |
| **纯脚本** | `python gen_report_final.py YYYYMMDD` | 仅生成 1-5 部分 + 数据源 JSON，六要素不精填（适合环境自检） |

> **优化1（v1.1.0）**：六七部分改由 **脚本渲染**（`--merge`），AI 只输出精简六要素 JSON——积分消耗省约 50%。

## 二、执行流程（5 阶段）

### 阶段 0：前置检查

| 检查项 | 规则 | 处理 |
|--------|------|------|
| 目标日期 | 默认昨天（`YYYYMMDD`）；用户显式指定时以用户为准 | 拒绝未来日期 |
| 报告已存在且 >10KB | 已有完整报告 | **备份到 `.temp\备份_新闻联播总结_YYYYMMDD_旧版.md` 后重新生成**（定时任务为高质量覆盖模式） |
| 报告已存在且 ≤10KB | 上次生成中断 | 删除后从头重新生成 |
| 月份文件夹不存在 | `归档\YYYY年M月\` 缺失 | 自动创建 |
| 环境变量 | **设 `XWLB_NO_DESENSITIZE=1`**（不脱敏版必需；任务结束前取消） | 不设则产出脱敏版 |

### 阶段 1：数据抓取（脚本，约 15-30 秒）

```powershell
$env:XWLB_NO_DESENSITIZE='1'
& 'C:\Users\Administrator\AppData\Local\Programs\Python\Python312\python.exe' gen_report_final.py YYYYMMDD
# 工作目录：流程\最新版本\代码（分阶段生成方案为开发历史版，无优化1改造）
```

**产出**：
- `归档\YYYY年M月\新闻联播总结_YYYYMMDD.md`（1-5 部分，脚本渲染）
- `归档\YYYY年M月\六要素数据源_YYYYMMDD.json`（AI 精读用临时文件）

**验证点**：
- 央视网分条数 ≥ 10（含完整版）
- 快讯子条目：国内 M 条 + 国际 K 条（以央视网快讯视频页面为准，非齐鲁网分条数）
- 齐鲁网链接匹配数 Q 与央视网基准 B 一致（缺失时降级用央视网目录链接）

### 阶段 2：AI 精读填六要素（核心质量环节）

AI 读取数据源 JSON，逐条精读 `title / summary / full_text`，为每条新闻填写五要素：

| 字段 | 规则 | 示例 |
|------|------|------|
| `location` | 地点，尽量精确到城市 | `天津` / `瑞士日内瓦` / `全国` |
| `subject` | 人物**职务+姓名**（不脱敏版），或机构名，或事件核心对象 | `联合国秘书长古特雷斯` / `交通运输部` / `也门冲突双方` |
| `event` | 核心事件简述（20字内） | `七部门印发新型电池产业规划` |
| `cause` | 原因/目的，依据正文实质提炼，**禁止滥填"—"** | `服务全球经济绿色低碳发展` |
| `method` | 方式/手段 | `印发规划文件` |

**质量红线**：
1. **禁止大量填"—"**：每条新闻必须依据正文实质提炼，"—"占比不得超过 30%（check_md_quality 第8项强制）
2. **分类修正**：脚本分类常见错误必须修正——假期文旅→社会/文化要闻、经济调研→经济要闻、联合国决议→国际新闻
3. **机构用全称**：如"国务院安委会办公室"（全称见第七部分 7.1.2）
4. **★快讯父目录行不出现**：第六部分**不列**快讯父目录行（序号8"国内联播快讯"、序号12"国际联播快讯"等纯目录行），只列其子条目行（8-1、8-2...12-1、12-2...）。父目录行保留在第二、五部分。第七部分也不再归类"国内/国际联播快讯"这种目录名主体
5. **特殊行固定值**：
   - 完整版行：`location=全国, subject=—, event=当日全部新闻汇总, cause=—, method=完整播报`
   - 快讯目录行：**不进入第六部分**（无需填写六要素）；其子条目行按常规新闻规则精填

### 阶段 3：保存六要素结果 JSON（AI）→ 脚本渲染第六七部分

**3a. AI 保存精简结果 JSON**（优化1：AI 只出 JSON，不渲染 markdown）：
- 保存为 `归档\YYYY年M月\六要素结果_YYYYMMDD.json`
- **精简格式**（推荐，约 2KB）：仅 `idx` + `elements`（五要素）+ 可选 `category` 修正
  - 基础字段（title/url/summary/full_text）由脚本自动从数据源 JSON 补齐
  - `is_placeholder=true` 的预填行（完整版、快讯目录行）可直接省略，脚本自动补回
- 完整格式（含全部字段）仍然兼容

**3b. 脚本渲染第六七部分**（`generate_part67()` v2.1.0，按模板自动完成）：
```powershell
& '<PYTHON_EXE>' gen_report_final.py YYYYMMDD --merge
# 自动：精简格式补齐 → 渲染第六七部分 → 清理中间件尾部水印行/重复分隔线 → 拼接写回报告
```
- **第六部分**：10 列六要素索引表（完整版首行 + 常规新闻 1..N + 快讯子条目 N-M，父目录行不出现）+ 编号规则说明
- **第七部分**：7.1.1 人物类（不脱敏版列"姓名 | 职务"，表外人物自动识别）/ 7.1.2 机构类（70+ 全称映射）/ 7.1.3 事件核心对象类 / 7.2 时间 / 7.3 地点（六要素全量提取）/ 7.4 数据占位符（26 种正则不限量，说明列取数值所在短语）/ 7.5 内容占位符
- **末尾**：数据来源区块 + 声明行（脚本自动写入）
- **自动清理**：merge 完成后删除六要素数据源与结果两个临时 JSON

### 阶段 4：质检

1. **质检**（必须 0 问题才算完成）：

```powershell
& 'C:\Users\Administrator\AppData\Local\Programs\Python\Python312\python.exe' check_md_quality.py <报告路径>
# 工作目录：流程\最新版本\代码；此时 XWLB_NO_DESENSITIZE=1 已设（跳过敏感词检查）
```

质检不通过 → 修复 → 重检，直到 CRITICAL/ERROR/WARNING 全 0。

> 拼接与编码由 `--merge` 一次性完成（UTF-8 无 BOM）；报告末尾的 `> AI生成` 为平台 AIGC 水印（hook 自动追加，保留勿删，见部署避坑指南坑 17）。

### 阶段 5：收尾

1. **取消环境变量**：`Remove-Item Env:\XWLB_NO_DESENSITIZE`
2. **确认中间件清理**：`--merge` 已自动删除 `归档\YYYY年M月\六要素数据源_*.json` 与 `六要素结果_*.json`，确认即可——**归档目录最终只保留 md 报告**
3. **汇报**：报告路径、行数与大小、质检结果、新闻条数、六要素填写数

## 三、质检标准（闭环）

### 3.1 check_md_quality.py 检测项

| 级别 | 检测项 | 通过标准 |
|------|--------|---------|
| CRITICAL | 文件大小 | > 10KB |
| CRITICAL | 敏感人名 | 脱敏版：无具体人名；不脱敏版：设开关后跳过此项 |
| ERROR | 七部分结构 | `## 一` 至 `## 七` 全部存在 |
| ERROR | 第六部分表头 | 严格 10 列，列名与模板完全一致 |
| ERROR | 双重标签 | 无 `<u><u>...</u></u>` |
| ERROR | 重复占位符 | 无 3 字以上中文相邻重复 |
| WARNING | 新闻主体覆盖率 | 第六部分"—"占比 ≤ 30% |
| WARNING | HTTP 链接 | 全部 HTTPS |
| WARNING | URL 格式 | 央视网 `.shtml` / 齐鲁网 `.html` |

### 3.2 质检之外的 AI 自检项（模板合规）

- [ ] 快讯排版：每条快讯之间有空 `>` 行分隔（见生成结果模板 4.1/4.2 规范）
- [ ] 快讯正文：完整不截断，禁止 `...` 省略号结尾（数据源 JSON 的 `full_text` 为准，不用截断版 `summary`）
- [ ] 编号连续：常规新闻 1..N 无跳号；快讯子条目 N-M 格式正确
- [ ] 完整版单独列出：序号列填"完整版"，不纳入计数
- [ ] **快讯父目录行不在第六部分**：序号8、12等纯目录行不出现，只列子条目行（8-1、12-1...）
- [ ] 第七部分与第六部分同源一致：人物/机构/地点/数据均来自同一份六要素数据

## 四、异常处理

| 异常 | 处理 |
|------|------|
| 央视网页面无法访问 | 重试 1 次（脚本内置）；仍失败则报告失败，不留空文件 |
| 齐鲁网正文返回 JS 脚本（已知问题） | 快讯六要素依赖央视网 `summary` 字段；第四部分正文用数据源 JSON 的 `full_text` |
| 齐鲁网缺失某子条目独立页 | 标题链接降级用央视网快讯目录视频链接，4.3 验证表标注 |
| 无快讯目录（极少数日期） | 第四部分标注"当日无国内/国际联播快讯"，第五部分 D=0 |
| 质检 CRITICAL 不通过 | 定位问题行修复后重检；结构问题重读模板后重渲染 |
| 定时任务连续 2 天无产出 | 标记"自动化任务异常"，需人工检查 TeleAgent 定时任务与网络 |
