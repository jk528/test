# 优化积分建议

> **版本**：v1.0.0（2026-10-07）
> **用途**：在保证 AI 精读六要素质量不变的前提下，降低每次执行的 token 消耗

---

## 一、当前消耗分析

### 1.1 单次执行 token 估算

| 环节 | 工具调用 | 输入 token | 输出 token |
|------|---------|----------|----------|
| 读取数据源 JSON（250 行） | Read | ~13,000 | — |
| AI 精读 20 条正文 + 思考六要素 | 内部推理 | ~3,000 | ~2,000 |
| **编辑拼接第六七部分（~300 行 markdown）** | **Edit** | **~15,000** | **~15,000** |
| 运行质检脚本 | PowerShell | ~500 | ~500 |
| 清理 JSON + 验证 | PowerShell ×3 | ~800 | ~300 |
| 对话交互与上下文累积 | — | ~5,000 | ~3,000 |
| **合计** | **~8 次** | **~37,000** | **~21,000** |

**每天约 5.5-6 万 token，约 1 次完整 TeleAgent 会话。**

### 1.2 消耗热点

```
编辑拼接第六七部分  ██████████████████████████████ 52%  ← 最大消耗
读取数据源 JSON     ████████████████ 22%
对话上下文累积      ████████ 14%
AI 思考六要素       ██████ 9%
工具调用开销        ███ 3%
```

**核心问题**：AI 不仅要填六要素，还要渲染 300 行第六七部分 markdown 并 Edit 拼接——一次 Edit 既要传 oldString 又要传 newString，输入和输出各占一半。

---

## 二、四个优化方向

### 优化 1：AI 只输出六要素 JSON，脚本渲染第六七部分 ★已实施完成（2026-10-07 E2E 验证通过）

**当前**：AI 读 JSON → 填六要素 → 渲染 300 行 markdown → Edit 拼接
**优化后**：AI 读 JSON → 只输出六要素 JSON（~800 token）→ 脚本渲染第六七部分

| 维度 | 当前 | 优化后 |
|------|------|--------|
| AI 输出 | ~21,000 token（含 300 行 markdown） | ~3,000 token（仅 JSON） |
| 节省 | — | **~50%+** |
| 质量影响 | — | 无（六要素仍由 AI 精读，渲染交给脚本） |

**前提**：需重写 `gen_report_final.py` 的 `generate_part67()`，解除已知限制：
- 数据占位符限 5 条 → 不限数量
- 地点只输出"北京/全国" → 从六要素提取全部
- 机构全称映射有限 → 扩充映射表 + 兜底标注
- 无 7.5 内容占位符 → 新增书名/文件名扫描
- 事件核心对象硬编码关键词 → 改为分类逻辑
- 不脱敏版人物类 → 直接列姓名+职务

**实施状态**：v1.0.0 已完成，见下方"实施记录"

### 优化 2：精简数据源 JSON（预计省 30% 输入 token）

**当前**：每条新闻同时有 `summary`（前 300 字）和 `full_text`（前 500 字），大量重复
**优化后**：去掉 `summary`，只保留 `full_text`；预填固定值行不传给 AI

**节省**：20 条 × 300 字 ≈ 6000 字符 ≈ 3000 token

**质量影响**：无（`full_text` 包含 `summary` 全部内容）

**实施难度**：低（改 `build_datasource()` 函数，30 分钟）

### 优化 3：减少工具调用轮次（预计省 10-15% token）

**当前**：Phase 1（PowerShell）→ 读 JSON（Read）→ 思考+编辑（Edit）→ 质检（PowerShell）→ 清理 → 汇报
**优化后**：prompt 中内嵌 JSON 内容，省 Read 调用往返

**质量影响**：无

### 优化 4：提高一次通过率（避免修复轮次）

**当前**：质检失败时 AI 重新读报告、定位问题、修复、重检——每轮约 1-2 万 token
**优化后**：脚本预检（填写率/分类/机构全称），AI 输出前自检

**质量影响**：正面

## 四、优化 1 实施记录（v1.0.0）

### 4.1 改动内容

**文件**：`代码\gen_report_final.py` 的 `generate_part67()` 函数

| 改动点 | 旧版 | 新版 |
|--------|------|------|
| 数据占位符 | 4 种正则，限 5 条 | 23 种正则，不限数量 |
| 地点占位符 | 只输出"北京/全国" | 从六要素提取全部地点 |
| 机构全称 | 17 个映射 | 40+ 映射 + 兜底"（待补充全称）" |
| 事件核心对象 | 5 个硬编码关键词 | 分类逻辑（机构后缀判定 + 兜底） |
| 内容占位符 7.5 | 无 | 新增《...》书名/文件名扫描 |
| 不脱敏版人物 | 不支持 | 检测 `XWLB_NO_DESENSITIZE`，直接列姓名+职务 |
| 父目录行 | 列出 | 跳过（已修复） |
| 空表兜底 | 无 | "本日无XXX"占位行 |

### 4.2 新流程

```
Phase 1: 脚本生成 1-5 部分 + 数据源 JSON（不变）
    ↓
Phase 2: AI 读 JSON → 填六要素 → 保存 result JSON（仅 JSON，不渲染 markdown）
    ↓
Phase 3: 脚本读 result JSON → generate_part67() 渲染高质量第六七部分 → 拼接
    ↓
质检 → 清理 JSON → 完成
```

**AI 输出从 ~21,000 token 降到 ~1,000 token（精简六要素 JSON）**（E2E 实测：20261006 报告 21 条仅 2.1KB JSON）。

### 4.3 质量保障

- 六要素仍由 AI 精读正文填写（核心质量环节不变）
- 脚本渲染格式与 `生成结果模板.md` 严格一致
- 质检脚本仍跑 12 项检测（E2E 验证 0 问题）
- 不脱敏版/脱敏版均支持

### 4.4 E2E 验证记录（2026-10-07，20261006 不脱敏版）

- 流程：Phase 1 → AI 填精简 JSON（18 条）→ `--merge` → 质检 0 问题（30.0KB/344 行）
- 第六部分 19 行（18 精读+完整版，父目录行 0）
- 7.1.1 人物 3 位（习近平/扎哈罗娃/古特雷斯，职务全取主体原文）；7.1.2 机构 9 个全称正确
- 7.4 数据占位符 37 条（基线仅约 20 条），说明列均为数值所在短语
- 五六部分交界干净（单一分隔线，无中部水印）；第四部分完整正文+空行分隔与基线一致
