## 修订重点（v1.0.0 解决的历史问题）

### 问题零：快讯父目录行在第六部分的处理（v1.0.0 重要修订）

**历史问题**：早期版本在第六部分同时列出快讯父目录行（序号8"国内联播快讯"、序号12"国际联播快讯"）和子条目行（8-1~8-4、12-1~12-3），父目录行用"播报XX联播快讯 / 目录播报"等占位值填充，制造噪音且语义勉强。

**本模板规范**：第六部分**不出现快讯父目录行**，只列子条目行。父目录行仍保留在第二部分（新闻速览，体现央视网实际分条顺序）和第五部分（完整性检测标题清单，央视网视频列表里确实存在），但不进入第六部分的六要素索引。这样与第五部分"N - D 减去目录行"的统计逻辑一致，第六部分只收录有实质内容的独立新闻。

### 问题一：快讯排版（第四部分）

**历史问题**：脚本旧版把每条快讯连续输出，条目之间无空行，视觉上挤成一团：

```
> (1) [标题A](url) — 摘要A...
> (2) [标题B](url) — 摘要B...
> (3) [标题C](url) — 摘要C...
```

**本模板规范**：每条快讯独立为一个引用块，**条目之间必须有一个空 `>` 行分隔**：

```
> (1) [标题A](url) — 完整摘要A
>
> (2) [标题B](url) — 完整摘要B
>
> (3) [标题C](url) — 完整摘要C
```

### 问题二：禁止省略信息

**历史问题**：脚本旧版将快讯正文截断为前 80 字并以 `...` 结尾：

```
> (1) [标题](url) — 国务院安委办、应急管理部日前调度国庆假期安全防范工作，要求高度关注云南、海南等地强降雨...
```

**本模板规范**：
1. **快讯正文必须完整**，禁止以 `...` 省略号结尾，禁止中途截断
2. 正文来源：数据源 JSON 中该条目的 `full_text` 字段（央视网"主要内容"区块完整提取）；**不得使用被截断的 `summary` 字段**（summary 仅为前 80 字预览）
3. 若 `full_text` 缺失（齐鲁网抓取返回 JS 垃圾的已知问题），使用央视网快讯视频页提取的完整正文；仍不可得时按下方降级规则处理并标注
4. 常规新闻第二部分的一句话概括除外（速览本来就是概括，允许收在句号处，但**同样禁止用 `...` 截断句中内容**）
