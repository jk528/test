## A. 零积分路径（不消耗积分）

### A1. oneshot 一键生成 ★默认

**命令**：
```powershell
python xwlb_report.py [date] --mode oneshot
```

**流程**：抓取央视网/齐鲁网 → 分类 → 重要性标注 → 正则提取六要素 → 渲染1-7部分 → 质检 → 归档

| 项 | 值 |
|----|-----|
| 积分消耗 | 0 |
| 耗时 | ~30秒 |
| 适用 | 日常自动生成 |
| 输出 | 归档/YYYY年MM月/新闻联播总结_YYYYMMDD.md |

---

### A2. oneshot + 定时补全 ★定时任务

**命令**：
```powershell
python auto_complete.py [date] --wait 1800 --max-retry 2
```

**流程**：A1首次运行 → 检测完整性（条目≥8 且 大小≥15KB 且 质检exit=0）→ 不全则等待30分钟 --force 重跑（最多2次）

| 项 | 值 |
|----|-----|
| 积分消耗 | 0 |
| 耗时 | 首次~30秒，补全最多+60分钟 |
| 适用 | 定时任务（每日11:10，已配置cron） |
| 完整性判定 | 条目数≥8 / 大小≥15KB / 质检退出码=0 |

**当前定时任务**：taskId=`fe438e99`，cron=`10 11 * * *`（每日11:10）

---

### A3. staged 分阶段（人工填要素）

**命令**：
```powershell
# Phase 1：生成1-5部分 + 数据源JSON
python gen_report_final.py 20261013

# 【人工填写精简结果JSON：六要素】

# Phase 3：合并渲染6-7部分
python gen_report_final.py 20261013 --merge
```

**流程**：phase1生成1-5部分+数据源JSON → 人工填写要素JSON → merge渲染6-7部分拼接

| 项 | 值 |
|----|-----|
| 积分消耗 | 0（但需人工介入） |
| 适用 | 需人工审核要素的精细场景 |
| 中间产物 | 数据源JSON / 结果JSON |

---

### A4. 批量重建归档

**命令**：
```powershell
python rebuild_archives.py              # 重建全部不达标归档
python rebuild_archives.py --all        # 全量重建（含已通过）
python rebuild_archives.py 20260601 20260715  # 指定日期
python rebuild_archives.py --dry-run    # 只列计划
```

**流程**：遍历归档 → 质检 → 不达标用A1流程重出 → 通过的保留 → 重出仍不达标保留旧文件

| 项 | 值 |
|----|-----|
| 积分消耗 | 0 |
| 适用 | 历史报告修复（6-8月旧流程产物） |
| 安全 | 重出结果自检通过才写盘，否则保留旧文件 |

## B. 后段消耗积分路径

### B1. staged：phase1纯脚本 → AI填要素 → merge ★推荐省积分

**命令**：
```powershell
# Step 1：phase1 生成1-5部分 + 数据源JSON（零积分）
python gen_report_final.py 20261013

# Step 2：AI API 填六要素（消耗积分）
python fill_elements_api.py 20261013 --api-key sk-xxx --base-url https://api.deepseek.com/v1 --model deepseek-chat

# Step 3：merge 合并渲染6-7部分（零积分）
python gen_report_final.py 20261013 --merge
```

**流程**：phase1纯脚本出框架 → AI仅填六要素 → merge纯脚本拼接

| 项 | 值 |
|----|-----|
| 积分消耗 | 仅Step2（AI填要素） |
| 适用 | 先零成本出框架，再AI增强六要素 |
| 优势 | 积分消耗最小化（AI只处理要素，不生成全文） |

---

### B2. oneshot生成后AI增强

**命令**：
```powershell

python xwlb_report.py 20261013 --mode oneshot

# Step 2：AI API 对已有报告增强六要素（消耗积分）
python fill_elements_api.py 20261013 --api-key sk-xxx --force
```

**流程**：oneshot完整生成 → AI事后增强六要素

| 项 | 值 |
|----|-----|
| 积分消耗 | 仅Step2 |
| 适用 | 报告已生成，事后AI增强 |
| 与B1区别 | B1是分阶段，B2是完整报告后增强 |

**流程**：ai_api模式首次生成 → 检测完整性 → 不全则等待后--force重跑（ai_api）

## 注意事项

1. **凭据安全**：AI API 凭据仅从 config.json 读取，不得写入报告与日志
2. **补全判定**：完整性检测标准为 条目≥8 且 大小≥15KB 且 质检exit=0，可按需调参
3. **路径共存**：各路径共用归档路径，通过 >10KB 跳过机制避免互相破坏
4. **定时切换**：修改执行时间或路径后，需重新注册 cron 任务或 schtasks
5. **C2 扩展**：`auto_complete.py` 当前未透传 `--mode`，需增加该参数方可支持 C2 路径
