# 新闻联播日报生成系统 — 最终版方案

> **版本**：1.0.0  
> **定位**：综合各版本优点的统一最终版，以央视网播出顺序为唯一排序基准，不脱敏保留原始人名  
> **核心修正**：联播快讯作为"合集条目"处理（与国内/国外新闻同级），而非旧版的"纯目录行不进入第六部分"

---

## 一、设计目标

1. **排序质量**：以央视网当日分条播出顺序为唯一排序基准，齐鲁网仅补链接与正文
2. **不脱敏**：保留新闻原始人名，人物以"职务+姓名"形式呈现，与央视网原始播报一致
3. **联播快讯合集**：联播快讯是压缩多条新闻的合集容器，合集本身计1条独立新闻，子条目各计1条
4. **结构契约**：所有章节标题、表头列名、类别枚举由 `contract.json` 统一定义，渲染层与质检层不得硬编码

---

## 二、联播快讯合集规则（核心修正）

### 2.1 问题背景

旧版将联播快讯视为"纯目录行"，不进入第六部分索引，导致：
- 10月13日等含单条"联播快讯"合集的日期，B=0（快讯子条目未展开）
- 条数公式不闭合，完整性检测失真

### 2.2 合集规则

联播快讯作为**合集条目**，与国内/国外新闻同级，参与常规连续编号：

| 部分 | 处理方式 |
|------|---------|
| 第二部分 | 合集行带编号，标注"（合集，内含X条子快讯，详见第四部分）" |
| 第三部分 | 合集行不展开（重点新闻详解仅收录🔴/🟡新闻） |
| 第四部分 | 展开全部子条目，国内/国际各自从 (1) 编号 |
| 第五部分 | 条数公式：独立新闻总数 = 分条总数（不含完整版，含合集行）+ 国内子条目数 + 国际子条目数 |
| 第六部分 | 合集行作为一行（序号=央视网分条实际序号，类别="联播快讯"）；子条目用"父序号-子序号"编号，单条合集时国际子条目序号接国内之后连续，避免重号 |
| 第七部分 | 子条目的占位符正常纳入统计 |

### 2.3 编号示例（10月13日）

```
常规新闻：1-10（10条）
联播快讯合集行：11（序号=央视网分条第11条）
  国内子条目：11-1, 11-2, 11-3, 11-4, 11-5（5条）
  国际子条目：11-6, 11-7（2条，接续国内编号）
条数公式：11 + 5 + 2 = 18 条独立新闻
```

### 2.4 识别逻辑

- `build_dataset` 识别标题为"联播快讯"的单条合集（兼容旧版"国内联播快讯"/"国际联播快讯"分开形式）
- 调用 `fetch_kuaixun_details` 解析合集页面子条目
- 按 `_looks_international` 分国内/国际
- `is_dir` 标记：`"联播快讯" in raw_title`

## 四、运行模式

| 模式 | 说明 | 命令 |
|------|------|------|
| oneshot | 正则一键生成（默认） | `python xwlb_report.py [date] --mode oneshot` |
| ai_api | AI API增强六要素 | `python xwlb_report.py [date] --mode ai_api` |
| staged | 分阶段生成 | `python xwlb_report.py [date] --mode staged` |

三种模式核心生成流程统一走 oneshot 链路，保证质量一致。ai_api/staged 模式提供后处理提示。

---

## 五、质量检测

`check_md_quality.py` 采用三级退出码：

| 退出码 | 含义 | 触发条件 |
|--------|------|---------|
| 0 | 全部通过 | 无 CRITICAL / ERROR / WARNING |
| 1 | 有 ERROR | 结构缺陷但非致命 |
| 2 | 有 CRITICAL | 致命问题（缺章节/表头错/链接不一致） |

**不脱敏**：最终版默认跳过敏感人名检查。如需检查，加 `--check-dedesensitize` 参数。

**合集完整性检测**：自动校验第二部分合集标注 ↔ 第四部分子条目展开 ↔ 第六部分合集行+子条目一致性。

## 六、关键技术决策

1. **CNTV接口漂移兜底**：CNTV栏目接口对历史日期只返回2条分段，`fetch_videos` 在返回<5条时回退央视网日页 `fetch_xwlb_list` 补全
2. **第七部分编号修正**：旧版 part7 跳过7.2（7.3时间/7.4地点/7.5数据/7.6内容），最终版修正为7.2时间/7.3地点/7.4数据/7.5内容
3. **前置备份**：`--force` 重新生成时，若已存在>10KB报告先备份到 `.temp/` 再覆盖
4. **load_contract优先读contract.json**：失败时回退模板抽取，保证健壮性
