## 一、总纲

### 1.1 一句话链路

【代码事实】

```
Windows 计划任务（每日 11:10）
  → auto_complete.py（首次跑 + 完整性判定 + 必要时等待重跑）
    → xwlb_report.py（oneshot 单一入口）
      → CNTV 栏目接口 / 央视网日页（常规新闻 + 完整版）
      → 央视网快讯目录页 + 齐鲁网索引（快讯子条目名录与链接）
      → 正文抓取 → 规则分类分级 → 正则/词典六要素
      → 七部分 Markdown 渲染（contract.json 约束结构）
      → 质量自检（三级问题级别 → 退出码 0/1/2）
      → 落盘 归档/YYYY年M月/新闻联播总结_YYYYMMDD.md
```

关键事实：**日常链路不调用 AI**。`--mode ai_api|staged` 仅打印提示，真正的 AI 脚本是独立的历史 CLI（`fill_elements_api.py` 等），不在定时任务链路中。

### 1.2 阶段索引（总纲 → 阶段）

| 阶段 | 名称 | 主责代码 | 核心产物 | 失败是否中断整链 |
|------|------|----------|----------|------------------|
| S0 | 触发/调度 | `auto_complete.py`、`register_task.ps1`、`run_now.ps1` | 一次进程调用 | 是（退出码非 0） |
| S1 | 内容获取（列表/完整版） | `xwlb_report.py: fetch_videos / fetch_segments_from_api / fetch_full_video`、`fetch_xwlb.py: fetch_xwlb_list` | 视频条目列表 | 是（无常规条目即抛错） |
| S2 | 解析清洗（标题/日期/去重/顺序） | `fetch_videos`、`_normalize_day_title`、`_url_path_date` | 归一化播出顺序 | 否（降级继续） |
| S3 | 快讯名录对账 | `fetch_kuaixun_details`、`fetch_iqilu_entries`、`reconcile_brief_roster` | 国内/国际快讯子条目 | 否（可产出 0 条） |
| S4 | 正文抓取 + 分类 + 六要素 | `fetch_video_detail`、`classify_and_grade`、`extract_six_elements` | `Dataset` 元素字段 | 否（字段退化为 `—`） |
| S5 | 结构化产出（MD） | `render_report` 及 `_render_part1..7`、`contract.json` | 七部分 Markdown | 是（渲染异常 → exit 1） |
| S6 | 质量自检 | `self_check`、`_report_issues` | 问题清单 + 退出码 | 否（但退出码决定任务成败） |
| S7 | 落盘与命名 | `resolve_output_path`、`main` 写文件段 | 归档 MD | 是（写失败 → exit 1） |
| S8 | 补全与结束状态 | `auto_complete.main`、日志 | 最终退出码 + 日志 | 是（最终非 0 即任务失败） |

### 1.3 运行入口与退出码

| 入口 | 命令 | 说明 |
|------|------|------|
| 定时任务 | `python auto_complete.py --wait 1800 --max-retry 2` | Windows 任务 `XWLB_DailyReport`，每日 11:10，工作目录 `最终版/代码` |
| 手动补全 | `python auto_complete.py 20261101 --wait 0 --max-retry 0` | 指定日期；`--wait 0` 便于调试 |
| 单次生成 | `python xwlb_report.py 20261101` | 默认日期 = 昨天 |
| 强制重建 | `python xwlb_report.py 20261101 --force` | 旧文件 >10KB 先备份到 `.temp` |
| 只自检 | `python xwlb_report.py 20261101 --check` | 不重新抓数据 |
| 预览 | `python xwlb_report.py 20261101 --dry-run` | 抓取+渲染+自检，不落盘 |

【代码事实】退出码映射（`xwlb_report.py: _report_issues`）：

| 退出码 | 触发条件 |
|--------|----------|
| 0 | 无 CRITICAL、无 ERROR（**WARNING 不影响退出码**） |
| 1 | 存在 ERROR（如主体覆盖率 <70%、行数不一致） |
| 2 | 存在 CRITICAL（缺章节、表头错误、重点新闻丢失） |

`auto_complete.py` 对上述退出码再做一次任务级判定：首次 `rc=0` 且结构完整 → 任务成功；否则按补全策略处理。

## 二、阶段拆解

### S0 触发与调度

**输入**：系统时间、`最终版/不用积分/config/config.json`、Windows 任务计划。

**处理动作**

1. 【代码事实】Windows 计划任务 `XWLB_DailyReport` 每日 `11:10` 触发：
   - 程序：`C:\Users\Administrator\python-sdk\python3.13.2\python.exe`
   - 参数：`"...\最终版\代码\auto_complete.py" --wait 1800 --max-retry 2`
   - 起始于：`...\最终版\代码`（`register_task.ps1:26` 用 `New-ScheduledTaskAction -WorkingDirectory` 设置）
   - 设置：`IgnoreNew`（禁止并发重复实例）、`StartWhenAvailable`（错过补跑）、`ExecutionTimeLimit=2h`
2. `auto_complete.py` 未给日期时取**昨天**（`auto_complete.py:76`）。
3. 手动入口 `run_now.ps1` 直接调用 `xwlb_report.py`，可选择日期与 `--force`。

**输出**：一次 Python 进程执行。

**关键判定**

- 目标日期格式必须 `YYYYMMDD`；非法 → 退出 1。
- 未来日期拒绝生成（`xwlb_report.py:2991-2993`）→ 退出 1。
- `IgnoreNew` 保证任务实例不并发；手动运行与定时运行**没有互斥锁**，理论上可并发写同一文件（见第 6 节建议）。

**失败分支与兜底**

- 错过触发时间：`StartWhenAvailable=true` 会尽快补跑。
- 任务实例超 2 小时：由系统强制结束（正常最长约 65 分钟：首次 + 2×30 分钟等待）。

**文档差异**

- 【差异】`运行路径配置指南.md:57,252,265` 写“cron `10 11 * * *`，taskId=`fe438e99`”；实际是 Windows 计划任务 `XWLB_DailyReport`，不存在 cron 表达式与 taskId。
- 【差异】文档多处写触发时间 05:00（`使用指南.md` 已修正为 11:10）。

### S1 内容获取（站点 / 接口 / 参数）

**输入**：`date_str`（YYYYMMDD）。

**数据源与请求参数**

| 用途 | URL / 接口 | 参数与说明 |
|------|------------|------------|
| 常规分段列表（首选） | `https://api.cntv.cn/NewVideo/getVideoListByColumn` | `id=TOPC1451528971114112&n=60&sort=desc&p=1&mode=1&serviceId=tvcctv`（`xwlb_report.py:341-343`） |
| 完整版列表 | 同上接口 | `mode=0`（`fetch_full_video`） |
| 央视网日页兜底 | `https://tv.cctv.com/lm/xwlb/day/{YYYYMMDD}.shtml` | `fetch_xwlb.py: fetch_xwlb_list`，重试 1 次、超时 30s、强制 UTF-8 |
| 央视网快讯目录页 | 来自常规列表中的合集条目 `url` | 解析 `div.content_area` 内 `<p><strong>标题</strong>` + 正文 |
| 齐鲁网索引 | `https://v.iqilu.com/jcdb/ysxwlb/index.html`；第 n 页 `index_{n-1}.html` | `_iqilu_page_url`；按日期定位页 ±2 页 |
| 快讯清单交叉校验 | CNTV `mode=1` 返回的 `brief` 字段 | `fetch_kuaixun_briefs`，只告警不阻断 |

**处理动作（按调用顺序）**

1. `fetch_segments_from_api(date_str)`（`xwlb_report.py:393`）
   - 调 `_cntv_column(mode=1)`，解析 `data.list`。
   - **日期窗口**：只保留 URL 路径日期 `== date_str` 的条目（`_url_path_date`，正则 `/YYYY/MM/DD/VIDE`）。
   - 标题去掉 `[视频]` 前缀；按标题去重；接口是倒序，`rows.reverse()` 还原播出顺序。
2. `fetch_videos(date_str)`（`xwlb_report.py:452`）
   - 若接口结果为空或 **<5 条**，回退央视网日页，并用 `_normalize_day_title` 剥掉页面统一加的“完整版”前缀（不能按“完整版”过滤，否则历史日期会被清空）。
   - 取条数更多的一份作为 `videos`。
3. 完整版挑选（`fetch_full_video` + `fetch_videos`）
   - 优先 `mode=0` 中标题含目标日期且含《新闻联播》的条目，排序键 `(URL 日期==目标日期, 是否19:00)`。
   - 接口无覆盖时从列表按日期或时长 >1500 秒兜底。
   - 剔除同日 21:00 重播（`_FULL_RERUN_RE`，`《新闻联播》 YYYYMMDD HH:MM`）。

**输出**：`[{title, duration, url}]`，首条为完整版，其余为常规分条。

**关键判定 / 跳过 / 终止**

- 接口失败（超时/非 JSON/网络错误）→ `_cntv_column` 返回 `[]`，进入日页兜底。
- 接口与日页都拿不到数据 → `build_dataset` 抛 `RuntimeError("央视网数据获取失败")`（`xwlb_report.py:2817-2818`）→ 整链退出 1，**不写报告**。
- 完整版缺失不阻断：`ds.full_url` 退化为日页 URL，后续质检会给 WARNING。

**失败分支与兜底**

- HTTP 层统一重试：`http_get`（`xwlb_report.py:306`）超时 30s，最多 1+2 次，重试间隔 3s，内存缓存同一 URL。
- 日页解析有模式 1（`<li>`）与模式 2（逐条正则）两级兜底（`fetch_xwlb.py:110-210`）。
- 【代码事实】`fetch_iqilu.py` 在最终版链路中**没有任何 import**，是遗留模块；齐鲁网能力实际在 `xwlb_report.py: fetch_iqilu_entries` 内。

**文档差异**

- 【差异】`项目总结报告.md:181`、`最终版方案.md:66` 把 `fetch_iqilu.py` 列为抓取模块；实际未使用。

### S2 解析与清洗（列表页 / 详情页 / 去重 / 日期窗）

**输入**：S1 返回的原始条目。

**处理动作**

1. 标题归一化：去 `[视频]`、去“完整版”前缀、去 `【联播快讯】`/“联播快讯”字样（`_normalize_day_title`、`fetch_iqilu_entries`）。
2. 去重：
   - CNTV 分段按**标题**去重；
   - 日页按 **URL** 去重（`fetch_xwlb.py`）；
   - 齐鲁网按**链接**去重。
3. 日期窗：只保留目标日期（CNTV 用 URL 路径日期；齐鲁网用链接里的 `YYYYMM/DD`）。
4. 顺序还原：
   - CNTV 倒序列表 → `reverse()`；
   - 齐鲁网按 URL 末尾数字 ID 升序（`pos` 递增），因为 ID 随播出顺序递增。
5. 完整版与 21:00 重播剔除。

**输出**：有序、去重、日期一致的条目集合。

**关键判定**

- 标题为空或清洗后为空 → 丢弃（齐鲁网 `if not clean: continue`）。
- 同日多条快讯合集：`contract.json` 的 `collection_patterns` 决定“国内/国际/单条合集”识别；单条合集再用 `_looks_international` 拆分国内/国际（`build_dataset:2843-2846`）。

**失败分支与兜底**

- 日页标题前缀漂移 → 归一化而非过滤（v5.3 修复的核心）。
- 齐鲁网定位页失败或超出 `_IQILU_MAX_PAGE=140` → 返回空名录，流程继续。

### S3 快讯名录对账（央视网 × 齐鲁网）

**输入**：常规新闻标题、央视网快讯页子条目、齐鲁网当日索引名录。

**处理动作**

1. `fetch_kuaixun_details(video_url)`（`xwlb_report.py:545`）
   - 只解析 `div.content_area`；页头“央视网消息（新闻联播）”跳过；`<strong>` 视为新条目标题，后续 `<p>` 视为正文。
   - 内容区为空（JS 动态注入）→ 返回 `[]` 并告警，**不再**用弱正则扫全页造伪条目。
2. `fetch_iqilu_entries(date_str)`（`xwlb_report.py:760`）
   - `_iqilu_find_page` 定位目标日期页，抓 `base-1..base+2` 四页；
   - 过滤目标日期、剔除“完整版”、按链接去重；
   - 按 URL 数字 ID 升序生成 `pos`。
3. `reconcile_brief_roster`（`xwlb_report.py:631`）
   - **名录基准** = 齐鲁网当日条目 − 央视网常规新闻（相似度 < `_SIM_MATCH=0.55` 视为快讯候选）。
   - 央视网快讯页可用时以其为国内/国际名录；不可用时按 `_looks_international` 启发式拆分。
   - 正文优先取条目自带正文，其次跨池（国内↔国际）模糊匹配正文；链接优先齐鲁网。
   - 名录顺序按齐鲁网 `pos` 倒序还原播出顺序。
4. `fetch_kuaixun_briefs` 交叉校验子条目条数，仅告警。

**输出**：`domestic_rows`、`international_rows`（各含 `{title, iqilu_url, body}`）。

**关键判定 / 跳过**

- 央视网快讯页全空 → 走齐鲁网名录 + 标题启发式，不中断。
- 齐鲁网也为空 → 快讯 0 条；**报告仍生成**，不报错（见第 6 节缺口）。
- 快讯子条目缺正文时仅按标题推导六要素，日志告警。

**失败分支与兜底**

- 名录对不齐：以齐鲁网为名录基准，央视网只补正文，避免“JS 空页导致丢条目”。
- 央视网条数与对账条数不一致：`logger.warning` 打印两份清单，不阻断。

### S4 正文抓取、分类分级、六要素（含 AI 阶段的真实状态）

**输入**：S1 的视频 URL、S3 的快讯行。

**处理动作**

1. `fetch_video_detail(video_url)`（`xwlb_report.py:508`）
   - 从页面 `主要内容` 区块提取 `<p>`；若段落不足 2 条，退化为按换行切分；
   - 去“央视网消息（…）：”前缀；返回 `{paragraphs, full_text, first_paragraph}`。
2. `classify_and_grade`（`xwlb_report.py:953`）
   - 关键词加权 + 强制规则（`_FORCE_RULES`）→ 类别（政策/会议、国际、经济、社会/文化等，枚举由 `contract.json` 约束）与重要性 `🔴/🟡/⚪`。
3. `extract_six_elements`（`xwlb_report.py:1660`）
   - 时间：播出日期 + 正文时间线索；
   - 地点：`extract_location`（`1312`）；
   - 主体：`extract_subject`（`1369`），优先级：
     `快讯固定词` → `_ACTOR_OVERRIDES`（书名出版/中共中央等）→ `PERSON_NAME_ROLES` 真实人名“职务+姓名” → `<u>职务占位符</u>` → 机构词典最长匹配 → 地名/“我国”兜底 → `—`；
   - 事件：`extract_event`；原因：`extract_cause`；方式：`extract_method`；
   - 出口统一 `desens()`（最终版为恒等，不脱敏）。
4. 快讯子条目：`make_brief` 复用同一套分类与要素抽取，国内快讯不强制国际类别。
5. `build_summary` 生成速览摘要；`build_tone_overview` 生成第一部分基调。

**输出**：`Dataset` 内每条新闻的 `{category, importance, elements, summary, detail}`。

**关键判定**

- 正文为空：不抛错，六要素仅依据标题推导，字段可能为 `—`。
- 主体为 `—` 的比例：`self_check` 要求 **覆盖率 ≥70%**，否则 ERROR（退出 1）。

**失败分支与兜底**

- 单条正文抓取失败 → `fetch_video_detail` 返回空结构，继续下一条。
- 分类无法命中 → 默认类别（由规则兜底），不会中断。

**AI 阶段的真实状态（重点）**

- 【代码事实】`xwlb_report.py:3071-3074`：`--mode ai_api` / `--mode staged` 只写日志提示，**不调用任何 AI**，也不调用 `fill_elements_api.py`。
- 【代码事实】`fill_elements_api.py` 是独立 CLI：读取 `gen_report_final.py` 的阶段产物，调用兼容 OpenAI 风格的 `/chat/completions`，**只写 `六要素结果_{date}.json`，不修改 MD**。
- 【差异】`运行路径配置指南.md:196` 称 ai_api 模式“自动调用 fill_elements_api.py 增强六要素”，不成立。
- 【差异】`运行路径配置指南.md:166-183` 的 B2“oneshot 生成后 AI 增强已有报告”不成立：该脚本不写回 MD，且 `gen_report_final.py --merge` 会把第六、七部分再次追加，存在结构风险。
- 【建议改动】若要保留 AI 能力，应新增一个明确的“后处理阶段”：读取完整 MD + 产出 JSON → 定点替换第六部分 → 原子写回；否则应在文档中删除 AI 路径，避免误用。

### S5 结构化产出（MD / JSON 字段）

**输入**：`Dataset` + `contract.json`。

**处理动作**

1. `load_contract()`（`xwlb_report.py:210`）加载 `contract.json`：章节标题、第六部分 10 列表头、第三部分子节、第七部分子节、引导语、合集模式。
2. `render_report`（`xwlb_report.py:2086`）依次渲染：
   - 第一部分 `_render_part1`：基调概述；
   - 第二部分 `_render_part2`：新闻速览（合集行标注“（合集，内含X条子快讯…）”）；
   - 第三部分 `_render_part3`：仅 🔴/🟡 重点新闻详解；
   - 第四部分 `_render_part4`：快讯子条目逐条展开；
   - 第五部分 `_render_part5`：完整性 N/D/M/K/X 统计与播放时间推算；
   - 第六部分 `_render_part6`：10 列六要素索引表，合集子条目编号 `父序号-子序号`；
   - 第七部分 `_render_part7`：人物/机构/事件对象、时间、地点、数据、内容占位符。
3. 产出为**纯 Markdown 字符串**；日常链路不产出 JSON 报告文件（`六要素结果_*.json` 只在 legacy AI 链路出现）。

**输出**：完整七部分 Markdown，UTF-8。

**关键判定**

- 结构契约不一致：`self_check` 直接判 CRITICAL。
- 第三部分不得丢失 🔴/🟡 新闻（否则 CRITICAL）。

### S7 文件落盘与命名

**输入**：Markdown 字符串、目标日期、`ARCHIVE_ROOT`。

**处理动作**

1. `_resolve_archive_root()`（`xwlb_report.py:74`）解析归档根，优先级：
   `环境变量 XWLB_ARCHIVE_ROOT` → `最终版/不用积分/config/config.json.archive_root` → `最终版/config/config.json` → `代码/config.json` → 脚本位置推导 `新闻联播/归档`。
   启动日志打印实际归档根（`logger.info(f"归档根目录：{ARCHIVE_ROOT}")`）。
2. `resolve_output_path`（`xwlb_report.py:2950`）：`{ARCHIVE_ROOT}\{YYYY}年{M}月\新闻联播总结_{YYYYMMDD}.md`，月份**不补零**。
3. 编码：`utf-8`（无 BOM）；自动 `os.makedirs(month_dir)`。
4. 存在性策略（`main:3023-3037`）：
   - 文件存在且 >10KB，且无 `--force`、非预览 → **跳过重新生成**，直接对旧文件自检并返回其退出码；
   - 文件 ≤10KB → 视为不完整，重新生成覆盖；
   - `--force` 且旧文件 >10KB → 先备份到 `归档\.temp\新闻联播总结_{date}_backup.md`。
5. 成功时打印报告路径与 `computer://` 链接。

**输出**：归档 MD 文件。

**关键判定 / 跳过**

- 已存在的大文件不会因定时重跑而被覆盖（防止把好文件改坏），但也不会修复旧文件的质量问题；需人工 `--force`。
- 未来日期、非法日期：不落盘，退出 1。

**失败分支与兜底**

- 写入异常会向上抛出（未单独捕获），`auto_complete` 看到非 0 后进入补全策略。
- 【缺口】≤10KB 覆盖时**不备份**；写入非原子（直接 `open(..., "w")`），进程中断可能留下半截文件。

### S8 补全与结束状态（auto_complete + 日志）

**输入**：日期、`--wait`、`--max-retry`、可选的 `--retry-on-quality`。

**处理动作**（`auto_complete.py:67-114`）

1. 首次执行 `xwlb_report.py <date>`（子进程，`cwd=最终版/代码`，注入 `PYTHONIOENCODING=utf-8`）。
2. `check_completeness`（`auto_complete.py:49-64`）判定：
   - 文件存在；
   - 大小 ≥15KB；
   - 第二部分 `### ...数字.` 标题数 ≥8。
   - 【代码事实】**不检查质检退出码**（与文档声明相反），退出码在 `main` 中单独判断。
3. 分支：
   - `完整 && rc==0` → 成功，退出 0。
   - `完整 && rc!=0 && 未传 --retry-on-quality` → 记录“结构完整但质检未通过”，**不空等重跑**，退出 1（本次修复）。
   - 其余（结构不完整，或显式要求重试）→ 循环 `max_retry` 次：等待 `wait` 秒 → `--force` 重跑 → 重新判定；成功即退出 0。
4. 达到上限仍不完整 → 退出 1，日志提示人工排查。

**输出**：任务最终退出码；日志写入 `%TEMP%\xwlb_cache\auto_complete.log`（补全）与 `xwlb_report.log`（生成/自检）。

**关键判定 / 终止**

- 结构完整但质检失败：默认**立即失败**（避免 30/60 分钟空跑），这是 2026-11-02 定时任务失败后的针对性修复。
- 结构不完整（缺条目/文件过小）仍会等待重跑，适合“数据源同步延迟”场景。

**失败分支与兜底**

- 子进程异常/非 0：按上述分支处理。
- 仍无法确定“今日是否已成功跑过”：没有成功标记文件，只能靠报告存在性判断（见第 6 节缺口）。
