## 二、四象限镜像对称

### 2.1 核心发现：方向反转 ≠ 左右镜像

用 A1A2 / B3B4B5 / C6C7C8C9（2×3×4=24组）验证后，发现：

| 概念 | 是否真正镜像 | 说明 |
|------|------------|------|
| 方向反转（正↔反） | ❌ 不是 | 只是不同的遍历顺序，不是镜像 |
| 数据反转（上下颠倒） | ✅ 是 | 等价于行顺序反转，真正的上下镜像 |
| **元素反转（列顺序反转）** | ✅ 是 | 每行元素左右翻转，真正的左右镜像 |

### 2.2 真正的四象限镜像

以基准数据为左上，通过两种翻转生成另外三个象限：

| 位置 | 变换方式 | 说明 | 示例（A1B3C6） |
|------|---------|------|--------------|
| 左上 | 原始（基准） | 基准 | A1B3C6 |
| 右上 | 左右镜像 | 每行元素反转（列顺序翻转） | C6B3A1 |
| 左下 | 上下镜像 | 行顺序反转（第1行 ↔ 最后1行） | A2B5C9 |
| 右下 | 中心镜像 | 行反转 + 元素反转 | C9B5A2 |

**对称性验证（全部严格成立）：**
- ✅ 左右对称：右上 = reverse(左上每行)
- ✅ 上下对称：左下 = 左上行反转
- ✅ 中心对称：右下 = 行反转 + 元素反转

### 2.3 4 种基准

四象限开关打开时，点击按钮 1~4 分别生成不同基准的四象限：

| 按钮 | 基准 | 布局 | 说明 |
|------|------|------|------|
| 按钮1 | 反竖 | 竖向 | 左慢右快为基准的竖向四象限 |
| 按钮2 | 正横 | 横向 | 左快右慢为基准的横向四象限 |
| 按钮3 | 正竖 | 竖向 | 左快右慢为基准的竖向四象限 |
| 按钮4 | 反横 | 横向 | 左慢右快为基准的横向四象限 |

布局自动跟随基准：竖按钮 → 竖四象限，横按钮 → 横四象限。

## 三、两种布局对比

### 3.1 竖向布局（按钮1、按钮3）

组合**竖向排列**（一列一组），四象限按 2×2 摆放：

```
┌───────────────┬───────────────┐
│【原始】       │【左右镜像】   │
│ A1-B3-C6      │ C6-B3-A1      │
│ A2-B3-C6      │ C6-B3-A2      │
│ A1-B4-C6      │ C6-B4-A1      │
│ ...           │ ...           │
├───────────────┼───────────────┤
│【上下镜像】   │【中心镜像】   │
│ A2-B5-C9      │ C9-B5-A2      │
│ A1-B5-C9      │ C9-B5-A1      │
│ A2-B4-C9      │ C9-B4-A2      │
│ ...           │ ...           │
└───────────────┴───────────────┘
```

特点：每个组合占 1 行，适合**列数少、行数多**的数据。

### 3.2 横向布局（按钮2、按钮4）

组合**横向排列**（每列一个组合，元素向下延伸），四象限按 2×2 摆放。

**合并模式**（每个组合1个单元格，横向排列）：
```
┌──────────────────────────────────────────┐
│【原始】         │【左右镜像】             │
│ A1B3C6 A2B3C6… │ C6B3A1 C6B3A2…         │
├────────────────┼─────────────────────────┤
│【上下镜像】     │【中心镜像】             │
│ A2B5C9 A1B5C9… │ C9B5A2 C9B5A1…         │
└────────────────┴─────────────────────────┘
```

**分开模式**（每列一个组合，元素从上往下读，3列元素 × 24列组合 = 3行 × 24列 = 72格）：
```
每象限：3行 × 24列 = 72个单元格

  组1  组2  组3  ...  组24
  A1   A2   A1   ...  A2    ← 第1列元素
  B3   B3   B4   ...  B5    ← 第2列元素
  C6   C6   C6   ...  C9    ← 第3列元素
```

### 3.3 布局尺寸（M=组合数，K=列数）

| 模式 | 竖向布局（每象限） | 横向布局（每象限） |
|------|------------------|------------------|
| 合并 | M 行 × 1 列 | 1 行 × M 列 |
| 分开 | M 行 × K 列 | K 行 × M 列 |

例：3 列 × 24 组合 = 24 组
- 竖合：24 行 × 1 列 = 24 格
- 横合：1 行 × 24 列 = 24 格
- 竖分：24 行 × 3 列 = 72 格
- **横分：3 行 × 24 列 = 72 格** ✅

四象限整体尺寸 = 每象限 × 2 + 分隔（空行/空列）+ 标签行

## 四、使用方法

### 4.1 基本操作

1. 将 `四方镜子_单模块版_v11.bas` 导入 Excel VBA 工程
2. 运行 `四方镜子()` 宏
3. 勾选/取消顶部开关：
   - **合并**：组合元素合并成一列 vs 多列分开
   - **数据反转**：每列数据从下往上读取
   - **四象限对称**：按钮1~4生成四象限 vs 单表
4. 点击对应按钮生成结果

### 4.2 四象限使用技巧

- 想看竖向四象限 → 点按钮1（反竖基准）或按钮3（正竖基准）
- 想看横向四象限 → 点按钮2（正横基准）或按钮4（反横基准）
- 正竖 vs 反竖的区别：生成顺序不同（左快右慢 vs 左慢右快），但镜像关系相同
- 4 种基准生成的表名不同（四象限_正竖_…、四象限_反横_… 等），不会互相覆盖

### 4.3 如何选择竖版还是横版

| 数据特征 | 推荐 | 原因 |
|---------|------|------|
| 2列各3行（2×3=6组合） | 竖版 | 6行少，竖版紧凑 |
| 3列各2行（3×2=6组合） | 横版 | 6列少，横版紧凑 |
| 行数 < 列数 | 横版 | 行数少，横排更直观 |
| 行数 > 列数 | 竖版 | 列数少，竖排更直观 |

简单说：**数据瘦高用竖版，数据矮胖用横版**。

## 八、v11.6 修复：横向布局镜像公式分模式

### 8.1 问题发现

v11.5 中 Q2/Q3/Q4 镜像公式只按"竖向/横向"两种布局区分，但实际测试发现横向合并模式不对称。

### 8.2 根本原因：视觉对称 = 字符串反转

**核心洞察**：视觉对称的本质就是**字符串反转**（含连字符位置对称）。

例如 `2-5-9` 反转 = `9-5-2`，这就是视觉上的左右/上下镜像。

**关键原则**：横向合并每象限仅 1 行，上下镜像 = identity（单行无纵向可翻转），左右镜像 = RE（整行视觉翻转 = 顺序反转 + 元素反转）。

以正横为例，横向合并 [RE,identity,RE] 的输出中，"259 952" 的左右镜像对成立：
- 左右镜像对1：Q1 末位 259 ↔ Q2 首位 952（双反转=视觉翻转）✓
- 左右镜像对2：Q3 末位 259 ↔ Q4 首位 952（双反转）✓
- 上下相同对1：Q1 末位 259 ↔ Q3 末位 259（identity）✓
- 上下相同对2：Q2 首位 952 ↔ Q4 首位 952（identity）✓

| 布局 | Q2 左右镜像 | Q3 上下镜像 | Q4 中心 |
|------|-----------|-----------|--------|
| 竖向 | 元素反转(E) | 行反转(R) | 双反转(RE) |
| 横向合并 | 双反转(RE) | 无变换(identity) | 双反转(RE) |
| 横向分开 | 组合反转(R) | 元素反转(E) | 双反转(RE) |

横向合并用 [RE,identity,RE]；横向分开用 [R,E,RE]；竖向用 [E,R,RE]。

### 8.3 修复方案：变换表 + 取值函数

基于"视觉对称=字符串反转"概念，用变换表统一处理。横向合并用 [RE,identity,RE]，横向分开用 [R,E,RE]，竖向用 [E,R,RE]：

```
变换类型: 0=identity(无变换), 1=R(组合反转, 反转行), 2=E(元素反转, 反转列), 3=RE(双反转)
变换表 = 横向合并 ? [3,0,3] : 横向分开 ? [1,2,3] : [2,1,3]
取值(变换, c, r) = Q1[变换含E?反转c:c][变换含R?反转r:r]
```

代码结构：
- 变换表：按布局+合并模式选择 Q2/Q3/Q4 的变换类型（三分支：横合/横拆/竖向）
- 取值函数：统一处理 identity/R/E/RE 四种变换
- 循环内：Q2/Q3/Q4 都调用同一函数，无需 if-else 分支

### 8.4 区域视觉对称性验证（2×3×4 数据）

横向合并用 [RE,identity,RE]，横向分开用 [R,E,RE]，竖向用 [E,R,RE]：

|--------|------|---------|---------|
| Q1↔Q2 左右 | 镜像 | 镜像 | 相同 |
| Q1↔Q3 上下 | 相同 | 相同 | 镜像 |

### 8.4.3 横向合并 vs 横向分开：公式分模式

| Q2↔Q4 上下 | 相同 | 镜像 |
| Q3↔Q4 左右 | 镜像 | 相同 |

横向合并（Q1=Q3, Q2=Q4）：

- 上下相同对1：Q1 末位 259 ↔ Q3 末位 259（identity）✓

- 上下镜像对1：Q1 末位 259 ↔ Q3 末位 952（元素反转）✓

## 九、调试过程与逻辑思路

### 9.1 问题排查流程（多轮迭代）

整个 v11.6 修复历经三轮迭代，每轮都由用户反馈+code_mode 验证驱动：

**第一轮：横向布局公式不分模式**
1. 用户反馈：反横合并错误、反横分开正确
2. code_mode 模拟 2×3 数据，发现横向布局下"合并"和"分开"视觉方向不同
3. 初步修复：仅横向分开互换 Q2/Q3 公式，其他用竖向公式

**第二轮：验证函数公式用错**
1. 自测发现反竖也"假阴性"，排查后发现是验证函数用了错的横向公式
2. 按布局选择验证公式后，8 个四象限 4 种对称性全通过
3. 但用户反馈"四象限_正横_合并_18 还是有问题"

**第三轮：方向重叠错误判断**
1. 误以为横向合并左右方向=列+元素重叠，推导出 Q2=RE、Q4=R（三套独立公式）
2. 用户给出正横·合并_24 实际输出，确认"还要保留"

**第四轮：用户指出横向合并单行视觉翻转 = RE（最终修复）**
1. 用户给出正横·合并输出，指出 Q1=Q3、Q2=Q4（横向合并每象限仅1行）
2. 分析发现：横向合并单行——左右镜像 = 整行视觉翻转 = RE，上下镜像 = identity（单行无纵向可翻转）
3. 关键认知：横向合并用 [RE,identity,RE]，横向分开用 [R,E,RE]，竖向用 [E,R,RE]
4. 变换表从二分支改为三分支，增加 0=identity 类型
5. 验证：左右镜像对 Q1末259↔Q2首952、Q3末259↔Q4首952 全部成立 ✓
6. 上下相同对 Q1末259↔Q3末259、Q2首952↔Q4首952 全部成立 ✓
7. 8 个四象限 × 6 种对称性 = 48 个检查点全部通过 ✓

### 9.2 关键调试手段

用 Exec 沙箱独立验证公式，不依赖 WPS 环境：

```javascript
// 构造 2x3x4 数据
var 源数据 = [['a1','b1','c1'],['a2','b2','c2'],['','b3','c3'],['','','c4']];
// 生成 Q1，按公式生成 Q2/Q3/Q4，逐一验证对称性
```

每次公式修改后都重新运行验证，最终 8 个四象限 × 6 种区域视觉对称性 = 48 个检查点全部通过。

### 9.3 视觉对称的本质

**视觉对称 = 字符串反转**（含连字符位置对称）：

- `2-5-9` ↔ `9-5-2`（字符串反转，视觉对称）
- `1-3-6` ↔ `6-3-1`（字符串反转，视觉对称）

横向合并下，每个象限是 1 行字符串，左右镜像 = 整行视觉翻转 = 双反转（Q2=RE），上下镜像 = 单行无纵向可翻转 = identity（Q3=identity），中心镜像 = 双反转（Q4=RE）。横合用 [RE,identity,RE]，横拆用 [R,E,RE]。

### 9.4 设计原则总结

**镜像公式取决于最终输出布局的视觉方向**，不是数据存储方向：
- 数据按列存 `Q[c][r]` 是固定的
- 但"左右"和"上下"在最终输出表中的含义会随布局变化
- 必须按"输出布局"而非"数据结构"来定义镜像公式
- 横向合并用 [RE,identity,RE]（单行：左右=RE, 上下=identity），横向分开用 [R,E,RE]（多行：左右=R, 上下=E），竖向用 [E,R,RE]

### 9.5 经验教训

1. **局部对称 ≠ 区域对称**：每个位置局部对称不一定保证整个区域视觉对称
2. **验证函数也会用错公式**：调试时验证函数本身可能有 bug，需要根据布局选择验证公式
3. **视觉对称 = 字符串反转**：用字符串反转概念验证比 R/E/RE 代数分析更直观简洁
4. **小数据测边界**：2×3×4=24 组合足够暴露所有对称性问题，又不会太多导致看不清规律

## 二、四象限对称是什么

### 2.1 布局结构

### 2.2 对称关系

| 对称类型 | 两象限 | 对称方式 |
|---------|--------|---------|
| **左右对称** | 左上 ↔ 右上 | 正竖 ↔ 反竖（列序方向反转） |
| **上下对称** | 左上 ↔ 左下 | 正常数据 ↔ 反转数据（每行内容上下颠倒） |
| **中心对称** | 左上 ↔ 右下 | 正竖+正常 ↔ 反竖+反转（双反转） |
| **左右对称** | 左下 ↔ 右下 | 正竖+反转 ↔ 反竖+反转 |
| **上下对称** | 右上 ↔ 右下 | 反竖+正常 ↔ 反竖+反转 |

整体效果：**上下对称 + 左右对称 + 中心对称**，四象限拼在一起是一个完整的对称图案。

## 四、四象限的实现原理

### 4.1 核心思路

四象限同时生成 4 组数据：

```
Q1 左上 = 正竖（左快右慢，正常数据）
Q2 右上 = 反竖（右快左慢，正常数据）
Q3 左下 = 正竖（左快右慢，反转数据）
Q4 右下 = 反竖（右快左慢，反转数据）
```

**为什么用正竖/反竖（竖向）？**
- 竖向排列时，左右两列并排放置，视觉上就是"左右对称"
- 上下两行堆叠放置，视觉上就是"上下对称"
- 如果用横向，左右并排会变成"行"，不符合直觉

### 4.2 数据反转（内部）

四象限内部有一个独立的"数据反转"逻辑，与全局的"数据反转"开关是**分开**的：

- 全局开关：影响**所有**算法（四方/双边/备选/四象限）的源数据读取
- 四象限内部：始终同时生成"正常"和"反转"两个版本，用于上下对称

**如果全局勾选了"数据反转"会怎样？**
- 左上 = 正竖（已全局反转的数据）
- 右上 = 反竖（已全局反转的数据）
- 左下 = 正竖（全局反转后再内部反转 = 恢复正常）
- 右下 = 反竖（全局反转后再内部反转 = 恢复正常）

简单说：全局开关是"整体翻不翻"，四象限内部是"上下两部分互为镜像"。

### 4.3 布局细节

**合并模式（每象限1列）：**
- 列：A=左列两象限，B=空列，C=右列两象限
- 行：第1行=上标签，2~M+1=上半，M+2=空行，M+3=下标签，M+4~2M+3=下半

**分开模式（每象限K列）：**
- 列：1~K=左列两象限，K+1=空列，K+2~2K+1=右列两象限
- 行：与合并模式相同

象限之间都留有空行/空列作为分隔，避免混淆。

## 二、数据反转是什么

```
  A1          A1-B1
  A2    →     A2-B1
              A1-B2
              A2-B2
```

**反转模式**（勾选）：数据从下到上读取
```
A列数据：    组合（正向）：
  A1          A2-B3    ← 原来的最后一行变成第一行
  A2    →     A1-B3
              A2-B2
              A1-B2
              A2-B1
              A1-B1    ← 原来的第一行变成最后一行
```

**核心公式**：反转后第 i 行元素 = 原第 (n - i + 1) 行元素，其中 n = 该列行数。

### 2.2 以 2×2×2 为例验证

源数据（3列，每列2行）：
```
A列  B列  C列
 1    1    1
 2    2    2
```

| 模式 | 输出前3行 | 输出后3行 | 说明 |
|------|----------|----------|------|
| 正常（正向） | 1-1-1, 2-1-1, 1-2-1 | ...1-2-2, 2-2-2 | 1开头在前，2开头在后 |
| **反转（正向）** | **2-2-2, 1-2-2, 2-1-2** | **...2-1-1, 1-1-1** | 2开头在前，1开头在后 |

反转模式下，数据填写顺序从 `111 / 222` 变为 `222 / 111`（从上到下看）。

## 三、为什么需要数据反转

### 3.1 四方镜的对称场景

四方镜的核心用途是生成**左右对称、上下对称**的图案组合。当源数据本身有方向含义时（如"上/下"、"左/右"、"正/反"），镜像翻转后数据方向也应该同步翻转。

**举个直观例子**：
- A列存图案的"左半部分"，从上到下是 A1, A2, A3
- 正常模式下，左右对称时右边还是 A1, A2, A3 的顺序
- 但真正的"镜像"应该是：左边从上到下 A1→A2→A3，右边从下到上 A3→A2→A1

**勾选"数据反转"后**，生成的组合就像把源数据上下颠倒了再组合，配合四方镜的正/反向按钮，就能得到真正对称的效果。

### 3.2 四种对称组合方式

| 操作 | 效果 |
|------|------|
| 不反转 + 正向 | 正常左快右慢 |
| 不反转 + 反向 | 正常右快左慢 |
| **反转 + 正向** | **数据颠倒，左快右慢**（上下镜像） |
| **反转 + 反向** | **数据颠倒，右快左慢**（上下+左右镜像） |

这四种方式对应四方镜的四种对称形态，点击一下即可生成。

## 三、新旧算法差异详解

### 3.1 算法A 进位计数法 vs 四方循环 `scct`

**相同点**：
- 输出结果**完全相同**（都是笛卡尔积正向：A1B1, A2B1, A1B2...）
- 行数相同（各列行数乘积）

**差异点**：

| 维度 | scct | 算法A 进位计数 |
|------|------|---------------|
| 实现思路 | **按行定位**：先算每列步长，再用 `ys(cd(行,步长),列数)` 直接算出每行的源行号 | **逐行递推**：每列一个计数器，末位+1满则进位（像计程表） |
| 依赖步长 | 需要预计算 `fwdSteps`/`revSteps` | 完全不需要 |
| 支持正/反向 | 正反向都支持（步长不同） | 天然只产生"正向"顺序 |
| 代码直观度 | 公式化，需理解步长 | 循环+进位，直观易懂 |
| 扩展性 | 支持任意列数 | 同样支持任意列数 |

**本质关系**：算法A 是笛卡尔积的"计数器视角"实现，与 scct 的"步长定位"视角殊途同归。

---

### 3.2 算法B 回溯法 vs 四方循环 `scct`

**相同点**：
- 输出结果**完全相同**（笛卡尔积正向）
- 行数相同

**差异点**：

| 维度 | scct | 算法B 回溯法 |
|------|------|-------------|
| 实现思路 | 步长定位（迭代） | **递归 DFS**：逐列选择，选满输出，回溯 |
| 代码结构 | 双层循环 + 公式 | 递归函数（深度=列数） |
| 加筛选条件 | 难（需改公式） | **容易**（叶子处加 `If 条件 Then`） |
| 性能 | 快（纯循环） | 中（递归有调用开销） |
| 可读性 | 数学公式化 | 贴近"组合的数学定义" |

**典型扩展**（回溯法独有优势）：
```vba
If 当前列 > 总列数 Then
    If 临时行(1) <> 临时行(2) Then   ' 只要两列值不同的组合
        输出当前行
    End If
    Exit Sub
End If
```

---

### 3.3 算法C 自定义周期循环 vs 双边循环 `zxgbs`

**相同点**：
- 都是"每列独立循环"，行数 = LCM
- 输出顺序风格一致（对角线式）

**差异点**：

| 维度 | zxgbs | 算法C 自定义周期 |
|------|-------|-----------------|
| 每列周期 | 固定 = 该列行数 | **可任意指定**（如 A列2、B列3） |
| 周期与列长关系 | 必须相等 | 可不等（数据循环复用） |
| 灵活性 | 低 | 高（zxgbs 是周期=列长的特例） |
| 典型场景 | 标准周期对齐 | 自定义节奏（2-3-4 错开循环） |

**验证**：当周期 = 各列行数时，算法C 输出与 zxgbs **完全一致**（算法C 是 zxgbs 的超集）。

---

### 3.4 算法D 随机抽样 vs 其他所有算法

**核心差异**：

| 维度 | scct/zxgbs/A/B/C | 算法D 随机抽样 |
|------|------------------|---------------|
| 生成方式 | 确定性（每次结果相同） | **随机**（每次结果不同） |
| 覆盖范围 | 全部/部分组合 | 随机子集 |
| 行数控制 | 由列数决定 | **用户指定 N 行** |
| 可重复 | 固定序列 | 可重复模式（同一组合可多次出现） |
| 适用场景 | 全量组合、周期对齐 | 随机测试、抽样 |

**独特价值**：前 5 种算法都无法生成随机组合，算法D 填补了这个空白。

---

### 3.5 算法E 逐列扩展法 vs 四方循环 `scct`

**相同点**：
- 输出结果**完全相同**（笛卡尔积正向，左快右慢）
- 行数相同（各列行数乘积）

**差异点**：

| 维度 | scct | 算法E 逐列扩展 |
|------|------|---------------|
| 实现思路 | 步长定位，一次性算出所有行 | **逐步构建**：从第1列开始，每加一列就把已有结果复制 n 份并追加新列元素 |
| 内存模式 | 一次性分配完整结果数组 | 数组逐列膨胀（中间结果越来越大） |
| 直观性 | 数学公式，需理解步长概念 | **非常直观**：就像"先列A的所有元素，再每个都搭配B的每个元素..." |
| 扩展列 | 列数一开始就要确定 | 天然支持"动态加列"（流式扩展） |
| 性能 | 快（纯索引计算） | 中（大量数组复制） |
| 方向 | 正/反向都支持 | **仅正向（左快右慢）** |

**核心思想**：第 k 列加入时，已有 `M` 行结果 → 复制 `每列行数(k)` 份，第 i 份的第 k 列 = 源数据第 i 行。

> **方向备注**：算法E 是**左快右慢**（与 scct 正向、算法A、算法B 输出完全一致）。左边列变化频繁，右边列变化慢。

---

### 3.6 算法F 格雷码遍历 vs 四方循环 `scct`

**相同点**：
- 都生成**全部**笛卡尔积组合（行数=乘积）
- 都覆盖所有组合不重复、不遗漏

**核心差异——相邻组合的变化量**：

| 维度 | scct 正向 | 算法F 格雷码 |
|------|-----------|-------------|
| 相邻变化 | 可能变**多列**（如 A2B3 → A1B1，两列都变） | **只变一列**（每次只有某一列前进/后退一格） |
| 顺序 | 字典序（左快右慢） | 反射格雷码序（**左慢右快**，递归反射构造） |
| 典型用途 | 常规枚举、输出展示 | **相邻用例测试**（每次只改一个参数，定位问题更快） |
| 实现难度 | 简单 | 中（递归反射，方向交替） |
| 方向 | 正/反向都支持 | **仅左慢右快**（递归从左到右，左列是外层） |

**直观理解**：格雷码遍历就像在组合空间里"走迷宫"，每次只挪一步（一列变化），走遍所有房间不重复。

> **方向备注**：算法F 是**左慢右快**。递归从第1列（最左）开始，左列是最外层循环→变化最慢；最右列是最内层递归→变化最快。这与 scct 正向（左快右慢）的方向正好相反。

**2×3 示例对比**：
- scct 正向（左快右慢）：A1B1 → A2B1 → A1B2 → A2B2 → A1B3 → A2B3（第2→3步两列都变）
- 格雷码（左慢右快）：A1B1 → A1B2 → A1B3 → A2B3 → A2B2 → A2B1（每步只变一列）

验证格雷码性质：逐行对比相邻两行，每次只有一列的值不同（汉明距离=1）。

---

### 3.7 算法G 混合进制随机访问 vs 其他所有算法

**核心独特性**：算法G 不是"从头生成序列"，而是**给定方向、起始和结束序号，直接算出该区间内的所有组合**。

| 维度 | 其他算法（A/B/E/F等） | 算法G 随机访问（区间+正反） |
|------|----------------------|---------------------------|
| 输入 | 列数据 | 列数据 + **方向 + 起始序号 + 结束序号** |
| 输出 | 全部 N 行 | **区间 M 行**（第 start ~ end 个组合） |
| 时间 | O(N) 生成全部 | O(M × 列数)，只算你要的那一段 |
| 方向 | 部分支持正/反向 | **正/反向都支持**（权重方向反转） |
| 用途 | 全量枚举 | **断点续算、并行分区、区间抽检** |
| 依赖 | 需要按顺序从头生成 | 完全独立，不需要先生成前面的组合 |

**两种方向的权重计算**：

- **正向（左快右慢）**：`权重(列) = 权重(列-1) × 每列行数(列-1)`，第一列权重=1
- **反向（右快左慢）**：`权重(列) = 权重(列+1) × 每列行数(列+1)`，最后一列权重=1

以 2×3 数据（A列2行、B列3行）为例：

| k | 正向（左快右慢） | 反向（右快左慢） |
|---|-----------------|-----------------|
| 1 | A1B1 | A1B1 |
| 2 | A2B1 | A1B2 |
| 3 | A1B2 | A1B3 |
| 4 | A2B2 | A2B1 |
| 5 | A1B3 | A2B2 |
| 6 | A2B3 | A2B3 |

**验证**：
- 正向输出与 scct 正向（按钮3）完全一致
- 反向输出与 scct 反向（按钮1）完全一致

**性能优化**：预计算权重数组（只算一次），避免每行重复累乘。

**典型应用场景**：
- 数据量太大无法一次生成 → 多线程/多进程分区计算（每个 worker 算自己负责的序号段）
- 只想看第 10000~10100 个组合 → 直接算，不用先生成前 9999 个
- 断点续跑 → 记录上次跑到第几个，下次从那个序号继续
- 验证某段区间的组合是否符合预期

**关键差异总结**：
- **A/B/E 与 scct**：输出相同，仅实现方式不同（验证"殊途同归"——笛卡尔积至少有 4 种实现路径）

## 六、验证方法（在 v8 中实际操作）

### 6.1 验证 A/B = scct 正向

1. 活动工作表放 2×3 数据（A1,A2 / B1,B2,B3）
2. 点"备选算法验证"→ 选 **A**，生成 `备选A_进位计数`
3. 再点按钮3（正向竖向）生成 `四方_正竖_合并`
4. **两张表内容应完全一致** → 证明算法A 正确实现了笛卡尔积

同理可验证 B。

### 6.2 验证 C = zxgbs（周期=列长时）

1. 数据用 2×4（A1,A2 / B1..B4）
2. 算法C 周期默认 2,3 → LCM=6，输出 6 行
3. 与 zxgbs 的 LCM(2,4)=4 对比 → 可见"周期可自定义"的差异

### 6.3 验证 D 随机性

连续运行算法D 两次，结果通常不同 → 体现随机性。

### 6.4 验证 E = scct 正向（逐列扩展）

1. 同样用 2×3 数据
2. 选 **E** 生成 `备选E_逐列扩展`
3. 与 scct 正向结果对比 → 应完全一致
4. **直观理解**：E 是"一层一层搭出来的"，先有 A 列 2 行，再加 B 列时复制 3 份，最终 6 行

### 6.5 验证 F 格雷码特性（相邻只变一列）

1. 用 2×3 数据生成 `备选F_格雷码`
2. 逐行对比相邻两行 → 每次只有**某一列**的值不同
3. 这就是格雷码的核心性质："汉明距离 = 1"

### 6.6 验证 G 随机访问区间（正/反向）正确性

**验证正向（左快右慢）：**
1. 用 2×3 数据（乘积=6）
2. 选 **G**，方向输入 `1`（正向），起始 `2`、结束 `5` → 4 行
3. 与 scct 正向（按钮3）输出的第 2~5 行对比 → 应完全一致

**验证反向（右快左慢）：**
1. 选 **G**，方向输入 `0`（反向），起始 `1`、结束 `6` → 6 行
2. 与 scct 反向（按钮1）输出对比 → 应完全一致

## 八、结论

- **现有算法不变**：v8 完全兼容 v6 的所有行为，可放心升级
- **备选算法是"验证+补充"**：
  - A/B/E 证明笛卡尔积有多种实现（步长 / 进位 / 递归 / 数组扩展，殊途同归）
  - C 扩展了双边循环（任意周期）
  - D 补充了随机能力（含不重复洗牌算法）
  - F 提供格雷码顺序（相邻只变一列，适合调试）
  - G 提供随机访问能力（并行计算基础）
- **选用建议**：
  - 日常用现有 6 按钮
  - 需要随机数据用 D
  - 需要带筛选条件的组合用 B
  - 需要自定义循环节奏用 C
  - 需要相邻用例测试（每次只改一个参数）用 F
  - 需要大数据量分区计算/断点续跑，底层原理参考 G
